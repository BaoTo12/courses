## Narrative Bridge: Moving to Real Execution

In [Lecture 01.03](./01.03-build-order-api-handler.md) and [Lecture 01.04](./01.04-provisioning-sam-template.md), you constructed the Java backend code and the declarative SAM template.

Now comes the moment of operational execution:
1. First, you will emulate API Gateway and Lambda locally on your machine using Docker via `sam local start-api`.
2. Second, you will build and package the production artifacts using `sam build`.
3. Third, you will execute a guided deployment (`sam deploy --guided`) to provision live resources in your real AWS account.
4. Finally, you will trigger the deployed cloud endpoint using `curl`.

---

## Part A: Local Emulation with AWS SAM CLI

Before pushing infrastructure to AWS, verify the API Gateway routing locally using Docker and the SAM CLI:

### 1. Build the Artifacts
Navigate to the module directory and execute:
```bash
sam build
```
*Verification*: The `.aws-sam/build/` directory is generated containing `template.yaml` and the compiled Fat JAR.

### 2. Start Local API Gateway Emulation
```bash
sam local start-api -p 3000
```
*Note*: Requires Docker running. Emulates an HTTP server matching the API Gateway routing spec.

### 3. Test Ingestion via cURL
In a separate terminal window:
```bash
curl -i -X POST http://localhost:3000/orders/electronics?region=us-east-1 \
  -H "Content-Type: application/json" \
  -d '{"itemId":"PHONE-99","quantity":3,"customerEmail":"tester@cloudorder.internal"}'
```

**Assertion Checklist**:
- [ ] Returns HTTP `201 Created`
- [ ] Response headers contain `Access-Control-Allow-Origin: *`
- [ ] Response body contains `"status":"CREATED"` and `"categoryPath":"electronics"`

## Part B: Deploy to Real AWS Account

Now deploy the real stack to your AWS account:

```bash
sam deploy --guided
```

**Prompts Configuration**:
* **Stack Name**: `cloudorder-api-dev`
* **AWS Region**: Your preferred region (e.g. `us-east-1`)
* **Confirm changes before deploy**: `y`
* **Allow SAM CLI IAM role creation**: `y`
* **Disable rollback for faster debugging**: `n`
* **OrderApiFunction has no authentication. Is this okay?**: `y` *(We will add Cognito Authentication in Module 5)*
* **Save arguments to configuration file**: `y`

### Physical Verification on Live AWS
Once deployment finishes, grab the `OrderApiEndpoint` from the CloudFormation outputs and call it live:

```bash
curl -i -X POST "<OrderApiEndpoint>" \
  -H "Content-Type: application/json" \
  -d '{"itemId":"ITEM-REAL-01","quantity":1,"customerEmail":"admin@cloudorder.internal"}'
```
