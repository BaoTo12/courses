## Narrative Bridge: The Ghost in the Machine

In [Lecture 01.06](./01.06-live-verification-cloudwatch-insights.md), we learned how to monitor and query CloudWatch log streams. 

Now, we will use that observability skill to solve one of the most frustrating errors in AWS serverless development: **HTTP 502 Bad Gateway with zero errors in Lambda**.

Imagine an engineer tries to "simplify" the `OrderApiHandler` by removing the `APIGatewayProxyResponseEvent` boilerplate and returning the `OrderResponse` POJO directly. Let's see what happens to API Gateway when this is deployed.

---

## 1. Symptom / The Broken Code

The developer modifies the handler to return the `OrderResponse` POJO directly:

```java
// Broken code snippet:
public OrderResponse handleRequest(APIGatewayProxyRequestEvent input, Context context) {
    return new OrderResponse("ORD-1", "CREATED", "ITEM-1", 1, 99.99, "books", "us-east-1");
}
```

When invoking the API via `curl`, the client receives:
```http
HTTP/1.1 502 Bad Gateway
Content-Type: application/json
Content-Length: 36

{"message": "Internal server error"}
```

---

## 2. The Error / Investigate

The developer opens Lambda CloudWatch Logs and sees:
```text
REPORT RequestId: 44e12a34-b567-4890-a123-456789abcdef
Duration: 14.21 ms    Billed Duration: 15 ms    Memory Size: 1769 MB
```
*Zero exceptions in Lambda! The function succeeded with no error stack!*

Next, the developer enables Execution Logging in API Gateway and inspects the API Gateway log stream:
```text
(44e12a34-b567-4890-a123-456789abcdef) Endpoint response body before transformations: {"orderId":"ORD-1","status":"CREATED",...}
(44e12a34-b567-4890-a123-456789abcdef) Execution failed due to configuration error: Malformed Lambda proxy response
(44e12a34-b567-4890-a123-456789abcdef) Method completed with status: 502
```

---

## 3. Root Cause

In Proxy Integration (`AWS_PROXY`), API Gateway performs **zero transformation**. It expects Lambda to return a structured JSON response matching this schema:

```json
{
  "isBase64Encoded": false,
  "statusCode": 200,
  "headers": { "Content-Type": "application/json" },
  "body": "{ ... payload string ... }"
}
```

If the Java handler returns a POJO or raw string, the Lambda runtime serializes it as `{ "orderId": "..." }`. When API Gateway attempts to parse the mandatory top-level key `"statusCode"`, it encounters `null` and throws `Malformed Lambda proxy response` $\to$ `502 Bad Gateway`.

---

## 4. The Fix

Always return `APIGatewayProxyResponseEvent`:

```java
return new APIGatewayProxyResponseEvent()
    .withStatusCode(201)
    .withHeaders(DEFAULT_HEADERS)
    .withBody(OBJECT_MAPPER.writeValueAsString(response));
```
