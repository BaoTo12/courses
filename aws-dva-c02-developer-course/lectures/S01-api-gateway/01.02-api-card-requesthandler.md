## Narrative Bridge: The Contract Between Gateway and JVM

In [Lecture 01.01](./01.01-mechanical-sympathy-api-gateway-lambda.md), we established that API Gateway uses **Proxy Integration (`AWS_PROXY`)** to bypass Velocity Template Language (VTL) mappings and stream the raw HTTP invocation directly into Lambda.

Because API Gateway does not transform the payload, your Java application must implement a strictly defined serialization contract. If you return an unformatted Java object, a raw string, or forget the status code, API Gateway will choke and return a `502 Bad Gateway` error to the customer (we will reproduce and debug this exact scenario in [Lecture 01.07](./01.07-debug-malformed-proxy-response.md)).

Here is the exact AWS SDK for Java interface that enforces this contract.

---

## 📇 API Card: `RequestHandler<I, O>`

```java
package com.amazonaws.services.lambda.runtime;

public interface RequestHandler<I, O> {
    O handleRequest(I input, Context context);
}
```

When building an API Gateway proxy handler, the type arguments are:
* **`I` (Input)**: `com.amazonaws.services.lambda.runtime.events.APIGatewayProxyRequestEvent`
* **`O` (Output)**: `com.amazonaws.services.lambda.runtime.events.APIGatewayProxyResponseEvent`

---

### 1. `APIGatewayProxyRequestEvent` (Incoming Wire Payload)

When a client sends an HTTP request, API Gateway serializes it into this Java object before calling `handleRequest`:

| Method | Return Type | Description & Production Usage |
|---|---|---|
| `getPathParameters()` | `Map<String, String>` | Path tokens extracted from URL templates. For greedy paths like `/orders/{proxy+}`, key `"proxy"` contains the sub-path (e.g., `"electronics/phones"`). |
| `getQueryStringParameters()` | `Map<String, String>` | URL query parameters (e.g. `?region=us-east-1` $\to$ `get("region")`). |
| `getBody()` | `String` | Raw UTF-8 string payload (or Base64 if `getIsBase64Encoded()` is true). Must be parsed via Jackson. |
| `getHeaders()` | `Map<String, String>` | Case-insensitive map of incoming HTTP request headers (`Authorization`, `Content-Type`). |
| `getHttpMethod()` | `String` | Invoking HTTP verb: `GET`, `POST`, `PUT`, `DELETE`, `OPTIONS`. Used for routing. |
| `getRequestContext()` | `ProxyRequestContext` | Stage name, AWS account ID, authorizer claims (used for Cognito in [Module 5](../S05-security/)), and caller IP. |

---

### 2. `APIGatewayProxyResponseEvent` (Outgoing Response Contract)

The Lambda handler must return this structured object back to API Gateway:

| Method | Argument Type | Description & Production Usage |
|---|---|---|
| `withStatusCode(Integer code)` | `Integer` | HTTP response status code (e.g. `201 Created`, `400 Bad Request`, `500 Server Error`). |
| `withHeaders(Map<String, String>)` | `Map<String, String>` | **Mandatory** for CORS (`Access-Control-Allow-Origin: *`) and Content-Type (`application/json`). |
| `withBody(String body)` | `String` | Raw JSON string payload returned to the caller. Must be serialized via Jackson. |
| `withIsBase64Encoded(Boolean)` | `Boolean` | Set to true when returning binary data (images, PDFs, archives). |

---

## Minimal Example (Outside CloudOrder)

```java
public class HealthCheckHandler implements RequestHandler<APIGatewayProxyRequestEvent, APIGatewayProxyResponseEvent> {

    @Override
    public APIGatewayProxyResponseEvent handleRequest(APIGatewayProxyRequestEvent request, Context context) {
        context.getLogger().log("Health check invoked from IP: " + request.getRequestContext().getIdentity().getSourceIp());

        return new APIGatewayProxyResponseEvent()
            .withStatusCode(200)
            .withHeaders(Map.of(
                "Content-Type", "application/json",
                "Access-Control-Allow-Origin", "*"
            ))
            .withBody("{\"status\":\"UP\",\"timestamp\":" + System.currentTimeMillis() + "}");
    }
}
```

---

## Operational Traps & Exam Watch

* **The CORS Trap**: Even if you configure CORS in API Gateway's SAM template, if your Lambda function returns a 400 or 500 error *without* the `Access-Control-Allow-Origin` header in its response map, the user's browser will discard the response with a CORS block error!
* **The 502 Proxy Malformed Trap**: If your Java method returns `OrderResponse` directly instead of `APIGatewayProxyResponseEvent`, API Gateway cannot find the required `statusCode` key and throws an `HTTP 502 Bad Gateway` error.
