## Lab Objective

In this hands-on lab, you will:
1. Start an AWS CodePipeline execution via the AWS CLI and monitor stage progress across Source, Build, and Deploy.
2. Track an active AWS CodeDeploy deployment undergoing `Canary10Percent5Minutes` traffic shifting.
3. Query the `live` Lambda function alias repeatedly to witness the 10/90 traffic split.
4. Simulate a failing synthetic validation check in `CanaryValidationHookHandler` and observe CodeDeploy's automated rollback sequence.

## Task 1: Trigger Pipeline Execution via AWS CLI

First, determine your pipeline name from AWS CloudFormation outputs:
```bash
PIPELINE_NAME=$(aws cloudformation describe-stacks \
  --stack-name cloudorder-cicd-pipeline \
  --query "Stacks[0].Outputs[?OutputKey=='PipelineName'].OutputValue" \
  --output text)

echo "Target Pipeline: $PIPELINE_NAME"
```

### 1.1 Start Pipeline Execution
```bash
EXECUTION_ID=$(aws codepipeline start-pipeline-execution \
  --name "$PIPELINE_NAME" \
  --query "pipelineExecutionId" \
  --output text)

echo "Triggered Execution ID: $EXECUTION_ID"
```

### 1.2 Monitor Stage Transitions
```bash
aws codepipeline get-pipeline-state \
  --name "$PIPELINE_NAME" \
  --query "stageStates[*].{Stage:stageName,Status:latestExecution.status}" \
  --output table
```

Observe each stage transitioning from `InProgress` to `Succeeded`:
* **Source**: `Succeeded`
* **Build**: `Succeeded` (CodeBuild executed `mvn clean compile test`)
* **Deploy**: `InProgress`

## Task 2: Observe Canary Traffic Shifting in CodeDeploy

When the Deploy stage activates, extract the active deployment ID:

```bash
DEPLOYMENT_ID=$(aws deploy list-deployments \
  --application-name "cloudorder-deploy-prod" \
  --deployment-group-name "cloudorder-canary-group-prod" \
  --include-only-statuses "InProgress" \
  --query "deployments[0]" \
  --output text)

echo "Active Deployment: $DEPLOYMENT_ID"
```

### 2.1 Inspect Canary Status
```bash
aws deploy get-deployment \
  --deployment-id "$DEPLOYMENT_ID" \
  --query "deploymentInfo.{Status:status,Config:deploymentConfigName,Rollback:autoRollbackConfiguration.enabled}" \
  --output json
```

Inspect the traffic routing progress:
* CodeDeploy executes the `BeforeAllowTraffic` hook (`CanaryValidationHookFunction`).
* Once the hook reports `SUCCEEDED`, CodeDeploy splits traffic: **10% to Version 2**, **90% to Version 1**.
* A 5-minute evaluation timer begins.

## Task 3: Simulate a Hook Failure to Trigger Automated Rollback

Now, test automated rollback resilience:
1. Trigger a deployment where the synthetic health probe throws an error or fails.
2. Watch the deployment status update:
   ```bash
   aws deploy get-deployment \
     --deployment-id "$DEPLOYMENT_ID" \
     --query "deploymentInfo.errorInformation" \
     --output json
   ```
3. Observe the output:
   ```json
   {
     "ErrorCode": "HOOK_EXECUTION_FAILURE",
     "ErrorMessage": "The lifecycle event hook execution failed for BeforeAllowTraffic"
   }
   ```
4. Query the deployment status again:
   ```text
   Status: Failed (Rolling back to previous revision)
   ```
✅ **Checkpoint**: CodeDeploy detects the failed hook and restores 100% of traffic to Version 1 immediately without routing any user traffic to the failing version.
