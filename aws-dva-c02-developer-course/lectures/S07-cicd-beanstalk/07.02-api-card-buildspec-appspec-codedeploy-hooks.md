## 1. AWS CodeBuild: `buildspec.yml` Specification

The `buildspec.yml` file defines commands and settings executed by CodeBuild inside its build environment:

```yaml
version: 0.2

env:
  variables:
    JAVA_HOME: "/usr/lib/jvm/java-21-amazon-corretto"
  parameter-store:
    DB_URL: "/cloudorder/prod/db_url"
  secrets-manager:
    PAYMENT_API_KEY: "cloudorder/payment-gateway:apiKey"
  exported-variables:
    - BUILD_TIMESTAMP

phases:
  install:
    runtime-versions:
      java: corretto21
    commands:
      - echo "Installing dependencies..."
  pre_build:
    commands:
      - echo "Running unit tests before packaging..."
      - mvn clean test
  build:
    commands:
      - echo "Building fat JAR..."
      - mvn package -DskipTests
      - BUILD_TIMESTAMP=$(date +%s)
  post_build:
    commands:
      - echo "Build completed on ${BUILD_TIMESTAMP}"

artifacts:
  files:
    - target/*.jar
    - appspec.yaml
    - template.yaml
  discard-paths: no

cache:
  paths:
    - '/root/.m2/**/*'
```

### High-Yield DVA-C02 Mechanics:
1. **`finally` Blocks**: Each phase supports a `finally` block that executes even if earlier commands fail, ensuring diagnostic logs or reports are published.
2. **`exported-variables`**: Allows exporting environment variables generated during the build (like build timestamps or commit hashes) into downstream CodePipeline actions.
3. **`parameter-store` and `secrets-manager`**: Pulls credentials securely into build memory without embedding secrets in git.

## 2. AWS CodeDeploy: `appspec.yaml` Specification

For **AWS Lambda** deployments, `appspec.yaml` defines the function alias, version target, and verification hooks:

```yaml
version: 0.0
Resources:
  - TargetFunction:
      Type: AWS::Lambda::Function
      Properties:
        Name: CloudOrderServiceFunction
        Alias: live
        CurrentVersion: "1"
        TargetVersion: "2"
Hooks:
  - BeforeAllowTraffic: CanaryValidationHookFunction
  - AfterAllowTraffic: PostDeploymentAuditHookFunction
```

### Lifecycle Hooks for AWS Lambda Deployments:
* **`BeforeAllowTraffic`**: Executes **before** CodeDeploy begins shifting any traffic to the new version (`TargetVersion`). Used for synthetic health checks, integration sanity testing, and database schema compatibility checks.
* **`AfterAllowTraffic`**: Executes **after** 100% of traffic has been shifted to the new version. Used for post-deployment metrics validation, warm container cache priming, or notifying alerting channels.

## 3. CodeDeploy Lifecycle Hook Protocol

When CodeDeploy triggers a hook Lambda function, it passes a JSON payload:

```json
{
  "DeploymentId": "d-ABC12345",
  "LifecycleEventHookExecutionId": "e-XYZ67890"
}
```

The hook function **must** invoke the AWS CodeDeploy API to report completion:

```java
import software.amazon.awssdk.services.codedeploy.CodeDeployClient;
import software.amazon.awssdk.services.codedeploy.model.LifecycleEventStatus;
import software.amazon.awssdk.services.codedeploy.model.PutLifecycleEventHookExecutionStatusRequest;

public class CodeDeployHookHelper {

    public static void reportStatus(CodeDeployClient client, String deploymentId, String hookId, boolean success) {
        PutLifecycleEventHookExecutionStatusRequest request = PutLifecycleEventHookExecutionStatusRequest.builder()
                .deploymentId(deploymentId)
                .lifecycleEventHookExecutionId(hookId)
                .status(success ? LifecycleEventStatus.SUCCEEDED : LifecycleEventStatus.FAILED)
                .build();

        client.putLifecycleEventHookExecutionStatus(request);
    }
}
```

> [!IMPORTANT]
> If the hook function finishes execution without calling `putLifecycleEventHookExecutionStatus`, CodeDeploy waits until the hook timeout expires (default: 60 minutes), marks the deployment as **FAILED**, and triggers an automated rollback!
