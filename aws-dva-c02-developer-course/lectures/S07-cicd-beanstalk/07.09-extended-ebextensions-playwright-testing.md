## 1. Elastic Beanstalk Customization with `.ebextensions`

To configure underlying EC2 operating systems, install native Linux packages, configure NGINX, and run database migrations, developers place `.config` files inside the `.ebextensions/` directory at the root of their source bundle.

```text
cloudorder-web-app.zip
├── .ebextensions/
│   ├── 01_system_packages.config
│   ├── 02_environment_variables.config
│   └── 03_database_migration.config
├── application.jar
└── Procfile
```

### 1.1 The `.ebextensions` Execution Order & Key Directives
Files in `.ebextensions/` are processed in **alphabetical lexicographical order** (`01_...` before `02_...`).

```yaml
# 01_system_packages.config
packages:
  yum:
    htop: []
    postgresql15: []

# 03_database_migration.config
container_commands:
  01_run_migrations:
    command: "java -cp application.jar com.cloudarchitect.dvac02.MigrateDatabase"
    leader_only: true
```

### The Critical Difference for DVA-C02: `commands` vs. `container_commands`

| Directive | Execution Timing | `leader_only` Support? | DVA-C02 Primary Use Case |
|---|---|:---:|---|
| **`commands`** | Runs early in the deployment process **before** application source code is unpacked. | ❌ No (runs on every instance) | Installing OS patches, setting system sysctl parameters. |
| **`container_commands`** | Runs **after** application code and dependencies have been extracted, right before the server starts. | ✅ **Yes** | **Database Schema Migrations** (`leader_only: true` ensures migrations execute only on ONE leader instance, preventing race conditions). |

## 2. Automated Playwright Browser Testing in AWS CodeBuild

Unit tests prove that individual functions work in isolation, but only browser-level end-to-end tests prove that the entire system functions properly from the user's perspective.

### 2.1 Running Headless Playwright in CodeBuild
AWS CodeBuild supports running headless browser test suites (Playwright, Cypress, Puppeteer) inside standard Linux container images:

```yaml
# In buildspec.yml
phases:
  install:
    runtime-versions:
      nodejs: 20
      java: corretto21
    commands:
      - npm ci
      - npx playwright install --with-deps chromium
  post_build:
    commands:
      - echo "Running end-to-end browser validation tests against staging..."
      - npx playwright test tests/e2e/checkout-flow.spec.ts
```

### 2.2 Sample Playwright Test Script (`checkout-flow.spec.ts`)

```typescript
import { test, expect } from '@playwright/test';

test('Customer can authenticate and complete order checkout', async ({ page }) => {
  // 1. Visit CloudOrder Web Portal
  await page.goto(process.env.STAGING_URL || 'https://staging.cloudorder.com');

  // 2. Perform Login Flow
  await page.fill('#email-input', 'developer@cloudorder.com');
  await page.fill('#password-input', 'SecureCloudOrder2026!');
  await page.click('#login-submit-btn');

  // 3. Verify Dashboard Loads
  await expect(page.locator('#order-history-table')).toBeVisible();

  // 4. Create Order & Verify Checkout
  await page.click('#create-order-btn');
  await expect(page.locator('.toast-success')).toHaveText(/Order #ord-.* created successfully/);
});
```

If the Playwright test encounters a UI regression, JavaScript error, or broken API route, the process exits with status code 1. CodeBuild halts, preventing the regression from ever reaching production.
