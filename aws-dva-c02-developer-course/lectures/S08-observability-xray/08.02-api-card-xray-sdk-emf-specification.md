## 1. AWS X-Ray SDK for Java: Subsegment API

When AWS Lambda active tracing is enabled, AWS Lambda automatically creates the root **Segment**. To instrument downstream calls and internal business logic, developers create **Subsegments**.

### 1.1 Managing Subsegment Lifecycles

```java
import com.amazonaws.xray.AWSXRay;
import com.amazonaws.xray.entities.Subsegment;

public class OrderTracingHelper {

    public static void executeWithTracing(String subsegmentName, String orderId, Runnable operation) {
        // 1. Begin Subsegment
        Subsegment subsegment = AWSXRay.beginSubsegment(subsegmentName);
        try {
            // 2. Put Indexed Annotations (String, Number, Boolean)
            subsegment.putAnnotation("orderId", orderId);
            subsegment.putAnnotation("environment", "prod");

            // 3. Put Non-Indexed Forensic Metadata (Complex JSON)
            subsegment.putMetadata("debugContext", Map.of(
                    "threadName", Thread.currentThread().getName(),
                    "allocatedMemoryMb", Runtime.getRuntime().totalMemory() / (1024 * 1024)
            ));

            // Execute business logic
            operation.run();

        } catch (Exception e) {
            // Marks subsegment as Fault / Error in X-Ray Service Map
            subsegment.addException(e);
            throw e;
        } finally {
            // 4. Critical Invariant: Always end the subsegment in a finally block!
            AWSXRay.endSubsegment();
        }
    }
}
```

> [!CAUTION]
> If `AWSXRay.endSubsegment()` is omitted or bypassed due to an uncaught exception, the subsegment is never closed. X-Ray fails to emit the trace to the daemon, causing missing downstream nodes in your service map! Always wrap subsegments in `try / finally`.

### 1.2 Automated AWS SDK v2 Tracing with `TracingInterceptor`

To trace AWS service calls (DynamoDB, S3, SQS) automatically without manually creating subsegments for every query:

```java
import software.amazon.awssdk.core.client.config.ClientOverrideConfiguration;
import software.amazon.awssdk.services.dynamodb.DynamoDbClient;
import com.amazonaws.xray.interceptors.TracingInterceptor;

public class InstrumentedClients {

    public static DynamoDbClient createInstrumentedDynamoDbClient() {
        return DynamoDbClient.builder()
                .overrideConfiguration(ClientOverrideConfiguration.builder()
                        .addExecutionInterceptor(new TracingInterceptor())
                        .build())
                .build();
    }
}
```
Any `putItem` or `query` operation executed by this client automatically generates child subsegments detailing downstream latency, HTTP status codes, and retry counts.

## 2. CloudWatch Embedded Metric Format (EMF) Specification

The EMF specification is a single-line JSON structure written directly to `stdout`.

### 2.1 Complete Formal JSON Schema

```json
{
  "_aws": {
    "Timestamp": 1790500000000,
    "CloudWatchMetrics": [
      {
        "Namespace": "CloudOrder/Production",
        "Dimensions": [
          ["Service", "Environment", "PaymentMethod"]
        ],
        "Metrics": [
          {
            "Name": "OrderProcessingLatencyMs",
            "Unit": "Milliseconds"
          },
          {
            "Name": "OrderSuccessCount",
            "Unit": "Count"
          }
        ]
      }
    ]
  },
  "Service": "OrderService",
  "Environment": "prod",
  "PaymentMethod": "CREDIT_CARD",
  "OrderProcessingLatencyMs": 142.5,
  "OrderSuccessCount": 1,
  "OrderId": "ord-8888",
  "CustomerId": "cust-101"
}
```

### 2.2 Valid CloudWatch Metric Units
CloudWatch strictly validates the `Unit` string. Passing an invalid unit causes the metric extraction daemon to drop the point:
* **Time**: `Seconds`, `Milliseconds`, `Microseconds`
* **Bytes**: `Bytes`, `Kilobytes`, `Megabytes`, `Gigabytes`, `Terabytes`
* **Network**: `Bits`, `Kilobits`, `Megabits`, `Gigabits`, `Bytes/Second`, `Count/Second`
* **Percentages & Counts**: `Percent`, `Count`, `None`
