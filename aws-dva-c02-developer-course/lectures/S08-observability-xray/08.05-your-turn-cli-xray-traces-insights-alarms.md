## Lab Objective

In this hands-on lab, you will:
1. Generate an end-to-end distributed trace by passing an explicit `X-Amzn-Trace-Id` header through an API Gateway endpoint.
2. Query AWS X-Ray trace summaries via the AWS CLI using indexed annotation filter expressions.
3. Start and poll an asynchronous CloudWatch Logs Insights query calculating P50, P90, and P95 latency percentiles.
4. Inspect the evaluation state of a CloudWatch Composite Alarm.

---

## Task 1: Generate an X-Ray Trace with Custom Trace ID

Generate a valid AWS X-Ray Root Trace ID:
```bash
# X-Ray Trace ID format: 1-[8 hex chars epoch]-[24 hex chars random]
EPOCH_HEX=$(printf '%x' $(date +%s))
RANDOM_HEX=$(openssl rand -hex 12)
TRACE_ID="1-${EPOCH_HEX}-${RANDOM_HEX}"

echo "Generated Root Trace ID: $TRACE_ID"
```

Send a request through API Gateway with the trace header:
```bash
API_URL="https://api.cloudorder.com/orders"

curl -i -X POST "$API_URL" \
  -H "Content-Type: application/json" \
  -H "X-Amzn-Trace-Id: Root=${TRACE_ID};Sampled=1" \
  -d '{"orderId":"ord-5001","customerId":"cust-101","amount":199.99}'
```

Verify that the response returns HTTP 201 Created and echoes back the `X-Amzn-Trace-Id` header.

## Task 2: Query Trace Summaries via AWS CLI

Query X-Ray using an annotation filter expression to locate the trace:

```bash
START_TIME=$(date -u -d '15 minutes ago' +%s)
END_TIME=$(date -u +%s)

aws xray get-trace-summaries \
  --start-time "$START_TIME" \
  --end-time "$END_TIME" \
  --filter-expression 'annotation.orderId = "ord-5001"' \
  --query "TraceSummaries[*].{Id:Id,Duration:Duration,Http:Http.HttpStatus,Annotations:Annotations}" \
  --output table
```

### Retrieve Full Trace Document:
```bash
aws xray batch-get-traces \
  --trace-ids "$TRACE_ID" \
  --query "Traces[0].Segments[*].Document" \
  --output json | jq .
```

Inspect the output segments:
* Root Segment: API Gateway execution duration.
* Child Subsegments: Lambda function, DynamoDB `PutItem`, S3 `S3Presigner`, and EMF emission.

## Task 3: Execute Percentile Query in CloudWatch Logs Insights

Use the AWS CLI to run our P95 latency query:

```bash
LOG_GROUP="/aws/lambda/cloudorder-observability-prod"

QUERY_ID=$(aws logs start-query \
  --log-group-name "$LOG_GROUP" \
  --start-time $(date -u -d '1 hour ago' +%s) \
  --end-time $(date -u +%s) \
  --query-string 'filter @type = "REPORT" | stats percentile(@duration, 50) as p50, percentile(@duration, 90) as p90, percentile(@duration, 95) as p95 by bin(5m)' \
  --query "queryId" \
  --output text)

echo "Logs Insights Query ID: $QUERY_ID"
```

Poll for results:
```bash
aws logs get-query-results --query-id "$QUERY_ID" --output table
```

✅ **Checkpoint**: You should observe P50, P90, and P95 latency distributions calculated in 5-minute bins across all Lambda executions.

## Task 4: Inspect CloudWatch Composite Alarm Evaluation

Verify the status of the Composite Alarm:

```bash
aws cloudwatch describe-alarms \
  --alarm-names "CloudOrder-CriticalDegradation-prod" \
  --query "CompositeAlarms[*].{Name:AlarmName,State:StateValue,Rule:AlarmRule}" \
  --output table
```

Observe that the alarm evaluates:
```text
ALARM("CloudOrder-HighErrors-prod") OR ALARM("CloudOrder-P95LatencySpike-prod")
```
If neither base alarm is in `ALARM` state, the composite alarm remains `OK`.
