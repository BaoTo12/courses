## 📇 Card 1: `SfnClient` & `StartExecutionRequest` (AWS SDK Java v2)

### Maven Dependency
```xml
<dependency>
    <groupId>software.amazon.awssdk</groupId>
    <artifactId>sfn</artifactId>
</dependency>
```

### Signature & Factory
```java
package software.amazon.awssdk.services.sfn;

public interface SfnClient extends SdkClient {
    static SfnClient create();
    static SfnClientBuilder builder();
    
    // Asynchronous start (Standard and Express workflows)
    StartExecutionResponse startExecution(StartExecutionRequest request);
    
    // Synchronous execution (Express workflows only!)
    StartSyncExecutionResponse startSyncExecution(StartSyncExecutionRequest request);
    
    // Polling / query execution status
    DescribeExecutionResponse describeExecution(DescribeExecutionRequest request);
}
```

### Usage Pattern: Idempotent Execution Launch
```java
SfnClient sfnClient = SfnClient.builder()
    .region(Region.US_EAST_1)
    .httpClient(UrlConnectionHttpClient.create())
    .build();

StartExecutionRequest request = StartExecutionRequest.builder()
    .stateMachineArn("arn:aws:states:us-east-1:123456789012:stateMachine:CloudOrderCheckoutSaga")
    .name("order-exec-" + orderId) // ⚡ Idempotency Token
    .input(orderJsonPayload)
    .build();

StartExecutionResponse response = sfnClient.startExecution(request);
String executionArn = response.executionArn();
```

> [!IMPORTANT]
> **The Idempotency Contract**:
> If you call `startExecution` with an execution `name` that already ran (or is currently running) with the exact same input, Step Functions returns the **existing `executionArn`** without launching a new execution! If you call it with the same name but different input within 90 days, it throws `ExecutionAlreadyExistsException`.

## 📇 Card 2: Amazon States Language (ASL) Core State Types

ASL is a declarative JSON/YAML specification that defines state machine graphs.

| State Type | Purpose | Primary Fields |
|---|---|---|
| `Task` | Executes work (invokes Lambda, writes to DynamoDB, publishes to SQS). | `Resource`, `Parameters`, `ResultSelector`, `ResultPath`, `Retry`, `Catch`, `Next` |
| `Choice` | Conditional branching based on state JSON data. | `Choices` (`Variable`, `StringEquals`, `NumericGreaterThan`, `BooleanEquals`), `Default` |
| `Parallel` | Executes multiple state branches concurrently. | `Branches` (array of parallel state machines), `ResultPath`, `Next` |
| `Map` | Runs a dynamic set of steps for each element in an input array. | `ItemProcessor` (or `Iterator`), `ItemsPath`, `MaxConcurrency` |
| `Wait` | Delays execution by seconds or until an ISO timestamp. | `Seconds`, `Timestamp`, `SecondsPath`, `TimestampPath`, `Next` |
| `Pass` | Injects fixed data or transforms JSON without executing tasks. | `Result`, `ResultPath`, `Parameters`, `Next` |
| `Succeed` | Terminal success state. Stops execution with status `SUCCEEDED`. | N/A |
| `Fail` | Terminal error state. Stops execution with status `FAILED`. | `Error`, `Cause` |

## 📇 Card 3: The 5 JSONPath Processing Stages

Every state in ASL manipulates state JSON via five sequential processing filters:

```text
Raw State JSON
      │
      ▼
┌──────────────┐
│  InputPath   │ ── Filters which part of the state JSON is considered (e.g. "$.order")
└──────┬───────┘
       ▼
┌──────────────┐
│  Parameters  │ ── Constructs the actual payload sent to the worker/task
└──────┬───────┘
       ▼
┌──────────────┐
│ Task Handler │ ── Lambda execution runs and returns output (e.g. { "paymentId": "PAY-123" })
└──────┬───────┘
       ▼
┌──────────────┐
│ResultSelector│ ── Extracts desired fields from task output before placing in state
└──────┬───────┘
       ▼
┌──────────────┐
│  ResultPath  │ ── ⚠️ CRITICAL: Determines where task result is attached in state JSON!
└──────┬───────┘
       ▼
┌──────────────┐
│  OutputPath  │ ── Filters the final merged JSON before passing to next state
└──────────────┘
```

### JSONPath Syntax Rules:
* Root symbol: `$` represents the root of the JSON document.
* Child operator: `$.orderId` selects property `orderId`.
* Key with dynamic evaluation: Any parameter key ending with `.$` (e.g., `"orderId.$": "$.orderId"`) tells Step Functions to evaluate the value as a JSONPath expression rather than a literal string.

## 📇 Card 4: Error Handling Contract (`Retry` and `Catch`)

### Predefined System Errors
* `States.ALL`: Wildcard catching all error names.
* `States.TaskFailed`: Any unhandled exception thrown inside the task handler.
* `States.Timeout`: Task exceeded `TimeoutSeconds`.
* `States.Permissions`: State machine lacks IAM permissions to execute the task.

### Custom Error Matching
When a Java Lambda function throws an exception, Step Functions matches against the **simple class name** of the exception:

```yaml
Catch:
  - ErrorEquals:
      - PaymentDeclinedException # Exact Java exception class name!
    ResultPath: "$.error"
    Next: CompensateInventory
```
