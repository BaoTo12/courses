## Narrative Bridge: Assembling the Distributed Saga

In [Lecture 03.03](./03.03-build-saga-tasks-compensating-handlers.md), we built and verified the individual Java 21 Lambda functions: `ReserveInventoryFunction`, `ProcessPaymentFunction`, and `CancelInventoryCompensateFunction`.

In a distributed microservice architecture, these functions should not invoke each other directly. Direct Lambda-to-Lambda invocation introduces tight temporal coupling, brittle error handling, and silent transaction abandonment if a container crashes midway.

Instead, we declare an **AWS Step Functions State Machine** in our SAM template. Step Functions maintains persistent state across hours or days, visualizes each execution in real time, executes automatic retries with exponential backoff, and guarantees that if payment declines, the compensating transaction runs without exception.

## The Complete SAM Infrastructure Template

✍️ `template.yaml`

```yaml
AWSTemplateFormatVersion: '2010-09-09'
Transform: AWS::Serverless-2016-10-31
Description: >
  CloudOrder Module 3: Distributed Multi-Step Order Checkout Saga with AWS Step Functions.
  Demonstrating Standard Workflows, Amazon States Language (ASL), Task retry exponential backoff,
  JSONPath payload transformations, compensating transactions, and raw JSON IAM execution roles.

Globals:
  Function:
    Timeout: 30
    MemorySize: 1769 # Exactly 1 full vCPU thread allocated to Java 21 JVM
    Runtime: java21
    Architectures:
      - x86_64
    Environment:
      Variables:
        STAGE: Prod
        LOG_LEVEL: INFO

Resources:
  # ============================================================================
  # 1. Lambda Functions (Saga Worker Tasks)
  # ============================================================================
  ReserveInventoryFunction:
    Type: AWS::Serverless::Function
    Properties:
      CodeUri: .
      Handler: com.cloudarchitect.dvac02.workflow.handler.ReserveInventoryHandler::handleRequest
      Role: !GetAtt SagaLambdaExecutionRole.Arn

  ProcessPaymentFunction:
    Type: AWS::Serverless::Function
    Properties:
      CodeUri: .
      Handler: com.cloudarchitect.dvac02.workflow.handler.ProcessPaymentHandler::handleRequest
      Role: !GetAtt SagaLambdaExecutionRole.Arn

  CancelInventoryCompensateFunction:
    Type: AWS::Serverless::Function
    Properties:
      CodeUri: .
      Handler: com.cloudarchitect.dvac02.workflow.handler.CancelInventoryCompensateHandler::handleRequest
      Role: !GetAtt SagaLambdaExecutionRole.Arn

  # ============================================================================
  # 2. Raw JSON IAM Execution Roles (Bypassing managed policies)
  # ============================================================================
  SagaLambdaExecutionRole:
    Type: AWS::IAM::Role
    Properties:
      AssumeRolePolicyDocument:
        Version: '2012-10-17'
        Statement:
          - Effect: Allow
            Principal:
              Service:
                - lambda.amazonaws.com
            Action:
              - sts:AssumeRole
      Policies:
        - PolicyName: CloudOrderExplicitLoggingPolicy
          PolicyDocument:
            Version: '2012-10-17'
            Statement:
              - Effect: Allow
                Action:
                  - logs:CreateLogGroup
                  - logs:CreateLogStream
                  - logs:PutLogEvents
                Resource: !Sub 'arn:aws:logs:${AWS::Region}:${AWS::AccountId}:log-group:/aws/lambda/*:*'

  OrderCheckoutStateMachineRole:
    Type: AWS::IAM::Role
    Properties:
      AssumeRolePolicyDocument:
        Version: '2012-10-17'
        Statement:
          - Effect: Allow
            Principal:
              Service:
                - states.amazonaws.com
            Action:
              - sts:AssumeRole
      Policies:
        - PolicyName: CloudOrderStepFunctionsLambdaInvokePolicy
          PolicyDocument:
            Version: '2012-10-17'
            Statement:
              - Effect: Allow
                Action:
                  - lambda:InvokeFunction
                Resource:
                  - !GetAtt ReserveInventoryFunction.Arn
                  - !GetAtt ProcessPaymentFunction.Arn
                  - !GetAtt CancelInventoryCompensateFunction.Arn
        - PolicyName: CloudOrderStepFunctionsLoggingPolicy
          PolicyDocument:
            Version: '2012-10-17'
            Statement:
              - Effect: Allow
                Action:
                  - logs:CreateLogDelivery
                  - logs:GetLogDelivery
                  - logs:UpdateLogDelivery
                  - logs:DeleteLogDelivery
                  - logs:ListLogDeliveries
                  - logs:PutResourcePolicy
                  - logs:DescribeResourcePolicies
                  - logs:DescribeLogGroups
                Resource: "*"

  # ============================================================================
  # 3. Step Functions State Machine (Saga Orchestration)
  # ============================================================================
  OrderCheckoutStateMachine:
    Type: AWS::Serverless::StateMachine
    Properties:
      Name: CloudOrderCheckoutSaga
      Type: STANDARD
      Role: !GetAtt OrderCheckoutStateMachineRole.Arn
      Definition:
        Comment: "CloudOrder Distributed Saga: Reserve Inventory -> Process Payment -> Compensate on Failure"
        StartAt: ReserveInventory
        States:
          # --- State 1: Reserve Inventory Task ---
          ReserveInventory:
            Type: Task
            Resource: arn:aws:states:::lambda:invoke
            Parameters:
              FunctionName: !GetAtt ReserveInventoryFunction.Arn
              Payload.$: "$"
            ResultSelector:
              reservationId.$: "$.Payload.reservationId"
              status.$: "$.Payload.status"
            ResultPath: "$.inventoryResult"
            Retry:
              - ErrorEquals:
                  - Lambda.ServiceException
                  - Lambda.AWSLambdaException
                  - States.TaskFailed
                IntervalSeconds: 2
                MaxAttempts: 2
                BackoffRate: 2.0
            Catch:
              - ErrorEquals:
                  - InventoryUnavailableException
                  - States.ALL
                ResultPath: "$.error"
                Next: OrderFailedState
            Next: ProcessPayment

          # --- State 2: Process Payment Task ---
          ProcessPayment:
            Type: Task
            Resource: arn:aws:states:::lambda:invoke
            Parameters:
              FunctionName: !GetAtt ProcessPaymentFunction.Arn
              Payload.$: "$"
            ResultSelector:
              paymentId.$: "$.Payload.paymentId"
              status.$: "$.Payload.status"
            ResultPath: "$.paymentResult"
            Retry:
              - ErrorEquals:
                  - Lambda.ServiceException
                  - Lambda.AWSLambdaException
                IntervalSeconds: 2
                MaxAttempts: 3
                BackoffRate: 2.0
            Catch:
              - ErrorEquals:
                  - PaymentDeclinedException
                  - States.ALL
                ResultPath: "$.error"
                Next: CompensateInventory
            Next: OrderSucceededState

          # --- State 3: Compensating Transaction (Rollback) ---
          CompensateInventory:
            Type: Task
            Resource: arn:aws:states:::lambda:invoke
            Parameters:
              FunctionName: !GetAtt CancelInventoryCompensateFunction.Arn
              Payload.$: "$"
            ResultPath: "$.compensationResult"
            Next: OrderRolledBackState

          # --- Terminal States ---
          OrderSucceededState:
            Type: Succeed

          OrderRolledBackState:
            Type: Fail
            Cause: "Payment authorization declined. Compensating inventory transactions completed."
            Error: "PaymentDeclinedAndCompensated"

          OrderFailedState:
            Type: Fail
            Cause: "Inventory reservation failed. Order aborted."
            Error: "InventoryUnavailable"

Outputs:
  OrderCheckoutStateMachineArn:
    Description: "Step Functions OrderCheckoutStateMachine ARN"
    Value: !Ref OrderCheckoutStateMachine
  ReserveInventoryFunctionArn:
    Description: "ReserveInventoryFunction ARN"
    Value: !GetAtt ReserveInventoryFunction.Arn
  ProcessPaymentFunctionArn:
    Description: "ProcessPaymentFunction ARN"
    Value: !GetAtt ProcessPaymentFunction.Arn
  CancelInventoryCompensateFunctionArn:
    Description: "CancelInventoryCompensateFunction ARN"
    Value: !GetAtt CancelInventoryCompensateFunction.Arn
```

## Deep-Dive Architectural Breakdown

### 1. The 5 JSONPath Processing Levers
Every Step Functions state processes data through five sequential JSONPath stages:

```text
Raw State Input ──>[ InputPath ]──>[ Parameters ]──>[ Task Execution ]
                                                              │
Next State Input <──[ OutputPath ]<──[ ResultPath ]<──[ ResultSelector ]
```

1. **`InputPath`**: Filters the raw state JSON before feeding it to the task. Defaults to `$` (passes full input).
2. **`Parameters`**: Constructs a custom JSON payload sent to the Lambda handler:
   ```json
   "Parameters": {
     "FunctionName": "arn:aws:lambda:...:function:ReserveInventoryFunction",
     "Payload.$": "$"
   }
   ```
   The `.$` suffix signals to Step Functions that the value is a JSONPath expression rather than a literal string.
3. **`ResultSelector`**: Filters the raw response returned by the task (e.g. Lambda metadata wrapper containing `Payload`, `ExecutedVersion`, `StatusCode`):
   ```json
   "ResultSelector": {
     "reservationId.$": "$.Payload.reservationId",
     "status.$": "$.Payload.status"
   }
   ```
4. **`ResultPath`**: **The Most Critical Field on the DVA-C02 Exam**. Determines where the task output is placed in the overall state JSON.
   * If you set `"ResultPath": "$.inventoryResult"`, the output is inserted into the `inventoryResult` key while preserving `orderId`, `customerId`, and `amount`.
   * ⚠️ **Exam Trap**: If you set `"ResultPath": "$"`, the task output completely overwrites the root state, obliterating all original order data!
5. **`OutputPath`**: Filters the combined state before handing it off to the next state.

---

### 2. The Exponential Backoff Retry Pattern
```yaml
Retry:
  - ErrorEquals:
      - Lambda.ServiceException
      - Lambda.AWSLambdaException
      - States.TaskFailed
    IntervalSeconds: 2
    MaxAttempts: 2
    BackoffRate: 2.0
```

* **`IntervalSeconds: 2`**: Waits 2 seconds before the first retry attempt.
* **`BackoffRate: 2.0`**: Multiplies the wait time by 2 on each subsequent retry ($2\text{s} \to 4\text{s}$).
* **`MaxAttempts: 2`**: Retries at most twice before declaring task failure.

---

### 3. Catch Blocks & Automated Compensating Rollbacks
```yaml
Catch:
  - ErrorEquals:
      - PaymentDeclinedException
      - States.ALL
    ResultPath: "$.error"
    Next: CompensateInventory
```

* **Targeted Error Catching**: When `ProcessPaymentFunction` throws `PaymentDeclinedException`, Step Functions catches it immediately (bypassing retries, because credit card declines should never be retried automatically).
* **Safe Error Storage**: `"ResultPath": "$.error"` appends the error details (stack trace, error message) under `$.error` without destroying the order state.
* **Compensating Route**: The execution transitions to `CompensateInventory`, which calls `CancelInventoryCompensateFunction` to release the warehouse stock!
