## Narrative Bridge: Running the Saga in the Real Cloud

In [Lecture 03.04](./03.04-provisioning-step-functions-asl-sam.md), we defined the state machine graph in our declarative SAM template with retry backoff and catch handlers.

Now, let's deploy the stack to AWS and drive live executions through the AWS CLI. You will execute two real-world operational scenarios:
1. **The Happy Path**: A normal order where inventory is reserved, payment succeeds, and the saga completes with status `SUCCEEDED`.
2. **The Compensating Rollback**: An order with `failPayment: true` that triggers a credit card decline, activating the `Catch` block and invoking `CancelInventoryCompensateFunction` to release the warehouse reservation.

---

## Exercise 1: Build & Deploy the State Machine Stack

Navigate to the Module 03 directory:

```bash
cd reference/cloudorder/backend/module-03-step-functions
mvn clean package -DskipTests
sam build
sam deploy --guided
```

When prompted:
* **Stack Name**: `cloudorder-module-03`
* **AWS Region**: `us-east-1` (or your preferred region)
* **Allow SAM CLI IAM role creation**: `Y`

Once deployment finishes, capture the `OrderCheckoutStateMachineArn` output:
```text
OrderCheckoutStateMachineArn = arn:aws:states:us-east-1:123456789012:stateMachine:CloudOrderCheckoutSaga
```

---

## Exercise 2: Execute the Happy Path Workflow

Start an execution for a standard valid order:

```bash
aws stepfunctions start-execution \
  --state-machine-arn "<OrderCheckoutStateMachineArn>" \
  --name "cli-happy-order-101" \
  --input '{
    "orderId": "ORD-CLI-101",
    "customerId": "alice@example.com",
    "amount": 149.99,
    "items": ["LAPTOP-SLEEVE", "USB-C-CABLE"]
  }'
```

### Inspect the Execution:
Poll the execution status using the ARN returned from the previous command:

```bash
aws stepfunctions describe-execution \
  --execution-arn "<ExecutionArn>"
```

### Verification Criteria:
1. `"status"` changes from `"RUNNING"` to `"SUCCEEDED"`.
2. The `"output"` JSON contains both `inventoryResult` and `paymentResult`:
   ```json
   {
     "orderId": "ORD-CLI-101",
     "inventoryResult": {
       "reservationId": "RES-...",
       "status": "INVENTORY_RESERVED"
     },
     "paymentResult": {
       "paymentId": "PAY-...",
       "status": "PAYMENT_COMPLETED"
     }
   }
   ```

## Exercise 3: Trigger the Compensating Saga Rollback

Now simulate an order where the customer's credit card fails authorization:

```bash
aws stepfunctions start-execution \
  --state-machine-arn "<OrderCheckoutStateMachineArn>" \
  --name "cli-failed-order-202" \
  --input '{
    "orderId": "ORD-CLI-202",
    "customerId": "bob@example.com",
    "amount": 899.00,
    "items": ["SMARTPHONE"],
    "failPayment": true
  }'
```

### Inspect the Failure Execution:
```bash
aws stepfunctions describe-execution \
  --execution-arn "<FailedExecutionArn>"
```

### Verification Criteria:
1. `"status"` transitions to `"FAILED"`.
2. `"error"` is `"PaymentDeclinedAndCompensated"`.
3. Retrieve the full event history to confirm the compensating transaction ran:
   ```bash
   aws stepfunctions get-execution-history \
     --execution-arn "<FailedExecutionArn>" \
     --max-items 30
   ```
4. Look for the `TaskSucceeded` event for `CancelInventoryCompensateFunction`. The inventory was successfully unreserved!
