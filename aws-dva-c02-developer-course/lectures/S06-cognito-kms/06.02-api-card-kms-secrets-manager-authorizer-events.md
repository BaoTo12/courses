## 1. AWS SDK for Java v2: `KmsClient`

### 1.1 Generating a Data Encryption Key (DEK)

```java
import software.amazon.awssdk.core.SdkBytes;
import software.amazon.awssdk.services.kms.KmsClient;
import software.amazon.awssdk.services.kms.model.DataKeySpec;
import software.amazon.awssdk.services.kms.model.GenerateDataKeyRequest;
import software.amazon.awssdk.services.kms.model.GenerateDataKeyResponse;

import java.util.Map;

public class KmsKeyHelper {

    public static GenerateDataKeyResponse generateDek(KmsClient kmsClient, String keyId, String orderId) {
        GenerateDataKeyRequest request = GenerateDataKeyRequest.builder()
                .keyId(keyId) // Key ID, Key ARN, or Alias (alias/cloudorder-payment-key)
                .keySpec(DataKeySpec.AES_256) // Requests a 256-bit AES key
                // Encryption Context: Non-secret AAD (Additional Authenticated Data)
                .encryptionContext(Map.of(
                        "service", "cloudorder-payment",
                        "orderId", orderId
                ))
                .build();

        return kmsClient.generateDataKey(request);
    }
}
```

### 1.2 The Role of Encryption Context in AWS KMS
The `encryptionContext` is a map of key-value pairs that provides **Additional Authenticated Data (AAD)**:
* It is not encrypted, but it is cryptographically bound to the ciphertext.
* **Integrity Guard**: When decrypting the DEK, you **must supply the exact same encryption context**. If an attacker tampers with the context (e.g. changing `orderId: ord-101` to `ord-102`), KMS fails with `InvalidCiphertextException`.
* **Audit Trail**: The encryption context is logged in plain text in **AWS CloudTrail**, allowing security teams to audit exactly which order triggered which KMS decrypt request.

## 2. AWS SDK for Java v2: `SecretsManagerClient`

### 2.1 Fetching Secrets with Version Stages

```java
import software.amazon.awssdk.services.secretsmanager.SecretsManagerClient;
import software.amazon.awssdk.services.secretsmanager.model.GetSecretValueRequest;
import software.amazon.awssdk.services.secretsmanager.model.GetSecretValueResponse;

public class SecretsHelper {

    public static String fetchSecret(SecretsManagerClient client, String secretId) {
        GetSecretValueRequest request = GetSecretValueRequest.builder()
                .secretId(secretId)
                .versionStage("AWSCURRENT") // Defaults to AWSCURRENT
                .build();

        GetSecretValueResponse response = client.getSecretValue(request);
        return response.secretString();
    }
}
```

### Secrets Manager Version Stages:
* `AWSCURRENT`: The active production secret value in use.
* `AWSPENDING`: The new secret value generated during an active rotation in progress.
* `AWSPREVIOUS`: The previous secret value preserved for rollback if rotation fails.

## 3. Amazon API Gateway Custom Authorizer Schema

An API Gateway Lambda Authorizer must return an IAM Policy document:

```json
{
  "principalId": "user-sub-12345",
  "policyDocument": {
    "Version": "2012-10-17",
    "Statement": [
      {
        "Action": "execute-api:Invoke",
        "Effect": "Allow",
        "Resource": "arn:aws:execute-api:us-east-1:123456789012:api-123/prod/POST/orders/checkout"
      }
    ]
  },
  "context": {
    "customerId": "cust-9001",
    "role": "CUSTOMER"
  }
}
```

### Critical API Gateway Authorizer Mechanics:
1. **`principalId`**: String identifying the user in API Gateway access logs (`$context.authorizer.principalId`).
2. **`context` Map**: Key-value pairs containing string, number, or boolean values. These are injected into downstream Lambda integration events under `$event.requestContext.authorizer`.
3. **Policy Caching Invariant**:
   * API Gateway caches authorizer responses by default for **300 seconds** (configurable up to 3600s) keyed by the token or header.
   * If your authorizer issues an IAM policy restricting `Resource` to only `.../POST/orders/checkout`, and the same user then attempts `GET /orders`, API Gateway uses the cached policy, which denies `GET`, returning an unexpected `HTTP 403 Forbidden`!
   * **Fix**: To allow caching across multiple endpoints, wildcard the resource: `arn:aws:execute-api:us-east-1:123456789012:api-123/prod/*/*`.
