## Lab Objective

In this hands-on lab, you will:
1. Provision a test user with custom attributes in the Cognito User Pool via the AWS CLI.
2. Perform user authentication to receive an Access Token and an ID Token.
3. Parse and inspect the RS256 JWT claims using command-line tools.
4. Execute `CognitoAuthorizerFunction` to assert that valid tokens generate an `Allow` IAM policy and that tampered or expired tokens generate a `Deny` policy.

## Task 1: Register & Confirm a Test User in Cognito

Retrieve the User Pool ID and Client ID from your SAM deployment outputs:

```bash
USER_POOL_ID=$(aws cloudformation describe-stacks \
  --stack-name cloudorder-auth-security \
  --query "Stacks[0].Outputs[?OutputKey=='UserPoolId'].OutputValue" \
  --output text)

CLIENT_ID=$(aws cloudformation describe-stacks \
  --stack-name cloudorder-auth-security \
  --query "Stacks[0].Outputs[?OutputKey=='UserPoolClientId'].OutputValue" \
  --output text)

echo "User Pool: $USER_POOL_ID | App Client: $CLIENT_ID"
```

### 1.1 Sign Up a New User
```bash
aws cognito-idp sign-up \
  --client-id "$CLIENT_ID" \
  --username "developer@cloudorder.com" \
  --password "SecureCloudOrder2026!" \
  --user-attributes \
      Name=email,Value="developer@cloudorder.com" \
      Name="custom:customerId",Value="cust-7777" \
      Name="custom:role",Value="ENGINEER"
```

### 1.2 Administratively Confirm the User
Bypass email verification for local testing:
```bash
aws cognito-idp admin-confirm-sign-up \
  --user-pool-id "$USER_POOL_ID" \
  --username "developer@cloudorder.com"
```

## Task 2: Authenticate & Extract RS256 JWTs

Initiate authentication flow (`USER_PASSWORD_AUTH`) to obtain credentials:

```bash
AUTH_RESPONSE=$(aws cognito-idp initiate-auth \
  --client-id "$CLIENT_ID" \
  --auth-flow USER_PASSWORD_AUTH \
  --auth-parameters USERNAME="developer@cloudorder.com",PASSWORD="SecureCloudOrder2026!")

# Extract Access Token and ID Token
ACCESS_TOKEN=$(echo "$AUTH_RESPONSE" | jq -r '.AuthenticationResult.AccessToken')
ID_TOKEN=$(echo "$AUTH_RESPONSE" | jq -r '.AuthenticationResult.IdToken')

echo "Access Token: ${ACCESS_TOKEN:0:50}..."
echo "ID Token: ${ID_TOKEN:0:50}..."
```

### 2.1 Inspect JWT Claims
Decode the payload segment (the second base64-encoded part) of the Access Token:
```bash
echo "$ACCESS_TOKEN" | cut -d '.' -f 2 | base64 --decode 2>/dev/null | jq .
```

Verify that the decoded JSON contains:
* `"token_use": "access"`
* `"client_id": "$CLIENT_ID"`
* `"iss": "https://cognito-idp.us-east-1.amazonaws.com/$USER_POOL_ID"`

## Task 3: Invoke the Lambda Token Authorizer

Test the authorizer directly by invoking `CognitoAuthorizerFunction`:

### 3.1 Valid Token Test
```bash
aws lambda invoke \
  --function-name cloudorder-token-authorizer-prod \
  --cli-binary-format raw-in-base64-out \
  --payload '{
    "type": "TOKEN",
    "authorizationToken": "Bearer '"$ACCESS_TOKEN"'",
    "methodArn": "arn:aws:execute-api:us-east-1:123456789012:api-123/prod/POST/orders"
  }' \
  authorizer-response.json

cat authorizer-response.json | jq .
```

✅ **Expected Result**:
```json
{
  "principalId": "09a1b2c3-44dd-...",
  "policyDocument": {
    "Version": "2012-10-17",
    "Statement": [
      {
        "Action": "execute-api:Invoke",
        "Effect": "Allow",
        "Resource": "arn:aws:execute-api:us-east-1:123456789012:api-123/prod/POST/orders"
      }
    ]
  },
  "context": {
    "role": "ENGINEER",
    "customerId": "cust-7777"
  }
}
```

### 3.2 Tampered Token Test
Corrupt the last 10 characters of the signature and invoke again:
```bash
TAMPERED_TOKEN="${ACCESS_TOKEN:0:-10}XXXXXXXXXX"

aws lambda invoke \
  --function-name cloudorder-token-authorizer-prod \
  --cli-binary-format raw-in-base64-out \
  --payload '{
    "type": "TOKEN",
    "authorizationToken": "Bearer '"$TAMPERED_TOKEN"'",
    "methodArn": "arn:aws:execute-api:us-east-1:123456789012:api-123/prod/POST/orders"
  }' \
  tampered-response.json

cat tampered-response.json | jq .
```

✅ **Expected Result**:
```json
{
  "principalId": "anonymous",
  "policyDocument": {
    "Version": "2012-10-17",
    "Statement": [
      {
        "Action": "execute-api:Invoke",
        "Effect": "Deny",
        "Resource": "arn:aws:execute-api:us-east-1:123456789012:api-123/prod/POST/orders"
      }
    ]
  }
}
```
