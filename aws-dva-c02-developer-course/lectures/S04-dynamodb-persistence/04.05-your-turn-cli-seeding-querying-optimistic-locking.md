In [Lecture 04.04](./04.04-provisioning-dynamodb-sam-template.md), we defined our declarative SAM template with GSI1 overloading, TTL, and DynamoDB Streams.

Now, it is your turn to deploy the infrastructure and execute real operations from the AWS CLI:
1. Seed multi-entity records (customer profiles and customer orders) into the single table.
2. Execute a composite key range query using `begins_with(SK, "ORDER#")` to fetch all orders for a customer in a single round-trip.
3. Query the `GSI1` index across all customers to find pending orders.
4. Intentionally provoke a `ConditionalCheckFailedException` by executing conflicting optimistic locking updates.

## Exercise 2: Seed Multi-Entity Records

Insert a customer profile record:
```bash
aws dynamodb put-item \
  --table-name CloudOrderTable \
  --item '{
    "PK": {"S": "CUST#cust-101"},
    "SK": {"S": "METADATA"},
    "name": {"S": "Alice Johnson"},
    "email": {"S": "alice@example.com"},
    "tier": {"S": "GOLD"}
  }'
```

Insert two orders for Customer 101:
```bash
aws dynamodb put-item \
  --table-name CloudOrderTable \
  --item '{
    "PK": {"S": "CUST#cust-101"},
    "SK": {"S": "ORDER#ord-5001"},
    "GSI1PK": {"S": "STATUS#PENDING"},
    "GSI1SK": {"S": "DATE#2026-09-27T08:00:00Z"},
    "orderId": {"S": "ord-5001"},
    "customerId": {"S": "cust-101"},
    "amount": {"N": "149.99"},
    "status": {"S": "PENDING"},
    "version": {"N": "1"},
    "createdAt": {"S": "2026-09-27T08:00:00Z"}
  }'

aws dynamodb put-item \
  --table-name CloudOrderTable \
  --item '{
    "PK": {"S": "CUST#cust-101"},
    "SK": {"S": "ORDER#ord-5002"},
    "GSI1PK": {"S": "STATUS#COMPLETED"},
```

## Exercise 3: Querying the Single Table

### Query 1: Fetch All Orders for Customer 101
```bash
aws dynamodb query \
  --table-name CloudOrderTable \
  --key-condition-expression "PK = :pk AND begins_with(SK, :skPrefix)" \
  --expression-attribute-values '{
    ":pk": {"S": "CUST#cust-101"},
    ":skPrefix": {"S": "ORDER#"}
  }'
```
**Observation**: Both `ord-5001` and `ord-5002` are returned, while the `METADATA` profile row is filtered out on the partition!

### Query 2: Query Across All Customers via GSI1
Find all orders across the entire database with status `PENDING`:
```bash
aws dynamodb query \
  --table-name CloudOrderTable \
  --index-name GSI1 \
  --key-condition-expression "GSI1PK = :gsi1pk" \
  --expression-attribute-values '{
    ":gsi1pk": {"S": "STATUS#PENDING"}
  }'
```
**Observation**: Instant indexed lookup with zero full-table scans!

## Exercise 4: Simulating Optimistic Locking Collision

Now execute two concurrent update requests simulating two workers competing to update `ord-5001`.

### Worker 1: Updates order with expected version = 1 (Succeeds!)
```bash
aws dynamodb update-item \
  --table-name CloudOrderTable \
  --key '{"PK": {"S": "CUST#cust-101"}, "SK": {"S": "ORDER#ord-5001"}}' \
  --update-expression "SET #s = :newStatus, #v = :newVersion, #g = :newGsi" \
  --condition-expression "attribute_exists(PK) AND #v = :expectedVersion" \
  --expression-attribute-names '{"#s": "status", "#v": "version", "#g": "GSI1PK"}' \
  --expression-attribute-values '{
    ":newStatus": {"S": "PROCESSING"},
    ":newVersion": {"N": "2"},
    ":newGsi": {"S": "STATUS#PROCESSING"},
    ":expectedVersion": {"N": "1"}
  }'
```
*Result*: Succeeded! The order's version in DynamoDB is now **2**.

### Worker 2: Outdated worker attempts to update assuming version is still 1 (Fails!)
Run the exact same command a second time:

*Result*:
```text
An error occurred (ConditionalCheckFailedException) when calling the UpdateItem operation: The conditional request failed
```

DynamoDB rejected Worker 2's write because `#v = :expectedVersion` (`2 = 1`) evaluated to false. The update was atomically blocked, preventing a lost update!
