## Narrative Bridge: Declarative DynamoDB Infrastructure

In [Lecture 04.03](./04.03-build-single-table-repository-optimistic-locking.md), we built and verified our Java 21 repository with optimistic locking and CDC stream processing.

Now, we define the cloud infrastructure in AWS SAM. Provisioning a production DynamoDB table requires key architectural decisions:
1. **Capacity Mode**: Choosing between On-Demand (`PAY_PER_REQUEST`) and `PROVISIONED` with Auto-Scaling.
2. **Index Projections**: Configuring Global Secondary Index (`GSI1`) projections (`ALL`, `KEYS_ONLY`, or `INCLUDE`) to balance query flexibility against storage and write amplification costs.
3. **Change Data Capture**: Enabling DynamoDB Streams (`StreamViewType: NEW_AND_OLD_IMAGES`) to allow real-time downstream processing.
4. **Data Lifecycle**: Turning on Time to Live (TTL) on the `ttl` attribute so expired sessions or temporary orders delete automatically with **zero consumed Write Capacity Units**.
5. **Stream Failure Isolation**: Registering `BisectBatchOnFunctionError: true` on the Lambda event source mapping so poisoned stream records do not block the shard.

Here is the complete declarative SAM template.

## The Complete SAM Infrastructure Template

✍️ `template.yaml`

```yaml
AWSTemplateFormatVersion: '2010-09-09'
Transform: AWS::Serverless-2016-10-31
Description: >
  CloudOrder Module 4: DynamoDB Single-Table Design, GSI Overloading, and CDC Streams.
  Demonstrating composite primary keys (PK/SK), Global Secondary Indexes (GSI1PK/GSI1SK),
  TimeToLive (TTL), Point-In-Time Recovery (PITR), DynamoDB Streams with batch bisection,
  and raw JSON IAM execution roles.

Globals:
  Function:
    Timeout: 30
    MemorySize: 1769 # Exactly 1 full vCPU allocated to Java 21 JVM
    Runtime: java21
    Architectures:
      - x86_64
    Environment:
      Variables:
        STAGE: Prod
        LOG_LEVEL: INFO
        TABLE_NAME: !Ref CloudOrderTable

Resources:
  # ============================================================================
  # 1. DynamoDB Single-Table Design
  # ============================================================================
  CloudOrderTable:
    Type: AWS::DynamoDB::Table
    Properties:
      TableName: CloudOrderTable
      BillingMode: PAY_PER_REQUEST # On-Demand capacity for burst workloads
      AttributeDefinitions:
        - AttributeName: PK
          AttributeType: S
        - AttributeName: SK
          AttributeType: S
        - AttributeName: GSI1PK
          AttributeType: S
        - AttributeName: GSI1SK
          AttributeType: S
      KeySchema:
        - AttributeName: PK
          KeyType: HASH
        - AttributeName: SK
          KeyType: RANGE
      GlobalSecondaryIndexes:
        - IndexName: GSI1
          KeySchema:
            - AttributeName: GSI1PK
              KeyType: HASH
            - AttributeName: GSI1SK
              KeyType: RANGE
          Projection:
            ProjectionType: ALL
      StreamSpecification:
        StreamViewType: NEW_AND_OLD_IMAGES # Full before-and-after CDC state
      PointInTimeRecoverySpecification:
        PointInTimeRecoveryEnabled: true
      TimeToLiveSpecification:
        AttributeName: ttl
        Enabled: true

  # ============================================================================
  # 2. Raw JSON IAM Execution Role for DynamoDB Streams Consumer
  # ============================================================================
  OrderStreamProcessorFunctionRole:
    Type: AWS::IAM::Role
    Properties:
      AssumeRolePolicyDocument:
        Version: '2012-10-17'
        Statement:
          - Effect: Allow
            Principal:
              Service:
                - lambda.amazonaws.com
            Action:
              - sts:AssumeRole
      Policies:
        - PolicyName: CloudOrderExplicitLoggingPolicy
          PolicyDocument:
            Version: '2012-10-17'
            Statement:
              - Effect: Allow
                Action:
                  - logs:CreateLogGroup
                  - logs:CreateLogStream
                  - logs:PutLogEvents
                Resource: !Sub 'arn:aws:logs:${AWS::Region}:${AWS::AccountId}:log-group:/aws/lambda/*:*'
        - PolicyName: CloudOrderExplicitDynamoDBStreamPolicy
          PolicyDocument:
            Version: '2012-10-17'
            Statement:
              - Effect: Allow
                Action:
                  - dynamodb:DescribeStream
                  - dynamodb:GetRecords
                  - dynamodb:GetShardIterator
                  - dynamodb:ListStreams
                Resource: !GetAtt CloudOrderTable.StreamArn

  # ============================================================================
  # 3. Serverless Lambda Stream Consumer (Change Data Capture)
  # ============================================================================
  OrderStreamProcessorFunction:
    Type: AWS::Serverless::Function
    Properties:
      CodeUri: .
      Handler: com.cloudarchitect.dvac02.persistence.stream.OrderStreamProcessor::handleRequest
      Role: !GetAtt OrderStreamProcessorFunctionRole.Arn
      Events:
        OrderTableStream:
          Type: DynamoDB
          Properties:
            Stream: !GetAtt CloudOrderTable.StreamArn
            StartingPosition: TRIM_HORIZON
            BatchSize: 100
            MaximumBatchingWindowInSeconds: 5
            BisectBatchOnFunctionError: true # ⚡ Isolates poison pill records in CDC stream
            RetryAttempts: 3

Outputs:
  CloudOrderTableName:
    Description: "DynamoDB CloudOrderTable Name"
    Value: !Ref CloudOrderTable
  CloudOrderTableArn:
    Description: "DynamoDB CloudOrderTable ARN"
    Value: !GetAtt CloudOrderTable.Arn
  CloudOrderTableStreamArn:
    Description: "DynamoDB Streams ARN"
    Value: !GetAtt CloudOrderTable.StreamArn
  OrderStreamProcessorFunctionArn:
    Description: "OrderStreamProcessor Lambda Function ARN"
    Value: !GetAtt OrderStreamProcessorFunction.Arn
```

## Deep-Dive Architectural Breakdown

### 1. Primary Key Schema & GSI Overloading
```yaml
KeySchema:
  - AttributeName: PK
    KeyType: HASH
  - AttributeName: SK
    KeyType: RANGE
GlobalSecondaryIndexes:
  - IndexName: GSI1
    KeySchema:
      - AttributeName: GSI1PK
        KeyType: HASH
      - AttributeName: GSI1SK
        KeyType: RANGE
    Projection:
      ProjectionType: ALL
```

* **Composite Primary Key**: `PK` partitions data across the storage nodes; `SK` sorts items physically on the partition. This allows us to fetch a customer and all their orders in a single `Query` call using `begins_with(SK, "ORDER#")`.
* **GSI Index Projections**:
  * `ALL`: Projects all item attributes into the index. Fast queries with zero table fetch overhead, but doubles write costs and storage.
  * `KEYS_ONLY`: Projects only the primary and index keys. Minimizes index write cost, but requires a secondary `GetItem` call back to the main table if other attributes are needed.
  * `INCLUDE`: Projects a specified subset of attributes. The optimal production compromise.

---

### 2. Time to Live (TTL) Mechanics
```yaml
TimeToLiveSpecification:
  AttributeName: ttl
  Enabled: true
```

* **Zero WCU Consumption**: When DynamoDB expires and purges an item whose `ttl` timestamp is in the past, **it does not consume Write Capacity Units**.
* **Purge Timing**: TTL purges items in the background typically within 48 hours of expiration. Expired items are also emitted to DynamoDB Streams with `principalId: "dynamodb.amazonaws.com"`.

---

### 3. DynamoDB Streams & Shard Bisection
```yaml
Events:
  OrderTableStream:
    Type: DynamoDB
    Properties:
      Stream: !GetAtt CloudOrderTable.StreamArn
      StartingPosition: TRIM_HORIZON
      BatchSize: 100
      BisectBatchOnFunctionError: true # ⚡ The Poison Pill Isolator
      RetryAttempts: 3
```

* **`StreamViewType: NEW_AND_OLD_IMAGES`**: Emits both the previous image of the item and the modified image, enabling our Java stream processor to calculate status deltas (`PENDING -> CONFIRMED`).
* **`StartingPosition: TRIM_HORIZON`**: Reads from the oldest available records in the shard (up to 24 hours of stream retention).
* **`BisectBatchOnFunctionError: true`**: **High-Yield Exam Invariant**. If a batch of 100 records encounters an unhandled exception, Lambda automatically splits the batch in half (50 and 50) and retries each subset independently, isolating the single bad record without stalling the shard!
