## 📇 Card 2: `QueryRequest` & Key Condition Grammar

A `Query` finds items based on primary key values. It is the core access method in single-table design.

```java
QueryRequest request = QueryRequest.builder()
    .tableName("CloudOrderTable")
    .keyConditionExpression("PK = :pk AND begins_with(SK, :skPrefix)")
    .expressionAttributeValues(Map.of(
        ":pk", AttributeValue.fromS("CUST#cust-101"),
        ":skPrefix", AttributeValue.fromS("ORDER#")
    ))
    .consistentRead(true) // Strongly consistent read
    .build();

QueryResponse response = dynamoDbClient.query(request);
```

### Key Condition Rules on DVA-C02:
1. **Partition Key Requirement**: The partition key MUST use the equality operator (`=`). You cannot use `>`, `<`, `begins_with`, or `contains` on the partition key!
2. **Sort Key Operators**: The sort key can use `=`, `<`, `<=`, `>`, `>=`, `BETWEEN`, or `begins_with()`.
3. **`FilterExpression` vs. `KeyConditionExpression` Trap**:
   * `KeyConditionExpression` narrows the items read from the SSD partition, consuming minimal RCUs.
   * `FilterExpression` applies **AFTER** the query reads the data from disk. It filters out items from the response, but **you still pay the full RCU cost for reading them from storage**!

## 📇 Card 3: Optimistic Locking with Conditional Expressions

In distributed systems, two worker threads might read version 1 of an order and both attempt to transition it to a new state. Without locking, the second write silently overwrites the first (the **Lost Update** problem).

### The Atomic Conditional Update Pattern:
```java
UpdateItemRequest request = UpdateItemRequest.builder()
    .tableName("CloudOrderTable")
    .key(Map.of(
        "PK", AttributeValue.fromS("CUST#cust-101"),
        "SK", AttributeValue.fromS("ORDER#ord-5001")
    ))
    .updateExpression("SET #status = :newStatus, #version = :newVersion")
    .conditionExpression("attribute_exists(PK) AND #version = :expectedVersion")
    .expressionAttributeNames(Map.of(
        "#status", "status",   // ⚡ Avoids reserved keyword collision!
        "#version", "version"
    ))
    .expressionAttributeValues(Map.of(
        ":newStatus", AttributeValue.fromS("COMPLETED"),
        ":newVersion", AttributeValue.fromN("2"),
        ":expectedVersion", AttributeValue.fromN("1")
    ))
    .build();

try {
    dynamoDbClient.updateItem(request);
} catch (ConditionalCheckFailedException e) {
    // ⚡ Another worker already updated the item! Handle concurrency conflict.
    throw new ConcurrentModificationException("Order was modified concurrently. Retry with fresh version.");
}
```

## 📇 Card 4: Handling `UnprocessedItems` in Batch Operations

`BatchWriteItem` puts or deletes up to **25 items** (max 16 MB total) in a single API call.

> [!WARNING]
> **DVA-C02 Exam Invariant: Partial Batch Failures**:
> If DynamoDB lacks capacity to process all items in a batch write, the API **does NOT fail with an exception**. It returns HTTP 200 OK and returns the throttled items in the `unprocessedItems()` map!
> 
> ```java
> BatchWriteItemResponse response = dynamoDbClient.batchWriteItem(batchRequest);
> 
> // Must check for unprocessed items and retry with exponential backoff!
> while (response.hasUnprocessedItems() && !response.unprocessedItems().isEmpty()) {
>     Thread.sleep(calculateExponentialBackoff(retryCount));
>     batchRequest = BatchWriteItemRequest.builder()
>         .requestItems(response.unprocessedItems())
>         .build();
>     response = dynamoDbClient.batchWriteItem(batchRequest);
> }
> ```

## 📇 Card 5: The Reserved Keyword Trap

DynamoDB has hundreds of reserved keywords, including:
`status`, `year`, `name`, `date`, `percent`, `value`, `connection`, `timestamp`.

If you write:
```text
UpdateExpression: "SET status = :s"  <-- ❌ Throws ValidationException: Syntax error!
```
You **must** use an `ExpressionAttributeNames` placeholder:
```text
UpdateExpression: "SET #status = :s"
ExpressionAttributeNames: { "#status": "status" }  <-- ✅ Valid!
```
