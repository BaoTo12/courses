## Lab Objective

In this hands-on lab, you will step into the shoes of a CloudOrder platform engineer. You will verify:
1. Generating a presigned PUT URL and uploading a sample invoice PDF directly to S3 with strict Content-Type enforcement.
2. Generating a presigned GET URL and downloading the encrypted invoice directly from S3.
3. Connecting to ElastiCache Redis to inspect cached keys, query values, and observe real-time TTL decay.
4. Uploading an invoice to trigger `S3InvoiceNotificationFunction` and proving cache eviction via `redis-cli`.

## Task 1: Generate & Execute S3 Presigned URLs via AWS CLI

First, determine your provisioned S3 bucket name from SAM outputs:
```bash
BUCKET_NAME=$(aws cloudformation describe-stacks \
  --stack-name cloudorder-s3-caching \
  --query "Stacks[0].Outputs[?OutputKey=='InvoicesBucketName'].OutputValue" \
  --output text)

echo "Target Bucket: $BUCKET_NAME"
```

### 1.1 Generate a Presigned Download URL
Generate an pre-signed GET URL valid for 15 minutes (900 seconds):
```bash
DOWNLOAD_URL=$(aws s3 presign "s3://${BUCKET_NAME}/invoices/2026/09/invoice-ord-5001.pdf" --expires-in 900)
echo "Generated Presigned GET URL: $DOWNLOAD_URL"
```

Inspect the output. Notice the query parameters:
* `X-Amz-Expires=900`
* `X-Amz-Signature=...`

### 1.2 Generate a Sample Invoice and Upload via Presigned PUT
Create a mock PDF file locally:
```bash
echo "%PDF-1.4 Mock Invoice for Order ord-5001" > invoice-ord-5001.pdf
```

Generate a presigned PUT URL using the AWS CLI:
```bash
# Note: AWS CLI 's3 presign' defaults to GET. For PUT, our Java 21 InvoiceStorageService creates PUT presigned URLs.
# To test PUT directly via CLI, use the AWS CLI S3API:
aws s3 cp invoice-ord-5001.pdf "s3://${BUCKET_NAME}/invoices/2026/09/invoice-ord-5001.pdf" \
  --metadata "order-id=ord-5001,customer-id=cust-101"
```

Now, download the invoice using the presigned GET URL with `curl`:
```bash
curl -v "$DOWNLOAD_URL" -o retrieved-invoice.pdf
cat retrieved-invoice.pdf
```
✅ **Checkpoint**: You should see `%PDF-1.4 Mock Invoice for Order ord-5001` without providing AWS credentials to `curl`.

## Task 2: Inspect Keys & TTL in ElastiCache Redis

Retrieve the Redis endpoint address from SAM stack outputs:
```bash
REDIS_HOST=$(aws cloudformation describe-stacks \
  --stack-name cloudorder-s3-caching \
  --query "Stacks[0].Outputs[?OutputKey=='RedisEndpoint'].OutputValue" \
  --output text)

echo "Redis Cluster Endpoint: $REDIS_HOST"
```

### 2.1 Connect to Redis inside the VPC
Because ElastiCache Redis is located in private subnets, connect from an EC2 bastion, Cloud9 environment, or SSM Session Manager instance in the VPC:

```bash
redis-cli -h "$REDIS_HOST" -p 6379
```

### 2.2 Populate a Test Order Cache Entry with 120s TTL
Inside `redis-cli`:
```redis
# Write a cached order with 120 second TTL
SETEX order:ord-5001 120 '{"orderId":"ord-5001","customerId":"cust-101","totalAmount":199.99,"status":"PENDING"}'

# Read back immediately (Sub-millisecond)
GET order:ord-5001

# Inspect remaining TTL in seconds
TTL order:ord-5001
```

Observe the `TTL` output counting down: `119`, `115`, `108`... When it hits `0`, Redis automatically reclaims the memory and returns `(nil)`.

## Task 3: Trigger S3 Event Notification & Verify Automated Cache Eviction

Now, test automated cache eviction:
1. Re-populate the cache entry in Redis:
   ```redis
   SETEX order:ord-5001 300 '{"orderId":"ord-5001","customerId":"cust-101","totalAmount":199.99,"status":"PENDING"}'
   GET order:ord-5001
   ```
2. In a separate terminal, upload an invoice PDF for order `ord-5001` to S3:
   ```bash
   aws s3 cp invoice-ord-5001.pdf "s3://${BUCKET_NAME}/invoices/2026/09/invoice-ord-5001.pdf"
   ```
3. Watch the Lambda CloudWatch Logs:
   ```bash
   aws logs tail /aws/lambda/cloudorder-s3-invoice-consumer-prod --follow
   ```
   You will observe:
   ```text
   [S3-EVENT] Event: ObjectCreated:Put | Key: invoices/2026/09/invoice-ord-5001.pdf
   [S3-EVENT] Ingested invoice for orderId: ord-5001
   [S3-EVENT-CACHE] Evicted cached order: ord-5001
   ```
4. Back in `redis-cli`, immediately execute:
   ```redis
   GET order:ord-5001
   ```
   **Result**: `(nil)`! The S3 Event Notification Lambda executed the eviction, ensuring the next customer read will fetch fresh data from the database.
