## Narrative Bridge: Implementing the Saga Participants

In [Lecture 03.02](./03.02-api-card-sfn-client-asl-jsonpath.md), we studied the Amazon States Language (ASL) and the `SfnClient.startExecution()` contract. Now, we will implement the Java 21 components that act as participants in our **CloudOrder Checkout Saga**:

1. **`OrderCheckoutState` (Domain State)**: The shared JSON state passed from task to task across the state machine.
2. **`ReserveInventoryHandler` (Forward Task 1)**: Reserves stock in the warehouse. If items are out of stock, throws `InventoryUnavailableException`.
3. **`ProcessPaymentHandler` (Forward Task 2)**: Authorizes credit card charges. If the card is declined or the `failPayment` trigger is active, throws `PaymentDeclinedException`.
4. **`CancelInventoryCompensateHandler` (Compensating Task)**: The undo action! If payment declines, Step Functions catches the exception and executes this handler to release reserved stock.
5. **`OrderCheckoutService` (Client Trigger)**: Invokes `sfnClient.startExecution()` with idempotent execution names (`"order-exec-" + orderId`).

### Architectural Highlight:
* **Execution Name Idempotency**: Passing `.name("order-exec-" + state.getOrderId())` guarantees that if a network retry invokes `startExecution()` twice for the same order, Step Functions returns the existing execution ARN rather than starting a duplicate workflow run!
