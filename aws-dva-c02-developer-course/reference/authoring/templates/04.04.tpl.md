## Narrative Bridge: Declarative DynamoDB Infrastructure

In [Lecture 04.03](./04.03-build-single-table-repository-optimistic-locking.md), we built and verified our Java 21 repository with optimistic locking and CDC stream processing.

Now, we define the cloud infrastructure in AWS SAM. Provisioning a production DynamoDB table requires key architectural decisions:
1. **Capacity Mode**: Choosing between On-Demand (`PAY_PER_REQUEST`) and `PROVISIONED` with Auto-Scaling.
2. **Index Projections**: Configuring Global Secondary Index (`GSI1`) projections (`ALL`, `KEYS_ONLY`, or `INCLUDE`) to balance query flexibility against storage and write amplification costs.
3. **Change Data Capture**: Enabling DynamoDB Streams (`StreamViewType: NEW_AND_OLD_IMAGES`) to allow real-time downstream processing.
4. **Data Lifecycle**: Turning on Time to Live (TTL) on the `ttl` attribute so expired sessions or temporary orders delete automatically with **zero consumed Write Capacity Units**.
5. **Stream Failure Isolation**: Registering `BisectBatchOnFunctionError: true` on the Lambda event source mapping so poisoned stream records do not block the shard.

## Deep-Dive Architectural Breakdown

### 1. Primary Key Schema & GSI Overloading
```yaml
KeySchema:
  - AttributeName: PK
    KeyType: HASH
  - AttributeName: SK
    KeyType: RANGE
GlobalSecondaryIndexes:
  - IndexName: GSI1
    KeySchema:
      - AttributeName: GSI1PK
        KeyType: HASH
      - AttributeName: GSI1SK
        KeyType: RANGE
    Projection:
      ProjectionType: ALL
```

* **Composite Primary Key**: `PK` partitions data across the storage nodes; `SK` sorts items physically on the partition. This allows us to fetch a customer and all their orders in a single `Query` call using `begins_with(SK, "ORDER#")`.
* **GSI Index Projections**:
  * `ALL`: Projects all item attributes into the index. Fast queries with zero table fetch overhead, but doubles write costs and storage.
  * `KEYS_ONLY`: Projects only the primary and index keys. Minimizes index write cost, but requires a secondary `GetItem` call back to the main table if other attributes are needed.
  * `INCLUDE`: Projects a specified subset of attributes. The optimal production compromise.

---

### 2. Time to Live (TTL) Mechanics
```yaml
TimeToLiveSpecification:
  AttributeName: ttl
  Enabled: true
```

* **Zero WCU Consumption**: When DynamoDB expires and purges an item whose `ttl` timestamp is in the past, **it does not consume Write Capacity Units**.
* **Purge Timing**: TTL purges items in the background typically within 48 hours of expiration. Expired items are also emitted to DynamoDB Streams with `principalId: "dynamodb.amazonaws.com"`.

---

### 3. DynamoDB Streams & Shard Bisection
```yaml
Events:
  OrderTableStream:
    Type: DynamoDB
    Properties:
      Stream: !GetAtt CloudOrderTable.StreamArn
      StartingPosition: TRIM_HORIZON
      BatchSize: 100
      BisectBatchOnFunctionError: true # ⚡ The Poison Pill Isolator
      RetryAttempts: 3
```

* **`StreamViewType: NEW_AND_OLD_IMAGES`**: Emits both the previous image of the item and the modified image, enabling our Java stream processor to calculate status deltas (`PENDING -> CONFIRMED`).
* **`StartingPosition: TRIM_HORIZON`**: Reads from the oldest available records in the shard (up to 24 hours of stream retention).
* **`BisectBatchOnFunctionError: true`**: **High-Yield Exam Invariant**. If a batch of 100 records encounters an unhandled exception, Lambda automatically splits the batch in half (50 and 50) and retries each subset independently, isolating the single bad record without stalling the shard!
