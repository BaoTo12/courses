## Narrative Bridge: Assembling the Cloud Infrastructure

In [Lecture 02.03](./02.03-build-event-publisher-batch-consumer.md), we built and verified our Java 21 publisher and consumer components. But in AWS, code cannot run or communicate without cloud resources.

Wiring an asynchronous messaging pipeline in AWS Serverless requires solving several non-obvious infrastructure requirements:
1. **Access Control**: SNS cannot write to an SQS queue unless an explicit resource-based policy (`AWS::SQS::QueuePolicy`) permits `sns.amazonaws.com` with an `aws:SourceArn` condition. Omitting this causes SNS deliveries to silently fail with zero error messages.
2. **Timing Math**: SQS queue `VisibilityTimeout` must be configured with mechanical sympathy to satisfy the AWS Lambda Event Source Mapping invariant:
   $$\text{VisibilityTimeout} \ge 6 \times \text{Function Timeout}$$
   With a 30-second Lambda timeout, our queue visibility timeout must be at least **180 seconds**.
3. **Resilience**: A Dead Letter Queue (`BillingDLQ`) must catch persistent poison pills after a finite number of attempts (`maxReceiveCount: 3`), preventing message loops from burning Lambda compute budgets.
4. **Content-Based Routing**: SNS Subscriptions must filter incoming messages based on metadata attributes (`FilterPolicy: { priority: ["HIGH"] }`), offloading routing logic to AWS networking rather than custom code.
5. **Partial Batch Failure Registration**: The Lambda event source mapping must declare `FunctionResponseTypes: [ ReportBatchItemFailures ]` so the runtime understands the `SQSBatchResponse` POJO returned by our Java handler.

## Deep-Dive Architectural Breakdown

### 1. The Queue Policy Invariant (`AWS::SQS::QueuePolicy`)
```yaml
BillingQueuePolicy:
  Type: AWS::SQS::QueuePolicy
  Properties:
    Queues:
      - !Ref BillingQueue
    PolicyDocument:
      Version: '2012-10-17'
      Statement:
        - Effect: Allow
          Principal:
            Service: sns.amazonaws.com
          Action: sqs:SendMessage
          Resource: !GetAtt BillingQueue.Arn
          Condition:
            ArnEquals:
              aws:SourceArn: !Ref OrderEventsTopic
```
* **Why it is mandatory**: SQS queues are private by default. While IAM roles govern what identities can do, SQS uses resource-based policies to allow external AWS services (like SNS) to enqueue messages.
* **The Security Condition**: Always restrict `aws:SourceArn` to the specific topic ARN. Without this condition, any SNS topic in any AWS account could theoretically publish to your queue if cross-account policies are misconfigured (the "Confused Deputy" vulnerability).

---

### 2. SQS Redrive Policy & DLQ Wiring
```yaml
BillingQueue:
  Type: AWS::SQS::Queue
  Properties:
    VisibilityTimeout: 180
    ReceiveMessageWaitTimeSeconds: 20
    RedrivePolicy:
      deadLetterTargetArn: !GetAtt BillingDLQ.Arn
      maxReceiveCount: 3
```
* **`VisibilityTimeout: 180`**: Matches our $6 \times 30 = 180$ requirement. If Lambda crashes or takes 28 seconds, the message will remain invisible to other workers until the execution finishes.
* **`ReceiveMessageWaitTimeSeconds: 20`**: Enables **long polling**. When the Lambda poller requests messages, SQS waits up to 20 seconds for messages to arrive before returning an empty response. This cuts empty receive API calls by up to 90%, directly reducing AWS billable request counts.
* **`maxReceiveCount: 3`**: SQS increments the message's `ApproximateReceiveCount` attribute every time it is leased to a worker. If a message fails 3 times, SQS moves it to `BillingDLQ` without invoking Lambda a 4th time.

---

### 3. SNS Subscription Filter Policies
```yaml
PriorityQueueSubscription:
  Type: AWS::SNS::Subscription
  Properties:
    TopicArn: !Ref OrderEventsTopic
    Protocol: sqs
    Endpoint: !GetAtt PriorityQueue.Arn
    FilterPolicy:
      priority:
        - "HIGH"
```
* **No Compute Cost for Filtering**: The SNS routing plane inspects the `priority` message attribute during publication.
  * If `priority` == `"HIGH"`, SNS routes a copy to both `BillingQueue` and `PriorityQueue`.
  * If `priority` == `"STANDARD"`, SNS delivers only to `BillingQueue`.
* **Zero Lambda Execution**: Non-matching messages are discarded at the SNS layer, saving thousands of dollars in Lambda invocations compared to filtering inside application code.

---

### 4. Event Source Mapping with `ReportBatchItemFailures`
```yaml
BillingProcessorFunction:
  Type: AWS::Serverless::Function
  Properties:
    Handler: com.cloudarchitect.dvac02.consumer.BillingQueueProcessor::handleRequest
    Timeout: 30
    Events:
      BillingQueueEvent:
        Type: SQS
        Properties:
          Queue: !GetAtt BillingQueue.Arn
          BatchSize: 10
          MaximumBatchingWindowInSeconds: 5
          FunctionResponseTypes:
            - ReportBatchItemFailures
```
* **`MaximumBatchingWindowInSeconds: 5`**: Tells Lambda to buffer messages for up to 5 seconds or until `BatchSize` (10 messages) is reached, maximizing batch efficiency during low-traffic periods.
* **`FunctionResponseTypes: [ ReportBatchItemFailures ]`**: Informs the AWS Lambda internal poller to inspect the returned JSON for the `batchItemFailures` list. Any message ID in that list has its visibility timeout reset to 0 so it can be retried immediately or sent to DLQ; all other message IDs in the batch are permanently deleted.
