## Narrative Bridge: Turning Contract into Production Code

In [Lecture 02.02](./02.02-api-card-sns-sqs-batch-response.md), we analyzed the exact SDK contracts for `SnsClient.publish()` and `SQSBatchResponse`. Now, we will implement the two core Java 21 components powering the CloudOrder asynchronous pipeline:

1. **The Ingress Event Publisher (`OrderEventPublisher`)**: Takes an incoming domain order and pushes a structured event to an Amazon SNS topic, tagging it with typed message attributes (`priority`, `eventType`, `amount`) so downstream subscribers can filter without code execution.
2. **The Batch Consumer (`BillingQueueProcessor`)**: Polls the SQS `BillingQueue`, unescapes the SNS wrapper envelope, executes payment settlement logic, and returns item-level failures using `ReportBatchItemFailures`.

Without `ReportBatchItemFailures`, an error on the 5th message in a 10-message batch causes the entire batch to roll back and replay. With it, only failed message IDs re-enter the queue.

## 3. The SNS Event Publisher

Publishes order lifecycle events to the SNS topic with string and numeric message attributes for subscription filtering.

✍️ `src/main/java/com/cloudarchitect/dvac02/event/OrderEventPublisher.java`

{{file:backend/module-02-fanout-queues/src/main/java/com/cloudarchitect/dvac02/event/OrderEventPublisher.java:java}}

### Architectural Highlights:
* **Stateless Client Reuse**: `SnsClient` is initialized once per JVM lifecycle. Reusing the client across warm invocations avoids TCP handshake latency and AWS credentials re-resolution.
* **Message Attributes**: The publisher attaches `priority` ("HIGH" / "STANDARD") and `eventType` ("ORDER_CREATED"). SNS filter policies evaluate these metadata keys instantly at the routing plane without reading the JSON payload.

## 4. The SQS Batch Consumer with Partial Batch Failure Isolation

Implements `RequestHandler<SQSEvent, SQSBatchResponse>` to safely consume batches of SQS messages.

✍️ `src/main/java/com/cloudarchitect/dvac02/consumer/BillingQueueProcessor.java`

{{file:backend/module-02-fanout-queues/src/main/java/com/cloudarchitect/dvac02/consumer/BillingQueueProcessor.java:java}}

### Critical Mechanical Implementation Details:
1. **SNS Envelope Unwrapping**: When SNS delivers messages to SQS without `RawMessageDelivery=true`, the message body is an SNS wrapper JSON object containing metadata (`TopicArn`, `MessageId`, `Timestamp`) and a string-escaped `Message` attribute containing the real payload. The `extractPayload()` helper detects and parses both raw JSON and SNS envelopes.
2. **Item-Level Try/Catch**: Each message in `event.getRecords()` is processed independently inside a `try/catch` block.
3. **`BatchItemFailure` Registration**: Only messages that throw exceptions are added to `batchItemFailures`. Successfully processed messages are acknowledged and deleted from the queue by the Lambda runtime.
4. **Resilience Against Catastrophic Poison Pills**: If a poisoned message enters the batch, healthy orders in that same batch are processed immediately and are never re-billed.
