## Narrative Bridge: From Bytecode to CloudFormation

In [Lecture 01.03](./01.03-build-order-api-handler.md), we wrote and verified our Java 21 `OrderApiHandler`.

Now, we need to declare the cloud infrastructure that will host this code. In modern serverless engineering, you do not click buttons in the AWS Management Console; you write declarative **Infrastructure as Code (IaC)** using the **AWS Serverless Application Model (SAM)**.

Notice something critical about this module's security: we do **not** use SAM's convenient managed policy shortcuts (like `policies: [ AWSLambdaBasicExecutionRole ]`). In the early modules of this course, you will write **raw, explicit JSON IAM policies** (`AWS::IAM::Role`) by hand. Why? Because on the DVA-C02 exam, AWS tests your ability to evaluate JSON trust policies, action scopes, and resource ARNs. Once this foundation is mastered, we will graduate to SAM Policy Templates in [Module 5](../S05-security/).

## 2. Key SAM & CloudFormation Architectural Decisions

### 1. The 1,769 MB Memory Allocation Rule
```yaml
Globals:
  Function:
    Timeout: 30
    MemorySize: 1769
```
* As we proved in [Lecture 01.01](./01.01-mechanical-sympathy-api-gateway-lambda.md), configuring **1,769 MB** guarantees the JVM receives **1 full vCPU thread**. CPU power scales linearly with RAM in AWS Lambda. Below 1,769 MB, the JVM is allocated fractional vCPUs, which severely penalizes JIT bytecode compilation and cold starts.

### 2. Explicit Raw JSON IAM Execution Role
```yaml
  OrderApiFunctionRole:
    Type: AWS::IAM::Role
    Properties:
      AssumeRolePolicyDocument:
        Version: '2012-10-17'
        Statement:
          - Effect: Allow
            Principal:
              Service: [ lambda.amazonaws.com ]
            Action: [ sts:AssumeRole ]
      Policies:
        - PolicyName: CloudOrderExplicitLoggingPolicy
          PolicyDocument:
            Version: '2012-10-17'
            Statement:
              - Effect: Allow
                Action:
                  - logs:CreateLogGroup
                  - logs:CreateLogStream
                  - logs:PutLogEvents
                Resource: !Sub 'arn:aws:logs:${AWS::Region}:${AWS::AccountId}:log-group:/aws/lambda/*:*'
```
* **Trust Policy (`AssumeRolePolicyDocument`)**: Grants the Lambda control plane (`lambda.amazonaws.com`) permission to assume this execution role.
* **Inline Policy (`CloudOrderExplicitLoggingPolicy`)**: Scopes CloudWatch logging permissions strictly to the current AWS account and region using CloudFormation's `!Sub` intrinsic function.

### 3. Greedy Path Proxy Route
```yaml
      Events:
        OrderGreedyRoute:
          Type: Api
          Properties:
            RestApiId: !Ref OrderApi
            Path: /orders/{proxy+}
            Method: ANY
```
* The `{proxy+}` syntax matches any sub-path (e.g. `/orders/electronics`, `/orders/books/fiction`).
* The greedy match captures the entire remaining path string and injects it into `input.getPathParameters().get("proxy")`, which we handled in [Lecture 01.03](./01.03-build-order-api-handler.md).
