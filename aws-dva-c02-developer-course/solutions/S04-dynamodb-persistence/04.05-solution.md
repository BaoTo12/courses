## 3. Optimistic Locking Collision Transcript

### Worker 1: Succeeded
```bash
$ aws dynamodb update-item \
    --table-name CloudOrderTable \
    --key '{"PK": {"S": "CUST#cust-101"}, "SK": {"S": "ORDER#ord-5001"}}' \
    --update-expression "SET #s = :newStatus, #v = :newVersion, #g = :newGsi" \
    --condition-expression "attribute_exists(PK) AND #v = :expectedVersion" \
    --expression-attribute-names '{"#s": "status", "#v": "version", "#g": "GSI1PK"}' \
    --expression-attribute-values '{":newStatus": {"S": "PROCESSING"}, ":newVersion": {"N": "2"}, ":newGsi": {"S": "STATUS#PROCESSING"}, ":expectedVersion": {"N": "1"}}'
```
*Output*: HTTP 200 OK (Item updated; version is now 2).

### Worker 2: Collides on outdated version 1
```bash
$ aws dynamodb update-item \
    --table-name CloudOrderTable \
    --key '{"PK": {"S": "CUST#cust-101"}, "SK": {"S": "ORDER#ord-5001"}}' \
    --update-expression "SET #s = :newStatus, #v = :newVersion, #g = :newGsi" \
    --condition-expression "attribute_exists(PK) AND #v = :expectedVersion" \
    --expression-attribute-names '{"#s": "status", "#v": "version", "#g": "GSI1PK"}' \
    --expression-attribute-values '{":newStatus": {"S": "CANCELLED"}, ":newVersion": {"N": "2"}, ":newGsi": {"S": "STATUS#CANCELLED"}, ":expectedVersion": {"N": "1"}}'
```

Output:
```text
An error occurred (ConditionalCheckFailedException) when calling the UpdateItem operation: The conditional request failed
```

The database atomically blocked Worker 2 from overwriting Worker 1's status update!
