## 1. "JSP is a template, so it's safe", right?

In a branch, simplify one line of `list.jsp`:

```jsp
<td><a href="…"><%= task.getTitle() %></a></td>          <%-- ❌ lab only --%>
```

Create a task titled `<img src=x onerror=alert('stored')>` through `/tasks/new`, and open the list: **the alert runs**, for every visitor of the list. That's **stored** XSS (26.01), from a JSP.

Add a search box to the page that echoes the query:

```jsp
<p>Results for <%= request.getParameter("q") %></p>      <%-- ❌ --%>
```

`/taskflow/tasks?q=<script>alert(1)</script>` gives **reflected** XSS, exactly 30.14's bug, now in a template.

## 2. Why

`<%= expr %>` compiles to `out.print(expr)`: **no escaping**, ever (S33 shows the generated code). JSP expressions are as dangerous as `println`. Unlike React (26.02), classic JSP does **not** escape by default.

## 3. Fixes, from today to S35

| When | How |
|---|---|
| now (scriptlets) | `<%= Html.escape(task.getTitle()) %>` (the reference `list.jsp`) |
| S34 (EL) | `${task.title}` does **not** escape either! Careful. |
| S35 (JSTL) | `<c:out value="${task.title}"/>` or `${fn:escapeXml(task.title)}`: escaping by default |
| S40 | CSP blocks inline handlers, as the second wall |

## 4. The review rule for JSPs

> Every `<%= %>` and every `${…}` that prints **text from outside** (users, the database, parameters, headers) must be escaped for its context: HTML text or attribute (`escapeXml`), URL (`URLEncoder`, `<c:url>`), JavaScript (32.09 §3).

Numbers and enums from our own model (`task.getId()`, `task.getStatus()`) are safe to print as-is.
