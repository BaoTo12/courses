# Lecture 32.09 · The Server-Side vs Client-Side Boundary

> **Section:** S32 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~25 minutes

---

## 1. Three kinds of code in one file

```jsp
<%-- list.jsp --%>
<% int count = tasks.size(); %>                                     <%-- ① Java: runs on the SERVER, at request time --%>
<p>You have <%= count %> tasks.</p>                                   <%-- ② produces TEXT: "You have 4 tasks." --%>
<script>
  const n = <%= count %>;                                             // ③ JavaScript: runs later, in the BROWSER
  document.title = "(" + n + ") Tasks";
</script>
```

The browser receives:

```html
<p>You have 4 tasks.</p>
<script>
  const n = 4;
  document.title = "(" + n + ") Tasks";
</script>
```

| Line | Runs where | Runs when |
|---|---|---|
| `<% int count = … %>` | Tomcat, Java | while the response is being generated |
| `<%= count %>` inside `<script>` | Tomcat: it **writes the characters `4`** into the JS source | same time |
| `const n = 4;` | the browser's JS engine | after the page arrived, possibly seconds later |

JavaScript **cannot** call the JSP's Java, or read `request` or the attributes. The JSP can't react to a click. They meet only through **text** (the server writes JS source) or **HTTP** (the browser sends a new request, e.g. `fetch`, Part 3).

## 2. The classic confusion

```jsp
<button onclick="<% store.delete(task.getId()); %>">Delete</button>   <%-- ❌ --%>
```

This deletes the task **while rendering the page**, for every visitor, and sends an empty `onclick`. Server code runs once, on the server, when the page is built.

## 3. Data from the server inside `<script>`: a security trap

```jsp
<script>const name = "<%= user.getDisplayName() %>";</script>          <%-- ❌ --%>
```

A display name `"; alert(1); "` breaks out of the JS string: XSS in a JavaScript context. HTML escaping is the **wrong** encoding here (`&quot;` doesn't close a JS string; `</script>` does close the block). The safe patterns:

- put data in a **data attribute**, HTML-escaped, and read it from JS: `<div id="app" data-name="<%= Html.escape(name) %>">` → `el.dataset.name`;
- or emit a JSON blob with proper JSON encoding **and** `<`/`>` escaping (S49 does this for the React island).

## ✅ Recap

Server code runs first and writes text. The browser then runs HTML, CSS and JS. They share nothing but that text and later HTTP requests. Encode for the context you write into.
