# Lecture 32.04 · The Complete Flow: Browser → Servlet → `setAttribute` → `forward` → JSP → Browser

> **Section:** S32 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~25 minutes
> Verified: `S32JspTest` (the list and details pages rendered through forwards to JSPs, in an embedded Tomcat 9 with Jasper)

---

```text
 BROWSER                         TOMCAT (one worker thread, one request object)                         
 ───────                         ─────────────────────────────────────────────                         
 GET /taskflow/tasks?status=DONE                                                                        
   │                                                                                                    
   └──────────────►  ① Connector parses → request/response objects (30.03)                            
                     ② mapping /tasks → TaskListServlet.doGet(request, response)                       
                        │  filter = TaskStatus.parse(request.getParameter("status"))       ← SERVER, Java  
                        │  tasks  = store.findByStatus(DONE)                                              
                        │  request.setAttribute("tasks", tasks)                            ← into the request's map 
                        │  request.getRequestDispatcher("/WEB-INF/views/tasks/list.jsp")               
                        │         .forward(request, response)                                          
                        ▼                                                                               
                     ③ JspServlet → list_jsp._jspService(request, response)   ← SAME request object    
                        │  List<Task> tasks = (List<Task>) request.getAttribute("tasks")                 
                        │  out.write("<table>…") ; for each task: out.write(escaped title)             
                        ▼                                                                               
                     ④ the response buffer → status 200 + headers + HTML bytes                          
   ◄──────────────   text/html;charset=UTF-8   <!doctype html>…<td>Book flights…</td>…                  
 ⑤ the browser parses the HTML, requests /taskflow/static/css/app.css (a SECOND request), renders       
```

| Step | Where | When |
|---|---|---|
| ②, the controller | server, Java | during the request, first |
| ③, the view (JSP) | server, Java generated from the JSP | the same request, **after** the controller, on the **same thread** |
| ④ | the network | when the buffer flushes / the request ends |
| ⑤ | the **browser** | after the response arrived; JSP and Java are long gone |

Things to notice:

- **One HTTP request**, two components. The URL bar shows `/taskflow/tasks?status=DONE`.
- `request` in the JSP **is** the servlet's `request`: the attribute is simply there.
- Nothing from ② or ③ reaches the browser except the **text** written to `out` (32.08).
- The CSS is another, separate request, served by the `DefaultServlet` (32.10).
