# Lecture 32.15 · 🐞 Debug: CSS Doesn't Load on `/tasks/view` (Relative Path + Path Depth)

> **Section:** S32 · **Type:** 🐞 Debug · **Track:** ★ Core · **Time:** ~15 minutes

---

## 1. The report

> "The list page is styled. The details page is plain black-on-white."

Both JSPs contain:

```html
<link rel="stylesheet" href="static/css/app.css">
```

## 2. Investigate: DevTools → Network → `app.css`

| Page URL | Relative `static/css/app.css` resolves to | Status |
|---|---|---|
| `/taskflow/tasks` | `/taskflow/static/css/app.css` | 200 ✅ |
| `/taskflow/tasks/view?id=3` | `/taskflow/tasks/static/css/app.css` | **404** ❌ |

A relative URL resolves against the **browser's current URL** (its "directory"), **not** the JSP's location on disk. `view.jsp` lives in `WEB-INF/views/tasks/`, but the browser never knows that. It only knows `/taskflow/tasks/view`, whose directory is `/taskflow/tasks/`.

The forward hides the JSP's path, so the **URL** decides.

## 3. Fix

Absolute paths that include the context path, in every view:

```jsp
<link rel="stylesheet" href="<%= request.getContextPath() %>/static/css/app.css">      <%-- S32 --%>
<link rel="stylesheet" href="${pageContext.request.contextPath}/static/css/app.css">   <%-- S34 --%>
<link rel="stylesheet" href="<c:url value='/static/css/app.css'/>">                     <%-- S35 --%>
```

The same rule applies to images, scripts, links and form actions (31.11). (S28's static `index.html` could use a relative link only because it sits at the context root, 28.10 §5.)

## ✅ Takeaway

In server-rendered pages, relative URLs depend on the **request URL**, which forwards hide from you. Use context-path-absolute URLs.
