# Lecture 32.08 · What the Browser Receives: View Source

> **Section:** S32 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~15 minutes
> Verified: `S32JspTest` asserts the response contains no `<%` and no `request.getAttribute`, only HTML, with the context path already resolved (`href="/taskflow/static/css/app.css"`).

---

Open `/taskflow/tasks`, then **View Source** (`Ctrl+U`):

```html
<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <title>Tasks · TaskFlow Admin</title>
  <link rel="stylesheet" href="/taskflow/static/css/app.css">
…
        <tr>
            <td><a href="/taskflow/tasks/view?id=1">Write quarterly report</a></td>
            <td>IN_PROGRESS</td>
```

What's **not** there:

| From the JSP | In the browser? |
|---|---|
| `<%@ page … %>` directives | ❌ (it became the `Content-Type` header) |
| `<%-- comments --%>` | ❌ (removed at translation) |
| `<% for (Task task : tasks) { %>` | ❌ (only the rows it **produced**) |
| `<%= ctx %>` | ❌ (only its **value**: `/taskflow`) |
| the `tasks` attribute, the `Task` objects | ❌ (only the text written about them) |
| `<!-- HTML comments -->` | ✅ **sent!** (a JSP writes them as ordinary text) |

Consequences:

- The browser **can't** run JSP or Java: it receives text.
- **HTML comments are public.** Never write `<!-- TODO: admin password is … -->` or internal notes in a view. Use `<%-- --%>` for developer comments.
- To debug "what did my page produce?", View Source shows the truth. DevTools' Elements panel shows the DOM **after** parsing and any JavaScript.
- The blank lines where scriptlets were are also visible (whitespace). `<%@ page trimDirectiveWhitespaces="true" %>` removes some of them (S33).
