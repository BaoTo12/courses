## Requirements

1. `TaskViewServlet` stops writing HTML. It **validates** the id (400), **loads** the task (404), puts it in a request attribute `task`, and **forwards** to `/WEB-INF/views/tasks/view.jsp`.
2. `view.jsp` renders: a breadcrumb (Tasks › title), the title, status and priority badges, the description (or "No description."), the due date (or "no due date"), and a "Back to the list" link.
3. All error handling stays in the **servlet**. The JSP can assume a task exists.
4. Escape every user-supplied text. Links use the context path.
5. The existing tests keep passing (`S31TaskServletsTest`: `?id=abc` → 400, unknown → 404, the toggled task shows `DONE`).

## Test it

Add to `S32JspTest`: `/tasks/view?id=1` → 200 and `<h1 class="page__title">Write quarterly report</h1>`, `?id=999999` → 404, `?id=x` → 400.

## Hint

<details><summary>Where does the 404 go?</summary>

`response.sendError(404)` **before** any forward, then `return`. The JSP never runs for a missing task (30.18).
</details>
