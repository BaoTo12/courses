# Lecture 32.14 · 🐞 Debug: The JSP Shows Nothing: `sendRedirect` Instead of `forward`

> **Section:** S32 · **Type:** 🐞 Debug · **Track:** ★ Core · **Time:** ~15 minutes
> Verified: `S32JspTest.jspsUnderWebInfCannotBeRequestedDirectly` (what the browser gets when it requests the JSP itself: 404)

---

## 1. The code

```java
request.setAttribute("tasks", store.findAll());
response.sendRedirect(request.getContextPath() + "/WEB-INF/views/tasks/list.jsp");   // ❌
```

**Symptom:** the browser shows **404**. With the JSP at the web root instead (`/views/tasks/list.jsp`), it shows a page with **no tasks**, or a 500 (`NullPointerException` on `tasks.isEmpty()`).

## 2. Why

A redirect tells the **browser** to request that URL (31.06):

1. **`/WEB-INF/…` is never served to browsers** (28.04) → 404. The test proves it.
2. Even for a public JSP, it's a **new request**: the `tasks` attribute stayed in the first request, so `getAttribute("tasks")` is `null` (31.15).

## 3. Fix

```java
request.setAttribute("tasks", store.findAll());
request.getRequestDispatcher("/WEB-INF/views/tasks/list.jsp").forward(request, response);   // ✅
```

Note the path: **no context path** for a dispatcher (31.11). `getRequestDispatcher(ctx + "/WEB-INF/…")` looks for `/taskflow/WEB-INF/…` **inside** the app → 404 too.

## ✅ Takeaway

To a **view**: forward (same request, can reach `WEB-INF`). To another **page after a change**: redirect (a new request, public URLs only).
