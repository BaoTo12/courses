# Lecture 32.01 · The Pain: HTML Inside Java Strings

> **Section:** S32 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~15 minutes

---

Look again at S31's `TaskListServlet` and `TaskCreateServlet`:

```java
out.println("<td><a href=\"" + ctx + "/tasks/view?id=" + task.getId() + "\">" + Html.escape(task.getTitle()) + "</a></td>");
…
return "<div class=\"form-field" + (error == null ? "" : " form-field--error") + "\"><label class=\"form-field__label\">"
    + label + " " + control + "</label>" + (error == null ? "" : "<span class=\"form-field__error\">" + Html.escape(error) + "</span>")
    + "</div>";
```

| Problem | Consequence |
|---|---|
| HTML is a Java string: `\"` everywhere, concatenation, no HTML syntax highlighting or validation | unreadable; a missing `</td>` is found only in the browser |
| The page's **structure** is spread across `println` calls and helper methods | you can't see the page |
| A designer can't change markup or CSS classes | every visual change is a Java change: recompile, redeploy |
| **Logic and presentation mixed** in one method | "which tasks?" and "which `<td>`?" can't evolve separately; hard to test |
| Escaping is manual, in dozens of places | one forgotten `Html.escape` = XSS (30.14) |
| Reusing a layout means Java helper methods (`Layout.begin/end`) | layouts are code, not markup |

The idea of JSP: **flip it**. Write the page as HTML, with small holes where Java values go. Tomcat turns that template into a servlet for you (S33).

```jsp
<td><a href="<%= ctx %>/tasks/view?id=<%= task.getId() %>"><%= Html.escape(task.getTitle()) %></a></td>
```

Still a bit of Java (S34 and S35 remove it), but the page now **looks like the page**.
