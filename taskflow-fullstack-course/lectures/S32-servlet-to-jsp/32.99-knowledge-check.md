# Lecture 32.99 · ✅ Knowledge Check: From Servlet HTML to JSP

> **Section:** S32 · **Type:** ✅ Knowledge Check · **Track:** ★ Core · **Time:** ~15 minutes

---

**1.** Did the browser execute the JSP? When did the JSP execute relative to the servlet?

<details><summary>Answer</summary>

No. The JSP ran on the **server**, as a generated servlet, **after** the controller servlet forwarded to it, in the **same request** and on the same thread. The browser only received the HTML text it wrote (32.04, 32.08).
</details>

**2.** What would happen if the servlet redirected to the JSP instead of forwarding?

<details><summary>Answer</summary>

The browser would request the JSP's URL itself. Under `WEB-INF` that's a 404. At a public path, it's a new request without the attributes, so empty data or an NPE → 500 (32.14).
</details>

**3.** `<script>const n = "<%= request.getAttribute("name") %>";</script>`. Where does each part run? What does the browser receive?

<details><summary>Answer</summary>

`<%= … %>` runs on the **server** and writes the attribute's value as characters into the script's source. The browser receives e.g. `<script>const n = "Alice";</script>` and runs it later. If the value contains `"` or `</script>`, it breaks out of the string or the block: XSS in a JS context. Use a data attribute or proper JSON encoding (32.09).
</details>

**4.** Why should a servlet never write HTML again once JSP exists?

<details><summary>Answer</summary>

One place for markup (designers and developers know where to change it), separation of concerns (the controller is testable and decides; the view renders), consistent escaping in views, and no half-written responses before a decision is made (30.18) (32.02).
</details>

**5.** Why do JSPs live under `WEB-INF/views`?

<details><summary>Answer</summary>

The container never serves `WEB-INF` to browsers, so views are reachable **only** through controllers. The controller's validation and security checks can't be bypassed, and a view never runs without its data (32.07).
</details>

**6.** The details page is unstyled, and the list page is fine. Both use `href="static/css/app.css"`. Why?

<details><summary>Answer</summary>

Relative URLs resolve against the browser's URL: `/taskflow/tasks/view` → `/taskflow/tasks/static/…` → 404. Use `contextPath + "/static/…"` (32.15).
</details>
