2. Mixin, function or placeholder: what does each produce, and which does TaskFlow avoid and why? [03.01, 03.03, 03.08]

## B. Code reading

4. List the exact selectors produced:
   ```scss
   $status-colors: ('todo': (…), 'in-progress': (…), 'done': (…));
   .badge { @each $status, $c in $status-colors { &--#{$status} { color: map.get($c, 'fg'); } } }
   ```
5. What does this compile to (assuming `abstracts` is **not** loaded in this file)?
   ```scss
   .card { padding: space(4); color: theme('text'); }
   ```
6. What's the output of `@for $i from 1 to 3 { .gap-#{$i} { gap: space($i); } }`?

## C. Debugging

7. The compiled CSS is noticeably larger after a teammate introduced `@extend .btn` in 12 places. Why? [03.08]
8. Dark mode changes the cards but the page background stays light. List two possible causes. [03.12, 03.13]
9. `@include respond-to('tablet')` fails the build. Is that a bug in the mixin? [03.02]

## D. Design

10. For each, choose mixin, function or placeholder, and justify: a `truncate` text helper; a spacing scale; a shared card shadow. [03.01, 03.03]
11. The product team wants a "high contrast" theme. What do you change, and what must **not** need changing? [03.12]

## E. Implementation

12. Add a `high-contrast` theme: one new entry in `$themes`, one new block in `base/_root.scss` for `[data-theme='high-contrast']`, **no component edits**. Your theme guard from 03.14 must pass. Extend the UI kit toggle to cycle through it.

<details>
<summary><b>Answers</b></summary>

1. Sass maps are compile-time data; after compilation only literal values remain. Custom properties exist in the browser, cascade, and are resolved at computed-value time, so changing `data-theme` changes the values everywhere instantly.

2. **Mixin** → declarations/rules (copied). **Function** → one value. **Placeholder + `@extend`** → groups selectors onto an existing rule. TaskFlow avoids `@extend`: it doesn't work across media queries, moves output, can explode selectors, and gzip removes most of its size benefit.

3. `abstracts` is loaded by many files (and by every React `.module.scss`); any CSS in it would be duplicated in each output.

4. `.badge--todo`, `.badge--in-progress`, `.badge--done`.

5. `.card { padding: space(4); color: theme("text"); }`. Unknown functions pass through as plain CSS, and the browser ignores both declarations. That's the silent-failure trap from 03.03.

6. `.gap-1 { gap: 4px; }` and `.gap-2 { gap: 8px; }` (`to` excludes 3).

7. `@extend` adds the extending selector to **every** rule where `.btn` appears (including complex/contextual selectors), multiplying selectors ("selector explosion").

8. For example: (a) `body`'s background still uses a literal colour or an old `$color-background` Sass variable instead of `theme('background')`; (b) the dark theme map is missing `'background'` (the guard from 03.14 prevents this); (c) `base/root` isn't loaded in `main.scss`; (d) `data-theme` is set on an element other than `<html>` so `body` isn't a descendant.

9. **No.** It's the mixin working as designed: `'tablet'` isn't in `$breakpoints`. The error lists valid names. Use `'md'` or add the breakpoint to the map deliberately.

10. `truncate` → **mixin** (a group of declarations, with a `$lines` parameter). Spacing scale → **function** (returns a value). Card shadow → a **variable** (`$shadow-sm`), or a **mixin** if it's several declarations. Not a placeholder.

11. Add a `'high-contrast'` map to `$themes` with the **same keys**, and emit it under `[data-theme='high-contrast']`. Components must **not** change; if one needs editing, it's using a literal or a non-semantic token.

12. Example:
    ```scss
    // _tokens.scss, inside $themes
    'high-contrast': (
      'primary': #0000ee, 'primary-hover': #0000aa, 'on-primary': #ffffff,
      'danger': #b00000, 'danger-hover': #800000,
      'text': #000000, 'text-muted': #1a1a1a, 'border': #000000,
      'surface': #ffffff, 'surface-muted': #f0f0f0, 'background': #ffffff,
      'focus-ring': rgba(0, 0, 238, 0.5),
    ),
    ```
    ```scss
    // base/_root.scss
    [data-theme='high-contrast'] {
      @include emit-theme(map.get($themes, 'high-contrast'));
      color-scheme: light;
    }
    ```
    The guard loops over **all** themes, so a missing key in `high-contrast` fails the build too.
    Toggle cycle: `light → dark → high-contrast → system`.

</details>
