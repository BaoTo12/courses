# Lecture 03.07 · 🛠 Build: Generate Badge Variants from Maps

> **Section:** S03 · **Type:** 🛠 Build · **Track:** ★ Core · **Time:** ~20 minutes
> **Project feature:** `_badge.scss` generated from `$status-colors` and `$priority-colors`; old status variables deleted

---

## 1. Before

`_badge.scss` from 02.09 had six hand-written modifier blocks, and `_variables.scss` had six `$color-status-*` variables. Adding a `BLOCKED` status meant editing two files and copy-pasting.

## 2. ✍️ After

`styles/components/_badge.scss`:

```scss
@use 'sass:map';
@use '../abstracts/variables' as *;
@use '../abstracts/tokens' as *;
@use '../abstracts/functions' as *;

.badge {
  display: inline-flex;
  align-items: center;
  padding: 2px space(2);
  border-radius: $radius-full;
  font-size: to-rem(12px);
  font-weight: $font-weight-semibold;
  line-height: 1.5;
  white-space: nowrap;

  // One modifier per TaskStatus: .badge--todo, .badge--in-progress, .badge--done
  @each $status, $colors in $status-colors {
    &--#{$status} {
      background: map.get($colors, 'bg');
      color: map.get($colors, 'fg');
    }
  }

  // One modifier per Priority: .badge--priority-low, …-medium, …-high
  @each $priority, $color in $priority-colors {
    &--priority-#{$priority} {
      color: $color;
      box-shadow: inset 0 0 0 1px $color;
    }
  }
}
```

Now delete the six `$color-status-*` and three `$color-priority-*` variables from `_variables.scss`. (Search the project first to make sure nothing else uses them. `_card.scss` still uses the priority ones for the stripe; that's your 03.14 exercise. For now, keep the three priority variables until 03.14 replaces their last usage.)

## 3. Verify the output

Run `npm run styles:build` and open `ui-kit/css/main.css`. You should find exactly:

```css
.badge--todo { background: #e0e7ff; color: #3730a3; }
.badge--in-progress { background: #fef3c7; color: #92400e; }
.badge--done { background: #dcfce7; color: #166534; }
.badge--priority-low { color: #14b8a6; box-shadow: inset 0 0 0 1px #14b8a6; }
.badge--priority-medium { color: #f59e0b; box-shadow: inset 0 0 0 1px #f59e0b; }
.badge--priority-high { color: #ef4444; box-shadow: inset 0 0 0 1px #ef4444; }
```

The UI kit should look **identical** to before. That's the definition of a successful refactor: same output, better source.

## 4. The payoff: add a status in one line

Try it: add `'blocked': ('bg': #fee2e2, 'fg': #991b1b),` to `$status-colors`. Recompile: `.badge--blocked` exists. Remove it again (TaskFlow's statuses are fixed by the backend enum).

> 🔗 **Cross-stack consistency.** The keys `'todo' | 'in-progress' | 'done'` are the Java enum `TaskStatus { TODO, IN_PROGRESS, DONE }` lower-cased with `_` → `-`. In S07 (React) and S35 (JSP) you'll build class names like `badge--${toKebab(task.status)}`. When a new enum value is added in Java, the SCSS map is the one place to add its colours.

## 5. Commit

```bash
git add styles
```

```bash
git commit -m "refactor(styles): generate badge variants from token maps"
```

## 6. Summary

- `@each` over nested maps replaced six hand-written blocks.
- The output is identical, but the source now has a **single source of truth**.
- Token keys mirror backend enum values, which keeps class names predictable across React and JSP.
