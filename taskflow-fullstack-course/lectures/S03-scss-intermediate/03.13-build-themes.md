## 2. ✍️ Step 2: theme maps in `_tokens.scss`

Add `@use` lines at the top and the `$themes` map at the bottom:

```scss
@use 'sass:map';
@use 'variables' as *;

// … $breakpoints, $status-colors, $priority-colors unchanged …

// Semantic colour tokens per theme → emitted as --color-<name> in base/_root.scss
$themes: (
  'light': (
    'primary':       map.get($palette, 'indigo-600'),
    'primary-hover': #4338ca,
    'on-primary':    map.get($palette, 'white'),
    'danger':        map.get($palette, 'red-600'),
    'danger-hover':  #b91c1c,
    'text':          map.get($palette, 'slate-900'),
    'text-muted':    map.get($palette, 'slate-500'),
    'border':        map.get($palette, 'slate-200'),
    'surface':       map.get($palette, 'white'),
    'surface-muted': map.get($palette, 'slate-100'),
    'background':    map.get($palette, 'slate-50'),
    'focus-ring':    rgba(79, 70, 229, 0.25),
  ),
  'dark': (
    'primary':       map.get($palette, 'indigo-400'),
    'primary-hover': #a5b4fc,
    'on-primary':    map.get($palette, 'slate-900'),
    'danger':        map.get($palette, 'red-400'),
    'danger-hover':  #fca5a5,
    'text':          map.get($palette, 'slate-100'),
    'text-muted':    map.get($palette, 'slate-400'),
    'border':        map.get($palette, 'slate-700'),
    'surface':       map.get($palette, 'slate-800'),
    'surface-muted': #273449,
    'background':    map.get($palette, 'slate-900'),
    'focus-ring':    rgba(129, 140, 248, 0.35),
  ),
);
```

Design notes:
- **Both themes must have the same keys.** A missing key in dark mode would leave that custom property with its light value. (In the knowledge check you'll write an `@error` guard for this.)
- **`on-primary`**: the text colour *on top of* a primary background. In dark mode the primary is a light indigo, so text on it must be dark. Naming the role ("on-primary") instead of hard-coding `#fff` makes that possible.
- Hover colours are hand-picked here rather than derived with `color.scale`. Designers often tune dark-mode hovers separately, and both approaches are valid.

## 3. ✍️ Step 3: the `theme()` function in `_functions.scss`

```scss
@use 'sass:math';
@use 'sass:map';
@use 'variables' as *;
@use 'tokens' as *;

// … to-rem() and space() unchanged …

/// Reference a themed colour. Validated at COMPILE time, resolved at RUNTIME.
/// theme('text') → var(--color-text)
@function theme($name) {
  @if not map.has-key(map.get($themes, 'light'), $name) {
    @error 'Unknown theme token "#{$name}". Known: #{map.keys(map.get($themes, "light"))}';
  }
  @return var(--color-#{$name});
}
```

And update the `focus-ring` mixin default in `_mixins.scss` (it already uses `var(--color-primary)`, which now exists).

## 4. ✍️ Step 4: emit the custom properties in `base/_root.scss`

```scss
@use 'sass:map';
@use '../abstracts' as *;

/// Emit one custom property per semantic token: --color-<name>: <value>;
@mixin emit-theme($theme) {
  @each $name, $value in $theme {
    --color-#{$name}: #{$value};
  }
}

// 1. Default (light) theme, and explicit light
:root,
[data-theme='light'] {
  @include emit-theme(map.get($themes, 'light'));
  color-scheme: light;
}

// 2. Explicit dark theme (user chose dark in the app)
[data-theme='dark'] {
  @include emit-theme(map.get($themes, 'dark'));
  color-scheme: dark;
}

// 3. No explicit choice: follow the operating system preference
@media (prefers-color-scheme: dark) {
  :root:not([data-theme='light']) {
    @include emit-theme(map.get($themes, 'dark'));
    color-scheme: dark;
  }
}
```

Note where this lives: **`base/`**, not `abstracts/`. It emits CSS, so it must be loaded exactly once from `main.scss` (03.10). Add it right after the reset:

```scss
@use 'base/reset';
@use 'base/root';
@use 'base/typography';
// …
```

Compiled output (excerpt):

```css
:root,
[data-theme=light] {
  --color-primary: #4f46e5;
  --color-primary-hover: #4338ca;
  --color-on-primary: #ffffff;
  /* … */
  color-scheme: light;
}

[data-theme=dark] {
  --color-primary: #818cf8;
  /* … */
  color-scheme: dark;
}
```

## 5. ✍️ Step 5: convert components to `theme()`

Mechanical replacement in every file:

| Old | New |
|---|---|
| `$color-primary` | `theme('primary')` |
| `$color-primary-dark` | `theme('primary-hover')` |
| `#fff` on primary/danger buttons | `theme('on-primary')` |
| `$color-danger` / `$color-danger-dark` | `theme('danger')` / `theme('danger-hover')` |
| `$color-text` / `$color-text-muted` | `theme('text')` / `theme('text-muted')` |
| `$color-border` | `theme('border')` |
| `$color-surface` / `$color-surface-muted` | `theme('surface')` / `theme('surface-muted')` |
| `$color-background` | `theme('background')` |
| `$color-focus-ring` (02.11) | `theme('focus-ring')` |

For example, the complete `components/_button.scss`:

```scss
@use '../abstracts' as *;

.btn {
  display: inline-flex;
  align-items: center;
  justify-content: center;
  gap: space(2);
  padding: space(2) space(4);
  border: 1px solid transparent;
  border-radius: $radius-md;
  font-size: to-rem(14px);
  font-weight: $font-weight-medium;
  line-height: 1.25;
  text-decoration: none;
  cursor: pointer;
  transition:
    background-color $transition-fast,
    border-color $transition-fast,
    color $transition-fast;

  &:focus-visible {
    @include focus-ring;
  }

  &:disabled,
  &[aria-disabled='true'] {
    opacity: 0.5;
    cursor: not-allowed;
  }

  & + & {
    margin-left: space(2);
  }

  &--primary {
    background: theme('primary');
    color: theme('on-primary');

    &:hover:not(:disabled) {
      background: theme('primary-hover');
    }
  }

  &--secondary {
    background: theme('surface');
    color: theme('text');
    border-color: theme('border');

    &:hover:not(:disabled) {
      background: theme('surface-muted');
    }
  }

  &--danger {
    background: theme('danger');
    color: theme('on-primary');

    &:hover:not(:disabled) {
      background: theme('danger-hover');
    }
  }

  &--sm {
    padding: space(1) space(3);
    font-size: to-rem(12px);
  }
}
```

Convert `base/_typography.scss`, `layout/_page.scss`, `layout/_kit.scss`, `components/_card.scss`, `components/_form.scss` and `utilities/_text.scss` the same way. The complete converted files are in the [S03 reference styles](../../solutions/S03-scss-intermediate/03-reference-styles.md). Try converting them yourself first, then compare.

When you're done, **no component file should contain a literal colour** except the status/priority maps, which are intentionally not themed. Check with a search:

```bash
grep -rnE "#[0-9a-fA-F]{3,6}|rgba?\(" styles/components styles/layout styles/base/_typography.scss styles/utilities
```

Expected: no matches.

## 6. 📦 Provided: a theme toggle for the UI kit

Add this to `ui-kit/index.html`, inside `.page__header` after the nav, plus a small script before `</body>`. This is **provided JavaScript**; React will do this properly in S08/S10.

```html
<button class="btn btn--secondary btn--sm" type="button" id="theme-toggle">Toggle theme</button>
```

```html
<script>
  // Provided: cycles light → dark → system (no attribute)
  const root = document.documentElement;
  document.getElementById('theme-toggle').addEventListener('click', () => {
    const current = root.getAttribute('data-theme');
    const next = current === 'light' ? 'dark' : current === 'dark' ? null : 'light';
    if (next) root.setAttribute('data-theme', next);
    else root.removeAttribute('data-theme');
    console.log('theme:', next ?? 'system');
  });
</script>
```

## 7. Try it

1. Compile and open the UI kit. Click **Toggle theme**. The whole page switches instantly: header, cards, buttons, form fields, even the native date picker (thanks to `color-scheme`).
2. In DevTools → Elements, select `<html>` and watch the `data-theme` attribute change.
3. Select a card; in **Computed**, find `background-color` and expand it: it shows `var(--color-surface)` and the resolved value.
4. With no `data-theme` attribute, change your OS to dark mode (or DevTools → ⋮ → More tools → Rendering → *Emulate CSS media feature prefers-color-scheme: dark*). The page follows the OS.

> 🧠 Notice what did **not** happen: no recompilation, no new CSS downloaded. Sass did its work once at build time; the browser switched values at runtime.

## 9. Summary

- Palette (raw) → `$themes` (semantic, per theme) → `base/_root.scss` emits `--color-*` per theme.
- `theme('name')` validates at compile time and returns `var(--color-name)`.
- Three selection mechanisms: default light, explicit `data-theme`, OS preference fallback.
- Components contain **no literal colours**; a new theme = a new map entry.
