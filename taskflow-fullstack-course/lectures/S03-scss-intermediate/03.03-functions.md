# Lecture 03.03 · Functions: `@function`, `@return`, and When a Function Beats a Mixin

> **Section:** S03 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~20 minutes

---

## 1. Mixins produce declarations; functions produce values

| | Mixin | Function |
|---|---|---|
| Called with | `@include name(…)` | `name(…)` inside a value |
| Produces | **Declarations / rules** (`padding: …; margin: …;`) | **One value** (`1.5rem`, `#4338ca`, `var(--x)`) |
| Example | `@include truncate(2);` | `padding: space(4);` |

Rule of thumb: **if you need one value, write a function. If you need declarations, write a mixin.**

---

## 2. Syntax

```scss
@use 'sass:math';

@function to-rem($px, $base: 16px) {
  @return math.div($px, $base) * 1rem;
}

.card__title {
  font-size: to-rem(18px);   // 1.125rem
}
```

- `@function` defines it; `@return` gives the result (required).
- Arguments work like mixin arguments: defaults, keywords, `$args...`.
- Functions can contain `@if`, loops, local variables and `@error`, but **no CSS declarations**.

### What happens internally

When Sass evaluates `to-rem(18px)`, it runs the function body at compile time and replaces the call with the returned value. The output contains `font-size: 1.125rem;`, and no trace of the function.

---

## 3. ⚠️ The silent-failure trap: unknown functions become plain CSS

This one surprises everyone. What happens if you call a Sass function that **isn't loaded** in this file?

```scss
// _card.scss: forgot `@use '../abstracts' as *;`
.card {
  padding: to-rem(24px);
  color: theme('text');
}
```

You might expect "Undefined function". Instead Sass compiles it **without error**:

```css
.card {
  padding: to-rem(24px);
  color: theme("text");
}
```

Why? CSS itself has functions (`calc()`, `var()`, `min()`, `rgb()`…), and new ones are added all the time. Sass can't know every future CSS function, so **when it doesn't recognise a function name, it assumes it's a CSS function and outputs it as-is**. The browser then sees an invalid value and **ignores the declaration**. No error anywhere; the style just doesn't apply.

Worse: if your function's name matches a **real CSS function**, you get a completely different behaviour. CSS has a `rem(a, b)` function (the *remainder* of a division). If we had named our helper `rem()` and forgot the `@use`, `rem(24px)` would fail with a confusing "2 arguments required" error, or with two arguments it would silently compute a remainder! That's why TaskFlow's helper is called **`to-rem()`**, not `rem()`.

**How to protect yourself:**
- Always `@use` the module that defines your functions (02.12's lesson again).
- Give custom functions names that can't collide with CSS (`to-rem`, `space`, `theme` are fine; avoid `rem`, `min`, `max`, `round`, `mod`, `clamp`…).
- When a style mysteriously doesn't apply, search the **compiled CSS** for your function's name. If it appears there, the function never ran.

## 4. Functions vs mixins vs plain variables

```scss
// Variable: a fixed value
$radius-md: 6px;

// Function: a value computed from inputs
@function space($n) { @return $n * 4px; }

// Mixin: a group of declarations
@mixin card-surface {
  background: var(--color-surface);
  border: 1px solid var(--color-border);
  border-radius: $radius-md;
}
```

| Need | Use |
|---|---|
| A named constant | Variable |
| A value derived from arguments (scale, conversion, lookup) | Function |
| Several declarations together, or a wrapper | Mixin |
| A value that changes at runtime | CSS custom property (possibly *returned* by a function, e.g. `theme('text')` → `var(--color-text)`) |

That last row is the pattern you'll build in 03.12: a Sass function that validates a token name at **compile time** and returns a CSS custom property reference for **runtime**. It combines the benefits of both.

---

## 5. Summary

- Functions return **one value**; mixins emit **declarations**.
- `@function` + `@return`; evaluated at compile time; no trace in output.
- **Unknown function calls are output as plain CSS**, a silent failure. Always `@use` the defining module, and avoid names that collide with CSS functions (like `rem`).

## 6. Check yourself

1. A teammate writes `@include to-rem(16px);`. What's wrong?
2. The compiled CSS contains `padding: space(4);`. What does that tell you?
3. Why did we name our function `to-rem` instead of `rem`?

<details>
<summary>Answers</summary>

1. `to-rem` is a **function**, not a mixin. Call it inside a value: `font-size: to-rem(16px);`.
2. The `space()` function **wasn't available** in that file (missing `@use`), so Sass output it as a plain CSS function call. The browser will ignore the declaration.
3. CSS has a native `rem()` math function (remainder). A Sass function with the same name risks confusing errors, or silently different results when the module isn't loaded.

</details>
