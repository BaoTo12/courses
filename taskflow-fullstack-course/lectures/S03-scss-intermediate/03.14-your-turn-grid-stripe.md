# Lecture 03.14 · 🎯 Your Turn: Responsive Task Grid and a Map-Driven Priority Stripe

> **Section:** S03 · **Type:** 🎯 Your Turn · **Track:** ★ Core · **Time:** ~30–45 minutes

---

## 1. The task

### Part A: three-column grid

`.task-grid` currently has 1 column on small screens and 2 from `md`. Make it **3 columns from `lg`**, using only the `respond-to` mixin.

### Part B: priority stripe from the map

`_card.scss` still has three hand-written rules:

```scss
&--priority-low::before    { background: map.get($priority-colors, 'low'); }
&--priority-medium::before { background: map.get($priority-colors, 'medium'); }
&--priority-high::before   { background: map.get($priority-colors, 'high'); }
```

Replace them with a loop over `$priority-colors`, so adding a priority to the map automatically adds its stripe.

### Part C: a guard for theme completeness

Add a compile-time check (in `_tokens.scss`, right after `$themes`, or in `base/_root.scss`) that **fails the build** if the `dark` theme is missing any key that `light` has (or vice versa), naming the missing key(s).

---

## 2. Requirements

1. The grid is 1 → 2 → 3 columns at default → `md` → `lg`. No raw `@media` in the component.
2. The compiled CSS for card stripes is **identical** to before (three rules, same selectors, same colours).
3. Deleting the `'dark'` theme's `'border'` key makes the build fail with a message that names `border`.
4. No new literal colours in components.

## 3. Acceptance checks

- [ ] Resize the UI kit: 1, 2, then 3 columns.
- [ ] `git diff` of the compiled CSS for `.card--priority-*` shows no change.
- [ ] Temporarily remove `'border'` from `dark`: compile fails with a clear message. Put it back: compile succeeds.
