# Lecture 03.08 · `%placeholder` + `@extend` vs Mixins

> **Section:** S03 · **Type:** 📖 Theory · **Track:** ＋ Extended · **Time:** ~20 minutes

---

## 1. What `@extend` does

`@extend` tells Sass: "this selector should get **all the styles** of that other selector". Instead of copying declarations (like a mixin), Sass **adds your selector to the other selector's rule**.

```scss
%card-surface {                 // a placeholder: never output on its own
  background: #fff;
  border: 1px solid #e2e8f0;
  border-radius: 8px;
}

.card   { @extend %card-surface; padding: 16px; }
.dialog { @extend %card-surface; padding: 24px; }
```

Output:

```css
.dialog, .card {
  background: #fff;
  border: 1px solid #e2e8f0;
  border-radius: 8px;
}
.card { padding: 16px; }
.dialog { padding: 24px; }
```

- The declarations appear **once**, with a **grouped selector**.
- A **placeholder selector** (`%name`) is like a class that exists only to be extended; it's never output by itself.

---

## 2. Mixin vs extend: the output side by side

With a mixin:

```css
.card   { background: #fff; border: 1px solid #e2e8f0; border-radius: 8px; padding: 16px; }
.dialog { background: #fff; border: 1px solid #e2e8f0; border-radius: 8px; padding: 24px; }
```

| | `@include` (mixin) | `@extend` |
|---|---|---|
| Output | Declarations **copied** into each rule | Selectors **grouped** onto the original rule |
| Arguments | ✅ | ❌ |
| Works inside `@media` across contexts | ✅ | ❌ (you can't extend an outside selector from inside a media query; see 03.16) |
| Moves your styles in the file | No (stays where you wrote it) | **Yes**: the grouped rule lives where the *extended* selector was defined, which can change cascade order |
| Risk of "selector explosion" | No | **Yes**: extending a class that appears in many complex selectors multiplies selectors |
| Raw CSS size | Larger | Smaller |
| Size after gzip | Nearly the same (repetition compresses extremely well) | Nearly the same |

### Selector explosion example

```scss
.btn { … }
.toolbar .btn { … }
.modal .footer .btn:hover { … }

.link-button { @extend .btn; }
```

Sass must add `.link-button` everywhere `.btn` appears: `.toolbar .link-button`, `.modal .footer .link-button:hover`… In a large codebase this produces huge, surprising selectors and cascade changes.

---

## 3. Why most teams prefer mixins

1. Mixins are **predictable**: output appears where you wrote it.
2. Mixins take **arguments**.
3. Mixins work inside **media queries**.
4. The size advantage of `@extend` mostly **disappears after gzip/brotli**.

The Sass team's own guidance: use `@extend` only for genuine *"is-a"* relationships between classes that must **share the same semantic styles** (e.g. `.error--serious` is an `.error`), and keep it to placeholders. Many style guides simply ban it.

**TaskFlow's rule:** mixins, not `@extend`. You should still be able to **read** `@extend`, since you'll find it in older codebases.

---

## 4. Summary

- `@extend` groups selectors onto an existing rule; `%placeholder`s exist only to be extended.
- Pros: smaller raw CSS. Cons: no arguments, doesn't work across media queries, moves styles, selector explosion.
- Prefer mixins; after compression the size difference is negligible.
