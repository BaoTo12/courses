# Lecture 03.09 · Naming: BEM (Block__Element--Modifier)

> **Section:** S03 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~20 minutes

---

## 1. The problem naming solves

CSS has **one global namespace**. Every class name in every file can affect every element on the page. Without conventions:

- Two developers both write `.title` for different things → collision.
- People use descendant selectors (`.card h3`) to avoid inventing names → specificity creep (02.13) and coupling to HTML structure.
- Nobody can tell from `.active` or `.big` which component it belongs to, or whether it's safe to delete.

## 2. BEM in one table

| Part | Meaning | Syntax | TaskFlow example |
|---|---|---|---|
| **Block** | A standalone component | `.block` | `.card`, `.badge`, `.form-field` |
| **Element** | A part of a block that has no meaning outside it | `.block__element` | `.card__title`, `.form-field__input` |
| **Modifier** | A variant or state of a block or element | `.block--modifier`, `.block__element--modifier` | `.card--priority-high`, `.card__due--overdue` |

HTML:

```html
<article class="card card--priority-high">
  <h3 class="card__title">…</h3>
  <span class="card__due card__due--overdue">Overdue</span>
</article>
```

Notice: a modifier is **added alongside** the base class (`card card--priority-high`), never alone. The modifier only contains what *differs*.

## 3. Rules that make BEM work

1. **Flat selectors.** Style `.card__title`, not `.card .card__title` or `.card h3`. Specificity stays at one class, so any modifier or state can override it.
2. **No elements of elements in names.** Not `.card__meta__due`; use `.card__due` even if it's nested deep in the HTML. BEM names describe *belonging to the block*, not DOM depth.
3. **Blocks don't set their own outer layout.** A `.card` doesn't decide its margin in a grid; the *parent* (`.task-grid`) uses `gap`. This keeps blocks reusable anywhere.
4. **A block inside a block is still its own block.** A `.badge` inside a `.card` stays `.badge`, not `.card__badge`. (If the card needs to position it, give the wrapper a card element class: `<footer class="card__meta">`.)
5. **State classes**: BEM purists use modifiers (`.btn--loading`); many teams also allow `is-` / `has-` state classes (`.is-open`) or ARIA attributes (`[aria-expanded='true']`, `[aria-invalid='true']`). TaskFlow prefers **ARIA attributes** for states that assistive technology also needs (you did this in 02.10).

## 4. How Sass's `&` supports BEM

```scss
.card {
  &__title { … }           // .card__title
  &--priority-high { … }   // .card--priority-high
  &__due {
    &--overdue { … }       // .card__due--overdue
  }
}
```

Nesting in the *source*, flat selectors in the *output*. That's why BEM and SCSS are such a common pair.

## 5. Do you still need BEM with CSS Modules or styled-components?

- **CSS Modules** (S07) hash class names per file (`.title` → `.Card_title__x7Yz`), so collisions are impossible. Many teams use shorter names inside modules, but still apply the *ideas*: flat selectors, modifiers for variants.
- **styled-components** (S09) generates unique class names automatically; you don't name classes at all. Variants become **props** (`$variant="primary"`).
- **Global SCSS for JSP** (Part 2) has **no automatic scoping**. BEM is essential there.

Since TaskFlow's design system is shared between React and JSP, it uses BEM for everything in `styles/`.

## 6. Summary

- BEM: `.block`, `.block__element`, `.block--modifier`. Modifiers accompany base classes.
- Keep selectors flat (one class); don't encode DOM depth; blocks don't set outer layout.
- Sass `&` makes BEM pleasant to write.
- CSS Modules/styled-components reduce the need for naming conventions; global CSS for JSP needs BEM.

## 7. Check yourself

Rename these to BEM and explain:
1. `.task-card .title`
2. `.card .meta .due.red`
3. `.badgeDone`

<details>
<summary>Answers</summary>

1. `.card__title` (or `.task-card__title` if the block is named `task-card`): an element of the card block, one flat class.
2. `.card__due` + a modifier `.card__due--overdue`: "red" is a *look*, "overdue" is the *meaning*. Name by meaning, flat, no DOM depth.
3. `.badge.badge--done`: base block class plus a status modifier.

</details>
