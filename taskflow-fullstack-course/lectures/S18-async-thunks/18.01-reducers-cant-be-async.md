# Lecture 18.01 · Why Reducers Can't Be Async, and Where Side Effects Are Allowed

> **Section:** S18 · R5: Async Logic and Data Fetching
> **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~20 minutes
> 🔗 Official companion reading: Redux **Fundamentals, Part 6** ("Async Logic and Data Fetching")

---

## 1. The need

TaskFlow must load tasks from the server, save them, delete them. Each of those takes time and can fail. Redux's pieces so far:
- **Reducers:** pure, synchronous, `(state, action) → state` (15.04).
- **The store:** `dispatch` is synchronous (16.04).
- **Components:** can do async work, and in S17 they did, through `useTaskOperations()`.

So where should "call the API, then update the store" live?

## 2. Not in reducers

```ts
// ❌ what beginners try first
case 'tasks/fetchRequested': {
  api.getTasks().then((page) => /* …now what? */);
  return state;
}
```

- The reducer must **return the new state now**. The response arrives later, when the reducer has long finished.
- It can't dispatch the result: *"Reducers may not dispatch actions."* (16.04).
- It would break every property reducers give you: replaying actions (the DevTools, time travel) would call the API again; tests would need a server; the same action could produce different states.

## 3. Not (only) in components

S17's `useTaskOperations()` worked, but it has limits:
- **Only components can use it.** A middleware, a timer, or another async flow can't call a hook.
- **Every page wires it up:** the hook, the dispatch, the error handling.
- **Logic is tied to the UI layer.** Testing "saving a task updates the store" means rendering a component.

## 4. Middleware is the place

Remember 16.10: **middleware may have side effects**, and every dispatch passes through it. Redux's answer to async logic is a middleware that lets you **dispatch a function**. The function receives `dispatch` and `getState`, does its async work, and dispatches plain actions with the results. That function is called a **thunk**, and the middleware is the **thunk middleware**.

```ts
// what components will write in this section
await dispatch(saveNewTask(request));   // saveNewTask(...) returns a FUNCTION, not an action
```

The reducers stay pure. The async logic moves into plain functions that are easy to test (with a fake API, 18.13) and usable from anywhere that can dispatch.

(Other async middleware exist: redux-saga, redux-observable, and RTK's listener middleware, S21. Thunks are the official default: simplest, and built into Redux Toolkit.)

## 5. Summary

- Reducers must return synchronously and stay pure: no API calls.
- Components can do async work, but only they can use it, and it ties logic to the UI.
- Middleware is Redux's home for side effects; the thunk middleware lets you dispatch async functions.
