# Lecture 18.09 · When to Load: `useEffect` vs Route Loaders vs "Fetch If Needed"

> **Section:** S18 · **Type:** 📖 Theory + 🛠 Build · **Track:** ★ Core · **Time:** ~35 minutes
> **Project feature:** `fetchTasksIfNeeded()` and `tasks.fetchedAt`; the layout loads "if needed"
> Verified: the browser console shows **one** `tasks/fetchStarted` on page load (S17 showed two); the tests in §4 pass.

---

## 1. Three places to trigger loading

| Strategy | How | Pros | Cons |
|---|---|---|---|
| **In an effect** (TaskFlow) | `useEffect(() => { void dispatch(fetchX()); }, [dispatch])` | Simple; works in any React app | Runs after the first render (a "Loading…" flash); StrictMode runs it twice in development; every remount re-triggers it |
| **Route loaders** | React Router's **data mode** (`createBrowserRouter` + `loader` functions) runs loading **before** rendering the route | No loading flash for route data; loading starts in parallel with code-splitting | Needs the data router; TaskFlow uses declarative mode (12.02) |
| **"Fetch if needed" thunks** | Any trigger, but the thunk **checks the state first** and skips work | Duplicate triggers become harmless; cached data is reused | Needs a freshness rule |

They combine: TaskFlow triggers from an effect **and** makes the thunk idempotent. RTK Query (S22) automates exactly this: components declare what they need, and the cache decides whether a request is required.

## 2. ✍️ `fetchedAt` in the slice

`tasks.fetchedAt: number | null` records when the list was last loaded successfully. The timestamp comes from the **action creator** (`fetchSucceeded(requestId, tasks, fetchedAt = Date.now())`), never from the reducer (15.04).

## 3. ✍️ `fetchTasksIfNeeded()` (in `tasksThunks.ts`)

```ts
/** How long loaded data counts as fresh for fetchTasksIfNeeded (18.09). */
export const FRESH_FOR_MS = 30_000;

/** Skips the request when a load is already running, or the data is younger than FRESH_FOR_MS. */
export const fetchTasksIfNeeded =
  (now: () => number = Date.now): AppThunk<Promise<void>> =>
  async (dispatch, getState) => {
    const { status, fetchedAt } = getState().tasks;
    if (status === 'loading') return;
    if (fetchedAt !== null && now() - fetchedAt < FRESH_FOR_MS) return;
    await dispatch(fetchTasks());
  };
```

- **`getState()` to decide**: the classic use of the second argument (18.05).
- **A thunk dispatching a thunk**: `dispatch(fetchTasks())` goes back through the middleware (18.03).
- **`now` is injectable**: tests control time without fake timers.

And in `AppLayout`:

```tsx
// Load the tasks for every page. "If needed" skips it when a load is running or the data is fresh (18.09):
// StrictMode's second effect run (and every remount) finds status 'loading' and does nothing.
useEffect(() => {
  void dispatch(fetchTasksIfNeeded());
}, [dispatch]);
```

Verified in the browser: **one** `tasks/fetchStarted` on load. The second StrictMode run found `status === 'loading'` and returned.

## 4. ✍️ Tests (in `tasksThunks.test.ts`)

```ts
it('skips while loading and while fresh, and refetches when stale', async () => {
  const api = fakeApi();
  const store = makeStore(undefined, { api });
  await store.dispatch(fetchTasksIfNeeded());
  expect(api.getTasks).toHaveBeenCalledTimes(1);

  const fetchedAt = store.getState().tasks.fetchedAt ?? 0;
  await store.dispatch(fetchTasksIfNeeded(() => fetchedAt + FRESH_FOR_MS - 1));
  expect(api.getTasks).toHaveBeenCalledTimes(1); // still fresh

  await store.dispatch(fetchTasksIfNeeded(() => fetchedAt + FRESH_FOR_MS));
  expect(api.getTasks).toHaveBeenCalledTimes(2); // stale → refetch
});

it('two dispatches in a row (StrictMode) start only one request', async () => {
  const api = fakeApi();
  const store = makeStore(undefined, { api });
  const a = store.dispatch(fetchTasksIfNeeded());
  const b = store.dispatch(fetchTasksIfNeeded());
  await Promise.all([a, b]);
  expect(api.getTasks).toHaveBeenCalledTimes(1);
});
```

The second test works because `dispatch` is synchronous (16.04): the first thunk's `fetchStarted` is already in the state when the second thunk calls `getState()`.

## 5. Freshness is a product decision

30 seconds is arbitrary. How stale may a task list be? For a personal task list, a minute is fine; for a stock ticker, it isn't. Explicit "Try again"/"Refresh" actions call `fetchTasks()` directly and always refetch. And mutations keep the store up to date without refetching (the server returns the saved task, 18.07).

## 6. Summary

- Effects are the simplest trigger; route loaders load before render; "if needed" thunks make any trigger idempotent.
- `fetchedAt` + `status` in state let a thunk decide with `getState()`.
- TaskFlow: effect + `fetchTasksIfNeeded()`: one request per page load, even under StrictMode.
