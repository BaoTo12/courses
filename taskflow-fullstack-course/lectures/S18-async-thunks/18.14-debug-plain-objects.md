# Lecture 18.14 · 🐞 Debug: "Actions must be plain objects" (Thunk Middleware Not Applied)

> **Section:** S18 · **Type:** 🐞 Debug · **Track:** ★ Core · **Time:** ~15 minutes
> Reproduced in the reference tests (`tasksThunks.test.ts`, "18.14") and in 14.10's playground.

---

## Symptom

A teammate creates a store for a new test file:

```ts
const store = createStore(rootReducer);
await store.dispatch(fetchTasks());
```

and gets (Redux 5, development build, verified):

```text
Actions must be plain objects. Instead, the actual type was: 'function'. You may need to add middleware to your
store setup to handle dispatching other values, such as 'redux-thunk' to handle dispatching functions.
See https://redux.js.org/tutorials/fundamentals/part-4-store#middleware and
https://redux.js.org/tutorials/fundamentals/part-6-async-logic#using-the-redux-thunk-middleware for examples.
```

(In a production build, the same error appears as *"Minified Redux error #7"*, 14.10.)

## Investigation checklist

1. What does `fetchTasks()` return: an action or a function? (18.05)
2. Which part of Redux turns a dispatched function into a call? (18.03)
3. Is that part in this store's `applyMiddleware`?
4. Why doesn't TypeScript catch it? (18.08)

## Explanation

- `fetchTasks()` returns a **function**. Only the **thunk middleware** knows what to do with functions.
- This store has **no middleware**. The function reaches the store's real `dispatch`, which accepts plain objects only, and throws.
- TypeScript didn't complain because the test used `as never` or a loosely typed store. With `AppStore`/`AppDispatch` types, a plain `createStore(rootReducer)` store rejects a thunk at compile time (18.08's error: *"Argument of type 'AppThunk<Promise<void>>' is not assignable to parameter of type 'AppAction'"*).

Other ways to hit the same error:
- Adding the thunk middleware to **one** store but dispatching to **another** (two `createStore` calls; a test utility with its own store).
- Using the v2 import style with v3: `import thunk from 'redux-thunk'`. v3 has **no default export**. Verified: Node refuses to load it (*"The requested module 'redux-thunk' does not provide an export named 'default'"*), and TypeScript, with the template's module-interop settings, silently types `thunk` as the **whole module object**, which isn't a middleware. Use `import { thunk } from 'redux-thunk'` (or `withExtraArgument`).
- Wiring `applyMiddleware` to the **wrong argument** of `createStore`.

## Fix

Create test stores the same way the app does:

```ts
const store = makeStore(preloadedState, { api: fakeApi() });
await store.dispatch(fetchTasks()); // typed, with the thunk middleware and a fake API
```

That's why `makeStore` is a factory (16.11) and accepts `extra` overrides (18.06): one place builds correctly wired stores, for the app and for every test.

## Lessons

- "Actions must be plain objects … 'function'" = the thunk middleware isn't on **this** store.
- Build every store through one factory; type dispatch as `AppDispatch`.
