## Requirements

1. Move the `<tr>…</tr>` of `list.jsp` into `WEB-INF/views/tasks/task-row.jspf`. The list's output must not change: S33–S37's tests must pass untouched.
2. A new page `GET /dashboard` (a servlet + `WEB-INF/views/dashboard.jsp`) with two tables, both using the fragment:
   - **Overdue** (not done, due before today), with a count in the heading;
   - **Due in the next 7 days** (not done, due between today and today + 7);
   - an empty-state line for each when there's nothing.
3. The service computes both lists (`overdue()`, `dueWithin(days)`), sorted by due date. The controller doesn't filter.
4. The rows keep their Toggle and Delete forms (so the page needs the CSRF token) and their overdue highlighting.
5. A "Dashboard" link in the nav, active on the dashboard (39.08).

**Tests:** create a task due 2020-01-01 → it's in the dashboard's overdue table with `task-row--overdue`; a DONE seed task isn't on the dashboard; the Dashboard nav link is active.

## Hints

- **Directive or action?** The row needs the loop's `task` and `row`: page-scope variables of the including page (39.04).
- Write the fragment's **contract** at its top: what it expects the including page to provide.
- Including the same fragment twice in one page is fine here. 39.12 shows when it isn't.
