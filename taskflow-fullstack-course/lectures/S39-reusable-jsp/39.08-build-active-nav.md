# Lecture 39.08 · 🛠 Build: Highlighting the Current Section in the Navigation

> **Section:** S39 · **Type:** 🛠 Build · **Track:** ★ Core · **Time:** ~30 minutes
> **Project feature:** the nav link of the current section gets `is-active`.
> Verified: `S39ReusableViewsTest.theCurrentSectionIsHighlighted`, `.afterAForwardTheServletPathIsTheJsps` (`/WEB-INF/views/debug/el.jsp` vs `/debug/el`)

---

## 1. The trap: which path?

The obvious expression is `${pageContext.request.servletPath}`. But every TaskFlow page is rendered **after a forward**, and a forward changes the request's paths to the **target's**. The debug page (34.16) now shows both:

| Expression | Value on `/taskflow/debug/el` |
|---|---|
| `${pageContext.request.servletPath}` | `/WEB-INF/views/debug/el.jsp` |
| `${requestScope['javax.servlet.forward.servlet_path']}` | `/debug/el` |

The container saves the **original** request's paths in five request attributes when it forwards: `javax.servlet.forward.request_uri`, `.context_path`, `.servlet_path`, `.path_info` and `.query_string` (`RequestDispatcher.FORWARD_*` constants). With `servletPath`, no link would ever be active. (`<jsp:include>` has the same set with the `include` prefix.)

## 2. The fragment

✍️ `src/main/webapp/WEB-INF/views/common/nav.jspf`

```jsp
<%--
  S39 (39.08): the navigation, with the current section highlighted, and the theme switch (39.09).
  After a FORWARD, pageContext.request.servletPath is the JSP's path (/WEB-INF/views/…): the path the USER asked
  for is kept by the container in the request attribute javax.servlet.forward.servlet_path (39.08).
--%>
<%@ taglib prefix="c" uri="http://java.sun.com/jsp/jstl/core" %>
<%@ taglib prefix="fn" uri="http://java.sun.com/jsp/jstl/functions" %>
<c:set var="currentPath" value="${requestScope['javax.servlet.forward.servlet_path']}"/>
    <nav class="page__nav">
      <a class="page__nav-link${currentPath == '/dashboard' ? ' is-active' : ''}" href="<c:url value='/dashboard'/>">Dashboard</a>
      <a class="page__nav-link${fn:startsWith(currentPath, '/tasks') and currentPath != '/tasks/new' ? ' is-active' : ''}" href="<c:url value='/tasks'/>">Tasks</a>
      <a class="page__nav-link${currentPath == '/tasks/new' ? ' is-active' : ''}" href="<c:url value='/tasks/new'/>">New task</a>
      <a class="page__nav-link${fn:startsWith(currentPath, '/categories') ? ' is-active' : ''}" href="<c:url value='/categories'/>">Categories</a>
      <c:if test="${not empty csrfToken}">
        <c:set var="here" value="${requestScope['javax.servlet.forward.request_uri']}${empty requestScope['javax.servlet.forward.query_string'] ? '' : '?'}${requestScope['javax.servlet.forward.query_string']}"/>
        <form class="theme-switch" method="post" action="<c:url value='/preferences/theme'/>" style="display:inline">
          <input type="hidden" name="_csrf" value="${csrfToken}">
          <input type="hidden" name="returnTo" value="${fn:escapeXml(here)}">
          <button class="btn btn--sm btn--secondary" type="submit" name="theme" value="${theme == 'dark' ? 'light' : 'dark'}">${theme == 'dark' ? 'Light' : 'Dark'} theme</button>
        </form>
      </c:if>
    </nav>
```

| Link | Active when |
|---|---|
| Dashboard | the path is exactly `/dashboard` |
| Tasks | it starts with `/tasks`, except `/tasks/new`: the list, a task, its edit form |
| New task | `/tasks/new` |
| Categories | it starts with `/categories` |

A value choice, so a ternary on the class (34.11). The rules live in **one** fragment for all pages.

The theme switch at the end is 39.09's. It's only rendered when the page has a CSRF token (`${not empty csrfToken}`): pages without POST forms (the debug pages) don't prepare one, so they get no switch. S40's filter will make the token available everywhere.
