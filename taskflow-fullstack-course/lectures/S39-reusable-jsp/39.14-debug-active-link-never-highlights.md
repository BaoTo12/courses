# Lecture 39.14 · 🐞 Debug: the Active Nav Link Never Highlights (a Real One from This Course's Plan)

> **Section:** S39 · **Type:** 🐞 Debug · **Track:** ★ Core · **Time:** ~10 minutes
> This course's own curriculum planned 39.08 with `${pageContext.request.servletPath}`. `S39ReusableViewsTest.afterAForwardTheServletPathIsTheJsps` pinned why that can't work.

---

## 1. The code

```jsp
<a class="page__nav-link${pageContext.request.servletPath == '/tasks' ? ' is-active' : ''}" href="…/tasks">Tasks</a>
```

## 2. Symptom

No link is ever highlighted, on any page. No error.

## 3. Investigate

Print the value (the debug page does, 34.16):

```text
${pageContext.request.servletPath}                         → /WEB-INF/views/debug/el.jsp
${requestScope['javax.servlet.forward.servlet_path']}      → /debug/el
```

Every TaskFlow page is rendered by a JSP **after a forward** from its controller (32.06). During a forward, the request's path methods describe the **forward target**. The container keeps the original values in the `javax.servlet.forward.*` request attributes.

## 4. Fix

Compare against `requestScope['javax.servlet.forward.servlet_path']` (39.08). Alternatives: the controller sets an attribute (`request.setAttribute("section", "tasks")`), which is explicit and survives any dispatching; or a filter (S40) records the original path for every request.

## ✅ Takeaway

After a forward, `getServletPath()`, `getRequestURI()` and `getQueryString()` describe the JSP, not what the user requested. The originals are in the `javax.servlet.forward.*` attributes.
