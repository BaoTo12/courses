## 📇 API card: `<jsp:include>` and `<jsp:param>`

```jsp
<jsp:include page="/WEB-INF/views/common/form-errors.jsp">
  <jsp:param name="title" value="The category was not saved:"/>
</jsp:include>
```

| Attribute | Meaning |
|---|---|
| `page` | the resource to run: a JSP or a servlet path, relative to the app. EL allowed (`page="${widget}"`) |
| `flush` | `false` (default): don't flush the page's buffer first |
| `<jsp:param name value>` | extra request **parameters**, visible to the included resource only (`${param.title}`) |

What Jasper generated:

```java
JspRuntimeLibrary.include(request, response, "/WEB-INF/views/common/flash.jsp", out, false);
JspRuntimeLibrary.include(request, response, "/WEB-INF/views/common/form-errors.jsp" + "?"
    + JspRuntimeLibrary.URLEncode("title", request.getCharacterEncoding()) + "=" + …);
```

It's a **call**, at request time, to `RequestDispatcher.include`: the included JSP is a **separate servlet** with its own `_jspService`, and its output is written into the page's.

| Aspect | Behaviour |
|---|---|
| sees | the **same request**: its attributes (`${flash}`, `${errors}`) and parameters, plus the `<jsp:param>`s |
| doesn't see | the including page's **page scope** (`<c:set>` without `scope`), its local variables, its taglib declarations |
| response | can write the body; can't set the status or headers (they're the includer's) |
| changes picked up | the included JSP is re-translated on its own; the including page doesn't need to be |
| cost | a dispatch per include, per request: small, but not free |

**When to use:** self-contained widgets (the flash message, an error summary), content chosen at runtime (`page="${widgetPath}"`), or output from a servlet.
**When not to:** fragments that need the includer's loop variable or page-scoped values (39.13): use the include directive, or pass the data in request attributes.

**Common mistakes:**
- Expecting a `<c:set var="x">` from the includer to be visible (39.13).
- Setting `contentType` in the included page: it's ignored (the includer owns the response).
- Non-ASCII `<jsp:param>` values: they're URL-encoded with the **request's** character encoding (see the generated code), which isn't always UTF-8 for GET requests. Put text in request attributes instead, and keep params ASCII (flags, keys).

## ✅ Recap

`<jsp:include>` runs another resource during the request and inserts its output. It shares the request, not the page.
