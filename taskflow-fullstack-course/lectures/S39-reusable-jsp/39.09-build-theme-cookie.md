# Lecture 39.09 · 🛠 Build: the Theme from the `tf_theme` Cookie, with an Allow-List

> **Section:** S39 · **Type:** 🛠 Build · **Track:** ★ Core · **Time:** ~35 minutes
> **Project feature:** dark/light theme shared with the React app: the same cookie (`tf_theme`, 24.05) and the same design tokens (`[data-theme=…]` in the shared SCSS, S03).
> Verified: `S39ReusableViewsTest.theThemeComesFromTheSharedCookieThroughAnAllowList`, `.theThemeSwitchSetsTheCookieAndReturnsToThePage`

---

## 1. Reading it: an allow-list in the header

```jsp
<c:set var="theme" value="${cookie.tf_theme.value == 'dark' or cookie.tf_theme.value == 'light' ? cookie.tf_theme.value : ''}"/>
<!doctype html>
<html lang="en"<c:if test="${not empty theme}"> data-theme="${theme}"</c:if>>
```

- The shared stylesheet already has `[data-theme=light]` and `[data-theme=dark]` rules, and a `prefers-color-scheme` default. No attribute = follow the operating system.
- A cookie is **client input**. `${cookie.tf_theme.value}` printed into the page as is would be an injection point (a cookie can be set by a sibling subdomain, or by a script on a page with an XSS). Only the two allowed values ever reach the HTML. Anything else, `"><script>` included, gives no attribute, as the test checks.

## 2. Changing it: a POST that sets a cookie

✍️ `src/main/java/com/taskflow/web/ThemeServlet.java`

```java
package com.taskflow.web;

import java.io.IOException;
import java.util.Set;
import javax.servlet.annotation.WebServlet;
import javax.servlet.http.Cookie;
import javax.servlet.http.HttpServlet;
import javax.servlet.http.HttpServletRequest;
import javax.servlet.http.HttpServletResponse;

/**
 * S39 (39.09): POST /preferences/theme (theme = light | dark | system, returnTo) → sets the tf_theme cookie, the SAME
 * cookie the React app uses (24.05), then 303 back to the page the user was on.
 * The value is checked against an allow-list, and returnTo must be a path inside this app (no open redirect, 24.14).
 */
@WebServlet("/preferences/theme")
public class ThemeServlet extends HttpServlet {

  static final String COOKIE = "tf_theme";
  private static final Set<String> THEMES = Set.of("light", "dark", "system");
  private static final int ONE_YEAR = 365 * 24 * 60 * 60;

  @Override
  protected void doPost(HttpServletRequest request, HttpServletResponse response) throws IOException {
    if (!Csrf.isValid(request)) {
      response.sendError(HttpServletResponse.SC_FORBIDDEN, "Invalid or missing CSRF token");
      return;
    }
    String theme = request.getParameter("theme");
    if (theme == null || !THEMES.contains(theme)) {
      response.sendError(HttpServletResponse.SC_BAD_REQUEST, "theme must be light, dark or system");
      return;
    }
    Cookie cookie = new Cookie(COOKIE, theme);
    cookie.setPath("/");                                         // shared with the React app on the same host
    cookie.setMaxAge("system".equals(theme) ? 0 : ONE_YEAR);    // "system" = no preference: delete the cookie
    // Not HttpOnly: the React app reads it with js-cookie. It's a preference, not a secret.
    response.addCookie(cookie);
    Http.seeOther(response, safeReturnTo(request, request.getParameter("returnTo")));
  }

  /** A path of THIS application ("/taskflow/…"), or the task list. Never another site (24.14). */
  static String safeReturnTo(HttpServletRequest request, String returnTo) {
    String home = request.getContextPath() + "/tasks";
    if (returnTo == null || !returnTo.startsWith(request.getContextPath() + "/")) return home;
    if (returnTo.startsWith("//") || returnTo.contains("\\") || returnTo.contains("\r") || returnTo.contains("\n")) return home;
    return returnTo;
  }
}
```

### 📇 API card: `javax.servlet.http.Cookie`

| Call | Meaning |
|---|---|
| `new Cookie(name, value)` | name: a token (no spaces or `;`); value: no spaces, commas or quotes unless encoded |
| `setPath("/")` | sent for every path of the host. Default: the servlet's directory. `"/"` shares it with the React app |
| `setMaxAge(seconds)` | `-1` (default) = session cookie; `0` = **delete**; `> 0` = persistent |
| `setHttpOnly(true)` | hidden from JavaScript. **Not** set here: the React app reads it; it's a preference, not a secret |
| `setSecure(true)` | HTTPS only (S41, in production) |
| `response.addCookie(cookie)` | adds a `Set-Cookie` header |
| `request.getCookies()` | `Cookie[]` or **`null`** (no cookies); in EL: `${cookie.name.value}` (34.14) |

Servlet 4.0's `Cookie` has no `SameSite` setter: Tomcat adds it for every cookie through its cookie processor (37.14, S41).

## 3. Going back where the user was, safely

The form sends `returnTo` = the page's original URI (the `javax.servlet.forward.request_uri` + query string, 39.08). A redirect target taken from the request is an **open redirect** if not checked (24.14), so `safeReturnTo` accepts only paths inside this application (`/taskflow/…`). The test sends `https://evil.example/` and lands on `/taskflow/tasks`.

## ✅ Checkpoint

`mvn package` → green. Click "Dark theme" on the task list: the page comes back dark, with the same query string. Open the React app on the same host: it's dark too.
