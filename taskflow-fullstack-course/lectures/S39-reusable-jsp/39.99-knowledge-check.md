# Lecture 39.99 · ✅ Knowledge Check: Reusable JSP

> **Section:** S39 · **Type:** ✅ Knowledge Check · **Track:** ★ Core · **Time:** ~15 minutes

---

**1. (Concept)** You edit `header.jspf`. Why might pages not update until they're recompiled?

<details><summary>Answer</summary>

The header's text was pasted into each page's generated servlet at translation (39.02). Jasper re-translates a page when a file in its `_jspx_dependants` changes, but only in development mode, and only when it checks (`checkInterval`, 33.04). With precompiled JSPs, or development mode off, pages keep the old header until a redeploy or a cleared `work/` folder.
</details>

**2. (Design)** Include directive or `<jsp:include>` for: the site header, a widget that needs its own data, a dynamic sidebar chosen per page?

<details><summary>Answer</summary>

Header → **directive** (skeleton, uses page variables, no per-request cost). A widget with its own data → `<jsp:include>` of a **servlet** that loads the data and forwards to its JSP (a self-contained unit), or the controller puts the data in a request attribute and a JSP widget is included. Dynamic sidebar → `<jsp:include page="${sidebarPath}"/>`: only the action accepts an expression (39.04).
</details>

**3. (Concept)** After a forward, what does `${pageContext.request.servletPath}` return, and where is the path the user requested?

<details><summary>Answer</summary>

The forward target's path (the JSP, e.g. `/WEB-INF/views/tasks/list.jsp`). The original is in the request attribute `javax.servlet.forward.servlet_path` (and `…request_uri`, `…query_string`) (39.08, 39.14).
</details>

**4. (Security)** Why does the header allow-list the `tf_theme` cookie instead of printing its value?

<details><summary>Answer</summary>

Cookies are client input: they can be set by a sibling subdomain, a script on a page with an XSS, or the user. Printing one into an attribute would be an injection point. Only `dark` and `light` reach the HTML (39.09).
</details>

**5. (Implementation)** Write a reusable empty-state fragment with a message parameter.

<details><summary>Answer</summary>

```jsp
<%-- WEB-INF/views/common/empty-state.jsp --%>
<%@ page pageEncoding="UTF-8" session="false" trimDirectiveWhitespaces="true" %>
<%@ taglib prefix="c" uri="http://java.sun.com/jsp/jstl/core" %>
<p class="text-muted empty-state"><c:out value="${empty param.message ? 'Nothing to show.' : param.message}"/></p>
```

```jsp
<jsp:include page="/WEB-INF/views/common/empty-state.jsp">
  <jsp:param name="message" value="Nothing is overdue."/>
</jsp:include>
```

It's escaped with `<c:out>`, has a default, and the message is kept ASCII (or passed as a request attribute instead, 39.03).
</details>
