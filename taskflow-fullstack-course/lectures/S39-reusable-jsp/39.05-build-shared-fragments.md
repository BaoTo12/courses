## 1. The header

✍️ `src/main/webapp/WEB-INF/views/common/header.jspf`

```jsp
<%--
  The top of every page, pasted in at TRANSLATION time by <%@ include file="…" %> (33.10, 39.02).
  S34: no Java; ${pageTitle} is a REQUEST attribute set by the controller. S35: JSTL.
  S39: the theme comes from the tf_theme cookie (shared with the React app), through an ALLOW-LIST (39.09);
  the navigation is its own fragment (nav.jspf, static include); the flash message is a separate JSP, included at
  REQUEST time (<jsp:include>, 39.03), because it's a self-contained widget.
--%>
<%@ taglib prefix="c" uri="http://java.sun.com/jsp/jstl/core" %>
<c:set var="theme" value="${cookie.tf_theme.value == 'dark' or cookie.tf_theme.value == 'light' ? cookie.tf_theme.value : ''}"/>
<!doctype html>
<html lang="en"<c:if test="${not empty theme}"> data-theme="${theme}"</c:if>>
<head>
  <meta charset="utf-8">
  <title><c:out value="${pageTitle}"/> · TaskFlow Admin</title>
  <link rel="stylesheet" href="<c:url value='/static/css/app.css'/>">
</head>
<body>
<div class="page">
  <header class="page__header">
    <span class="page__brand">TaskFlow Admin</span>
    <%@ include file="/WEB-INF/views/common/nav.jspf" %>
  </header>
  <main class="page__main">
    <jsp:include page="/WEB-INF/views/common/flash.jsp"/>
```

Two includes inside an include: `nav.jspf` is pasted in (translation time), and `flash.jsp` is called (request time).

## 2. The flash widget

✍️ `src/main/webapp/WEB-INF/views/common/flash.jsp`

```jsp
<%--
  S39 (39.05): the flash message (37.09) as a separate JSP, included at REQUEST time by header.jspf:
  <jsp:include page="/WEB-INF/views/common/flash.jsp"/>. It's its own servlet with its own page scope; it sees the
  request's attributes (flash) and parameters. It sets no content type: the including page owns the response.
--%>
<%@ page pageEncoding="UTF-8" session="false" trimDirectiveWhitespaces="true" %>
<%@ taglib prefix="c" uri="http://java.sun.com/jsp/jstl/core" %>
<c:if test="${not empty flash}"><p class="flash" role="status"><c:out value="${flash}"/></p></c:if>
```

Note the page directive: `pageEncoding` and `session="false"`, but no `contentType`. An included page doesn't own the response.

## 3. The error summary, with a parameter

✍️ `src/main/webapp/WEB-INF/views/common/form-errors.jsp`

```jsp
<%--
  S39 (39.05, 39.06): a summary of a form's errors, reusable by any form page:
    <jsp:include page="/WEB-INF/views/common/form-errors.jsp">
      <jsp:param name="title" value="The category wasn't saved:"/>
    </jsp:include>
  Data in: the request attribute "errors" (Map field → message) and the parameter "title" (${param.title}).
--%>
<%@ page pageEncoding="UTF-8" session="false" trimDirectiveWhitespaces="true" %>
<%@ taglib prefix="c" uri="http://java.sun.com/jsp/jstl/core" %>
<c:if test="${not empty errors}">
      <div class="form-errors" role="alert">
        <p class="form-errors__title"><c:out value="${empty param.title ? 'Please fix the following:' : param.title}"/></p>
        <c:forEach items="${errors}" var="error"><p class="form-field__error"><c:out value="${error.value}"/></p></c:forEach>
      </div>
</c:if>
```

Used by `categories/list.jsp` instead of its own copy:

```jsp
<jsp:include page="/WEB-INF/views/common/form-errors.jsp">
  <jsp:param name="title" value="The category was not saved:"/>
</jsp:include>
```

`errors` arrives as a **request attribute** (a `Map`: attributes carry objects), and `title` as a **parameter** (a string for this one include). 39.06 compares the two.
