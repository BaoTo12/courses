# Lecture 39.07 · Layout Strategies: Includes vs Preludes/Codas vs Tag-File Layouts

> **Section:** S39 · **Type:** 📖 Theory · **Track:** ＋ Extended · **Time:** ~10 minutes

*Extended track: outline.*

---

```xml
<!-- web.xml: automatic includes for every matching JSP -->
<jsp-property-group>
  <url-pattern>/WEB-INF/views/*</url-pattern>
  <include-prelude>/WEB-INF/views/common/header.jspf</include-prelude>
  <include-coda>/WEB-INF/views/common/footer.jspf</include-coda>
</jsp-property-group>
```

- **Explicit includes** (TaskFlow): every page starts with `<%@ include file="…header.jspf" %>` and ends with the footer. Visible and flexible (a page can skip them), but it's two lines to remember per page.
- **Preludes/codas:** the container adds the includes at translation time for every matching JSP. Nothing to forget, but invisible when reading the page, and hard to opt out of (debug pages, fragments, AJAX snippets all get the header).
- **Tag-file layouts** (S44): `<tf:page title="Tasks"> …content… </tf:page>`, where `WEB-INF/tags/page.tag` wraps `<jsp:doBody/>` in the skeleton. The title becomes a declared **attribute** instead of a request attribute set by the controller. It's the closest JSP gets to a template engine's layout.
- **Outside JSP:** Thymeleaf layouts, SiteMesh (a filter that decorates any HTML response), JSF facelets templates.
- TaskFlow keeps explicit includes until S44 introduces tag files.
