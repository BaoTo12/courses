# Lecture 39.12 · 🐞 Debug: "Duplicate local variable" After Including the Same Fragment Twice

> **Section:** S39 · **Type:** 🐞 Debug · **Track:** ★ Core · **Time:** ~15 minutes
> (A legacy-code scenario: since S36, TaskFlow's `<scripting-invalid>` makes the fragment below a translation error of its own.)

---

## 1. The code

A fragment from an older, scriptlet-based app:

```jsp
<%-- price.jspf --%>
<% java.text.NumberFormat fmt = java.text.NumberFormat.getCurrencyInstance(); %>
<%= fmt.format(amount) %>
```

The page shows a subtotal and a total:

```jsp
<% double amount = subtotal; %><%@ include file="price.jspf" %>
<% amount = total; %><%@ include file="price.jspf" %>
```

## 2. The error

```text
org.apache.jasper.JasperException: Unable to compile class for JSP:
An error occurred at line: [2] in the jsp file: [/WEB-INF/views/common/price.jspf]
Duplicate local variable fmt
```

## 3. Why

The directive **pastes text** (39.02). Twice pasted = `NumberFormat fmt = …` declared twice in one `_jspService` method, and Java forbids that. The error names the **fragment** and its line, although the fragment alone is fine: the conflict only exists in the combined method.

## 4. Fixes

| Fix | Why it works |
|---|---|
| **EL/JSTL instead of Java**: `<fmt:formatNumber value="${amount}" type="currency"/>` (S44) | no local variables at all; `<c:set>` twice is fine |
| `<jsp:include>` (with the value in a request attribute) | each include is its own servlet and its own method |
| a tag file `<tf:price amount="${total}"/>` (S44) | a reusable component with a declared attribute |
| wrap scriptlet code in `{ … }` blocks | a scope per paste: works, but it's patching a pattern you should retire |

## ✅ Takeaway

The include directive has no scoping: whatever the fragment declares, the page declares, once per paste. EL/JSTL fragments don't have this problem, which is one more reason for S36's `<scripting-invalid>`.
