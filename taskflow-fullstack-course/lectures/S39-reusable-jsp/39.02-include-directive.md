## 📇 API card: `<%@ include file="…" %>`

```jsp
<%@ include file="/WEB-INF/views/common/header.jspf" %>
```

| Aspect | Behaviour |
|---|---|
| `file` | a path in the web app (leading `/` = from the app root; otherwise relative to the current file) |
| when | at **translation**: Jasper pastes the file's text in place, then compiles one servlet |
| result | **one** `_jspService` method: the fragment shares the page's variables, page scope, taglib prefixes and page directive |
| file extension | `.jspf` by convention ("JSP fragment"): never compiled on its own, and not served (it's under `WEB-INF`) |
| encoding | from `jsp-config` (33.19: without `<page-encoding>` for `*.jspf`, fragments were read as ISO-8859-1) |
| changes picked up | Jasper records each included file in `_jspx_dependants` and re-translates the page when one changes (development mode) |

What Jasper generated for the list page shows both effects:

```java
_jspx_dependants.put("/WEB-INF/views/common/nav.jspf", Long.valueOf(1790427975894L));      // "recompile me if this changes"
_jspx_dependants.put("/WEB-INF/views/common/header.jspf", Long.valueOf(1790428000607L));
…
out.write("      <a class=\"page__nav-link");                                              // nav.jspf's text, INLINE in list_jsp
```

**When to use:** the page skeleton (header, nav, footer) and fragments that need the page's own variables (the task row inside a loop, 39.10).
**When not to:** a self-contained widget with its own logic, or a piece that you want to change without recompiling every page → `<jsp:include>` (39.03).

**Common mistakes:**
- A variable **declared** in a fragment included twice → "Duplicate local variable" (39.12). With `<c:set>` there's no such problem: setting twice is fine.
- Relying on something the fragment doesn't declare (a taglib prefix, a variable): the fragment only works in some pages. TaskFlow's fragments declare their own taglibs and document what they expect.

## ✅ Recap

The include directive pastes text before compilation: one servlet, shared variables, and fast. The price is that pages must be re-translated when a fragment changes.
