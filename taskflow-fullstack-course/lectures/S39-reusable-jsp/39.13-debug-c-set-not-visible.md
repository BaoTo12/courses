# Lecture 39.13 · 🐞 Debug: An Included Fragment Can't See a `<c:set>` Variable

> **Section:** S39 · **Type:** 🐞 Debug · **Track:** ★ Core · **Time:** ~15 minutes

---

## 1. The code

```jsp
<%-- list.jsp --%>
<c:set var="emptyMessage" value="No tasks match your filters."/>
<jsp:include page="/WEB-INF/views/common/empty-state.jsp"/>

<%-- empty-state.jsp --%>
<p class="text-muted"><c:out value="${emptyMessage}"/></p>
```

## 2. Symptom

The paragraph renders **empty**. No error.

## 3. Investigate

- `<c:set>` without `scope` stores in **page** scope (35.10): the `PageContext` of `list.jsp`.
- `<jsp:include>` runs `empty-state.jsp` as a **separate servlet** with its **own** `PageContext` (39.03). Its page scope is empty.
- `${emptyMessage}` searches page → request → session → application of the **included** JSP: nothing → `""` (34.03).

## 4. Fixes

| Fix | Code |
|---|---|
| pass it as a parameter (a string) | `<jsp:include page="…"><jsp:param name="message" value="No tasks match your filters."/></jsp:include>` → `${param.message}` |
| put it in request scope | `<c:set var="emptyMessage" value="…" scope="request"/>` |
| use the include **directive** | the fragment becomes part of `list.jsp`: same page scope |
| a tag file with an attribute (S44) | `<tf:emptyState message="…"/>` |

The same symptom appears with `<c:forEach var="task">` around a `<jsp:include>`: the loop variable is page-scoped (39.11).

## ✅ Takeaway

`<jsp:include>` shares the **request**, not the page. Anything the included JSP needs must be a request attribute or a parameter.
