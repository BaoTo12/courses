# Lecture 24.03 · `document.cookie`: The Awkward Native API

> **Section:** S24 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~20 minutes
> 🔗 Reference: MDN, "Document: cookie property"

---

## 1. It looks like a string, but it isn't one

```js
document.cookie = 'theme=dark; path=/; max-age=31536000; samesite=lax';  // ADDS or UPDATES one cookie
document.cookie = 'lang=vi; path=/';                                     // adds another; theme is still there
document.cookie;                                                          // "theme=dark; lang=vi" ← all of them, values only
```

- **The setter** takes **one** cookie with attributes, and it doesn't replace the others.
- **The getter** returns **all** visible cookies for the current page, as `name=value` pairs joined by `"; "`, with **no attributes**. You can't read a cookie's path or expiry from JavaScript.
- `HttpOnly` cookies are **not in the getter** at all (24.07).

## 2. What you have to do by hand

| Task | Native |
|---|---|
| Read one cookie | split on `"; "`, find the name, `decodeURIComponent` the value |
| Write safely | encode `;`, `,`, spaces and non-ASCII in the value (`encodeURIComponent`), then append each attribute |
| Expire in N days | compute a UTC date string, or use `max-age` |
| Delete | write it again with the **same path/domain** and a past `expires` (or `max-age=0`) |

```js
// Reading, the "classic" way:
function getCookie(name) {
  return document.cookie
    .split('; ')
    .find((pair) => pair.startsWith(name + '='))
    ?.slice(name.length + 1);          // still encoded! decodeURIComponent it yourself
}
```

Classic bugs: forgetting to decode, matching `theme` inside `theme2=…`, a value containing `;` that silently truncates the cookie, and deleting without the right path.

## 3. Hence js-cookie

js-cookie (≈800 bytes) wraps exactly these chores: encoding and decoding, attributes as an object, `expires` in days, and `remove` with attributes. It adds no magic. It still can't see `HttpOnly` cookies, and it can't read attributes, because the browser doesn't expose them.

## ✅ Recap

- The setter writes **one** cookie; the getter reads **all** of them, values only.
- Encoding, parsing and deleting are manual, and each is a bug waiting to happen. js-cookie handles them (24.04).
