## 📇 API card

| Function | Signature | Returns |
|---|---|---|
| `Cookies.get` | `(name: string) => string \| undefined` | the decoded value, or `undefined` |
| `Cookies.get` | `() => { [name: string]: string }` | all visible cookies |
| `Cookies.set` | `(name, value: string, attributes?) => string \| undefined` | the written cookie string |
| `Cookies.remove` | `(name, attributes?) => void` | — (**pass the same `path`/`domain` as `set`**) |
| `Cookies.withAttributes` | `(defaults) => CookiesStatic` | a new instance whose `set`/`remove` use these defaults |
| `Cookies.withConverter` | `({ read?, write? }) => CookiesStatic` | a new instance with custom encoding |

### `attributes`

| Attribute | Type | Default | Meaning |
|---|---|---|---|
| `expires` | `number` (days) \| `Date` | none → **session cookie** | `7` = in 7 days; `0.5` = 12 hours |
| `path` | `string` | `'/'` | js-cookie's default is `/`, **not** the browser's "current directory" |
| `domain` | `string` | host-only | only for sharing with subdomains |
| `secure` | `boolean` | `false` | HTTPS only |
| `sameSite` | `'strict' \| 'lax' \| 'none'` | not written (the browser treats it as `Lax`) | cross-site behaviour (24.02) |

There is **no `httpOnly`** attribute. JavaScript can't create `HttpOnly` cookies, so js-cookie doesn't pretend it can.

## 2. Examples (outside TaskFlow)

```ts
Cookies.set('consent', 'analytics', { expires: 180, sameSite: 'lax', secure: true });
Cookies.get('consent');            // 'analytics'
Cookies.remove('consent');         // path '/' (the default) → matches the set above

// Defaults for a whole app: one configured instance
const appCookies = Cookies.withAttributes({ path: '/', sameSite: 'lax', secure: location.protocol === 'https:' });
appCookies.set('layout', 'compact', { expires: 365 });

// A cookie written by another system with its own encoding (e.g. '+' for spaces)
const legacy = Cookies.withConverter({ read: (value) => decodeURIComponent(value.replace(/\+/g, ' ')) });
legacy.get('legacy_name');
```

## 3. Values are strings

`Cookies.set('prefs', { a: 1 })` isn't allowed in v3. Serialise it yourself: `JSON.stringify` to write, `JSON.parse` in a `try` to read, then **validate** the shape (24.06). js-cookie encodes the characters that would break the cookie format. You still choose what goes in.

**When to use js-cookie:** any JavaScript-side cookie reading or writing.

**When not to:**
- The server should own the cookie → `Set-Cookie` from the server (sessions: always).
- Client-only data the server never needs → `localStorage`. It isn't sent with every request.
- Secrets → nowhere JavaScript can read (24.08).

**Common mistakes:**
- `remove` with a different `path` than `set`. Nothing is removed (24.18).
- Expecting `get` to return an `HttpOnly` cookie. It returns `undefined` (24.19).
- Storing objects without `JSON.stringify`, or parsing without `try`.
- `secure: true` during local `http://` development. The browser silently refuses to store the cookie.
