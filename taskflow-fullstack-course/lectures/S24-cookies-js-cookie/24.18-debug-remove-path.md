# Lecture 24.18 · 🐞 Debug: `Cookies.remove('theme')` Doesn't Remove It

> **Section:** S24 · **Type:** 🐞 Debug · **Track:** ★ Core · **Time:** ~20 minutes
> Verified by: `src/api/cookies.test.ts` ("a cookie set on another path is NOT removed by remove() on '/'"; jsdom)

---

## 1. The report

> "Reset preferences doesn't reset the theme. The code calls `Cookies.remove('theme')`, no error, but after a reload it's still dark."

## 2. The code (before the S24 wrapper)

```ts
// Settings page, mounted at /app/settings:
Cookies.set('theme', 'dark', { path: '/app', expires: 365 });   // "only the app needs it"
// Reset button, in a shared utility:
Cookies.remove('theme');                                          // default path: '/'
```

## 3. Investigate

1. DevTools → Application → Cookies: there's a `theme` row with **Path `/app`**.
2. In the console on `/app/settings`: `document.cookie` includes `theme=dark`. Run `Cookies.remove('theme')`, and it's still there.
3. Why: a cookie's identity is **name + domain + path** (24.02 §1). `remove` writes `theme=; path=/; expires=<past>`, which targets a **different** cookie (`theme` on `/`). That one doesn't exist, so nothing happens, and the browser reports no error.
4. A second symptom: on the page `/tasks`, `Cookies.get('theme')` returns `undefined`, because a `/app` cookie isn't visible outside `/app`. The test shows this in jsdom: `document.cookie` lists only cookies whose path matches the current page.

## 4. Fix

- Immediate: `Cookies.remove('theme', { path: '/app' })`, **the same attributes as `set`** (including `domain` if one was used).
- Structural: **one configured instance** (`Cookies.withAttributes({ path: '/', … })`) used for both `set` and `remove`. That's exactly what `cookies.ts` does (24.05), so the mismatch can't happen.

## 5. Clean-up for existing users

Users who already have the old `/app` cookie keep it until it expires. Remove the legacy one once, at start-up: `Cookies.remove('theme', { path: '/app' })`.

## ✅ Takeaway

Delete with the **exact** path and domain you set with. Centralise the attributes so `set` and `remove` can't disagree.
