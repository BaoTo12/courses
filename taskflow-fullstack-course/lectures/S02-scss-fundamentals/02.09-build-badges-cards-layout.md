## 1. Badges ✍️

`styles/components/_badge.scss`:

```scss
@use '../abstracts/variables' as *;

.badge {
  display: inline-flex;
  align-items: center;
  padding: 2px $space-2;
  border-radius: $radius-full;
  font-size: 0.75rem;
  font-weight: $font-weight-semibold;
  line-height: 1.5;
  white-space: nowrap;

  // Status: background + foreground pairs
  &--todo {
    background: $color-status-todo-bg;
    color: $color-status-todo-fg;
  }

  &--in-progress {
    background: $color-status-in-progress-bg;
    color: $color-status-in-progress-fg;
  }

  &--done {
    background: $color-status-done-bg;
    color: $color-status-done-fg;
  }

  // Priority: coloured outline style
  &--priority-low {
    color: $color-priority-low;
    box-shadow: inset 0 0 0 1px $color-priority-low;
  }

  &--priority-medium {
    color: $color-priority-medium;
    box-shadow: inset 0 0 0 1px $color-priority-medium;
  }

  &--priority-high {
    color: $color-priority-high;
    box-shadow: inset 0 0 0 1px $color-priority-high;
  }
}
```

Notice the repetition. Six nearly identical blocks, and adding a `BLOCKED` status means editing variables *and* this file. Remember this feeling. In **03.07** a map + `@each` loop will generate all of these from data.

> Why `box-shadow: inset …` instead of `border`? An inset shadow draws an outline **without** changing the element's size, so status and priority badges stay the same height.

> 🛡 **Accessibility note:** status is shown with **text** ("In progress") and colour, never colour alone. Colour-only indicators fail for colour-blind users.

## 2. Cards ✍️

`styles/components/_card.scss`:

```scss
@use '../abstracts/variables' as *;

.card {
  position: relative;
  display: flex;
  flex-direction: column;
  gap: $space-2;
  padding: $space-4;
  padding-left: $space-4 + $space-1;     // room for the priority stripe
  background: $color-surface;
  border: 1px solid $color-border;
  border-radius: $radius-lg;
  box-shadow: $shadow-sm;
  overflow: hidden;
  transition: box-shadow 150ms ease;

  &:hover {
    box-shadow: $shadow-md;
  }

  // Priority stripe on the left edge
  &::before {
    content: '';
    position: absolute;
    inset: 0 auto 0 0;       // top:0; right:auto; bottom:0; left:0
    width: $space-1;
    background: $color-border;
  }

  &--priority-low::before    { background: $color-priority-low; }
  &--priority-medium::before { background: $color-priority-medium; }
  &--priority-high::before   { background: $color-priority-high; }

  &__title {
    font-size: $font-size-lg;
    font-weight: $font-weight-semibold;
    line-height: 1.3;

    a {
      color: inherit;
      text-decoration: none;

      &:hover {
        color: $color-primary;
        text-decoration: underline;
      }
    }
  }

  &__body {
    color: $color-text-muted;
    font-size: $font-size-sm;
  }

  &__meta {
    display: flex;
    align-items: center;
    justify-content: space-between;
    margin-top: auto;           // push the footer to the bottom of equal-height cards
    padding-top: $space-2;
  }

  &__due {
    font-size: 0.75rem;
    color: $color-text-muted;

    &--overdue {
      color: $color-danger;
      font-weight: $font-weight-semibold;
    }
  }
}
```

### Things worth understanding

- **`&--priority-high::before`** compiles to `.card--priority-high::before`. The modifier changes a pseudo-element of the same element.
- **`&__title a`** is a descendant selector (`.card__title a`), one of the few places we nest a structural element, because the link inside the title is plain HTML without its own class. Specificity: (0,1,1). Fine.
- **`&__due--overdue`**: `&` here is `.card__due`, so this compiles to `.card__due--overdue` (an element modifier). `&` always refers to the *full* parent selector at that point.
- **`margin-top: auto`** in a flex column pushes the meta row to the bottom so cards in a row line up.

## 4. Wire everything into `main.scss`

```scss
@use 'base/reset';
@use 'abstracts/variables' as *;

@use 'layout/page';
@use 'layout/kit';
@use 'components/button';
@use 'components/badge';
@use 'components/card';

body {
  font-family: $font-family-base;
  background: $color-background;
  color: $color-text;
}
```

**Order matters for the output**, not for variable visibility. CSS rules appear in `main.css` in the order modules are first `@use`d. Base → layout → components is a sensible cascade: later, more specific layers can override earlier generic ones at equal specificity.

Refresh the UI kit. You should now see a header with nav, styled badges, a responsive grid of cards with priority stripes, and hover shadows.

## 7. Summary

- Badges: status (bg/fg pairs) and priority (outline) modifiers. Repetitive on purpose; fixed with maps in S03.
- Cards: priority stripe via `::before` + modifiers; BEM elements with `&__`; element modifiers with `&--` inside elements.
- Layout: page grid, header/nav, responsive task grid with a nested media query.
- `main.scss` order defines CSS output order: base → layout → components.
