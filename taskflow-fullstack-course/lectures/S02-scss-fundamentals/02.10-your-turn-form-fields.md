# Lecture 02.10 · 🎯 Your Turn: Form Fields

> **Section:** S02 · **Type:** 🎯 Your Turn · **Track:** ★ Core · **Time:** ~40 minutes
> **Deliverable:** `styles/components/_form.scss`, loaded in `main.scss`

---

## 1. The task

Style the **Form fields** section of `ui-kit/index.html`. The HTML is already there (from 02.03). Don't change the HTML; only write SCSS.

Classes to style:

| Class | Element |
|---|---|
| `.form` | The `<form>`: vertical stack of fields |
| `.form-field` | Wrapper for label + control + help/error |
| `.form-field__label` | `<label>` |
| `.form-field__input` | `<input>`, `<select>`, `<textarea>` |
| `.form-field__help` | Help text under the control |
| `.form-field__error` | Error text under the control |
| `.form-field--error` | Modifier on the wrapper when the field is invalid |
| `.form__actions` | Row of buttons at the bottom |

---

## 2. Requirements

1. **Layout:** fields stacked vertically with consistent spacing (use the spacing tokens). Label above the control. Max form width ~560px.
2. **Label:** small (`$font-size-sm`), medium weight, a little space below.
3. **Controls:** full width; same height for `input` and `select`; `textarea` resizes **vertically only**; border, radius and padding from tokens; white background.
4. **Focus state:** a clearly visible focus style using the primary colour (border colour change **and** a soft ring). Use `:focus-visible` or `:focus`. Explain your choice in a comment.
5. **Placeholder:** muted colour.
6. **Help text:** small, muted.
7. **Error state** (`.form-field--error`): the control's border becomes the danger colour, the focus ring becomes danger-coloured too, and `.form-field__error` is small, danger-coloured and medium weight.
8. **Also** style controls with `[aria-invalid='true']` as invalid, even without the wrapper modifier. (Why? Think about JSP/React later setting only the attribute.)
9. **Disabled controls:** muted background, `not-allowed` cursor.
10. **Actions row:** buttons on one line with spacing, separated a bit from the last field.
11. **Specificity budget:** no selector more specific than (0,3,0) / (0,2,1). No `!important`.
12. Use only tokens from `_variables.scss` (add new tokens if you need them, with good names).

## 3. Acceptance checklist

- [ ] The form looks consistent with buttons and cards (same radius, border colour, font sizes).
- [ ] Tabbing through the form shows a visible focus indicator on every control.
- [ ] The **Due date** field (which has `.form-field--error`) shows red border + red error message.
- [ ] A control with only `aria-invalid="true"` (test by adding it in DevTools) also looks invalid.
- [ ] The textarea can be resized vertically but not horizontally.
- [ ] Compiled CSS contains no selector deeper than two classes plus pseudo-classes.

## 4. Hints (open one at a time, only if stuck)

<details>
<summary>Hint 1: making input and select the same height</summary>

Give both the same `padding`, `font-size`, `line-height` and `border`. Selects have browser-specific internal padding; `appearance: none` gives you full control, but then you must draw the dropdown arrow yourself. It's optional here.
</details>

<details>
<summary>Hint 2: a "soft ring"</summary>

`box-shadow: 0 0 0 3px <primary colour at low opacity>`. Use `color.change($color-primary, $alpha: 0.2)` from `sass:color`.
</details>

<details>
<summary>Hint 3: error styles that depend on the wrapper</summary>

Inside `.form-field { &--error { … } }`, you can target the child control with `.form-field__input` inside the modifier block. Check the compiled selector's specificity.
</details>

<details>
<summary>Hint 4: aria-invalid</summary>

Inside `&__input { … }`, `&[aria-invalid='true']` compiles to `.form-field__input[aria-invalid='true']`, specificity (0,2,0).
</details>
