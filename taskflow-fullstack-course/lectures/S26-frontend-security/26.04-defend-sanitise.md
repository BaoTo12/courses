# Lecture 26.04 · 🛡 Defend: Render as Text; if HTML Is Truly Needed, DOMPurify with a Strict Allow-List

> **Section:** S26 · **Type:** 🛡 Defence · **Track:** ★ Core · **Time:** ~50 minutes
> **Project feature:** comments are plain text by default. A "Show formatting" checkbox renders the **same** bodies as sanitised HTML (bold, lists, code, safe links).
> Verified: `src/security/security.test.tsx` ("sanitizeHtml": formatting kept; `onerror`, `<script>`, `style`, `onclick`, SVG tricks removed; `javascript:` links dropped; safe links forced to `target=_blank rel=noopener noreferrer`; jsdom), `tsc`, lint.

---

## 1. First choice: don't render HTML at all

The 26.03 fix that solves 95% of cases is **no fix at all**: `<p>{comment.body}</p>`. React escapes it, the payload shows as harmless text, and `white-space: pre-wrap` keeps line breaks. **Ask whether you really need HTML.** Often Markdown rendered to React elements (26.05's approach) or `<Trans>` (25.03) does the job without HTML strings.

## 2. When HTML is a requirement: sanitise with DOMPurify

```bash
npm install dompurify      # v3 ships its own types
```

✍️ `src/security/markup.ts`

```ts
// S26: two ways to let users format text, both without handing them raw HTML in our page.
import DOMPurify from 'dompurify';

// ── 1. Links in descriptions: a tiny markdown subset, parsed into DATA, rendered by React (26.05) ─────

export type TextSegment = { kind: 'text'; text: string } | { kind: 'link'; label: string; url: string };

const LINK = /\[([^\]\n]{1,200})\]\(([^)\s]{1,2000})\)/g;

/** "See [the spec](https://x.test/spec)." → text, link, text. The URL is NOT validated here: SafeLink does. */
export function parseLinks(text: string): TextSegment[] {
  const segments: TextSegment[] = [];
  let last = 0;
  for (const match of text.matchAll(LINK)) {
    const [whole, label = '', url = ''] = match;
    if (match.index > last) segments.push({ kind: 'text', text: text.slice(last, match.index) });
    segments.push({ kind: 'link', label, url });
    last = match.index + whole.length;
  }
  if (last < text.length) segments.push({ kind: 'text', text: text.slice(last) });
  return segments;
}

// ── 2. "Show formatting" for comments: HTML, sanitised with DOMPurify and a STRICT allow-list (26.04) ──

const ALLOWED_TAGS = ['b', 'strong', 'i', 'em', 'u', 'code', 'pre', 'p', 'br', 'ul', 'ol', 'li', 'blockquote', 'a'];
const ALLOWED_ATTR = ['href']; // no style, no class, no on* handlers, no src

let hooksInstalled = false;
function installHooks() {
  if (hooksInstalled) return;
  hooksInstalled = true;
  // Every surviving link opens in a new tab without window.opener (same policy as SafeLink).
  DOMPurify.addHook('afterSanitizeAttributes', (node) => {
    if (node.tagName === 'A') {
      node.setAttribute('target', '_blank');
      node.setAttribute('rel', 'noopener noreferrer');
    }
  });
}

/**
 * Untrusted HTML → HTML that can't run script. DOMPurify parses it with the BROWSER's parser (so what it checks is
 * what the browser would build), removes everything not allowed, and drops dangerous URLs (`javascript:`…).
 * The result must go into the DOM AS IS: modifying it afterwards voids the guarantee (26.14).
 */
export function sanitizeHtml(dirty: string): string {
  installHooks();
  return DOMPurify.sanitize(dirty, {
    ALLOWED_TAGS,
    ALLOWED_ATTR,
    ADD_ATTR: ['target'], // allowed so our hook's value survives; the hook overwrites whatever the user wrote
    ALLOWED_URI_REGEXP: /^(?:https?:|mailto:|\/)/i, // same allow-list as safeHref
  });
}
```

Why each choice:

| Setting | Why |
|---|---|
| **`ALLOWED_TAGS`** (an allow-list) | everything not listed is removed: `img`, `svg`, `iframe`, `form`, `style`, `script`, `math`… You never need to know every attack vector |
| **`ALLOWED_ATTR: ['href']`** | no `on*` handlers, no `style` (CSS attacks), no `src`, no `class` (overlaying our UI) |
| **`ALLOWED_URI_REGEXP`** | the same protocol allow-list as `safeHref` (26.06): `javascript:` and `data:` hrefs are dropped |
| **`afterSanitizeAttributes` hook** | policy on what survives: every link gets `target="_blank"` and `rel="noopener noreferrer"`, whatever the user wrote |
| **DOMPurify parses with the browser's parser** | it checks what the browser *will* build, not a regex's idea of HTML (mXSS, namespace confusion) |

## 3. The one place HTML goes into the DOM

✍️ `src/security/RichText.tsx`

```tsx
import { useMemo } from 'react';
import { SafeLink } from './SafeLink';
import { parseLinks, sanitizeHtml } from './markup';

/** Plain text with `[label](url)` links (26.05): React renders every piece; no HTML is ever parsed. */
export function LinkifiedText({ text }: { text: string }) {
  const segments = useMemo(() => parseLinks(text), [text]);
  return (
    <>
      {segments.map((segment, index) =>
        segment.kind === 'text' ? (
          segment.text
        ) : (
          <SafeLink key={index} href={segment.url}>
            {segment.label}
          </SafeLink>
        ),
      )}
    </>
  );
}

/**
 * User HTML, sanitised (26.04). The ONLY `dangerouslySetInnerHTML` in TaskFlow, and its input is always the
 * direct output of `sanitizeHtml`. Grep for the prop name in review: every hit must look like this one.
 */
export function SanitizedHtml({ html, className }: { html: string; className?: string }) {
  const clean = useMemo(() => sanitizeHtml(html), [html]);
  return <div className={className} dangerouslySetInnerHTML={{ __html: clean }} />;
}
```

- `SanitizedHtml` is TaskFlow's **only** `dangerouslySetInnerHTML`, and its input is always `sanitizeHtml(...)`'s direct output. Nothing modifies the string in between (26.14 shows why).
- `useMemo` keys the sanitising on `html`, so it doesn't re-run on every render.

In `CommentsSection`:

```tsx
  // 26.04: plain text by default; "Show formatting" renders the SAME bodies as sanitised HTML.
  const [showFormatting, setShowFormatting] = useState(false);
  …
            {showFormatting ? <SanitizedHtml html={comment.body} /> : <p>{comment.body}</p>}
```

## 5. Store raw, sanitise on output

The server keeps the body **exactly as typed** (`server.mjs`: "escaping is the job of whoever RENDERS it"). Sanitising **on output** means that:

- a sanitiser upgrade protects old data too;
- the JSP admin portal can apply its **own** encoding for its context (S43);
- nothing is lost if the policy is loosened later.

## 📇 API card: `DOMPurify.sanitize(dirty, config?)`

| Config | Meaning |
|---|---|
| `ALLOWED_TAGS` / `ALLOWED_ATTR` | replace the defaults (an allow-list) |
| `ADD_TAGS` / `ADD_ATTR` | extend the defaults |
| `FORBID_TAGS` / `FORBID_ATTR` | block-list on top (rarely needed with an allow-list) |
| `ALLOWED_URI_REGEXP` | which URLs `href`/`src` may have |
| `USE_PROFILES: { html: true }` | the default HTML profile (instead of explicit lists) |
| `RETURN_DOM` / `RETURN_DOM_FRAGMENT` | return nodes instead of a string |
| `RETURN_TRUSTED_TYPE` | integrate with Trusted Types (a CSP feature, S40) |

`DOMPurify.addHook(name, fn)` with `'uponSanitizeElement'`, `'afterSanitizeAttributes'`, … adjusts the result (TaskFlow's link policy). Hooks are **global** to the DOMPurify instance.

**When to use:** user-authored HTML must be displayed (rich-text editors, imported emails, CMS content).

**When not to:** plain text (use React's escaping), or Markdown (render to elements). Never as a replacement for escaping in server templates.

**Common mistakes:** sanitising and then modifying the string (26.14); sanitising on input only and trusting the database forever; a permissive profile "for now"; running DOMPurify on the server without a DOM (it needs `jsdom` there).
