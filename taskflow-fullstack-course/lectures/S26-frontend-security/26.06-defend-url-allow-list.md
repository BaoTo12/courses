# Lecture 26.06 · 🛡 Defend: A URL Protocol Allow-List and `SafeLink`

> **Section:** S26 · **Type:** 🛡 Defence · **Track:** ★ Core · **Time:** ~40 minutes
> **Project feature:** `[label](url)` links in task descriptions render through `SafeLink`: http, https and mailto only, external links open safely, and anything else is shown as plain text.
> Verified: `src/security/security.test.tsx` ("safeHref": 4 allowed, 7 refused incl. `JaVaScRiPt:`, a leading space and a tab inside the scheme; "SafeLink": markup for safe and unsafe; jsdom), `tsc`, lint.

---

## 1. The validator

✍️ `src/security/safeUrl.ts`

```ts
// S26 (26.06): a URL from a user is attacker-controlled input. Allow-list the PROTOCOL; never block-list.

const ALLOWED_PROTOCOLS = new Set(['http:', 'https:', 'mailto:']);

/**
 * The URL to put in an href, or `undefined` if it isn't safe to link to.
 * - Parsed with the URL API (the same parser the browser uses), so tricks like `JaVaScRiPt:`, `java\tscript:`,
 *   leading spaces or entity-encoding don't slip past a string check.
 * - Relative URLs resolve against the app's origin and are allowed (they stay on our site).
 * - Anything else (`javascript:`, `data:`, `vbscript:`, `file:`, custom app schemes) is refused.
 */
export function safeHref(raw: string, base = window.location.origin): string | undefined {
  let url: URL;
  try {
    url = new URL(raw.trim(), base);
  } catch {
    return undefined; // not a URL at all
  }
  return ALLOWED_PROTOCOLS.has(url.protocol) ? url.href : undefined;
}

/** True when the URL leaves our origin: open it in a new tab, without giving it `window.opener`. */
export function isExternal(href: string, base = window.location.origin): boolean {
  return new URL(href, base).origin !== new URL(base).origin;
}
```

- **An allow-list**: three protocols we understand. A block-list (`!url.startsWith('javascript:')`) loses to `JaVaScRiPt:`, `java\tscript:` (browsers strip tabs and newlines inside URLs), `&#106;avascript:` in HTML contexts, and the next scheme nobody thought of.
- **`new URL(raw, base)`** is the WHATWG parser the browser itself uses. It lower-cases the scheme, removes the tab, and resolves relative URLs. We check the **parsed** protocol, which is what the browser would use.
- It **returns the normalised `href`** that was checked. Using the raw input after checking the parsed one would reopen the gap between "what we checked" and "what we use".
- `base` is injectable for tests. The app uses `window.location.origin`.

## 2. The component

✍️ `src/security/SafeLink.tsx`

```tsx
import type { ReactNode } from 'react';
import { isExternal, safeHref } from './safeUrl';

interface SafeLinkProps {
  /** Untrusted: typed by a user, stored by the server, shown to OTHER users. */
  href: string;
  children: ReactNode;
}

/**
 * S26 (26.06): the only way TaskFlow renders a user-supplied URL.
 * - unsafe protocol → plain text (the user still sees what was written, nothing is clickable);
 * - external → new tab with `rel="noopener noreferrer"`: the other site gets no `window.opener`
 *   (reverse tabnabbing) and no Referer (our URLs may contain ids);
 * - the real target is shown in `title`, so a label like "Google" can't hide where it goes.
 */
export function SafeLink({ href, children }: SafeLinkProps) {
  const safe = safeHref(href);
  if (safe === undefined) return <span className="text-muted">{children}</span>;
  const external = isExternal(safe);
  return (
    <a href={safe} title={safe} {...(external ? { target: '_blank', rel: 'noopener noreferrer' } : {})}>
      {children}
    </a>
  );
}
```

- Unsafe URL → **text**, not a removed link. The user still sees what was written, and nothing silently disappears.
- External → `target="_blank" rel="noopener noreferrer"`. `noopener` removes `window.opener`, and `noreferrer` keeps our URLs (with task ids) out of the other site's logs.
- `title={safe}` shows the real destination on hover.

## 3. Using it

✍️ `src/security/RichText.tsx`: `LinkifiedText` maps `parseLinks` segments to text or `<SafeLink>`. In `TaskDetailsPage`:

```tsx
      {/* `[label](url)` links become SafeLinks (26.06); everything else stays text. */}
      <p>{task.description ? <LinkifiedText text={task.description} /> : <span className="text-muted">{t('details.noDescription')}</span>}</p>
```

`parseLinks` deliberately **doesn't** validate. Parsing and policy are separate, and the test shows it happily extracts `javascript:alert(1` (the regex stops at the first `)`). `SafeLink` is the single place where the policy lives.

## 4. The same rule elsewhere

| Sink | Use |
|---|---|
| `<a href>` with user data | `SafeLink` |
| `window.open(url)`, `location.assign(url)` | `const safe = safeHref(url); if (safe) window.open(safe, '_blank', 'noopener')` |
| redirects after login | `safeReturnTo` (24.14): **internal paths only**, a stricter allow-list |
| URLs sent to the server | the server validates again (S41). The client check is UX plus defence in depth. |
