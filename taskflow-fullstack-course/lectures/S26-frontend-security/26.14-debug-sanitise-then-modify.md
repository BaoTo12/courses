# Lecture 26.14 · 🐞 Debug: DOMPurify's Output Still Triggers an Alert

> **Section:** S26 · **Type:** 🐞 Debug · **Track:** ＋ Extended · **Time:** ~15 minutes

*Extended track: outline.*

---

**The code**

```tsx
const clean = sanitizeHtml(comment.body);
// "Highlight the author's name": done AFTER sanitising
const html = clean.replace('{author}', `<b>${author.displayName}</b>`);
return <div dangerouslySetInnerHTML={{ __html: html }} />;
```

**Symptom:** a user with the display name `<img src=x onerror=alert(1)>` triggers an alert for every reader. "But we use DOMPurify!"

**Diagnosis:** DOMPurify guarantees its **output**. The string that reaches the DOM is `clean` **plus** unsanitised data inserted afterwards. Also watch for:

- string concatenation of two sanitised fragments: HTML parsing isn't compositional (`<a title="` + `">…` can create new markup);
- sanitising **before** decoding: `decodeURIComponent(sanitize(x))` re-introduces what was removed;
- sanitising in one context and using it in another: HTML-sanitised text put into an attribute, a URL or a `<script>` block.

**Fix:** sanitise **last**, immediately before the sink, on the final string:

```tsx
const html = sanitizeHtml(comment.body.replace('{author}', `<b>${escapeHtml(author.displayName)}</b>`));
```

Better: don't build HTML at all. Render `<b>{author.displayName}</b>` as a React element next to `<SanitizedHtml html={comment.body} />`.

**Rule:** the output of a sanitiser goes **directly** to its sink. TaskFlow enforces this structurally: `SanitizedHtml` takes the dirty string and sanitises inside the component, so there's no gap to insert anything.
