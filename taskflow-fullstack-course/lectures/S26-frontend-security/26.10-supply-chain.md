## 1. You run other people's code

TaskFlow Web lists about 15 direct dependencies and installs roughly 100 packages. Every one of them runs **inside your origin** in the browser (26.07 §4), and **on your machine** during `npm install` (install scripts). Real incidents: `event-stream` (a maintainer handed over the package, and a Bitcoin-wallet stealer was added), `ua-parser-js` (a hijacked account published malware), `colors`/`faker` (a maintainer sabotaged their own packages), and typosquats such as `crossenv` for `cross-env`.

## 2. The toolbox

| Tool | What it does | TaskFlow |
|---|---|---|
| **`package-lock.json`** | pins the **exact** version and integrity hash of every package, transitively | committed ✅ |
| **`npm ci`** | installs exactly the lockfile; fails if `package.json` disagrees | use in CI and in the WAR build (S49) |
| **`npm audit`** | compares installed versions with the advisory database | `found 0 vulnerabilities` today |
| `npm audit fix` | updates within your semver ranges | review the diff; `--force` may jump major versions |
| **Version ranges** | `^3.4.16` allows 3.x.y ≥ 3.4.16 | fine **with** a lockfile. The lockfile is what pins. |
| `npm install --ignore-scripts` / `ignore-scripts=true` in `.npmrc` | blocks install scripts | consider it for CI |
| **Renovate / Dependabot** | PRs for updates, one at a time | the "update regularly, in small steps" habit |

## 3. Before adding a dependency

- **Is it the right package?** Check the exact name (typosquatting), the repository link, the weekly downloads, the maintainers, and the last publish date.
- **Do you need it?** `left-pad` is one line. DOMPurify (26.04) and i18next are worth it: hard problems, well maintained.
- **What does it pull in?** `npm view <pkg> dependencies`, or check bundlephobia.

## 4. CDN scripts: Subresource Integrity

When a script comes from a CDN instead of your bundle:

```html
<script src="https://cdn.jsdelivr.net/npm/dompurify@3.4.16/dist/purify.min.js"
        integrity="sha384-<base64 hash of that exact file>"
        crossorigin="anonymous"></script>
```

The browser hashes the downloaded file and **refuses to run it** if the hash differs. A compromised CDN can't swap the code. A version-less URL (`…/dompurify/dist/…`) can't have SRI, because its content changes.

TaskFlow bundles everything through Vite, so the question disappears. SRI matters for the JSP portal (S44), if it uses CDN assets.

## ✅ Recap

Commit the lockfile, install with `npm ci`, audit regularly, update in small steps, vet new packages, and use SRI for anything loaded from a CDN.
