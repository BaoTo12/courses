# Lecture 26.02 · Why React Is Safe by Default, and Where It Isn't

> **Section:** S26 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~30 minutes
> Verified: `src/security/security.test.tsx` ("what React 19 does by itself": escaped text and attributes; `javascript:` href replaced; `data:` passed through; `dangerouslySetInnerHTML` inserted unchanged)

---

## 1. What React does for you

```tsx
<p title={userTitle}>{userText}</p>
```

With `userText = '<img src=x onerror=alert(1)>'` and `userTitle = '"><script>'`, React renders:

```html
<p title="&quot;&gt;&lt;script&gt;">&lt;img src=x onerror=alert(1)&gt;</p>
```

- **Text children** become text nodes. `<` is data, never markup.
- **Attribute values** are escaped, so they can't break out of the quotes.
- **`href`/`src` with `javascript:`**: React 19 replaces the URL with one that **throws** (`javascript:throw new Error('React has blocked a javascript: URL…')`). The test confirms it. React 16.9–18 only **warned** in development and rendered it.

## 2. Where React does NOT protect you

| Code | Why it's dangerous | Verified / reference |
|---|---|---|
| `<div dangerouslySetInnerHTML={{ __html: userHtml }} />` | inserted **unchanged** | test: `<img … onerror>` comes out as is |
| `<a href={userUrl}>` with `data:`, `vbscript:`, or a phishing `https:` | only `javascript:` is blocked | test: `data:text/html,…` passes |
| `window.open(userUrl)`, `location.href = userUrl`, `location.assign(userUrl)` | not rendering, so React never sees them; `javascript:` runs | 26.05 |
| `ref.current.innerHTML = …`, `insertAdjacentHTML`, `document.write` | direct DOM, outside React | 26.07 |
| `<iframe src={userUrl}>`, `<object data=…>`, `<embed>` | loads anything allowed by protocol | allow-list (26.06) |
| `style={userObject}`, or `<style>{userCss}</style>` | CSS can exfiltrate data (attribute selectors, `url()`) and overlay UI | never user CSS |
| `eval(userCode)`, `new Function(…)`, `setTimeout(string)` | code from data | never |
| server-rendered HTML (JSP, S40) | React isn't involved | JSTL `<c:out>` (S43) |
| a spread of user props: `<a {...userProps}>` | the user chooses the attributes (`href`, `onClick`?) | don't |

## 3. The review rule

> Grep for `dangerouslySetInnerHTML`, `innerHTML`, `window.open`, `location.`, `eval`, `new Function`, and `href={` / `src={` with a variable. Each hit needs a reason, and a sanitiser or validator right next to it.

In TaskFlow, after S26: exactly **one** `dangerouslySetInnerHTML` (inside `SanitizedHtml`, 26.04), and every user URL goes through `SafeLink` (26.06).

## ✅ Recap

React escapes text and attributes, and (since 19) blocks `javascript:` in `href`/`src`. Everything that bypasses rendering, and every other dangerous scheme, is on you.
