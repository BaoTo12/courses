# Lecture 26.05 · 🔓 Lab: Dangerous URLs in User-Supplied Links

> **Section:** S26 · **Type:** 🔓 Attack Lab · **Track:** ★ Core · **Time:** ~35 minutes
> ⚠️ **Local only**, in a lab branch.
> Verified: `src/security/security.test.tsx` (React 19 blocks `javascript:` in `href` and passes `data:`; `parseLinks` extracts URLs without judging them)

---

## 1. The feature

Descriptions may contain links in Markdown style: `See [the spec](https://example.com/spec)`. `parseLinks` (in `src/security/markup.ts`) turns the text into segments, `{ kind: 'text' }` and `{ kind: 'link', label, url }`, which React renders. No HTML is parsed at any point. The question is only: **what do we do with `url`?**

## 2. Vulnerable version A: a plain `<a href>`

```tsx
// ❌ lab only
segment.kind === 'link' ? <a href={segment.url}>{segment.label}</a> : segment.text
```

Put these in a task description (edit a task you own):

```text
[Open report](javascript:alert(document.cookie))
[Open report](data:text/html,<script>alert(1)</script>)
[Company login](https://taskflow-login.evil.example)
```

| Link | React 19 | Browser |
|---|---|---|
| `javascript:` | **replaced** with a URL that throws: "React has blocked a javascript: URL…" | nothing runs ✅ (React 18: it would have run) |
| `data:text/html,…` | **passed through** unchanged | modern browsers block top-level `data:` navigation, but the page still links to attacker content |
| `https://…evil…` | passed | a phishing page one click away, opened with `window.opener` access if `target=_blank` without `rel` |

## 3. Vulnerable version B: the URL outside rendering

```tsx
// ❌ lab only: "open in a popup"
<button onClick={() => window.open(segment.url)}>{segment.label}</button>
```

Click `[Open report](javascript:alert(document.cookie))`: **the alert runs.** React never sees the URL, so its protection doesn't apply. The same happens with `location.href = url` and `location.assign(url)`.

## 4. Lessons

1. React's `javascript:` blocking is a **safety net**, not a policy. It covers one scheme, in one place (rendered attributes).
2. User URLs need a **protocol allow-list** wherever they're used: `href`, `window.open`, `location`, `iframe src`, and when sent to the server.
3. `target="_blank"` needs `rel="noopener noreferrer"`, or the opened page gets `window.opener` and can redirect our tab (reverse tabnabbing).
4. Showing the real destination (a `title`, or an "external link" icon) helps users spot `[Company login](https://evil…)`. No protocol check can.
