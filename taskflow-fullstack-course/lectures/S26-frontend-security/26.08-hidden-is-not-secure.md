# Lecture 26.08 · 🛡 Hidden ≠ Secure: Client-Side Checks Are UX Only

> **Section:** S26 · **Type:** 📖 Theory + 🔓 mini-lab · **Track:** ★ Core · **Time:** ~35 minutes
> ⚠️ Local only: your mock API on `localhost`.

---

## 1. What the UI hides

TaskFlow hides the Delete button for anonymous users, redirects `/dashboard` to `/login`, and (from S45) will hide admin menus from users. All of that runs in **the user's browser**, which the user controls.

## 2. Prove it: bypass the UI in three ways

Log in as **bob** in the browser. Find the id of one of **alice's** tasks: ids are sequential, and alice owns task 1 in the seed.

**a) DevTools:** re-enable a disabled button (Elements panel → delete the `disabled` attribute), or dispatch an action from the console. The request goes out regardless.

**b) The Network tab:** right-click any request → **Copy as cURL (bash)**. You get bob's session cookie and CSRF token in a ready-made command.

**c) curl:** from that copy, change the URL and method:

```bash
curl -i -X DELETE 'http://localhost:5173/api/tasks/1' \
  -H 'Cookie: JSESSIONID=<bob>; XSRF-TOKEN=<token>' -H 'X-XSRF-TOKEN: <token>'
```

Result: **`404 Not Found`**. The mock's `findAccessibleTask` refuses: "Someone else's task is reported as 404, not 403 (no probing)". Bob can't even learn that task 1 exists. **The server enforced it.** The React code had nothing to do with it.

Now imagine the server check missing: the same curl would delete alice's task, even though no button for it ever appeared on bob's screen. That's **Broken Access Control** (OWASP A01), the most common web vulnerability. You'll exploit exactly this in the IDOR lab against the servlet backend (S41).

## 3. The rule

| Where | Purpose | Trust |
|---|---|---|
| **Server** (servlet filter, service layer) | **enforcement**: authentication, authorisation, validation | the only place that counts |
| Client (React) | **UX**: hide what can't be used, validate early, explain errors | zero: assume it's modified |

The client *also* checks, so users don't click buttons that will fail. It's never the reason something is safe.

## 4. The same applies to

- **`role` in the client**: `user.role === 'ADMIN'` may show an admin link. The admin **endpoints** check the role again on the server.
- **Form validation**: `maxLength={1000}` is a courtesy. The server returns 400 for 1001 characters (22.11 tested it).
- **Feature flags** in the bundle: hidden features are still downloadable code. Don't ship secrets or unreleased pricing in JavaScript.
- **Obfuscated or minified code**: not a secret. Anyone can read the bundle (Sources panel, "pretty print").

## ✅ Recap

Everything in the browser can be read and changed by the user. **The server decides**: every request, every time. Client checks exist for convenience.
