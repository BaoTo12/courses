# Lecture 26.09 · Sensitive Data on the Client: State, DevTools, Logs, Error Trackers

> **Section:** S26 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~30 minutes

---

## 1. Everything in the browser is readable

By the user, by any script running in the page (XSS, a malicious dependency or extension), and by anything you send it to (log services, analytics).

| Place | Who can read it | TaskFlow today |
|---|---|---|
| Redux state | DevTools (dev), any script (`window.__REDUX_DEVTOOLS_EXTENSION__`, React internals) | tasks, the user's profile. No tokens and no passwords. ✅ |
| `localStorage` / `sessionStorage` | any script, until cleared | nothing since S24 (the theme moved to a cookie) ✅ |
| JS-readable cookies | any script; also sent to the server | `XSRF-TOKEN`, preferences, `tf_last_task` ✅ |
| `console.*` logs | anyone with DevTools open; screenshots in bug reports | `[api] GET /tasks → 200 in 12 ms` in **development only** ✅ |
| Error trackers (Sentry…) | the vendor, your whole team | not wired yet (S27: `crashReporter` sink) ⚠️ |
| URLs (query strings) | server logs, proxies, browser history, the Referer header | ids, filters, `returnTo` ✅; never tokens or emails |
| The JS bundle | everyone | no API keys, no secrets ✅ |

## 2. Rules

1. **Never store secrets client-side**: passwords (clear the field after a failed login, 24.12), session ids (HttpOnly), API keys for paid services (proxy them through your server).
2. **Minimise what's cached**: clear it on logout (23.10), and prefer session cookies for user data (24.16).
3. **Logs**: development only (`import.meta.env.DEV`), and never log request **bodies** or **headers** (they contain passwords and CSRF tokens). TaskFlow's logger middleware logs action types and state diffs in dev. `devTools: import.meta.env.DEV` keeps the Redux DevTools off in production (14.11).
4. **Error trackers**: scrub before sending. Remove `Authorization`/`Cookie` headers, form bodies, and `state.api` payloads. Send action **types**, not payloads. When S27 points the crash reporter (16.12) at a real endpoint, it must forward `actionType` and the error, not the whole crash object.
5. **Anything in `VITE_*` env variables is public**: Vite inlines them into the bundle.

## 3. A quick self-audit

```bash
# secrets that ended up in the build?
npm run build && grep -rEi "api[_-]?key|secret|password|token" dist/assets/*.js | head
```

Expect only identifiers (`XSRF-TOKEN`, form field names), never values.

## ✅ Recap

Assume every byte in the browser is public. Keep secrets on the server, log little and only in development, scrub what goes to third parties, and clear user data on logout.
