# Lecture 26.07 · DOM XSS: `innerHTML`, `location.hash`, Third-Party Widgets

> **Section:** S26 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~30 minutes
> 🔗 Reference: OWASP, "DOM based XSS Prevention Cheat Sheet"

---

## 1. Sources and sinks

DOM XSS never touches the server. JavaScript moves attacker-controlled data from a **source** to a dangerous **sink**.

| Sources (attacker-controlled) | Sinks (execute or parse HTML) |
|---|---|
| `location.hash`, `location.search`, `location.href` | `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write` |
| `document.referrer`, `window.name` | `eval`, `new Function`, `setTimeout('string')` |
| `postMessage` event data | `location = …`, `location.assign`, `window.open` (with `javascript:`) |
| `localStorage` / cookies another script wrote | `element.src`/`href` set directly; jQuery's `$(html)`, `.html()` |

## 2. A classic, in a React app

```tsx
// ❌ "show a welcome banner from the URL": /tasks#welcome=<img src=x onerror=alert(1)>
useEffect(() => {
  const msg = decodeURIComponent(location.hash.slice('#welcome='.length));
  bannerRef.current!.innerHTML = msg;   // a sink outside React's escaping
}, []);
```

The fix is the React way: `const msg = …; return <p>{msg}</p>`. Text, escaped. Treat URL parts like any other user input (we already validate `?status=` and `?page=`, 12.03 and 23.07).

## 3. `postMessage`

```ts
window.addEventListener('message', (event) => {
  if (event.origin !== 'https://widgets.trusted.example') return;   // ✅ check who sent it
  if (typeof event.data?.height !== 'number') return;               // ✅ validate the shape
  frame.style.height = `${event.data.height}px`;
});
```

Without the origin check, **any** page that frames us, or that we open, can send messages.

## 4. Third-party widgets and scripts

A `<script src="https://cdn.chat-widget.example/w.js">` runs with **full access to your origin**: the DOM, cookies without HttpOnly, the API as the user. That's equivalent to XSS by design, so trust it accordingly:

- prefer self-hosted and bundled dependencies (reviewed, and in the lockfile, 26.10);
- for CDN scripts: pin the version and add **Subresource Integrity** (`integrity="sha384-…"`);
- isolate what you can in an `<iframe sandbox>` on another origin;
- CSP `script-src` lists exactly what may load (26.11).

## ✅ Recap

Find every **sink**, and never feed it a **source**. In React: render text, don't set `innerHTML`, check `postMessage` origins, and treat third-party scripts as trusted code, because they are.
