# Lecture 11.03 · Selects, Checkboxes, Dates and Numbers: Value Types and Conversions

> **Section:** S11 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~20 minutes

---

## 1. The rule: the DOM speaks strings

| Control | Controlled prop | What `e.target` gives you |
|---|---|---|
| `<input type="text">` / `<textarea>` | `value` | `e.target.value`: `string` |
| `<select>` | `value` | `e.target.value`: `string` (the chosen option's `value`) |
| `<input type="checkbox">` | **`checked`** | `e.target.checked`: `boolean` |
| `<input type="radio">` | `checked` per option | `e.target.value` of the chosen radio |
| `<input type="number">` | `value` | `e.target.value`: **`string`** (`''` when empty or invalid); `e.target.valueAsNumber`: `number` (`NaN` if empty) |
| `<input type="date">` | `value` | `'YYYY-MM-DD'` string, or `''` when empty |

Everything arrives as text, just like request parameters on the server (`request.getParameter()` returns `String`, S31) and `dataset` values in the DOM (04.13). **Convert and validate at the boundary.**

## 2. Selects: string → union

```tsx
<select
  value={values.priority}
  onChange={(e) => {
    if (isPriority(e.target.value)) setField('priority', e.target.value);
  }}
>
  {PRIORITIES.map((p) => <option key={p} value={p}>{PRIORITY_TEXT[p]}</option>)}
</select>
```

- `value` on `<select>` (not `selected` on options) makes it controlled.
- Options generated from `PRIORITIES` (06.05): the runtime array drives both the UI and the guard.

## 3. Checkboxes: `checked`, not `value`

```tsx
<input
  type="checkbox"
  checked={values.done}
  onChange={(e) => setField('done', e.target.checked)}
/>
```

A common bug is using `value={values.done}`: the checkbox won't reflect state.

## 4. Dates: `''` vs `null`

`<input type="date">` gives `'2026-10-03'` or `''`. The API wants `string | null` (06.04). The form keeps `''` (so the input stays controlled: never `undefined` or `null` as `value`), and `toCreateRequest` converts `''` → `null`.

The date input's value is always ISO `YYYY-MM-DD`, whatever format the browser **displays** (e.g. `03/10/2026` in a Vietnamese locale). Display format ≠ value format, which is convenient.

## 5. Numbers: `valueAsNumber` or `Number(…)` + validation

```tsx
<input
  type="number"
  value={values.estimateHours}               // keep a string in form state
  onChange={(e) => setField('estimateHours', e.target.value)}
/>
// convert on submit:
const hours = values.estimateHours === '' ? null : Number(values.estimateHours);
if (hours !== null && (!Number.isFinite(hours) || hours < 0)) errors.estimateHours = '…';
```

Keeping the raw string in state lets users type intermediate values (`'1.'`, `''`) without the field fighting them.

## 6. Summary

- DOM controls speak strings (checkbox: boolean `checked`).
- Convert at the boundary: string → union (type guard), `''` → `null`, string → number with validation.
- Keep form state in "input-friendly" types; convert once on submit.
