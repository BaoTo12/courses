## E. Implementation

11. Add a live title-length counter that turns red above the limit (you have the text; add the colour), and a rule that the description can't equal the title. <details>
<summary><b>Answers</b></summary>

1. The client can be bypassed (DevTools, modified requests, raw HTTP with curl). Only the server's checks are guaranteed to run, so client validation is UX and server validation is enforcement.

2. **Derived**: `errors` (from `values`), `isDirty` (values vs initial), counters. **State**: `values`, `touched`, `submitAttempted`, `isSubmitting` (for rendering). Plus a **ref** for the synchronous submit lock.

3. `setIsSubmitting(true)` schedules a re-render; a second click in the same frame runs a handler from the same render whose closure still sees `false`, and the button isn't disabled yet. A ref's `.current` changes immediately and is shared across renders.

4. `''` (an empty string) when empty; `'3'` (a **string**) when it contains 3. Use `Number(…)` or `valueAsNumber` and validate.

5. Without `preventDefault`, the browser sends `POST /tasks/new` with `title=…` as `application/x-www-form-urlencoded` and **navigates** to the response (a full page load). With it, nothing is sent and the page stays; your JS handles the submission.

6. (a) A **ref** lock checked at the top of the handler (the real lock, synchronous); (b) a **disabled** submit button while saving (visual feedback, and it blocks clicks after the re-render). Also, the server should prevent duplicates (unique constraints, idempotency keys, PRG for page forms).

7. `value` was `undefined` on the first render (uncontrolled), then a string (controlled). Initialise with `''` or use `value={x ?? ''}`.

8. `useState(initialValues)` only reads its argument when the instance is created; the same `TaskForm` instance is reused for B. Fix: a `key` that changes with the task (`key={\`edit-${task.id}\`}`), which gives a fresh instance.

9. Generally **no**. The Redux Style Guide recommends keeping form state local (only the submitted result becomes global data). Keystrokes in a global store cause needless work across the app, and nobody else needs a half-typed draft.

10. In `validateTaskForm` (pure, client) for UX, and **on the server** (S37/S46) for enforcement. The client rule should never be stricter than the server's.

11. Example additions:
    ```ts
    if (values.description.trim() !== '' && values.description.trim() === title) {
      errors.description = 'Description should add information beyond the title.';
    }
    ```
    Counter colour: `help={<span className={values.title.trim().length > TITLE_MAX ? 'text-danger' : undefined}>{…}</span>}`.
    Tests: `expect(validateTaskForm({ ...EMPTY_TASK_FORM, title: '   ' }, '2026-10-01', true).title).toBe('Title is required.')`, and so on for each rule; for the date rule, the same values with `isNew = false` must produce **no** `dueDate` error.
