# Lecture 11.02 · 🛠 Build: `TaskForm` with Typed Form State and a Type-Safe `setField`

> **Section:** S11 · **Type:** 🛠 Build · **Track:** ★ Core · **Time:** ~45 minutes
> **Project feature:** `src/domain/task-form.ts` (pure form model), a first `TaskForm` (create), and a "+ New task" panel in `App`

## 1. Model the form separately from the entity

A form doesn't edit a `Task` directly. Inputs hold **strings** (and our union types for selects), and some fields have form-only representations:

| Field | In `Task` (API) | In the form |
|---|---|---|
| `dueDate` | `string \| null` | `string`, where `''` = empty date input |
| `id`, `ownerId`, timestamps | present | absent (the server sets them, 06.04) |
| `title` | trimmed | raw text as typed |

So we define **`TaskFormValues`**, plus pure functions to convert between the two.

## 2. ✍️ `src/domain/task-form.ts` (pure, no React)

```ts
import type { IsoDate, Priority, Task, TaskStatus } from './types';
import type { CreateTaskRequest } from './api-types';

/** What the form edits. Every field is what an <input>/<select> actually holds: strings and unions. */
export interface TaskFormValues {
  title: string;
  description: string;
  status: TaskStatus;
  priority: Priority;
  /** '' means "no due date" (an empty date input), converted to null on submit. */
  dueDate: IsoDate | '';
}

export type TaskFormErrors = Partial<Record<keyof TaskFormValues, string>>;

export const TITLE_MAX = 120;
export const DESCRIPTION_MAX = 2000;

export const EMPTY_TASK_FORM: TaskFormValues = {
  title: '',
  description: '',
  status: 'TODO',
  priority: 'MEDIUM',
  dueDate: '',
};

export function toFormValues(task: Task): TaskFormValues {
  return {
    title: task.title,
    description: task.description,
    status: task.status,
    priority: task.priority,
    dueDate: task.dueDate ?? '',
  };
}

/** Form values → the API request shape (06.04): trimmed, '' → null. */
export function toCreateRequest(values: TaskFormValues, categoryId: number | null = null): CreateTaskRequest {
  return {
    title: values.title.trim(),
    description: values.description.trim(),
    status: values.status,
    priority: values.priority,
    dueDate: values.dueDate === '' ? null : values.dueDate,
    categoryId,
  };
}

/** Local "today" as YYYY-MM-DD (not UTC; see 05.12). */
export function localToday(): IsoDate {
  return new Date().toLocaleDateString('en-CA');
}
```

(Validation functions are added to this file in 11.05.)

Everything here is testable without React, exactly like the reducer (08.08).

## 3. 📦 Provided: `src/data/fake-save.ts`

A fake server with realistic latency, so you can see "Saving…" states and double-submit problems (replaced by real API calls in S13):

```ts
// 📦 Provided: a fake "server" for S11. Replaced by real API calls (Axios) in S13.
import type { Task } from '../domain/types';
import type { CreateTaskRequest } from '../domain/api-types';

const LATENCY_MS = 600;
let nextId = 1000;

const delay = (ms: number) => new Promise((resolve) => setTimeout(resolve, ms));

/** Like POST /api/tasks: the SERVER assigns id, owner and timestamps (06.04). */
export async function fakeCreateTask(request: CreateTaskRequest): Promise<Task> {
  await delay(LATENCY_MS);
  const now = new Date().toISOString();
  return { ...request, id: nextId++, ownerId: 1, createdAt: now, updatedAt: now };
}

/** Like PUT /api/tasks/{id}: the server keeps id/owner/createdAt and sets updatedAt. */
export async function fakeUpdateTask(existing: Task, request: CreateTaskRequest): Promise<Task> {
  await delay(LATENCY_MS);
  return { ...existing, ...request, updatedAt: new Date().toISOString() };
}
```

## 4. ✍️ The heart of the form: state + a type-safe `setField`

```tsx
const [values, setValues] = useState<TaskFormValues>(initialValues);

/** Type-safe single-field update: the value type follows the key (06.02). */
function setField<K extends keyof TaskFormValues>(field: K, value: TaskFormValues[K]) {
  setValues((current) => ({ ...current, [field]: value }));
}
```

This is `updateTaskField` from 06.02 applied to form state: `setField('priority', 'HIGH')` compiles, and `setField('priority', 'URGENT')` doesn't.

### Why not one generic `handleChange` using `e.target.name`?

A popular shortcut:

```tsx
function handleChange(e: ChangeEvent<HTMLInputElement | HTMLSelectElement>) {
  setValues((v) => ({ ...v, [e.target.name]: e.target.value }));
}
```

It's short, but `e.target.name` is just a `string` and `e.target.value` is just a `string`. TypeScript can't check that a `<select name="priority">` only produces a valid `Priority`, and a typo in `name="titel"` silently adds a junk field. For selects, we **validate** the string with a type guard (06.08) before storing it:

```tsx
onChange={(e) => {
  if (isPriority(e.target.value)) setField('priority', e.target.value);
}}
```

That's more explicit, and the HTML options *are* user-modifiable input: someone can edit an `<option value>` in DevTools. We validate, not trust.

In `App`, model the panel as a union, not booleans (06.06):

```tsx
type FormPanel = { mode: 'closed' } | { mode: 'create' };
const [panel, setPanel] = useState<FormPanel>({ mode: 'closed' });

async function handleCreate(values: TaskFormValues) {
  const created = await fakeCreateTask(toCreateRequest(values));
  addTask(created);
  show({ tone: 'success', message: `Created: ${created.title}` });
  setPanel({ mode: 'closed' });
}

// in the JSX:
<Button size="sm" variant="primary" onClick={() => setPanel({ mode: 'create' })}>
  + New task
</Button>
{panel.mode === 'create' && (
  <TaskForm initialValues={EMPTY_TASK_FORM} onSubmit={handleCreate} onCancel={() => setPanel({ mode: 'closed' })} />
)}
```

## 6. Summary

- Form values ≠ entity: model `TaskFormValues`, with pure conversion functions (`toFormValues`, `toCreateRequest`).
- `setField<K extends keyof …>` gives type-safe updates; selects are validated with type guards.
- The server assigns ids and timestamps; the form sends a `CreateTaskRequest`.
