# Lecture 43.04 · Error Attributes: `javax.servlet.error.*` and `${pageContext.errorData}`

> **Section:** S43 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~15 minutes
> Verified: `S43ErrorHandlingTest.aBadIdGetsThe400PageWithItsFixedMessage` (`message`), `.otherStatusesGetTheDefaultErrorPage` (`errorData.statusCode`)

---

## 📇 API card: the error attributes (`RequestDispatcher.ERROR_*` constants)

| Attribute | Type | Set by |
|---|---|---|
| `javax.servlet.error.status_code` | `Integer` | always |
| `javax.servlet.error.message` | `String` | `sendError(status, message)`, or the exception's message |
| `javax.servlet.error.exception` | `Throwable` | an uncaught exception |
| `javax.servlet.error.exception_type` | `Class` | an uncaught exception |
| `javax.servlet.error.request_uri` | `String` | always: the URI that failed |
| `javax.servlet.error.servlet_name` | `String` | always: the servlet that was running |

## Reading them in a JSP

```jsp
${requestScope['javax.servlet.error.status_code']}      <%-- dots in the name: bracket syntax (34.06) --%>
${pageContext.errorData.statusCode}                     <%-- javax.servlet.jsp.ErrorData: statusCode, requestURI, servletName, throwable --%>
```

TaskFlow's pages use two of them:

```jsp
<%-- error.jsp: the default page, for any status --%>
<c:set var="pageTitle" value="Error ${pageContext.errorData.statusCode}"/>

<%-- 400.jsp: the fixed message of a BadRequestException --%>
<c:set var="message" value="${requestScope['javax.servlet.error.message']}"/>
<p class="error-page__text"><c:out value="${empty message ? 'The request could not be understood.' : message}"/></p>
```

## Which ones may be shown to the user?

| Attribute | Show? |
|---|---|
| status code | ✅ |
| a message **we** wrote (`BadRequestException`) | ✅, escaped |
| any exception's message | ❌: `SQLException` messages contain SQL, table names, sometimes values (43.09) |
| the exception, its class, its stack trace | ❌: logs only |
| `request_uri` | ⚠️ it's user input: if shown, escape it (a crafted URL is a classic reflected-XSS vector on error pages) |
| `servlet_name` | ❌: internal structure |

## ✅ Recap

The container records the error in request attributes; `errorData` is the convenient view. Show the status and your own messages, nothing else.
