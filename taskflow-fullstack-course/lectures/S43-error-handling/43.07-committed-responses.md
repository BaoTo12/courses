# Lecture 43.07 · Exceptions After the Response Is Committed

> **Section:** S43 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~15 minutes
> Verified: `S43ErrorHandlingTest.afterTheResponseIsCommittedNoErrorPageCanBeShown` (`/debug/fail?after=commit` → status **200**, a partial page, no error page)

---

## 1. "Committed"

The response is **committed** once its status line and headers have been sent to the client. That happens when:
- the buffer fills up (Tomcat's default: 8 KB);
- the code calls `flush()` (or `flushBuffer()`);
- a JSP's `<%@ page autoFlush="true" %>` buffer (default 8 KB) fills while rendering a large page.

From then on, `response.isCommitted()` is `true`, and:

| Call | Result |
|---|---|
| `setStatus`, `setHeader`, `addCookie` | silently ignored |
| `sendError`, `sendRedirect`, `resetBuffer` | `IllegalStateException` |
| `forward` | `IllegalStateException` |
| the container's error page | impossible: the client already has "200 OK" and part of a body |

## 2. What the user gets

TaskFlow's `/debug/fail?after=commit` writes `<p>partial page`, flushes, then throws:

```text
HTTP/1.1 200
<p>partial page                  ← and then the connection ends
```

`ErrorHandlingFilter` can only log it (captured: `… ERROR [d080be315a680cf] c.t.w.f.ErrorHandlingFilter - Exception after the response was committed: GET /taskflow/debug/fail`, followed by `GET /taskflow/debug/fail?after=commit 200 0ms`):

```java
if (response.isCommitted()) {
  log.error("Exception after the response was committed: {} {}", request.getMethod(), request.getRequestURI(), cause);
  return;
}
```

## 3. How MVC avoids it

- **Do all the work before rendering.** The controller loads everything, then forwards. The JSP only reads attributes: nothing in it should be able to fail (35.08's "no logic in views").
- Don't `flush()` in views.
- Lazy loading from the view (a JPA collection loaded while the JSP iterates) moves database errors into the rendering phase. TaskFlow's service returns complete view models (`TaskDetails`).
- Very large responses (exports) stream on purpose: errors there need an in-band signal (e.g. a final "export incomplete" line), 45.14.

## ✅ Recap

Once bytes are sent, the status can't change. Fail before rendering, not during.
