# Lecture 43.14 · 🐞 Debug: The Custom 404 Page Itself Throws

> **Section:** S43 · **Type:** 🐞 Debug · **Track:** ★ Core · **Time:** ~15 minutes

---

## 1. Symptom

Logged-in users get the TaskFlow 404 page. But for a missing **static** file (`/taskflow/static/css/old.css`) or a mistyped `/debug/` URL, the browser shows Tomcat's bare "HTTP Status 500", and the log says:

```text
java.lang.NullPointerException: Cannot invoke "com.taskflow.security.AuthUser.getDisplayName()" because the return value of … is null
    at …ErrorPageServlet.doGet(…)
```

## 2. The cause

A team member replaced `404.jsp` with an `ErrorPageServlet` that personalises the page:

```java
String name = CurrentUser.get(request).getDisplayName();   // ❌ assumes a user
```

For logged-in requests to application URLs, it works. But:
- `/static/*` and `/debug/*` are **public** (41.09): no user;
- the ERROR dispatch runs only filters mapped for `ERROR` (43.03), and `AuthenticationFilter` isn't one of them, so nothing establishes a user for the error page either.

The error page throws, and an error inside an error page falls back to Tomcat's own page (43.02), with status 500 instead of 404.

## 3. Rules for error pages

| Rule | TaskFlow |
|---|---|
| assume **nothing**: no user, no session, no service data, possibly a broken database | the pages use only `${pageTitle}`, `${requestId}`, the error attributes, null-safe EL |
| no new sessions | `session="false"` |
| no database calls | an error page that needs the database fails exactly when the database is the problem |
| keep them simple enough to review at a glance | fixed texts |
| if a filter must run for them, map it with `<dispatcher>ERROR</dispatcher>` | `securityHeaders` (40.08) |

## 4. Fix

Null-safe (`CurrentUser.get(request)` may be `null`), or, better, a static page without personalisation. EL's `${currentUser.displayName}` is already null-safe, which is one reason TaskFlow's error pages are JSPs with EL rather than servlets.

## ✅ Takeaway

An error page runs in the worst conditions: the fewer things it depends on, the more reliably it appears.
