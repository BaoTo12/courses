# Lecture 43.12 · 🎯 Your Turn: A 400 Page for Bad Input, a Reference Number on 500

## Requirements

1. **400:** `/tasks/view?id=abc` (and every task URL with a missing or invalid id) shows a TaskFlow page "Bad request" with the message `Parameter 'id' must be a positive number.` and status 400. A comment that's blank or too long shows `A comment needs 1 to 1000 characters.`
2. The 400 page shows **only** messages written by us; the input value is never echoed.
3. **500:** the page says "Something went wrong" and shows the request's reference: the same value as the `X-Request-Id` header and the `[id]` in the log line of the exception.
4. Controllers contain no `sendError(400, …)` / `return` pairs for ids any more.

**Tests:** `/tasks/view?id=%3Cscript%3E` → 400 with the message, and no `<script>` in the body; `/debug/fail` → 500 whose body contains `<code>` + the `X-Request-Id` value + `</code>`.

## Hints

- One helper, `Params.requiredId(request, "id")`, that returns a `long` or throws.
- Which exception class, and which case of `ErrorHandlingFilter` turns it into `sendError(400, message)`?
- The message arrives in the error page as `javax.servlet.error.message` (43.04).
- The request id lives in the MDC while the chain runs. When the 500 page renders, the logging filter has already returned (43.03). Where else could it put the id?
