## 1. The pages

✍️ `src/main/webapp/WEB-INF/views/errors/404.jsp`

```jsp
<%--
  S43 (43.06): <error-page> for 404, reached by an ERROR dispatch (43.03): the same request object, with the
  javax.servlet.error.* attributes added. Only a fixed text for the user; nothing from the exception or the URL.
--%>
<%@ page contentType="text/html;charset=UTF-8" pageEncoding="UTF-8" session="false" trimDirectiveWhitespaces="true" %>
<%@ taglib prefix="c" uri="http://java.sun.com/jsp/jstl/core" %>
```

✍️ `src/main/webapp/WEB-INF/views/errors/error.jsp` (the default page)

```jsp
<%--
  S43 (43.02): the DEFAULT error page (an <error-page> with only a <location>, Servlet 3.0+): every status without a
  page of its own (405, 413, …). pageContext.errorData (a javax.servlet.jsp.ErrorData) exposes the error attributes.
--%>
<%@ page contentType="text/html;charset=UTF-8" pageEncoding="UTF-8" session="false" trimDirectiveWhitespaces="true" %>
<%@ taglib prefix="c" uri="http://java.sun.com/jsp/jstl/core" %>
<c:set var="pageTitle" value="Error ${pageContext.errorData.statusCode}"/>
<%@ include file="/WEB-INF/views/common/header.jspf" %>
    <h1 class="page__title">Error ${pageContext.errorData.statusCode}</h1>
    <p class="error-page__text">TaskFlow couldn't handle this request.</p>
    <p><a href="<c:url value='/tasks'/>">Back to your tasks</a></p>
<%@ include file="/WEB-INF/views/common/footer.jspf" %>
```

`500.jsp` is the same shape with "Something went wrong"; 43.12 adds the reference number to it.

| Detail | Why |
|---|---|
| `<c:set var="pageTitle" …/>` **before** the header include | no controller ran for the error page, and `header.jspf` prints `${pageTitle}`. A page-scope variable is found first (34.03) |
| the normal header and nav | the user can go on; `currentUser` is still a request attribute when the error happened after authentication (43.03) |
| no `isErrorPage` | no `exception` object to print by accident (43.05) |
| `session="false"` | an error page must not create sessions (a 404 from a crawler, 41.02) |
| no dependency on REQUEST-only filters | `${currentUser}` may be missing (an anonymous static 404): the nav simply hides the user part (43.14) |
