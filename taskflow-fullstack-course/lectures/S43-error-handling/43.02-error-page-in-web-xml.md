# Lecture 43.02 · `<error-page>` in `web.xml`: By Code, by Exception Type, and a Default

> **Section:** S43 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~20 minutes
> Verified: `S43ErrorHandlingTest.anUnknownPageGetsTheCustom404`, `.otherStatusesGetTheDefaultErrorPage` (405 → the default page)

---

## 📇 API card: `<error-page>`

| Form | Matches | Example |
|---|---|---|
| `<error-code>404</error-code>` + `<location>` | `sendError(404)`, or an exception mapped to 404 | the custom 404 page |
| `<exception-type>fully.qualified.Class</exception-type>` + `<location>` | an exception thrown out of the servlet/filter chain, **or a subclass** | `java.lang.Throwable` → the 500 page |
| `<location>` alone (Servlet 3.0+) | the **default**: any error without a more specific match | 405, 413, … |

The `location` is a path **inside** the application (context-relative): a JSP under `WEB-INF/`, or a servlet.

## ✍️ TaskFlow's `web.xml`

```xml
<error-page><error-code>400</error-code><location>/WEB-INF/views/errors/400.jsp</location></error-page>
<error-page><error-code>403</error-code><location>/WEB-INF/views/errors/403.jsp</location></error-page>
<error-page><error-code>404</error-code><location>/WEB-INF/views/errors/404.jsp</location></error-page>
<error-page><error-code>500</error-code><location>/WEB-INF/views/errors/500.jsp</location></error-page>
<error-page><exception-type>java.lang.Throwable</exception-type><location>/WEB-INF/views/errors/500.jsp</location></error-page>
<error-page><location>/WEB-INF/views/errors/error.jsp</location></error-page>
```

## Matching rules

| Situation | Page chosen |
|---|---|
| `sendError(404)` | the `404` entry; none → the default; none → Tomcat's own page (`ErrorReportValve`, 43.10) |
| an exception reaches the container | the **closest** `exception-type` in the class hierarchy (`IllegalStateException` → `RuntimeException` → … → `Throwable`); then the page for status 500; then the default |
| a `ServletException` wrapping a cause | the wrapper's type is tried first, then the **root cause's** type |
| the error page itself fails | Tomcat's own page |

## Why TaskFlow also has `java.lang.Throwable`

`ErrorHandlingFilter` (43.08) catches exceptions and calls `sendError`, so normally the status entries do the work. The `Throwable` entry is the safety net for an exception thrown **before** that filter runs (the encoding or logging filter) or while it's being bypassed.

## ✅ Recap

Map statuses to pages, keep a `Throwable` catch-all, and add a default page for every status you didn't think of.
