# Lecture 16.15 · 🐞 Debug: a Middleware Forgets `return next(action)`; `dispatch` Now Returns `undefined`

> **Section:** S16 · **Type:** 🐞 Debug · **Track:** ★ Core · **Time:** ~20 minutes
> Reproduced in the reference tests (`middleware.test.ts`, "16.15").

---

## Symptom

A teammate adds a "performance marker" middleware:

```ts
const perfMarker: Middleware = () => (next) => (action) => {
  performance.mark('dispatch-start');
  next(action);
  performance.mark('dispatch-end');
};
```

Everything seems fine: the UI updates, the DevTools show the actions. Then, in S18, code that relies on dispatch's return value breaks:

```ts
const action = store.dispatch(sortChanged('title', 'desc'));
console.log(action);                       // undefined
await store.dispatch(fetchTasks());        // S18: resolves immediately with undefined, no error, nothing awaited
```

Verified (with a middleware that calls `next(action)` without returning it): `store.dispatch(action)` returned `undefined`, and **the state still updated** (`listPrefs.sort.key === 'title'`).

## Investigation checklist

1. What does `store.dispatch(x)` return **without** middleware? (16.02)
2. With middleware, who decides the return value of `store.dispatch`? (16.10 §1)
3. What does a JavaScript function return when it has no `return` statement?
4. Why did the UI still work?

## Explanation

- With middleware, `store.dispatch` **is** the outermost middleware's innermost function. Its return value is whatever that function returns.
- `perfMarker` calls `next(action)`, which runs the rest of the chain and the reducers (so the state updates, and the UI works), but it **drops** the result and implicitly returns `undefined`.
- One middleware in the chain without `return` breaks the return value for everything **outside** it, and the error surfaces far away, in code that uses the return value.

Why it matters more than it seems:
- **Thunks (S18)** return promises through `dispatch`. `await dispatch(saveTask())` becomes `await undefined`: the page navigates away before the save finishes, and errors aren't caught.
- **RTK Query (S22)** returns an object with `.unwrap()` and `.abort()` from `dispatch`. `undefined.unwrap()` is a `TypeError`.

## Fix

```ts
const perfMarker: Middleware = () => (next) => (action) => {
  performance.mark('dispatch-start');
  const result = next(action);
  performance.mark('dispatch-end');
  return result;
};
```

The pattern: **`const result = next(action); …; return result;`**, or simply `return next(action)` when there's nothing to do afterwards.

## Lessons

- Every middleware must return what `next` returned (unless it deliberately stops or replaces the action).
- The bug doesn't show where it's written; it shows wherever `dispatch`'s return value is used.
- A one-line test catches it: `expect(store.dispatch(action)).toBe(action)` (16.08's logger test does this).
