## 1. ✍️ `src/app/mini-redux/apply-middleware.ts`

```ts
// 16.09: our own compose + applyMiddleware, for learning. The app uses Redux's (store.ts).
import type { MiniAction, MiniReducer, MiniStore } from './create-mini-store';

/**
 * compose(f, g, h)(x) === f(g(h(x))): right to left.
 * (Redux's compose also allows each function to change the type; ours keeps T → T, which is all we need.)
 */
export function compose<T>(...funcs: Array<(arg: T) => T>): (arg: T) => T {
  if (funcs.length === 0) return (arg) => arg;
  return funcs.reduce((outer, inner) => (arg) => outer(inner(arg)));
}

type Dispatch<A> = (action: A) => unknown;

export interface MiniMiddlewareAPI<S, A extends MiniAction> {
  getState: () => S;
  dispatch: Dispatch<A>;
}

/** storeAPI => next => action: the three-level shape of every Redux middleware (16.07). */
export type MiniMiddleware<S, A extends MiniAction> = (api: MiniMiddlewareAPI<S, A>) => (next: Dispatch<A>) => Dispatch<A>;

type StoreCreator<S, A extends MiniAction> = (reducer: MiniReducer<S, A>, preloadedState?: S) => MiniStore<S, A>;

/** An ENHANCER (16.05): takes createStore, returns a new createStore whose store has a wrapped dispatch. */
export function applyMiniMiddleware<S, A extends MiniAction>(...middlewares: MiniMiddleware<S, A>[]) {
  return (createStore: StoreCreator<S, A>): StoreCreator<S, A> =>
    (reducer, preloadedState) => {
      const store = createStore(reducer, preloadedState);
      let dispatch: Dispatch<A> = () => {
        throw new Error('Dispatching while constructing your middleware is not allowed.');
      };
      // Middleware get a dispatch that goes through the WHOLE chain (important for thunks, S18).
      const api: MiniMiddlewareAPI<S, A> = { getState: store.getState, dispatch: (action) => dispatch(action) };
      const chain = middlewares.map((middleware) => middleware(api));
      // compose(m1, m2, m3)(store.dispatch) === m1(m2(m3(store.dispatch))): m1 runs first, the real dispatch last.
      dispatch = compose(...chain)(store.dispatch);
      return { ...store, dispatch: dispatch as MiniStore<S, A>['dispatch'] };
    };
}
```

## 2. `compose`, step by step

```ts
compose(add1, double, square)(3)
// = add1(double(square(3)))
// = add1(double(9))
// = add1(18)
// = 19                                    ← verified
```

`reduce` folds the list into one function: `(outer, inner) => (arg) => outer(inner(arg))`. For `[f, g, h]`, the first step produces `x => f(g(x))`, the second `x => (x => f(g(x)))(h(x))` = `x => f(g(h(x)))`. With no functions, it returns the identity function.

## 3. `applyMiddleware`, step by step

For `applyMiniMiddleware(A, B, C)`:

1. It's an **enhancer** (16.05): it receives `createStore` and returns a new one.
2. It creates a normal store.
3. It builds `api = { getState, dispatch }`. The `dispatch` inside `api` is a **forwarding function**, `(action) => dispatch(action)`, that reads the `dispatch` **variable** at call time.
4. It calls each middleware's outer level: `chain = [A(api), B(api), C(api)]`. Each is now `next => action => …`.
5. `compose(...chain)(store.dispatch)` = `A'(B'(C'(store.dispatch)))`. `C'` gets the real dispatch as its `next`, `B'` gets C's wrapper, and `A'` gets B's wrapper. The result is the new `dispatch`.
6. The variable `dispatch` is reassigned to that result. From now on, `api.dispatch` (step 3) goes through the **whole** chain.

Step 3's indirection solves a chicken-and-egg problem: middleware need `dispatch` at setup time (step 4), but the final dispatch only exists after setup (step 5). Before step 6, calling it throws *"Dispatching while constructing your middleware is not allowed."*, like Redux.

## 4. ✍️ Tests (in `src/app/mini-redux/mini-redux.test.ts`)

```ts
/** Records the order in which each middleware sees the action, before and after next(). */
function tracer(name: string, log: string[]): MiniMiddleware<RootState, AppAction> {
  return () => (next) => (action) => {
    log.push(`${name} before`);
    const result = next(action);
    log.push(`${name} after`);
    return result;
  };
}

it('the first middleware runs first on the way in, and last on the way out', () => {
  const ours: string[] = [];
  const store = applyMiniMiddleware(tracer('A', ours), tracer('B', ours), tracer('C', ours))(createMiniStore)(rootReducer);
  store.dispatch(taskSelectionToggled(1));

  const theirs: string[] = [];
  const real = createStore(
    rootReducer,
    applyMiddleware(
      tracer('A', theirs) as never,
      tracer('B', theirs) as never,
      tracer('C', theirs) as never,
    ),
  );
  real.dispatch(taskSelectionToggled(1));

  expect(ours).toEqual(['A before', 'B before', 'C before', 'C after', 'B after', 'A after']);
  expect(ours).toEqual(theirs);
});
```

Verified: both traces are `A before, B before, C before, C after, B after, A after`. The chain is an **onion**, exactly like interceptors (13.06) and servlet filters (S40).

(`as never` adapts our `MiniMiddleware` type to Redux's `Middleware` type. The runtime shapes are identical; only the type definitions differ.)

### Re-dispatching jumps the queue

A second test uses a middleware that, when it sees `ui/selectionCleared`, dispatches `taskSelectionToggled(99)` through `api.dispatch` **before** calling `next`:

```ts
store.dispatch({ type: 'ui/selectionCleared' });
// log: ['saw ui/selectionCleared', 'saw ui/taskSelectionToggled']
// state: selectedTaskIds === []   (not [99]!)
```

The new action went through the whole chain **and the reducers** first (99 selected), and then the original `selectionCleared` continued down with `next` and cleared it. When middleware dispatches, the new action is processed immediately, before the one that triggered it. My first version of this test expected `[99]` and failed. The failure was the lesson.

## 5. Summary

- `compose(f, g, h)(x) = f(g(h(x)))`, implemented with `reduce`.
- `applyMiddleware` is an enhancer: create the store, give middleware a forwarding `dispatch`, compose the chain around the real dispatch.
- The chain is an onion; dispatching from middleware runs the new action to completion first.
