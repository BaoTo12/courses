# Lecture 16.12 · 🎯 Your Turn: a Crash Reporter and an Analytics Middleware That Ignores Sensitive Actions

> **Section:** S16 · **Type:** 🎯 Your Turn · **Track:** ★ Core · **Time:** ~90 minutes

---

## 1. The task

Write two middleware factories, add them to `store.ts`, and test them.

### `createCrashReporter(report)` (`src/app/middleware/crash-reporter.ts`)

1. If anything **after** it in the chain (another middleware or a reducer) throws while handling an action, call `report({ error, actionType, action })`, with the action **redacted** (16.08).
2. Then **re-throw** the error. Reporting must never hide a failure (13.14).
3. It must work for non-action values (a function passed through, later a thunk): report `actionType` as `typeof action` in that case.

### `createAnalyticsMiddleware(send, now?)` (`src/app/middleware/analytics.ts`)

4. Send `{ name: action.type, at: timestamp }` for **tracked** actions only. Never send payloads (task titles and comments are user content; S24's login actions will contain credentials).
5. Decide **which** actions are tracked in a way that's **safe by default**: a new action added next month, possibly sensitive, must **not** be tracked unless someone decides it should be.
6. Track an action only if the reducers handled it **without throwing**.
7. `now` is injectable, so tests are deterministic.

### Wiring

8. In `buildMiddleware()` (`store.ts`): crash reporter **first**, logger (development only), analytics **last**. For now, `report` logs with `console.error` and `send` with `console.info` (real endpoints come later).

### Tests

9. The crash reporter reports the failing action type and re-throws (use a middleware that throws, placed after it).
10. Analytics sends allowlisted types only, and a test proves a task title never appears in what was sent.

## 2. Hints

<details>
<summary>Hint 1: catching errors "after" you</summary>

Wrap `next(action)` in `try/catch`. Everything further down the chain, including the reducers, runs **inside** that call.
</details>

<details>
<summary>Hint 2: safe by default</summary>

A **denylist** ("track everything except `auth/…`") silently tracks every new action type, including sensitive ones someone forgets to add. An **allowlist** ("track only these") fails safe: a new action is untracked until someone deliberately adds it. Same reasoning as `safeReturnTo` (12.07).
</details>

<details>
<summary>Hint 3: "only if the reducers didn't throw"</summary>

Call `next(action)` first, and send **after** it returns. If it throws, the line after never runs.
</details>

## 3. Acceptance checklist

- [ ] A throwing middleware after the crash reporter: the error reaches the caller **and** `report` was called with `actionType: 'tasks/taskDeleted'`.
- [ ] Analytics: `sortChanged` and `taskAdded` sent; `toastShown` not sent; no task title in the sent data.
- [ ] `makeStore()` works in a Node test (no `window` error) and runs the whole chain.
- [ ] `npm test`, `npx tsc -b`, `npm run lint` pass.
