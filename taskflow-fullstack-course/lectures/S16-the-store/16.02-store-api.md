# Lecture 16.02 · The Store API: `getState`, `dispatch`, `subscribe`; `createStore` vs `legacy_createStore`

## 1. Creating a store

```ts
createStore(reducer)
createStore(reducer, preloadedState)
createStore(reducer, enhancer)
createStore(reducer, preloadedState, enhancer)
```

- **`reducer`**: the root reducer (15.09).
- **`preloadedState`** (optional): a starting state, for example from `localStorage`, from server-rendered HTML, or in tests. With `combineReducers`, it can be **partial**: slices you don't provide use their own initial state (verified: `makeStore({ ui: { … } })` kept the default `tasks` and `listPrefs`).
- **`enhancer`** (optional): a wrapper around `createStore` itself. `applyMiddleware(…)` and the DevTools are enhancers (16.05).

When the second argument is a function, Redux treats it as the enhancer. That's how the `createStore(reducer, enhancer)` form works.

## 2. The three methods

### `getState()`

Returns the current state. It's the **same object** until an action changes it. Don't mutate it (14.06).

### `dispatch(action)`

The only way to change state. It's **synchronous** (16.04): when it returns, the reducers have run and the subscribers have been called. It returns the dispatched action (middleware can change that: S18's thunks return promises).

### `subscribe(listener)`

Registers a function called after **every** dispatch, with **no arguments**. It returns an `unsubscribe` function:

```ts
const unsubscribe = store.subscribe(() => console.log(store.getState().ui.selectedTaskIds));
// …later
unsubscribe();
```

Listeners are notified even when the state didn't change: comparing is **their** job (React-Redux does it for you, S17).

(There's also `replaceReducer(nextReducer)`, used for code-splitting reducers, and `[Symbol.observable]` for interop with observable libraries. You'll rarely call either.)

## 3. `createStore` vs `legacy_createStore` (again)

Recap of 14.04, now that you'll use it in a real project:

| Import | Behaviour | Editor display |
|---|---|---|
| `createStore` | The store described above | ~~struck through~~ (`@deprecated`) |
| `legacy_createStore` | **Identical** function | No strikethrough |
| RTK `configureStore` (S20) | Calls `createStore` for you, with good defaults: thunk, DevTools, dev checks | The recommendation for new apps |

TaskFlow uses `createStore` in S16–S19 on purpose, and switches to `configureStore` in S20. Some codebases alias it to avoid the strikethrough: `import { legacy_createStore as createStore } from 'redux'`. That's also what the deprecation note in Redux's own type definitions suggests.

## 4. Summary

- `createStore(reducer, preloadedState?, enhancer?)`.
- `getState`, `dispatch` (synchronous, returns the action), `subscribe` (no arguments, returns unsubscribe).
- `createStore` is deprecated as a nudge towards RTK; `legacy_createStore` is the same function.
