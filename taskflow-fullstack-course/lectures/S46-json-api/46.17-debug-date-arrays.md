# Lecture 46.17 · 🐞 Debug: Dates Serialise as `[2026,10,1]`

> **Section:** S46 · **Type:** 🐞 Debug · **Track:** ★ Core · **Time:** ~10 minutes
> Verified: `S46JsonApiTest.theListIsAPageEnvelopeOfTaskDtos` (`"2026-10-03"` and `"2026-09-01T08:00:00Z"`)

---

## 1. Symptom

The React app shows "Invalid Date" or crashes in `formatDate`; the JSON has:

```json
"dueDate": [2026, 10, 3], "createdAt": 1788249600.000000000
```

or the request fails entirely with `InvalidDefinitionException: Java 8 date/time type java.time.LocalDate not supported by default`.

## 2. Causes

| JSON | Cause |
|---|---|
| exception "not supported by default" | `JavaTimeModule` not registered (Jackson 2.12+ refuses `java.time` without it) |
| `[2026,10,3]`, `1788249600.0` | module registered, but `WRITE_DATES_AS_TIMESTAMPS` still **on** (the default) |
| `"2026-09-01T10:00:00+02:00"` vs expected `Z` | an `OffsetDateTime`/`ZonedDateTime` in the server's zone instead of an `Instant` |
| off by hours | a `LocalDateTime` read from a `TIMESTAMP` column in the JVM's zone (TaskFlow's entities use `Instant`, and Hibernate's `jdbc.time_zone` is UTC) |
| a new `ObjectMapper()` somewhere without the configuration | only some endpoints are wrong |

## 3. Fix

One configured mapper, used everywhere (`Json.MAPPER`):

```java
new ObjectMapper()
    .registerModule(new JavaTimeModule())                         // jackson-datatype-jsr310
    .disable(SerializationFeature.WRITE_DATES_AS_TIMESTAMPS);
```

`LocalDate` → `"2026-10-03"` (the contract's `IsoDate`), `Instant` → `"2026-09-01T08:00:00Z"` (`IsoDateTime`).

## ✅ Takeaway

Dates are part of the contract. Pick ISO-8601 strings, configure the mapper once, and use only that mapper.
