# Lecture 46.13 · Why Not Spring? What a Framework Would Give You

> **Section:** S46 · **Type:** 📖 Theory · **Track:** ＋ Extended · **Time:** ~10 minutes

*Extended track: outline.*

---

| Hand-written in TaskFlow | Spring Boot (Spring MVC + Spring Security) |
|---|---|
| `ApiServlet.route` + `pathInfo` segments | `@RestController`, `@GetMapping("/api/tasks/{id}")`, `@PathVariable long id` |
| `request.getParameter` + manual validation | `@RequestParam`, `@RequestBody CreateTaskRequest`, Bean Validation (`@NotBlank`, `@Size`) → `MethodArgumentNotValidException` |
| `Json` + `ObjectMapper` config | auto-configured Jackson (`spring.jackson.*`) |
| `ApiExceptionFilter` | `@RestControllerAdvice` + `@ExceptionHandler`, or `ProblemDetail` (RFC 7807) |
| `AppContextListener` + context attributes | the IoC container: `@Service`, constructor injection |
| filters in `web.xml` order | the `SecurityFilterChain` (a filter chain, like S40's) |
| `AuthenticationFilter`, `LoginServlet`, `changeSessionId` | form/JSON login, session-fixation protection on by default |
| `CsrfFilter`, double-submit (S47) | `CsrfFilter` with `CookieCsrfTokenRepository` (the same `XSRF-TOKEN` / `X-XSRF-TOKEN` names) |
| `CorsFilter` (S47) | `CorsConfigurationSource` |
| ownership in `TaskService` | still **your** code (or `@PreAuthorize` expressions calling it) |

- **Why build it by hand first:** every line above is something Spring does for you **invisibly**. When a Spring app returns 403 on every POST (a CSRF misconfiguration, 47.15) or 401 on preflights (47.16), you'll recognise the filter that did it, because you wrote one.
- **What frameworks don't do:** decide your contract, your status codes, your DTOs, your authorisation rules, your validation messages. Those stay the same size.
- Spring Boot 3 requires `jakarta.*` (Tomcat 10+); TaskFlow's `javax.*` + Tomcat 9 corresponds to Spring Boot 2.x.
