# Lecture 46.02 · REST Basics: Resources, Methods, Status Codes, `Location`, Idempotency

> **Section:** S46 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~25 minutes

---

## 1. Resources and methods (TaskFlow's contract)

| Method | URL | Meaning | Success |
|---|---|---|---|
| GET | `/api/tasks?…` | list (filtered, sorted, paged) | 200 + page envelope |
| POST | `/api/tasks` | create | **201** + `Location: …/api/tasks/42` + the task |
| GET | `/api/tasks/42` | read one | 200 |
| PUT | `/api/tasks/42` | replace (every editable field) | 200 + the task |
| PATCH | `/api/tasks/42` | change some fields | 200 + the task |
| DELETE | `/api/tasks/42` | delete | **204**, no body |
| GET/POST | `/api/tasks/42/comments` | a sub-collection | 200 / 201 |
| GET | `/api/categories`, `/api/stats` | read-only resources | 200 |

## 2. Properties of methods

| Method | Safe (no state change) | Idempotent (repeat = same effect) |
|---|---|---|
| GET, HEAD, OPTIONS | ✅ | ✅ |
| PUT | ❌ | ✅: sending the same full representation twice leaves the same state |
| DELETE | ❌ | ✅: the second one finds nothing (404), the state is the same |
| PATCH | ❌ | ❌ in general (`{"count": +1}`); TaskFlow's "set these fields" patches happen to be idempotent |
| POST | ❌ | ❌: two POSTs create two tasks |

Idempotency is why browsers and proxies may **retry** PUT/DELETE after a network error, but must not retry POST silently.

## 3. Status codes TaskFlow uses

| Code | When |
|---|---|
| 200 OK | a read or update with a body |
| 201 Created | POST created something; `Location` says where |
| 204 No Content | success with nothing to return (DELETE, `GET /api/auth/csrf`) |
| 400 Bad Request | invalid fields (`VALIDATION_FAILED` + `fieldErrors`), malformed JSON (`MALFORMED_JSON`) |
| 401 Unauthorized | not logged in (S47) |
| 403 Forbidden | logged in but refused, e.g. a missing CSRF token (S47) |
| 404 Not Found | no such resource, someone else's resource, no such endpoint |
| 409 Conflict | the request conflicts with the resource's state (a concurrent edit with a version check; TaskFlow doesn't use it) |
| 415 Unsupported Media Type | a body that isn't `application/json` |
| 422 Unprocessable Entity | well-formed JSON that breaks a rule; some APIs use it instead of 400 for validation (46.99 Q3) |
| 429 Too Many Requests | throttled (S47) |
| 500 | a bug: `INTERNAL_ERROR`, no details |

TaskFlow keeps the codes its mock defined in Part 1: the React app was written against them. **The contract wins over personal taste.**

## ✅ Recap

Nouns in URLs, verbs as methods, outcomes as status codes: 201 + `Location` for creations, 204 for empty successes, and one error format for everything else.
