## 1. The contract

`GET /api/tasks?q=report&status=TODO&priority=HIGH&categoryId=1&page=0&size=20&sort=dueDate,asc`

| Parameter | Default | Valid | Invalid → |
|---|---|---|---|
| `q` | none | any text (title or description contains it, case-insensitive) | |
| `status`, `priority` | all | `TODO`/`IN_PROGRESS`/`DONE`, `LOW`/`MEDIUM`/`HIGH` (exact) | 400 + `fieldErrors` |
| `categoryId` | all | a positive integer | 400 |
| `page` | 0 | an integer ≥ 0 (**0-based**) | 400 |
| `size` | 20 | 1–100 | 400 |
| `sort` | `id,asc` | `<id\|title\|priority\|dueDate\|createdAt\|updatedAt>,<asc\|desc>` | 400 |

```json
{ "items": [ … ], "page": 0, "size": 20, "totalItems": 22, "totalPages": 2 }
```

## 2. API vs HTML: different choices, on purpose

| | HTML list (S44) | API |
|---|---|---|
| invalid values | silently replaced by defaults (`?page=abc` → 1): a person clicked a link | **400**: a program sent it, and should learn about the bug |
| page numbers | 1-based, clamped | 0-based, not clamped: `?page=999` → `items: []` |
| sort | `?sort=due&dir=desc` | `?sort=dueDate,desc` |

Both end in the same `TaskService` + `TaskFilter`. `PageDto.from(page, TaskDto::from)` converts the service's 1-based `Page` to the contract's 0-based envelope.

## 3. Design notes

- **`totalItems` costs a `COUNT(*)`** per request. For huge tables, APIs switch to cursor pagination (`?after=<last id>`) without totals.
- **Offset pagination drifts**: a task created while you're on page 2 shifts page 3 by one row. Acceptable for TaskFlow; cursors avoid it.
- **Sorting is allow-listed** (36.09): the field name picks a `TaskSort` constant; nothing from the request reaches the query text.
- `size` has a **maximum**, or one request can ask for a million rows.

## ✅ Recap

Query parameters describe the slice; the envelope describes the whole. Validate strictly: API clients are programs.
