# Lecture 46.11 · 🛡 Defend: Request DTOs with Only the Allowed Fields; `FAIL_ON_UNKNOWN_PROPERTIES`

> **Section:** S46 · **Type:** 🛡 Defend · **Track:** ★ Core · **Time:** ~15 minutes
> Verified: `S46JsonApiTest.clientsCannotSetServerControlledFields` (`id`, `ownerId`, `createdAt`, `role` sent → ignored)

---

## 1. TaskFlow's defence

`TaskInput` (46.05) reads **six** named fields from the body and nothing else. `applyTo(task)` copies those six onto the entity. The owner comes from the session; the id, timestamps and owner of an existing task come from the database.

```java
if (checks("title")) task.setTitle(title);
…
if (checks("categoryId")) task.setCategoryId(categoryId);   // and no line for ownerId, id, createdAt
```

With a data-binding style, the same idea is a **request record**:

```java
public record CreateTaskRequest(String title, String description, TaskStatus status, Priority priority,
                                LocalDate dueDate, Long categoryId) {}
CreateTaskRequest body = Json.read(request, CreateTaskRequest.class);   // "ownerId" has no component to land in
```

(TaskFlow uses a tree for tasks because PATCH needs "absent" vs `null`, 46.03.)

## 2. Unknown properties: ignore or reject?

| `FAIL_ON_UNKNOWN_PROPERTIES` | Behaviour | Pros | Cons |
|---|---|---|---|
| `false` (TaskFlow, like its mock) | extra fields are ignored | clients can send a whole object back (React sends the task it received, including `id` and `ownerId`); old clients keep working when the API drops a field | an attacker's extra field fails **silently** (fine: it had no effect) |
| `true` (Jackson's default) | 400 for any unknown field | typos (`"dueDat"`) are caught instead of ignored | brittle: every client must send exactly the known fields |

Either way, the **security** comes from the request DTO having only allowed fields. The flag only decides whether extra fields are an error.

## 3. The same rule elsewhere

- The user management endpoints change `role` and `enabled` only on admin URLs, by explicit parameters (42.07).
- A future "update my profile" endpoint gets its own `UpdateProfileRequest(displayName, locale)`, never `User`.

## ✅ Recap

Define what a client may send as its own type, copy only those fields, and set identity and ownership on the server.
