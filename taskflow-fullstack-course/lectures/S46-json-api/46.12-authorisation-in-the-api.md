# Lecture 46.12 · 🛡 Authorisation in the API Reuses the S42 Service-Layer Checks

> **Section:** S46 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~10 minutes
> Verified: `S46JsonApiTest.someoneElsesTaskIsNotFoundForEveryMethod` (GET, PATCH, DELETE, comments of task 23 as alice → 404; as bob → 200)

---

IDOR (42.04) in an API looks like this: `GET /api/tasks/23`, `PATCH /api/tasks/23 {"status":"DONE"}`, `DELETE /api/tasks/23`. The ids are in the JSON of every list response, so they're even easier to find than in the Admin Portal.

TaskFlow's API contains **no** ownership code:

| Request | Goes through | Rule applied |
|---|---|---|
| `GET /api/tasks` | `TaskService.pageAt(…, caller)` | `ownerScope`: only the caller's tasks (admins: all) |
| `GET/PUT/PATCH/DELETE /api/tasks/23` | `task`/`update`/`delete(…, caller)` | `visible`: someone else's → `AccessDeniedException` |
| `…/23/comments` | `comments`/`comment(…, caller)` | `visible` |
| `GET /api/stats` | `countByStatus/countByPriority(caller)` | `ownerScope` |

`ApiExceptionFilter` turns `AccessDeniedException` into a JSON 404 and an `ACCESS_DENIED` audit event, exactly as `ErrorHandlingFilter` does for pages.

**The lesson from S42, confirmed:** because the rules lived in the service, a whole new client got them for free. Had they lived in the JSP controllers, this section would have needed to copy them, and the day someone forgot one, the API would leak.

**Tests prove it per method.** An API test suite should include "another user's id" for every endpoint that takes an id.
