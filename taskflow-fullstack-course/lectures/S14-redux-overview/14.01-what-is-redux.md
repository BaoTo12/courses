## 1. Welcome to the Redux track

We follow the same order: first understand the machine, then use the modern tools that hide it. At work, you'll meet both: older codebases with hand-written `switch` reducers and `connect()`, newer ones with `createSlice` and RTK Query. You need to read both fluently.

Each lecture lists its official companion page. Read it **after** the lecture: it will feel like a review, and you'll notice details you'd otherwise skip.

## 2. What Redux is, in one sentence

> Redux is a **pattern and a library for managing application state that many parts of the UI need**, where every change is described by a plain object called an **action**, and handled by pure functions called **reducers**.

Unpack that:

| Phrase | Meaning | TaskFlow example |
|---|---|---|
| **State many parts need** | "Global" state: not owned by one component | The task list (list page, board, details, dashboard, header badge) |
| **Changes are described by actions** | You don't change state; you **report what happened** | `{ type: 'tasks/taskCompleted', payload: 5 }` |
| **Handled by reducers** | Pure functions `(state, action) → newState` | `tasksReducer` computes the new list |
| **A pattern** | The idea works without the library | Your `useReducer` + context from S08/S12 is already a small version of it |
| **A library** | `redux` provides the store, and helpers to combine reducers and add middleware | S16: you'll write each of those yourself first |

## 3. You've already used the core idea

In 08.07 you moved the task list into `useReducer`:

```ts
dispatch({ type: 'fetchSucceeded', tasks });
// …
function tasksReducer(state: TasksState, action: TasksAction): TasksState { switch (action.type) { … } }
```

Then in 12.02 you lifted it into a context so every page could share it. That's the Redux pattern at component scale:
- **actions** describing events;
- a **pure reducer** computing the next state;
- **one** owner of the state, shared by many readers.

Redux takes that pattern **out of the React tree** into a standalone **store**, and adds what the context version lacked:
- components re-render **only** when the data *they* read changes (08.09 §4: a context value change re-renders every consumer);
- **middleware**: a standard place for side effects (logging, async calls);
- **DevTools**: a log of every action, the state after each one, and time travel;
- **conventions** that make large codebases navigable.

## 4. Redux is not tied to React

The `redux` package knows nothing about React. The store is a plain JavaScript object with three methods (`getState`, `dispatch`, `subscribe`). In 14.10 you'll drive a counter in a plain HTML page, with no React and no build step. React support comes from a separate package, **React-Redux** (S17).

## 5. Summary

- Redux = global state + actions (events) + pure reducers + one store.
- It's the `useReducer` pattern moved out of the component tree, with better re-render control, middleware and tooling.
- The course path: Fundamentals by hand (S14–S19), then Redux Toolkit and RTK Query (S20–S23).
