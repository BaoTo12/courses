# Lecture 14.11 · 🛠 Redux DevTools on the Counter: Action Log, State Diff, Time Travel

> **Section:** S14 · **Type:** 🛠 Build · **Track:** ★ Core · **Time:** ~25 minutes
> 🔗 Reference: the Redux DevTools extension's README (github.com/reduxjs/redux-devtools)
> ℹ️ Verification note: the course's automated test browser can't install extensions. The **hook-up code** below was verified (the page works with and without the extension), but the **panel descriptions** come from the extension's documentation. Tab names can differ slightly between versions.

---

## 1. Install

Install **Redux DevTools** from your browser's extension store (Chrome Web Store, Firefox Add-ons or Edge Add-ons; the publisher is the Redux DevTools project). Restart DevTools (close and reopen the panel), then reload the counter page. A **Redux** tab appears in DevTools.

## 2. How the page connects to it

```js
const store = createStore(counterReducer, window.__REDUX_DEVTOOLS_EXTENSION__?.());
```

- The extension injects a global function, `__REDUX_DEVTOOLS_EXTENSION__`, into every page.
- Calling it returns a **store enhancer** (16.05): a wrapper around `createStore` that reports every action and state to the extension, and lets the extension replace the state (for time travel).
- `?.()` (optional call, ES2020): without the extension, the expression is `undefined`, and `createStore` runs without an enhancer. Verified: the page works identically without the extension.

With middleware (S16) you'll combine enhancers using `__REDUX_DEVTOOLS_EXTENSION_COMPOSE__`. From S20, RTK's `configureStore` wires the DevTools up automatically.

## 3. A tour (do each step)

Click `+`, `+`, `−`, `+5`, then open the **Redux** tab.

### The action list (left)

Every dispatched action, in order: `@@INIT` (the store's creation), then `counter/incremented`, `counter/incremented`, `counter/decremented`, `counter/incrementedBy`. Click one to select it.

### The inspector (right) for the selected action

| Tab | Shows | Use it to… |
|---|---|---|
| **Action** | The action object (`type`, `payload`) | Check that the payload is what you expect |
| **State** | The whole state **after** this action | See the result |
| **Diff** | Only what this action changed (`value: 2 → 7`) | Spot unexpected changes in a big state tree |
| **Trace** | The stack trace of the `dispatch` call (when tracing is enabled) | Find **which code** dispatched it |

For **Trace**, enable it in the enhancer: `window.__REDUX_DEVTOOLS_EXTENSION__?.({ trace: true })`. Tracing costs performance, so use it while debugging only.

### Time travel

- **Jump**: hover an action and click *Jump*. The store's state becomes the state at that point, and the page's number **changes** (the extension replaced the state; `render()` ran because the store notified subscribers).
- **Skip**: remove an action from history as if it never happened. The later actions are **replayed** from the earlier state. This is only possible because reducers are **pure** (14.08): replaying the same actions gives the same results.
- **The slider** (a "play" control at the bottom) steps through the history.

Try: skip the `counter/incrementedBy` action. The value drops by 5, and the later actions still apply.

### Dispatch from the panel

The extension has a dispatcher (keyboard icon or "Dispatcher" panel) where you type an action, for example `{ "type": "counter/incrementedBy", "payload": 100 }`, and dispatch it. It's useful for testing a reducer before the UI exists.

## 4. What DevTools can't show you

- **Mutations.** If a reducer mutates, the "previous" states in the history were changed too. Diffs show nothing, and jumping back shows wrong values (14.06). When the DevTools look "wrong", suspect a mutation first (15.14).
- **Non-serialisable values** (functions, class instances, `Date` objects) show up as placeholders or not at all. Another reason to keep state and actions plain (14.07).
- **What happened outside Redux**: local `useState`, the URL, the network. Use the React DevTools and the Network tab for those.

## 5. 🛡 DevTools in production

The DevTools connect to **any** page whose store is set up for them, including production. RTK's `configureStore` enables them by default in **every** environment unless you pass `devTools: false`. Verified in RTK 2.12's source: the option defaults to `devTools = true`, and RTK turns on `trace` automatically when `NODE_ENV` isn't `'production'`. Anyone with the extension can then read your store's state and dispatch actions.

- The state isn't a secret from the user it belongs to, who can read browser memory anyway. Still, **never put secrets in client state** (13.11's rule applies to Redux too).
- Dispatching arbitrary actions only changes that user's own UI, and the **server** must still reject anything they aren't allowed to do (12.07).
- Many teams disable DevTools in production builds (`devTools: import.meta.env.DEV`) to reduce noise and exposure. You'll decide this in S20.

## 6. Summary

- The extension provides an enhancer via `window.__REDUX_DEVTOOLS_EXTENSION__`. Use `?.()` so the page works without it.
- Action list, Action/State/Diff/Trace tabs, jump/skip/slider time travel, and a dispatcher.
- Time travel works because reducers are pure and state is immutable and serialisable.
