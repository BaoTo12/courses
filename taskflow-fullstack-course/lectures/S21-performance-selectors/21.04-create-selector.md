# Lecture 21.04 · reselect's `createSelector` in Depth: Input Selectors, Result Function, Two Caches

> **Section:** S21 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~30 minutes
> Verified with reselect 5.3 (through RTK 2.12): `src/verification/s21-selectors-and-listeners.claims.test.ts`.

---

## 1. Anatomy

```ts
const selectVisibleIds = createSelector(
  [selectTasks, (state: RootState, filter: TaskFilter) => filter.status], // INPUT selectors
  (tasks, status) => tasks.filter((t) => !status || t.status === status).map((t) => t.id), // RESULT function
);

selectVisibleIds(state, { status: 'TODO' }); // called like any selector
```

- **Input selectors** receive **all** the arguments the selector is called with (`state`, then any extra arguments). Their job: **extract** values. They must be cheap and must return existing references or primitives.
- The **result function** (also called the *combiner*) receives the input selectors' results, in order. Its job: **compute**. It runs only when an input result changed.

RTK's `createSelector` **is** reselect's (verified: `createSelector === reselect.createSelector`). You don't need to install reselect.

## 2. What happens on a call: two levels of cache

reselect 5 memoizes twice:

1. **The arguments** (`argsMemoize`): if `(state, …args)` are the same references as a previous call, return that call's result immediately. Not even the input selectors run.
2. **The inputs** (`memoize`, around the result function): run the input selectors; if their results are all the same references (`===`) as a cached set, return the cached result without running the result function.

That's why, verified in the claims test, an input selector that builds a new object recomputes on every **new state** (every dispatch) but **not** when called twice with the same state: the argument cache answered the second call (21.19).

## 3. What it compares, and what it doesn't

- It compares **input results**, not the output. If the inputs changed, the result function runs and returns whatever it returns, a new array even if the content is identical. (The `resultEqualityCheck` option can fix that for arrays of ids, 21.08.)
- The comparison is **reference equality**. Immer (20.05) makes this work: an update to task 5 gives a new `entities` object but keeps `state.listPrefs` and every other slice.

## 4. The selector object: metadata for debugging and tests

Verified: a selector made by `createSelector` has these members:

```text
argsMemoize, clearCache, dependencies, dependencyRecomputations, lastResult, memoize,
memoizedResultFunc, recomputations, resetDependencyRecomputations, resetRecomputations,
resetResultsCount, resultFunc, resultsCount
```

The useful ones:

| Member | Use |
|---|---|
| `recomputations()` | how many times the result function ran: **the** number to assert in tests |
| `resetRecomputations()` | reset it between test steps |
| `resultFunc` | the raw result function: test the computation without building a state |
| `lastResult()` | the most recent result |
| `dependencies` | the input selectors |

```ts
it('recomputes only when tasks change', () => {
  const first = selectDoneTasks(state1);
  expect(selectDoneTasks(state2)).toBe(first);  // unrelated change
  expect(selectDoneTasks.recomputations()).toBe(1);
});
```

## 5. 📇 API card: `createSelector`

```ts
createSelector(inputSelectors: Selector[], resultFunc: (...inputResults) => Result, options?: CreateSelectorOptions)
createSelector(input1, input2, …, resultFunc, options?)   // the same, without the array (older style)
```

| Parameter | Meaning |
|---|---|
| `inputSelectors` | functions `(state, ...args) => value`; each receives **all** the arguments the selector is called with |
| `resultFunc` | `(...inputResults) => result`; runs only when an input result changed |
| `options.memoize` | the memoizer around `resultFunc` (default `weakMapMemoize`; or `lruMemoize`, 21.08) |
| `options.memoizeOptions` | options for it: `maxSize`, `resultEqualityCheck` (and `equalityCheck` for `lruMemoize`) |
| `options.argsMemoize` / `argsMemoizeOptions` | the memoizer (and its options) for the **arguments** cache (default `weakMapMemoize`) |
| `options.devModeChecks` | `{ inputStabilityCheck, identityFunctionCheck }`, each `'once'` (default), `'always'` or `'never'` (verified) |

**Returns** a selector `(state, ...args) => Result` with the debugging members of §4.

**Related helpers**

| Helper | Where from | What it does |
|---|---|---|
| `createSelector.withTypes<RootState>()` | RTK / reselect | a `createSelector` whose input selectors' `state` is already typed (verified) |
| `createSelectorCreator(memoize, options?)` | RTK / reselect | a custom `createSelector` with different defaults (e.g. `lruMemoize` everywhere) |
| `createStructuredSelector({ a: selA, b: selB })` | **`reselect` only** (RTK doesn't re-export it) | a selector returning `{ a, b }`, memoized as a whole (verified: same object while inputs are unchanged) |

**Minimal example (outside TaskFlow)**

```ts
const selectTodos = (state: RootState) => state.todos;
const selectDoneCount = createSelector([selectTodos], (todos) => todos.filter((t) => t.done).length);
const selectTodosByTag = createSelector(
  [selectTodos, (_state: RootState, tag: string) => tag],
  (todos, tag) => todos.filter((t) => t.tags.includes(tag)),
);
```

**Use it when** a selector **derives** new data (filter, map, sort, join, group, count into an object) that components read, so that the derived value keeps the same reference until its inputs change.

**Don't use it when** the selector just **reads** a value (`state.todos`, `state.todos.entities[id]`), or returns a primitive: memoization adds cost and memory for nothing (21.09). And not for values computed **once** in an event handler: a plain function is enough.

**Common mistakes** (each has its own lecture)

- An input selector that builds a new object or array → recomputes on every state change (21.19).
- A result function that returns its input unchanged (`(todos) => todos`) → pointless; the identity check warns (21.08).
- One selector shared by many components with different arguments under a size-1 cache → thrashing (21.07, 21.20).
- Creating the selector inside a component body without `useMemo` → a new, empty cache on every render (21.07).

## 6. Summary

- Input selectors **extract**, the result function **computes**.
- Two caches: arguments first, then input results; both compare references.
- The output isn't compared (unless you ask, 21.08); `recomputations()` is how you test memoization.
