# Lecture 21.20 · 🐞 Debug: Three Board Columns Share One Parameterised Selector and Thrash Its Cache

> **Section:** S21 · **Type:** 🐞 Debug · **Track:** ★ Core · **Time:** ~20 minutes
> Reproduced with reselect 5.3: recomputation counts pinned by `src/verification/s21-selectors-and-listeners.claims.test.ts` (*"cache size per memoizer"*).

---

## Symptom

A project bounds memory by making `lruMemoize` the default for all its selectors (a common setup in apps that started on reselect 4):

```ts
// app/createAppSelector.ts
export const createAppSelector = createSelectorCreator({ memoize: lruMemoize, argsMemoize: lruMemoize });
```

The board uses one shared selector for its three columns:

```ts
export const selectTaskIdsByStatus = createAppSelector(
  [selectSortedTasks, (_state: RootState, status: TaskStatus) => status],
  (tasks, status) => tasks.filter((t) => t.status === status).map((t) => t.id),
);

function BoardColumn({ status }: { status: TaskStatus }) {
  const taskIds = useAppSelector((state) => selectTaskIdsByStatus(state, status));
  …
}
```

The Profiler shows all three columns, and all their cards, re-rendering after **every** action, even a toast. `selectTaskIdsByStatus.recomputations()` grows by 3 per dispatch.

## Investigation checklist

1. How many argument sets does `lruMemoize` remember by default? (21.08)
2. In which order are the three columns' selectors called after a dispatch? What does each call do to the cache?
3. Would the default `weakMapMemoize` have this problem with a string argument?
4. How do you give each column its own cache, whatever the memoizer?

## Explanation

`lruMemoize` defaults to `maxSize: 1`. After each dispatch, React-Redux runs the three columns' selectors: `'TODO'`, then `'IN_PROGRESS'`, then `'DONE'`. Each call has a different argument than the one cached, so it **misses**, recomputes, returns a **new** array, and **evicts** the previous column's entry. Every column gets a new array every time → every column re-renders → every card re-renders. Verified: alternating 2 arguments 4 times with `lruMemoize` size 1 → **4** recomputations (every call).

## Fixes (pick one)

1. **A factory, one instance per column** (TaskFlow's choice, robust with any memoizer):

   ```ts
   export const makeSelectTaskIdsByStatus = () =>
     createSelector([selectSortedTasks, (_state: RootState, status: TaskStatus) => status], (tasks, status) =>
       tasks.filter((t) => t.status === status).map((t) => t.id),
     );

   const selectTaskIdsByStatus = useMemo(() => makeSelectTaskIdsByStatus(), []);
   ```

   Verified (`taskListSelectors.test.ts`): two instances, 2 recomputations in total, cached arrays after an unrelated action.

2. **A larger cache** for this selector: `memoizeOptions: { maxSize: 3 }` and `argsMemoizeOptions: { maxSize: 3 }`. Verified: 2 alternating arguments → 2 recomputations. Fragile: a fourth column breaks it again.

3. **The default `weakMapMemoize`** for this selector: cached per argument (verified: 2 recomputations). Fine for a handful of primitive arguments.

## Lessons

- A size-1 cache + callers with different arguments = thrashing: every call misses.
- A selector factory gives each component instance its own cache, independent of the memoizer.
- Check the project's `createSelector` setup before assuming reselect 5's defaults.
