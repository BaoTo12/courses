# Lecture 21.14 · The Listener Middleware: "When This Action Happens, Run That Effect"

> **Section:** S21 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~50 minutes

## 1. The problem it solves

Some logic doesn't start with a user click. It **reacts** to something that happened:

- "When a task is saved, show a toast." (Every page that saves would otherwise repeat it.)
- "When the quick-find text changes, wait 300 ms of silence, then search, and cancel the older search." (21.15)
- "When the sort preference changes, save it to a cookie." (24.06)

A **thunk** runs when *you* dispatch it. A **reducer** can't have side effects. A hand-written **middleware** (16.10) can react, but you'd write the plumbing yourself: matching, async, cancellation. The **listener middleware** is RTK's ready-made middleware for exactly this: you register *listeners*, each with a **trigger** and an **effect**.

## 2. How it works

```text
dispatch(action) ─► listener middleware ─► … ─► reducers update the state
                           │
                           └─ after the reducers: for each listener whose trigger matches,
                              run effect(action, listenerApi)   (sync or async, not awaited by dispatch)
```

- Effects run **after** the action reached the reducers (verified: `getState()` shows the new value, `getOriginalState()` the old one).
- `dispatch` doesn't wait for async effects, and an error thrown in an effect doesn't make `dispatch` throw: it goes to `onError` (verified).

## 3. 📇 API card: `createListenerMiddleware`

```ts
const listenerMiddleware = createListenerMiddleware({ extra?, onError? })
```

| Option | Meaning |
|---|---|
| `extra` | a value available as `listenerApi.extra` in every effect (TaskFlow passes the same `extra` as its thunks: the API layer) |
| `onError(error, { raisedBy })` | called when an effect or predicate throws; `raisedBy` is `'effect'` or `'predicate'` (verified). Default: logs with `console.error` |

**Returns** an instance:

| Member | Meaning |
|---|---|
| `middleware` | add it to the store: `getDefaultMiddleware().prepend(listenerMiddleware.middleware)` |
| `startListening(options)` | registers a listener; **returns an unsubscribe function** (verified) |
| `stopListening(options)` | removes a listener registered with the same options (`{ cancelActive: true }` also cancels running effects) |
| `clearListeners()` | removes all listeners |

**`startListening` options: exactly one trigger, plus the effect**

| Trigger | Example | Runs for |
|---|---|---|
| `actionCreator` | `actionCreator: saveTask.fulfilled` | that creator's actions (payload typed) |
| `type` | `type: 'tasks/saved'` | that type string |
| `matcher` | `matcher: isTaskSaved` (a **constant**, see §5) | actions the type guard accepts |
| `predicate` | `predicate: (action, currentState, originalState) => boolean` | any condition, including **state changes** (verified: "value increased") |
| `effect` (required) | `effect: async (action, listenerApi) => { … }` | the work |

**The `listenerApi` (the effect's second argument)**

| Member | Meaning |
|---|---|
| `dispatch`, `getState`, `extra` | as in thunks |
| `getOriginalState()` | the state **before** this action; callable only **synchronously** at the start of the effect (verified: after an `await` it throws *"getOriginalState can only be called synchronously"*) |
| `cancelActiveListeners()` | cancel **other running instances** of this same listener (the key to debouncing) |
| `signal` | an `AbortSignal` aborted when this instance is cancelled: pass it to `fetch`/Axios |
| `delay(ms)` | wait; **rejects if this instance is cancelled** meanwhile, which stops the effect silently (verified) |
| `pause(promise)` | await a promise, but stop if cancelled |
| `condition(predicate, timeout?)` | wait until the predicate is true → `true`, or the timeout → `false` (verified) |
| `take(predicate, timeout?)` | wait for the next matching action → `[action, currentState, previousState]` (verified), or `null` on timeout |
| `fork(executor)` | start a child task; `await task.result` → `{ status: 'ok', value }` / `'rejected'` / `'cancelled'` (verified) |
| `cancel()`, `throwIfCancelled()` | cancel this instance / throw if it was cancelled |
| `unsubscribe()`, `subscribe()` | remove / re-add this listener (e.g. "run only once") |

**Typing:** `listenerMiddleware.startListening.withTypes<RootState, AppDispatch, Extra>()`, or the type `TypedStartListening<RootState, AppDispatch, Extra>` (20.08).

**Adding listeners at runtime** (for example in a component's `useEffect`): `const unsubscribe = dispatch(addListener({ actionCreator, effect }))` returns the unsubscribe function (verified); `removeListener` and `clearAllListeners` are the matching actions.

## 4. Minimal examples (outside TaskFlow)

```ts
// 1. React to an action
listenerMiddleware.startListening({
  actionCreator: todoAdded,
  effect: (action, api) => {
    api.dispatch(notificationShown(`Added: ${action.payload.text}`));
  },
});

// 2. React to a STATE change (predicate compares old and new state)
listenerMiddleware.startListening({
  predicate: (_action, current, original) => current.cart.items.length !== original.cart.items.length,
  effect: (_action, api) => {
    localStorage.setItem('cartSize', String(api.getState().cart.items.length));
  },
});

// 3. Debounce + cancel: only the last of several quick actions does the work
listenerMiddleware.startListening({
  actionCreator: searchChanged,
  effect: async (action, api) => {
    api.cancelActiveListeners();   // older runs stop at their next delay/pause, and their signal aborts
    await api.delay(300);
    const results = await searchApi(action.payload, api.signal);
    api.dispatch(searchResultsReceived(results));
  },
});
```

## 5. The typing trap: don't write the matcher inline

Verified with `tsc`: with `matcher: isAnyOf(a.fulfilled, b.fulfilled)` or `matcher: isFulfilled(a, b)` written **inside** the options object, TypeScript types the effect's `action` as a bare `Action`, so `action.payload` doesn't compile (*"Property 'payload' does not exist on type 'Action'"*). The same matcher stored in a **constant** first, or a creator's `.match`, works:

```ts
const isTaskSaved = isFulfilled(saveNewTask, saveTask);
startAppListening({ matcher: isTaskSaved, effect: (action) => { action.payload.title; /* typed */ } });
```

## 6. When to use it, when not

**Use a listener when** the logic is a **reaction**: it starts because an action or a state change happened, not because a component asked for it. Also for long-running workflows (wait for X, then Y) and for anything that needs "latest wins" cancellation.

**Don't use a listener when**

- a component wants to **start** an operation and use its result (`unwrap()` for navigation, field errors): a **thunk** (20.09);
- you're fetching and caching server data: **RTK Query** (S22);
- the "reaction" is just deriving data from state: a **selector**, not an effect that writes derived data back into the store.

21.16 compares thunks, listeners and middleware side by side.

## 7. Common mistakes

- Forgetting `cancelActiveListeners()` in a debounce: every keystroke's effect still runs after its delay.
- Not passing `listenerApi.signal` to the request: the old request isn't aborted, it only has its result ignored.
- Dispatching the same action the listener listens to, unconditionally: an infinite loop.
- An inline `isAnyOf(…)` matcher (§5).
- Putting the listener middleware **after** a middleware that swallows actions: it never sees them. Prepend it.

## 8. Summary

- `createListenerMiddleware({ extra, onError })`, add `.middleware` to the store, register with `startListening({ trigger, effect })`.
- Effects run after the reducers, can be async, and can wait (`delay`, `condition`, `take`), cancel (`cancelActiveListeners`, `signal`) and fork.
- Use listeners for reactions; thunks for component-initiated operations; RTK Query for server data.
