# Lecture 21.08 · reselect 5: `weakMapMemoize`, `lruMemoize`, `resultEqualityCheck` and the Development Checks

> **Section:** S21 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~35 minutes
> Verified with reselect 5.3 via RTK 2.12: `src/verification/s21-selectors-and-listeners.claims.test.ts` and `taskListSelectors.test.ts`. Option names and defaults are copied from reselect's type definitions.

---

## 1. Two memoizers ship with reselect (and RTK re-exports both)

| | `weakMapMemoize` (**default** since reselect 5) | `lruMemoize` (reselect 4's `defaultMemoize`) |
|---|---|---|
| Remembers | a result **per argument set** | the last `maxSize` argument sets (default **1**) |
| Keyed by | object arguments in `WeakMap`s (released when the object is garbage-collected); primitives in `Map`s (kept until `clearCache()`) | a list compared with `equalityCheck` (default `===`) |
| Alternating arguments `1,2,1,2` | 2 recomputations (verified) | 4 with `maxSize: 1`; 2 with `maxSize: 3` (verified) |
| Risk | unbounded growth for many distinct **primitive** arguments (search texts, ids, timestamps) | thrashing when callers alternate arguments |

Remember: `createSelector` uses a memoizer **twice**: `argsMemoize` for the arguments and `memoize` for the input results (21.04). Both default to `weakMapMemoize`.

## 2. 📇 API card: memoizer options

**`weakMapMemoize(fn, options?)`**

| Option | Default | Meaning |
|---|---|---|
| `resultEqualityCheck` | — | `(a, b) => boolean`: when a **newly computed** result equals a cached one, return the cached one |
| `maxSize` | unbounded | bound for **primitive** arguments; **generational**, not LRU: after `maxSize` results the whole cache becomes the "previous generation"; entries still used are copied forward, unused ones are dropped with their generation (verified: an argument unused for a while was recomputed; the most recent wasn't) |

**`lruMemoize(fn, options?)`**

| Option | Default | Meaning |
|---|---|---|
| `maxSize` | `1` | how many argument sets to remember (least recently used evicted first) |
| `equalityCheck` | `===` (`referenceEqualityCheck`) | how **arguments** are compared (you could pass `shallowEqual`) |
| `resultEqualityCheck` | — | as above |

**Passing them to `createSelector`** (to bound a selector, set **both** caches):

```ts
createSelector(inputs, resultFunc, {
  memoize: lruMemoize,           // or weakMapMemoize (default)
  memoizeOptions: { maxSize: 10 },
  argsMemoize: lruMemoize,
  argsMemoizeOptions: { maxSize: 10 },
});
```

**When to change the defaults**

- Leave them for most selectors.
- A selector called with **many different primitive arguments** for the lifetime of the page (a search text, an id per row, a date): add `maxSize` to both caches, or use a factory per component (21.07).
- A selector returning a **list of ids** that often recomputes to the same ids: add `resultEqualityCheck` (§3).
- A codebase that wants reselect 4 behaviour everywhere: `createSelectorCreator(lruMemoize)` once, and use that instead of `createSelector`.

## 3. `resultEqualityCheck`: same content → same reference

The weakness from 21.04: when an input changes, the result function runs and returns a **new** array, even if its content is identical. Example: renaming a task changes `selectTasks`' output, so `selectVisibleTaskIds` recomputes; the visible ids are the same, but the array is new, so `TaskList` would re-render.

TaskFlow's list selectors pass a shallow array comparison:

```ts
function sameItems(a: readonly unknown[], b: readonly unknown[]): boolean {
  return a.length === b.length && a.every((item, index) => item === b[index]);
}

const keepSameIds = { memoizeOptions: { resultEqualityCheck: sameItems } };
```

Verified (*"resultEqualityCheck: a change that keeps the same ids returns the SAME ids array"*): after a task edit, the selector **recomputed**, then returned the **previous** array.

Cost: one extra comparison per recomputation (O(n) for an ids array). Use it for arrays of primitives; don't deep-compare big object trees.

## 4. The development checks

In development, reselect runs two checks on each selector's **first** call (`'once'`, the default):

| Check | Warns when | Captured message (start) |
|---|---|---|
| `inputStabilityCheck` | an input selector returns a **different** reference when called twice with the **same** arguments | *"An input selector returned a different result when passed same arguments. This means your output selector will likely run more frequently than intended."* |
| `identityFunctionCheck` | the result function returns its first input unchanged | *"The result function returned its own inputs without modification. e.g `createSelector([state => state.todos], todos => todos)`"* |

Configure them per selector, or for the whole app with `setGlobalDevModeChecks` (exported by **`reselect`**, not by RTK):

```ts
createSelector(inputs, resultFunc, { devModeChecks: { inputStabilityCheck: 'always' } }); // 'once' | 'always' | 'never'
```

Verified: `'always'` warned on every call (2 calls → 2 warnings); `'never'` stayed silent. The checks don't run in production builds.

## 5. Summary

- Default `weakMapMemoize`: per-argument cache; bound primitives with `maxSize` (both caches).
- `lruMemoize`: size-limited, reselect 4 style; size 1 thrashes with alternating arguments.
- `resultEqualityCheck` keeps the same reference for equal results (ids arrays).
- Read the development warnings: they point straight at the two most common selector bugs (21.19).
