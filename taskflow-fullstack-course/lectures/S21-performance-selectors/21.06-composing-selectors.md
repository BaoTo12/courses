# Lecture 21.06 · Composing Selectors; Selectors That Take Arguments

> **Section:** S21 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~25 minutes
> Verified: the examples come from `taskListSelectors.ts` and its tests (21.05).

---

## 1. Selectors are functions of the state, so they compose

Any selector can be an input of another:

```text
selectTasks ──┐
              ├─► selectSortedTasks ──┐
selectSort ───┘                       ├─► selectVisibleTaskIds(state, filter)
filter.status / .categoryId / .q ─────┘
```

Each level caches its own result. A sort change recomputes `selectSortedTasks` and then `selectVisibleTaskIds`; a toast recomputes nothing. When you design a chain, put the expensive, widely shared step (sorting) where many selectors can reuse it.

Composition also keeps knowledge in one place: only `tasksSlice.ts` knows that tasks live in `state.tasks.entities`; everything else goes through `selectTasks`. When the slice moved to an entity adapter (21.13), no other selector changed.

## 2. Arguments: `(state, …args)`

```ts
selectTaskById(state, 5)
selectVisibleTaskIds(state, { status: 'TODO', q: 'report' })
selectOverdueTasks(state, '2026-09-26')
```

Rules for arguments:

1. **All input selectors receive all arguments.** `(_state, filter) => filter.status` ignores the state; `selectTasks` ignores the filter. Name unused parameters with `_`.
2. **Extract primitives** in the input selectors when the argument is an object. The result function then receives stable values (`'TODO'`, `undefined`), and a new `{ … }` each render still hits the cache (21.09).
3. **Values that change over time are arguments, not reads.** A selector must not call `Date.now()`: the same state must give the same result. `selectOverdueTasks(state, today)` receives the date from the component (21.17).

### Calling it from a component

```ts
const visibleIds = useAppSelector((state) =>
  selectVisibleTaskIds(state, { status: statusFilter ?? undefined, categoryId: categoryFilter ?? undefined, q: debouncedQ }),
);
```

The inline arrow is fine: `useSelector` calls it after each dispatch, and the memoized selector returns the same array while nothing relevant changed.

## 3. Selectors that don't need `createSelector`

| Selector | Why not memoized |
|---|---|
| `selectSort = (state) => state.listPrefs.sort` | returns an existing reference |
| `selectTaskById(state, id)` (the adapter's) | a lookup: returns an existing reference, O(1) |
| `selectTasksStatus`, `selectCompletionRate` | return primitives |

## 4. Summary

- Build selectors from selectors; each level caches.
- Pass values from outside the store (URL, today's date) as arguments; extract primitives in input selectors.
- Memoize only what builds new objects or arrays.
