## 1. The task

Rebuild `/dashboard` (today it groups the tasks in render) as four widgets:

```text
┌ Completion ─────────┐ ┌ By status ──────────────────┐
│ (ring)  27%         │ │ To do 12  In progress 4  Done 6 │
│ 27% of 22 tasks done│ └──────────────────────────────┘
└─────────────────────┘ ┌ Overdue (1) ────────────────┐
┌ By priority ────────┐ │ Fix login redirect bug  due 2026-09-20 │
│ Low 7 Medium 9 High 6│ └──────────────────────────────┘
└─────────────────────┘
```

## 2. Requirements

1. Four selectors in `src/features/dashboard/dashboardSelectors.ts`:
   - `selectStatusCounts(state)` → `Record<TaskStatus, number>`
   - `selectPriorityCounts(state)` → `Record<Priority, number>`
   - `selectCompletionRate(state)` → a number 0–100 (0 when there are no tasks)
   - `selectOverdueTasks(state, today)` → the open tasks due **before** `today` (a `'YYYY-MM-DD'` string), oldest first. A task due today isn't overdue; a DONE task never is.
2. **No selector reads the clock.** `today` comes from a small hook, `useToday()`, returning the **local** date (careful: `toISOString()` gives the UTC date).
3. Each widget is its own component and selects **only** what it displays.
4. `DashboardPage` selects nothing that changes when a task is edited except what it needs to decide "loading or not".
5. **Performance proof:** with React's `<Profiler>` (or the DevTools Profiler), show that dispatching a toast, changing the sort preference, and typing in the quick find cause **zero** commits in the dashboard's widgets, while toggling a task causes exactly one.
6. Tests: values (including "due today" and "done" edge cases), "same result after unrelated actions" for the memoized selectors, and "recomputes when a task changes".

## 3. Hints

<details>
<summary>Hint 1: which selectors need <code>createSelector</code>?</summary>

The ones that build objects or arrays (the two count records, the overdue list). The completion rate returns a number: `===` works without memoization, but it can **reuse** the memoized counts.
</details>

<details>
<summary>Hint 2: the date argument</summary>

`createSelector([selectTasks, (_state, today: string) => today], …)`. A string is a primitive, so the same date hits the cache.
</details>

<details>
<summary>Hint 3: dispatching actions from the browser console for the proof</summary>

On a fresh page load (no hot update since), `const { store } = await import('/src/app/store.ts')` gives the app's store (17.13), and you can import action creators the same way.
</details>

<details>
<summary>Hint 4: existing helpers</summary>

`domain/task-utils.ts` already has `groupByStatus`, `countByPriority` and `isOverdue(task, today)`.
</details>
