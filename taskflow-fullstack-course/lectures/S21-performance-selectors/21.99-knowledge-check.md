2. Why does a selector returning `tasks.filter(…)` re-render its component after every action, even when the result's content is unchanged? [21.02]
3. `memo`, `useCallback`, selecting by id: what does each contribute to "toggling one task re-renders one card"? What happens if you remove only one? [21.10]
4. What's the difference between `setOne`, `upsertOne` and `addOne` for an entity that already exists? [21.12]

## B. Code reading

   const select = createSelector([(s: S) => s.tasks, (_s: S, status: string) => status], (tasks, status) => tasks.filter((t) => t.status === status));

6. A listener effect does `api.cancelActiveListeners(); await api.delay(300); await search(q, api.signal);`. Three actions arrive 100 ms apart. How many searches start? What happens to the second effect at its `delay`? [21.14]

## C. Debugging

8. In a listener, `startListening({ matcher: isAnyOf(a.fulfilled, b.fulfilled), effect: (action) => action.payload.title })` doesn't compile: *"Property 'payload' does not exist on type 'Action'"*. Fix it without a cast. [21.14 §5]

## D. Design

10. The sort order is a user preference. Why doesn't TaskFlow use the entity adapter's `sortComparer` for it? [21.12 §4]
11. "When a task is saved, show a toast": thunk, listener or middleware? And "the form must show the server's field errors after saving"? [21.16]

## E. Implementation

12. Write `makeSelectTasksByStatus()`, used by three columns without cache thrashing whatever the project's memoizer, and the component code that creates one instance per column. Write a test proving there's no thrashing across an unrelated dispatch.

<details>
<summary><b>Answers</b></summary>

1. The **input selectors' results**, each with `===` (reference equality). Output isn't compared unless you set `resultEqualityCheck`. Two caches: the **arguments** cache (`argsMemoize`: same `state` and arguments → return the last result without running anything) and the **inputs** cache (`memoize`: same input results → skip the result function). Both default to `weakMapMemoize`.

2. `useSelector` compares the new result with the previous one using `===`. `filter` creates a new array every call, so it's always "different", and every dispatch (which runs all selectors) re-renders the component. Memoization makes the selector return the **same** array while its inputs are unchanged.

3. **Select by id** in the item: only the toggled task's item gets a new value from `useSelector`. **`memo`**: items whose props didn't change skip rendering when the parent renders. **`useCallback`**: keeps the function props identical, so `memo`'s shallow comparison succeeds. Measured: without `useCallback`, or without `memo`, a toggle re-renders all **22** cards; with all three, **1**.

4. `addOne` **ignores** it (the old entity stays); `setOne` **replaces** it entirely (fields missing in the new object disappear); `upsertOne` **shallow-merges** the new fields into the old entity. Verified in the claims tests.

5. reselect 5 defaults (`weakMapMemoize`): **2** (one per distinct status; the 3rd and 4th calls hit). `lruMemoize` size 1: **4** (each call evicts the other's entry: thrashing). Both verified.

6. **One** search (for the third action). Each new action's effect calls `cancelActiveListeners()`, cancelling the previous instance; the cancelled instance's `delay` **rejects** (a `TaskAbortError`), which ends that effect silently. Only the third effect survives its 300 ms delay. If a search were already in flight, the cancellation would abort its `signal` too.

7. The input selector builds a new object on every call. After each dispatch there's a new root state, so the input runs, returns a new object, and the result function recomputes a new result: a re-render on every action. The unit test passed because calling twice with the **same** state object is answered by the **arguments** cache. Fix: extract in inputs, combine in the result function: `createSelector([selectTasks, (s) => s.listPrefs.sort], (tasks, sort) => …)`, or select primitives. Test across an unrelated dispatch.

8. Store the matcher in a constant first: `const isSaved = isAnyOf(a.fulfilled, b.fulfilled); startListening({ matcher: isSaved, effect: (action) => action.payload.title })`, or use `actionCreator` / `.match` for a single action. Written inline, TypeScript types the effect's action as a bare `Action` (verified).

9. `state.tasks.entities[id]` already returns the **same** object reference until that task changes (Immer keeps unchanged entities). A memoized wrapper would add cache lookups and memory to return the same reference.

10. `sortComparer` imposes **one fixed** order on `ids`, re-sorting on every insert and update. The user can change the sort key and direction at runtime; that's a derived view, computed by a memoized selector (`selectSortedTasks`) from the tasks and the preference. `ids` keep the server's order.

11. The toast is a **reaction** to "a task was saved", whoever saved it: a **listener**. Showing field errors needs the **result** in the component that started the save: a **thunk**, awaited with `.unwrap()`. (Logging every action would be middleware.)

12. Verified in TaskFlow (`taskListSelectors.ts`, `Board.tsx`, and the test *"makeSelectTaskIdsByStatus: one instance per column, no thrashing"*):
    ```ts
    export const makeSelectTasksByStatus = () =>
      createSelector(
        [selectSortedTasks, (_state: RootState, status: TaskStatus) => status],
        (tasks, status) => tasks.filter((task) => task.status === status),
      );

    function BoardColumn({ status }: { status: TaskStatus }) {
      const selectTasksByStatus = useMemo(() => makeSelectTasksByStatus(), []);
      const tasks = useAppSelector((state) => selectTasksByStatus(state, status));
      …
    }
    ```
    ```ts
    it('no thrashing across an unrelated dispatch', () => {
      const store = sample();
      const selectTodo = makeSelectTasksByStatus();
      const selectDone = makeSelectTasksByStatus();
      const todo = selectTodo(store.getState(), 'TODO');
      const done = selectDone(store.getState(), 'DONE');
      store.dispatch(toastShown({ tone: 'info', message: 'x' }));
      expect(selectTodo(store.getState(), 'TODO')).toBe(todo);
      expect(selectDone(store.getState(), 'DONE')).toBe(done);
      expect(selectTodo.recomputations() + selectDone.recomputations()).toBe(2);
    });
    ```
    Each instance only sees one status, so even a size-1 cache always hits. (TaskFlow returns ids rather than tasks, so each card selects its own task, 21.11.)
