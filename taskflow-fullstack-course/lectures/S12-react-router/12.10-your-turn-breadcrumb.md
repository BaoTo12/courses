# Lecture 12.10 · 🎯 Your Turn: a Breadcrumb, and "Back to List Keeps My Filters"

> **Section:** S12 · **Type:** 🎯 Your Turn · **Track:** ★ Core · **Time:** ~60 minutes

---

## 1. The problem

A user filters the list to `/tasks?status=IN_PROGRESS&q=report`, opens a task, then clicks **Back to list**. The link goes to `/tasks`, so their filters are gone. (The browser's Back button works, because history has the filtered URL. But the in-page link doesn't know where the user came from.)

The same happens after **Edit → Save**: the details page's "Back to list" has lost the filters.

## 2. The task

1. When a user opens a task **from the list** (the card title or its Edit link), remember the list's query string.
2. On the details page, show a **breadcrumb** `Tasks › <task title>` above the title. "Tasks" links to the remembered list URL.
3. The "Back to list" link goes to the same remembered URL.
4. The details page gets an **Edit** link that keeps the remembered state, so that after Edit → Save (12.05 already passes `state: location.state` on save), "Back to list" still restores the filters.
5. When the page is opened **directly** (a pasted URL, a bookmark, a new tab), there's nothing remembered, and both links fall back to `/tasks`.

## 3. Requirements

- Use React Router's **history state** (`<Link to=… state={…}>`, read with `useLocation().state`). Don't add the filters to the details URL (`/tasks/5?status=…` would make "task 5" URLs non-canonical and leak list filters into shared links).
- `location.state` is typed `unknown`. Validate it with a small **pure function** in `src/pages/list-link.ts`:
  ```ts
  export function backToListHref(state: unknown): string
  ```
  It returns `/tasks` + the remembered search string, or `/tasks` if the state is missing or malformed. Only accept a search string that is empty or starts with `?`.
- The breadcrumb is accessible: a `<nav aria-label="Breadcrumb">`, and the current page marked with `aria-current="page"`.
- Unit-test `backToListHref` and `parseTaskId` with Vitest (install it in `frontend/` with `npm install -D vitest` and add `"test": "vitest"` to `package.json`, as in S04).

## 4. Hints

<details>
<summary>Hint 1: where does the list's query string come from?</summary>

Inside `TaskCard`, `useLocation().search` is the current query string, such as `?status=DONE&q=report` (or `''`). The card is rendered by the list page, so that's the list's URL.
</details>

<details>
<summary>Hint 2: what shape should the state have?</summary>

A small object with one named field, such as `{ listSearch: location.search }`. A named field is easier to validate and to extend than a bare string.
</details>

<details>
<summary>Hint 3: narrowing <code>unknown</code></summary>

`typeof state === 'object' && state !== null && 'listSearch' in state` narrows `state` to `object & Record<'listSearch', unknown>` (TypeScript 4.9+). Then check `typeof state.listSearch === 'string'`. This is the 06.09 technique.
</details>

<details>
<summary>Hint 4: why validate at all? It's our own state.</summary>

History state is stored by the browser **per history entry** and survives reloads. It can be written by any script on the page (`history.replaceState({ usr: … }, '')`), by an older version of your app (after a deploy, the shape may have changed), or by a different page of the app. Treat it like any other input. And because the value ends up in a link's `href`, an unvalidated `//evil.example` would create a link to another site.
</details>

## 5. Acceptance checklist

- [ ] Filter the list, open a task: the breadcrumb and "Back to list" go to the filtered list.
- [ ] Filter, click a card's **Edit**, save: on the details page, "Back to list" still restores the filters.
- [ ] Filter, open a task, click **Edit** on the details page, save: same result.
- [ ] Paste `/tasks/3` into a new tab: both links go to `/tasks`.
- [ ] **Reload** the details page opened from a filtered list: the filters are still remembered (history state survives a reload; check in your browser).
- [ ] `npm test` passes, including malformed states (`null`, `42`, `{}`, `{ listSearch: 5 }`, `{ listSearch: '//evil.example' }`).
- [ ] `npm run build` and `npm run lint` pass.
