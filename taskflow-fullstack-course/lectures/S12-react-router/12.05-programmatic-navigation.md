# Lecture 12.05 · Programmatic Navigation, `replace`, and Redirecting After a Submit

> **Section:** S12 · **Type:** 📖 Theory + 🛠 Build · **Track:** ★ Core · **Time:** ~35 minutes
> **Project feature:** `/tasks/new` and `/tasks/:id/edit` pages; the form panel from S11 becomes real routes

---

## 1. `useNavigate`

Links are for things the user **clicks to go somewhere**. For navigation that happens **as a result of logic** (after saving, after login, on Cancel), use `useNavigate`:

```tsx
const navigate = useNavigate();

navigate('/tasks/5');                         // push a new history entry
navigate('/tasks/5', { replace: true });      // replace the current entry
navigate(-1);                                 // go back one entry (like the Back button)
navigate('/tasks/5', { state: { from: 'list' } });   // attach history state (12.10)
```

Call it in **event handlers or effects**, never during render (07.04: render must be pure). To redirect *during render* (e.g. a guard), return `<Navigate to="…" replace />` instead (12.06).

## 2. Why `replace` after a successful submit

Sequence **without** `replace`:

```text
/tasks  →  /tasks/new  →(submit)→  /tasks/1001
Back → /tasks/new   ← the form again, as if nothing was saved. Submit again → a duplicate task.
```

With `navigate(`/tasks/${created.id}`, { replace: true })`, `/tasks/new` is **replaced** by the new task's page, so Back returns to the list. This is the SPA equivalent of **Post/Redirect/Get (PRG)**, which you'll implement on the server for JSP forms in S37 to solve the same problem ("refresh resubmits the form").

## 3. ✍️ `src/pages/NewTaskPage.tsx`

```tsx
import { useNavigate } from 'react-router';
import { EMPTY_TASK_FORM, toCreateRequest } from '../domain/task-form';
import type { TaskFormValues } from '../domain/task-form';
import { toErrorMessage } from '../domain/guards';
import { fakeCreateTask } from '../data/fake-save';
import { useTasksContext } from '../tasks/tasks-context';
import { useToast } from '../toast/toast-context';
import { TaskForm } from '../components/TaskForm';

export function NewTaskPage() {
  const { addTask } = useTasksContext();
  const { show } = useToast();
  const navigate = useNavigate();

  async function handleSubmit(values: TaskFormValues) {
    try {
      const created = await fakeCreateTask(toCreateRequest(values));
      addTask(created);
      show({ tone: 'success', message: `Created: ${created.title}` });
      // replace: the form page shouldn't stay in history (Back would re-open a submitted form)
      navigate(`/tasks/${created.id}`, { replace: true });
    } catch (error) {
      show({ tone: 'error', message: toErrorMessage(error) });
    }
  }

  return (
    <>
      <h1 className="page__title">New task</h1>
      <TaskForm mode="create" initialValues={EMPTY_TASK_FORM} onSubmit={handleSubmit} onCancel={() => navigate(-1)} />
    </>
  );
}
```

## 4. ✍️ `src/pages/EditTaskPage.tsx`

```tsx
import { useLocation, useNavigate, useParams } from 'react-router';
import { toCreateRequest, toFormValues } from '../domain/task-form';
import type { TaskFormValues } from '../domain/task-form';
import { toErrorMessage } from '../domain/guards';
import { fakeUpdateTask } from '../data/fake-save';
import { useTasksContext } from '../tasks/tasks-context';
import { useToast } from '../toast/toast-context';
import { TaskForm } from '../components/TaskForm';
import { parseTaskId } from './list-link';
import { NotFoundPage } from './NotFoundPage';

export function EditTaskPage() {
  const { id: rawId } = useParams();
  const { state, replaceTask } = useTasksContext();
  const { show } = useToast();
  const navigate = useNavigate();
  const location = useLocation();

  const id = parseTaskId(rawId);
  if (id === null) return <NotFoundPage />;
  if (state.status !== 'succeeded') return <p className="text-muted">Loading…</p>;

  const task = state.data.find((t) => t.id === id);
  if (!task) return <NotFoundPage />;
  const existing = task; // a const the async handler can close over safely (05.07 §4)

  async function handleSubmit(values: TaskFormValues) {
    try {
      const saved = await fakeUpdateTask(existing, toCreateRequest(values, existing.categoryId));
      replaceTask(saved);
      show({ tone: 'success', message: `Saved: ${saved.title}` });
      navigate(`/tasks/${saved.id}`, { replace: true, state: location.state });
    } catch (error) {
      show({ tone: 'error', message: toErrorMessage(error) });
    }
  }

  return (
    <>
      <h1 className="page__title">Edit task</h1>
      <TaskForm
        key={task.id}
        mode="edit"
        initialValues={toFormValues(task)}
        onSubmit={handleSubmit}
        onCancel={() => navigate(-1)}
      />
    </>
  );
}
```

- **`key={task.id}`**: navigating from `/tasks/1/edit` to `/tasks/2/edit` reuses the same page component; the key gives a fresh form (11.11).
- **`state: location.state`** passes the history state along (used by the 12.10 exercise to remember the list's filters).

## 5. ✍️ Routes and the card's Edit link

In `App.tsx` add (protected in 12.06):

```tsx
<Route path="tasks/new" element={<NewTaskPage />} />
<Route path="tasks/:id/edit" element={<EditTaskPage />} />
```

Route **ranking** means `tasks/new` wins over `tasks/:id` for `/tasks/new`: static segments beat dynamic ones, whatever the order.

In `TaskCard`, replace the `onEdit` callback from S11 with a link:

```tsx
<Link className="btn btn--secondary btn--sm" to={`/tasks/${task.id}/edit`}>
  Edit
</Link>
```

…and **delete the `onEdit` prop** from `TaskCard`, `TaskList`, `Board` and `BoardColumn`. Navigation no longer needs to be drilled through props: any component can link anywhere. Remove the old `FormPanel` state from the tasks page too; routes replace it.

## 6. Summary

- `useNavigate()` for logic-driven navigation (in handlers); `<Navigate>` for render-time redirects.
- `replace: true` after successful submits = SPA-style PRG; `navigate(-1)` for Cancel.
- Routes replace UI state like "which panel is open"; links replace callback drilling for navigation.
