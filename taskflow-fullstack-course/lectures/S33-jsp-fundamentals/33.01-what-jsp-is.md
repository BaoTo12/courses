# Lecture 33.01 · What JSP Is: a Text Template Tomcat Turns into a Servlet

> **Section:** S33 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~15 minutes

---

**JavaServer Pages (JSP)** is a template format: a text file, mostly HTML, with special tags where dynamic content goes. The container's JSP engine (Tomcat's **Jasper**) **translates** each JSP into a Java **servlet** source file, **compiles** it, and runs it like any servlet.

```text
list.jsp  ──translate──►  list_jsp.java  ──compile──►  list_jsp.class  ──►  a servlet: _jspService(request, response)
(you write)               (Jasper writes)              (javac/JDT)          (Tomcat calls it)
```

Why it exists (1999, and still in countless applications):

- **HTML-first authoring.** Page authors write the page, and developers plug in values. It's the opposite of `println` (32.01).
- **No manual compile step.** Edit the `.jsp`, reload, and Jasper re-translates it (33.04).
- **The full servlet API underneath**: the same request, response, session and application (33.06).

What JSP is **not**:
- Not client-side. The browser never sees it (32.08).
- Not a different runtime. At request time, it's a servlet (33.05 proves it with the generated class).
- Not automatically safe. `<%= %>` and `${}` don't escape (32.11).

Its evolution, which this part of the course follows: scriptlets (Java in the page, **S33**) → Expression Language (`${task.title}`, **S34**) → JSTL tags (`<c:forEach>`, `<c:out>`, **S35**) → clean MVC views with **no Java at all** (S36+). Modern template engines (Thymeleaf, Freemarker, Jinja, Razor) share the same core idea.
