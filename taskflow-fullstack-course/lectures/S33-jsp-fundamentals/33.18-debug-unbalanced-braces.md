# Lecture 33.18 · 🐞 Debug: A Stray `<% } %>` Breaks the Page

> **Section:** S33 · **Type:** 🐞 Debug · **Track:** ★ Core · **Time:** ~15 minutes

---

## 1. The code

```jsp
<% if (tasks.isEmpty()) { %>
  <p class="text-muted">No tasks.</p>
<% } else { %>
  <table>
  <% for (Task task : tasks) { %>
    <tr><td><%= Html.escape(task.getTitle()) %></td></tr>
  <% } %>
  </table>
<% } %>
<% } %>                                <%-- ← one too many, left over from a copy-paste --%>
<%@ include file="/WEB-INF/views/common/footer.jspf" %>
```

## 2. The error

```text
Unable to compile class for JSP: … Syntax error on token "}", delete this token
```

It often points **near the end** of the generated method, or at the footer, not at the stray brace. Other variants: a **missing** `}` → "reached end of file while parsing", reported at the very last line.

## 3. Why it's so confusing

Each `<% … %>` is pasted **verbatim** into `_jspService`, with `out.write(…)` calls in between (33.03). Java sees one long method, and your braces must balance **across** all the scriptlets and HTML. The compiler can only notice at the point where the structure becomes impossible, which is usually far from the mistake.

## 4. Find it

1. Open the generated `list_jsp.java`: the IDE's brace matching works there, and in the JSP it doesn't.
2. Or comment out halves of the JSP (`<%-- --%>`) until it compiles (bisection).
3. Indent scriptlet blocks like code, and always open and close a block in **matching** positions.

## ✅ Takeaway

Blocks spanning scriptlets are fragile by construction. That's the strongest argument for S35's `<c:if>`/`<c:forEach>`: tags are **well-formed** (`<c:forEach>…</c:forEach>`), so a mismatch is reported exactly where it is.
