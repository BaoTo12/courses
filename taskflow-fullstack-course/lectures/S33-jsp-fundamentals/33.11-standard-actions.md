# Lecture 33.11 · Standard Actions: `<jsp:include>`, `<jsp:forward>`, `<jsp:param>`, `<jsp:useBean>`

> **Section:** S33 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~20 minutes

---

## 1. `<jsp:include>`: runtime include

```jsp
<jsp:include page="/WEB-INF/views/common/stats.jsp">
  <jsp:param name="compact" value="true"/>
</jsp:include>
```

| | `<%@ include file %>` (33.10) | `<jsp:include page>` |
|---|---|---|
| When | translation time | **each request** (`RequestDispatcher.include`, 31.10) |
| Result | one servlet, text pasted in | two servlets; the output inserted |
| Shares local variables | ✅ | ❌ (only request attributes and parameters) |
| Change detection | the including page is re-translated | the included JSP is re-translated on its own |
| Dynamic path | ❌ | ✅ (`page="${…}"`) |
| Use for | layout pieces (header, footer) | self-contained widgets |

## 2. `<jsp:forward>`

```jsp
<jsp:forward page="/WEB-INF/views/error/404.jsp"/>
```

It's `RequestDispatcher.forward` from a JSP. Deciding *where to go* is a controller's job (32.02). If a view needs to forward, the controller made its decision too late. Avoid it.

## 3. `<jsp:useBean>`, `<jsp:setProperty>`, `<jsp:getProperty>` (historical)

```jsp
<jsp:useBean id="task" class="com.taskflow.model.Task" scope="request"/>
<jsp:setProperty name="task" property="*"/>            <%-- copies EVERY request parameter onto matching setters! --%>
<jsp:getProperty name="task" property="title"/>        <%-- prints, UNESCAPED --%>
```

From the "Model 1" era, when JSPs did everything. Two reasons you'll only **read** them in old code:
- `property="*"` is **mass assignment** (31.12): `?ownerId=3` would call `setOwnerId(3)`.
- `getProperty` doesn't escape.

EL (`${task.title}`, S34) replaced `getProperty`, and controllers replaced `useBean`.
