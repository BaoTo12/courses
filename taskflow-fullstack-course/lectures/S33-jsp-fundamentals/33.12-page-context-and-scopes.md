# Lecture 33.12 · `pageContext` and the Four Scopes: the Foundation for EL

> **Section:** S33 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~20 minutes

---

## 1. Four scopes, one lookup

| Scope | Constant | Stored in | Lives |
|---|---|---|---|
| page | `PageContext.PAGE_SCOPE` | the `PageContext` of this JSP execution | one JSP's `_jspService` call |
| request | `REQUEST_SCOPE` | `HttpServletRequest` | one request (+ forwards/includes) |
| session | `SESSION_SCOPE` | `HttpSession` | one user's visit |
| application | `APPLICATION_SCOPE` | `ServletContext` | the app's lifetime |

```java
pageContext.setAttribute("x", 1);                                    // page scope
pageContext.setAttribute("x", 2, PageContext.REQUEST_SCOPE);          // = request.setAttribute("x", 2)
pageContext.getAttribute("x", PageContext.SESSION_SCOPE);
pageContext.findAttribute("tasks");   // searches page → request → session → application, first hit wins
```

## 2. Why this matters: EL is `findAttribute`

In S34, `${tasks}` means: **`pageContext.findAttribute("tasks")`**. It looks through the four scopes in that order. So:

- the controller's `request.setAttribute("tasks", …)` is found as `${tasks}`;
- a **session** attribute with the same name is **shadowed** by the request one (the narrower scope wins);
- a typo (`${task}` for `${tasks}`) finds nothing and prints **empty**, silently, with no exception (S34 debugging).

Explicit scopes avoid ambiguity: `${requestScope.tasks}`, `${sessionScope.user}`, `${applicationScope.stats}`.

## 3. Choose the narrowest scope

| Data | Scope |
|---|---|
| the list for this page | request |
| the logged-in user | session |
| the category list shared by everyone | application |
| a loop variable in a view | page (JSTL's `var` in S35) |

Wider scopes live longer, cost memory, and are shared: the application scope by **everyone** (30.13 §3), and the session by all of a user's tabs.
