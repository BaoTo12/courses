# Lecture 33.99 · ✅ Knowledge Check: JSP Fundamentals

> **Section:** S33 · **Type:** ✅ Knowledge Check · **Track:** ★ Core · **Time:** ~15 minutes

---

**1.** What's the difference between `<%! int x = 0; %>` and `<% int x = 0; %>` in the generated servlet? Which is thread-safe?

<details><summary>Answer</summary>

`<%! %>` is a **field** of the JSP's single servlet instance, shared by all requests and threads: not thread-safe, and it leaks data between users (33.09). `<% %>` is a **local variable** inside `_jspService`, one per request and thread: safe (33.07).
</details>

**2.** Is a JSP a servlet? Justify with the generated class's superclass.

<details><summary>Answer</summary>

Yes. The generated `list_jsp extends org.apache.jasper.runtime.HttpJspBase`, which extends `javax.servlet.http.HttpServlet`. Your page is the body of its `_jspService(request, response)` (33.03, 33.05).
</details>

**3.** Predict the generated `_jspService` body for:

```jsp
<%@ page contentType="text/html;charset=UTF-8" session="false" %>
<h1>Hi <%= name %></h1>
```

<details><summary>Answer</summary>

`response.setContentType("text/html;charset=UTF-8");`, then `getPageContext(…, needsSession=false, 8192, true)`, `out = pageContext.getOut();`, then `out.write("<h1>Hi ");`, `out.print( name );` (no escaping), `out.write("</h1>\n");`, all inside try/catch/finally with `handlePageException` and `releasePageContext`. There's no `session` variable (33.03).
</details>

**4.** After editing a JSP, the change doesn't appear. List the possible causes.

<details><summary>Answer</summary>

WAR (not exploded) deployment without a redeploy; editing a different copy than the deployed one; browser cache; development mode off / a long `checkInterval`; a stale `work/` translation (after `web.xml`/`jsp-config` changes, which Jasper doesn't watch); the change was in a Java class the JSP uses, which needs a redeploy (33.04).
</details>

**5.** Name three things a JSP should never do.

<details><summary>Answer</summary>

Any three of: access the database or call services; decide redirects, forwards or HTTP status; check permissions; hold state in declarations; contain business rules (like "overdue"); read the clock; print user data unescaped (33.13).
</details>

**6.** `<%@ include file %>` vs `<jsp:include page>`: which one can see the including page's local variables, and why?

<details><summary>Answer</summary>

The **directive**: it pastes the text in at translation time, so it's one method with shared locals. `<jsp:include>` calls another servlet at runtime, so it sees only request attributes and parameters (33.10, 33.11).
</details>

**7.** Why do TaskFlow's views declare `session="false"`?

<details><summary>Answer</summary>

With the default `true`, merely rendering the page **creates** an `HttpSession` and sends a `JSESSIONID` cookie to every visitor, anonymous ones and bots included. That wastes memory, and a pre-login session id is a session-fixation risk (S41). `S33JspFundamentalsTest` checks that `/tasks` sends no `Set-Cookie` (33.10).
</details>
