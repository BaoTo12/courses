# Lecture 33.05 · JSP vs Servlet: the Same Thing at Runtime, a Different Authoring Model

> **Section:** S33 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~10 minutes

---

**Is a JSP a servlet?** Yes. The generated `list_jsp` extends `HttpJspBase`, which extends `javax.servlet.http.HttpServlet` (33.03). Tomcat registers JSPs through its `JspServlet` (the `*.jsp` mapping), which loads and calls those generated servlets.

| | Servlet | JSP |
|---|---|---|
| You write | Java, with HTML in strings | HTML, with Java or EL or tags in it |
| Compiled | by you (Maven) | by Jasper, at runtime (or precompiled) |
| Mapping | `@WebServlet` / `web.xml` | its path (`/x.jsp`), or reached by forward |
| Lifecycle | `init` / `service` / `destroy` | `jspInit` / `_jspService` / `jspDestroy` (the same, underneath) |
| Instances | one per declaration | one per JSP file |
| Good at | **deciding**: HTTP, validation, calling services, choosing the view | **rendering** HTML |

That's why TaskFlow uses both, together: the servlet is the controller, and the JSP is the view (32.02). Each is terrible at the other's job. A JSP that queries the database, or a servlet that prints tables: you've now seen both.
