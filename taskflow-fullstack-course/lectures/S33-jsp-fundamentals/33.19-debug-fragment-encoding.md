# Lecture 33.19 · 🐞 Debug: `Â·` in the Title: the Fragment's Encoding (a Real One from This Course)

> **Section:** S33 · **Type:** 🐞 Debug · **Track:** ★ Core · **Time:** ~15 minutes
> This happened while building S33's reference project. `S32JspTest` and `S33JspFundamentalsTest` caught it.

## 1. Symptom

After moving the page frame into `header.jspf` (33.08), the browser tab reads `Tasks Â· TaskFlow Admin`. The body text is fine, and every page is served with `charset=UTF-8`. Two tests failed on `<title>Tasks · TaskFlow Admin</title>`.

## 2. Investigate: look at the generated code

```java
out.write(" Â· TaskFlow Admin</title>\n");        // from list_jsp.java: already wrong IN THE JAVA SOURCE
```

So the damage happened at **translation**, when Jasper read the file, not when the response was written.

- `list.jsp` declares `pageEncoding="UTF-8"`. It's read correctly.
- `header.jspf` declares **nothing**. For an included file, the JSP spec takes the encoding from a `jsp-config` property group or the file's own page directive. Neither existed, so **ISO-8859-1**.
- `·` is two bytes in UTF-8 (`C2 B7`). Read as ISO-8859-1, that's two characters: `Â` and `·`. Written out as UTF-8, it's mojibake (30.17 §5: "mis-decoded").

## 3. Fix, once for all JSPs and fragments

```xml
<jsp-config>
  <jsp-property-group>
    <url-pattern>*.jsp</url-pattern>
    <url-pattern>*.jspf</url-pattern>
    <page-encoding>UTF-8</page-encoding>
  </jsp-property-group>
</jsp-config>
```

## 4. The second surprise: the fix "didn't work"

After adding it, the tests **still** failed. Jasper reuses a translation while the `.jsp` and its fragments are unchanged, and it doesn't watch `web.xml` (33.04). Deleting the work folder, or touching the JSP, forced re-translation, and everything passed. The test harness now cleans its work folder on every run.

## ✅ Takeaways

- Every file that is part of a JSP needs a known encoding. Set `<page-encoding>` for `*.jsp` **and** `*.jspf` in `web.xml`.
- `Â` + a symbol = UTF-8 bytes read as Latin-1. Find **where** they were read (here: translation), not just where they're shown.
- After configuration changes, clear `work/` before believing a result.
