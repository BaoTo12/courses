# Lecture 33.07 · Scripting Elements: Scriptlets, Expressions, Declarations

> **Section:** S33 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~20 minutes

---

| Syntax | Name | Lands in the generated class as | Scope |
|---|---|---|---|
| `<% statements %>` | **scriptlet** | code inside `_jspService`, verbatim | local, **per request** |
| `<%= expression %>` | **expression** | `out.print( expression );` | per request |
| `<%! declarations %>` | **declaration** | **fields and methods of the class** | the **one** instance → shared by all requests and threads |
| `<%-- … --%>` | JSP comment | nothing | — |

```jsp
<%! int hits = 0; %>                <%-- a FIELD: shared by every user (33.09) --%>
<% int local = 0; hits++; local++; %>  <%-- local: 1 for everyone; hits: 1, 2, 3… across ALL users --%>
<p><%= hits %> / <%= local %></p>
```

Rules that follow from the generated code:

- Scriptlets can **open a block** that later scriptlets close: `<% for (Task t : tasks) { %> … <% } %>`. The HTML in between becomes `out.write` calls **inside** the loop. Unbalanced braces break compilation far from the mistake (33.18).
- An expression must be a **single Java expression, no semicolon**: `<%= task.getTitle(); %>` is a compile error.
- Declarations are **instance state**: the same thread-safety rules as servlet fields (30.05). Almost never use them.

**The TaskFlow rule from S34 on: no scripting elements in views at all.** S33 uses them so you understand what EL and JSTL replace.
