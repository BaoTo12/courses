# Lecture 33.17 · 🐞 Debug: A JSP Compile Error Points at `list_jsp.java:142`

> **Section:** S33 · **Type:** 🐞 Debug · **Track:** ★ Core · **Time:** ~20 minutes

---

## 1. The error

After renaming `Task.isDone()` to `Task.isCompleted()` in a branch:

```text
org.apache.jasper.JasperException: Unable to compile class for JSP:

An error occurred at line: [16] in the jsp file: [/WEB-INF/views/tasks/list.jsp]
The method isDone() is undefined for the type Task
13:   LocalDate today = LocalDate.now();
14:   int overdueCount = 0;
15:   for (Task t : tasks) {
16:     if (!t.isDone() && t.getDueDate() != null && t.getDueDate().isBefore(today)) overdueCount++;
17:   }

Stacktrace: … list_jsp.java:140 …
```

## 2. Two line numbers, two files

| Number | Refers to |
|---|---|
| `line: [16] in the jsp file` | **your** `list.jsp` (Jasper maps it back for you) |
| `list_jsp.java:140` in a stack trace | the **generated** servlet (33.03) |

Jasper usually reports the JSP line, as above. Runtime exceptions (an NPE in a scriptlet) show only the generated line in the stack trace. Then:

1. Open `list_jsp.java` in the work folder (33.03 §1) and go to line 140.
2. Your scriptlet code appears **verbatim**, so find the same statement in the `.jsp`.
3. Template text appears as `out.write("…")`: search the JSP for that text to locate the surrounding markup.

For included fragments, the error names the **fragment** (`header.jspf`) and its line.

## 3. Why the build didn't catch it

The JSP is compiled **at runtime** (33.02). `mvn package` compiled `Task.java` fine, and nothing compiled `list.jsp` until the first request. Defences:
- **tests that render every view** (TaskFlow's `TomcatTest` suites: the rename fails `S31`/`S32`/`S33` tests at build time);
- JSP **precompilation** in the build (33.04 §4);
- and fewer scriptlets. EL fails more gently: `${task.done}` on a missing property throws a `PropertyNotFoundException`, with the JSP line (S34).
