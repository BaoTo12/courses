# Lecture 33.13 · Why Modern JSP Avoids Java Code: Evidence from the Page You Wrote

> **Section:** S33 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~20 minutes

---

Look at `list.jsp` after 33.15 (the overdue feature). Each problem below is **in that file**:

| # | Problem | Where in `list.jsp` |
|---|---|---|
| 1 | **Business logic in the view**: "what is overdue?" is a domain rule. Duplicated in `view.jsp`, and in the API (Part 3), it will drift. | the `overdueCount` loop, and the `boolean overdue = …` per row |
| 2 | **Untestable**: the rule can only be tested by rendering HTML (a full HTTP test) | the same |
| 3 | **Time as a hidden input**: `LocalDate.now()` in a view makes the page depend on the server clock and timezone, and it's impossible to test for "tomorrow" | `LocalDate today = LocalDate.now();` |
| 4 | **Unchecked cast and null risk**: `(List<Task>) request.getAttribute("tasks")`. A wrong name → an NPE → 500 | the first scriptlet |
| 5 | **Escaping by memory**: every `<%= %>` must remember `Html.escape` (three times in `view.jsp`) | every title |
| 6 | **Braces across HTML**: `<% for … { %> … <% } %>`. One missing `}` fails compilation with a line number from the generated file (33.17, 33.18) | the loops |
| 7 | **Designers can't touch it**: Java syntax, imports, generics | the whole file |
| 8 | **Logic creep**: "just one more if" until the view queries the database | where it always ends |

**The replacement, S34–S36:**
- The **controller** computes the overdue flags and the count, via a service, testable with plain JUnit, with a `Clock` passed in.
- The **view** only displays: `<c:if test="${task.overdue}">`, `<c:out value="${task.title}"/>` (escaped by default), and `${overdueCount}`.
- `web.xml` can then **forbid** scripting entirely (33.14).
