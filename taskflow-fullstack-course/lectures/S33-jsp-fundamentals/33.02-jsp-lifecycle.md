# Lecture 33.02 · The JSP Lifecycle: Translation → Compilation → Load → `jspInit` → `_jspService` → `jspDestroy`

> **Section:** S33 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~20 minutes
> Checked against the class Jasper generated for TaskFlow's `list.jsp` (Tomcat 9.0.93, read in 33.03)

---

```text
first request for list.jsp (or first forward to it)
 │
 ├─ 1. TRANSLATION   list.jsp (+ its static includes) → list_jsp.java      (Jasper; syntax errors surface HERE)
 ├─ 2. COMPILATION   list_jsp.java → list_jsp.class                         (Java compile errors surface HERE)
 ├─ 3. LOAD + INSTANTIATE   one instance (like any servlet, 30.05)
 ├─ 4. jspInit() → _jspInit()        once
 │
every request
 ├─ 5. _jspService(request, response)  ← YOUR PAGE: every out.write / out.print / scriptlet, in order
 │
undeploy / reload of that JSP
 └─ 6. jspDestroy() → _jspDestroy()    once
```

| Phase | Output | Errors you'll see |
|---|---|---|
| Translation | `…_jsp.java` in Tomcat's `work/` folder | `JasperException: /WEB-INF/views/tasks/list.jsp (line: 12, column: 3) Unterminated <% tag` |
| Compilation | `…_jsp.class` | `JasperException: Unable to compile class for JSP: An error occurred at line: [140] in the jsp file` (33.17) |
| `_jspService` | the HTML response | runtime exceptions (a `NullPointerException` in a scriptlet) → 500 |

The generated class `extends org.apache.jasper.runtime.HttpJspBase` (itself an `HttpServlet`), and **your page is the body of `_jspService`**. You can override `jspInit()`/`jspDestroy()` in a declaration (`<%! public void jspInit() { … } %>`), but you shouldn't need to: initialisation belongs in listeners or servlets.

**The first request is slow.** It pays for translation and compilation (hundreds of milliseconds). That's why production builds **precompile** JSPs (33.04).
