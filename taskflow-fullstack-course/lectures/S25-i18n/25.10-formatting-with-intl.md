## 1. `Intl` is built into every browser

No date library and no month-name tables. The browser ships the CLDR data for every locale.

✍️ `src/i18n/format.ts`

```ts
export function formatDate(date: IsoDate, language: string): string {
  return new Intl.DateTimeFormat(language, { day: 'numeric', month: 'short', year: 'numeric', timeZone: 'UTC' }).format(
    new Date(`${date}T00:00:00Z`),
  );
}

export function formatRelativeDay(today: IsoDate, date: IsoDate, language: string): string {
  return new Intl.RelativeTimeFormat(language, { numeric: 'auto' }).format(daysBetween(today, date), 'day');
}

export function formatDue(dueDate: IsoDate, today: IsoDate, language: string): string {
  return `${formatDate(dueDate, language)} (${formatRelativeDay(today, dueDate, language)})`;
}
```

- **`timeZone: 'UTC'`** plus a `…T00:00:00Z` date: a **date without a time** (the due date) must not move to the previous day for users west of UTC. The classic "due Oct 2" bug, when it's due on Oct 3.
- **`numeric: 'auto'`** gives words ("tomorrow", "yesterday", "Ngày mai") instead of "in 1 day".
- **`language` as a parameter**, not read from a global. The functions are pure and testable, and components pass `i18n.language`.
- The output is **Intl's** text. Intl capitalises Vietnamese "Ngày mai" as a stand-alone phrase, and the test pins it.

Used by the details page (`Due: Oct 3, 2026 (in 7 days)`), comments (dates) and the dashboard (25.14).

## 📇 API card: the `Intl` formatters

| Formatter | Key options | Example (`en`) |
|---|---|---|
| `Intl.DateTimeFormat(lng, opts)` | `dateStyle`/`timeStyle`, or `day`, `month`, `year`, `weekday`, `hour`…; `timeZone` | `Oct 3, 2026` |
| `Intl.RelativeTimeFormat(lng, opts)` | `numeric: 'always' \| 'auto'`, `style` | `tomorrow`, `in 3 days` |
| `Intl.NumberFormat(lng, opts)` | `style: 'decimal' \| 'percent' \| 'currency' \| 'unit'`, `currency`, `maximumFractionDigits` | `1,234.5`, `42%`, `₫12,000` |
| `Intl.PluralRules(lng)` | `type: 'cardinal' \| 'ordinal'` | what i18next uses for `_one`/`_other` |
| `Intl.ListFormat(lng, opts)` | `type: 'conjunction' \| 'disjunction'` | `a, b, and c` |

Creating a formatter isn't free. Cache instances per language in hot paths, such as long lists.

## 2. i18next's own formatters

i18next 21+ can format inside translations:

```json
"dueOn": "Due {{date, datetime}}",
"done": "{{value, percent}} done"
```

```ts
t('dueOn', { date: new Date(task.dueDate), formatParams: { date: { dateStyle: 'medium' } } })
```

It's convenient for translators (they choose the position). TaskFlow keeps formatting in `format.ts` instead: typed, tested in one place, reusable outside `t()`. Both are valid.

**Common mistakes:** `new Date('2026-10-03')` (parsed as **UTC** midnight) displayed in local time, which shows the previous day in the Americas. Formatting in the wrong language, e.g. `toLocaleDateString()` without an argument uses the *browser's* locale, not the app's.
