# Lecture 25.11 · Namespaces and Lazy Loading with `i18next-http-backend`; Suspense

> **Section:** S25 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~30 minutes
> 🔗 Reference: i18next-http-backend README; react-i18next docs, "useTranslation → not using Suspense"

## 1. Why split translations

The whole app's text for every language in one bundle means every user downloads every language, and the dashboard's text even if they never open it. Namespaces plus a backend load **one language, and only the namespaces in use**:

```text
first render   GET /locales/vi/common.json      (ns: ['common'] at init)
/tasks         GET /locales/vi/tasks.json        (useTranslation(['tasks', 'common']))
/dashboard     GET /locales/vi/dashboard.json    (useTranslation('dashboard')), alongside the lazy JS chunk (12.09)
switch to en   GET /locales/en/common.json + tasks.json   (the namespaces in use, for the new language)
```

## 📇 API card: `i18next-http-backend`

| Option | Default | Meaning |
|---|---|---|
| `loadPath` | `'/locales/{{lng}}/{{ns}}.json'` | a URL template, or a function `(lngs, namespaces) => url` |
| `addPath` | `'/locales/add/{{lng}}/{{ns}}'` | for `saveMissing` (sending missing keys to a server) |
| `parse` | `JSON.parse` | a custom format |
| `crossDomain`, `withCredentials` | `false` | a CDN on another origin |
| `requestOptions` | `{ mode: 'cors', credentials: 'same-origin', cache: 'default' }` | passed to `fetch` |
| `reloadInterval` | `false` | re-fetch periodically (long-lived kiosks) |

TaskFlow: `loadPath: \`${import.meta.env.BASE_URL}locales/{{lng}}/{{ns}}.json\``. The prefix keeps it working when the SPA is served from `/<context>/app/` inside the WAR (S49).

## 2. Suspense: no flash of raw keys

With `useSuspense: true` (react-i18next's default), `useTranslation('dashboard')` **suspends** until `dashboard.json` is loaded. The nearest `<Suspense>` shows its fallback. `main.tsx` wraps `<App />` in one, and the dashboard route already has its own (12.09), which now also covers its translations.

Without Suspense (`useSuspense: false`), the component renders at once with `ready: false`, and `t` returns **keys**. You'd have to check `ready` yourself.

## 3. Caching and versions

- Browsers cache `/locales/*.json` like any static file. After a deploy, users might keep **old** translations while the new code expects new keys. They'd see the English fallback or raw keys.
- Fixes: a version query in `loadPath` (`…json?v=${import.meta.env.VITE_APP_VERSION}`), `Cache-Control: no-cache` for `/locales` on the server (S49), or bundling translations with the code (`import()` of JSON, which Vite hashes).

## 4. When not to lazy-load

A small app with two languages and a few hundred strings can bundle everything (`resources` inline, or `i18next-resources-to-backend` with `import()`). There are fewer moving parts, and no Suspense for text. TaskFlow lazy-loads because the course covers it, and because the admin portal will add many more strings.

## ✅ Recap

Namespaces = files. The backend fetches `{{lng}}/{{ns}}` on demand. Suspense hides the loading, and cache-busting handles deploys.
