# Lecture 25.99 · ✅ Knowledge Check: Internationalisation

> **Section:** S25 · **Type:** ✅ Knowledge Check · **Track:** ★ Core · **Time:** ~20 minutes

**1.** Walk through how TaskFlow's detector chooses a language on the first visit and on the second visit.

<details><summary>Answer</summary>

**First visit:** no `?lng`, no `tf_lang` cookie → `navigator` (e.g. `vi-VN`) → normalised to `vi` (25.06) → cached in `tf_lang` for a year. **Second visit:** the `tf_lang` cookie answers before `navigator`, so the same language is used, including a language chosen with the switcher that differs from the browser's (25.04 §2).
</details>

**2.** Config `order: ['querystring', 'cookie', 'navigator']`, `caches: ['cookie']`. The request has `?lng=vi`, cookie `tf_lang=en`, and a French browser. Which language wins? What gets cached?

<details><summary>Answer</summary>

**`vi`**: the query string is first in `order`. It's cached, so `tf_lang` becomes `vi`. The next visit without `?lng` is in Vietnamese. The French browser is never consulted (the test "?lng= beats the cookie" asserts exactly this).
</details>

**3.** A translated string shows `&lt;b&gt;` on screen. Which escaping layer double-escaped?

<details><summary>Answer</summary>

i18next's interpolation (`escapeValue: true`, the default) turned `<b>` into `&lt;b&gt;`, and then React escaped the `&` again when rendering the text node, so the entity is shown literally. With React, set `escapeValue: false` and let React escape once (25.08).
</details>

**4.** Why share the `tf_lang` cookie with the Java backend instead of keeping the language in localStorage?

<details><summary>Answer</summary>

The server can read cookies (every request carries them) but never localStorage. With the cookie, the JSP admin portal (S44), server-side validation messages, and any emails or exports use the **same** language the user chose in the SPA, with one setting for the whole product (25.04 §3, 25.13 §3).
</details>

**5.** Implement `formatDue(dueDate, today, language)` that returns e.g. "Oct 3, 2026 (in 7 days)".

<details><summary>Answer</summary>

```ts
export function formatDue(dueDate: IsoDate, today: IsoDate, language: string): string {
  const date = new Intl.DateTimeFormat(language, { day: 'numeric', month: 'short', year: 'numeric', timeZone: 'UTC' })
    .format(new Date(`${dueDate}T00:00:00Z`));
  const days = Math.round((Date.parse(`${dueDate}T00:00:00Z`) - Date.parse(`${today}T00:00:00Z`)) / 86_400_000);
  return `${date} (${new Intl.RelativeTimeFormat(language, { numeric: 'auto' }).format(days, 'day')})`;
}
```

In a component, pass `i18n.language` from `useTranslation()` so it re-renders on language change (25.10).
</details>

**6.** Why does `vi/tasks.json` have `clearConfirm_other` but no `clearConfirm_one`?

<details><summary>Answer</summary>

`Intl.PluralRules('vi')` has a single category, `other`, for every number. i18next only ever looks up `_other` in Vietnamese (25.09).
</details>

**7.** A new server error code, `ACCOUNT_LOCKED`, appears. What does a Vietnamese user see before anyone adds a translation?

<details><summary>Answer</summary>

The server's (English) `message`, via `defaultValue` in `useErrorMessage`. That's not ideal, but readable. They don't see the raw key `errors.ACCOUNT_LOCKED` (25.13).
</details>
