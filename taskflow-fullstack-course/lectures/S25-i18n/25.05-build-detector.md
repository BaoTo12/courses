## 1. The options (in `src/i18n/i18n.ts`)

```ts
export const detectionOptions: DetectorOptions = {
  order: ['querystring', 'cookie', 'navigator'],
  lookupQuerystring: 'lng',
  lookupCookie: COOKIE_NAMES.language,
  caches: ['cookie'],
  cookieMinutes: 60 * 24 * 365, // one year, like any device preference (24.16)
  cookieOptions: { path: '/', sameSite: 'lax' },
};
```

Line by line:

- **`order`**: no `localStorage` (the server couldn't read it) and no `htmlTag` (our `<html lang>` is an *output*, 25.07, not an input).
- **`lookupCookie: COOKIE_NAMES.language`**: the name comes from `cookies.ts` (24.05), which is still the list of every cookie we use. In S24, `rememberLanguage()` wrote this cookie by hand. The detector now reads **and** writes it, so the S24 helper was **deleted**. Two writers for one cookie would sooner or later disagree.
- **`cookieMinutes`**: a year. The default of 10 minutes would forget the choice before lunch.
- **`cookieOptions`**: the same `path: '/'` and `sameSite: 'lax'` as our wrapper. The detector's default is `strict`, which would drop the cookie on the first request after following a link from an email to TaskFlow. The server would then see no language on that request.

## 2. What the tests pin down

```ts
async function startAt(url: string) {
  window.history.replaceState({}, '', url);        // jsdom: pretend the page is at this URL
  const instance = i18next.createInstance();
  await instance.use(LanguageDetector).init({ ...baseOptions, ns: NAMESPACES, resources });
  return instance;
}
```

| Test | Setup | Expect |
|---|---|---|
| query beats cookie, and is cached | cookie `tf_lang=en`, URL `?lng=vi` | `vi`, and the cookie is now `vi` |
| cookie beats browser | cookie `tf_lang=vi`, jsdom's browser language `en-US` | `vi`, `t('nav.tasks')` = "Công việc" |
| browser, normalised | nothing | `en` (from `en-US`, 25.06) |
| regional code | `?lng=vi-VN` | `resolvedLanguage` = `vi` |
| unsupported | `?lng=fr` | `en` |

`resources` come from the **real** `public/locales` files, via Vite's `import.meta.glob(…, { eager: true })`. A missing key in a JSON file fails a test, not a user.
