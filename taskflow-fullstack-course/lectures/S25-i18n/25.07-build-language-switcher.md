# Lecture 25.07 · 🛠 Build: A Language Switcher; the Cookie and `<html lang>` Follow

> **Section:** S25 · **Type:** 🛠 Build · **Track:** ★ Core · **Time:** ~25 minutes
> **Project feature:** a language `<select>` in the header. Switching re-renders the app, loads the namespaces it needs, rewrites `tf_lang`, and updates `<html lang>`.
> Verified: `tsc`, lint; the cookie caching is covered by `src/i18n/i18n.test.ts`.

---

✍️ `src/i18n/LanguageSwitcher.tsx`

```tsx
import { useTranslation } from 'react-i18next';
import { isAppLanguage, SUPPORTED_LANGUAGES } from './i18n';

/**
 * 25.07: `changeLanguage` re-renders every `useTranslation` consumer, loads missing namespaces for the new
 * language, and (detector `caches: ['cookie']`) writes `tf_lang`. `<html lang>` follows via 'languageChanged'.
 */
export function LanguageSwitcher() {
  const { t, i18n } = useTranslation();
  // `resolvedLanguage`: the supported language actually in use ('vi'), not the raw detected one ('vi-VN').
  const current = i18n.resolvedLanguage ?? 'en';

  return (
    <select
        value={current}
        aria-label={t('language.label')}
        onChange={(e) => {
          const language = e.target.value;
          if (isAppLanguage(language)) void i18n.changeLanguage(language);
        }}
      >
        {SUPPORTED_LANGUAGES.map((language) => (
          // Each language's name in ITSELF: someone who can't read the current language still finds theirs.
          <option key={language} value={language} lang={language}>
            {t(`language.${language}`)}
          </option>
        ))}
    </select>
  );
}
```

- **`i18n.changeLanguage(language)`** returns a Promise that resolves once the new language's loaded namespaces are fetched. Every `useTranslation` consumer re-renders, and components wait in Suspense if they need a namespace that isn't there yet.
- **The cookie:** because of `caches: ['cookie']`, the detector writes `tf_lang` on every language change. No code of ours touches the cookie.
- **`isAppLanguage`** narrows the `<select>`'s string, the same validation habit as the page sizes (23.07).
- **`resolvedLanguage`** for `value`, so a browser at `vi-VN` shows "Tiếng Việt" as selected (25.06).
- **Language names in themselves** ("English", "Tiếng Việt") in *both* JSON files, with `lang` on each `<option>`. Someone stuck in a language they can't read still recognises their own.
- An `aria-label`, because the select has no visible label.

`<html lang>` is kept in sync in `initI18n`:

```ts
  i18n.on('languageChanged', (language) => {
    document.documentElement.lang = language; // screen readers, hyphenation, :lang() CSS (25.07)
  });
```

- Screen readers choose their **voice** from `lang`. Vietnamese read with an English voice is unintelligible.
- CSS `hyphens: auto` and `:lang(vi)` rules depend on it.
- The event fires for the initial detection too, so it's right from the first render.

Mount it in `AppLayout`'s header, next to the theme toggle: `<LanguageSwitcher />`.

## ✅ Checkpoint

Switch to Tiếng Việt: the UI changes, `<html lang="vi">` appears in the Elements panel, `tf_lang=vi` is in Cookies, and the Network tab shows `GET /locales/vi/common.json` (and `tasks.json` on the tasks page).
