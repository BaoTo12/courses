# Lecture 25.08 · Interpolation, and Why `escapeValue: false` Is Safe *with React*

> **Section:** S25 · **Type:** 📖 Theory (🛡 Security) · **Track:** ★ Core · **Time:** ~30 minutes
> Verified: `src/i18n/i18n.test.ts` ("escapeValue: false returns interpolated values raw")

---

## 1. Interpolation

```json
{ "deleteConfirm": "Delete \"{{title}}\"? This cannot be undone." }
```

```ts
t('details.deleteConfirm', { title: task.title })   // Delete "Plan offsite"? This cannot be undone.
```

`{{name}}` placeholders are filled from the options object. Translators can move them anywhere in the sentence, which is the reason for whole messages (25.01).

## 2. Two layers that might escape

A task title containing `<b>x</b>` passes through two layers:

| Layer | With `escapeValue: true` (i18next's default) | With `escapeValue: false` (TaskFlow) |
|---|---|---|
| i18next interpolation | `Delete "&lt;b&gt;x&lt;/b&gt;"…` | `Delete "<b>x</b>"…` |
| React renders `{text}` as a text node | shows `&lt;b&gt;` **literally**, double-escaped ❌ | shows `<b>x</b>` as text, safely ✅ |

React **always** escapes strings it renders as children or attribute values. Escaping in i18next as well produces visible entities, the "`&lt;b&gt;` bug" from the knowledge check. So with React, turn i18next's escaping off, and let React do it once.

## 3. Where `escapeValue: false` is NOT safe

The React guarantee covers **React rendering only**. Any path that treats a translated string as HTML bypasses it:

| Danger | Why |
|---|---|
| `<div dangerouslySetInnerHTML={{ __html: t('x', { name }) }} />` | `name` is inserted raw into HTML → XSS |
| `element.innerHTML = t(…)` in non-React code | the same |
| translations sent to the server and put into an email template unescaped | the server's template must escape (S44: JSTL `<c:out>`) |
| `window.confirm(t(…))` / `alert` | safe: plain text, no HTML |

If a translation needs markup (bold, links), use **`<Trans>`** (25.03 §5). It builds React elements, not HTML strings.

## 4. Don't trust translations either

Translation files are code. A malicious or careless translation could contain `<script>`. With React plus `<Trans>`, it would render as text. With `dangerouslySetInnerHTML`, it would run. One more reason to never render translations as HTML.

## ✅ Recap

- `escapeValue: false` + React = escaping exactly once, by React.
- The moment a translated string goes into HTML (`innerHTML`, `dangerouslySetInnerHTML`, server templates), **someone must escape**. Use `<Trans>` for markup.
