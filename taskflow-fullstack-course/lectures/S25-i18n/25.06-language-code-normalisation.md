# Lecture 25.06 · Language Codes: `vi-VN` → `vi`, `supportedLngs`, `nonExplicitSupportedLngs`, `load`

> **Section:** S25 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~25 minutes
> Verified: `src/i18n/i18n.test.ts` ("vi-VN is accepted as vi", "an unsupported language falls back to English")

---

## 1. The problem

Browsers report **BCP 47 tags** with regions: `vi-VN`, `en-US`, `en-GB`, sometimes `zh-Hant-TW`. We translate per **language** (`vi`, `en`). Without configuration, i18next could:

- request `/locales/vi-VN/common.json`, which returns 404, then fall back to English. The Vietnamese user sees English (25.17);
- accept `fr` from `?lng=fr` and show raw keys or English, with `fr` cached in the cookie.

## 2. The three options

| Option | Effect for a detected `vi-VN` | Effect for `fr` |
|---|---|---|
| `supportedLngs: ['en', 'vi']` | `vi-VN` isn't in the list… | rejected → the next candidate or `fallbackLng` |
| `nonExplicitSupportedLngs: true` | …but `vi` is, so accepted | still rejected |
| `load: 'languageOnly'` | loads `vi/*.json` only, never `vi-VN/*.json` | — |

Together, `i18n.language` may be `vi-VN` (the raw value), `i18n.resolvedLanguage` is `vi` (what's actually used), and only `vi` files are requested.

## 3. `language` vs `resolvedLanguage`

| | `?lng=vi-VN` | `?lng=fr` |
|---|---|---|
| `i18n.language` | `vi-VN` | `fr` or `en`, depending on the fallback chain |
| `i18n.resolvedLanguage` | `vi` | `en` |

Use **`resolvedLanguage`** for UI decisions (the switcher's selected value) and for `<html lang>`. Use `language` for `Intl` formatting, where the region matters (`en-GB` dates differ from `en-US`) and `Intl` handles any tag.

## 📇 API card

| Option | Type | Default |
|---|---|---|
| `supportedLngs` | `string[] \| false` | `false` (anything accepted) |
| `nonExplicitSupportedLngs` | `boolean` | `false` |
| `load` | `'all' \| 'currentOnly' \| 'languageOnly'` | `'all'` (loads `vi-VN` **and** `vi`) |
| `lowerCaseLng` / `cleanCode` | `boolean` | `false` (`cleanCode` lower-cases just the language part) |

**Common mistakes:** listing `supportedLngs: ['en', 'vi']` without `nonExplicitSupportedLngs`, which rejects every regional browser; `load: 'all'` with files only for `vi`, which gives a 404 per namespace for `vi-VN` in the Network tab.
