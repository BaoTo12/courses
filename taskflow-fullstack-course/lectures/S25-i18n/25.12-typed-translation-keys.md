# Lecture 25.12 · TypeScript: Typed Translation Keys

> **Section:** S25 · **Type:** 📖 Theory · **Track:** ＋ Extended · **Time:** ~20 minutes
> 🔗 Reference: i18next docs, "TypeScript"

*Extended track: outline. TaskFlow doesn't enable it yet (see the trade-offs below).*

---

**Goal:** `t('nav.tasks')` compiles, and `t('nav.taks')` doesn't.

**How:** declaration merging (06.10) of i18next's `CustomTypeOptions`:

```ts
// src/i18n/i18next.d.ts
import 'i18next';
import type common from '../../public/locales/en/common.json';
import type tasks from '../../public/locales/en/tasks.json';

declare module 'i18next' {
  interface CustomTypeOptions {
    defaultNS: 'common';
    resources: { common: typeof common; tasks: typeof tasks };
  }
}
```

**Requirements and consequences**

- `resolveJsonModule` in `tsconfig.app.json`, so TypeScript can type JSON imports (a type-only import adds nothing to the bundle).
- English is the **source of truth** for keys. A key missing in `vi` isn't a type error, so add a test that compares key sets.
- **Dynamic keys** (`t(\`status.${status}\`)`) still type-check if the template literal's union matches the JSON keys: `status` is `TaskStatus`, and the JSON has exactly those keys. A mismatch is a compile error, which is useful.
- Plurals: write `t('clearConfirm', { count })`. The typings strip `_one`/`_other`.
- Cost: compile time on big files, and cryptic errors for deep keys.

**Try it** (optional): add the file above, fix what `tsc -b` reports, then misspell a key and watch it fail.
