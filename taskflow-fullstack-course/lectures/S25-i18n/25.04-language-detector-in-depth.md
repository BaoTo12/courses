## 1. What it does

At init (and when you call `changeLanguage` without an argument), the detector asks each **lookup** in `order` for a language. It takes the first one that i18next accepts (with `supportedLngs`, the best supported match), and then **caches** the result in the places listed in `caches`.

```text
order: ['querystring', 'cookie', 'navigator']
  ?lng=vi            → "vi"      ← first answer wins
  cookie tf_lang=en  → (not asked)
  navigator: en-US   → (not asked)
caches: ['cookie']   → Set tf_lang=vi (1 year)
```

## 📇 API card: detector options

| Option | Default | Meaning |
|---|---|---|
| `order` | `['querystring', 'cookie', 'localStorage', 'sessionStorage', 'navigator', 'htmlTag']` | the lookups, in priority order. Others: `path`, `subdomain`, `hash`. |
| `lookupQuerystring` | `'lng'` | `?lng=vi` |
| `lookupCookie` | `'i18next'` | the cookie's name |
| `lookupLocalStorage` / `lookupSessionStorage` | `'i18nextLng'` | storage keys |
| `lookupFromPathIndex` | `0` | `/vi/tasks` → index 0 of the path |
| `lookupFromSubdomainIndex` | `0` | `vi.example.com` |
| `caches` | `['localStorage']` | where to **store** the language (`[]` = never) |
| `excludeCacheFor` | `['cimode']` | languages never cached |
| `cookieMinutes` | `10` | the cookie's lifetime. **10 minutes by default!** |
| `cookieDomain` | host-only | share with subdomains |
| `cookieOptions` | `{ path: '/', sameSite: 'strict' }` | more attributes: `path`, `sameSite`, `secure` |
| `htmlTag` | `document.documentElement` | where the `htmlTag` lookup reads `lang` |
| `convertDetectedLanguage` | — | map codes, e.g. `(lng) => lng.replace('-', '_')` |

### The lookups, briefly

| Lookup | Reads | Good for |
|---|---|---|
| `querystring` | `?lng=` | shareable links, testing, support ("send me a screenshot with `?lng=vi`") |
| `cookie` | `document.cookie` | a choice the **server** can see too (TaskFlow: `tf_lang` for the JSP portal) |
| `localStorage` | `localStorage` | a client-only choice |
| `navigator` | `navigator.languages` | the first visit: the browser or OS preference |
| `htmlTag` | `<html lang>` | server-rendered pages that already decided |
| `path` / `subdomain` | `/vi/…`, `vi.site.com` | SEO sites with a URL per language |

## 2. First visit vs second visit (TaskFlow's config)

| | First visit | Second visit |
|---|---|---|
| query | none | none |
| cookie | none | `tf_lang=vi` (cached last time) ✅ wins |
| navigator | `vi-VN` → `vi` ✅ wins | not asked |
| cached | `tf_lang` written | refreshed |

A user who switches to English with the switcher gets `tf_lang=en`. From then on, the cookie beats their Vietnamese browser. That's what "remember my choice" means.

## 3. `caches` is a *write*, and a design decision

- `caches: ['cookie']`: every detection or `changeLanguage` writes `tf_lang`. The JSP admin portal's `LocaleFilter` (S44) reads the same cookie, so there's **one language setting for both apps**.
- `caches: []`: nothing is remembered. The query or the browser decides every time.
- With the **default** `['localStorage']`, the server never learns the choice, and emails or PDFs generated by the backend would ignore it.

## ✅ Recap

`order` = where to **read**, first wins. `caches` = where to **write**. Set `cookieMinutes`: the default is 10 minutes. Choose cookie over localStorage when the server must know the language.
