# Lecture 25.13 · Translating API Enums (`TaskStatus`) and Server Error Codes

> Verified: `src/i18n/i18n.test.ts` ("error codes are translated, unknown codes fall back to the default value"), `tsc`, lint.

## 1. Enums: one key per value

The API sends `status: "IN_PROGRESS"`. That's a **code**, not text. S06's `statusLabel()` switch mapped it to English. Now the mapping lives in the translation files:

```json
"status":   { "TODO": "To do", "IN_PROGRESS": "In progress", "DONE": "Done" },
"priority": { "LOW": "Low", "MEDIUM": "Medium", "HIGH": "High" }
```

✍️ `src/components/Badge.tsx`

```tsx
import type { Priority, TaskStatus } from '../domain/types';
import { toKebab } from '../domain/format';
import { useTranslation } from 'react-i18next';

// S25 (25.13): enum values from the API are translated by KEY: status.TODO, priority.HIGH (common namespace).
export function StatusBadge({ status }: { status: TaskStatus }) {
  const { t } = useTranslation();
  return <span className={`badge badge--${toKebab(status)}`}>{t(`status.${status}`)}</span>;
}

export function PriorityBadge({ priority }: { priority: Priority }) {
  const { t } = useTranslation();
  return <span className={`badge badge--priority-${toKebab(priority)}`}>{t(`priority.${priority}`)}</span>;
}
```

- `t(\`status.${status}\`)` builds the key from the enum value, so the keys **must** equal the API's values.
- The exhaustiveness check from 06.12 (`assertNever`) is gone for these labels. Replace it with a test that every `TASK_STATUSES` value has a key in both languages. With typed keys (25.12), TypeScript checks it.
- The CSS class still uses the **code** (`badge--in-progress`). Styling never depends on translated text.

## 2. Server errors: translate the CODE, never the message

The server's error body has `error: "BAD_CREDENTIALS"` (a stable code) and `message: "Invalid username or password"` (English, for developers). Our `ApiErrorPayload` keeps both (`code`, `message`, 20.09). Client-side kinds become codes too: `NETWORK`, `TIMEOUT`, `UNEXPECTED`.

✍️ `src/i18n/useErrorMessage.ts`

```ts
import { useCallback } from 'react';
import { useTranslation } from 'react-i18next';
import { toErrorMessage } from '../domain/guards';

/**
 * 25.13: translate an API error by its machine-readable CODE ('BAD_CREDENTIALS', 'NETWORK'…), never by its
 * English message. Unknown codes fall back to the server's message, so a new server error is still readable.
 */
export function useErrorMessage(): (error: unknown) => string {
  const { t } = useTranslation();
  return useCallback(
    (error: unknown) => {
      const code = typeof error === 'object' && error !== null && 'code' in error ? error.code : undefined;
      const fallback = toErrorMessage(error);
      return typeof code === 'string' ? t(`errors.${code}`, { defaultValue: fallback }) : fallback;
    },
    [t],
  );
}
```

- **Translate by code.** Matching on the English `message` would break the day the backend rewords it.
- **`defaultValue: fallback`**: a code we don't know yet (the backend added `ACCOUNT_LOCKED`) shows the server's message, not the raw key `errors.ACCOUNT_LOCKED`.
- **A hook**, because it needs the current language from `useTranslation`, and it re-renders when the language changes.
- Used in `LoginPage`, `TasksPage`, `TaskDetailsPage` and `CommentsSection`, instead of `toErrorMessage`.

## 3. Field errors

`fieldErrors.body = "must be 1 to 1000 characters"` comes from the server in English. Two options:

| Option | How |
|---|---|
| the server localises | it reads the language (the `tf_lang` cookie, or `Accept-Language`) and sends Vietnamese messages. That's S44's `LocaleFilter` plus a `ResourceBundle`. |
| codes per field | the server sends `{ body: "LENGTH" }`, and the client maps it: `t('fieldErrors.LENGTH', { min: 1, max: 1000 })` |

TaskFlow chooses **the server localises**: one message catalogue per language for both apps (SPA and JSP), and the validation rules live in one place.

## 4. Messages created outside React

Toasts ("Created: …", "Your session has expired") are created in **listeners**, outside React, and stored as text in the Redux state. The text is then frozen in whatever language was active at that moment. The clean fix is to store the **key and values** in the state (`{ messageKey: 'toasts.created', values: { title } }`) and translate when rendering. That's on the S27 sprint list. Don't call `i18n.t` inside reducers: they must stay pure (14.05).

## ✅ Recap

Enums and error codes are translated **by key**. Unknown codes fall back to the server's message. Field messages are localised by the server (S44). Store keys, not text, in state.
