## 1. Plurals: suffixes from `Intl.PluralRules`

```json
// en/tasks.json
"clearConfirm_one":   "Delete {{count}} completed task? This cannot be undone.",
"clearConfirm_other": "Delete {{count}} completed tasks? This cannot be undone."

// vi/tasks.json: Vietnamese has ONE plural category
"clearConfirm_other": "Xoá {{count}} công việc đã hoàn thành? Không thể hoàn tác."
```

```ts
t('clearConfirm', { count: doneCount })   // the key WITHOUT the suffix; `count` picks the form
```

- i18next asks `Intl.PluralRules(language).select(count)`, which returns `zero | one | two | few | many | other`, and appends `_<category>`.
- **English:** `one` (1) and `other` (0, 2, 5…). **Vietnamese:** only `other`. **Arabic:** all six. **Polish:** `one`, `few`, `many`, `other`.
- `count` is also interpolated as `{{count}}`.
- Never `count === 1 ? 'task' : 'tasks'` in code. It's only right for English-like languages.

## 2. Context: one key, variants by situation

```json
"assigned": "Assigned",
"assigned_male": "He was assigned",
"assigned_female": "She was assigned"
```

```ts
t('assigned', { context: user.pronoun })   // falls back to "assigned" when there's no matching variant
```

Context and plurals combine: `key_context_one`. It's useful for grammatical gender, or "on/off" wording.

## 3. Nesting: reuse a translation inside another

```json
"appName": "TaskFlow",
"welcome": "Welcome to $t(appName)!"
```

Keep it for **stable terms** (the product name). Nesting whole sentences makes grammar impossible to get right.

## 4. Default values

```ts
t('errors.SOMETHING_NEW', { defaultValue: 'Server said no' })   // key missing → the default
```

TaskFlow uses this for **unknown error codes** (25.13): a new server code still shows the server's message.

## 📇 API card: `t` options used in TaskFlow

| Option | Meaning |
|---|---|
| `count` | plural selection + `{{count}}` |
| `context` | picks `key_<context>` |
| `defaultValue` | used when the key is missing everywhere |
| `ns` | the namespace (or use the `ns:key` prefix) |
| `lng` | translate in a specific language (e.g. an email preview) |
| any other key | interpolation values |

**Common mistakes:**
- Writing `t('clearConfirm_one', …)` (with the suffix). Always use the base key and pass `count`.
- Passing the count as a string: `count: '5'` doesn't select plurals reliably.
- Copying the English `_one`/`_other` pair into Vietnamese. Harmless, but misleading: only `_other` is ever used.
