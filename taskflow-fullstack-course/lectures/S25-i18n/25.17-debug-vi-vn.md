# Lecture 25.17 · 🐞 Debug: Vietnamese Shows as `vi-VN` and No Translations Load

> **Section:** S25 · **Type:** 🐞 Debug · **Track:** ★ Core · **Time:** ~20 minutes
> Verified by: `src/i18n/i18n.test.ts` ("vi-VN is accepted as vi")

---

## 1. The report

> "A tester in Hanoi says everything is in English. Her browser is Vietnamese. The switcher shows nothing selected. In the console, `i18n.language` is `vi-VN`."

## 2. Investigate

Network tab, filtered by `locales`:

```text
GET /locales/vi-VN/common.json   404
GET /locales/vi/common.json      200     ← only with load: 'all' (the default)
GET /locales/en/common.json      200
```

The config:

```ts
fallbackLng: 'en',
supportedLngs: ['en', 'vi'],
// nonExplicitSupportedLngs missing
// load missing (defaults to 'all')
```

1. The detector answers `vi-VN` (the browser language).
2. `supportedLngs` doesn't contain `vi-VN`, and without `nonExplicitSupportedLngs` it isn't matched to `vi`. It's **rejected**, so the fallback `en` is used.
3. The switcher's `<select value={i18n.language}>` gets `vi-VN`. No `<option>` has that value, so nothing is selected.

## 3. Fix

```ts
supportedLngs: ['en', 'vi'],
nonExplicitSupportedLngs: true, // vi-VN → vi
load: 'languageOnly',           // request /vi/…, never /vi-VN/…
```

And in the switcher: `value={i18n.resolvedLanguage}` (25.06 §3).

## 4. Verify

`?lng=vi-VN` → `resolvedLanguage` `vi`, "Hoàn thành" for `DONE`. That's the test. The Network tab shows only `/locales/vi/…`.

## ✅ Takeaway

Browsers speak **regions** (`vi-VN`), and translations usually exist per **language** (`vi`). Tell i18next to bridge them, and read `resolvedLanguage` in the UI.
