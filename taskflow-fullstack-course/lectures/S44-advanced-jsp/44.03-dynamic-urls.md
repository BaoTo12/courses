## 1. Two encodings, two contexts

A link with user input goes through **two** encodings, for two different parsers:

| Step | Encodes | For | Tool |
|---|---|---|---|
| 1. URL encoding | `&` → `%26`, `=` → `%3D`, space → `+`, `é` → `%C3%A9` | the **URL** parser: where parameters start and end | `<c:param>` (inside `<c:url>`) |
| 2. HTML escaping | `&` → `&amp;`, `"` → `&#034;` | the **HTML** parser: where the attribute ends | `fn:escapeXml` on the finished URL |

```jsp
<c:url var="href" value="/tasks">
  <c:param name="q" value="${param.q}"/>          <%-- R&D → q=R%26D --%>
  <c:param name="page" value="2"/>
</c:url>
<a href="${fn:escapeXml(href)}">2</a>              <%-- /taskflow/tasks?q=R%26D&amp;page=2 --%>
```

Leaving out step 1 breaks the URL (44.19). Leaving out step 2 is XSS-adjacent: a value like `" onmouseover="…` could end the attribute (35.11).

## 📇 API card: `<c:url>` and `<c:param>`

| Attribute | Meaning |
|---|---|
| `c:url value` | a path: starting with `/` → the **context path** is prepended (`/taskflow/tasks`); otherwise used as is |
| `c:url var` / `scope` | store the URL instead of printing it |
| `c:url context` | another web app's context path (rare) |
| `c:param name` / `value` | added as `name=value`, **both URL-encoded** (UTF-8 once the response encoding is set) |

`<c:url>` also rewrites the URL with `;jsessionid=` when the session isn't tracked by cookie. TaskFlow is `COOKIE`-only (41.02), so it never does.

`<c:param>` works when nested **anywhere** inside `<c:url>`, including inside `<c:forEach>` and `<c:if>`: it finds its enclosing `<c:url>` by walking up the tag tree. TaskFlow's page links use that to keep a list of parameters:

```jsp
<c:url var="href" value="${path}">
  <c:forEach items="${fn:split(keep, ',')}" var="name">
    <c:if test="${not empty param[name]}"><c:param name="${name}" value="${param[name]}"/></c:if>
  </c:forEach>
  <c:if test="${number > 1}"><c:param name="page" value="${number}"/></c:if>
</c:url>
```

## 2. What to keep, what to drop

| Link | Keeps | Drops |
|---|---|---|
| page N | filters, search, sort, direction | the old page |
| a sort header (44.16) | filters, search | the page (a new order starts at 1), the old direction |
| a status filter | search, category, sort | the page |

An explicit **list** of parameters to keep (never "all current parameters"): unknown parameters shouldn't travel from link to link.

## ✅ Recap

`<c:param>` URL-encodes each value; `fn:escapeXml` makes the finished URL safe in HTML. Build every link with both.
