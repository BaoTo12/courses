# Lecture 44.05 · JSTL `fmt`: Dates, Numbers, Parsing, Time Zones

> **Section:** S44 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~25 minutes

---

`<%@ taglib prefix="fmt" uri="http://java.sun.com/jsp/jstl/fmt" %>`

## 📇 API card: formatting tags

| Tag | Key attributes | Example → output (en) |
|---|---|---|
| `<fmt:formatNumber>` | `value`, `type` (number/currency/percent), `pattern`, `maxFractionDigits`, `groupingUsed`, `currencyCode`, `var` | `value="${1234.5}"` → `1,234.5` (vi: `1.234,5`) |
| `<fmt:parseNumber>` | `value`, `type`, `pattern`, `integerOnly`, `var` | `"1.234,5"` in vi → `1234.5` |
| `<fmt:formatDate>` | `value` (**`java.util.Date`**), `type` (date/time/both), `dateStyle`/`timeStyle` (short/medium/long/full), `pattern`, `timeZone`, `var` | `dateStyle="medium"` → `Oct 3, 2026` |
| `<fmt:parseDate>` | `value`, `pattern`, `type`, `timeZone`, `var` | `"2026-10-03"` + `pattern="yyyy-MM-dd"` → a `Date` |
| `<fmt:timeZone value="…">` | a time zone for the tags in its body | `Asia/Ho_Chi_Minh` |
| `<fmt:setTimeZone value="…" scope="…"/>` | the same, for a whole scope | |

All of them use the **formatting locale**: the one set by `<fmt:setLocale>` or `Config.FMT_LOCALE` (44.07), otherwise the request's `Accept-Language`.

## The `java.util.Date` limitation

JSTL 1.2 (2006) predates `java.time`. `<fmt:formatDate value="${task.dueDate}"/>` with a `LocalDate` fails with a type-conversion error. The options:

| Option | Verdict |
|---|---|
| convert to `Date` in the controller (`Date.from(localDate.atStartOfDay(zone).toInstant())`) | works, but reintroduces time zones for a date that has none |
| a getter `getDueDateAsDate()` on the model | puts view concerns in the model |
| **a custom tag** using `DateTimeFormatter.ofLocalizedDate(FormatStyle.MEDIUM).withLocale(locale)` | TaskFlow's choice: `<tf:date value="${task.dueDate}"/>` (44.13), same locale as `fmt` |

## Time zones

A `LocalDate` (a due date) has **no** time zone: show it as is. An `Instant`/`TIMESTAMP` (`created_at`, audit `at`) is a moment: choose the zone to display it in (the user's; TaskFlow stores and logs in UTC, 43.11). `<fmt:timeZone>` applies to `java.util.Date` values; for `java.time`, the formatter's `withZone(...)`.

## ✅ Recap

`fmt` formats numbers and `java.util.Date`s in the request's locale. For `java.time` values, write a small tag that uses the same locale.
