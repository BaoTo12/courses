# Lecture 44.02 · Null Handling End to End

> **Section:** S44 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~15 minutes

---

## 1. How EL treats null

| Expression | `x` is null → |
|---|---|
| `${x}` | prints nothing |
| `${x.y}` | null (no `NullPointerException`) |
| `${x + 1}` | `1`: null is 0 in arithmetic. TaskFlow's `${rowOffset + row.count}` relies on it: the dashboard sets no `rowOffset` |
| `${x == 'DONE'}` | false |
| `${empty x}` | true (also for "", empty collections, empty maps, empty arrays) |
| `${x ? 'a' : 'b'}` | `'b'`: null is false |

## 📇 API card: the null tools

| Tool | Use | Example |
|---|---|---|
| `empty` / `not empty` | "is there anything?" | `<c:if test="${not empty recentTasks}">` |
| ternary | a fallback value in an expression | `${empty lang ? 'en' : lang}` |
| `<c:out value="…" default="…"/>` | a fallback when the value is **null** (not for "") | `<c:out value="${task.description}" default="(no description)"/>` |
| `<c:out>` with a body | the same, the default as body content | `<c:out value="${x}">none</c:out>` |
| a tag's own rule | the tag decides | `<tf:date value="${null}"/>` prints "—" (44.13) |

## 2. Keeping nulls out of views

| Layer | Rule |
|---|---|
| database | `NOT NULL` where a value is always required (title, status, owner) |
| service | returns empty lists, never null; `Optional` for "maybe one" |
| controller | turns `Optional.empty()` into a 404 (43.08), and sets every attribute the view reads |
| view | handles only the nulls that **mean** something ("no due date") |

A view full of `empty` checks usually means the controller didn't finish its job.

## ✅ Recap

EL is null-safe by design; use `empty`, ternaries and `default` for nulls that carry meaning, and make the rest impossible upstream.
