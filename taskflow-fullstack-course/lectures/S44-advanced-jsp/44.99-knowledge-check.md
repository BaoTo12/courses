**1. (Concept)** How do `<fmt:message>` and i18next differ in *where* and *when* translation happens?

<details><summary>Answer</summary>

| | `<fmt:message>` (Admin Portal) | i18next (React) |
|---|---|---|
| where | on the **server**, while the JSP renders | in the **browser**, while React renders |
| when | once per request: the HTML arrives already translated | at runtime; switching language re-renders without a reload |
| bundles | `.properties` on the classpath, loaded by `ResourceBundle` (cached by the JVM) | JSON files fetched over HTTP (`i18next-http-backend`), per namespace |
| locale choice | `LocaleFilter`: cookie → `Accept-Language` → en | detector: cookie → `navigator.language` → fallback |
| switching | a POST that sets the cookie, then a new page | `changeLanguage()`, then the cookie is written |

Both read and write the same `tf_lang` cookie, so the user has one preference (44.08).
</details>

**2. (Design)** Tag file vs `<jsp:include>` vs custom tag handler: pick one for a layout, a badge and a date formatter.

<details><summary>Answer</summary>

- **Layout:** a tag file (`<t:layout title="…">`): typed attribute, the page's content as the body, no Java.
- **Badge:** a tag file (`<t:statusBadge status="…"/>`): a typed enum attribute, a few lines of markup and `<fmt:message>`.
- **Date formatter:** a `SimpleTagSupport` handler (`<tf:date>`): it needs Java (`DateTimeFormatter`, `java.time`, the fmt locale via `Config.find`); JSTL's `fmt:formatDate` can't take a `LocalDate`.

`<jsp:include>` remains right for independent widgets that could be requested on their own (the flash message).
</details>

**3. (Implementation)** A localised "Due in 3 days" / "Còn 3 ngày" label.

<details><summary>Answer</summary>

Bundle entries with MessageFormat choice:

```properties
due.inDays={0,choice,1#Due tomorrow|1<Due in {0} days}
due.inDays={0,choice,1#Hạn ngày mai|1<Còn {0} ngày}        # messages_vi
```

and a tag that computes the number of days from the controller's `today` and looks the text up with `LocaleSupport.getLocalizedMessage(pageContext, "due.inDays", new Object[] {days})`: TaskFlow's `<tf:relativeTime value="${task.dueDate}" today="${today}"/>` (44.13). Without a custom tag: compute `daysLeft` in the controller and write `<fmt:message key="due.inDays"><fmt:param value="${daysLeft}"/></fmt:message>`.
</details>

**4. (Debugging)** A user named `<b>Eve</b>` sees her name in bold in the nav after the i18n change, but not before. Why?

<details><summary>Answer</summary>

Before, the nav used `<c:out value="${currentUser.displayName}"/>`, which escapes. Now the name is a `<fmt:param>` of `nav.loggedInAs`, and `<fmt:message>` inserts parameters **without escaping**. The fix is `<fmt:param value="${fn:escapeXml(currentUser.displayName)}"/>` (TaskFlow's nav does this: 44.06). A `<script>` name would have been stored XSS on every page.
</details>

**5. (Code reading)** Why does the pagination link for page 1 have no `page` parameter?

<details><summary>Answer</summary>

`/tasks` and `/tasks?page=1` show the same content. With one canonical URL per page, the "current page" state, visited-link colouring, caches and bookmarks all agree, and "Previous" from page 2 leads back to the same URL as the nav's **Tasks** link.
</details>
