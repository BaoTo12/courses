# Lecture 44.01 · Nested Objects, Collections and Maps: Advanced EL Patterns and Their Limits

## 1. Navigating object graphs

| Expression | Resolves to |
|---|---|
| `${details.task.title}` | `getDetails().getTask().getTitle()`: each dot is a getter (34.07) |
| `${details.owner.displayName}` | null-safe: if `owner` is null, the result is null → prints nothing |
| `${details.comments[0].body}` | a `List` by index; out of range → null, not an exception |
| `${stats['TODO']}`, `${stats[status.name()]}` | a `Map` by key; the key can be computed (S44's list: one loop over the statuses) |
| `${taskPage.items}` | a **record**: EL 3.0 needs `getItems()` methods, which TaskFlow's records declare explicitly |
| `${fn:length(overdue)}` | the size of a collection (`.size` is not a property) |
| `${task.isOverdue(today)}` | a method call with arguments (EL 2.2+) |

## 2. Map keys: the trap

```jsp
${counts[category.id]}     <%-- Map<Long, Integer>: category.id is a Long → works --%>
${counts[3]}               <%-- the literal 3 is a LONG in EL → works for Long keys, NOT for Integer keys --%>
${stats[status]}           <%-- Map<String, …> with an enum → the enum is NOT converted to a String: null --%>
${stats[status.name()]}    <%-- explicit: works --%>
```

EL doesn't coerce map **keys**: the lookup is `map.get(key)` with whatever type the expression produced.

## 3. What EL can't (and shouldn't) do

| Wanted | Why not in EL | Where instead |
|---|---|---|
| sorting, grouping, filtering a list | EL 3.0 has lambdas and `.stream()`, but that's logic in the view | the service / controller |
| "the user's overdue count" | a query | the controller sets `overdueCount` |
| formatting a `LocalDate` | JSTL 1.2's `fmt` only knows `java.util.Date` | a custom tag (44.13) |
| anything with side effects | views must be safe to re-render | the controller |

EL 3.0 does allow `${tasks.stream().filter(t -> t.done).toList()}`. It works, and it's hard to test and easy to repeat. TaskFlow's rule (35.08): the controller prepares **exactly** what the view shows.

## ✅ Recap

EL reads graphs of getters, lists and maps, null-safely. Map keys aren't coerced. Computations belong before the view.
