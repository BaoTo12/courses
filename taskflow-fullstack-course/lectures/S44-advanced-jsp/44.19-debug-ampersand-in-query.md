# Lecture 44.19 · 🐞 Debug: `&` in the Search Breaks the Pagination Links

> **Section:** S44 · **Type:** 🐞 Debug · **Track:** ★ Core · **Time:** ~15 minutes
> Verified: `S44AdvancedJspTest.pageLinksKeepTheFiltersAndEncodeThem` (the correct version: `q=R%26D+…&amp;sort=title&amp;page=2`)

---

## 1. Symptom

Searching `R&D` works on page 1. Clicking **2** shows page 2 of **all** tasks, searching for `R`.

## 2. The broken link

```jsp
<a href="/taskflow/tasks?q=${param.q}&page=2">2</a>          <%-- ❌ --%>
```

renders `href="/taskflow/tasks?q=R&D&page=2"`. The server parses three parameters: `q=R`, `D` (empty), `page=2`. The `&` inside the value was read as a separator.

The same bug takes other forms:

| Input | Broken link parses as |
|---|---|
| `R&D` | `q=R` + a stray `D` |
| `100%` | `%` + two characters decoded as a byte → garbage or a 400 |
| `a+b` | `q=a b` (`+` means space) |
| `C#` | `q=C` (`#` starts the fragment, never sent) |
| `x&status=DONE` | the user **injects** a parameter |
| `" onmouseover="…` | breaks out of the `href` attribute (HTML context) |

## 3. Fix

```jsp
<c:url var="href" value="/tasks">
  <c:param name="q" value="${param.q}"/>
  <c:param name="page" value="2"/>
</c:url>
<a href="${fn:escapeXml(href)}">2</a>
```

URL-encode the value (`<c:param>`), then HTML-escape the URL (`fn:escapeXml`), in that order (44.03). TaskFlow's `pageLink.tag` and `sortHeader.tag` do it once, so pages can't get it wrong.

## ✅ Takeaway

Never concatenate a value into a URL. Build URLs with a tool that encodes each parameter, then escape the result for HTML.
