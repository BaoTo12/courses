"Công việc" passes through six places. Each one must agree on UTF-8, or the user sees `CÃ´ng viá»‡c` or `C?ng vi?c`.

| # | Place | Setting | TaskFlow |
|---|---|---|---|
| 1 | source files (`.java`, `.jsp`, `.tag`) | the editor + Maven's `project.build.sourceEncoding` | UTF-8 (28.03) |
| 2 | JSP → servlet translation | `pageEncoding` / `<page-encoding>` for `*.jsp`, `*.jspf`; `pageEncoding` in each `<%@ tag %>` | UTF-8 (33.10) |
| 3 | `.properties` bundles | **Java 9+** reads `PropertyResourceBundle` files as UTF-8 (falls back to ISO-8859-1 if the bytes aren't valid UTF-8). Before Java 9: ISO-8859-1 only, and non-Latin text had to be written as `ô` escapes (`native2ascii`) | UTF-8 files, Java 17 |
| 4 | request bodies (form posts) | `request.setCharacterEncoding("UTF-8")` before any parameter is read | `CharacterEncodingFilter` (40.05) |
| 5 | the response | `contentType="text/html;charset=UTF-8"` → the `Content-Type` header; `<meta charset="utf-8">` | every page |
| 6 | the database | `utf8mb4` (real 4-byte UTF-8, emoji included) for tables and the connection | `db/02-schema.sql`, server flags (28.07) |

## Symptoms and causes

| You see | Usually |
|---|---|
| `Ã´` instead of `ô` | UTF-8 bytes **decoded as ISO-8859-1** (a missing charset: #2, #3 on old Java, #5) |
| `?` instead of `ô` | a character **encoded** into a charset that doesn't have it (the DB column wasn't `utf8mb4`, or the response writer used ISO-8859-1) |
| `�` | invalid bytes for the decoder (mixed encodings in one file) |
| correct on the page, wrong in the database | #4 or #6 |

## ✅ Recap

UTF-8 in every file, every translation, every request, every response and every column. Java 9+ finally made bundles part of that by default.
