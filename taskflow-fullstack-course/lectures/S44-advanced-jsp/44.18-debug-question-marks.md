# Lecture 44.18 · 🐞 Debug: `???tasks.title???` Instead of Text

> **Section:** S44 · **Type:** 🐞 Debug · **Track:** ★ Core · **Time:** ~15 minutes

---

## 1. Symptom

The page shows `???tasks.title???`, `???nav.logout???`: every message, or only some.

`<fmt:message>` prints `???key???` when it **can't find the key**. It never throws, so nothing appears in the log.

## 2. Checklist

| # | Cause | Check |
|---|---|---|
| 1 | **no bundle at all**: the `localizationContext` context param is missing or misspelt | every key fails, in every language |
| 2 | the **basename** is wrong: `messages` instead of `i18n.messages` (the path under `WEB-INF/classes`, with dots) | the file is at `target/classes/i18n/messages.properties`? |
| 3 | the file isn't **on the classpath**: saved under `src/main/webapp/` or `src/main/java/` (Maven only copies resources from `src/main/resources`) | look in `target/classes` / the WAR |
| 4 | the **key** is misspelt, or computed from the wrong value: `status.${task.statusLabel}` → `status.In progress` (EL turns an **enum** into its `name()`, so `status.${task.status}` → `status.IN_PROGRESS` is fine) | print the key: `<c:out value="status.${task.status}"/>` |
| 5 | a key only in `messages_vi` (not in the base): missing for English users | every key belongs in the base bundle |
| 6 | a **tag file** or a page uses `<fmt:bundle>`/`<fmt:setBundle>` with another basename | search for `setBundle` |
| 7 | the file's name: `messages_VI.properties` or `message_vi.properties` | exact names, lowercase language |

## 3. Related symptoms

| You see | Cause |
|---|---|
| `Cong viec` with `?` or `Ã´` | the file's encoding (44.09) |
| `{0} overdue tasks` literally | no `<fmt:param>` given, or a quote problem: in MessageFormat, `'` starts a quoted section. `Don't miss {0}` prints `Dont miss {0}`; write `Don''t miss {0}` |
| English on a Vietnamese page for **one** key | the key is missing in `messages_vi` → the base bundle's text (by design) |
| always the server's language | the locale came from the JVM default: no `Accept-Language` handling (44.07) |

## 4. Preventing it

A unit test that loads both bundles and compares their key sets catches #4, #5 and #7 before anyone sees a page.

## ✅ Takeaway

`???key???` means "no text for this key in any bundle I could find". Check the context parameter, the basename, the file's location and name, then the key.
