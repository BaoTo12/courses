## 1. The servlet

✍️ `src/main/java/com/taskflow/web/LanguageServlet.java`

```java
package com.taskflow.web;

import com.taskflow.web.errors.BadRequestException;
import com.taskflow.web.filters.LocaleFilter;
import java.io.IOException;
import javax.servlet.annotation.WebServlet;
import javax.servlet.http.Cookie;
import javax.servlet.http.HttpServlet;
import javax.servlet.http.HttpServletRequest;
import javax.servlet.http.HttpServletResponse;

/**
 * S44 (44.08): POST /preferences/language (lang, returnTo) → the tf_lang cookie → back to the page.
 * The SAME cookie the React app's i18next reads and writes (S25: lookupCookie 'tf_lang', path '/'): cookies are per
 * HOST, not per port, so on localhost the Admin Portal (:8080) and the React dev server (:5173) share it, and in
 * Part 4 both are served from one origin anyway. Switch here → the React app follows on its next load, and vice versa.
 */
@WebServlet("/preferences/language")
public class LanguageServlet extends HttpServlet {

  private static final int ONE_YEAR = 365 * 24 * 60 * 60;

  @Override
  protected void doPost(HttpServletRequest request, HttpServletResponse response) throws IOException {
    String lang = request.getParameter("lang");
    if (!LocaleFilter.LANGUAGES.contains(lang)) throw new BadRequestException("Unsupported language.");
    Cookie cookie = new Cookie(LocaleFilter.COOKIE, lang);
    cookie.setPath("/");                 // the whole host: the React app too
    cookie.setMaxAge(ONE_YEAR);
    // Not HttpOnly: i18next reads it in the browser. A preference, not a secret. SameSite=Lax comes from context.xml (41.12).
    response.addCookie(cookie);
    Http.seeOther(response, Redirects.safeLocalPath(request, request.getParameter("returnTo"), request.getContextPath() + "/tasks"));
  }
}
```

The same pattern as the theme switch (39.09): POST (it changes state) with the CSRF token, an allow-listed value, a cookie on `/`, a safe `returnTo` (41.17), PRG.

## 2. The button

In `nav.jspf`, next to the theme switch:

```jsp
<form class="language-switch inline-form" method="post" action="<c:url value='/preferences/language'/>">
  <input type="hidden" name="_csrf" value="${csrfToken}">
  <input type="hidden" name="returnTo" value="${fn:escapeXml(here)}">
  <button class="btn btn--sm btn--secondary" type="submit" name="lang" value="${lang == 'vi' ? 'en' : 'vi'}"
          lang="${lang == 'vi' ? 'en' : 'vi'}"><fmt:message key="nav.language.switchTo"/></button>
</form>
```

The label is the **other** language, in that language ("Tiếng Việt" on English pages, "English" on Vietnamese ones): someone who can't read the current language can still find it.

## 3. Why the two apps agree

| | React (S25) | Admin Portal (S44) |
|---|---|---|
| reads | i18next detector: `lookupCookie: 'tf_lang'`, then `navigator` | `LocaleFilter`: `tf_lang`, then `Accept-Language` |
| writes | `caches: ['cookie']`, `cookieOptions: { path: '/' }` | `LanguageServlet`, `Path=/` |
| values | `en`, `vi` (`supportedLngs`) | `en`, `vi` (allow-list) |

Cookies belong to a **host**, not a port: during development `localhost:5173` (Vite) and `localhost:8080` (Tomcat) send the same `tf_lang`. In Part 4 both are served from one origin. The cookie isn't `HttpOnly` because i18next reads it in the browser; it's a preference, not a secret.

## ✅ Checkpoint

Click **Tiếng Việt** in the Admin Portal, then reload the React app: it's in Vietnamese. Switch back in React: the next Admin Portal page is in English.
