# Lecture 05.03 · Primitive Types, Arrays, Tuples, and `any` vs `unknown` vs `never`

> **Section:** S05 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~25 minutes

---

## 1. Primitive types

```ts
let title: string = 'Write report';
let count: number = 3;            // integers and floats: one type
let done: boolean = false;
let nothing: null = null;
let notSet: undefined = undefined;
let big: bigint = 10n;
let key: symbol = Symbol('id');
```

Use the **lowercase** names. `String`, `Number`, `Boolean` (capitalised) are wrapper-object types; you almost never want them.

## 2. Arrays and readonly arrays

```ts
const ids: number[] = [1, 2, 3];
const titles: Array<string> = ['a', 'b'];          // same thing, generic syntax (06.01)

function total(values: readonly number[]): number {
  // values.push(4);   ❌ Property 'push' does not exist on type 'readonly number[]'.
  return values.reduce((sum, v) => sum + v, 0);
}
```

`readonly Task[]` is the TypeScript way to say "this function won't mutate the array". All the `task-utils` functions take `readonly Task[]`. If you accidentally write `tasks.sort()` inside, the compiler stops you (04.05's trap, now caught at compile time).

`readonly` is a **compile-time** promise only. At runtime the array is a normal array (type erasure again). `Object.freeze` is the runtime equivalent.

## 3. Tuples: fixed-length arrays with typed positions

```ts
const pair: [string, number] = ['TODO', 4];
const [status, n] = pair;              // status: string, n: number

// React's useState returns a tuple:
const [count, setCount] = useState(0); // [number, Dispatch<SetStateAction<number>>]
```

Tuples are perfect for small, positional return values. For anything with more than 2–3 parts, prefer an object with named properties.

## 4. `any`: turning the checker off

```ts
let data: any = JSON.parse(text);
data.whatever.you.want();     // compiles; may crash at runtime
const n: number = data;       // compiles: any is assignable to everything
```

`any` means "don't check anything involving this value". It spreads: anything you derive from an `any` is also unchecked. Sources of `any` to watch for: `JSON.parse`, some older library types, and missing annotations when `noImplicitAny` is off (it's on under `strict`).

**TaskFlow rule:** no `any` in our code. If you truly don't know a type, use `unknown`.

## 5. `unknown`: the safe "I don't know yet"

```ts
const value: unknown = JSON.parse(text);
value.title;
// ~~~~~ error TS18046: 'value' is of type 'unknown'.

if (typeof value === 'object' && value !== null && 'title' in value) {
  // narrowed: TS now knows value is an object with a 'title' property
}
```

`unknown` accepts **any value** (like `any`) but lets you do **nothing** with it until you **narrow** it (05.07) with checks. That's exactly the right type for data crossing a trust boundary: API responses, `catch` errors (06.09), `localStorage` contents.

| | `any` | `unknown` |
|---|---|---|
| Can hold any value | ✅ | ✅ |
| Can use it without checks | ✅ (dangerous) | ❌ (must narrow first) |
| Assignable to other types | ✅ | ❌ (only to `unknown`/`any`) |

## 6. `never`: the impossible type

`never` is the type with **no values**. It appears when something can't happen:

```ts
function fail(message: string): never {
  throw new Error(message);          // never returns normally
}

type Impossible = 'A' & 'B';         // no string is both → never
```

Its most useful job is **exhaustiveness checking**. When you've handled every member of a union, what's left is `never`:

```ts
function label(status: TaskStatus): string {
  switch (status) {
    case 'TODO': return 'To do';
    case 'IN_PROGRESS': return 'In progress';
    case 'DONE': return 'Done';
    default: {
      const unreachable: never = status;   // compiles only if every case is handled
      return unreachable;
    }
  }
}
```

If someone adds `'BLOCKED'` to `TaskStatus`, this line fails to compile: `Type 'string' is not assignable to type 'never'`, pointing you at every switch that needs a new case. You'll formalise this with `assertNever` in 06.06 and use it in every Redux reducer.

## 7. `void`

The return type of functions that don't return a value: `function log(msg: string): void { console.log(msg); }`.

## 8. Summary

- Primitives: `string`, `number`, `boolean`, `null`, `undefined`, `bigint`, `symbol` (lowercase).
- `T[]` / `readonly T[]`; tuples `[A, B]` for small positional values.
- **`any`** disables checking and spreads. Avoid it.
- **`unknown`** holds anything but must be narrowed before use. Use it at trust boundaries.
- **`never`** = impossible; the key to exhaustiveness checks.

## 9. Check yourself

1. Why is `unknown` a better type than `any` for `JSON.parse` results?
2. What error do you get for `const xs: readonly number[] = [3,1]; xs.sort();`?
3. When would a variable have type `never` in the `default` branch of a switch?

<details>
<summary>Answers</summary>

1. `unknown` forces you to check the value's shape before using it; `any` silently lets you use it however you like, so mistakes surface only at runtime.
2. `Property 'sort' does not exist on type 'readonly number[]'.` Mutating methods are removed from readonly arrays. (Use `xs.toSorted()`.)
3. When every member of the union has been handled by previous `case`s: nothing is left, so the remaining type is `never`.

</details>
