## D. Design

## E. Implementation

11. Write `formatDue(task: Task, today: IsoDate): string` returning `'No due date'`, `'Overdue'`, `'Due today'` or `'Due YYYY-MM-DD'`, with tests. No `!`, no `as`.

<details>
<summary><b>Answers</b></summary>

1. **None from TypeScript.** Only runtime checks (status codes, shape validation, type guards) give guarantees. Types describe what you *expect*.

2. Vitest (like Vite) **strips** types without checking them, so tests can pass with type errors. Trust **both** for their own jobs: tests verify behaviour, `tsc` verifies types. A type error is a real problem even if tests pass (e.g. the 05.01 fixtures missing `description`).

3. `any` disables checking; avoid it in app code. `unknown` accepts anything but forces narrowing before use; use it for untrusted data (API bodies, `JSON.parse`, `catch` variables).

4. `const` keeps the literal (it can't change); `let` widens to `string`. A `string` variable can't be assigned to `TaskStatus` (`Type 'string' is not assignable to type 'TaskStatus'`). Fix with `const`, an annotation (`let s: TaskStatus = 'TODO'`), or `as const`.

5. (a) `string | number` (b) `number` (c) `string`.

6. `a`: ❌ (`string | undefined` not assignable to `string`). `b`: ❌ (`Object is possibly 'undefined'`). `c`: ✅.

7. If the domain type says `dueDate: Date`, it lies: JSON has no `Date` type; the API sends a **string** like `"2026-10-03"`. `JSON.parse` returns `any` (or the code used `as`), so nothing checked it, and at runtime `dueDate` is a string without `toISOString`. Type dates from JSON as `string` (ISO) and convert explicitly where needed.

8. `field: keyof Task` and `value: Task[keyof Task]` aren't linked. `value` accepts the union of **all** property types, and `42` is valid for `id`. A generic `K extends keyof Task` with `value: Task[K]` links them (06.02).

9. **No, not blindly.** DTOs should model **what the API sends**: never `passwordHash` (it must not leave the server); dates as ISO **strings**; Java enums as **string literal unions** with the same values; nullability matching the JSON (`null`), not Java's `Optional`. Separate request and response shapes (06.04).

10. A **string literal union**: zero runtime code, directly matches the JSON strings from Java, works with type-stripping tools, and still gives autocomplete/typo checks. Iterate via an `as const` array when needed (06.05).

11. One solution:
    ```ts
    export function formatDue(task: Task, today: IsoDate): string {
      if (task.dueDate === null) return 'No due date';
      if (task.status !== 'DONE' && task.dueDate < today) return 'Overdue';
      if (task.dueDate === today) return 'Due today';
      return `Due ${task.dueDate}`;
    }
    ```
    Tests: one per branch, plus "DONE with a past date is not 'Overdue'".
