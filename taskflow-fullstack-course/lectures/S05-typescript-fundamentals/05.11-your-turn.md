## 1. Tasks

### A. `isOverdue(task: Task, today: IsoDate): boolean`

A task is overdue when it has a due date **strictly before** `today` and is **not DONE**. The provided test (05.09) must pass.

Why pass `today` as a parameter instead of calling `new Date()` inside? (Think about 04.06's definition of a pure function, and about testing.)

### B. `countByPriority(tasks: readonly Task[]): Record<Priority, number>`

Always returns all three keys (`{ LOW: 0, MEDIUM: 2, HIGH: 1 }`). Write at least two tests for it yourself in `task-utils.test.ts`.

### C. `loadTasks(url: string): Promise<Task[]>`

In a new file `src/api.ts`, write an async function that fetches a JSON document shaped like `{ "tasks": [ … ] }` (the S04 `db.json`) and returns the tasks.

Requirements:
1. **No `any`** and **no `as Task[]`** anywhere.
2. Treat `await response.json()` as `unknown`.
3. If the HTTP status isn't OK, throw an `Error` with the status in the message.
4. If the JSON isn't an object with a `tasks` **array**, throw `Error('Invalid response: expected { tasks: [...] }')`.
5. You may assume each array element *is* a valid Task after the array check (full per-item validation comes with type guards in 06.08). Write a comment explaining this remaining gap.

Use it from a quick script or test by mocking `fetch` (hint below).

## 2. Acceptance

- [ ] `npm run typecheck` → no errors.

- [ ] `grep -n "any\|as Task" src/api.ts` → nothing.

## 3. Hints

<details>
<summary>Hint 1: isOverdue in one expression</summary>

`&&` chains narrow: after `task.dueDate !== null &&`, the next operand knows `dueDate` is a `string`. ISO dates compare correctly as strings.
</details>

<details>
<summary>Hint 2: getting from unknown to "has a tasks array"</summary>

`typeof data === 'object' && data !== null && 'tasks' in data && Array.isArray(data.tasks)`. After this, what type does TS give `data.tasks`? (Hover it. It's `any[]`, because `Array.isArray` narrows to `any[]`. Returning it as `Task[]` compiles, which is exactly the remaining gap you should document.)
</details>

<details>
<summary>Hint 3: testing loadTasks without a server</summary>

Vitest can replace globals: `vi.stubGlobal('fetch', async () => new Response(JSON.stringify({ tasks: [] }), { status: 200 }))`. `Response` is built into Node 18+.
</details>
