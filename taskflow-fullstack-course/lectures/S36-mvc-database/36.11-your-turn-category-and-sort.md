## Requirements

**URL:** `/tasks?category=4&sort=title` (combinable with `status` and `q`).

1. **Data layer (📦 provided):** `TaskFilter(status, text, categoryId, sort)` and the `TaskSort` allow-list (oldest first, newest first, due date, priority, title) already exist; `TaskService.find(filter)` does the query. Read `TaskSort`: it's 36.09 §3's pattern.
2. **Sort options** come from `TaskSort.values()`: each has a URL value (`getParam()`: `due`) and a label (`getLabel()`: `Due date`).
3. **Controller:** parse `category` with `Params.positiveId` (invalid → no filter, not a 400 or 500), and `sort` with `TaskSort.parse` (unknown → the default). Provide the categories (`service.categories()`) and the sort options to the view.
4. **View:** one GET form with the search box, a category `<select>` ("All categories" + one option per category, the current one `selected`) and a sort `<select>`. The status links must keep the current search, category and sort.
5. **Nothing else changes** in the service or the data layer.

**Tests to write first:**
- `?category=4` lists "Book dentist appointment" but not "Write quarterly report", and the "Personal" option is selected;
- `?sort=title` puts "Archive old Jira epics" before "Write quarterly report", and by default it's the other way round;
- `?sort=title; DROP TABLE tasks` → 200, the default order, and the table is still there;
- `?category=abc` → 200;
- `?category=4&sort=title`: the DONE link is `/taskflow/tasks?status=DONE&amp;category=4&amp;sort=title`.

## Hints

- `TaskSort.parse(request.getParameter("sort"))` never throws: unknown → the default.
- `<option value="${category.id}"${category.id == categoryFilter ? ' selected' : ''}>`: compare a `long` with a `Long` that may be `null` (34.13).
