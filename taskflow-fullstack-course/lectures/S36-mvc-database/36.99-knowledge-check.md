# Lecture 36.99 · ✅ Knowledge Check: MVC with a Real Database

> **Section:** S36 · **Type:** ✅ Knowledge Check · **Track:** ★ Core · **Time:** ~20 minutes

---

**1. (Concept)** Why can't a query parameter (`:text`, `?`) change the query's structure, while a concatenated string can?

<details><summary>Answer</summary>

With concatenation, data and SQL are one string, and the database parses both together, so syntax in the data is parsed as SQL (36.08). With a parameter, the query text is parsed **before** any value is known. Values are bound later, into slots, as typed values: a value is compared, never parsed (36.09 §1).
</details>

**2. (Code reading)** Is `"… ORDER BY " + sortParam` injectable? Fix it.

<details><summary>Answer</summary>

Yes: `sortParam` becomes SQL text. `ORDER BY ?` doesn't work (it binds a constant value). Fix: an allow-list, where the input **selects** a constant from your code, and anything unknown gets a default: `TaskSort.parse(param).orderBy()` (36.09 §3, 36.12).
</details>

**3. (Design)** Which layer should validate "due date not in the past"? Which layer checks "the user owns this task"?

<details><summary>Answer</summary>

"Is it a date?" is **shape**: the controller (parsing). "Not in the past" is a **business rule**: the service (S37 moves create/update validation there), so the JSON API (S46) enforces it too. Ownership is **authorisation**, also enforced in the service (or a filter plus the service, S42), with the current user passed in from the session. It's never a view's job, and never based on a form field (36.01, 36.02).
</details>

**4. (Concept)** What does the least-privilege DB user protect against after an injection, and what doesn't it?

<details><summary>Answer</summary>

It blocks schema changes (`DROP`/`CREATE`/`ALTER` → 1142), rewriting the audit log, and access to other databases. It does **not** stop reading or changing the app's own tables, password hashes included, because the app needs those rights (36.10). Parameterised SQL is the defence; privileges limit the damage.
</details>

**5. (Debugging)** A search for `50%` lists tasks that don't contain "50%" at all. Injection? What's wrong?

<details><summary>Answer</summary>

Not injection (the query's structure didn't change), but `%` is a `LIKE` **wildcard**, so `50%` means "50 followed by anything". Escape `%` and `_` (and the escape character) before binding, with `ESCAPE '!'` in the query, as the provided `TaskDao` does (36.09 §2).
</details>

**6. (Design)** Why are the DataSource and `TaskService` created in a `ServletContextListener`, not in each servlet's `init()`?

<details><summary>Answer</summary>

One pool for the whole application (per-servlet pools multiply connections), created before any request, and **closed** at shutdown (`contextDestroyed`), which `init()` has no counterpart for at the application level. The service is shared via the `ServletContext` and is thread-safe because it has no per-request state (36.04).
</details>

**7. (Implementation)** Show a task count per category on the list page, through the service.

<details><summary>Answer</summary>

DAO: `SELECT category_id, COUNT(*) FROM tasks GROUP BY category_id` → `Map<Long, Integer>`. Service: `countByCategory()`. Controller: `request.setAttribute("categoryCounts", service.countByCategory())`. View, in the category options: `<c:out value="${category.name}"/> (${categoryCounts[category.id] + 0})`. `category.id` is a `long` and EL uses `Long` keys, so `Map<Long, …>` matches (34.10 §3). `+ 0` turns a missing key (`null`) into 0 (34.13).
</details>
