## 1. The rule: the query text is fixed, values travel separately

Every data-access technology has the same fix: a **placeholder** in the query, and the value **bound** to it. In TaskFlow's provided `TaskDao`:

```java
jpql.append(" and t.title like :text escape '!'");            // the query text: constant
…
query.setParameter("text", "%" + escapeLike(filter.text()) + "%");   // the value: bound, never pasted in
```

**Why a bound value can't change the query:** the query text is parsed **first**, with a slot for `:text`. The value arrives afterwards, as a value. However many quotes or keywords it contains, it's compared as text and never parsed as query syntax. That's why every input in `S36MvcDatabaseTest`'s injection list simply finds nothing.

What to look for in any codebase, whatever the library:

| ✅ Safe | ❌ Injectable |
|---|---|
| a placeholder (`?`, `:name`) + a bind call | `"… where title like '%" + q + "%'"` |
| query text built only from **constants** | query text built from request data |

## 2. `LIKE` has its own wildcards

Inside a `LIKE` pattern, `%` (any text) and `_` (any one character) are wildcards. That's not injection (the query's structure can't change), but it changes the **meaning**: a search for `100%` would match every title containing "100". TaskFlow escapes them with a declared escape character:

```java
static String escapeLike(String text) {
  return text.replace("!", "!!").replace("%", "!%").replace("_", "!_");   // escape the escape character first
}
```

The test creates "Coverage at 100% …" and checks that `?q=100%` finds it and nothing else.

## 3. Sorting can't be a parameter: allow-list it

A placeholder stands for a **value**, and a sort column isn't a value. `order by :sort` would sort by a constant string, which means no sorting at all. So the sort needs variable query **text**, and that text must come from **your code**, chosen by the input:

```java
public enum TaskSort {
  ID("Oldest first", "t.id"), NEWEST("Newest first", "t.id desc"), DUE(…), PRIORITY(…), TITLE("Title", "t.title, t.id");
  public static TaskSort parse(String value) { … unknown → ID … }
  String orderBy() { return orderBy; }            // package-private: only the DAO sees query text
}
```

The request can only **pick** one of five constants. Anything else, `title; DROP TABLE tasks` included, becomes the default, as the test checks.

The same technique covers every identifier or keyword that varies: columns, directions (`asc`/`desc`), table names.

## ✅ Takeaways

- Placeholders + bound values for every piece of data: data can't become query syntax.
- Escape `%` and `_` when a user's text means literal text in `LIKE`.
- Identifiers and keywords come from an allow-list in your code, **selected** by the input, never copied from it.
