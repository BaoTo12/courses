# Lecture 36.01 · MVC Formally: Model, View, Controller, and Their Boundaries

> **Section:** S36 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~20 minutes

---

## 1. Where we are

Since S32, TaskFlow has been *roughly* MVC: servlets decide, JSPs display. But the "model" was an in-memory store the servlets called directly, and some decisions (what "toggle" means) sat inside servlets. S36 makes the boundaries explicit and puts a real database behind them.

## 2. The three roles

```text
            HTTP request
                 │
                 ▼
┌──────────────────────────────────┐   parses parameters, validates their SHAPE, calls the model,
│  CONTROLLER  (a servlet)         │   chooses the view (or redirects / sends an error status)
└───────┬─────────────────▲────────┘
        │ calls            │ returns data (Task, TaskDetails, List<Category>…)
        ▼                  │
┌──────────────────────────┴───────┐   the domain: data + RULES ("overdue", "toggle", "a comment needs
│  MODEL  (service + DAO + domain) │   an existing task"), and access to storage. Knows NOTHING about HTTP.
└──────────────────────────────────┘
        controller puts data in request attributes, then forwards
                 ▼
┌──────────────────────────────────┐   renders HTML from the attributes. Reads, never decides,
│  VIEW  (a JSP: EL + JSTL)        │   never changes data (33.13, 35.10).
└──────────────────────────────────┘
```

| Role | TaskFlow classes | Must not |
|---|---|---|
| **Controller** | `TaskListServlet`, `TaskViewServlet`, `TaskCreateServlet`… | contain SQL, business rules, or HTML |
| **Model** | `TaskService`; `TaskDao`, `CategoryDao`, `UserDao`, `CommentDao`; `Task`, `TaskDetails`, `TaskStatus` | know about `HttpServletRequest`, sessions, JSPs |
| **View** | `list.jsp`, `view.jsp`, the fragments | contain Java (enforced since S36: `<scripting-invalid>`), load data, decide redirects |

## 3. "Model" is not just "the data classes"

In web MVC, *model* means the whole application core: domain objects **and** the services and data access behind them. Some teams say "model" for the data passed to the view (Spring's `Model` object). That's the **view model** (36.06). Keep the two meanings apart when you read code.

## 4. The test for a good boundary

Ask of each line: *could this code run without a web server?*

- `TaskService.toggle(id)`: yes. It can be tested with a plain JUnit test, called from a JSON API (S46), a CLI or a scheduled job. → **model**
- `Params.positiveId(request.getParameter("id"))`: no, it's about HTTP input. → **controller**
- `<c:forEach items="${tasks}">`: no, it's about HTML. → **view**

If the JSON API (S46) would need to copy a line from a servlet, that line belongs in the model.

## ✅ Recap

Controller = HTTP in/out. Model = rules and data, no HTTP. View = HTML from attributes, no decisions. S36 moves TaskFlow's rules into a service and its data into MySQL.
