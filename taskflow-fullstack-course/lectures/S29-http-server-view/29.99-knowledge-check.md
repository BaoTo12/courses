# Lecture 29.99 · ✅ Knowledge Check: HTTP from the Server's Point of View

> **Section:** S29 · **Type:** ✅ Knowledge Check · **Track:** ★ Core · **Time:** ~15 minutes

---

**1.** Why can a browser "follow" a 302, while a `fetch` from JavaScript might handle it differently?

<details><summary>Answer</summary>

On a navigation (a link or form), the browser follows the `Location` and shows the new page. With `fetch`/XHR, the browser also follows redirects **transparently** by default: your code gets the *final* response, and `response.redirected === true`. Cross-origin redirects are subject to CORS, and with `redirect: 'manual'` you get an opaque response and can't read `Location`. A JSON API should return 401/403 rather than redirect to a login page, or JS code receives the login page's HTML with a 200 (Part 3).
</details>

**2.** Identify method, path, query, headers, cookies and body:

```text
POST /taskflow/tasks/edit?from=list HTTP/1.1
Host: localhost:8080
Cookie: JSESSIONID=5F2C; tf_lang=vi
Content-Type: application/x-www-form-urlencoded
Content-Length: 25

id=7&title=Plan+offsite
```

<details><summary>Answer</summary>

Method `POST`. Path `/taskflow/tasks/edit` (context `/taskflow` + servlet path `/tasks/edit`). Query `from=list`. Headers `Host`, `Cookie`, `Content-Type`, `Content-Length`. Cookies `JSESSIONID=5F2C` and `tf_lang=vi`. Body `id=7&title=Plan offsite` (the `+` decodes to a space). `getParameter("from")`, `getParameter("id")` and `getParameter("title")` all work, because the query and a urlencoded body are merged (29.06).
</details>

**3.** Deleting a task via `GET /tasks/delete?id=5`: list three problems.

<details><summary>Answer</summary>

(1) Prefetchers, crawlers and link previews trigger it. (2) CSRF becomes trivial: an `<img src>` on any site does it, and `SameSite=Lax` still sends cookies on top-level GETs. (3) It can be cached, replayed from history, and it leaks into logs and Referers. Also, GET is supposed to be safe, and tools rely on that (29.03).
</details>

**4.** A logged-in USER requests `/taskflow/admin/users`. 401, 403 or 404? And for someone else's task id?

<details><summary>Answer</summary>

The admin page: **403** (authenticated, not allowed). Someone else's task: **404**, so the existence of ids isn't revealed (29.04 §3).
</details>

**5.** A form has `<input type="hidden" name="ownerId" value="1">`. What must the servlet do with it?

<details><summary>Answer</summary>

Ignore it for anything security-relevant. The owner is the **logged-in user from the session**, and edits must check ownership on the server. Hidden fields are user input (29.09).
</details>

**6.** What does HTTPS protect in `Cookie: JSESSIONID=…`, and what doesn't it?

<details><summary>Answer</summary>

It protects the cookie from being **read or modified in transit**. It doesn't stop XSS from using the session in the page, a CSRF request from another site, or a stolen laptop's browser profile. Hence also HttpOnly, SameSite, CSRF tokens and `Secure` (29.10).
</details>
