# Lecture 29.02 · 🛠 Talking HTTP by Hand: `curl -v`, and a Raw Request via `ncat`

> **Section:** S29 · **Type:** 🛠 Build · **Track:** ★ Core · **Time:** ~40 minutes
> Captured for this lecture: the two curl exchanges below, against the local mock API (`node server.mjs`).

---

## 1. curl: your HTTP microscope

```bash
curl -v http://localhost:3001/api/auth/me                    # -v: show the request and the response headers
curl -i http://localhost:3001/api/categories                 # -i: response headers + body, no request
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8080/taskflow/     # just the status
```

## 📇 API card: the curl options you'll use in Parts 2–3

| Option | Meaning |
|---|---|
| `-v` | verbose: request line, headers, response headers (`>`/`<`) |
| `-i` | include response headers in the output |
| `-X METHOD` | the method (`-X DELETE`). `-d` implies POST. |
| `-H "Name: value"` | add a header (repeatable) |
| `-d 'a=1&b=2'` | a body, **form-encoded** by default (`Content-Type: application/x-www-form-urlencoded`) |
| `--data-urlencode 'q=a b&c'` | a body field, URL-encoded for you |
| `-F 'file=@report.pdf'` | multipart/form-data (file upload) |
| `--json '{"title":"x"}'` | a JSON body with the right headers (curl 7.82+) |
| `-b 'JSESSIONID=…'` / `-c jar.txt` / `-b jar.txt` | send cookies / save them / send saved ones: a "session" |
| `-L` | follow redirects (by default curl **shows** the 302, it doesn't follow it) |
| `-o file` / `-s` | save the body / silent |

## 2. A form POST the server refuses

```text
> POST /api/tasks HTTP/1.1
> Host: localhost:3001
> Content-Type: application/x-www-form-urlencoded
> Content-Length: 7
>
> title=x
< HTTP/1.1 415 Unsupported Media Type
< Content-Type: application/json; charset=utf-8
< Content-Length: 181
```

`curl -d 'title=x'` sent a form body, and the JSON API answers **415**: "I only accept JSON bodies". That's the rule in `server.mjs` (a CSRF layer, 24.10). The same request with `--json '{"title":"x"}'` gets past it (and then needs a session).

## 3. No curl at all: a raw TCP conversation

`ncat` (from Nmap), or `telnet`, opens a TCP connection and lets you **type** HTTP:

```bash
ncat localhost 8080
```

Type, pressing Enter after each line, **and an extra Enter at the end** (the blank line):

```text
GET /taskflow/ HTTP/1.1
Host: localhost

```

Tomcat answers with a status line, headers and the HTML of `index.html`. You just did what a browser does. Try it without the `Host` line: **400 Bad Request**, because HTTP/1.1 requires it.

(Windows: install Nmap for `ncat`, or enable the Telnet client. PowerShell has no raw TCP client built in.)

## 4. The browser's version: DevTools → Network

Click a request → **Headers** (the request and response headers), **Payload** (the body), **Response** (the raw body), **Timing**. Right-click → **Copy → Copy as cURL (bash)** replays the exact request, cookies included (26.08 used it).
