# Lecture 29.04 · Status Codes: 2xx, 3xx, 4xx, 5xx, and the Pairs People Confuse

> **Section:** S29 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~35 minutes
> 🔗 Reference: RFC 9110 §15

---

## 1. The classes

| Class | Meaning | Who's "at fault" |
|---|---|---|
| 1xx | informational (rare: `100 Continue`, `101 Switching Protocols`) | — |
| **2xx** | success | — |
| **3xx** | redirection: look elsewhere | — |
| **4xx** | client error: fix the request | the client |
| **5xx** | server error: the request may be fine | the server |

## 2. The ones TaskFlow uses, and the pairs to get right

**Success**

| Code | Use | TaskFlow |
|---|---|---|
| `200 OK` | success with a body | GET a task, PUT returns the saved task |
| `201 Created` | a new resource was made; `Location:` header points to it | `POST /api/tasks` |
| `204 No Content` | success, **no** body | `DELETE /api/tasks/5`, logout |

**Redirects**

| Code | Meaning | Method on the next request |
|---|---|---|
| `301 Moved Permanently` | the URL changed forever (browsers cache it!) | browsers may switch POST → GET |
| `302 Found` | "temporarily, look there" | browsers switch POST → GET in practice |
| **`303 See Other`** | "the result is over there, GET it" | always GET: **the PRG pattern** (S37) |
| `307` / `308` | temporary / permanent, **keep** the method and body | same method |

`response.sendRedirect(url)` in a servlet sends **302** (S31). For a POST → redirect → GET, browsers treat 302 like 303.

**Client errors**

| Code | Means | Example |
|---|---|---|
| `400 Bad Request` | malformed or invalid input | validation failed (`fieldErrors`) |
| **`401 Unauthorized`** | **not authenticated**: who are you? | no session (24.13) |
| **`403 Forbidden`** | authenticated, but **not allowed** | a USER on `/admin/users` (S42); a bad CSRF token |
| `404 Not Found` | no such resource, **or** "you may not know it exists" | someone else's task (26.08) |
| `405 Method Not Allowed` | wrong method for this URL | `DELETE` on a GET-only servlet |
| `409 Conflict` | the request conflicts with the current state | an edit on a stale version (optional) |
| `415 Unsupported Media Type` | wrong `Content-Type` for the body | a form body sent to the JSON API (29.02) |
| `429 Too Many Requests` | rate limit | login throttling (S41) |

**Server errors**

| Code | Means |
|---|---|
| `500 Internal Server Error` | an unhandled exception: a bug, never "expected" |
| `502` / `503` / `504` | a gateway or proxy problem / unavailable / timeout |

## 3. 401 vs 403 vs 404

```text
no session?                      → 401  (log in, then retry)
session, but not your role       → 403  (logging in again won't help)
session, but not YOUR task       → 404  (don't even confirm it exists: no probing of ids, S42)
```

## 4. Status codes are an API

TaskFlow Web **branches** on them: 401 → `sessionExpired` (24.13), 404 → the "Not found" page (22.09), 400 → field errors. A server that answers `200 {"error": "..."}` breaks all of that. Status first, and the error body (02-project-spec §5) for details.

## ✅ Recap

2xx = done, 3xx = look elsewhere, 4xx = fix the request, 5xx = our bug. 201 + `Location` for creates, 204 for empty success, 303 after POSTs. 401 = who are you, 403 = not allowed, 404 = not found (or not yours).
