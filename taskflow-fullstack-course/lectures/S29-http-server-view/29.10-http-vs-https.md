# Lecture 29.10 · 🛡 HTTP vs HTTPS: What TLS Protects, and What It Doesn't

> **Section:** S29 · **Type:** 📖 Theory (🛡 Security) · **Track:** ★ Core · **Time:** ~25 minutes

---

## 1. Plain HTTP on a shared network

On café Wi-Fi, anyone on the path (the router, the ISP, a malicious hotspot) can **read** every byte of 29.01's exchanges, including `Cookie: JSESSIONID=…` (session hijacking) and the login form's `password=alice123`, and can **modify** responses (inject scripts, change download links).

## 2. What HTTPS (HTTP over TLS) adds

| Property | Meaning |
|---|---|
| **Confidentiality** | the request and response (path, headers, cookies, bodies) are encrypted |
| **Integrity** | tampering in transit is detected |
| **Server authentication** | the certificate proves you're talking to `taskflow.example`, not an impostor (as long as the certificate is valid and the user doesn't click through warnings) |

The HTTP messages inside are **exactly the same text**. TLS is a tunnel around them.

## 3. What TLS does NOT protect

| Not protected | Why |
|---|---|
| **The server's own bugs**: XSS, SQL injection, IDOR, CSRF | the attacker uses the same encrypted channel as everyone |
| Data at the endpoints | the browser (malware, extensions) and the server (logs, database) see plain text |
| Which **site** you visit | the domain is visible (DNS, the SNI field), the path isn't |
| A server that *is* malicious | a valid certificate proves identity, not honesty (phishing sites have certificates) |

## 4. Making the browser insist on HTTPS

- The **`Secure`** cookie attribute (24.02): the session cookie is never sent over HTTP. Tomcat sets it for the session cookie on HTTPS requests (S38 verifies).
- **HSTS**: `Strict-Transport-Security: max-age=31536000; includeSubDomains` makes the browser refuse plain HTTP for that site (S40's headers filter).
- Redirect HTTP → HTTPS at the entry point (a reverse proxy, or Tomcat's `redirectPort`).

## 5. In TaskFlow

Development runs on `http://localhost` (browsers treat localhost as a secure context). Production (S49) terminates TLS at a reverse proxy or at Tomcat, and the app must know the original scheme to build correct redirects and `Secure` cookies (`RemoteIpValve`, S49).

## ✅ Recap

TLS = privacy + integrity + server identity **in transit**. It doesn't make the application secure. Add `Secure` cookies and HSTS so the browser never falls back to HTTP.
