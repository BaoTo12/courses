# Lecture 29.07 · Statelessness: Why Sessions and Cookies Had to Be Invented

> **Section:** S29 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~25 minutes

---

## 1. Each request stands alone

Nothing in HTTP links `POST /login` to the `GET /tasks` that follows. They may arrive on different TCP connections, at different server instances, minutes apart. The protocol is **stateless**: the server remembers nothing *by default*.

That's a strength (any server can answer any request, and a restart loses nothing HTTP depends on) and a problem (how does the server know it's still alice?).

## 2. The solution: the client carries an identifier

```text
POST /taskflow/login            → server: creates a SESSION (a map in memory), id = 5F2C…
                                ← Set-Cookie: JSESSIONID=5F2C…; Path=/taskflow; HttpOnly
GET  /taskflow/tasks
     Cookie: JSESSIONID=5F2C…   → server: looks up session 5F2C… → { user: alice, locale: vi, … }
```

- The **cookie** (24.01) carries only the **id**. The state lives on the **server**, in the `HttpSession` (S38).
- Tomcat creates the id, sends the cookie, and maps it back on each request. You call `request.getSession()`.

## 3. Alternatives, and their trade-offs

| Approach | State lives | Trade-off |
|---|---|---|
| **Server session + cookie id** (TaskFlow) | server memory (or a shared store) | easy to revoke (delete the session), but needs sticky sessions or shared storage across servers |
| URL rewriting (`;jsessionid=5F2C…`) | server | the id leaks into logs, Referers and shared links. Disabled in our `web.xml` (`tracking-mode COOKIE`, 28.04). |
| Hidden form fields | the page | per-form only, and editable |
| Signed tokens (JWT) in a header | the token itself | no server lookup, but hard to revoke before expiry (a S47 discussion) |

## 4. Three scopes you'll use, by lifetime

| Scope | Lives for | Servlet API | TaskFlow |
|---|---|---|---|
| **request** | one request (through forwards) | `request.setAttribute` | the list of tasks passed to a JSP (S31) |
| **session** | one user's visit | `session.setAttribute` | the logged-in user, flash messages (S38) |
| **application** | the app's whole run | `servletContext.setAttribute` | cached categories, stats (S38) |

## ✅ Recap

HTTP forgets. Sessions give memory: the server keeps the state, and the cookie carries the id. Choose the narrowest scope that works.
