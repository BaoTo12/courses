# Lecture 29.08 · Server-Side Rendering: "The Server Sends HTML" Really Means Bytes

> **Section:** S29 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~25 minutes

---

## 1. Two ways to get the same page on screen

```text
TaskFlow Web (Part 1): CLIENT-side rendering
  GET /tasks            → 200 index.html (almost empty: <div id="root"></div> + a script)
  GET /assets/app.js    → the React bundle runs in the browser
  GET /api/tasks        → JSON → React builds the DOM

TaskFlow Admin (Part 2): SERVER-side rendering
  GET /taskflow/tasks   → the servlet queries MySQL → the JSP writes HTML text → 200 text/html
                          <ul><li>Write quarterly report</li>…</ul>   (complete, ready to display)
```

The browser never knows *how* the HTML was produced. A servlet `println`, a JSP, a static file: it receives **bytes** with `Content-Type: text/html;charset=UTF-8` and renders them.

## 2. Consequences for the server side

| Topic | Client-side (React) | Server-side (JSP) |
|---|---|---|
| Who escapes user data | React, automatically (26.02) | **you**, in every JSP (`<c:out>`, `fn:escapeXml`, S35) |
| Where "state" of the UI lives | JS memory, Redux | request/session attributes, the URL, hidden fields |
| Every click | JS + an API call | a **full page request** (links, forms) |
| After a POST | the component updates | **redirect** (PRG) so Reload doesn't resubmit (S37) |
| SEO, first paint, no-JS | weaker | strong |

## 3. Look at it yourself

View Source (`Ctrl+U`) on `http://localhost:8080/taskflow/`: the HTML **as sent**. Then DevTools Elements: the DOM **after** the browser parsed it (and after any JS changed it). For a JSP page, they match. For TaskFlow Web, the source is nearly empty.

## 4. Both, in one product

TaskFlow ends with both: JSP pages for the admin portal, the React SPA for users, **and** a React "island" inside a JSP page (S49). Understanding "it's all bytes over HTTP" is what makes that combination unsurprising.

## ✅ Recap

Server-side rendering = the response body is finished HTML. The browser only ever sees bytes and a Content-Type. On the server, escaping and redirects become your job.
