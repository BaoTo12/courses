# Lecture 29.09 · 🛡 Everything in a Request Is Attacker-Controlled

> **Section:** S29 · **Type:** 📖 Theory (🛡 Security) · **Track:** ★ Core · **Time:** ~30 minutes
> ⚠️ Experiments only against your own local TaskFlow.

---

## 1. The server's view of a request

Your servlet receives bytes. It can't know whether they came from your beautiful form, from curl, or from a script. **Every part** can be anything:

| Part | "But my UI…" | Reality | Consequence |
|---|---|---|---|
| Method | only uses POST for deletes | anyone can send GET, PUT, `DELETE`, `FOO` | handle only what you designed; the rest → 405 |
| Path | only links to existing ids | `/tasks/view?id=1`, `…?id=-1`, `…?id=1 OR 1=1` | validate; authorise per object (S42) |
| Query and body parameters | has a `<select>` with 3 values | any value, missing, repeated, 10 MB long | validate type, range, length; allow-lists (S37) |
| **Hidden fields** | `<input type="hidden" name="ownerId" value="1">` | edited in DevTools in 3 seconds | never trust ids, prices or roles from hidden fields |
| Disabled / `readonly` fields | can't be changed | they're just not sent; a crafted request can send them | the server decides which fields are editable |
| `maxlength`, `required`, `pattern` | enforce input rules | browser UX only | re-validate everything on the server |
| Headers | `User-Agent`, `Referer` | any string, or absent | informational only; never for security decisions |
| `X-Forwarded-For` | "the client IP" | a header the client can set | trust it only from your own proxy (S45's audit log) |
| Cookies | set by the server | edited, deleted, forged | only the **session id** (random, server-side lookup) is meaningful; validate preference cookies (24.06) |
| Content-Type | matches the body | can lie | parse defensively; reject what you don't accept (415) |
| Size and timing | normal users | huge bodies, slow drip ("slowloris"), thousands of requests | limits (Tomcat `maxPostSize`, timeouts), rate limits (S41) |

## 2. A 2-minute demo (local)

On the S37 edit form, open DevTools, change the hidden `id` field to another user's task id, and submit. If the servlet trusts the hidden field and checks nothing, you just edited someone else's task. That's **IDOR** (S42). With curl, you don't even need the form:

```bash
curl -b "JSESSIONID=<bob's>" -d "id=1&title=pwned&_csrf=<token>" http://localhost:8080/taskflow/tasks/edit
```

## 3. The mindset for Parts 2–3

1. **Validate** every input: type, format, range, length, allow-listed values. Reject rather than "fix".
2. **Authorise** every action on every object, on the server: "may *this* user do *this* to *this* task?"
3. **Encode** output for its context: HTML, attribute, URL, JavaScript, SQL (parameters, S36).
4. The UI is a **convenience layer**. The server is the security boundary (26.08).

## ✅ Recap

Method, path, parameters, hidden fields, headers, cookies, size: all attacker-controlled. The server validates, authorises and encodes, every time.
