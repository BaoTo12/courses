<summary><b>Answers</b></summary>

1. **Browser:** React, Redux, Axios, js-cookie, i18next, styled-components, and the HTML/CSS rendering of both clients. **Tomcat:** filters, Servlets, JSP (compiled), EL, JSTL, services, DAOs. **Never received by the browser:** Java objects, JSP source/tags/EL expressions, SQL queries, session contents, server-side code, and SCSS source/TypeScript types (these don't exist at runtime at all).

2. **JSP:** on the **server**, when a request arrives, *before* any response is sent. It produces HTML text. **React:** in the **browser**, *after* the JS bundle is downloaded and run. It produces DOM nodes, usually from JSON data fetched afterwards.

3. A line where data moves from something you don't control to something you do. TaskFlow's main one is **every HTTP request into Tomcat**. Everything on the browser side (including our React app) is untrusted.

4. **Validation** rejects input that doesn't make sense (type, length, allowed values) at the boundary. **Encoding** makes data safe for the specific output context (HTML, attribute, JS, URL, SQL) at the moment of use. Valid data can still be dangerous in a given context (e.g. a valid title containing `<`), so you need both.

5. (a)
   ```html
   <p>Hello, An</p>
   <script>
     const taskCount = 3;
     document.querySelector('#add').onclick = () => { /* … */ };
   </script>
   ```
   (b) Still **3**. The value was computed once on the server; in the browser it's just a literal. Only browser JavaScript could change it.
   *(Security bonus: `${user.displayName}` was not encoded. If the name contained `<script>`, it would run. See S34/S35.)*

6. A redirect makes the **browser** send a **new request**. Request attributes live only as long as the **original** request, so the list page runs in a different request where `msg` never existed. Tomcat isn't losing anything. Use forward (same request) or a session "flash" attribute with PRG (S37).

7. Because the JSP runs **on the server** with direct access to the data prepared by the Servlet (request attributes). The server sends finished HTML; there's no browser code that needs JSON.

8. Any three: URL/path/query parameters, form fields (including hidden ones), JSON bodies, headers, cookies, the order and timing of requests, the JavaScript running in their own browser, whether they use our UI at all.

9. Example: "Hiding the button improves the user experience, but it doesn't protect anything. The button is just HTML in the user's browser, and anyone can send the delete request directly with DevTools or curl. The server must check that the logged-in user owns the task before deleting it. We'll do both: hide the button *and* enforce the rule on the server."

10. Example extra row: *"An attacker's script (via XSS) reads a JS-readable cookie containing session data → account takeover → keep the session ID in an HttpOnly cookie; keep only non-sensitive values (lang, theme, CSRF token) readable."*
