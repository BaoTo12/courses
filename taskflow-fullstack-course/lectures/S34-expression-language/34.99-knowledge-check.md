# Lecture 34.99 · ✅ Knowledge Check: Expression Language

> **Section:** S34 · **Type:** ✅ Knowledge Check · **Track:** ★ Core · **Time:** ~20 minutes

---

**1. (Concept)** Explain exactly how `${user.address.city}` is evaluated, step by step: every scope searched and every method called.

<details><summary>Answer</summary>

Jasper generated `proprietaryEvaluate("${user.address.city}", String.class, pageContext, null)` (34.04).

1. `user` (base `null`): the **ImplicitObjectELResolver** says it's not an implicit object. The **ScopedAttributeELResolver** calls `pageContext.findAttribute("user")`: page → request → session (if the page has one) → application; the first non-null wins (34.03). If it's still not found: an imported class named `user`? no → `null` → the whole expression is `null` → prints `""`.
2. `.address` (base = the User): not a Map/List/array → **BeanELResolver** → `getAddress()` (public class, public no-arg getter) (34.07). If it returns `null`, stop → `""` (34.08).
3. `.city` → `getCity()` → coerced to `String` → written with `out.write`.
</details>

**2. (Concept)** `${user}` vs `${requestScope.user}`: when do they give different results?

<details><summary>Answer</summary>

When `user` exists in **page** scope (then `${user}` returns the page one), or when it's **not** in the request but is in the session/application (then `${user}` finds it, and `${requestScope.user}` is empty). They agree only when the request scope holds the narrowest `user`, or when nobody does (34.05).
</details>

**3. (Code reading)** Predict the output, with `list` an empty `ArrayList` and no `page` parameter: `${empty list}`, `${list.size() > 0}`, `${param.page + 1}`, `${'5' == 5}`.

<details><summary>Answer</summary>

`true` (34.12) · `false` (a method call, 34.07 §2) · `1` (`null` → `0`) · `true` (the string is coerced to a number). The last two are rows of TaskFlow's debug page, checked by `S34ElTest` (34.13).
</details>

**4. (Debugging)** The servlet did `request.getSession().setAttribute("tasks", …)` and the JSP uses `${requestScope.tasks}`. Output?

<details><summary>Answer</summary>

Nothing: `requestScope` looks **only** at request attributes, and the list is in the session. No exception either (34.22, check #4). `${tasks}` would have found it, which is exactly why explicit scopes are both safer and less forgiving. (And in a `session="false"` page, `${sessionScope.tasks}` would **throw**: 34.25.)
</details>

**5. (Code reading)** `Map<Integer, String> names` with key `1`. What does `${names[1]}` print, and why?

<details><summary>Answer</summary>

Nothing. The EL literal `1` is a `Long`, and map keys aren't coerced: `names.get(1L)` → `null`. Use `Long` or `String` keys (34.10 §3).
</details>

**6. (Security)** Why is `<input value="${param.q}">` an XSS vulnerability, and why is `Html.escape` enough there but not inside `<script>`?

<details><summary>Answer</summary>

EL writes the raw string, so `">` closes the attribute and the tag, and a `<script>` follows (34.18). In a **quoted attribute**, entity-encoding `& < > " '` makes the value inert (34.19). Inside `<script>`, the browser doesn't decode entities, and `Html.escape` leaves backslashes alone: a `\` can swallow a closing quote and turn the next value into code. Put data in a `data-` attribute instead.
</details>

**7. (Design)** When would you insist on explicit scopes in your team's JSP style guide?

<details><summary>Answer</summary>

For generic names that can exist in several scopes (`user`, `locale`, `message`), for anything identity- or security-related (the logged-in user: `${sessionScope.currentUser}`), and in shared fragments and layouts included by pages you don't control. Page-specific model attributes set by that page's own controller can stay implicit (34.05, 34.06).
</details>

**8. (Implementation)** Show `Welcome, <name>` for the session user, falling back to "Guest".

<details><summary>Answer</summary>

```jsp
Welcome, ${empty sessionScope.currentUser ? 'Guest' : Html.escape(sessionScope.currentUser.displayName)}
```

With an explicit scope, `empty` for the fallback, and escaping (a display name is user input). The page must have `session="true"` (34.25). In S35, `<c:out value="${sessionScope.currentUser.displayName}" default="Guest"/>` does the same and escapes by default.
</details>
