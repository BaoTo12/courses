# Lecture 34.13 · Type Coercion: `${param.page + 1}`, Strings vs Numbers, Enums vs Strings

> **Section:** S34 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~20 minutes
> Verified: `S34ElTest` (`${param.page + 1}` without `page` → `1`; `${'5' == 5}` → `true`; `${statusFilter == 'DONE'}` with the enum → `is-active`)

---

## 1. EL converts types for you

EL is untyped from your point of view. Each operator decides what it needs and **coerces** the operands:

| Operation | Operands become | Example |
|---|---|---|
| `+ - * %` | numbers (`Long`, `Double` or `BigDecimal`) | `${param.page + 1}`: `"4"` → `4` → `5` |
| `/` | `Double` (or `BigDecimal`) | `${7 / 2}` → `3.5` |
| `< > <= >=` | numbers if either side is a number, else `Comparable` | `${'10' > 9}` → `true` |
| `== !=` | by the "most specific" type: number, then `Boolean`, then **enum**, then `String` | `${'5' == 5}` → `true` |
| `&& \|\| !` and `? :` test | `Boolean` | `${'true' && true}` → `true` |
| template text output | `String`; `null` → `""` | `${null}` → nothing |

## 2. The null rules

| Target type | `null` becomes |
|---|---|
| number (in arithmetic) | `0` → `${param.page + 1}` = `1` |
| `String` (output) | `""` |
| `Boolean` (a condition) | `false` |

So `${param.page + 1}` works on page 1 **without** a `page` parameter. That's convenient, and it can mask a missing value.

## 3. What fails loudly

| Expression | Result |
|---|---|
| `${param.page + 1}` with `?page=abc` | `ELException`: "abc" can't be coerced to `Long` → **500** |
| `${task.status == 'DNOE'}` (typo) | `ELException`: `Enum.valueOf(TaskStatus, "DNOE")` fails. A typo in an enum literal is an error, not `false` |
| `${'a' + 'b'}` | `ELException`: `+` wants numbers |

**Rule for TaskFlow:** parse and validate parameters in the **controller** (`Params.positiveId`, `TaskStatus.parse`), and give the view typed values. `${param.page + 1}` in a view is fine for a quick debug page; a real pager gets `${page.next}` from the controller.

## 4. Enums vs strings

```jsp
${statusFilter == 'DONE'}          <%-- statusFilter is TaskStatus.DONE or null --%>
```

With an enum on one side, the string is converted with `Enum.valueOf`, then compared. It reads naturally, and a misspelling fails fast (§3). For map **keys** there's no coercion at all (34.10 §4).

## ✅ Recap

Operators coerce their operands, and `null` becomes `0`, `""` or `false`. Bad strings in arithmetic, and misspelt enum names, throw. Validate input in Java, and let the view compare typed values.
