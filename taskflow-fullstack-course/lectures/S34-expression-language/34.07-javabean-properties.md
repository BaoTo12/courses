# Lecture 34.07 · JavaBean Property Resolution: `${task.title}` → `getTitle()`

> **Section:** S34 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~25 minutes
> Verified: `S34ElTest` (`${task.done}` → `isDone()`, `${details.owner.displayName}` → `getDisplayName()` on read-only classes)

---

## 1. The rule

For a value that isn't a Map, List or array, `${x.name}` is handed to the **BeanELResolver** (34.04), which uses `java.beans.Introspector` to find the **read method** of property `name`:

| Property in EL | Method it calls | Notes |
|---|---|---|
| `${task.title}` | `public String getTitle()` | `get` + capitalised name |
| `${task.done}` | `public boolean isDone()` | `is` works only for primitive **`boolean`** |
| `${task.dueDate}` | `public LocalDate getDueDate()` | camelCase stays camelCase |
| `${user.admin}` | `public boolean isAdmin()` | a computed property: no field needed |
| `${task.URL}` | `public String getURL()` | two leading capitals stay as they are |

**EL never touches fields.** `private String title` is invisible. `${task.title}` means "call the getter", which is why the getter must exist, be **public**, and take **no arguments**.

## 📇 API card: what makes a class readable from EL

| Requirement | Example | If missing |
|---|---|---|
| the **class** is `public` | `public class Task` | `PropertyNotFoundException` (the getter isn't accessible), even though the method is public |
| a **public no-arg getter** | `public String getTitle()` | `PropertyNotFoundException: Property [title] not found on type [com.taskflow.model.Task]` |
| `boolean` (primitive) for `is…` | `public boolean isDone()` | with `Boolean isDone()` (the wrapper), `${task.done}` isn't found: use `getDone()` or `boolean` |
| a no-arg constructor and setters | | **not needed** for reading. `Category`, `User` and `TaskDetails` are read-only (constructor + getters) and work fine |

Minimal example outside TaskFlow:

```java
public class Money {
  private final long cents;
  public Money(long cents) { this.cents = cents; }
  public long getCents() { return cents; }                            // ${price.cents}
  public String getFormatted() { return String.format("%.2f", cents / 100.0); }  // ${price.formatted}
  public boolean isFree() { return cents == 0; }                      // ${price.free}
}
```

**When to add a getter for the view:** a derived value every view needs and that has no arguments (`isDone()`, `getFormatted()`).
**When not to:** anything that needs outside input (today's date, the current user, a locale). That's a method with parameters (`isOverdue(LocalDate today)`, called as a method, 34.17), or better, a value the controller computes (`${overdueCount}`).

**Common mistakes:**
- A getter named `getIsDone()` → the property is `isDone`, so `${task.done}` fails (34.23).
- A package-private class (no `public`), e.g. a nested helper class → "not found"/"not readable" although the method exists.
- A getter with side effects (loading from the DB, counting calls). EL may call it **several times** per page: once per `${…}`.
- Expecting `${task.getTitle}` to work: that asks for property `getTitle` → `getGetTitle()`.

## 2. Method calls (EL 2.2+)

```jsp
${task.isOverdue(today)}      <%-- a real method call with an argument --%>
${tasks.size()}               <%-- works; ${tasks.size} does NOT (no getSize()) --%>
```

Method calls exist, but they reopen the door to "Java in the view". TaskFlow allows one: `isOverdue(today)`, a pure domain rule. S36's style rule: views read properties, and controllers call methods.

## ✅ Recap

`${x.name}` → public class, public `getName()` (or `boolean isName()`), no args. Fields are never read, and setters are never needed for display.
