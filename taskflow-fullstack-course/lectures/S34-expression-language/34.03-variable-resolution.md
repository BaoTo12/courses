# Lecture 34.03 · Variable Resolution: `${user}` → `pageContext.findAttribute("user")`

> **Section:** S34 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~25 minutes
> Verified: `S34ElTest.theElDebugPageShowsImplicitObjectsAndCoercions` (`scopeDemo` set in request **and** application scope → `${scopeDemo}` prints `request`)

---

## 1. The first identifier is special

In `${details.task.title}`, only `details` is looked up by **name**. `task` and `title` are properties of whatever `details` turned out to be (34.07).

The first identifier is resolved in this order:

```text
${details}
  1. Is it an implicit object?  pageContext, param, header, cookie, requestScope, … (34.14)   → no
  2. Is it an attribute?        pageContext.findAttribute("details"):
         page scope        pageContext.getAttribute("details")          → null
         request scope     request.getAttribute("details")              → TaskDetails ✔ stop
         session scope     (only if the page has a session)
         application scope servletContext.getAttribute("details")
  3. (EL 3.0) Is it an imported class name?  Html → com.taskflow.web.Html (34.17)
  4. Nothing found → null
```

## 2. The order: page → request → session → application

Narrowest to widest. The **first** match wins, and the search stops there.

```java
// what EL does for ${scopeDemo} on TaskFlow's debug page (34.16):
getServletContext().setAttribute("scopeDemo", "application");  // ElDebugServlet.init()
request.setAttribute("scopeDemo", "request");                   // ElDebugServlet.doGet()
```

```text
${applicationScope.scopeDemo}  → application
${scopeDemo}                   → request      (request is searched before application)
```

That's **shadowing**: a narrower attribute hides a wider one with the same name. It's often what you want (a per-request override), and sometimes a nasty bug (34.06, 34.24).

## 3. Not found → `null` → *nothing*

```jsp
<p>Hello ${usre.name}</p>      <%-- typo --%>
```

Output: `<p>Hello </p>`. No exception, no log line. In template text, `null` is printed as the **empty string**. Compare S33:

| | Scriptlet `<%= x %>` | EL `${x}` |
|---|---|---|
| `x` is `null` | prints `null` | prints nothing |
| misspelled name | compile error (a local variable) | prints nothing |

It's friendly for optional values, and it hides typos. The "prints nothing" checklist is in 34.22.

## 4. The session is skipped in `session="false"` pages

TaskFlow's views declare `session="false"` (33.10). Then `findAttribute` simply **skips** the session step. But **explicitly** asking for `${sessionScope.x}` in such a page throws an exception. That's a real one from this section: 34.25.

## 📇 API card: `PageContext.findAttribute(String name)`

| | |
|---|---|
| Signature | `Object findAttribute(String name)` |
| Searches | page → request → session (if valid and present) → application |
| Returns | the first non-null value, or `null` |
| Related | `getAttribute(name)` (page scope only), `getAttribute(name, scope)` with `PageContext.PAGE_SCOPE`, `REQUEST_SCOPE`, `SESSION_SCOPE`, `APPLICATION_SCOPE`; `setAttribute(name, value[, scope])` |

EL calls it for you. In Java code (tags, S39) you'd call it directly.

**When to rely on the search:** short, unambiguous names in your own pages (`${tasks}`, `${details}`).
**When not to:** names that exist in several scopes (`user`, `locale`, `message`). Say the scope explicitly (34.05).

## ✅ Recap

`${name}` → implicit object? → first attribute in page, request, session, application → imported class? → `null`, printed as nothing.
