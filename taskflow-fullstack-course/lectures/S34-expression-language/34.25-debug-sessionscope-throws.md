# Lecture 34.25 · 🐞 Debug: `${sessionScope.user}` Throws in a `session="false"` Page (a Real One from This Course)

> **Section:** S34 · **Type:** 🐞 Debug · **Track:** ★ Core · **Time:** ~15 minutes
> This happened while building 34.16's debug page. `S34ElTest` caught it; the page now uses `${empty pageContext.session}`.

---

## 1. Symptom

The first version of `debug/el.jsp` had a row:

```jsp
<tr><td><code>\${empty sessionScope.user}</code></td><td>${empty sessionScope.user}</td></tr>
```

The expectation was "`true`: nobody is logged in yet". The test got a **500**:

```text
org.apache.jasper.JasperException: An exception occurred processing [/WEB-INF/views/debug/el.jsp] at line [26]
…
Root Cause: java.lang.IllegalStateException: Cannot access session scope in page that does not participate in any session
```

## 2. Investigate

- Line 26 is the `sessionScope` row. Every other row, including `${scopeDemo}`, which **searches** the session, worked.
- The page directive: `session="false"` (33.10: TaskFlow's views don't create sessions).

## 3. Cause

A page with `session="false"` has no `session` variable, and its `PageContext` has no session (33.06). Two different code paths react differently:

| Expression | What Tomcat does without a session |
|---|---|
| `${user}` (implicit search, 34.03) | `findAttribute` **skips** the session scope silently |
| `${sessionScope.user}` (explicit) | the `sessionScope` map is backed by `pageContext.getSession()` → **throws** `IllegalStateException` |
| `${pageContext.session}` | `getSession()` → `null` → `${empty pageContext.session}` is `true` |

The explicit form is treated as a programming error: "you asked for the session in a page that declared it doesn't use one".

## 4. Fix

- For the debug page: show `${empty pageContext.session}`. That's what the row was really asking ("is there a session?"), and it doesn't create one (the test also checks: no `Set-Cookie`).
- For S38's layout, which needs `${sessionScope.currentUser}`: pages that show the logged-in user must **participate** in the session, with `session="true"` (the default). Such a page creates a session for **every** visitor, anonymous ones included (33.10). S38 weighs that trade-off and makes TaskFlow's choice.

## ✅ Takeaways

- `session="false"` + `sessionScope` = `IllegalStateException`, not "empty".
- A value that's fine one way (`${user}`) can throw another way (`${sessionScope.user}`). Implicit and explicit lookups use different code paths.
- Test every page by **rendering** it: this bug was invisible until a request hit line 26.
