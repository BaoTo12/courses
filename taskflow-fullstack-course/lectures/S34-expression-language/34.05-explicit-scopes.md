# Lecture 34.05 · Explicit Scopes: `${requestScope.user}` vs `${user}`

> **Section:** S34 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~15 minutes
> Verified: `S34ElTest.theElDebugPageShowsImplicitObjectsAndCoercions` (`${applicationScope.scopeDemo}` → `application` while `${scopeDemo}` → `request`)

---

## 1. Four maps

| Implicit object | Type | Backed by |
|---|---|---|
| `pageScope` | `Map<String, Object>` | `pageContext.getAttribute(name)` |
| `requestScope` | `Map<String, Object>` | `request.getAttribute(name)` |
| `sessionScope` | `Map<String, Object>` | `session.getAttribute(name)` (⚠ throws in `session="false"` pages: 34.25) |
| `applicationScope` | `Map<String, Object>` | `servletContext.getAttribute(name)` |

```jsp
${requestScope.tasks}           <%-- only the request; never a session "tasks" --%>
${sessionScope.user.displayName}
${applicationScope.appVersion}
```

They're **maps of attributes**, not the scope objects. `${requestScope.contextPath}` is an *attribute* named `contextPath`, not `request.getContextPath()`. For the request object itself, use `${pageContext.request.contextPath}` (34.14).

## 2. `${user}` vs `${sessionScope.user}`

| Situation | `${user}` | `${sessionScope.user}` |
|---|---|---|
| only the session has `user` | the session user | the session user |
| a request attribute `user` exists too (e.g. "the user being edited") | **the request one** | the session user |
| nobody has `user` | nothing | nothing |

## 3. When to be explicit (a style-guide answer)

Be explicit when:
- the name is **generic** and could live in several scopes: `user`, `locale`, `message`, `error`;
- the value **must** come from one place for correctness or security: "the logged-in user" is `sessionScope`, never "whatever is called `user`" (34.06);
- the page is shared (layouts, headers) and included by pages you don't control.

Don't bother for page-specific model attributes set by that page's own controller (`${tasks}`, `${details}`): the explicit form adds noise.

A good team convention: **the session user has a name nothing else uses** (`currentUser`), and the layout reads it as `${sessionScope.currentUser}`. TaskFlow uses exactly that from S38.

## ✅ Recap

`xxxScope.name` looks in one scope only. Use it for generic names and anything security-relevant. Plain `${name}` searches all four, narrowest first.
