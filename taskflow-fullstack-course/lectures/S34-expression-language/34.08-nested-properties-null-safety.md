# Lecture 34.08 · Nested Properties and Null-Safety: `${details.category.name}`

> **Section:** S34 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~15 minutes
> Verified: `S34ElTest.theDetailsPageShowsNestedPropertiesAndIsNullSafe` (task 4 has no category and no due date)

---

## 1. A chain is evaluated left to right

```text
${details.category.name}
   details                → TaskDetails            (request attribute)
   details.category       → getCategory()          → Category | null
   details.category.name  → getName()              → "Work"
```

If any step gives `null`, **the whole expression is `null`**: EL doesn't call `getName()` on `null`. No `NullPointerException`, and the page prints nothing.

The Java equivalent needs a check at every step:

```java
String name = details == null || details.getCategory() == null ? null : details.getCategory().getName();
```

## 2. Nothing is not always what you want

For task 4 ("Review PR #42", no category):

```jsp
<dd>${details.category.name}</dd>                                      → <dd></dd>          (blank: looks broken)
<dd>${empty details.category ? 'No category' : Html.escape(details.category.name)}</dd>   → <dd>No category</dd>
```

The null-safety prevents crashes. **You** still decide what a missing value looks like. `empty` (34.12) is the tool.

## 3. What is *not* null-safe

| Expression | When `x` is null | Result |
|---|---|---|
| `${x.a.b}` | property access | `null` → nothing ✅ |
| `${x.size()}` | a **method call** on null | `null` too (EL checks the base) |
| `${Html.escape(x.a)}` | argument is null | the method is **called** with `null`. `Html.escape` returns `""`; your own methods must cope |
| `${x.a + 1}` | arithmetic | `null` is coerced to `0` → `1` (34.13) |
| `${x.a == 'DONE'}` | comparison | `false` |

## 4. Design note: shape the model for the view

`TaskDetails` exists so the page can say `${details.owner.displayName}` instead of looking up user 1 itself. The controller **assembles** what the view needs (a view model). The view only walks it. S36 fills the same class from a database join.

## ✅ Recap

A `null` anywhere in a property chain ends it quietly. Use `empty` to show a real fallback, and remember that methods receiving `null` arguments aren't protected.
