# Lecture 34.02 · `${…}` Syntax, Where EL Is Evaluated, `#{}` and `isELIgnored`

> **Section:** S34 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~20 minutes
> Verified: `S34ElTest.theElDebugPageShowsImplicitObjectsAndCoercions` (`\${param.q}` prints a literal `${param.q}`)

## 1. The anatomy

```text
${ details . task . title }
   └─┬───┘   └┬─┘   └─┬─┘
 identifier  property property      → getDetails? no: findAttribute("details"), then getTask(), then getTitle()

${ stats['IN_PROGRESS'] }           → a map lookup (34.10)
${ empty tasks ? 'none' : 'some' }  → operators (34.11)
${ Html.escape(details.task.title) } → a static method of an imported class (EL 3.0, 34.17)
```

Literals: strings in **single or double** quotes (`'DONE'`, `"DONE"`), integers (`42` → `Long`), decimals (`2.5` → `Double`), `true`/`false`, `null`.

## 2. Where `${…}` is evaluated

| Place | Example | Evaluated? |
|---|---|---|
| template text | `<h1>${task.title}</h1>` | ✅ |
| inside an HTML attribute (it's template text to JSP) | `<a href="${ctx}/tasks">` | ✅ |
| a tag's attribute that accepts expressions | `<c:out value="${task.title}"/>` (S35) | ✅ |
| a JSP comment `<%-- ${x} --%>` | | ❌ (removed at translation) |
| an HTML comment `<!-- ${x} -->` | | ✅, and **sent to the browser** |
| inside a scriptlet `<% String s = "${x}"; %>` | | ❌: it's just a Java string |

JSP doesn't know HTML. For Jasper, `<a href="` is text like any other, which is why EL works inside attributes, and why **you** must choose the right escaping for that context (34.19).

## 3. Printing a literal `${`

```jsp
<code>\${param.q}</code>     → <code>${param.q}</code>
```

The backslash escapes the EL. TaskFlow's debug page (34.16) shows each expression next to its value this way.

## 4. `${}` vs `#{}`

| | `${expr}` | `#{expr}` |
|---|---|---|
| Name | immediate evaluation | deferred evaluation |
| When | while the page renders | later, by the framework that owns the tag |
| Used by | JSP, JSTL | **JSF** (`<h:inputText value="#{bean.name}"/>`) |
| In JSP template text | ✅ | ❌ translation error ("#{...} is not allowed in template text"), unless `deferredSyntaxAllowedAsLiteral="true"` |

In a JSP/Servlet application you only use `${}`. If you see `#{}`, you're reading JSF.

## 5. `isELIgnored`

```jsp
<%@ page isELIgnored="true" %>      <%-- ${x} is printed literally --%>
```

The default is `false` for any `web.xml` of version 2.4 or later (ours is 4.0). You'd only meet `true` in very old applications, where `${` appeared in text before EL existed. Symptom of an accidentally ignored EL: the browser shows `${task.title}` literally. Check the page directive, `<el-ignored>` in `jsp-config`, and the `web.xml` version.

## ✅ Recap

`${…}` is evaluated in template text and tag attributes, at request time. `\${` prints it literally. `#{}` is JSF. `isELIgnored` is a legacy switch.
