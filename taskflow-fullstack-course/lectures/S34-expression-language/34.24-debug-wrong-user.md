# Lecture 34.24 · 🐞 Debug: `${user.name}` Shows the Wrong User

> **Section:** S34 · **Type:** 🐞 Debug · **Track:** ★ Core · **Time:** ~15 minutes

---

## 1. Symptom

A support ticket: "On the *Task owner* page, the header says I'm logged in as Bob. On every other page it says Alice. I *am* Alice."

## 2. Investigate

1. Which pages? Only `/tasks/owner?id=…`. So it's something **that page's controller** does differently.
2. The header reads `${user.displayName}`: **no explicit scope**.
3. The owner controller:

   ```java
   request.setAttribute("user", directory.findUser(task.getOwnerId()).orElseThrow());   // the task's owner, Bob
   ```

4. `${user}` → page? no → **request? yes (Bob)** → the session is never reached (34.03).

## 3. Cause

Scope shadowing: two different meanings ("the logged-in user", "the user this page is about") share one name, and the narrower scope wins. It's the same mechanism as the 34.06 lab, found here through a bug report instead of an attack.

## 4. Fix

- The owner page: `request.setAttribute("owner", …)` and `${owner.displayName}`.
- The header: `${sessionScope.currentUser.displayName}`, with an explicit scope and a unique name (34.05). TaskFlow's S38 login uses exactly that.
- A regression test: render the owner page with a session user, and assert the header shows the **session** user.

## ✅ Takeaway

When a value is right on most pages and wrong on one, look for an attribute with the same name in a **narrower** scope on that one page.
