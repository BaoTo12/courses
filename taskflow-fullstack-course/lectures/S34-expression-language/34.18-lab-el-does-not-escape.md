# Lecture 34.18 · 🔓 Lab: EL Does NOT Escape: `${param.q}` in a Search Box → XSS

> **Section:** S34 · **Type:** 🔓 Attack Lab · **Track:** ★ Core · **Time:** ~25 minutes
> ⚠️ Local only, in a lab branch. The fixed version is TaskFlow's real search box (34.19), checked by `S34ElTest.theSearchBoxEchoesTheQueryEscapedAndFilters`.

---

## 1. The "feature"

A search box on the task list that keeps what you typed. With EL, it looks harmless:

```jsp
<form method="get" action="${pageContext.request.contextPath}/tasks">
  <input type="search" name="q" value="${param.q}">
  <button type="submit">Search</button>
</form>
<p>Results for: ${param.q}</p>
```

## 2. The exploit

1. Search for `report`. The box keeps "report". Fine.
2. Now open this URL (your local TaskFlow):

   ```text
   http://localhost:8080/taskflow/tasks?q=%22%3E%3Cscript%3Ealert(document.domain)%3C%2Fscript%3E
   ```

   `q` decodes to `"><script>alert(document.domain)</script>`.
3. View Source:

   ```html
   <input type="search" name="q" value=""><script>alert(document.domain)</script>">
   <p>Results for: "><script>alert(document.domain)</script></p>
   ```

   The `"` closes the attribute, `>` closes the tag, and the script runs **twice**, on your origin.

4. The attack is a **link**. Send it to a logged-in admin (a comment, an email, a chat message): it runs as them. From S38 on, that means reading the page's CSRF token and performing actions in their name. It's reflected XSS (30.19), rebuilt with shinier syntax.

## 3. Why it works

`${param.q}` evaluates to the raw `String`, and the generated servlet writes it with `out.write(…)` (34.04). Nothing in between knows it's HTML. It's **exactly** `<%= request.getParameter("q") %>`. EL made reading values easier and did nothing for safety.

(Contrast: React escapes `{q}` by default, 26.02. JSP's safe default arrives with `<c:out>` in S35. In plain EL there's no default.)

## 4. Other ways in, same bug

| Source | Example |
|---|---|
| `${header['Referer']}` | a page that says "you came from …" |
| `${cookie.theme.value}` inside `class="…"` | cookies can be set by a sibling subdomain or by another XSS |
| `${task.title}` (stored!) | S31's malicious seed title `<img src=x onerror=…>` would now fire on **every** list view: stored XSS (S35's lab) |

## 5. Fix

34.19: escape for the output context. Every `${…}` that prints text that anyone else can influence goes through an escaper.

## Lesson

EL doesn't escape. Every `${…}` printing user-influenced text is a potential XSS until proven otherwise.
