# Lecture 34.23 · 🐞 Debug: `${task.done}` → `PropertyNotFoundException`

> **Section:** S34 · **Type:** 🐞 Debug · **Track:** ★ Core · **Time:** ~15 minutes

---

## 1. The code

A teammate "cleaned up" `Task`:

```java
public boolean getIsDone() { return status == TaskStatus.DONE; }   // was: isDone()
```

## 2. The error

```text
HTTP 500
org.apache.jasper.JasperException: An exception occurred processing [/WEB-INF/views/tasks/list.jsp] at line [45]
…
Root Cause: javax.el.PropertyNotFoundException: Property [done] not found on type [com.taskflow.model.Task]
```

Unlike a missing **attribute** (34.22), a missing **property** on an existing object is an exception. EL knows the object, and it knows there's no such getter.

## 3. Why

JavaBeans naming (34.07): the property name comes from the **method** name, not the field:

| Method | Property | EL |
|---|---|---|
| `boolean isDone()` | `done` | `${task.done}` ✅ |
| `boolean getIsDone()` | `isDone` | `${task.isDone}` works; `${task.done}` ❌ |
| `Boolean isDone()` (wrapper) | none (`is` is only for primitive `boolean`) | ❌ both |
| `boolean isOverdue(LocalDate)` | none (it has a parameter) | `${task.isOverdue(today)}` as a method |

## 4. Find and fix

1. Read the message: property **`[done]`** on type **`[…Task]`** tells you both halves.
2. Open the class. Look for `getDone()` or `isDone()` exactly: public, no arguments, returning `boolean`.
3. Fix the **method name** (`isDone()`), not the view. Other views and JSON serialisation (Jackson uses the same bean rules, S46) depend on it too.

## ✅ Takeaway

EL reads properties by **getter name**. `getIsX()` creates a property called `isX`. For booleans, use `boolean isX()`. The page's tests (`TomcatTest`) turn this runtime error into a build failure.
