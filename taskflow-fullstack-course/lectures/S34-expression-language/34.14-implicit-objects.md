## 📇 API card: the 11 implicit objects

| Object | Type | Gives you | Example |
|---|---|---|---|
| `pageContext` | `PageContext` (**the only non-map**) | the request, response, session, servlet context… as beans | `${pageContext.request.contextPath}` |
| `pageScope` | `Map<String, Object>` | page attributes | `${pageScope.task}` (inside S34's loop) |
| `requestScope` | `Map<String, Object>` | request attributes | `${requestScope.tasks}` |
| `sessionScope` | `Map<String, Object>` | session attributes | `${sessionScope.currentUser}` (S38) · ⚠ 34.25 |
| `applicationScope` | `Map<String, Object>` | `ServletContext` attributes | `${applicationScope.scopeDemo}` |
| `param` | `Map<String, String>` | the **first** value of each parameter | `${param.q}` |
| `paramValues` | `Map<String, String[]>` | all values | `${paramValues.tag[1]}` |
| `header` | `Map<String, String>` | the first value of each header | `${header['User-Agent']}` |
| `headerValues` | `Map<String, String[]>` | all values | `${headerValues['Accept-Language'][0]}` |
| `cookie` | `Map<String, javax.servlet.http.Cookie>` | a **`Cookie` object** per name | `${cookie.tf_lang.value}` |
| `initParam` | `Map<String, String>` | context params (`<context-param>` in `web.xml`) | `${initParam.greeting}` |

## 1. Compared with the JSP implicit objects (33.06)

| Scriptlet object | EL equivalent |
|---|---|
| `request` | `${pageContext.request}` (not `${request}`: that's an *attribute* named `request`) |
| `session` | `${pageContext.session}` |
| `application` | `${pageContext.servletContext}` |
| `request.getParameter("q")` | `${param.q}` |
| `request.getHeader("Accept")` | `${header.Accept}` |
| `config.getInitParameter("x")` | none: servlet init params aren't exposed (context params are: `initParam`) |

## 2. Details that matter

- **`param` vs `paramValues`:** `?tag=a&tag=b` → `${param.tag}` is `a`, and `${paramValues.tag[1]}` is `b`.
- **`cookie.x` is a `Cookie`**, not the value: `${cookie.tf_lang}` prints something like `javax.servlet.http.Cookie@1a2b3c`. You want `.value`. Only the cookies the browser **sent**: `HttpOnly` ones included (this is the server), expired ones not.
- **Header names** are case-insensitive (it's `request.getHeader`). Dashes need brackets: `${header['user-agent']}`.
- **Implicit names win.** An attribute named `param` or `header` can never be read as `${param}`: the implicit object is checked first (34.04). Don't name attributes after them.

## 3. Everything here is attacker-controlled

`param`, `paramValues`, `header`, `headerValues` and `cookie` come **from the request**. Anyone can send any value. Every one of them printed into HTML needs escaping (34.18), and none of them should drive a security decision in a view.

## ✅ Recap

Four scope maps, `param`/`paramValues`, `header`/`headerValues`, `cookie` (values are `Cookie` objects), `initParam`, and `pageContext` for everything else.
