<details>
<summary><b>Answers</b></summary>

1. It makes the reducer **non-deterministic**: replaying the same actions (DevTools time travel, tests) gives different results, and tests can't assert exact state. Create the timestamp in the **action creator** (`allCompleted(updatedAt = new Date().toISOString())`) or the thunk, or use the **server's** timestamp, and put it in the payload.

2. **State:** the task list, the loading status, the selected task ids. **Not state:** the DONE count and the filtered list (derived: selectors), and a `Date` object (not serialisable: store an ISO string, if you need the value at all).

3. A Redux slice reducer receives **every** action: Redux's init action, `combineReducers`' probe action, and other slices' actions. `assertNever` throws on all of them, and the store can't even be created (verified). TaskFlow's `useReducer` received only its own closed union, so exhaustiveness checking was safe there.

4. The **same root object** (verified: identical reference). Subscribers and `useSelector` compare references. A new root after every action would make every subscriber re-check, and anything comparing the root would think something changed.

5. Two. `state.items.sort(…)` sorts the **old** array in place (it returns the same array): use `toSorted`. The `map` callback **assigns** `t.title` on the existing object: a new array, but a mutated item shared with the old state. Use `t.id === id ? { ...t, title } : t`.

6. `Prefs | undefined`: TypeScript infers it, and nothing forces `Prefs` (verified: an inferred reducer accepted `undefined`). There's no default parameter and no fallback return, so it returns `undefined` for the init action. `combineReducers` throws *"The slice reducer for key … returned undefined during initialization…"*. With `: Prefs` as the return type, TypeScript reports TS2366 *"Function lacks ending return statement…"*.

7. Check for **mutation** in the `taskUpdated` case: DevTools showing no diff is the signature (the previous state was modified too). **Deep-freezing the reducer's input** in the test would have thrown *"Cannot assign to read only property…"* and failed the test. Also assert identity: the updated task must be a **new** object (`not.toBe(old)`), and untouched tasks the same (`toBe`).

8. A slice reducer's `default` branch calls `assertNever` (or throws), and Redux's init action reaches it. Fix: `default: return state`.

9. **One `taskUpdated` with the whole task:** simple, it matches the API (PUT/PATCH returns the task), and there are few action types. But the DevTools log says less about **why**, and slices that care only about, say, moves must inspect the payload. **Specific events:** a meaningful log, precise reactions (a "moved" event could trigger an analytics event), but more types and creators. Many teams use a mix: specific events for meaningful user actions, and `taskUpdated` for "the server sent a new version". With RTK Query (S22), server updates mostly bypass reducers anyway.

10. Other slices (like `ui`) don't have the tasks, and a reducer can only see its own slice. The event must carry everything every interested slice needs.

11. Until Alice's own data arrives, she could see **Bob's** data from the slice that wasn't reset (tasks, selection, preferences…). The SPA doesn't reload on logout, so the store stays in memory. Protection: every user-data slice resets on `auth/loggedOut`; the server never returns another user's data (owner checks, 13.02/S44); in S23, the RTK Query cache is also reset.

12. Verified (the test passes on frozen state, and `tsc` is clean):
    ```ts
    const MAX_TOASTS = 3;

    case 'ui/toastShown':
      return { ...state, toasts: [...state.toasts, action.payload].slice(-MAX_TOASTS) };
    ```
    ```ts
    it('keeps the newest 3 toasts', () => {
      let state: UiState = deepFreeze({ toasts: [], selectedTaskIds: [] });
      for (let id = 1; id <= 5; id++) {
        state = deepFreeze(uiReducer(state, { type: 'ui/toastShown', payload: { id, tone: 'info', message: `#${id}` } }));
      }
      expect(state.toasts.map((t) => t.id)).toEqual([3, 4, 5]);
    });
    ```
    `slice(-3)` returns a new array with the last three elements; nothing is mutated.
