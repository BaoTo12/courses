# Lecture 15.05 · Immutable Update Patterns: Add, Update by Id, Remove, Nested, Toggle

> **Section:** S15 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~35 minutes
> 🔗 Official companion reading: the Redux docs page "Immutable Update Patterns"
> Every pattern below was run against a **deep-frozen** state in Node 24 (so any mutation would have thrown), and the original state was checked to be unchanged afterwards.

---

## 1. The starting state

```js
const state = {
  items: [
    { id: 1, title: 'A', status: 'TODO', tags: ['x'] },
    { id: 2, title: 'B', status: 'DONE', tags: [] },
  ],
  sort: { key: 'dueDate', direction: 'asc' },
};
```

## 2. The patterns

| Goal | Pattern | Verified result |
|---|---|---|
| **Add** at the end | `{ ...state, items: [...state.items, newItem] }` | ids `[1, 2, 3]` |
| **Insert** at index 1 | `{ ...state, items: state.items.toSpliced(1, 0, newItem) }` | ids `[1, 9, 2]` |
| **Update by id** | `{ ...state, items: state.items.map((t) => (t.id === 1 ? { ...t, title: 'A2' } : t)) }` | title `'A2'`; item 2 is the **same object** as before |
| **Toggle** a field | `…map((t) => (t.id === 2 ? { ...t, status: t.status === 'DONE' ? 'TODO' : 'DONE' } : t))` | `'TODO'` |
| **Remove by id** | `{ ...state, items: state.items.filter((t) => t.id !== 1) }` | ids `[2]` |
| **Nested object** field | `{ ...state, sort: { ...state.sort, direction: 'desc' } }` | `items` keeps the same reference |
| **Array inside an item** | `…map((t) => (t.id === 1 ? { ...t, tags: [...t.tags, 'y'] } : t))` | tags `['x', 'y']` |
| **Sorted copy** | `{ ...state, items: state.items.toSorted((a, b) => b.id - a.id) }` | ids `[2, 1]` |
| **Replace at index** | `state.items.with(0, { ...state.items[0], title: 'W' })` | titles `['W', 'B']` |
| **Remove a key** from a record | `const { [id]: _removed, ...rest } = record;` | `{ 2: 'b' }` |

`toSpliced`, `toSorted`, `toReversed` and `with` are **ES2023** copy-returning versions of `splice`, `sort`, `reverse` and index assignment. TaskFlow's `tsconfig.app.json` has `"target": "es2023"` and `"lib": ["ES2023", …]` (the Vite template's settings), so they're available and typed.

## 3. The shape of every pattern

Copy **every level on the path** to the change, and **reuse** everything else:

```text
state            → new object   ({ ...state })
└── items        → new array    (map)
    ├── item 1   → new object   ({ ...t, title })   ← the change
    └── item 2   → SAME object                       ← untouched: React can skip re-rendering it
sort             → SAME object
```

Missing a level is the classic bug:

```js
// ❌ a new state object, but item 1 is MUTATED (shared with the old state)
const bad = { ...state, items: state.items.map((t) => { if (t.id === 1) t.title = 'A2'; return t; }) };
```

`map` returned a new array, which *looks* immutable, but the object inside was changed in place. On frozen state it throws *"Cannot assign to read only property 'title' of object '#<Object>'"* (verified). That's why reducer tests freeze their input (15.11).

## 4. Watch out for these mutating methods

`push`, `pop`, `shift`, `unshift`, `splice`, `sort`, `reverse`, `fill`, `copyWithin`, and any assignment (`obj.x = …`, `arr[i] = …`, `delete obj.x`).

`sort` is the sneakiest, because it *returns* the array, so it looks like a copy: `{ ...state, items: state.items.sort(byTitle) }` sorts the **old** array in place (15.14).

## 5. When the patterns get heavy

Three levels of spread for one field is hard to read. Options:
- **Normalise** the state (S19): `entities[id]` replaces the `map` over the array.
- **Redux Toolkit's Immer** (S20) lets you write `state.items.find((t) => t.id === 1).title = 'A2'` inside a slice reducer, and produces the same immutable result.

Learn the manual patterns anyway: Immer is built on them, and you'll debug code that uses them.

## 6. Summary

- Copy along the path to the change, reuse the rest: that preserves identity for unchanged data.
- Use the non-mutating array methods (`map`, `filter`, spread, `toSorted`, `toSpliced`, `with`).
- The most common bug is a mutated **inner** object inside a new outer array.
