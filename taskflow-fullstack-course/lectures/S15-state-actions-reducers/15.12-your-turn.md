# Lecture 15.12 · 🎯 Your Turn: `listPrefs` and `ui` Reducers, Two New Task Events, and Tests

> **Section:** S15 · **Type:** 🎯 Your Turn · **Track:** ★ Core · **Time:** ~2 hours

---

## 1. The task

Complete TaskFlow's S15 state (the design from 14.13):

```text
tasks      { items, status, error }                   ← extend with 2 events
listPrefs  { sort: { key, direction }, pageSize }     ← new slice
ui         { toasts, selectedTaskIds }                ← new slice
```

## 2. Requirements

### `src/features/listPrefs/listPrefsSlice.ts`

1. `PAGE_SIZES = [10, 20, 50] as const`, with `PageSize` derived from it (06.05).
2. Initial state: sort by `dueDate` ascending, page size 20.
3. Events: `listPrefs/sortChanged` (`{ key: SortKey; direction: SortDirection }`) and `listPrefs/pageSizeChanged` (`PageSize`), each with an action creator.
4. When the new value equals the current one, return the **same** state object.
5. Reset on `auth/loggedOut`.

### `src/features/ui/uiSlice.ts`

6. State: `toasts: Toast[]` (reuse the `Toast` type from `toast/toast-context.ts`) and `selectedTaskIds: number[]`.
7. Events: `ui/toastShown` (a `Toast`), `ui/toastDismissed` (id), `ui/taskSelectionToggled` (task id), `ui/selectionCleared`.
8. `toastShown(input: ToastInput)` **generates the id** (the reducer must not).
9. React to other slices' events (15.10): `tasks/taskDeleted` and `tasks/completedCleared` remove those ids from the selection (return the **same** state when nothing was selected); `auth/loggedOut` resets.

### `tasksSlice.ts`: two new events

10. `tasks/allCompleted`: the server marked every task done. Tasks that are already `DONE` keep their identity. The others get `status: 'DONE'` and an `updatedAt` that comes **from the action**. The creator's parameter defaults to `new Date().toISOString()`.
11. `tasks/completedCleared`: the server deleted the completed tasks. The payload is the **list of deleted ids**.

### Wiring and tests

12. Add `ListPrefsAction` and `UiAction` to `AppAction`, and both reducers to `combineReducers` in `rootReducer.ts`.
13. Tests (with frozen inputs) for every new event, including: the cross-slice cases; `loggedOut()` returning the whole store to its initial state (use a real `createStore(rootReducer)`); and "same reference when nothing changes".
14. Run the 15.09 comparison test (ours vs Redux's `combineReducers`).
15. `npm test`, `npx tsc -b` and `npm run lint` pass.

## 3. Hints

<details>
<summary>Hint 1: typing <code>PageSize</code></summary>

`export type PageSize = (typeof PAGE_SIZES)[number];` gives `10 | 20 | 50`. `pageSizeChanged(30)` is then a compile error.
</details>

<details>
<summary>Hint 2: a module-level counter in the action creator?</summary>

A counter in the slice module (`let nextToastId = 1`) is fine **in the action creator**: creators aren't required to be pure, reducers are. The reducer only copies the payload.
</details>

<details>
<summary>Hint 3: "same state when nothing changed" for the selection</summary>

Filter, then compare lengths: if nothing was removed, return `state`. Write it once as a helper used by both cross-slice cases.
</details>

<details>
<summary>Hint 4: testing that logout resets everything</summary>

```ts
const store = createStore(rootReducer);
const initial = store.getState();
store.dispatch(sortChanged('title', 'desc'));
// …more changes…
store.dispatch(loggedOut());
expect(store.getState()).toEqual(initial);
```
</details>

## 4. Acceptance checklist

- [ ] `pageSizeChanged(30)` and `sortChanged('createdAt', 'asc')` don't compile.
- [ ] `sortChanged` with the current values returns the same `listPrefs` object, **and** the same root state.
- [ ] Deleting a selected task removes it from the selection; deleting an unselected one returns the same `ui` object.
- [ ] `allCompleted('2026-10-01T10:00:00Z')` sets exactly that `updatedAt`, and leaves DONE tasks untouched.
- [ ] After `loggedOut()`, the store equals its initial state.
- [ ] All tests pass on frozen inputs.
