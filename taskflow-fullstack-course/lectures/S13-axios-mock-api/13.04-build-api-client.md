# Lecture 13.04 · 🛠 Build: `api/client.ts`, the One Axios Instance

> **Section:** S13 · **Type:** 🛠 Build · **Track:** ★ Core · **Time:** ~25 minutes
> **Project feature:** `src/api/client.ts` with `baseURL`, `timeout`, `withCredentials`; typed `VITE_API_BASE_URL`

---

## 1. Why an instance, not the global `axios`

`axios.get(…)` uses a global default instance. Any library, or any file, can change its defaults (`axios.defaults.headers…`), and those changes leak everywhere. `axios.create()` gives TaskFlow **its own** instance, with its own config and interceptors. If a second API ever appears (a payment provider, say), it gets its own instance with different settings.

## 2. ✍️ `src/api/client.ts` (first version)

```ts
import axios from 'axios';

/** The one Axios instance for TaskFlow's API. Nothing else in the app imports axios directly. */
export const api = axios.create({
  // '/api' goes through the Vite dev proxy (same origin). Part 3 changes only this line (or the env var).
  baseURL: import.meta.env.VITE_API_BASE_URL ?? '/api',
  timeout: 10_000,
  // Send cookies on CROSS-origin requests too (13.10). Same-origin requests send them anyway.
  withCredentials: true,
  headers: { Accept: 'application/json' },
});
```

Option by option:

- **`baseURL: '/api'`**: every call uses a path relative to it: `api.get('/tasks')` requests `/api/tasks`. A path starting with `/` is still joined onto the base URL (Axios combines them). A full URL (`http://…`) bypasses `baseURL`, which you'll use on purpose in 13.15.
- **`timeout: 10_000`**: without a timeout, a hung server leaves the UI in "Loading…" **forever**. The browser has no short default. After 10 s, Axios aborts and rejects (verified: `code: 'ECONNABORTED'`, `message: 'timeout of 300ms exceeded'` with a 300 ms test timeout, 13.08). Choose a value that's longer than your slowest normal request, but short enough that a person would give up anyway.
- **`withCredentials: true`**: tells the browser to include **cookies** on **cross-origin** requests (and to accept `Set-Cookie` from them). Same-origin requests (our proxy setup) send cookies regardless. We set it now so the client keeps working if the API ever moves to another origin. 13.10 explains the CORS rules that come with it.
- **`headers.Accept`**: asks for JSON. Our servlets will use it in Part 3 to decide the response format.

`10_000` is a numeric separator (ES2021): it's just `10000`, easier to read.

## 3. ✍️ Typing `import.meta.env` (`src/vite-env.d.ts`)

`import.meta.env.VITE_API_BASE_URL` is a Vite **environment variable** (13.11). TypeScript doesn't know it exists. Tell it, using declaration merging on Vite's `ImportMetaEnv` interface (06.10):

```ts
// Declaration merging (06.10): tell TypeScript which VITE_* variables exist.
// Everything in import.meta.env is compiled INTO the bundle: never put secrets here (13.11).
interface ImportMetaEnv {
  /** Optional override of the API base URL. Default: '/api' (through the Vite proxy). */
  readonly VITE_API_BASE_URL?: string;
}
```

Optional (`?:`) because we don't require it, hence `?? '/api'` in the client. It's a `.d.ts` file with no imports or exports, so it's a **global** declaration that merges with the one from `vite/client` (listed in `tsconfig.app.json` → `types`).

## 4. Try it from the browser console

With the mock and the dev server running, Vite serves your source modules, so you can import them in the console:

```js
const { api } = await import('/src/api/client.ts');
const response = await api.get('/tasks', { params: { size: 2, status: 'DONE' } });
response.status;          // 200
response.data.items;      // two DONE tasks
response.config.url;      // '/tasks'
```

Look at the Network tab: `GET /api/tasks?size=2&status=DONE`. Axios built the query string from `params`.

(This console trick works only in the dev server. It's a debugging aid, not part of the app.)

## 5. Summary

- One instance per API, created with `axios.create`; never configure the global `axios`.
- `baseURL` from an env var with a default, a `timeout` always, `withCredentials` for cookie-based auth.
- Declare your `VITE_*` variables in `vite-env.d.ts`.
