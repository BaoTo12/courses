# Lecture 13.15 · 🐞 Debug: a CORS Error When Calling `:3001` Directly Instead of Through the Proxy

> **Section:** S13 · **Type:** 🐞 Debug · **Track:** ★ Core · **Time:** ~25 minutes
> Every message below was captured in the reference app (Chrome), with the dev server and the mock running.

---

## Symptom

A teammate's `.env.local` contains:

```ini
VITE_API_BASE_URL=http://localhost:3001/api
```

("Why go through the proxy? Calling the API directly is simpler.")

Verified: the task list now says *"Cannot reach the server. Check your connection."*, and saving shows the same. Yet `curl http://localhost:3001/api/tasks` works perfectly, and the mock's terminal shows requests arriving.

The browser console shows (verified):

```text
Access to XMLHttpRequest at 'http://localhost:3001/api/tasks' from origin 'http://localhost:5173' has been
blocked by CORS policy: Response to preflight request doesn't pass access control check:
No 'Access-Control-Allow-Origin' header is present on the requested resource.
```

## Investigation checklist

1. What are the page's origin and the API's origin? Same or different? (13.10 §1)
2. Why does curl work? Who enforces CORS?
3. The mock's log shows `OPTIONS /api/tasks 404`. What is that request, and why is it sent? Hint: which headers does our `api` instance add? (13.07)
4. Why does the app show "Cannot reach the server" rather than a CORS message? (13.08 Lesson 1)

## Explanation

1. The page runs on `http://localhost:5173` and calls `http://localhost:3001`. Different port = **different origin**.
2. CORS is enforced **by the browser**, protecting the user. curl isn't a browser and has no user session to protect, so it ignores CORS.
3. Our requests carry `X-Request-Id` (a custom header), and writes send `Content-Type: application/json`. Both make the browser send a **preflight** `OPTIONS` first. The mock has no CORS support (`noCors: true`), so the preflight gets our generic 404 JSON, without any `Access-Control-Allow-*` header. The browser **never sends the real request**. Verified: a POST through this path created **no** task.
   (A plain GET *without* custom headers is a "simple" request: verified, it **reached** the server and got 200, and the browser only refused to show the response to the script.)
4. Scripts only get `ERR_NETWORK` / `'Network Error'` for CORS failures, deliberately (to prevent network probing), so our normaliser correctly says "network". The **console** has the real reason.

## Fix

**Use the proxy.** Delete the variable (or set it to `/api`). Vite 8 notices `.env` changes and restarts itself (verified: *".env.local changed, restarting server..."*); reload the page afterwards:

```ini
# VITE_API_BASE_URL is not needed in development: '/api' goes through the Vite proxy (13.02).
```

Same origin → no CORS, no preflights, cookies just work (S24).

### Why not "just enable CORS on the mock"?

You could (json-server's default does it, with `origin: true, credentials: true`, i.e. "any website, with cookies"). It would hide the problem in development and **not match production**, where TaskFlow is same-origin (S49). Development setups should resemble production. If TaskFlow ever does need cross-origin access, CORS is configured **deliberately**, with an exact allowlist, on the real backend (S47).

## Lessons

- "Network Error" + the server logging your request (or an `OPTIONS` for it) = look at CORS in the **console**.
- CORS is a browser rule. "It works in curl/Postman" proves nothing about the browser.
- A failed preflight means the real request never ran. A blocked simple request **did** run.
- Prefer same-origin setups (proxy, single deployment) over enabling CORS.

## Related traps

- Mixing `localhost` and `127.0.0.1`: they're **different origins** (and different cookie hosts).
- `Access-Control-Allow-Origin: *` doesn't work with `withCredentials: true`: the browser rejects the wildcard for credentialed requests (13.10 §3).
- Env values are replaced **at build/serve time** (13.11). Vite 8 restarts the dev server when a `.env` file changes; if a page still shows old behaviour, reload it. A production build never changes: rebuild to change a `VITE_` value.
