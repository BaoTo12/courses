# Lecture 13.03 · Why Axios over `fetch`

> **Section:** S13 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~30 minutes
> 🔗 Reference: axios-http.com/docs/intro · MDN "Using the Fetch API"

---

## 1. `fetch` is good. Why add a library?

`fetch` is built into every browser, and you've used it since 08.04. It's a low-level primitive. For an **application** with dozens of API calls, you end up writing the same wrapper around it every time. Axios is that wrapper, standardised. It's one of the most common HTTP libraries in React codebases, so you'll likely meet it at work.

Verified side by side against the mock (`GET /api/tasks/999`, which returns 404):

```ts
// fetch: a 404 RESOLVES. You must check response.ok yourself.
const response = await fetch('/api/tasks/999');
response.ok;      // false
response.status;  // 404, and no exception was thrown

// axios: a 404 REJECTS with an AxiosError.
await axios.get('/api/tasks/999');
// ✗ AxiosError { code: 'ERR_BAD_REQUEST', message: 'Request failed with status code 404', response: { status: 404, … } }
```

## 2. The comparison

| Need | `fetch` | Axios |
|---|---|---|
| Non-2xx = error | ❌ You check `response.ok` | ✅ Rejects (configurable with `validateStatus`) |
| JSON request body | `body: JSON.stringify(x)` + `Content-Type` header by hand | ✅ Pass an object |
| JSON response | `await response.json()` (a second await) | ✅ `response.data`, already parsed |
| Query params | Build `URLSearchParams` yourself | ✅ `params: { status: 'DONE' }`, and `undefined` values are skipped |
| Base URL, default headers, timeout | Repeat at every call, or write a wrapper | ✅ `axios.create({ baseURL, headers, timeout })` |
| Timeout | `AbortSignal.timeout(ms)` (modern browsers) | ✅ `timeout: 10_000` |
| Cancellation | `AbortController` | ✅ The same `AbortController` (`signal`) |
| **Interceptors** (code that runs on every request/response) | ❌ Wrap `fetch` yourself | ✅ `interceptors.request/response` |
| Upload progress | ❌ (no progress events for request bodies) | ✅ `onUploadProgress` (XHR-based in browsers) |
| Bundle size | 0 kB | Verified in TaskFlow: +53 kB raw, **+19 kB gzip** |

Interceptors are the big one. They give you **one place** for cross-cutting concerns: auth headers, CSRF tokens (S24), request ids, logging, error normalisation (13.07), redirect-to-login on 401 (S24). With `fetch`, every call site must remember them, or you build your own mini-Axios.

## 3. What Axios does NOT change

- It's still HTTP from the browser. **CORS, cookies and the same-origin policy work exactly the same** (13.10).
- It uses `XMLHttpRequest` in browsers by default (there's also a `fetch` adapter). You'll see **XHR** as the request type in DevTools; the "Fetch/XHR" filter shows both.
- Validation is still your job. `response.data` is typed `any` by default. We'll type it as `unknown` and validate (13.05).

## 4. The rule for TaskFlow

> **Components never import `axios`.** Only the `src/api/` layer does.

```text
components / pages / hooks (S17+: thunks)
        │  call typed functions: getTasks(), createTask()…
        ▼
src/api/tasks.ts ─── src/api/client.ts (the one Axios instance + interceptors)
        │
        ▼
      HTTP
```

Benefits:
- **Swap the transport** without touching the UI: another library, RTK Query (S22), or `fetch`.
- **Change the backend** with one config line (Part 3).
- **One error type** for the whole app (13.07), instead of every component parsing `AxiosError`.
- Easy to **mock in tests**: fake `api/tasks.ts`, not the network.

## 5. Install

Stop the dev server first (09.03's lesson about installing while Vite runs), then:

```bash
npm install axios
```

At the time of writing this installs **Axios 1.20**. It ships its own TypeScript types (no `@types/axios`).

## 6. Summary

- `fetch` resolves on 404/500; Axios rejects on any non-2xx. That single difference prevents a whole class of "the save failed silently" bugs.
- Axios adds instances, base URL, JSON handling, params, timeouts and **interceptors**. It costs about 19 kB gzip.
- Only `src/api/` touches Axios.
