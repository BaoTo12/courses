# Lecture 13.07 · 🛠 Build: a Request-ID + Timing Interceptor, and One Normalised `ApiRequestError`

> **Section:** S13 · **Type:** 🛠 Build · **Track:** ★ Core · **Time:** ~55 minutes
> **Project feature:** every request carries `X-Request-Id`; dev-only timing logs; every failure becomes an `ApiRequestError`

---

## 1. The goal

After this lecture, code outside `src/api/` can rely on one promise:

> Every API function either **resolves with validated data**, or **rejects with an `ApiRequestError`** that says *what kind* of failure it was, with a message fit for a user.

No component will ever see an `AxiosError`, a `TypeError` from a bad response shape, or a raw status code it must interpret.

## 2. ✍️ `src/api/api-error.ts` (replace the temporary version from 13.05)

```ts
import axios from 'axios';
import { isApiError } from '../domain/guards';

/** What went wrong, from the UI's point of view (13.08). */
export type ApiErrorKind =
  | 'http' // the server answered with a non-2xx status
  | 'timeout' // no answer within the client's timeout
  | 'network' // no answer at all: server down, DNS, CORS, offline
  | 'cancelled' // we aborted it ourselves (AbortController): usually not an error to show
  | 'unexpected'; // a bug: something that isn't an HTTP failure

/**
 * The ONE error type the rest of the app sees. Components never inspect AxiosError:
 * the api/ layer hides the HTTP library (so it could be replaced without touching the UI).
 */
export class ApiRequestError extends Error {
  readonly kind: ApiErrorKind;
  /** HTTP status, or null when there was no response. */
  readonly status: number | null;
  /** Machine-readable code from the error body (e.g. 'VALIDATION_FAILED'), or the kind. */
  readonly code: string;
  readonly fieldErrors: Readonly<Record<string, string>>;

  constructor(options: {
    kind: ApiErrorKind;
    message: string;
    status?: number | null;
    code?: string;
    fieldErrors?: Record<string, string>;
    cause?: unknown;
  }) {
    super(options.message, { cause: options.cause });
    this.name = 'ApiRequestError';
    this.kind = options.kind;
    this.status = options.status ?? null;
    this.code = options.code ?? options.kind.toUpperCase();
    this.fieldErrors = options.fieldErrors ?? {};
  }
}

/** Turns anything an Axios call can throw into an ApiRequestError. */
export function toApiRequestError(error: unknown): ApiRequestError {
  if (error instanceof ApiRequestError) return error;

  if (axios.isCancel(error)) {
    return new ApiRequestError({ kind: 'cancelled', message: 'Request cancelled', cause: error });
  }

  if (axios.isAxiosError(error)) {
    if (error.code === 'ECONNABORTED' || error.code === 'ETIMEDOUT') {
      return new ApiRequestError({ kind: 'timeout', message: 'The server took too long to respond.', cause: error });
    }
    if (error.response) {
      const { status, data } = error.response;
      if (isApiError(data)) {
        // Our contract's error body (02-project-spec §5): use the server's message and field errors.
        const fields = Object.entries(data.fieldErrors ?? {});
        const details = fields.map(([field, problem]) => `${field} ${problem}`).join('; ');
        return new ApiRequestError({
          kind: 'http',
          status,
          code: data.error,
          message: details ? `${data.message}: ${details}` : data.message,
          fieldErrors: data.fieldErrors,
          cause: error,
        });
      }
      // A non-contract body: usually a PROXY answering for a server that is down (Vite's proxy sends
      // an empty 502; Nginx an HTML page). Verified: with the mock API stopped, we get 502, not a network error.
      const message =
        status >= 500 ? `The server is unavailable (HTTP ${status}). Try again in a moment.` : `Request failed (HTTP ${status}).`;
      return new ApiRequestError({ kind: 'http', status, message, cause: error });
    }
    // A request was sent but no response arrived.
    return new ApiRequestError({ kind: 'network', message: 'Cannot reach the server. Check your connection.', cause: error });
  }

  return new ApiRequestError({
    kind: 'unexpected',
    message: error instanceof Error ? error.message : 'Unexpected error',
    cause: error,
  });
}

export function isCancelled(error: unknown): boolean {
  return error instanceof ApiRequestError && error.kind === 'cancelled';
}
```

### Why these choices

- **A class extending `Error`**, not a plain object: it has a stack trace, `instanceof` works, and the existing `toErrorMessage` (06.08) already handles any `Error`. Every toast in the app keeps working unchanged.
- **Explicit fields, no parameter properties.** `constructor(readonly kind: …)` would be shorter, but the Vite template's `erasableSyntaxOnly` flag (TS 5.8+) forbids TypeScript-only syntax that emits JavaScript. Parameter properties are one of those features, like `enum` (05.06, 07.02).
- **`cause`** (ES2022) keeps the original `AxiosError` for debugging: `console.log(error.cause)` shows the full request and response.
- **`kind` drives UI decisions** (13.08): cancelled → show nothing; network/timeout → "check your connection" + retry; `http` 4xx → the server's message; 5xx → "try again later".
- **`fieldErrors`** will map the server's validation errors onto form fields (the 13.12 stretch goal).
- **The order of checks matters.** `CanceledError` is also an `AxiosError` (verified: `isAxiosError` and `isCancel` were both true for an aborted request), so the cancel check must come first.

## 3. ✍️ The interceptors (`src/api/client.ts`, final)

```ts
import axios from 'axios';
import { toApiRequestError } from './api-error';

// Declaration merging (06.10): add our own field to Axios's request config type.
declare module 'axios' {
  interface InternalAxiosRequestConfig {
    /** Set by the timing interceptor. */
    metadata?: { startedAt: number };
  }
}

/** The one Axios instance for TaskFlow's API. Nothing else in the app imports axios directly. */
export const api = axios.create({
  // '/api' goes through the Vite dev proxy (same origin). Part 3 changes only this line (or the env var).
  baseURL: import.meta.env.VITE_API_BASE_URL ?? '/api',
  timeout: 10_000,
  // Send cookies on CROSS-origin requests too (13.10). Same-origin requests send them anyway.
  withCredentials: true,
  headers: { Accept: 'application/json' },
});

// ── Request interceptor: a correlation id + a start time ─────────────────────
api.interceptors.request.use((config) => {
  // The same id appears in the browser's Network tab and (in Part 3) in the server's logs.
  config.headers.set('X-Request-Id', crypto.randomUUID());
  config.metadata = { startedAt: performance.now() };
  return config;
});

// ── Response interceptor: timing log + ONE error type for the whole app ──────
api.interceptors.response.use(
  (response) => {
    logTiming(response.config.method, response.config.url, response.status, response.config.metadata);
    return response;
  },
  (error: unknown) => {
    const apiError = toApiRequestError(error);
    if (axios.isAxiosError(error) && apiError.kind !== 'cancelled') {
      logTiming(error.config?.method, error.config?.url, apiError.status ?? apiError.kind, error.config?.metadata);
    }
    // ALWAYS reject: returning a value here would turn the failure into a "success" (13.14).
    return Promise.reject(apiError);
  },
);

function logTiming(
  method: string | undefined,
  url: string | undefined,
  outcome: number | string,
  metadata: { startedAt: number } | undefined,
) {
  if (!import.meta.env.DEV || metadata === undefined) return;
  const ms = Math.round(performance.now() - metadata.startedAt);
  console.debug(`[api] ${method?.toUpperCase()} ${url} → ${outcome} in ${ms} ms`);
}
```

### Line by line

- **`declare module 'axios'`**: module augmentation (06.10). Axios's config type has no `metadata` field, so we add one instead of casting to `any`. Inside a module file (this one has imports), `declare module 'axios'` **merges** with Axios's own declarations.
- **`config.headers.set(…)`**: in Axios 1.x, `config.headers` is an `AxiosHeaders` object. `.set()` is the typed way to add a header.
- **`X-Request-Id`**: a **correlation id**. When a user reports "saving failed at 10:42", the id in the Network tab links to the exact server log line. In Part 3, your logging filter will read and log it (S43). `crypto.randomUUID()` is built into modern browsers (secure contexts, which includes `localhost`).
- **`performance.now()`**: a monotonic clock in milliseconds, unaffected by system clock changes. Better than `Date.now()` for durations.
- **`import.meta.env.DEV`**: `true` in the dev server, `false` in production builds, where Vite removes that branch (dead-code elimination). Verified: the production bundle contains no `[api]` string at all.
- **The response error handler always rejects**, with the normalised error. The `logTiming` for errors skips cancellations: they're intentional.

## 4. See it

Reload the app. The console shows (verified):

```text
[api] GET /tasks → 200 in 324 ms
```

In DevTools → Network → the request → Headers, you'll find `X-Request-Id: <uuid>` under the request headers.

Then try failures from the console:

```js
const { api } = await import('/src/api/client.ts');
const t = await import('/src/api/tasks.ts');
await t.getTask(23).catch((e) => [e.name, e.kind, e.status, e.code, e.message]);
// ['ApiRequestError', 'http', 404, 'NOT_FOUND', 'Task not found']        ← bob's task: 404 for alice
await t.getTasks({ status: 'HACKED' }).catch((e) => e.message);
// 'Request contains invalid fields: status must be one of TODO, IN_PROGRESS, DONE'
await api.get('/tasks', { timeout: 300, params: { _mockDelay: 1500 } }).catch((e) => e.kind);
// 'timeout'
```
