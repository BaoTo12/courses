## 1. The task

Replace the fake data layer with the API layer from 13.04–13.07. After this lecture, **every** change a user makes is saved by the mock API and survives a reload.

## 2. Requirements

### `useTasks` (`src/hooks/useTasks.ts`)

1. Load the list with `getTasks({ size: 100 }, signal)`. (100 is the API's maximum page size; real pagination arrives in S21.) Keep the `AbortController` cleanup.
2. Replace `toggle` and `editTitle` (local-only changes) and `addTask`/`replaceTask` with **async operations that call the API first, then update the reducer**:
   ```ts
   return { state, reload, create, update, patch, remove };
   // create(request: CreateTaskRequest): Promise<Task>          → POST
   // update(id, request: CreateTaskRequest): Promise<Task>      → PUT
   // patch(id, changes: UpdateTaskRequest): Promise<Task>       → PATCH
   // remove(id): Promise<void>                                  → DELETE
   ```
   Each one **throws** (an `ApiRequestError`) on failure, and the **caller** decides how to report it.
3. The reducer: remove `taskToggled` and `titleEdited` (the server now decides the new state), add `taskRemoved`. Keep the switch exhaustive (`assertNever`).

### Pages

4. **Tasks list:** "Mark done / Reopen" sends `PATCH {status}`. Inline title editing sends `PATCH {title}` (skip the request if the title is blank or unchanged). On failure, show an error toast with the error's message. Keep the "Completed: …" success toast, shown only **after** the server accepted the change.
5. **New / Edit pages:** use `create` / `update`. The toasts and `navigate(…, { replace: true })` from 12.05 stay.
6. **Details page:** add a **Delete** button, shown only to logged-in users (UX only: 12.07). Ask for confirmation (`window.confirm` is fine here), show "Deleting…" while waiting, toast the result, and navigate back to the list (keeping the filters: `backHref` from 12.11) with `replace`.
7. **Error state:** the list's "Try again" button must recover after the mock API is restarted.

### Cleanup

8. Delete `src/data/fetch-tasks.ts`, `src/data/fake-save.ts` and `public/db.json`. `npm run build`, `npm run lint` and `npm test` must pass.

## 3. Hints

<details>
<summary>Hint 1: the shape of an operation</summary>

```ts
const patch = useCallback(async (id: number, changes: UpdateTaskRequest) => {
  const saved = await patchTask(id, changes);
  dispatch({ type: 'taskUpdated', task: saved });
  return saved;
}, []);
```

Why dispatch the **server's** task rather than the changes you sent? Because the server may have changed more than you sent: trimmed the title, updated `updatedAt`… The UI should show what was saved.
</details>

<details>
<summary>Hint 2: the toggle needs the current status</summary>

The server doesn't have a "toggle" operation. `PATCH` sets a value. `TasksPage` already finds the task in `state.data`: compute `nextStatus` there and call `patch(id, { status: nextStatus })`.
</details>

<details>
<summary>Hint 3: TaskCard's prop types</summary>

`onToggle: (id: number) => void` accepts an `async` function: a function returning `Promise<void>` is assignable to one returning `void` (05.08). You don't need to change `TaskCard`, `TaskList` or `Board`.
</details>

<details>
<summary>Hint 4: testing failures</summary>

- Stop the mock (Ctrl+C) and toggle a task, or reload the list.
- Restart it and click "Try again".
- For a validation error, edit a title inline to 121+ characters (the client-side 120 limit only applies in the form).
</details>

## 4. Acceptance checklist

- [ ] Reload the page after each of these, and the change is still there: toggle, inline title edit, create, edit, delete.
- [ ] `mock-api/db.json` shows the changes.
- [ ] The Network tab shows `PATCH`, `POST` (201), `PUT` and `DELETE` (204) requests to `/api/tasks…`, each with an `X-Request-Id` header.
- [ ] While a toggle is in flight (300 ms), the button still shows the **old** label: the UI waits for the server (pessimistic update).
- [ ] With the mock stopped: the list shows *"The server is unavailable (HTTP 502). Try again in a moment."*, and a toggle shows the same message in a toast. After restarting the mock, "Try again" loads the list.
- [ ] A 121-character inline title shows *"Request contains invalid fields: title size must be at most 120"*.
- [ ] 🔍 **Watch closely when you delete a task.** Does "Page not found" flash for a moment before the list appears? If it does, find out **why** (the answer involves React Router and `startTransition`) and fix it. This is the hardest item; the solution explains it in detail.
