## E. Implementation

11. Add to `task-utils.js` (with your own tests): `removeTask` already exists. Write `moveTask(tasks, id, newStatus)` and `countByPriority(tasks)` (always returns `{ LOW, MEDIUM, HIGH }` numbers). Both immutable, unchanged tasks keep their references.

---

<details>
<summary><b>Answers</b></summary>

1. `const` prevents **reassigning** `tasks`, not **mutating** the array. Redux (and React) detect change by reference; mutating keeps the same reference, so the change goes unnoticed and history/time-travel get corrupted.

2. Reference comparison is O(1), deep comparison is O(size) and too slow to run on every render/dispatch. The contract: **changed data ⇒ new object; unchanged data ⇒ same object** (immutable updates with structural sharing).

3. A function plus the variables it captured from where it was created, kept alive as long as the function exists. Examples: hooks and stale closures (S08), middleware `store => next => action` (S16), thunks (S18), memoization caches (S21).

4. `Binh false true`: shallow copy; the inner `user` object is shared.

5. `sync`, `promise`, `timeout`: sync code, then microtasks, then tasks.

6. An array of `undefined`. The braces are a function body; use `(t) => ({ title: t.title })`.

7. (a) It mutates the task object in place; (b) `setTasks(tasks)` passes the **same array reference**, so React bails out and doesn't re-render; (c) any other holder of the old state (history, memoised selectors) is corrupted. Fix: `setTasks(tasks.map(x => x.id === id ? { ...x, status: 'DONE' } : x))`.

8. Async work started inside `forEach` (or promises not awaited/returned). Nobody waits for them. Use `await Promise.all(tasks.map(…))`.

9. `sortTasks` with `.sort()`: **impure** (mutates input). `now()`: **impure** (different result each call). `formatTitle`: **pure**. `groupByStatus`: **pure** (mutates only arrays it created).

10. For independent working copies (form drafts, undo snapshots, defensive copies). Wrong for state updates because it gives **every** nested object a new reference, which defeats structural sharing and causes unnecessary re-renders; it also loses functions/prototypes.

11. One solution:
    ```js
    export function moveTask(tasks, id, newStatus) {
      return tasks.map((t) => (t.id === id && t.status !== newStatus ? { ...t, status: newStatus } : t));
    }

    export function countByPriority(tasks) {
      const counts = { LOW: 0, MEDIUM: 0, HIGH: 0 };
      for (const t of tasks) counts[t.priority] += 1;
      return counts;
    }
    ```
    Note `t.status !== newStatus`: if nothing changes, return the **same** object, which avoids a pointless new reference.

</details>
