# Lecture 04.07 · Array Methods in Depth: `map`, `filter`, `reduce`, `find`, `some`, `every`, `toSorted`, `flatMap`

> **Section:** S04 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~30 minutes

---

## 1. Why these matter so much in React/Redux code

In React you render lists with `map`. In Redux you update arrays with `map`/`filter` and compute derived data (counts, groups, stats) in selectors with `filter`/`reduce`. Being fluent with these methods, and knowing which **return new arrays** and which **mutate**, is essential.

| Method | Returns | Mutates? | Typical use |
|---|---|---|---|
| `map(fn)` | New array, same length | No | Transform each item; render lists in JSX |
| `filter(fn)` | New array, ≤ length | No | Keep matching items; remove by id |
| `reduce(fn, init)` | Any single value | No | Sum, count, group, index by id |
| `find(fn)` / `findIndex(fn)` | First match / its index (or `undefined` / `-1`) | No | Look up one item |
| `findLast` / `findLastIndex` | Last match | No | |
| `some(fn)` / `every(fn)` | Boolean | No | "Any overdue?" / "All done?" |
| `includes(x)` | Boolean | No | Membership with `===` (and NaN-aware) |
| `flatMap(fn)` | New array, flattened one level | No | Map + flatten (tags across tasks) |
| `toSorted` / `toReversed` / `toSpliced` / `with` | New array | No | Immutable versions (ES2023) |
| `sort` / `reverse` / `splice` / `push` / `pop` / `shift` / `unshift` / `fill` | Same array (mutated) | **Yes** ⚠️ | Only on arrays you own and just created |
| `forEach(fn)` | `undefined` | No (but your fn may) | Side effects only |

## 2. `map`: transform

```js
const titles = tasks.map((t) => t.title);
const withLabels = tasks.map((t) => ({ ...t, label: `${t.priority}: ${t.title}` }));
```

⚠️ Arrow functions returning an object literal need **parentheses**: `(t) => ({ … })`. Without them, `{` is parsed as a function body, and you return `undefined`.

In JSX (S07): `{tasks.map((t) => <TaskCard key={t.id} task={t} />)}`.

## 3. `filter`: select

```js
const open = tasks.filter((t) => t.status !== 'DONE');
const overdue = tasks.filter((t) => t.dueDate !== null && t.dueDate < today);
```

The callback must return truthy/falsy. `filter(Boolean)` is a handy idiom to remove falsy values: `[a, null, b].filter(Boolean)`.

## 4. `reduce`: fold into one value

`reduce` walks the array carrying an **accumulator**:

```js
const total = [3, 5, 2].reduce((sum, n) => sum + n, 0);   // 10
```

Step by step: `sum=0` → `0+3=3` → `3+5=8` → `8+2=10`.

### Counting by status (a dashboard stat, S21)

```js
const counts = tasks.reduce(
  (acc, t) => ({ ...acc, [t.status]: (acc[t.status] ?? 0) + 1 }),
  {},
);
// { TODO: 1, IN_PROGRESS: 1, DONE: 1 }
```

This is pure, but it creates a new object on **every** iteration. For large arrays, it's fine (and common) to mutate an accumulator **you created inside the function**:

```js
const counts = tasks.reduce((acc, t) => {
  acc[t.status] = (acc[t.status] ?? 0) + 1;   // mutating our OWN new object: OK
  return acc;
}, {});
```

The function as a whole is still pure: it doesn't touch its input and returns a fresh object. *"Don't mutate what you don't own"* is the real rule.

### Indexing by id (normalisation preview, S19)

```js
const byId = tasks.reduce((acc, t) => {
  acc[t.id] = t;
  return acc;
}, {});
// or: Object.fromEntries(tasks.map((t) => [t.id, t]))
```

### Always give an initial value

`[].reduce((a, b) => a + b)` throws `TypeError: Reduce of empty array with no initial value`. With `0` as the initial value, it returns `0`.

### `Object.groupBy` (ES2024)

```js
const groups = Object.groupBy(tasks, (t) => t.status);
// { TODO: [...], IN_PROGRESS: [...], DONE: [...] }  (keys only for statuses that exist!)
```

Useful, but note: missing statuses are **absent**, not empty arrays. The 04.14 exercise requires all three keys.

## 5. `find`, `some`, `every`, `includes`

```js
const task = tasks.find((t) => t.id === id);          // the object or undefined
const anyOverdue = tasks.some((t) => isOverdue(t));   // stops at the first true
const allDone = tasks.every((t) => t.status === 'DONE'); // stops at the first false
const valid = ['LOW', 'MEDIUM', 'HIGH'].includes(priority);
```

`every` on an empty array returns `true` (vacuous truth). "All done?" with zero tasks is `true`, which may or may not be what your UI wants.

## 6. `flatMap`

```js
const allTags = tasks.flatMap((t) => t.tags);                       // [['a'],['b','c']] → ['a','b','c']
const uniqueTags = [...new Set(tasks.flatMap((t) => t.tags))];
```

## 7. Chaining and performance

```js
const visibleTitles = tasks
  .filter((t) => t.status !== 'DONE')
  .toSorted((a, b) => a.title.localeCompare(b.title))
  .map((t) => t.title);
```

Each step creates a new array. That's fine for hundreds or thousands of items. What matters for React performance is not the loop cost but that each call returns a **new array reference**, which triggers re-renders if it runs on every render. That's the problem memoised selectors solve (S21).

## 8. Summary

- `map`, `filter`, `reduce`, `find`, `some`, `every`, `flatMap`, `toSorted`… return new values; `sort`, `reverse`, `splice`, `push`… **mutate**.
- Wrap object literals in parentheses in arrow functions: `=> ({ … })`.
- `reduce` needs an initial value; mutating an accumulator you created is fine.
- `Object.groupBy` exists but omits empty groups.
- Chains are cheap in CPU; new references matter for React (memoization later).

## 9. Check yourself

1. What does `tasks.map((t) => { id: t.id })` return?
2. `[].every((x) => x > 5)`?
3. Write "number of HIGH priority open tasks" with one `reduce`, and with `filter(…).length`. Which is clearer?

<details>
<summary>Answers</summary>

1. An array of `undefined`s. The braces are a function body, `id:` is parsed as a label, and nothing is returned. Use `(t) => ({ id: t.id })`.
2. `true`.
3. `tasks.reduce((n, t) => n + (t.priority === 'HIGH' && t.status !== 'DONE' ? 1 : 0), 0)` vs `tasks.filter((t) => t.priority === 'HIGH' && t.status !== 'DONE').length`. The `filter` version is clearer; prefer clarity unless profiling says otherwise.

</details>
