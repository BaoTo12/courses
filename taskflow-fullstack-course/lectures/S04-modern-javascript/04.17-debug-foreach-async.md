# Lecture 04.17 · 🐞 Debug: `forEach` with `async` Callbacks "Finishes Too Early"

> **Section:** S04 · **Type:** 🐞 Debug · **Track:** ＋ Extended · **Time:** ~15 minutes

---

## Symptom

"Mark all done" should save each task, then show "All saved!":

```js
async function markAllDone(tasks) {
  tasks.forEach(async (task) => {
    await saveTask({ ...task, status: 'DONE' });   // each takes ~300 ms
  });
  showToast('All saved!');
}
```

The toast appears **instantly**, before any save finishes. Sometimes a save fails and there's an `Uncaught (in promise)` error in the console, but the user already saw "All saved!".

## Investigation checklist

1. What does `forEach` do with the **return value** of its callback?
2. What does an `async` function return?
3. Does anything `await` the promises created inside `forEach`?
4. Where do rejections from those promises go?

## Explanation

- An `async` callback returns a **promise**.
- `forEach` **ignores return values**. It calls the callback for each item and moves on synchronously.
- So `forEach` finishes immediately, having *started* N saves that nobody waits for. `showToast` runs right away.
- Rejections from those promises have no handler → `Uncaught (in promise)`.

**Fix: parallel (all at once), wait for all:**

```js
async function markAllDone(tasks) {
  await Promise.all(tasks.map((task) => saveTask({ ...task, status: 'DONE' })));
  showToast('All saved!');
}
```

`map` **collects** the promises; `Promise.all` waits for all of them (and rejects if any fails, so wrap in `try/catch` to show an error toast).

**Fix: sequential (one after another), when order matters or the server can't handle bursts:**

```js
for (const task of tasks) {
  await saveTask({ ...task, status: 'DONE' });
}
```

`for…of` works with `await`; `forEach` doesn't.

**If you need to know which ones failed:** `Promise.allSettled` (04.11).

## What this trained

Asking "**who is waiting for this promise?**" If the answer is "nobody", you have a timing bug and probably an unhandled rejection. You'll ask the same question about thunks that forget to `return` their promise (S18).
