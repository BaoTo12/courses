# Lecture 04.04 · Destructuring, Spread and Rest; Shallow Copies and Their Limits

> **Section:** S04 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~25 minutes

---

## 1. Destructuring: unpacking values into variables

### Objects

```js
const task = { id: 1, title: 'Write report', status: 'TODO', priority: 'HIGH' };

const { title, status } = task;                 // title = 'Write report', status = 'TODO'
const { title: taskTitle } = task;              // rename → taskTitle
const { dueDate = null } = task;                // default when the property is undefined
const { owner: { name } = {} } = task;          // nested, with a fallback so it doesn't crash
```

### Arrays (by position)

```js
const [first, second] = ['a', 'b', 'c'];       // first = 'a', second = 'b'
const [, , third] = ['a', 'b', 'c'];           // skip positions → third = 'c'
const [count, setCount] = useState(0);         // ← you'll write this in every React component (S07)
```

`useState` returns a two-element array precisely so you can destructure and name both parts however you like.

### Function parameters

```js
function filterTasks(tasks, { status, priority, q } = {}) { … }
filterTasks(tasks, { status: 'DONE' });
```

The `= {}` default means calling `filterTasks(tasks)` without options doesn't crash trying to destructure `undefined`. React components destructure props the same way: `function TaskCard({ task, onToggle }) { … }`.

## 2. Spread `...`: expand into a new array/object

```js
const a = [1, 2];
const b = [...a, 3];                 // [1, 2, 3]: a NEW array
const c = [0, ...a];                 // [0, 1, 2]

const task = { id: 1, title: 'A', status: 'TODO' };
const done = { ...task, status: 'DONE' };     // new object, status overridden
```

**Order matters** in object spread: later properties win.

```js
{ ...task, status: 'DONE' }   // status = 'DONE'
{ status: 'DONE', ...task }   // status = 'TODO' (task's status overwrites)
```

### Computed property names

```js
const field = 'title';
const updated = { ...task, [field]: 'New title' };   // { …, title: 'New title' }
```

You'll use this in the 04.14 exercise (`updateTaskField`) and in React forms (S11): one change handler for many inputs.

## 3. Rest `...`: collect the remainder

Same syntax, opposite direction: in a **destructuring** position, `...` collects "everything else".

```js
const { id, ...withoutId } = task;          // withoutId = { title: 'A', status: 'TODO' }
const [head, ...tail] = [1, 2, 3];          // head = 1, tail = [2, 3]
function log(level, ...messages) { … }      // rest parameters: any number of args
```

`const { passwordHash, ...safeUser } = user;` is a neat way to drop a sensitive field before sending data somewhere. Keep it in mind for S46 (response DTOs).

## 4. Spread makes a **shallow** copy

Spread copies **one level**. Nested objects are copied **by reference**:

```js
const task = { id: 1, title: 'A', tags: ['urgent'], owner: { name: 'An' } };
const copy = { ...task };

copy === task              // false: new outer object ✅
copy.tags === task.tags    // true: SAME array ⚠️
copy.owner === task.owner  // true: SAME object ⚠️

copy.tags.push('work');    // mutates task.tags too!
copy.owner.name = 'Binh';  // mutates task.owner too!
```

```text
task ─▶ { id, title, tags ─┬─▶ ['urgent'] , owner ─┬─▶ { name: 'An' } }
                           │                        │
copy ─▶ { id, title, tags ─┘               , owner ─┘ }
```

This is the most common immutability bug in Redux code written by hand. It leads directly to 04.05: to change a nested value, you must **copy every level on the path** to it.

## 5. Summary

- Destructuring unpacks objects (by name) and arrays (by position), with renames, defaults and nesting.
- Spread builds **new** arrays/objects; later object properties override earlier ones.
- Rest collects remaining properties/elements/arguments.
- Spread is **shallow**: nested objects are shared, so mutating them affects the original.

## 6. Check yourself

1. What is `{ ...{ a: 1, b: 2 }, b: 3, ...{ a: 4 } }`?
2. `const { id, ...rest } = { id: 1, title: 'X' }`. What's `rest`?
3. Why does `copy.tags.push('x')` change the original after `const copy = { ...task }`?

<details>
<summary>Answers</summary>

1. `{ a: 4, b: 3 }`: properties are applied left to right; later ones win.
2. `{ title: 'X' }`.
3. Spread copied the **reference** to the `tags` array, not the array. Both objects point to the same array.

</details>
