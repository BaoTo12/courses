# Lecture 31.10 · `include()` vs `forward()`: a First Look

> **Section:** S31 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~15 minutes

---

```java
PrintWriter out = Layout.begin(request, response, "Tasks");
request.getRequestDispatcher("/fragments/stats").include(request, response);  // inserts the stats HTML HERE
out.println("<table>…</table>");                                               // …then we continue writing
```

| | `forward` | `include` |
|---|---|---|
| Who writes the response | the target **only** (our uncommitted output is discarded) | us **and** the target (its output is inserted) |
| After the call | stop | continue |
| Can the target set the status or headers? | yes | **no**: changes are ignored (the included part is a fragment) |
| Committed-response check | must not be committed | may already be committed |
| Typical use | servlet → view | a shared fragment: a header, a footer, a widget |

In practice, JSP gives you `<jsp:include>` and `<%@ include %>` (S33) for layouts, and you'll rarely call `include()` from Java. Remember the difference for S33, where the two JSP includes differ in exactly this way (runtime vs translation time).

## ✅ Recap

`forward` = hand over completely. `include` = insert a fragment and carry on. The included component can't change the status or the headers.
