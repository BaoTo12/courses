# Lecture 31.07 · Forward (`RequestDispatcher.forward`): Server-Internal, Same Request

> **Section:** S31 · **Type:** 📖 Theory + 🛠 demo · **Track:** ★ Core · **Time:** ~30 minutes

## 1. One request, handled by two components

```text
Browser ── GET /taskflow/tasks/latest ─► TaskLatestServlet ──forward("/tasks/view?id=7")──► TaskViewServlet
        ◄────────────────────────────── 200 <html>…task 7… ◄──────────────────────────────┘
The URL bar still shows /taskflow/tasks/latest. The browser never knew.
```

✍️ `com/taskflow/web/tasks/TaskLatestServlet.java` (a demo)

```java
package com.taskflow.web.tasks;

import com.taskflow.model.Task;
import com.taskflow.store.InMemoryTaskStore;
import java.io.IOException;
import java.util.List;
import javax.servlet.ServletException;
import javax.servlet.annotation.WebServlet;
import javax.servlet.http.HttpServlet;
import javax.servlet.http.HttpServletRequest;
import javax.servlet.http.HttpServletResponse;

/**
 * S31 (31.07): GET /tasks/latest → FORWARDS to /tasks/view?id=<newest>. A forward is server-internal: one request,
 * the URL bar keeps /tasks/latest, and TaskViewServlet sees id as a parameter (the forward path's query string).
 */
@WebServlet("/tasks/latest")
public class TaskLatestServlet extends HttpServlet {

  private final InMemoryTaskStore store = InMemoryTaskStore.shared();

  @Override
  protected void doGet(HttpServletRequest request, HttpServletResponse response) throws ServletException, IOException {
    List<Task> all = store.findAll();
    if (all.isEmpty()) {
      response.sendError(HttpServletResponse.SC_NOT_FOUND);
      return;
    }
    long newest = all.get(all.size() - 1).getId();
    // A path relative to the CONTEXT (no /taskflow prefix): forwards never leave the web app.
    request.getRequestDispatcher("/tasks/view?id=" + newest).forward(request, response);
  }
}
```

## 📇 API card: `RequestDispatcher`

| Call | Meaning |
|---|---|
| `request.getRequestDispatcher("/tasks/view?id=7")` | a path **inside the app**: starts with `/` = relative to the context root (no `/taskflow`) |
| `request.getRequestDispatcher("view")` | relative to the current servlet path |
| `getServletContext().getNamedDispatcher("hello")` | by servlet name |
| `.forward(req, res)` | hand the request over **completely**; the target writes the response |
| `.include(req, res)` | insert the target's output here and continue (31.10) |

Rules of `forward`:
- **Before anything is committed.** Forwarding after the buffer has flushed throws `IllegalStateException`. Any uncommitted output is **discarded**.
- The target sees the **same** request object: the same attributes (31.09) and the same parameters, **plus** the forward path's query string (`id=7`), whose parameters take precedence.
- After `forward` returns, **don't write anything**. `return`.
- It can target **`/WEB-INF/...`**. That's exactly how S32+ reaches JSPs the browser can't request directly (28.04).

## 2. Why forward exists: MVC

```java
// S36 onwards, every page servlet ends like this:
request.setAttribute("tasks", tasks);                                      // the MODEL
request.getRequestDispatcher("/WEB-INF/views/tasks/list.jsp").forward(request, response);  // the VIEW
```

The servlet (the controller) decides, and the JSP (the view) renders. `/tasks/latest` is the same mechanism, between two servlets.

## ✅ Recap

A forward is server-internal: one request, the same request object, the URL unchanged, and it can reach `WEB-INF`. It must happen before the response is committed.
