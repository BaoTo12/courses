# Lecture 31.12 · 🔓 Lab: Parameter Tampering: Change `id`, Add Parameters, POST with curl

> **Section:** S31 · **Type:** 🔓 Attack Lab · **Track:** ★ Core · **Time:** ~30 minutes
> ⚠️ Local only.

---

The forms are the UI. The **servlets** are the attack surface. Bypass the forms:

## 1. Change ids

```bash
curl -i -d "id=1" http://localhost:8080/taskflow/tasks/toggle      # toggles task 1: nobody checked who you are
curl -i -d "id=0" http://localhost:8080/taskflow/tasks/delete      # 400: Params.positiveId refused it
curl -i -d "id=1 OR 1=1" http://localhost:8080/taskflow/tasks/delete   # 400: not a number (and in S36, not SQL either)
```

There's no login yet, so **anyone can toggle or delete any task**. The servlets validate the *format*, but nothing checks *permission*. S41 adds authentication, and S42 the per-task ownership check (IDOR). Keep a note: *"every state-changing servlet needs: who is it (session), may they (owner or admin), and did they mean it (CSRF, S37)?"*

## 2. Send values the form never offers

```bash
curl -i -d "title=Hack&priority=CRITICAL" http://localhost:8080/taskflow/tasks/new           # 400: allow-list
curl -i -d "title=$(python -c 'print("x"*500)')&priority=LOW" http://localhost:8080/taskflow/tasks/new   # 400: length
curl -i -d "title=Mine&priority=LOW&ownerId=3" http://localhost:8080/taskflow/tasks/new      # ownerId IGNORED
```

The last one matters: the servlet never reads an `ownerId` parameter. **Mass assignment** (binding every parameter onto an object) would have let the attacker choose the owner. Read only the fields you intend to accept.

## 3. Use the "wrong" method

```bash
curl -i "http://localhost:8080/taskflow/tasks/delete?id=2"          # 405: no doGet (29.03 honoured)
curl -i -X PUT http://localhost:8080/taskflow/tasks/new             # 405
```

## 4. Duplicate parameters

```bash
curl -i -d "id=2&id=3" http://localhost:8080/taskflow/tasks/delete
```

`getParameter` takes the **first** (2). A different component reading `getParameterValues`, or a proxy that keeps the **last**, may disagree: **HTTP parameter pollution**. Keep it consistent, and reject duplicates for security-relevant parameters if in doubt.

## What held, and what didn't

| Defence | Held? |
|---|---|
| format validation (`Params`, allow-lists, lengths) | ✅ |
| ignoring unexpected fields (`ownerId`) | ✅ |
| method restriction (POST-only changes) | ✅ |
| **authentication / authorisation** | ❌ not built yet (S41, S42) |
| **CSRF** protection | ❌ not built yet (S37 lab, S41) |
