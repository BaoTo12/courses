# Lecture 31.08 · Forward vs Redirect, Side by Side

> **Section:** S31 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~20 minutes

---

| | **Forward** | **Redirect** |
|---|---|---|
| API | `request.getRequestDispatcher(path).forward(req, res)` | `response.sendRedirect(url)` |
| HTTP requests | **1** | **2** (302, then a GET) |
| URL bar | unchanged (the original URL) | the new URL |
| Request attributes | ✅ survive (the same request) | ❌ lost (a new request) |
| Parameters | the same (+ the forward's query string) | only those in the new URL |
| Can target | only this web app, including `/WEB-INF/…` | any URL (never `WEB-INF`: it's a browser request) |
| Reload repeats | the **original** request (a POST!) | the final GET |
| Speed | one round trip | two round trips |
| Typical use | servlet → JSP view (MVC) | after a **successful POST** (PRG); after login/logout; moved URLs |

## Decision rule

```text
Did the request CHANGE something (POST succeeded)?        → REDIRECT to a page that shows the result
Is it a read, or a failed POST showing the form + errors? → FORWARD to the view (status 200 / 400)
```

## TaskFlow's flows

| Flow | Result |
|---|---|
| GET `/tasks` | forward to the list view (S36; println today) |
| POST `/tasks/new`, valid | **redirect** to `/tasks/view?id=N` |
| POST `/tasks/new`, invalid | the form + errors, **400** (forward in S37) |
| POST `/tasks/delete` | **redirect** to `/tasks` |
| POST `/login`, valid | **redirect** to `returnTo` (validated, 24.14) |

## ✅ Recap

Forward = inside the server, one request, the URL unchanged, attributes kept. Redirect = the browser makes a new request, the URL changes, attributes are lost. Redirect after changes, forward to render.
