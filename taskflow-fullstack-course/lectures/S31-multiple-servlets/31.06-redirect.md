# Lecture 31.06 · Redirect (`sendRedirect`): 302 + `Location` → a *New* Request

> **Section:** S31 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~25 minutes
> Verified: `S31TaskServletsTest` (create → `302`, `Location: /taskflow/tasks/view?id=N`; toggle and delete → `302`, `Location: /taskflow/tasks`)

---

## 1. Two round trips

```text
① Browser ── POST /taskflow/tasks/new  (title=…) ──────────────────► TaskCreateServlet.doPost
          ◄── 302 Found   Location: /taskflow/tasks/view?id=7   (no body worth showing)
② Browser ── GET /taskflow/tasks/view?id=7 ────────────────────────► TaskViewServlet.doGet
          ◄── 200 OK   <html>…the new task…
   The URL bar now shows /taskflow/tasks/view?id=7
```

`response.sendRedirect(url)` sets status **302**, the `Location` header, and **commits** the response (30.18). The browser then makes a **brand-new request**: new request object, new parameters, new attributes, maybe even another server.

## 📇 API card: `sendRedirect(String location)`

| `location` | Resolved against | Example from `/taskflow/tasks/new` |
|---|---|---|
| `"/taskflow/tasks/view?id=7"` (starts with `/`) | the **server** root | `/taskflow/tasks/view?id=7` ✅ (TaskFlow's style: `ctx + "/…"`) |
| `"view?id=7"` (relative) | the **current URL's directory** | `/taskflow/tasks/view?id=7` (works, but fragile) |
| `"https://example.com/"` | absolute | leaves the app: never with user input (open redirect, 24.14) |

- Throws `IllegalStateException` if the response is already committed. **`return`** after it.
- Status is 302. For a POST → GET redirect, 303 is the precise code (29.04). Browsers treat 302 after POST the same way. S37 uses 303 explicitly for PRG.

## 2. What survives a redirect?

| Survives | Doesn't |
|---|---|
| anything **in the URL** (`?id=7`) | **request attributes** (a new request, 31.15) |
| cookies, the session (S38) | the POST body |
| | objects in local variables |

To show "Task created ✓" on the next page: the URL (`?created=1`), or a **flash** attribute in the session (S38).

## ✅ Recap

A redirect tells the browser "go GET that URL". There are two requests, the URL changes, and request data doesn't survive.
