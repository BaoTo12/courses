# Lecture 31.11 · Relative vs Absolute URLs in Redirects; `getContextPath()`; `encodeRedirectURL`

> **Section:** S31 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~20 minutes

---

## 1. Three kinds of paths, three bases

| Where | `/tasks` means | Include the context path? |
|---|---|---|
| `sendRedirect("/…")`, `<a href="/…">`, `<form action="/…">` (**browser** URLs) | server root: `http://host:8080/tasks` | **yes**: `request.getContextPath() + "/tasks"` |
| `getRequestDispatcher("/…")` (**forward/include**) | the **app's** root | **no** (it's inside the app) |
| `web.xml` / `@WebServlet` patterns | the app's root | no |

The classic bug: `response.sendRedirect("/tasks")` sends the user to `http://localhost:8080/tasks`, outside the app → 404. It works only if the app is deployed as ROOT. TaskFlow's rule: **`request.getContextPath() + "/…"`** for every browser URL (`Layout`, every servlet), and the same in JSP with `${pageContext.request.contextPath}` (S32).

## 2. Building URLs with parameters

```java
String url = request.getContextPath() + "/tasks?q=" + URLEncoder.encode(query, StandardCharsets.UTF_8);
response.sendRedirect(url);
```

Encode each **value**. Without it, `q=a&status=DONE` typed by a user becomes **two** parameters (parameter injection), and a space breaks the header.

## 3. `encodeRedirectURL` / `encodeURL`

```java
response.sendRedirect(response.encodeRedirectURL(request.getContextPath() + "/tasks"));
```

They add `;jsessionid=…` to the URL **if** the container tracks sessions via URL rewriting (29.07 §3). TaskFlow's `web.xml` sets `<tracking-mode>COOKIE</tracking-mode>` (28.04), so these calls return the URL unchanged. You'll see them in older code. Session ids in URLs leak through logs, Referers and shared links: keep URL tracking off.

## 4. Never redirect to user input as-is

`sendRedirect(request.getParameter("next"))` is an **open redirect** (24.14): validate that it's an internal path first (`safeReturnTo`'s server-side twin, S41).

## ✅ Recap

Browser URLs need the context path, and dispatcher paths don't. Encode parameter values. Keep session ids out of URLs. Validate redirect targets.
