# Lecture 31.04 · GET vs POST in Practice

> **Section:** S31 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~25 minutes

---

| | GET form (`method="get"`) | POST form (`method="post"`) |
|---|---|---|
| Parameters live in | the **URL** (`/tasks?status=DONE`) | the **body** |
| Bookmark, share, Back | ✅ the URL *is* the state | ❌ |
| Reload | silently repeats | the browser asks "Resend the form?" |
| Cached, prefetched, crawled | may be | no |
| Visible in history, logs, Referer | ✅ (never put secrets there) | not in the URL |
| Size | URL limits (~8 KB in Tomcat by default) | large (`maxPostSize`, 2 MB default) |
| Use for | search, filters, pagination: **reads** | create, update, delete, login: **changes** (29.03) |

## In TaskFlow Admin

| Page | Method | Why |
|---|---|---|
| `/tasks?status=DONE` | GET | a view: bookmarkable, shareable |
| `/tasks/view?id=3` | GET | a view |
| `/tasks/new` (show the form) | GET | a view |
| `/tasks/new` (submit) | **POST** | creates |
| `/tasks/toggle`, `/tasks/delete` | **POST** | change state |
| `/login` (submit) | POST | a password must not be in the URL (S41) |

One URL, two methods: `TaskCreateServlet` answers **GET** with the form and **POST** with the processing. The same resource is read or written depending on the method (30.07).

## "Resend the form?": the reason for redirects

If a POST answers with a page (200), **Reload** re-sends the POST: a second task is created. So after a **successful** POST, answer with a **redirect** (31.06). The browser then GETs the result, and Reload repeats only the harmless GET. That's the **Post/Redirect/Get** pattern, formalised in S37. A **failed** POST (validation errors) answers 400 with the form: nothing was saved, so resending is harmless.

## ✅ Recap

GET for reads (the state is in the URL), POST for changes (in the body). After a successful POST, redirect.
