# Lecture 20.04 · `createSlice`: One Object In, Reducer and Action Creators Out

> **Section:** S20 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~30 minutes
> Verified with RTK 2.12 in Node: every "prints" below is a captured output.

---

## 1. The hand-written slice you are replacing (S15)

```ts
export type ListPrefsAction =
  | { type: 'listPrefs/sortChanged'; payload: { key: SortKey; direction: SortDirection } }
  | { type: 'listPrefs/pageSizeChanged'; payload: PageSize };

export const pageSizeChanged = (pageSize: PageSize): ListPrefsAction => ({
  type: 'listPrefs/pageSizeChanged',
  payload: pageSize,
});

export function listPrefsReducer(state = initialListPrefsState, action: AppAction): ListPrefsState {
  switch (action.type) {
    case 'listPrefs/pageSizeChanged':
      return action.payload === state.pageSize ? state : { ...state, pageSize: action.payload };
    // …
    default:
      return state;
  }
}
```

The string `'listPrefs/pageSizeChanged'` appears **three** times. The union type must list every action. The reducer spreads.

## 2. The same thing with `createSlice`

```ts
import { createSlice } from '@reduxjs/toolkit';
import type { PayloadAction } from '@reduxjs/toolkit';

const listPrefsSlice = createSlice({
  name: 'listPrefs',                        // the prefix of every generated type
  initialState: initialListPrefsState,
  reducers: {
    pageSizeChanged(state, action: PayloadAction<PageSize>) {
      state.pageSize = action.payload;      // "mutation" of an Immer draft (20.05)
    },
  },
});

export const { pageSizeChanged } = listPrefsSlice.actions;
export const listPrefsReducer = listPrefsSlice.reducer;
```

What `createSlice` did with that object:

| You wrote | It generated |
|---|---|
| `name: 'listPrefs'` + key `pageSizeChanged` | the type string `'listPrefs/pageSizeChanged'` |
| `action: PayloadAction<PageSize>` | an action creator typed `(payload: PageSize) => { type; payload: PageSize }` |
| the case function | one reducer that dispatches on `action.type`, returns `state` for unknown actions, and wraps every case in Immer |
| `initialState` | the `state = initialState` default and `slice.getInitialState()` |

Captured in Node:

```text
pageSizeChanged.type            → 'listPrefs/pageSizeChanged'
pageSizeChanged(50)             → { type: 'listPrefs/pageSizeChanged', payload: 50 }
pageSizeChanged.match(action)   → true   (a type guard: narrows `action` in TypeScript)
String(pageSizeChanged)         → 'listPrefs/pageSizeChanged'
reducer(state, { type: 'other' }) === state → true
```

### `PayloadAction<P>`

`PayloadAction<P>` is `{ type: string; payload: P }`. You annotate **only the action parameter**; `state` is typed from `initialState`. A reducer that needs no payload omits the parameter, and its creator takes no arguments: `selectionCleared()`.

If `initialState`'s inferred type is too narrow (a `null` that will later hold a number, a union like `'idle' | 'loading'`), declare the state type and annotate: `initialState: initialTasksState` where `initialTasksState: TasksState`. TaskFlow always does this.

## 3. The generated action creators are events, named by you

`createSlice` doesn't change the rule from 15.03: name reducers after **what happened** (`sortChanged`, `taskSelectionToggled`), not after a setter (`setSort`). The generated type `listPrefs/sortChanged` then reads well in the DevTools and in the logger.

## 4. What a slice may and may not do

The case functions are still **reducers** (15.04): no API calls, no `Date.now()`, no `Math.random()`, no dispatching. RTK doesn't check this. Values like timestamps and ids come from a `prepare` callback (20.07) or a thunk, exactly as in 19.01.

## 5. Reading the result: it's just a reducer

```ts
listPrefsSlice.reducer(undefined, { type: '@@INIT' })  // → initialListPrefsState
listPrefsSlice.name                                     // → 'listPrefs'
listPrefsSlice.actions                                  // → { sortChanged, pageSizeChanged }
listPrefsSlice.getInitialState()                        // → initialListPrefsState
```

So every S15 reducer test still works: `reducer(deepFreeze(state), action)` with the generated creators. TaskFlow's `listPrefs` tests didn't change at all; the `ui` tests changed only where behaviour changed on purpose (toast ids became `nanoid` strings, 20.07).

### Selectors in a slice

`createSlice` also accepts a `selectors` field (`selectSlice`-relative selectors). TaskFlow keeps plain exported selector functions taking `RootState`, as in S19, because several of them read more than one slice (`selectTaskCountsByCategory`). Both styles are fine; be consistent.

## 6. 📇 API card: `createSlice`

```ts
function createSlice(options: CreateSliceOptions): Slice
```

| Option | Type | Required | Meaning |
|---|---|---|---|
| `name` | `string` | **yes** | Prefix of every generated action type (`'counter'` → `'counter/incremented'`), and the default `reducerPath`. |
| `initialState` | `State` or `() => State` | **yes** | The state when the reducer first receives `undefined`. A **function** is a lazy initializer (e.g. read from storage), called when the initial state is needed. |
| `reducers` | object of case reducers (or `{ reducer, prepare }` objects) | **yes** (may be `{}`) | The slice's **own** events. Each key generates an action creator and a type. |
| `extraReducers` | `(builder) => void` | no | Reactions to actions **defined elsewhere**: other slices' events, `createAction` events, thunk lifecycles, matchers (20.07, 20.11). |
| `selectors` | object of `(sliceState, …args) => value` | no | Selectors written against the **slice's** state; RTK binds them to the root state for you (below). |
| `reducerPath` | `string` | no | Where the slice lives in the root state, if not `name`. Used by `selectors` and by lazy-loaded slices (`combineSlices`, not used in this course). |

A case reducer is `(state: Draft<State>, action: PayloadAction<P>) => void | State`: mutate the draft, **or** return a new state (20.05).

**Returns** a `Slice` object (all members verified in `s20-api-cards.claims.test.ts`):

| Member | What it is |
|---|---|
| `reducer` | the slice reducer: pass it to `configureStore` / `combineReducers` |
| `actions` | the generated action creators, one per key of `reducers` |
| `caseReducers` | your case reducer functions themselves (handy to reuse one inside another, or to test it directly) |
| `name`, `reducerPath` | as given (`reducerPath` defaults to `name`) |
| `getInitialState()` | the initial state (calls the lazy initializer if you passed a function) |
| `selectors` | your `selectors`, bound to the **root** state at `state[reducerPath]` |
| `getSelectors()` / `getSelectors(selectSliceState)` | the same selectors unbound (they take the slice state) or bound through your own function |
| `selectSlice(rootState)` | returns `rootState[reducerPath]` |

**Minimal example (outside TaskFlow)**

```ts
const counterSlice = createSlice({
  name: 'counter',
  initialState: { value: 0 },
  reducers: {
    incremented(state) {
      state.value += 1;
    },
    addedBy(state, action: PayloadAction<number>) {
      state.value += action.payload;
    },
  },
  selectors: {
    selectValue: (state) => state.value,
  },
});

export const { incremented, addedBy } = counterSlice.actions;
export const { selectValue } = counterSlice.selectors; // selectValue(rootState)
export default counterSlice.reducer;
```

**Use it when** you write any Redux state with its update logic: it's the standard way, and the Style Guide asks for it.

**Don't use it when** a reducer only reacts to actions defined elsewhere and needs no creators: `createReducer` is enough (20.07). Don't use slices for **server cache** data when you have RTK Query (S22): a slice per endpoint is the boilerplate RTK Query removes.

**Common mistakes**

- Naming reducers as setters (`setTasks`) instead of events (`tasksLoaded`, 15.03).
- Putting side effects in a case reducer (`Date.now()`, `nanoid()`, API calls): use `prepare` or a thunk.
- Destructuring the slice state in a case reducer and reassigning it (`let { value } = state; value++`): changes a local copy, not the draft.
- Exporting the slice object and calling `slice.reducer` in components: components dispatch `slice.actions.x()` and read with selectors; only the store needs the reducer.

## 7. Summary

- `createSlice({ name, initialState, reducers })` → `slice.reducer` + `slice.actions` (one creator per case) with types `name/key`.
- Annotate the action as `PayloadAction<P>`; the state type comes from `initialState`.
- Generated creators have `.type` and `.match()`.
- Case functions are reducers: pure. They "mutate" a **draft**. How that can be immutable is the next lecture.
