# Lecture 20.05 · How Immer Works: Drafts, Proxies, Structural Sharing

> **Section:** S20 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~40 minutes
> Verified with RTK 2.12 (Immer 11.1.18) in Node. All results below were captured.

---

## 1. The claim, and why it sounds wrong

```ts
pageSizeChanged(state, action: PayloadAction<PageSize>) {
  state.pageSize = action.payload;
}
```

Since 14.04 you've been told "never mutate state". This looks like a mutation, yet it's correct. The reason: **`state` here is not the state.** It's a **draft**.

## 2. What happens during one reducer call

1. RTK calls Immer's `produce(currentState, yourCaseFunction)`.
2. Immer creates a **draft**: a JavaScript `Proxy` wrapped around `currentState`. The proxy intercepts reads and writes.
3. **Reads** go through to the original. Reading `state.sort` returns another draft (created lazily) for that nested object.
4. **Writes** never touch the original. Immer makes a shallow **copy** of the object being written (and of each parent on the path up to the root), and marks them modified.
5. When your function returns, Immer **finalises**: modified objects become new objects; **unmodified subtrees are reused by reference**. The result is deep-frozen in development (and by default in production too).

The original state is never changed. The result is exactly what you would have built with spreads.

Captured:

```text
s1 = reducer(s0, pageSizeChanged(50))
s1.sort === s0.sort                  → true    (untouched subtree: same reference, "structural sharing")
Object.isFrozen(s1) && isFrozen(s1.sort) → true
reducer(s0, pageSizeChanged(20)) === s0 → true    (20 is already the value: no change, SAME state)
```

That last line matters for React-Redux (17.04): assigning a primitive that is **identical** (`Object.is`) to the current one isn't recorded as a change, so the reducer returns the very same state object, and no component re-renders. Your S15 code had to write `if (value === state.x) return state` by hand; Immer does it for you.

## 3. The rules of drafts

### Rule 1: mutate the draft, **or** return a new value. Never both.

Both styles are valid:

```ts
// mutate
toastDismissed(state, action) { state.toasts = state.toasts.filter((t) => t.id !== action.payload); }

// return a new value (replaces the slice state)
.addCase(fetchCategories.fulfilled, (_state, action) => {
  return { ...normalize(action.payload), status: 'succeeded', error: null };
})
.addCase(loggedOut, () => initialTasksState)
```

Doing both is an error; debugged in 20.17:

> [Immer] An immer producer returned a new value \*and\* modified its draft. Either return a new value \*or\* modify the draft.

A one-line arrow function **returns** its expression. `(state) => state.items.push(x)` returns the new array length: "modified the draft **and** returned a number". TypeScript rejects that one (20.17 shows the message); in plain JavaScript, Immer throws. Use braces: `(state) => { state.items.push(x); }`. The variant TypeScript **can't** catch is modifying the draft and then returning a new state object (20.17).

### Rule 2: reassigning `state` does nothing

```ts
reset(state) {
  state = initialState;  // ❌ rebinds a local variable; the draft is untouched → no change
}
reset() {
  return initialState;   // ✅
}
```

Verified: the reassignment version returns the unchanged old state, with no error. It's a silent bug.

### Rule 3: a new object is a change, even with equal values

Captured with the `listPrefs` slice:

```text
state.sort = { key: 'dueDate', direction: 'asc' }   (same values as now) → a NEW state (=== s0: false)
state.sort.key = 'dueDate'; state.sort.direction = 'asc'                  → the SAME state (=== s0: true)
```

Immer compares by reference: a new object literal is always "different". That's why TaskFlow's `sortChanged` assigns the two fields separately (20.06). It matters wherever re-renders matter; for a one-off reset it doesn't.

### Rule 4: log drafts with `current()`

`console.log(state)` inside a reducer prints a **Proxy** (in Node: `[object Object]` when converted to a string; in the browser DevTools, a `Proxy(Object)` whose contents are hard to read, and which is **revoked** after the reducer ends). Use RTK's re-exports of Immer's helpers:

```ts
import { current, original, isDraft } from '@reduxjs/toolkit';

state.items.push(2);
current(state)   // → {"items":[1,2]}  a plain snapshot of the draft NOW
original(state)  // → {"items":[1]}    the state before this reducer
isDraft(state)   // → true
```

Keeping a reference to a draft and using it later (in a `setTimeout`, in a thunk) throws:

> Cannot perform 'get' on a proxy that has been revoked

### Rule 5: only inside `createSlice` / `createReducer`

Immer runs only in RTK's reducer helpers. In a hand-written reducer, in a component or in a thunk, `state.x = y` is a **real** mutation (the immutability check will throw, 20.02).

## 4. What Immer can't draft

- Class instances (except with `immerable`), `Date`s, functions: they aren't drafted, and they don't belong in Redux state anyway (20.16).
- `Map` and `Set` can be drafted only after calling Immer's `enableMapSet()` (RTK doesn't call it). They aren't serialisable anyway, so TaskFlow keeps arrays and records (14.13).

## 5. Cost

Proxies cost a little on every write. For UI state (hundreds or thousands of items) it doesn't matter. Normalised state (19.05) helps Immer too: updating `entities[5]` copies one task and one `entities` object, not an array.

## 6. 📇 API card: Immer's helpers, as re-exported by RTK

You never call Immer's `produce` yourself in RTK code: `createSlice` and `createReducer` call it around every case reducer. RTK re-exports the helpers you need **inside** those case reducers:

| Function | Signature | Returns | Use it for |
|---|---|---|---|
| `current(draft)` | `<T>(draft: T) => T` | a plain (not frozen) **snapshot** of the draft right now | logging (`console.log(current(state))`), or passing a copy to a function that must not see a Proxy |
| `original(draft)` | `<T>(draft: T) => T \| undefined` | the value **before** this reducer started | comparing old and new inside a reducer |
| `isDraft(value)` | `(value: any) => boolean` | whether `value` is an Immer draft | helpers used both inside and outside reducers |

Verified (claims tests, *"rule 4"* and *"current() snapshots"*): the snapshot from `current()` is not frozen, and `return current(state)` after a mutation throws the mutate-*and*-return error. Inside a reducer that pushed `2`, `current(state)` was `{"items":[1,2]}`, `original(state)` was `{"items":[1]}`, `isDraft(state)` was `true`; reading a kept draft **after** the reducer threw *"Cannot perform 'get' on a proxy that has been revoked"*.

**Minimal example**

```ts
removed(state, action: PayloadAction<number>) {
  const before = original(state)?.items.length;
  state.items = state.items.filter((id) => id !== action.payload);
  console.debug('removed', before, '→', current(state).items.length);
}
```

**Use them when** debugging or comparing inside a case reducer. **Don't use** `current()` to "return a copy" (`return current(state)` after mutating is the forbidden mutate-*and*-return, 20.17), and don't call these helpers outside reducers: there are no drafts there.

**Rules recap (the "API" of a draft):** mutate the draft **or** return a new state; never reassign `state`; a new object is always a change; don't keep a draft after the reducer returns.

## 7. Summary

- `state` in a slice reducer is an Immer **draft** (a Proxy). Writes create copies; untouched subtrees are shared; the result is frozen.
- Assigning an identical primitive = no change = the same state object (fewer re-renders).
- Mutate **or** return; never reassign `state`; a new object is always a change; inspect with `current()`.
