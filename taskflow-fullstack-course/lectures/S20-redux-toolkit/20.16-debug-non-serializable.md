# Lecture 20.16 · 🐞 Debug: "A non-serializable value was detected in the state" (a `Date` in State)

> **Section:** S20 · **Type:** 🐞 Debug · **Track:** ★ Core · **Time:** ~20 minutes
> Reproduced with RTK 2.12 (`configureStore` defaults, development). The console output below is captured.

---

## Symptom

A teammate thinks epoch milliseconds are unreadable in the DevTools and changes the fetch thunk to return a `Date`:

```ts
return { tasks: page.items, fetchedAt: new Date() }; // was Date.now()
```

They change `fetchedAt: number | null` to `Date | null` in `TasksState` and update `fetchTasksIfNeeded` to `now() - fetchedAt.getTime()`. Everything compiles and the app works: the list loads, and "fetch if needed" still skips fresh data. But the console fills with red errors (captured in TaskFlow's reference project):

```text
A non-serializable value was detected in an action, in the path: `payload.fetchedAt`. Value:
  Sat Sep 26 2026 15:00:00 GMT+0700
Take a look at the logic that dispatched this action: {…}
(See https://redux.js.org/faq/actions#why-should-type-be-a-string-or-at-least-serializable-why-should-my-action-types-be-constants)
(To allow non-serializable values see: https://redux-toolkit.js.org/usage/usage-guide#working-with-non-serializable-data)

A non-serializable value was detected in the state, in the path: `tasks.fetchedAt`. Value:
  Sat Sep 26 2026 15:00:00 GMT+0700
Take a look at the reducer(s) handling this action type: tasks/fetch/fulfilled.

A non-serializable value was detected in the state, in the path: `tasks.fetchedAt`. Value:
  Sat Sep 26 2026 15:00:00 GMT+0700
Take a look at the reducer(s) handling this action type: ui/toastShown.
```

The last message repeats after **every** later action, each time naming that action.

## Investigation checklist

1. Which middleware prints these? Is it active in production? (20.02)
2. There are two kinds of message. Which one points at the **cause**?
3. The third message blames `ui/toastShown`. Did the `ui` reducer do anything wrong?
4. What would go wrong with a `Date` in state, if the check didn't exist?

## Explanation

The **serializability check** (a dev-only default middleware) walks every action, and the whole state after every action, looking for values that aren't plain data: `Date`, `Map`, `Set`, class instances, functions, Promises.

- The **action** message is the cause: a `Date` entered through `payload.fetchedAt` of `tasks/fetch/fulfilled`.
- The **state** message then appears after **every** action, because the `Date` stays in the state. Its "Take a look at the reducer(s) handling this action type" line names whichever action just ran (`ui/toastShown`), which is **misleading**: the ui reducer is innocent. Always scroll up to the **first** message.

Why Redux forbids it (Style Guide, Priority A, 19.10):

- **DevTools and time travel** serialise state and actions: a `Date` becomes a string there, so replayed state differs from the real one.
- **Persistence** (TaskFlow saves preferences to a cookie in S21; any `JSON.stringify` of state) turns it into a string; reading it back gives a string, not a `Date`, and `fetchedAt.getTime()` crashes after a reload.
- **`Date` is mutable**: `state.tasks.fetchedAt.setHours(0)` in a component mutates the store behind Redux's back, with no action, no re-render and no check (the immutability check doesn't look inside `Date`s).
- **Equality**: two `Date`s with the same time are different objects, which breaks "same value → same reference" (20.05).

## Fix

Store a **primitive**, and convert when displaying:

```ts
return { tasks: page.items, fetchedAt: Date.now() };   // epoch ms: a number (TaskFlow's choice)
// or: fetchedAt: new Date().toISOString()             // an ISO string: readable in the DevTools
```

```ts
// display only
const fetchedAtText = fetchedAt === null ? '—' : new Date(fetchedAt).toLocaleTimeString();
```

TaskFlow already follows this everywhere: task dates are ISO strings from the API (`dueDate`, `createdAt`), `fetchedAt` is epoch ms, errors travel as `ApiErrorPayload` objects rather than `ApiRequestError` instances (20.09), and the `AbortController` lives in the thunk's `extra`, not in state (18.11).

## When the check is legitimately in the way

Rarely, a non-serialisable value in an **action** is intended, for example a `File` passed to a thunk. RTK already ignores `meta.arg` and `meta.baseQueryMeta` by default. For other cases, configure the check narrowly:

```ts
getDefaultMiddleware({
  serializableCheck: {
    ignoredActions: ['attachments/upload/pending'], // this action only
    ignoredPaths: ['uploads.currentFile'],          // this state path only (think twice!)
  },
})
```

Never disable the check globally to silence a warning you don't understand.

## Lessons

- Read the **first** serializability message: it names the action and path that introduced the value. Later "state" messages name whatever action ran last.
- Keep dates as ISO strings or epoch numbers in Redux; create `Date` objects only for display.
- The check exists only in development: in production, the same bug is silent.
