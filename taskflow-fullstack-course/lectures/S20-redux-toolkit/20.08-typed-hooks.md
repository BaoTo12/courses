# Lecture 20.08 · Typed Hooks with `.withTypes()` (Current RTK Style)

> **Section:** S20 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~15 minutes
> Verified: TaskFlow's `hooks.ts`, and the lint rule that forbids the untyped hooks, with `tsc` and oxlint.

---

## 1. You already have them

In 17.06 you wrote:

```ts
export const useAppSelector = useSelector.withTypes<RootState>();
export const useAppDispatch = useDispatch.withTypes<AppDispatch>();
```

That **is** the current RTK style (React-Redux 9.1+). Nothing changes in S20 except where the types come from:

| Type | S18 | S20 |
|---|---|---|
| `RootState` | derived from the slice reducers, plus a cast on `combineReducers` | `ReturnType<typeof rootReducer>`, no cast |
| `AppDispatch` | `ThunkDispatch<RootState, ThunkExtra, AppAction>`, declared by hand | `AppStore['dispatch']`, **inferred** from `configureStore` |

The inferred `AppDispatch` knows everything the middleware add. `dispatch(fetchTasks())` returns a promise with `.unwrap()` and `.abort()`; `dispatch(fetchTasksIfNeeded())` returns `Promise<void>`; `dispatch(toastShown(…))` returns the action.

## 2. Older styles you'll see in existing code

```ts
// React-Redux 7/8 era: still correct, more verbose
export const useAppDispatch: () => AppDispatch = useDispatch;
export const useAppSelector: TypedUseSelectorHook<RootState> = useSelector;

// or a wrapper function
export const useAppDispatch = () => useDispatch<AppDispatch>();
```

All three produce the same types. Prefer `.withTypes()` in new code; don't rewrite old code just for this.

The same pattern exists for thunks: `createAsyncThunk.withTypes<{ state; dispatch; extra; rejectValue }>()` (20.09). TaskFlow calls the result `createAppAsyncThunk`.

## 3. Make the plain hooks impossible to use by accident

Importing `useSelector` from `react-redux` in a component still compiles; `state` is then `unknown`, and the fix is usually an `as` cast, which hides errors. TaskFlow's `.oxlintrc.json` forbids the plain hooks everywhere except `hooks.ts`:

```json
"no-restricted-imports": ["error", {
  "paths": [{
    "name": "react-redux",
    "importNames": ["useSelector", "useDispatch"],
    "message": "Use useAppSelector / useAppDispatch from src/app/hooks.ts (17.06)."
  }]
}]
```

plus an override that turns the rule off for `src/app/hooks.ts`. `npm run lint` in CI then catches it in review, not in production.

## 4. 📇 API card: the `.withTypes()` family

Each of these returns **the same function**, with your types filled in once. They add no runtime behaviour: only types.

| Call | Returns | Fixes the type of |
|---|---|---|
| `useSelector.withTypes<RootState>()` | a `useSelector` | the `state` parameter of every selector passed to it |
| `useDispatch.withTypes<AppDispatch>()` | a `useDispatch` | the returned `dispatch` (accepts thunks, returns their results) |
| `useStore.withTypes<AppStore>()` | a `useStore` | the returned store (rarely needed in components) |
| `createAsyncThunk.withTypes<{ state; dispatch; extra; rejectValue; … }>()` | a `createAsyncThunk` | `getState()`, `dispatch`, `extra` and `rejectWithValue` inside every payload creator (20.09) |
| `createSelector.withTypes<RootState>()` | a `createSelector` | the `state` parameter of the input selectors (S21) |
| `listenerMiddleware.startListening.withTypes<RootState, AppDispatch, Extra>()` | a `startListening` | `getState()`, `dispatch` and `extra` in listener effects (21.14) |

**Where:** once, in `app/hooks.ts` (hooks) and next to the store or the feature (thunks, selectors, listeners). Never repeat `useSelector((state: RootState) => …)` in components.

**Minimal example**

```ts
// app/hooks.ts
export const useAppSelector = useSelector.withTypes<RootState>();
export const useAppDispatch = useDispatch.withTypes<AppDispatch>();

// in a component
const count = useAppSelector((state) => state.counter.value); // state: RootState, inferred
```

**Common mistake:** deriving `AppDispatch` from a store created **without** its middleware types (for example `Store<RootState>`): `dispatch(thunk)` then doesn't type-check. Derive it from the real store: `AppStore['dispatch']` (20.02).

## 5. Summary

- `useSelector.withTypes<RootState>()` and `useDispatch.withTypes<AppDispatch>()`, in `app/hooks.ts`, used everywhere.
- In S20 the types they receive are **inferred** by RTK: no hand-written `AppStore` or `ThunkDispatch`.
- Enforce the typed hooks with a lint rule.
