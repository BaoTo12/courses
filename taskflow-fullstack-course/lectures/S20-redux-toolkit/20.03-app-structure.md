## 1. The standard layout

The Redux template for Vite (`npx degit reduxjs/redux-templates/packages/vite-template-redux`) and the Essentials tutorial use this shape:

```text
src/
├── app/
│   ├── store.ts        configureStore, RootState, AppDispatch
│   └── hooks.ts        useAppSelector, useAppDispatch (typed once)
└── features/
    └── counter/
        ├── counterSlice.ts   createSlice: state, reducers, generated actions, selectors
        └── Counter.tsx       the feature's UI
```

TaskFlow already has this shape since S19 (19.10). S20 changes what's **inside** the files, not where they are:

```text
src/app/
├── store.ts          configureStore (was createStore + applyMiddleware + compose)
├── rootReducer.ts    RTK's combineReducers, no cast any more
├── hooks.ts          .withTypes() hooks (unchanged since 17.06)
├── thunk-types.ts    ThunkExtra, AppThunk, createAppAsyncThunk        (AppAction deleted)
└── middleware/  enhancers/  mini-redux/                               (unchanged)

src/features/
├── auth/authActions.ts        createAction('auth/loggedOut')
├── tasks/tasksSlice.ts        createSlice + extraReducers for the thunks
├── tasks/tasksThunks.ts       createAsyncThunk ×7 + one plain thunk
├── categories/…Slice.ts, …Thunks.ts
├── listPrefs/listPrefsSlice.ts
└── ui/uiSlice.ts, toastActions.ts   (new: breaks an import cycle, 20.15)
```

## 2. Why TaskFlow keeps a separate `rootReducer.ts`

The template puts the reducer object directly in `configureStore({ reducer: { … } })` and writes `type RootState = ReturnType<typeof store.getState>`. TaskFlow derives `RootState` from a separate root reducer instead:

```ts
export const rootReducer = combineReducers({ tasks: tasksReducer, categories: categoriesReducer, listPrefs: listPrefsReducer, ui: uiReducer });
export type RootState = ReturnType<typeof rootReducer>;
```

Two reasons:

1. **Tests** create stores and call the root reducer without the app's store module (and without its side effect of creating the singleton `store`).
2. `RootState` doesn't depend on `store.ts`, so slice files can import the type without a circular dependency through `store.ts` → slices → `store.ts`.

Both are allowed by the Essentials tutorial ("infer the type from the store or from the root reducer").

## 3. Where things go, as a rule

| Kind of code | File |
|---|---|
| State shape, reducers, generated actions, simple selectors of one slice | `features/x/xSlice.ts` |
| Async logic (API calls) | `features/x/xThunks.ts` (TaskFlow's choice; the Essentials put thunks in the slice file) |
| Events shared by several slices, with no single owner | a small actions file (`authActions.ts`, `toastActions.ts`) |
| Selectors that combine several slices | the slice that "owns" the result (`selectTaskCountsByCategory` in categories) or a `selectors.ts` |
| Store wiring, typed hooks | `app/` |

Why TaskFlow separates thunks: the slice file stays free of API imports, so reducer tests don't load Axios, and it avoids import cycles when a slice handles **another** feature's thunk actions (`ui` handles `deleteTask.fulfilled`).

## 4. Summary

- `app/` for the store and typed hooks; `features/<name>/` for slice + UI.
- TaskFlow's structure didn't move in S20; only the contents got shorter.
- `RootState` comes from the root reducer, to keep tests and slice files free of the store singleton.
