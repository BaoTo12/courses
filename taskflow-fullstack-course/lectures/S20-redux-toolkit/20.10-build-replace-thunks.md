# Lecture 20.10 · 🛠 Build: Replace the S18 Thunks with `createAsyncThunk`; Delete the Boilerplate; Compare Line Counts

> **Section:** S20 · **Type:** 🛠 Build · **Track:** ★ Core · **Time:** ~120 minutes
> **Project feature:** every task I/O operation as `createAsyncThunk`; `tasksSlice` handles their lifecycle in `extraReducers`; pages use `.unwrap()` / `.match()`
> Verified (final S20 state): `tsc`, lint, **9 test files / 87 tests**, production build. In the browser against the mock API: 22 tasks load; toggling shows *"Completed: Write quarterly report"*; the logger prints `tasks/fetch/pending` → `tasks/fetch/fulfilled`, `tasks/toggle/pending` → `ui/toastShown` → `tasks/toggle/fulfilled`; a duplicate title (*"write quarterly REPORT"*) shows *"A task with this title already exists."* under the Title field (`aria-invalid="true"`, no toast); deleting navigates back with *"Deleted: Prepare 1:1 notes"*; a failed delete stays on the page with *"Cannot reach the server. Check your connection."*; no serializability warnings.

## 1. The plan

| Delete | Replace with |
|---|---|
| `fetchStarted` / `fetchSucceeded` / `fetchFailed` and the request-id generator `extra.nextRequestId` | `fetchTasks.pending` / `.fulfilled` / `.rejected` and `meta.requestId` |
| `taskAdded` / `taskUpdated` | the `fulfilled` actions of `saveNewTask`, `saveTask`, `saveTaskChanges`, `toggleTaskOnServer` |
| `taskDeleted` / `completedCleared` | `deleteTask.fulfilled` (payload: the id) and `clearCompleted.fulfilled` (payload: the deleted ids) |
| `AppThunk<Promise<Task>>` thunks that **throw** | thunks whose promise **resolves with an action**; callers use `.unwrap()` or `.match()` |
| the hand-written `AppStore` and `AppDispatch` | inferred types (20.02) |
| the `as Reducer<…>` cast in `rootReducer.ts` | nothing: RTK's `combineReducers` infers it once no reducer takes a narrow action union |

The event names change on purpose: `tasks/fetch/fulfilled` says *what happened* just as well as `tasks/fetchSucceeded`, and it's generated.

## 2. ✍️ `src/app/thunk-types.ts`

```ts
import { createAsyncThunk } from '@reduxjs/toolkit';
import type { ThunkAction, UnknownAction } from '@reduxjs/toolkit';
import type * as taskflowApi from '../api';
import type { ApiErrorPayload } from '../api/api-error';
import type { AppDispatch } from './store';
import type { RootState } from './rootReducer';

/**
 * What every thunk receives as `extra` (18.04): the API layer, and the list request in flight.
 * Injected, not imported, so tests can pass fakes.
 */
export interface ThunkExtra {
  /** The whole API layer (api/index.ts): tasks and categories. */
  api: typeof taskflowApi;
  /** The list request in flight, so a newer one can abort it (18.11). One holder PER STORE. */
  listRequest: { controller: AbortController | null };
}

/** A hand-written thunk (still useful for simple "if needed" logic). */
export type AppThunk<R = void> = ThunkAction<R, RootState, ThunkExtra, UnknownAction>;

/**
 * createAsyncThunk with TaskFlow's types filled in once (20.09): getState() is RootState,
 * `extra` is ThunkExtra, and rejectWithValue takes a serialisable ApiErrorPayload.
 */
export const createAppAsyncThunk = createAsyncThunk.withTypes<{
  state: RootState;
  dispatch: AppDispatch;
  extra: ThunkExtra;
  rejectValue: ApiErrorPayload;
}>();
```

`nextRequestId` is gone from `ThunkExtra`: RTK generates the request id. `AppThunk` stays for plain thunks like `fetchTasksIfNeeded`.

## 3. ✍️ `src/features/tasks/tasksThunks.ts`

```ts
// S20: every task I/O operation as createAsyncThunk. Each one generates three action types,
// e.g. 'tasks/fetch/pending' | '…/fulfilled' | '…/rejected', handled in tasksSlice's extraReducers.
import { toApiErrorPayload } from '../../api/api-error';
import type { TaskQuery } from '../../api/tasks';
import type { CreateTaskRequest, UpdateTaskRequest } from '../../domain/api-types';
import type { Task } from '../../domain/types';
import { createAppAsyncThunk } from '../../app/thunk-types';
import type { AppThunk } from '../../app/thunk-types';
import { toastShown } from '../ui/toastActions';

/** Until pagination arrives (S23), the list loads the first 100 tasks: the API's maximum page size. */
const DEFAULT_QUERY: TaskQuery = { size: 100 };

/**
 * Loads the task list. The reducer ignores results from all but the LATEST request, using the
 * `meta.requestId` RTK generates (18.11). The previous request is also aborted, to save work.
 */
export const fetchTasks = createAppAsyncThunk(
  'tasks/fetch',
  // `TaskQuery | void` makes the argument optional: dispatch(fetchTasks()) (a default value alone isn't enough, 20.09)
  async (query: TaskQuery | void, { extra, signal, rejectWithValue }) => {
    extra.listRequest.controller?.abort(); // a newer request supersedes the older one
    const controller = new AbortController();
    extra.listRequest.controller = controller;
    try {
      // Aborted by EITHER a newer fetch (our controller) or the caller's promise.abort() (RTK's signal)
      const page = await extra.api.getTasks(query ?? DEFAULT_QUERY, AbortSignal.any([signal, controller.signal]));
      // The payload creator may read the clock; the reducer may not (15.04): fetchedAt travels in the payload.
      return { tasks: page.items, fetchedAt: Date.now() };
    } catch (error) {
      return rejectWithValue(toApiErrorPayload(error)); // a serialisable payload, not the Error instance
    } finally {
      if (extra.listRequest.controller === controller) extra.listRequest.controller = null;
    }
  },
);

/** How long loaded data counts as fresh for fetchTasksIfNeeded (18.09). */
export const FRESH_FOR_MS = 30_000;

/** Skips the request when a load is already running, or the data is younger than FRESH_FOR_MS. */
export const fetchTasksIfNeeded =
  (now: () => number = Date.now): AppThunk<Promise<void>> =>
  async (dispatch, getState) => {
    const { status, fetchedAt } = getState().tasks;
    if (status === 'loading') return;
    if (fetchedAt !== null && now() - fetchedAt < FRESH_FOR_MS) return;
    await dispatch(fetchTasks());
  };

// ── Writes: fulfilled = what the server returned; rejected = a serialisable ApiErrorPayload ──

/** POST. Components call `dispatch(saveNewTask(r)).unwrap()` to get the Task or catch the payload. */
export const saveNewTask = createAppAsyncThunk(
  'tasks/saveNew',
  async (request: CreateTaskRequest, { extra, rejectWithValue }) => {
    try {
      return await extra.api.createTask(request);
    } catch (error) {
      return rejectWithValue(toApiErrorPayload(error));
    }
  },
);

/** PUT. */
export const saveTask = createAppAsyncThunk(
  'tasks/save',
  async ({ id, request }: { id: number; request: CreateTaskRequest }, { extra, rejectWithValue }) => {
    try {
      return await extra.api.updateTask(id, request);
    } catch (error) {
      return rejectWithValue(toApiErrorPayload(error));
    }
  },
);

/** PATCH (e.g. an inline title edit). */
export const saveTaskChanges = createAppAsyncThunk(
  'tasks/saveChanges',
  async ({ id, changes }: { id: number; changes: UpdateTaskRequest }, { extra, rejectWithValue }) => {
    try {
      return await extra.api.patchTask(id, changes);
    } catch (error) {
      return rejectWithValue(toApiErrorPayload(error));
    }
  },
);

// ── Thunks that report to the user themselves (18.12) ──────────────────────────

/** Toggles DONE ↔ TODO on the server; success/error toasts are dispatched here. */
export const toggleTaskOnServer = createAppAsyncThunk(
  'tasks/toggle',
  async (id: number, { extra, getState, dispatch, rejectWithValue }) => {
    const task = getState().tasks.entities[id];
    if (!task) return rejectWithValue(toApiErrorPayload(new Error(`Task ${id} is not loaded`)));
    const nextStatus = task.status === 'DONE' ? 'TODO' : 'DONE';
    try {
      const saved: Task = await extra.api.patchTask(id, { status: nextStatus });
      if (nextStatus === 'DONE') dispatch(toastShown({ tone: 'success', message: `Completed: ${saved.title}` }));
      return saved;
    } catch (error) {
      const payload = toApiErrorPayload(error);
      dispatch(toastShown({ tone: 'error', message: payload.message }));
      return rejectWithValue(payload);
    }
  },
);

/** Deletes on the server; fulfilled payload = the id (the ui slice uses it too). */
export const deleteTask = createAppAsyncThunk(
  'tasks/delete',
  async (id: number, { extra, getState, dispatch, rejectWithValue }) => {
    const title = getState().tasks.entities[id]?.title ?? `Task ${id}`;
    try {
      await extra.api.deleteTask(id);
      dispatch(toastShown({ tone: 'success', message: `Deleted: ${title}` }));
      return id;
    } catch (error) {
      const payload = toApiErrorPayload(error);
      dispatch(toastShown({ tone: 'error', message: payload.message }));
      return rejectWithValue(payload);
    }
  },
);

/** True when at least one loaded task is DONE. */
const hasCompletedTasks = (state: { tasks: { ids: number[]; entities: Record<number, Task> } }) =>
  state.tasks.ids.some((id) => state.tasks.entities[id]?.status === 'DONE');

/** Deletes every DONE task; fulfilled payload = the ids really deleted (partial failures are reported). */
export const clearCompleted = createAppAsyncThunk(
  'tasks/clearCompleted',
  async (_: void, { extra, getState, dispatch }) => {
    const { ids, entities } = getState().tasks;
    const doneIds = ids.filter((id) => entities[id]?.status === 'DONE');
    const results = await Promise.allSettled(doneIds.map((id) => extra.api.deleteTask(id)));
    const deleted = doneIds.filter((_id, index) => results[index]?.status === 'fulfilled');
    const failed = doneIds.length - deleted.length;
    dispatch(
      failed === 0
        ? toastShown({ tone: 'success', message: `Deleted ${deleted.length} completed task(s).` })
        : toastShown({ tone: 'error', message: `Deleted ${deleted.length}, but ${failed} could not be deleted.` }),
    );
    return deleted;
  },
  // `condition` (20.09): don't even start (no pending action) when there's nothing to clear.
  { condition: (_: void, { getState }) => hasCompletedTasks(getState()) },
);
```

Read it against the S18 version:

1. **Every catch path returns `rejectWithValue(toApiErrorPayload(error))`.** The `ApiRequestError` instance never enters an action; its data does, as a plain object (20.09 §5).
2. **`fetchTasks` no longer checks `isCancelled`.** A cancelled request now produces a `rejected` action with `payload.kind === 'cancelled'` (our abort, via Axios) or `meta.aborted` (RTK's `abort()`). The **reducer** decides that this isn't an error.
3. **`fetchedAt` is in the payload**: the payload creator may read the clock, the reducer may not (15.04).
4. **The write thunks don't dispatch `taskAdded` / `taskUpdated`**: their `fulfilled` action *is* the event. One `addMatcher` in the slice handles all four.
5. **`clearCompleted` has a `condition`**: with nothing DONE, nothing is dispatched at all.
6. `toastShown` is imported from `../ui/toastActions`, a file you create in 20.14. **Until then**, keep importing it from the hand-written `ui` slice; nothing else changes.

## 4. ✍️ `src/features/tasks/tasksSlice.ts` (final for S20)

```ts
// S20: the tasks slice with Redux Toolkit. Same state shape and behaviour as S19; about half the code.
import { createSelector, createSlice, isAnyOf } from '@reduxjs/toolkit';
import type { PayloadAction } from '@reduxjs/toolkit';
import type { Task } from '../../domain/types';
import { denormalize, normalize } from '../../domain/normalize';
import type { Normalized } from '../../domain/normalize';
import type { RootState } from '../../app/rootReducer';
import { loggedOut } from '../auth/authActions';
import {
  clearCompleted,
  deleteTask,
  fetchTasks,
  saveNewTask,
  saveTask,
  saveTaskChanges,
  toggleTaskOnServer,
} from './tasksThunks';

export type LoadStatus = 'idle' | 'loading' | 'succeeded' | 'failed';

/** Normalised since S19: `ids` keep the server's order, `entities` hold each task once. */
export interface TasksState extends Normalized<Task> {
  status: LoadStatus;
  error: string | null;
  /** RTK's `meta.requestId` of the fetch in flight; results of any other fetch are ignored (18.11). */
  currentRequestId: string | null;
  /** When the list was last loaded successfully (epoch ms), for "fetch if needed" (18.09). */
  fetchedAt: number | null;
}

export const initialTasksState: TasksState = {
  ids: [],
  entities: {},
  status: 'idle',
  error: null,
  currentRequestId: null,
  fetchedAt: null,
};

/** Insert or replace one task (Immer: mutate the draft). */
function upsert(state: TasksState, task: Task) {
  if (!state.entities[task.id]) state.ids.push(task.id);
  state.entities[task.id] = task;
}

function removeMany(state: TasksState, ids: readonly number[]) {
  for (const id of ids) delete state.entities[id];
  state.ids = state.ids.filter((id) => !ids.includes(id));
}

const tasksSlice = createSlice({
  name: 'tasks',
  initialState: initialTasksState,
  reducers: {
    /** A local event kept from S15 (the server marked all tasks done). `prepare` supplies the timestamp. */
    allCompleted: {
      reducer(state, action: PayloadAction<{ updatedAt: string }>) {
        for (const id of state.ids) {
          const task = state.entities[id];
          if (task && task.status !== 'DONE') {
            task.status = 'DONE'; // DONE tasks aren't touched, so Immer keeps their identity
            task.updatedAt = action.payload.updatedAt;
          }
        }
      },
      prepare(updatedAt: string = new Date().toISOString()) {
        return { payload: { updatedAt } };
      },
    },
  },
  extraReducers: (builder) => {
    builder
      // ── the list: pending / fulfilled / rejected, generated by createAsyncThunk ──
      .addCase(fetchTasks.pending, (state, action) => {
        state.status = 'loading'; // keep the current tasks visible while reloading
        state.error = null;
        state.currentRequestId = action.meta.requestId; // the NEWEST fetch wins
      })
      .addCase(fetchTasks.fulfilled, (state, action) => {
        if (action.meta.requestId !== state.currentRequestId) return; // stale: ignore (18.10)
        const { ids, entities } = normalize(action.payload.tasks);
        state.ids = ids;
        state.entities = entities;
        state.status = 'succeeded';
        state.currentRequestId = null;
        state.fetchedAt = action.payload.fetchedAt;
      })
      .addCase(fetchTasks.rejected, (state, action) => {
        if (action.meta.requestId !== state.currentRequestId) return;
        state.currentRequestId = null;
        if (action.meta.aborted || action.payload?.kind === 'cancelled') {
          state.status = state.fetchedAt === null ? 'idle' : 'succeeded'; // cancelled on purpose: not an error
          return;
        }
        state.status = 'failed';
        // rejectWithValue's payload carries the server's message; `error` only has a generic one (20.18)
        state.error = action.payload?.message ?? action.error.message ?? 'Unexpected error';
      })
      .addCase(deleteTask.fulfilled, (state, action) => removeMany(state, [action.payload]))
      .addCase(clearCompleted.fulfilled, (state, action) => removeMany(state, action.payload))
      .addCase(loggedOut, () => initialTasksState) // another user may log in next (15.10)
      // ── writes: every thunk whose fulfilled payload is a saved Task (isAnyOf matcher, 20.12) ──
      // (Matchers must come AFTER all addCase calls: the builder enforces that order.)
      .addMatcher(
        isAnyOf(saveNewTask.fulfilled, saveTask.fulfilled, saveTaskChanges.fulfilled, toggleTaskOnServer.fulfilled),
        (state, action) => upsert(state, action.payload),
      );
  },
});

export const { allCompleted } = tasksSlice.actions;
export const tasksReducer = tasksSlice.reducer;

// ── Selectors (unchanged from S19; createSelector now comes from @reduxjs/toolkit) ──
export const selectTaskIds = (state: RootState): number[] => state.tasks.ids;
export const selectTasksStatus = (state: RootState): LoadStatus => state.tasks.status;
export const selectTasksError = (state: RootState): string | null => state.tasks.error;

/** O(1) since S19: a lookup, not a search. */
export const selectTaskById = (state: RootState, id: number): Task | undefined => state.tasks.entities[id];

/** The tasks as an ordered array, memoised: the same array until `ids` or `entities` change (19.02). */
export const selectTasks = createSelector(
  [selectTaskIds, (state: RootState) => state.tasks.entities],
  (ids, entities) => denormalize({ ids, entities }),
);

/** Returns a number (a primitive), so `useSelector` can compare it with === safely (17.04). */
export const selectOpenTaskCount = (state: RootState): number =>
  selectTasks(state).filter((task) => task.status !== 'DONE').length;
```

- The request-id check is the S18 one, reading `action.meta.requestId`.
- **Cancelled ≠ failed:** `meta.aborted` or `payload.kind === 'cancelled'` puts the status back to what it was (`'idle'` before the first load, otherwise `'succeeded'`). Captured after `promise.abort()`: `status: 'idle'`, no error.
- `rejected` reads `action.payload?.message` first; `action.error.message` would be the generic `"Rejected"` (20.18).
- The builder order (all `addCase`, then `addMatcher`) is enforced by RTK (20.07).
- Compared with step 1 (20.06), eight hand-written events are gone; the only reducer left in `reducers` is the local event `allCompleted`.

## 5. The hand-written `ui` slice, until 20.14

The `ui` reducer reacted to `tasks/taskDeleted` and `tasks/completedCleared`, which no longer exist. Thunk lifecycle actions are typed with `type: string` (not a literal), so they can't join the `AppAction` discriminated union. Until you migrate `ui` in 20.14, test them with `.match()` **before** the `switch` (verified with `tsc`):

```ts
export function uiReducer(state: UiState = initialUiState, incoming: UnknownAction): UiState {
  // Thunk lifecycle actions are typed `type: string`: they can't join a discriminated union. Match them first.
  if (deleteTask.fulfilled.match(incoming)) return removeFromSelection(state, [incoming.payload]);
  if (clearCompleted.fulfilled.match(incoming)) return removeFromSelection(state, incoming.payload);
  const action = incoming as AppAction; // temporary, until this slice uses createSlice (20.14)
  switch (action.type) {
    // … the S18 cases, unchanged
  }
}
```

The `as` is a known, temporary compromise, and `createSlice` removes it. Taking `UnknownAction` also means `rootReducer`'s cast can go now for this slice.

## 6. Callers: from try/catch-on-throw to `.unwrap()` and `.match()`

### Forms: `.unwrap()`

`src/pages/NewTaskPage.tsx`:

```tsx
import { useNavigate } from 'react-router';
import { EMPTY_TASK_FORM, hasErrors, pickFormErrors, toCreateRequest } from '../domain/task-form';
import type { TaskFormValues } from '../domain/task-form';
import { toErrorMessage } from '../domain/guards';
import { fieldErrorsOf } from '../api/api-error';
import { useAppDispatch } from '../app/hooks';
import { saveNewTask } from '../features/tasks/tasksThunks';
import { useToast } from '../toast/toast-context';
import { TaskForm } from '../components/TaskForm';

export function NewTaskPage() {
  const dispatch = useAppDispatch();
  const { show } = useToast();
  const navigate = useNavigate();

  async function handleSubmit(values: TaskFormValues) {
    try {
      // unwrap(): resolve with the created Task, or throw the rejection payload (20.09)
      const created = await dispatch(saveNewTask(toCreateRequest(values))).unwrap();
      show({ tone: 'success', message: `Created: ${created.title}` });
      // replace: the form page shouldn't stay in history (Back would re-open a submitted form)
      navigate(`/tasks/${created.id}`, { replace: true });
    } catch (error) {
      // A 400 with field errors (e.g. duplicate title) → show them in the form, not in a toast (19.09).
      // unwrap() rejects with the rejectWithValue payload: a plain ApiErrorPayload (20.09)
      const fieldErrors = pickFormErrors(fieldErrorsOf(error) ?? {});
      if (hasErrors(fieldErrors)) return fieldErrors;
      show({ tone: 'error', message: toErrorMessage(error) });
    }
  }

  return (
    <>
      <h1 className="page__title">New task</h1>
      <TaskForm mode="create" initialValues={EMPTY_TASK_FORM} onSubmit={handleSubmit} onCancel={() => navigate(-1)} />
    </>
  );
}
```

`EditTaskPage` is the same with `saveTask({ id, request })`. Note the **single object argument**: a thunk takes exactly one argument, so `saveTask(id, request)` from S18 becomes `saveTask({ id, request })`.

`fieldErrorsOf(error)` works for both shapes the catch may receive: the `ApiErrorPayload` from `rejectWithValue`, or (for an unexpected throw) a `SerializedError`, which simply has no field errors.

### Delete: `.match()`

```ts
const result = await dispatch(deleteTask(current.id));
if (deleteTask.fulfilled.match(result)) navigate(backHref, { replace: true }); // the deleted URL leaves history
else setIsDeleting(false);
```

The S18 version was `if (await dispatch(deleteTask(id)))`, because the old thunk resolved to `true` or `false`. With RTK, the result is always an **action object**, so it's always truthy: without `.match()`, a failed delete would navigate away as if it had worked. Verified: with the DELETE request failing, the page stays, the button re-enables, and the error toast appears.

### The inline title edit: `.unwrap()` for the error toast

```ts
await dispatch(saveTaskChanges({ id, changes: { title } })).unwrap();
```

inside the existing `try / catch` that shows the error toast.

## 7. Tests: what changed and why

The 87 tests pass. The edits, all expected:

| Test | Edit | Reason |
|---|---|---|
| reducer tests | `fetchStarted('r1')` → `fetchTasks.pending('r1', undefined)`, etc. | the lifecycle creators can build actions for tests (20.09 §11) |
| "an API error becomes a failure" | the resolved value is a `rejected` action; its `payload` carries `status` and the server message | thunks don't throw any more |
| `saveNewTask` rejects | `await expect(dispatch(saveNewTask(r)).unwrap()).rejects.toMatchObject({ status: 400, fieldErrors: { title: 'taken' } })` | `unwrap()` throws the payload |
| `clearCompleted` with nothing DONE | `clearCompleted.rejected.match(skipped) && skipped.meta.condition` is `true` | `condition` (20.09 §7) |
| "one action, several slices" | `taskDeleted(5)` → `deleteTask.fulfilled(5, 'req', 5)` | the event was renamed |

## 8. Line counts: an honest comparison

Measured on the files involved (the "code" column ignores blank lines and comments):

| Area | Raw lines before → after | Code lines before → after |
|---|---|---|
| `tasksSlice.ts` | 165 → 130 | 128 → 105 |
| `tasksThunks.ts` | 142 → 149 | 112 → 114 |
| `listPrefsSlice.ts` | 46 → 47 | 38 → 37 |
| `uiSlice.ts` + `toastActions.ts` | 62 → 67 | 50 → 51 |
| `categoriesSlice.ts` + `categoriesThunks.ts` | 93 → 97 | 73 → 73 |
| wiring: `store`, `rootReducer`, `thunk-types`, `app-action`, `authActions` | 121 → 96 | 78 → 63 |
| **Total** | **629 → 586** | **479 → 443** (−7.5 %) |

(The `ui` and `categories` rows include the 20.14 exercise, so the table shows the finished migration.)

**Only 7.5 % fewer lines.** RTK tutorials often show a large reduction, because they start from code without types, without request ids and without careful "same state when unchanged" checks. TaskFlow's hand-written code was already dense. The thunks even grew, because each one now has an explicit `try / catch` with `rejectWithValue`.

What RTK removed isn't mostly lines. It's **places to make a mistake**:

- no action type string written twice; no hand-written unions to keep in sync;
- no spreads: a forgotten spread can't mutate state, and mutations are caught at runtime in development;
- the request id, abort and the three lifecycle actions are generated and consistent across every operation;
- three typing workarounds deleted: the `combineReducers` cast (16.03), the hand-written `AppStore` (18.08), and the `AppAction` union (15.07, deleted in 20.15);
- dev-time checks for non-serialisable values and misused action creators.

Measure your own migrations the same way, and argue for RTK with these reasons, not with a line count.
