# Lecture 08.15 · 🎯 Your Turn: Inline Title Editing via the Reducer

> **Section:** S08 · **Type:** 🎯 Your Turn · **Track:** ★ Core · **Time:** ~60 minutes

---

## 1. The task

Let users rename a task directly on its card:

- An **Edit** button (and double-click on the title) switches the title into an input.
- **Enter** or leaving the field (**blur**) saves; **Escape** cancels.
- The input is **focused and its text selected** when editing starts.
- An empty or whitespace-only title is **not** saved (the old title stays).
- Titles are trimmed before saving.
- Works in both the list and the board view.

## 2. Architecture requirements

1. Add a **`titleEdited`** action to `TasksAction` in `tasks-reducer.ts`. The reducer's `switch` must stay **exhaustive** (`assertNever` in `default`). Try compiling **before** adding the `case` and read the error.
2. Validation (trim, reject empty) belongs in the **reducer**, not the component. Why? (Think: which one is pure and testable, and which one will become a Redux slice?)
3. `useTasks` exposes `editTitle(id, title)` (stable, via `useCallback`).
4. The **draft** text while editing is **local component state** in `TaskCard`, not in the reducer. Why? (Hint: 07.13, and the Redux style guide's "form state stays local" rule in S17.)
5. Use a **ref** + **effect** for focus/select (08.06).
6. Use the existing `updateTaskField` (06.02) inside the reducer.

## 3. Acceptance

- [ ] Rename a task; it's renamed in both views.
- [ ] Escape leaves the title unchanged.
- [ ] Saving `"   "` keeps the old title.
- [ ] `npm run build` and `npm run lint` pass.

## 4. Hints

<details>
<summary>Hint 1: the action and the case</summary>

`| { type: 'titleEdited'; id: number; title: string }`. In the reducer: guard `state.status !== 'succeeded'`, trim, return `state` unchanged if empty, otherwise `updateTaskField(state.data, action.id, 'title', title)`.
</details>

<details>
<summary>Hint 2: starting from the right draft</summary>

Set the draft from `task.title` **when editing starts** (in the handler), not with an effect watching `task.title` (08.05, anti-pattern 3).
</details>

<details>
<summary>Hint 3: focus</summary>

`const inputRef = useRef<HTMLInputElement>(null);` then `useEffect(() => { if (isEditing) inputRef.current?.select(); }, [isEditing]);`. `select()` also focuses.
</details>
