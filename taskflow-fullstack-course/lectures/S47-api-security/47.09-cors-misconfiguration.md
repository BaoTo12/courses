# Lecture 47.09 · 🔓 A Misconfigured CORS: Reflecting Any Origin with Credentials (Conceptual)

> **Section:** S47 · **Type:** 🔓 Attack Lab (conceptual) · **Track:** ★ Core · **Time:** ~15 minutes

---

## 1. The misconfiguration

A developer fighting "CORS errors" during development writes:

```java
response.setHeader("Access-Control-Allow-Origin", request.getHeader("Origin"));   // ❌ echo whatever asks
response.setHeader("Access-Control-Allow-Credentials", "true");
```

Browsers refuse `*` with credentials, so echoing the `Origin` "fixes" the error. It also grants **every** website the right to read TaskFlow's API responses with the visitor's session.

## 2. What that allows

A logged-in TaskFlow user visits any page that contains a script calling `GET /api/tasks` with `credentials: "include"`:
- the browser attaches `JSESSIONID` (for cross-site `fetch`, only if the cookie isn't `SameSite=Lax/Strict`, which is why the misconfiguration usually comes with `SameSite=None`);
- the server answers with the user's tasks **and** `Access-Control-Allow-Origin: <that page's origin>`;
- the browser lets the page's script read the JSON: the user's data has left the site.

The same pattern with `/api/auth/me` leaks identity; with a preflight approved for any origin, write requests go through too (only the CSRF header stands in the way, and a script that can read responses can often obtain it).

## 3. Variants to recognise

| Variant | Why it fails |
|---|---|
| allowing `Origin: null` | sandboxed iframes and some redirects send `null`: attackers can produce it |
| suffix or prefix checks (`endsWith("taskflow.example")`) | `eviltaskflow.example` matches |
| regexes without anchors or with unescaped dots | `taskflow.example.evil.net` |
| trusting every subdomain | one vulnerable subdomain reads everything |

## Lesson

CORS with credentials must name **exact** origins from a fixed list. 47.10 builds that.
