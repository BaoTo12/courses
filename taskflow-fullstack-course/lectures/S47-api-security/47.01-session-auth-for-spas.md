# Lecture 47.01 · Session Auth for SPAs: The Browser Holds `JSESSIONID`; the SPA Asks `/me`

> **Section:** S47 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~20 minutes

---

## 1. The model TaskFlow uses (decided in S24)

| Piece | Where | Who can read it |
|---|---|---|
| `JSESSIONID` | an `HttpOnly` cookie | the **browser** sends it; **no JavaScript** can read it (41.12) |
| the logged-in user | the server's session (`AuthUser`) | the server |
| "who am I?" | `GET /api/auth/me` → `UserDto` or 401 | the SPA, after every page load |
| `XSRF-TOKEN` | a **readable** cookie | the SPA copies it into `X-XSRF-TOKEN` (47.05) |

The React app never handles a credential after the login form: it can't leak one in an XSS, localStorage or a log.

## 2. The flow

```text
app start      GET  /api/auth/me          → 401 (not logged in)      → show the login page
               GET  /api/auth/csrf        → 204 + Set-Cookie XSRF-TOKEN=abc   (readable)
login          POST /api/auth/login       X-XSRF-TOKEN: abc  {"username","password"}
                                          → 200 UserDto + Set-Cookie JSESSIONID=…; HttpOnly   (+ a new XSRF-TOKEN)
every call     GET  /api/tasks            Cookie: JSESSIONID=…; XSRF-TOKEN=…   → 200
               PATCH /api/tasks/5         + X-XSRF-TOKEN: …                    → 200
reload         GET  /api/auth/me          → 200 UserDto (the session is still there)
logout         POST /api/auth/logout      → 204, the session is gone
```

## 3. Versus tokens in JavaScript (JWT in localStorage)

| | Session cookie (TaskFlow) | Bearer token in JS storage |
|---|---|---|
| XSS can steal it | ❌ HttpOnly | ✅ any script reads `localStorage` |
| CSRF | ✅ possible: cookies are sent automatically → needs a CSRF defence | ❌ not sent automatically |
| logout / revocation | server-side: `invalidate()` | the token stays valid until it expires (unless the server keeps a deny-list) |
| server state | a session per user | none (for signed tokens) |
| across domains / mobile apps | cookies are per site | works anywhere |

For a browser app served with its API, a session cookie + CSRF protection is the simpler and safer default. Tokens fit third-party clients and mobile apps.

## 4. One session, two clients

The API login stores the **same** `AuthUser` under the same key as the Admin Portal's login, so logging in through React also opens the JSP pages, and logging out in either ends both (`S47ApiSecurityTest.theSpaLoginFlowSharesTheSessionWithThePortal`).

## ✅ Recap

The browser keeps the session id where scripts can't reach it; the SPA learns who it is by asking the server.
