# Lecture 47.13 · 🎯 Your Turn: An Audit Event for Every API 401/403, with the Request Id

> **Section:** S47 · **Type:** 🎯 Your Turn · **Track:** ★ Core · **Time:** ~30 minutes

## Requirements

1. Every 401 and 403 answered by `/api/*` writes an `ACCESS_DENIED` audit event with the username (if any), the IP, and the details `403 CSRF_TOKEN_INVALID DELETE /api/tasks/23 [request 5f3a9c1e2b7d4a60]`.
2. The request id is the one in the `X-Request-Id` response header and in the application log's `[…]` (40.06).
3. One place in the code, whichever filter or servlet produced the 401/403.
4. The SPA's normal startup probe (an anonymous `GET /api/auth/me` → 401) is **not** logged: it happens on every visit.

**Test:** bob sends `DELETE /api/tasks/23` without the CSRF header → 403; an audit row exists for bob whose details end with `[request <the X-Request-Id value>]`.
