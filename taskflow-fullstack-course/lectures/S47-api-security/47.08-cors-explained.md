# Lecture 47.08 · CORS Explained Properly

> **Section:** S47 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~30 minutes
> Verified: `S47ApiSecurityTest.corsAllowsOnlyTheListedOrigin`

---

## 1. The same-origin policy (the default)

An **origin** is scheme + host + port: `http://localhost:5173` ≠ `http://localhost:8080`. A page's JavaScript may **send** requests to other origins, but may **not read** their responses, unless the other origin says so. That rule protects the user: a random site can't read your mail by calling your webmail with your cookies.

## 2. CORS: the other origin's permission

**Cross-Origin Resource Sharing** is how a server grants that permission, with response headers the **browser** checks.

| Header (response) | Meaning |
|---|---|
| `Access-Control-Allow-Origin: http://localhost:5173` | this origin's scripts may read the response (`*` = anyone, **not allowed** together with credentials) |
| `Access-Control-Allow-Credentials: true` | … even when the request carried cookies |
| `Access-Control-Allow-Methods`, `-Allow-Headers` | (preflight) what the real request may use |
| `Access-Control-Max-Age` | (preflight) cache the answer, in seconds |
| `Access-Control-Expose-Headers` | response headers the script may read beyond the basic ones (`Location`, `X-Request-Id` need it) |
| `Vary: Origin` | the response differs per `Origin`: caches must key on it |

## 3. Simple vs preflighted requests

| Simple (sent directly; the browser only decides whether the script may **read** the answer) | Preflighted (the browser asks first with `OPTIONS`) |
|---|---|
| GET, HEAD, POST | PUT, PATCH, DELETE, … |
| only "safe" headers | any custom header (`X-XSRF-TOKEN`) |
| `Content-Type` form, multipart or `text/plain` | `application/json` |

```text
OPTIONS /taskflow/api/tasks/5
Origin: http://localhost:5173
Access-Control-Request-Method: PATCH
Access-Control-Request-Headers: content-type,x-xsrf-token
                                                   → 204 + Allow-Origin/Credentials/Methods/Headers   → then the PATCH
```

## 4. What CORS is **not**

| Myth | Reality |
|---|---|
| "CORS protects my API from other clients" | curl, Postman, servers and scripts outside browsers **ignore** CORS. `S47ApiSecurityTest` shows `evil.example`'s request answered 200, just without the header that would let a **browser** script read it |
| "CORS is authentication" | it's a browser permission about **reading** responses; authentication and CSRF tokens still decide what's allowed |
| "a simple request is blocked if CORS fails" | it's **sent** and executed; only reading the response is blocked. That's why simple cross-site POSTs are a CSRF concern (47.05) |
| "`Allow-Origin: *` is fine" | for public, cookie-less data, yes; with credentials, browsers reject it, and reflecting the Origin instead is the classic misconfiguration (47.09) |

## ✅ Recap

The same-origin policy protects users; CORS relaxes it for the origins you list. It governs what browser scripts may read, not who may call your server.
