# Lecture 47.05 · CSRF for SPAs: Why a Hidden Field Doesn't Fit; the Double-Submit Cookie

> **Section:** S47 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~20 minutes

---

## 1. The threat is the same

The API uses a **cookie** session, so a request from any site carries `JSESSIONID` (subject to `SameSite`, 41.12). A malicious page could try to change tasks with the victim's session (37.12).

## 2. Why the Admin Portal's defence doesn't fit

| Synchroniser token (S37) | For an SPA |
|---|---|
| the server renders the token into every **form** (`<input name="_csrf">`) | the SPA's HTML is static (Vite build): the server renders nothing |
| the token lives in the **session** | the SPA needs a token **before** login (the login POST itself must be protected: "login CSRF") |
| sent as a form field | the SPA sends JSON; the natural place is a **header** |

## 3. The double-submit cookie

```text
server:  Set-Cookie: XSRF-TOKEN=<random>; Path=/; SameSite=Lax      (NOT HttpOnly)
SPA:     reads the cookie (js-cookie, S24) → header X-XSRF-TOKEN: <random> on POST/PUT/PATCH/DELETE
server:  cookie value == header value ?  → continue  :  403 CSRF_TOKEN_INVALID
```

- The **server stores nothing**: it compares two copies the client sent.
- An attacker's page makes the browser send the **cookie**, but it can't **read** it (another origin's cookies are invisible to its scripts) and so can't produce the matching **header** (47.07).
- Axios does this automatically (`xsrfCookieName: 'XSRF-TOKEN'`, `xsrfHeaderName: 'X-XSRF-TOKEN'`); TaskFlow's React app does it explicitly in an interceptor (S24).

## 4. Hardening options (for recognition)

| Weakness | Hardening |
|---|---|
| an attacker who can **set** cookies for your site (a compromised subdomain, 41.10) can plant a cookie and send the same value in the header | **signed** double submit: the token is an HMAC of the session id; or the `__Host-` cookie prefix (41.12) |
| none of this helps against XSS | XSS can read the cookie and send the header: XSS defences (S26, S35) remain essential |

TaskFlow's layers: `SameSite=Lax` + JSON-only bodies (46.07) + CORS allow-list (47.10) + double submit.

## ✅ Recap

A readable cookie plus an echoed header proves the request came from a page that can read your cookies, which means your own origin.
