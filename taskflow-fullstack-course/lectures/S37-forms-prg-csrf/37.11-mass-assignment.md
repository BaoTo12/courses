# Lecture 37.11 · 🛡 Mass Assignment: Only Copy the Fields You Expect

> **Section:** S37 · **Type:** 🛡 Defend · **Track:** ★ Core · **Time:** ~15 minutes
> Verified: `S37FormsTest.editIsPrefilledAndSavesOnlyTheFormFields` (the POST adds `ownerId=2&status=DONE`: the owner stays Alice, the status stays TODO)

---

## 1. The flaw

"Binding" code that copies **every** request parameter onto an object:

```java
for (Map.Entry<String, String[]> p : request.getParameterMap().entrySet()) {
  BeanUtils.setProperty(task, p.getKey(), p.getValue()[0]);   // ❌ title, priority… and ownerId, id, status, createdAt
}
```

The form only shows five fields, but the request can contain anything. An extra `ownerId=2` moves the task to Bob, and `role=ADMIN` on a profile form makes you an admin. Frameworks with automatic binding (Spring MVC's `@ModelAttribute`, Rails, many ORMs) are known for this bug when used carelessly. GitHub was famously compromised through it in 2012.

## 2. TaskFlow's defence

| Where | How |
|---|---|
| `TaskForm.from(request)` | reads exactly five named parameters; anything else is ignored |
| `TaskForm.applyTo(task)` | copies exactly those five onto the task |
| create | `task.setOwnerId(1)`: the server decides (S41: the session's user) |
| edit | starts from the **stored** task: id, owner, status and timestamps come from the database |

## 3. The general rule

Use an **allow-list** of fields per form (a form object, a DTO), never "copy whatever came in". Fields that matter for security (owner, role, price, status, ids of other objects) come from the server's state, never from the form, even as hidden fields.

## ✅ Recap

A request can carry any parameter. Bind only the fields that form is meant to change, and take everything else from the server.
