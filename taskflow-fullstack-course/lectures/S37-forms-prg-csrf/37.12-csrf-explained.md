# Lecture 37.12 · 🔓 CSRF: Why a Logged-In Browser Can Be Tricked Into Posting

> **Section:** S37 · **Type:** 🔓 Attack Lab (conceptual) · **Track:** ★ Core · **Time:** ~20 minutes
> Verified: `S37FormsTest.postsWithoutTheRightTokenAreRefused` (a POST without the token, or with a wrong one → 403, nothing changed)

---

## 1. The ingredients

Cross-Site Request Forgery needs three things, and before S37 TaskFlow had all three:

| Ingredient | TaskFlow before S37 |
|---|---|
| a state-changing request that is **predictable** | `POST /taskflow/tasks/delete` with `id=7`: nothing secret in it |
| authentication by something the **browser adds automatically** | the session cookie (from S38/S41 on: "logged in as admin") |
| a victim who visits **another** page while logged in | any web page, email or ad |

## 2. How it works, conceptually

Any web page can contain a form whose `action` points to **another** site, and submit it with script. The browser sends the request to TaskFlow **with TaskFlow's cookies**, because cookies go with requests to their site, whoever triggered them. TaskFlow sees a valid session and a well-formed POST, and can't tell that the user never clicked anything on TaskFlow.

What the attacker **can't** do: read TaskFlow's response or pages. The same-origin policy blocks that. So the attack is "write-only": the attacker must know every parameter in advance.

## 3. What doesn't protect you

| Idea | Why it fails |
|---|---|
| "we only accept POST" | cross-site forms can POST |
| "the endpoint needs a login" | the victim's browser **is** logged in: that's the whole attack |
| a confirmation dialog in JavaScript | the forged request doesn't go through your page's JavaScript |
| checking `Referer` only | sometimes missing (privacy settings); useful as an extra, not alone |
| HTTPS | protects the connection, not who triggered the request |

## 4. The fix

A value the attacker **can't know**, required on every state-changing request: the synchroniser token (37.13). A second layer is to stop the browser sending the cookie on cross-site requests: `SameSite` (37.14).

(TaskFlow Web, the React app, uses the double-submit variant with the `XSRF-TOKEN` cookie and the `X-XSRF-TOKEN` header, 24.10. It's the same idea: a value only your own pages can read.)

## Lesson

Cookies prove **which browser** sent a request, not **which page** made it. State-changing requests need proof that they came from your own page.
