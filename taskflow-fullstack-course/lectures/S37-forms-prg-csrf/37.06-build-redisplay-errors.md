              <option${p.name() == form.priority ? ' selected' : ''}>${p}</option>
            </c:forEach>

## The patterns, one by one

| Pattern | Code | Why |
|---|---|---|
| error class on the field | `class="form-field${empty errors.title ? '' : ' form-field--error'}"` | CSS highlights the field (a value choice: a ternary, 34.11) |
| error message | `<c:if test="${not empty errors.title}"><span …><c:out value="${errors.title}"/></span></c:if>` | rendered only when there's an error |
| old value in an input | `value="${fn:escapeXml(form.title)}"` | the user's own text goes back into an **attribute**: escape it (35.16); the test sends `"><b>x</b>` |
| old value in a textarea | `<textarea …><c:out value="${form.description}"/></textarea>` | text content: `<c:out>` |
| selected option | `<option${p.name() == form.priority ? ' selected' : ''}>` | compares **strings**, see below |
| hidden id (edit only) | `<c:if test="${not empty taskId}"><input type="hidden" name="id" …>` | which task to update; the servlet re-checks that it exists |
| CSRF token | `<input type="hidden" name="_csrf" value="${csrfToken}">` | 37.13 |

## Why `p.name() == form.priority` and not `p == form.priority`

`form.priority` is what the user sent: it can be `"URGENT"`. Comparing it with an **enum**, EL converts the string to the enum (34.13), and `"URGENT"` isn't one, which is an `ELException` and a 500 on the very page meant to show "must be one of LOW, MEDIUM, HIGH". Comparing two strings can't fail. The same goes for the category: `category.id.toString() == form.categoryId`, where the form value can be `"abc"`.

**Rule:** a form bean holds **untrusted strings**. Compare them as strings in the view.

## ✅ Checkpoint

`mvn package` → green. Submit `priority=URGENT` with `curl` (with a valid token and cookie, or temporarily through DevTools): 400, and the form shows the error instead of crashing.
