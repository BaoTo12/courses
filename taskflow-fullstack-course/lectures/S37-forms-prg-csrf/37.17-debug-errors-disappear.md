# Lecture 37.17 · 🐞 Debug: Validation Errors Disappear After Submit

> **Section:** S37 · **Type:** 🐞 Debug · **Track:** ★ Core · **Time:** ~15 minutes

---

## 1. Symptom

Submitting the task form with an empty title shows the form again, **empty**, with no error message. The server log shows the validation ran.

## 2. The code

```java
if (!errors.isEmpty()) {
  request.setAttribute("errors", errors);
  request.setAttribute("form", form);
  response.sendRedirect(request.getContextPath() + "/tasks/new");   // ❌ "PRG everywhere"
  return;
}
```

## 3. Investigate

Network tab:

```text
POST /taskflow/tasks/new    302  Location: /taskflow/tasks/new
GET  /taskflow/tasks/new    200  (a NEW request: no "errors", no "form" attributes)
```

The attributes were set on the POST's request, which ended with the redirect (31.06). The GET is a fresh request, and its controller shows an empty form.

## 4. Fix

On failure, **forward** (with 400); on success, **redirect** (37.05, 37.08):

```java
response.setStatus(HttpServletResponse.SC_BAD_REQUEST);
TaskFormPage.show(request, response, service, form, errors, null);
```

(Frameworks that *do* redirect after validation errors carry the errors and values through the session, like a flash, but it's more machinery for no real gain.)

## ✅ Takeaway

PRG is for **success**. Errors must be shown in the same request that detected them.
