# Lecture 37.18 · 🐞 Debug: the Flash Message Appears Twice, or Never

> **Section:** S37 · **Type:** 🐞 Debug · **Track:** ★ Core · **Time:** ~15 minutes

---

## Variant A: it appears twice (or on every page)

```jsp
<%-- header, reading the session directly --%>
<c:if test="${not empty sessionScope.flash}"><p class="flash">${sessionScope.flash}</p></c:if>
```

Nothing ever **removes** it, so it stays until the session ends. Or it's removed in the wrong place: after the redirect **and** on a page that runs twice (an `<jsp:include>` of the header, or a favicon/asset request routed through a servlet that doesn't consume it).

**Fix:** one place moves it from the session to the request and removes it: `Flash.consume()`, called by the GET controller of the page that shows it.

## Variant B: it never appears

| Cause | Check |
|---|---|
| the target page's controller doesn't call `Flash.consume` | the message waits in the session and appears on some **later** page, which is confusing |
| it was put in a **request** attribute before the redirect | gone with the request (37.17's mechanism) |
| consumed by an **intermediate** request: the redirect goes to a URL that redirects again (e.g. `/tasks/` → `/tasks`), and the first GET consumed it | the Network tab shows two GETs |
| `Flash.put` was called, but then an exception led to an error page | the server log |
| the session changed between POST and GET (S41: a new session at login, a different host name, cookies blocked) | compare `JSESSIONID` in both requests |
| the view reads `${sessionScope.flash}` in a `session="false"` page | 34.25: that throws |

## ✅ Takeaway

A flash must be read **exactly once**, by the page right after the redirect. Put it in the session, and take it out in one well-defined place.
