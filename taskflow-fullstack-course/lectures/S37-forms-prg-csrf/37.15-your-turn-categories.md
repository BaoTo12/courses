## Requirements

**Pages and actions:**

| Request | Result |
|---|---|
| `GET /categories` | every category (by name) with its task count; per row: a form to rename/recolour and a Delete button; below: a "New category" form |
| `POST /categories/save` without `id` | create |
| `POST /categories/save` with `id` | rename/recolour |
| `POST /categories/delete` | delete, **unless** tasks use it |

**Rules:**
1. Name: required, trimmed, at most 50 characters, unique (case-insensitively: "work" = "Work").
2. Colour: `#rrggbb` (what `<input type="color">` sends).
3. A category used by tasks is **not** deleted. The list shows a flash: `Category "Work" is used by 6 tasks: move them to another category first.`
4. Invalid or duplicate → 400, the list again with the errors (a new-category form keeps its values).
5. Every success → flash + **303** → `/categories`.
6. Every POST needs the CSRF token (403 otherwise). A link "Categories" in the header.

**📦 Provided:** the data layer already has `CategoryDao.insert/update/delete/countTasksByCategory` (a duplicate name → `DuplicateKeyException`). You write a `CategoryService` (the "in use" rule belongs there), a `CategoryForm`, three servlets, and `categories/list.jsp`. Register the service in `AppContextListener`.

**Tests to write first:** the list shows counts; create → 303 → flash → listed; rename; delete an unused one; delete "Work" is refused with the message and it's still listed; "work" → 400 "already exists"; blank name and colour `red` → 400 with both messages; delete without a token → 403.

## Hints

- The task count per category is a `Map<Long, Integer>`. In the view, `${counts[category.id] + 0}` prints 0 for a category that's absent from the map (34.10, 34.13).
- The "in use" refusal isn't a form-field error: it's the outcome of an action. So PRG with a flash, not a 400 page.
- Put the category's name in the flash message **with** `<c:out>` in the header: it's user text (it already is).
