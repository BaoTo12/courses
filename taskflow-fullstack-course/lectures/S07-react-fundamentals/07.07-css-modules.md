# Lecture 07.07 · CSS Modules: Hashed Class Names, `:global`, and Global vs Local Styles

> **Section:** S07 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~20 minutes

---

## 1. The problem CSS Modules solve

Global CSS has one namespace (03.09). BEM is a **convention** that avoids collisions. CSS Modules make collisions **impossible by construction**: every class name in a `*.module.scss` file is **renamed to a unique, file-specific name** at build time.

## 2. How it works

```scss
/* TaskCard.module.scss */
.badges { display: flex; }
```

```tsx
import styles from './TaskCard.module.scss';
<div className={styles.badges}>…</div>
```

At build time, Vite:
1. Compiles the SCSS to CSS.
2. Renames each class to a unique name, e.g. `.badges` → `._badges_hcaju_1` (verified in this course's reference app via DevTools).
3. Emits the CSS with the renamed selectors.
4. Makes the import return an object mapping **original → generated** names: `{ badges: '_badges_hcaju_1', due: '…' }`.

So `styles.badges` is just a string, and two different modules can both have `.title` without conflict. The naming is an implementation detail; never hard-code generated names.

## 3. Global vs local in one file: `:global`

Sometimes a module needs to target a **global** class, such as the design system's `.btn`:

```scss
/* FilterBar.module.scss */
@use '@styles/abstracts' as *;

.bar {
  display: flex;
  flex-wrap: wrap;
  gap: space(2);

  // The design system's `.btn + .btn` margin is for inline buttons; a flex row uses gap.
  :global(.btn) + :global(.btn) {
    margin-left: 0;
  }
}
```

`:global(.btn)` means "don't rename this class". The compiled selector (from the actual production build) is `._bar_1n9bi_1 .btn+.btn{margin-left:0}`: scoped by the local `.bar`, targeting global `.btn`s inside it. That's a clean way to adapt shared components in one specific context.

## 4. TypeScript and `*.module.scss`

`import styles from './X.module.scss'` type-checks because the template's `"types": ["vite/client"]` declares CSS module files as an index signature, `{ readonly [key: string]: string }`. Consequences:
- **Any** property name is accepted: `styles.typo` compiles, and at runtime it's `undefined`, so no class is applied and nothing warns you.
- With `noUncheckedIndexedAccess` (our setting), each lookup is typed `string | undefined`. `className={styles.badges}` is fine (className accepts `undefined`), but assigning to a `string` variable fails: `Type 'string | undefined' is not assignable to type 'string'` (verified).

If you want per-class checking, there are plugins that generate a `.d.ts` per module. Many teams live with the risk and catch typos visually or in code review.

## 5. CSS Modules vs BEM vs styled-components

| | Global BEM (`styles/`) | CSS Modules | styled-components (S09) |
|---|---|---|---|
| Scoping | Convention | Automatic (renamed classes) | Automatic (generated classes) |
| Runtime cost | None | None (build time) | Runtime CSS generation |
| Dynamic values from props | Via modifiers/custom properties | Via modifiers/custom properties | Direct interpolation `${p => …}` |
| Usable from JSP | ✅ | ❌ (names only known to the JS bundle) | ❌ |
| TaskFlow uses it for | Shared components | React-only structure | Prop-driven components |

## 6. Summary

- CSS Modules rename classes per file at build time, and the import gives you a name map.
- `:global(.x)` targets global classes from inside a module.
- They're a build-time, zero-runtime scoping tool, and they only exist for the JS bundle.
