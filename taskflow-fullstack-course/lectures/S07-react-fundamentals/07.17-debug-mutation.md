# Lecture 07.17 · 🐞 Debug: "I Clicked, State Changed, but the UI Didn't Update"

> **Section:** S07 · **Type:** 🐞 Debug · **Track:** ★ Core · **Time:** ~15 minutes

---

## Symptom

A teammate adds a "Mark all done" button:

```tsx
function handleCompleteAll() {
  for (const task of tasks) {
    task.status = 'DONE';
  }
  setTasks(tasks);
  console.log(tasks.every((t) => t.status === 'DONE'));   // true!
}
```

The console prints `true`, but **nothing changes on screen**. Then, after they click a filter button (any unrelated state change), suddenly all badges show "Done".

## Investigation checklist

1. What does `setTasks` compare the new value with? (07.08)
2. Is `tasks` after the loop a new array or the same one?
3. Why does an **unrelated** re-render (filter click) suddenly reveal the change?
4. What does React DevTools show for `App`'s `tasks` state before the filter click?

## Explanation

- The loop **mutates** the task objects inside the **same** array.
- `setTasks(tasks)` passes the **same reference** that's already in state. React checks `Object.is(tasks, tasks)` → `true` → **bails out** (no re-render).
- The data *did* change in memory, so when anything else triggers a render (the filter click), the components read the mutated objects and the change "appears". That's the confusing part: the bug looks intermittent.
- It's worse than "no update": the previous state was **destroyed**. Any memoised component, selector or undo history holding the old objects now sees the new values (04.16).

**Fix:** create new data:

```tsx
function handleCompleteAll() {
  setTasks((current) =>
    current.map((task) => (task.status === 'DONE' ? task : { ...task, status: 'DONE' })),
  );
}
```

- New array → re-render.
- New objects only for tasks that changed → unchanged tasks keep their identity (useful for `React.memo` later, S21).

## How to catch this class of bug earlier

- TypeScript can help, but only if you ask for deep enough readonly-ness. `useState<readonly Task[]>` stops `tasks.push(…)`, but **not** `task.status = …`, because a readonly *array* doesn't make its *elements* readonly. `useState<ReadonlyArray<Readonly<Task>>>` makes both lines compile errors (`Cannot assign to 'status' because it is a read-only property`).
- Tests with frozen fixtures (04.06).
- In Redux Toolkit, development-mode immutability checks throw on exactly this (S20).
