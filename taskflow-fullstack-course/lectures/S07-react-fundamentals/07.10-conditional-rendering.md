# Lecture 07.10 · Conditional Rendering and the `&&` + `0` Gotcha

> **Section:** S07 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~15 minutes

---

## 1. Four ways to render conditionally

```tsx
// 1. Early return (whole component)
if (tasks.length === 0) {
  return <p className="text-muted">No tasks match this filter.</p>;
}

// 2. Ternary (either/or)
{isDone ? 'Reopen' : 'Mark done'}

// 3. && (something or nothing)
{task.dueDate && <p>Due {task.dueDate}</p>}

// 4. A variable prepared before the JSX
let content: ReactNode;
if (state.status === 'loading') content = <Spinner />;
else if (state.status === 'failed') content = <ErrorMessage … />;
else content = <TaskList … />;
return <section>{content}</section>;
```

React renders nothing for `null`, `undefined`, `true` and `false`. That's why `condition && <X/>` works: when the condition is `false`, the expression is `false`, and nothing shows.

## 2. The gotcha: numbers are rendered

```tsx
{tasks.length && <TaskList tasks={tasks} />}
```

When `tasks.length` is `0`, the expression evaluates to **`0`**, which **is** rendered, and a stray "0" appears on the page. `&&` returns its left operand when that's falsy, and React renders numbers (including `0`) but not booleans.

Fixes:

```tsx
{tasks.length > 0 && <TaskList tasks={tasks} />}    // boolean on the left
{tasks.length ? <TaskList tasks={tasks} /> : null}   // explicit ternary
```

The same trap applies to `''` (renders nothing visible, but can surprise you) and `NaN` (renders "NaN").

## 3. Discriminated unions make conditional rendering safe

With `RequestState<T>` (06.06), a `switch` over `status` is exhaustive and each branch gets correctly narrowed data:

```tsx
switch (state.status) {
  case 'idle': return null;
  case 'loading': return <p>Loading…</p>;
  case 'failed': return <p role="alert">{state.error}</p>;
  case 'succeeded': return <TaskList tasks={state.data} … />;
  default: return assertNever(state);
}
```

You'll use exactly this in S08's `useTasks` hook.

## 4. Summary

- Early return, ternary, `&&`, or a prepared variable.
- `null`/`undefined`/booleans render nothing; **numbers render**, including `0`.
- Put a boolean on the left of `&&`.
- `switch` on a discriminated union for multi-state UIs.

## 5. Check yourself

What does `{tasks.length && <TaskList />}` render when the list is empty?

<details>
<summary>Answer</summary>

The text **`0`**. Use `tasks.length > 0 && …`.

</details>
