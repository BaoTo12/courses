## 2. Tour of the generated files

```text
frontend/
├── index.html            ← the ONLY HTML page: <div id="root"> + <script type="module" src="/src/main.tsx">
├── package.json          ← scripts: dev, build (tsc -b && vite build), lint (oxlint), preview
├── vite.config.ts        ← Vite config: the React plugin (JSX transform + Fast Refresh)
├── tsconfig.json         ← "solution" file referencing the two below
├── tsconfig.app.json     ← settings for YOUR code (src/)
├── tsconfig.node.json    ← settings for config files that run in Node (vite.config.ts)
├── .oxlintrc.json        ← lint rules (rules of hooks, Fast Refresh safety)
├── public/               ← copied as-is to the site root (favicon)
└── src/
    ├── main.tsx          ← entry point: mounts <App/> into #root
    └── App.tsx           ← the root component
```

### What happens when you open the app

```text
Browser ── GET / ──────────────▶ Vite dev server: index.html (almost empty)
Browser ── GET /src/main.tsx ──▶ Vite transforms TSX → JS on the fly (types stripped, JSX compiled)
Browser: runs main.tsx → createRoot(#root).render(<App/>) → React builds the DOM
```

Open **View Source** (Ctrl+U): you'll see only `<div id="root"></div>`. Open **Elements**: the full UI. That's client-side rendering (00.04) in one glance.

### Two TypeScript configs?

`tsconfig.app.json` covers browser code (DOM types, JSX). `tsconfig.node.json` covers `vite.config.ts`, which runs in **Node** (Node types, no DOM). Same language, different environments. It's the "where does this code run?" question built into the configuration. `tsc -b` ("build mode") checks both.

## 3. ✍️ Adjust `tsconfig.app.json`

TypeScript 6 enables `strict` by default (verified: an implicit `any` parameter is already an error). We still write it explicitly (so nobody has to know the default) and add `noUncheckedIndexedAccess` (05.10). Add these two lines in `compilerOptions`:

```jsonc
    /* Type-checking (TaskFlow additions: explicit strict + honest index access) */
    "strict": true,
    "noUncheckedIndexedAccess": true,
```

Notice the template also sets **`"erasableSyntaxOnly": true`**: TypeScript features that need code generation, like `enum`, are **forbidden**. That's exactly the reasoning from 05.06, now enforced by the default config.

## 4. ✍️ Connect the shared design system: a Vite alias

The SCSS lives in `taskflow/styles/`, outside the frontend folder. Give it a short, stable import name in `vite.config.ts`:

```ts
import { fileURLToPath, URL } from 'node:url';
import react from '@vitejs/plugin-react';
import { defineConfig } from 'vite';

// https://vite.dev/config/
export default defineConfig({
  plugins: [react()],
  resolve: {
    alias: {
      // The shared design system lives outside the frontend folder (taskflow/styles).
      '@styles': fileURLToPath(new URL('../styles', import.meta.url)),
    },
  },
});
```

`@styles` now works in TypeScript imports (`import '@styles/main.scss'`) **and** inside SCSS (`@use '@styles/abstracts' as *;`). Vite resolves aliases for Sass too.

After renaming `domain.ts` → `types.ts`, update the imports inside the other files from `'./domain'` to `'./types'`.

Create `src/domain/format.ts`:

```ts
/** 'IN_PROGRESS' → 'in-progress' (matches the SCSS token map keys, 03.07). */
export const toKebab = (value: string) => value.toLowerCase().replaceAll('_', '-');
```

(Why a separate file instead of exporting it from a component file? See 07.06, the Fast Refresh rule.)

## 6. ✍️ `src/main.tsx`

Delete `src/App.css`, `src/index.css` and `src/assets/` (the template's demo styles). Then:

```tsx
import { StrictMode } from 'react';
import { createRoot } from 'react-dom/client';
import '@styles/main.scss';
import { App } from './App';

const rootElement = document.getElementById('root');
if (!rootElement) {
  throw new Error('#root element missing from index.html');
}

createRoot(rootElement).render(
  <StrictMode>
    <App />
  </StrictMode>,
);
```

- **`import '@styles/main.scss'`** loads the whole design system once: base, layout, components, themes. This is the same stylesheet the JSP portal will use.
- **The explicit null check** replaces the template's `getElementById('root')!` (05.10: prefer a real check over `!`).
- **`<StrictMode>`** enables development-only checks. It intentionally **double-invokes** some functions (component bodies, effects) to surface impure code. You'll see its effect in S08.
- **`createRoot(...).render(...)`** is the single place React takes over the DOM.

Set a proper title in `index.html`: `<title>TaskFlow</title>`.

## 7. ✍️ A first `App.tsx`

```tsx
export function App() {
  return (
    <div className="page">
      <main className="page__main">
        <h1 className="page__title">TaskFlow</h1>
        <span className="badge badge--in-progress">It works</span>
      </main>
    </div>
  );
}
```

Note: **`className`**, not `class` (JSX maps to DOM properties, where it's `className`). And `App` is a **named export** (04.01 convention), so `main.tsx` imports `{ App }`.

## 8. Run it

```bash
npm run dev
```

Open `http://localhost:5173`. You should see the page styled by the design system (in dark mode if your OS is dark). Edit the text in `App.tsx` and save: the browser updates **without a reload**, keeping state. That's **Fast Refresh** from the React plugin.

Then check the production pipeline:

```bash
npm run build
```

`tsc -b` type-checks (both configs), then `vite build` writes `dist/`. Expect roughly `index.html`, one CSS file and one JS file (~220 kB, ~70 kB gzipped, mostly React itself).

```bash
npm run lint
```
