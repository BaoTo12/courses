> **Project feature:** the task list with status filters and toggling, the React version of 04.13 (verified in the reference app: filter shows `(1/5)` for Done; toggling updates the badge; no console warnings)

## 1. ✍️ `src/components/TaskList.tsx`

```tsx
import type { Task } from '../domain/types';
import { TaskCard } from './TaskCard';

interface TaskListProps {
  tasks: readonly Task[];
  onToggle: (id: number) => void;
}

export function TaskList({ tasks, onToggle }: TaskListProps) {
  if (tasks.length === 0) {
    return <p className="text-muted">No tasks match this filter.</p>;
  }

  return (
    <div className="task-grid">
      {tasks.map((task) => (
        <TaskCard key={task.id} task={task} onToggle={onToggle} />
      ))}
    </div>
  );
}
```

`TaskList` doesn't own the tasks and doesn't change them. It **renders what it's given** and **passes the callback down**. That makes it a *presentational* component: easy to reuse (the dashboard will reuse it) and easy to test.

## 2. ✍️ `src/components/FilterBar.tsx`

```tsx
import { TASK_STATUSES } from '../domain/types';
import type { TaskStatus } from '../domain/types';
import { statusLabel } from '../domain/labels';
import { Button } from './Button';
import styles from './FilterBar.module.scss';

interface FilterBarProps {
  value: TaskStatus | null;
  onChange: (status: TaskStatus | null) => void;
}

export function FilterBar({ value, onChange }: FilterBarProps) {
  return (
    <div className={styles.bar} role="group" aria-label="Filter by status">
      <Button
        size="sm"
        variant={value === null ? 'primary' : 'secondary'}
        aria-pressed={value === null}
        onClick={() => onChange(null)}
      >
        All
      </Button>
      {TASK_STATUSES.map((status) => (
        <Button
          key={status}
          size="sm"
          variant={value === status ? 'primary' : 'secondary'}
          aria-pressed={value === status}
          onClick={() => onChange(status)}
        >
          {statusLabel(status)}
        </Button>
      ))}
    </div>
  );
}
```

And `src/components/FilterBar.module.scss` (explained in 07.07):

```scss
@use '@styles/abstracts' as *;

.bar {
  display: flex;
  flex-wrap: wrap;
  gap: space(2);
  margin-bottom: space(4);

  // The design system's `.btn + .btn` margin is for inline buttons; a flex row uses gap.
  :global(.btn) + :global(.btn) {
    margin-left: 0;
  }
}
```

Notes:
- **`TASK_STATUSES.map(…)`**: the runtime array from 06.05 drives the UI. Add a status to the array → a new filter button appears automatically. `key={status}` is fine because statuses are unique and stable.
- **`FilterBar` is a controlled component**: it doesn't store the current filter. The parent passes `value` and `onChange` (07.13). That's the same pattern as form inputs in S11.
- **`aria-pressed`** tells screen readers which toggle button is active; the colour change alone wouldn't. `role="group"` + `aria-label` names the group.

## 4. ✍️ `src/App.tsx`: state lives here

```tsx
import { useState } from 'react';
import type { Task, TaskStatus } from './domain/types';
import { filterTasks, toggleTask } from './domain/task-utils';
import { SAMPLE_TASKS } from './data/sample-tasks';
import { PageLayout } from './components/PageLayout';
import { FilterBar } from './components/FilterBar';
import { TaskList } from './components/TaskList';

export function App() {
  const [tasks, setTasks] = useState<Task[]>(SAMPLE_TASKS);
  const [statusFilter, setStatusFilter] = useState<TaskStatus | null>(null);

  const visibleTasks = filterTasks(tasks, { status: statusFilter ?? undefined });

  function handleToggle(id: number) {
    setTasks((current) => toggleTask(current, id));
  }

  return (
    <PageLayout title="Tasks" subtitle={`(${visibleTasks.length}/${tasks.length})`}>
      <FilterBar value={statusFilter} onChange={setStatusFilter} />
      <TaskList tasks={visibleTasks} onToggle={handleToggle} />
    </PageLayout>
  );
}
```

### How a click flows through the app

```text
click "Mark done" on task 2
  → TaskCard: onClick → onToggle(2)            (callback prop)
  → TaskList passed onToggle straight through
  → App.handleToggle(2) → setTasks(current => toggleTask(current, 2))
  → React schedules a re-render of App
  → App renders: tasks is a NEW array; visibleTasks recomputed (derived, not state)
  → TaskList / TaskCards re-render; reconciliation by key
  → Commit: only task 2's badge text/class and button label change in the DOM
```

- **`onChange={setStatusFilter}`**: a state setter has exactly the signature `(value) => void`, so it can be passed directly.
- **`statusFilter ?? undefined`**: our `TaskFilter.status` is optional (`undefined` = no filter), while the state uses `null` = "All". Converting at the boundary keeps both types honest.
- **`visibleTasks` is derived** (07.08), computed on every render. Cheap here; S21 memoises derived data when it matters.

## 5. Try it

- Click the filters: the list and the `(n/5)` counter update.
- Toggle tasks: badges change; with a filter active, a toggled task may disappear from the view (it no longer matches). That's correct behaviour, but notice it as a UX question.
- Open React DevTools → **Components**: select `App` and watch `tasks` and `statusFilter` change. Enable "Highlight updates when components render" and click. Note which components flash.

## 7. Summary

- State (`tasks`, `statusFilter`) lives in `App`; `visibleTasks` is derived.
- `TaskList`, `TaskCard` and `FilterBar` are presentational: data in via props, intent out via callbacks.
- `TASK_STATUSES` drives the filter UI; `aria-pressed` + `role="group"` make it accessible.
- The click → callback → setState → re-render → minimal commit flow is the core React loop.
