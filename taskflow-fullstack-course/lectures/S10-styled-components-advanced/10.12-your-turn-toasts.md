# Lecture 10.12 · 🎯 Your Turn: a Themed Toast System

> **Section:** S10 · **Type:** 🎯 Your Turn · **Track:** ★ Core · **Time:** ~75 minutes

---

## 1. The task

Build a small notification ("toast") system:

```tsx
const { show } = useToast();
show({ tone: 'success', message: 'Completed: Write quarterly report' });
```

Toasts stack in the bottom-right corner, slide in, and disappear automatically after 4 seconds, or when the user clicks ×.

Use it in `App`: when a task is toggled **to** done, show `Completed: <title>`.

## 2. Requirements

**Architecture**
1. `src/toast/toast-context.ts`: types (`ToastTone = 'success' | 'error' | 'info'`, `ToastInput`, `Toast` with `id`), the context, and a `useToast()` hook that throws outside the provider (the 08.10 pattern).
2. `src/toast/ToastProvider.tsx`: holds the toast list in state; renders `children` plus a fixed viewport with the toasts; exports **only** the provider component.
3. `show` and `dismiss` are **stable** functions (`useCallback`), and the context value is memoised (08.09).

**Behaviour**
4. Each toast has a unique `id` (not `Date.now()` or `Math.random()`: why is a counter in a ref better?).
5. Auto-dismiss after 4 s; clicking × dismisses immediately **and cancels** that toast's timer.
6. When the provider unmounts, all pending timers are cleared (08.03: cleanup).

**Styling (styled-components + theme)**
7. A tone variant map (10.09) typed with `satisfies Record<ToastTone, …>`. Tone shown as a coloured left border from `theme.colors.success/danger/primary`.
8. `keyframes` slide-in animation, disabled for reduced motion (the global rule from 10.06 covers it, but think about why a component-level rule is also good practice).
9. No hard-coded colours except neutral shadows; everything else from `theme`.

**Accessibility**
10. Success/info toasts: `role="status"` + `aria-live="polite"`. Error toasts: `role="alert"` + `aria-live="assertive"`.
11. The dismiss button has `aria-label="Dismiss notification"` and a visible focus ring.

## 3. Acceptance

- [ ] Completing a task shows a toast; it disappears after ~4 s.
- [ ] Two quick completions show two stacked toasts.
- [ ] × removes a toast immediately.
- [ ] Theme switching restyles toasts without re-rendering them (class names unchanged).
- [ ] Build and lint clean.

## 4. Hints

<details>
<summary>Hint 1: where do timers live?</summary>

In a `useRef(new Map<number, number>())` from toast id to timeout id. Refs don't cause re-renders (08.06), and the map survives renders.
</details>

<details>
<summary>Hint 2: dismiss inside show</summary>

`show` schedules `setTimeout(() => dismiss(id), 4000)`, so `show` depends on `dismiss` (put it in the `useCallback` dependencies). `dismiss` uses a functional `setToasts` update, so it has no dependencies.
</details>

<details>
<summary>Hint 3: the "task was not done before" check in App</summary>

Read the task's status **before** calling `toggle(id)`: `const task = state.data.find(t => t.id === id)`.
</details>
