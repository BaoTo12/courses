# Lecture 10.05 · 🛠 Build: a Theme of `var()` References, Shared with SCSS

> **Section:** S10 · **Type:** 🛠 Build · **Track:** ★ Core · **Time:** ~45 minutes
> **Project feature:** SCSS emits status/priority/success/warning tokens; a typed `theme` object references them; all S09 components use `props.theme`; no hard-coded colours remain in styled components
> Verified in the reference app: build and lint clean; class names unchanged across theme switches; computed arc colour = `rgb(217, 119, 6)` (light warning) / `rgb(251, 191, 36)` (dark warning).

---

## 1. ✍️ SCSS: emit the remaining tokens as custom properties

### a) Add `success` and `warning` to both themes (`styles/abstracts/_tokens.scss`)

In the `'light'` map, after `'danger-hover'`:

```scss
    'success':       #16a34a,
    'warning':       #d97706,
```

In the `'dark'` map, after `'danger-hover'`:

```scss
    'success':       #4ade80,
    'warning':       #fbbf24,
```

Your theme-completeness guard (03.14) checks that both themes got both keys. Try adding one to light only and read the error.

### b) Emit status and priority colours (`styles/base/_root.scss`)

They were compile-time-only maps (03.07). JavaScript needs them at runtime, so emit them once, theme-independent, before the theme blocks:

```scss
// 0. Theme-independent tokens shared with JavaScript (styled-components, S10):
//    --color-status-<status>-bg / -fg and --color-priority-<priority>
:root {
  @each $status, $colors in $status-colors {
    --color-status-#{$status}-bg: #{map.get($colors, 'bg')};
    --color-status-#{$status}-fg: #{map.get($colors, 'fg')};
  }
  @each $priority, $color in $priority-colors {
    --color-priority-#{$priority}: #{$color};
  }
}
```

Compiled (excerpt):

```css
:root {
  --color-status-todo-bg: #e0e7ff;
  --color-status-todo-fg: #3730a3;
  /* … */
  --color-priority-low: #14b8a6;
  /* … */
}
```

## 2. ✍️ `src/theme/theme.ts`

```ts
import type { Priority, TaskStatus } from '../domain/types';

/** `var(--color-…)` references to the custom properties emitted by styles/base/_root.scss (03.13). */
const cssVar = (name: string) => `var(--color-${name})`;

const status = (s: string) => ({ bg: cssVar(`status-${s}-bg`), fg: cssVar(`status-${s}-fg`) });

/**
 * The styled-components theme. It contains NO literal colours: every colour is a reference to a
 * CSS custom property owned by the SCSS design system. Light/dark switching happens in CSS
 * (data-theme on <html>), so this object never changes, and styled components don't re-render.
 */
export const theme = {
  colors: {
    primary: cssVar('primary'),
    primaryHover: cssVar('primary-hover'),
    onPrimary: cssVar('on-primary'),
    danger: cssVar('danger'),
    dangerHover: cssVar('danger-hover'),
    success: cssVar('success'),
    warning: cssVar('warning'),
    text: cssVar('text'),
    textMuted: cssVar('text-muted'),
    border: cssVar('border'),
    surface: cssVar('surface'),
    surfaceMuted: cssVar('surface-muted'),
    background: cssVar('background'),
    focusRing: cssVar('focus-ring'),
    status: {
      TODO: status('todo'),
      IN_PROGRESS: status('in-progress'),
      DONE: status('done'),
    } satisfies Record<TaskStatus, { bg: string; fg: string }>,
    priority: {
      LOW: cssVar('priority-low'),
      MEDIUM: cssVar('priority-medium'),
      HIGH: cssVar('priority-high'),
    } satisfies Record<Priority, string>,
  },
  /** Same 4px scale as SCSS space() (03.04). */
  space: (n: number) => `${n * 4}px`,
  radii: { sm: '4px', md: '6px', lg: '8px', full: '999px' },
  /** Same values as SCSS $breakpoints (03.02): media queries can't use var(). */
  breakpoints: { sm: '480px', md: '768px', lg: '1024px', xl: '1280px' },
  fontSizes: { xs: '0.75rem', sm: '0.875rem', md: '1rem', lg: '1.125rem', xl: '1.5rem' },
} as const;

export type AppTheme = typeof theme;
```

- **`satisfies Record<TaskStatus, …>`** (06.05): if a status is added to `TASK_STATUSES`, this fails to compile until its colours exist. That's the cross-language checklist item from 06.13, now partly enforced.
- **camelCase names in TS** (`textMuted`) map to kebab-case CSS names (`--color-text-muted`), matching each language's convention.

## 3. ✍️ `src/styled.d.ts`

The augmentation from 10.02:

```ts
// Module augmentation (06.10): tell styled-components what our theme looks like.
import 'styled-components';
import type { AppTheme } from './theme/theme';

declare module 'styled-components' {
  // DefaultTheme is an empty interface in the library; we merge our theme's shape into it.
  export interface DefaultTheme extends AppTheme {}
}
```

## 4. ✍️ Provide it: `src/theme/ThemeProvider.tsx`

Add the styled-components provider **inside** your existing preference provider:

```tsx
import { ThemeProvider as StyledThemeProvider } from 'styled-components';
import { theme } from './theme';
import { GlobalStyle } from './GlobalStyle';   // written in 10.06
// …
  return (
    <ThemeContext.Provider value={value}>
      {/* `theme` is a module constant: it never changes, so switching light/dark re-renders nothing. */}
      <StyledThemeProvider theme={theme}>
        <GlobalStyle />
        {children}
      </StyledThemeProvider>
    </ThemeContext.Provider>
  );
```

(`as StyledThemeProvider` avoids a name clash with our own `ThemeProvider`.)

## 5. ✍️ Refactor the S09 components

**PriorityBar**: pass the priority, let the theme resolve the colour. Delete `PRIORITY_COLOR` usage:

```tsx
const Segment = styled.span<{ $filled: boolean; $priority: Priority }>`
  flex: 1;
  border-radius: ${({ theme }) => theme.radii.full};
  background: ${({ $filled, $priority, theme }) =>
    $filled ? theme.colors.priority[$priority] : theme.colors.border};
  transition: background-color 150ms ease;
`;
// …
<Segment key={n} $filled={n <= level} $priority={priority} />
```

**ProgressRing**: threshold colours from the theme:

```tsx
import type { DefaultTheme } from 'styled-components';

/** Threshold colours from the theme: danger below 34%, warning below 67%, success otherwise. */
function ringColor(percent: number, theme: DefaultTheme): string {
  if (percent < 34) return theme.colors.danger;
  if (percent < 67) return theme.colors.warning;
  return theme.colors.success;
}

const Arc = styled.circle<{ $offset: number; $percent: number }>`
  stroke: ${({ $percent, theme }) => ringColor($percent, theme)};
  /* … rest unchanged … */
`;
// …
<Arc cx={SIZE / 2} cy={SIZE / 2} r={RADIUS} $offset={offset} $percent={percent} />
```

**StyledButton**: replace each `var(--color-x)` with `${({ theme }) => theme.colors.x}`.

Finally, **delete `PRIORITY_COLOR`** from `domain/labels.ts` if nothing else uses it. The hex copy is gone; SCSS is the only owner of colour values.

## 6. Verify

- `npm run build` and `npm run lint`.
- Toggle the theme and compare in DevTools: the `class` of a priority segment **doesn't change**, but its computed colour does. That's the browser re-resolving `var()`, with no React involvement.

> 🐞 **Debugging tip learned while building this lecture:** in a **background tab**, browsers don't advance CSS transitions. `getComputedStyle` on an element with `transition: stroke 300ms` kept returning the *old* colour after a theme switch while the tab was hidden. With `transition: none` it returned the new colour immediately. If computed styles "don't update" in automated checks or background tabs, suspect transitions.
