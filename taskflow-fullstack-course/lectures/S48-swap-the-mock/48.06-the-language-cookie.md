# Lecture 48.06 · The `tf_lang` Cookie in Action: React Switches, the Portal Follows

## Try it

1. In TaskFlow Web, pick **Tiếng Việt** in the language menu. i18next's detector writes `tf_lang=vi; Path=/` (25.05).
2. Open the Admin Portal on the same host (`http://localhost:8080/taskflow/tasks`, or your DevServer port). `LocaleFilter` reads `tf_lang` (44.07): the portal is in Vietnamese.
3. Click **English** in the portal. `LanguageServlet` writes `tf_lang=en; Path=/` (44.08).
4. Reload TaskFlow Web: English.

## Why it works

| Condition | TaskFlow |
|---|---|
| the same **cookie name** | `tf_lang` on both sides |
| the same **values** | `en`, `vi` (both allow-listed) |
| a cookie visible to both | cookies belong to a **host**, not a port: `localhost:5173` and `localhost:8080` share them; `Path=/` covers every path |
| readable by JavaScript | not HttpOnly (a preference, not a secret) |

In production (one origin, S49), it's trivially the same cookie.

## What doesn't cross over

The **user's stored** locale (`users.locale`, returned by `/api/auth/me`) isn't used to choose the language yet; the cookie wins in both apps. Letting the profile set the cookie at login is a small Part 4 extension.
