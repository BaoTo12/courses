## 1. What the Network tab shows

Open the React app in a fresh private window with DevTools → Network, then log in as alice and click **Reopen** on a task:

```text
GET   /api/auth/me                               → 401 Unauthorized     app start: "am I logged in?" (no session)
GET   /api/auth/csrf                             → 204 No Content       the interceptor needs a token before the first POST
POST  /api/auth/login                            → 200 OK               {"id":1,"username":"alice",…}
GET   /api/tasks?size=100                        → 200 OK               the category counters
GET   /api/categories                            → 200 OK
GET   /api/tasks?sort=dueDate,asc&page=0&size=20 → 200 OK               the list page
GET   /api/tasks/12/comments                     → 200 OK
PATCH /api/tasks/12                              → 200 OK               "Reopen" (optimistic update, 23.05)
GET   /api/tasks?size=100                        → 200 OK               tag invalidation → refetch (22.08)
GET   /api/tasks?sort=dueDate,asc&page=0&size=20 → 200 OK
```

The only Console error is the first 401 ("Failed to load resource"): that's how the app learns nobody is logged in.

## 2. The cookies and headers, per hop

| Hop | Browser sends | Server answers |
|---|---|---|
| `GET /api/auth/csrf` | nothing special | `Set-Cookie: XSRF-TOKEN=…; Path=/; SameSite=Lax` (readable) |
| `POST /api/auth/login` | `Cookie: XSRF-TOKEN=…`, `X-XSRF-TOKEN: …` (js-cookie → interceptor, 24.11), `Content-Type: application/json` | `Set-Cookie: JSESSIONID=…; Path=/` (rewritten from `/taskflow` by Vite); `HttpOnly`; a **new** `XSRF-TOKEN` |
| `GET /api/tasks…` | `Cookie: JSESSIONID=…; XSRF-TOKEN=…` | the page |
| `PATCH /api/tasks/12` | + `X-XSRF-TOKEN` (the **new** value: the interceptor reads the cookie on every request) | the updated task |

Every request also carries `X-Request-Id: <uuid>` (13.12); since S48 the server adopts it (48.08).
