# Lecture 48.99 · ✅ Knowledge Check: TaskFlow Web on the Real Backend

> **Section:** S48 · **Type:** ✅ Knowledge Check · **Track:** ★ Core · **Time:** ~15 minutes

---

**1.** Explain every hop of a `PATCH /api/tasks/5` from the React button to MySQL and back, naming each cookie and header involved.

<details><summary>Answer</summary>

48.08's table. The cookies: `JSESSIONID` (HttpOnly, the session; its path rewritten to `/` by Vite), `XSRF-TOKEN` (readable, copied into the header), `tf_lang` (the language). The headers: `X-XSRF-TOKEN` (double submit), `X-Request-Id` (a UUID from Axios, adopted by the server), `Content-Type: application/json` (else 415). In the response: `Content-Type: application/json;charset=UTF-8`, `X-Request-Id`, the security headers, `Cache-Control: no-store`, `Vary: Origin`.
</details>

**2.** Which bugs from the 48.05 lab would TypeScript have caught, and which not? Why?

<details><summary>Answer</summary>

**None, at runtime.** TypeScript checks the code against the types it **declares**; the JSON arriving from the server isn't checked by the compiler (Axios returns `any`-ish data typed by assertion). A renamed field (`total`) or a string id compiles fine and fails when used. TypeScript does help afterwards: once you change the type (`totalItems` → `total`), the compiler shows every place to update. Runtime guards at the boundary (TaskFlow's `isApiError`, `isPageOf`) catch shape changes (3, 4); schema validation catches types and enums (2, 6); formats inside strings (1) need a pattern; a changed status code (5) needs a contract test (48.07).
</details>

**3.** Login succeeds through the Vite proxy, but the next call is a 401. The Network tab shows `Set-Cookie: JSESSIONID=…; Path=/taskflow`. Explain and fix.

<details><summary>Answer</summary>

The browser stores the cookie for path `/taskflow`, but it only ever requests `/api/…` on the Vite origin, so the cookie is never sent. Rewrite the path in the proxy (`cookiePathRewrite: { '/taskflow': '/' }`), or deploy the backend as the root context, or serve everything from one origin under `/taskflow` (S49).
</details>

**4.** Why does the server accept the client's `X-Request-Id` only if it's a UUID?

<details><summary>Answer</summary>

The id is written into every log line (`[id]`) and returned in a header. An arbitrary value could forge log content ("`] INFO admin logged in [`"), carry control characters, or be megabytes long. A strict pattern keeps the correlation benefit and removes the injection risk; anything else is replaced by a server-generated id (43.11).
</details>

**5.** With the backend on another port, what changes in the React app's code?

<details><summary>Answer</summary>

Nothing. The proxy target is configuration (`TASKFLOW_BACKEND=http://localhost:8081`); the app keeps calling relative `/api/…` URLs (48.01).
</details>
