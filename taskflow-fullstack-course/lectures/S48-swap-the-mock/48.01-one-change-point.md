# Lecture 48.01 · The Payoff of the `api/` Layer: One Change Point

> **Section:** S48 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~10 minutes

---

Part 1 built TaskFlow Web against a mock with one rule: **nothing outside `src/api/` knows where the server is or how HTTP works** (13.04).

```text
components ─► RTK Query hooks (features/api/apiSlice.ts) ─► axiosBaseQuery ─► api (src/api/client.ts: ONE Axios instance)
                                                                                 baseURL: '/api'
                                                                                   │
                                                          Vite dev server proxy ◄──┘   (vite.config.ts)
                                                          Part 1: → json-server :3001
                                                          Part 3: → Tomcat :8080/taskflow
```

## What changes in S48

| File | Change |
|---|---|
| `vite.config.ts` | the proxy target: Tomcat instead of the mock, plus a path rewrite and a cookie-path rewrite (48.02) |
| everything else in `src/` | **nothing** |

That's possible because:
- the **contract** (URLs, JSON shapes, status codes, error body) was written down in Part 1 and the servlets of S46–S47 implement the same one;
- every call uses **relative** URLs (`/api/tasks`), so the browser never learns the backend's address;
- auth (`/api/auth/*`), CSRF (`XSRF-TOKEN` → `X-XSRF-TOKEN`) and error handling (`ApiRequestError`) were built against the mock's `--secure` mode (S24), which behaves like the real backend.

## What can still go wrong

Anything the contract didn't pin down: cookie paths, context paths, header names, formats nobody wrote down. S48 finds them the way real projects do: by running the two halves together and reading the Network tab (48.05).

## ✅ Recap

One Axios instance, relative URLs and a written contract turn "switch to the real backend" into a proxy setting.
