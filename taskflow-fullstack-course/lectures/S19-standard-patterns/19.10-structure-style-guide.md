## 1. TaskFlow's `src/` after S19

```text

├── main.tsx, App.tsx               entry point, route table
├── app/                            the Redux "wiring": store, root reducer, typed hooks, middleware

│   ├── tasks/          tasksSlice.ts  tasksThunks.ts  OpenTasksBadge.tsx  (+ tests)
```

(While preparing this lecture, the tree revealed `data/fake-search.ts` and `data/sample-tasks.ts`, leftovers from S08's race-condition demo that nothing imports any more. They're deleted. Looking at the whole tree now and then is a good habit.)

### "Ducks" = one file per feature's Redux logic

The Style Guide's recommendation is **feature folders with single-file logic**: a feature's reducer, action types, action creators and selectors in **one** "slice" file (historically called the "ducks" pattern). TaskFlow adds a separate `…Thunks.ts` per feature, which keeps the slice file free of API imports and makes the reducer tests independent of the API layer. `createSlice` (S20) generates most of a slice file; `createAsyncThunk` lives beside it.

### The dependency direction

```text
pages / features UI  →  features (slices, thunks)  →  api  →  domain
        ↘ components (props only)                    ↘ domain
```

- `domain/` imports nothing app-specific: the easiest code to test and reuse (Part 2 mirrors these rules in Java).
- `components/` don't call store hooks themselves: they receive data through props. `features/*` components may use the store, and a presentational component may **render** one (`TaskCard` renders `<TaskCategoryTag>`, 19.07).
- `api/` never imports from `features/`: HTTP doesn't know about Redux.

## 2. The Style Guide's Priority A ("Essential") rules

Paraphrased, and where TaskFlow applies each:

| Rule | TaskFlow |
|---|---|
| **Do not mutate state** | `deepFreeze` in every reducer test (15.11); Immer from S20 |
| **Reducers must not have side effects** | No API calls, timers or `Date.now()` in reducers; they live in creators and thunks (15.04, 19.01) |
| **Do not put non-serializable values in state or actions** | ISO date strings, arrays instead of `Set`s, no `AbortController` in state (it lives in `extra`, 18.11) |
| **Only one Redux store per app** | `store.ts` exports one app store; `makeStore()` exists for **tests** |

## 3. Priority B ("Strongly Recommended") rules you've already applied

| Rule | Where |
|---|---|
| Use Redux Toolkit for writing Redux logic | S20 (you learned the hand-written version first, on purpose) |
| Structure files as feature folders with single-file logic | §1 |
| Model actions as events, not setters | 15.03 |
| Write meaningful action names | 15.03 |
| Allow many reducers to respond to the same action | `auth/loggedOut`, `tasks/taskDeleted` (15.10) |
| Keep state minimal and derive additional values | Counts, filtered lists and joins are selectors (15.01, 19.07) |
| Normalise complex nested/relational state | 19.06 |
| Treat reducers as state machines | The `status` enum (19.03) |
| Use the React-Redux hooks API | 17.04–17.06 (`connect` only for reading old code, 17.12) |
| Call `useSelector` multiple times; select only what you need | `TasksPage` (19.04), `OpenTasksBadge` (17.13) |
| Use static typing | `RootState`, `AppDispatch`, `AppThunk`, typed hooks |

Two Priority C ("Recommended") rules you've also applied: **write action types as `domain/eventName`** (15.03) and **avoid putting form state in Redux** (`TaskForm` stays local, 17.08). 20.13 lists the rest.

Some Priority B rules TaskFlow adapts with a reason: the Style Guide suggests putting as much logic as possible in **reducers**, while TaskFlow's "which task should toggle to what" lives in a thunk (`toggleTaskOnServer`), because the **server** decides the result. The reducer records what the server returned (13.13).

## 4. Summary

- Feature folders with one slice file per feature (plus thunks); `app/` for wiring; `api/` and `domain/` below the features.
- The four essential rules: no mutation, no side effects in reducers, serialisable state and actions, one store.
- Most recommended rules are already habits; RTK (S20) makes several of them automatic.
