# Lecture 19.11 · 🎯 Your Turn: a Category Sidebar with Task Counts, Using Normalised State

> **Section:** S19 · **Type:** 🎯 Your Turn · **Track:** ★ Core · **Time:** ~75 minutes

---

## 1. The task

Above the status filter on the list page, show the categories with their task counts:

```text
All categories   [Work] 5   [Engineering] 8   [Team] 6   [Personal] 3
```

Clicking a category filters the list to it; "All categories" removes the filter.

## 2. Requirements

1. **The URL is the source of truth** (12.03): the filter lives in `?category=<id>`. Clicking keeps the other parameters (`status`, `q`, `view`). Parse and validate the parameter like any user input (a positive integer, or no filter).
2. **Counts** come from a memoised selector `selectTaskCountsByCategory(state)` returning `{ byCategory: Record<number, number>; uncategorized: number }`. It must return the **same object** when the tasks didn't change (a toast, for example).
3. Categories are rendered with the existing `Tag` component (validated colours), in the categories' order from the server.
4. The active category link has `aria-current="true"`, visually emphasised.
5. `filterTasks` supports `categoryId` (the `TaskFilter` type already has the field).
6. Show "Uncategorised: N" when some tasks have no category.
7. Tests: the counts selector (values and memoisation), and the category URL parser.

## 3. Hints

<details>
<summary>Hint 1: building a link that changes one parameter</summary>

```ts
const next = new URLSearchParams(searchParams);
next.set('category', String(id)); // or next.delete('category')
<Link to={{ search: `?${next.toString()}` }}>…</Link>
```

A `Link` with a `search`-only `to` stays on the current path.
</details>

<details>
<summary>Hint 2: memoising the counts</summary>

`createSelector([selectTasks], (tasks) => …)`. `selectTasks` is itself memoised (19.02), so the counts recompute only when the task list changes.
</details>

<details>
<summary>Hint 3: parsing the parameter</summary>

The rule is the same as for task ids (12.03): digits only, a safe integer, greater than zero. Reuse `parseTaskId` behind a well-named function.
</details>

## 4. Acceptance checklist

- [ ] Counts match the list (the sum plus uncategorised equals the total).
- [ ] Clicking "Personal" → `?category=4`, only Personal tasks, the link emphasised; "All categories" removes the parameter.
- [ ] `?category=abc` or `?category=-1` shows all tasks (invalid input is ignored).
- [ ] Toggling a task's status doesn't change the counts; renaming a category updates the sidebar and every card.
- [ ] The counts selector returns the same object after an unrelated action (test).
- [ ] `npm test`, `npx tsc -b`, `npm run lint` pass.
