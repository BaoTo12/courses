# Lecture 19.04 · 🛠 Build: Loading and Error UI Driven by the Status Field

> **Section:** S19 · **Type:** 🛠 Build · **Track:** ★ Core · **Time:** ~25 minutes
> **Project feature:** every screen that reads async data renders from `status` + "do we have data?"
> Verified in the browser in S17–S18: first load ("Loading tasks…"), refresh (" · refreshing…"), first-load failure (error + "Try again"), refresh failure (old list + "Refresh failed…").

---

## 1. Four situations, one table

With data kept during reloads, the UI has four cases, not three:

| `status` | Data present? | What TaskFlow shows |
|---|---|---|
| `idle` / `loading` | no | "Loading tasks…" |
| `loading` | yes | the list, with " · refreshing…" in the title |
| `failed` | no | the error and a **Try again** button (`role="alert"`) |
| `failed` | yes | the (old) list, plus "Refresh failed: … **Try again**" |
| `succeeded` | yes (possibly empty) | the list (or "No tasks match this filter.") |

## 2. ✍️ `TasksPage` (the relevant part)

```tsx
// Three selectors, three stable results: `selectTasks` is memoised (19.02), the others are primitives.
const items = useAppSelector(selectTasks);
const status = useAppSelector(selectTasksStatus);
const error = useAppSelector(selectTasksError);

const hasData = status === 'succeeded' || items.length > 0;

let content;
if (status === 'failed' && items.length === 0) {
  content = (
    <div role="alert">
      <p className="text-danger">{error}</p>
      <Button onClick={reload}>Try again</Button>
    </div>
  );
} else if (!hasData) {
  content = <p className="text-muted">Loading tasks…</p>;
} else {
  // …the filtered list
}
```

And in the heading:

```tsx
<h1 className="page__title">
  Tasks {hasData && <span className="text-muted">({items.length})</span>}
  {status === 'loading' && hasData && <span className="text-muted"> · refreshing…</span>}
</h1>
{status === 'failed' && hasData && (
  <p role="alert" className="text-danger">
    Refresh failed: {error} <Button size="sm" onClick={reload}>Try again</Button>
  </p>
)}
```

- **Three `useAppSelector` calls**, not one returning `{ items, status, error }`: each result is stable (17.04). S18's version selected the whole slice object, which also worked (it was a stable reference). After normalisation, the list must be **built**, so it gets its own memoised selector.
- **`status === 'succeeded'` with an empty list** is a valid state ("no tasks yet"), distinct from loading.
- **`role="alert"`** for errors: screen readers announce them (11.07).

## 3. Details and edit pages: "not found" only when we know

```tsx
if (!task && (status === 'idle' || status === 'loading')) return <p className="text-muted">Loading…</p>;
if (!task) return <NotFoundPage />;
```

A direct visit to `/tasks/5` starts with `status: 'idle'`. Showing "not found" at that moment would be a lie. The status field makes the difference between "not loaded yet" and "doesn't exist" explicit.

## 4. Summary

- Render from `status` **and** data presence: four distinct cases.
- Keep old data visible during refreshes; show refresh errors without hiding it.
- Decide "not found" only after loading has finished.
