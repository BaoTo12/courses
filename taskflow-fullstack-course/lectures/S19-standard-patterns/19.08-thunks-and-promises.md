# Lecture 19.08 · Thunks and Promises: Return the Promise, `await dispatch(saveTask())`, Then Navigate

> **Section:** S19 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~20 minutes
> 🔗 Official companion reading: Fundamentals Part 7 ("Thunks and Promises")

---

## 1. The pattern

Components often need to know **when** async work finished, and **how**:
- "Save, **then** go to the task's page."
- "Save; **if** the server rejects the title, show it under the field."
- "Delete; navigate back **only if** it worked."

Because the thunk middleware returns the thunk's return value (18.03), and TaskFlow's thunks are `async` functions, `dispatch` returns a **promise** the component can await:

```ts
const created = await dispatch(saveNewTask(request)); // resolves with the server's Task, or rejects
navigate(`/tasks/${created.id}`, { replace: true });
```

## 2. Rules that keep it clean

- **Return (or be) the promise.** A thunk that starts async work and doesn't return it (`api.createTask(r).then(…)` without `return`) gives callers `undefined`: they can't await it, and errors become unhandled rejections.
- **Resolve with what the caller needs**: the saved entity (`saveNewTask` → `Task`), a success flag (`deleteTask` → `boolean`), or nothing (`fetchTasks` → `void`).
- **Pick an error contract per thunk** (18.05): reject (the caller handles it) or resolve with a status (the thunk reported it). Document it on the thunk.
- **Always `await` (or `void`) the dispatch** in components. A floating promise that rejects shows up as an "Uncaught (in promise)" error with no UI feedback.
- **The store has already been updated when the promise resolves.** `saveNewTask` dispatches `taskAdded` before returning, so the details page finds the task in the store immediately after navigation.

## 3. What NOT to do with the promise

Don't use the resolved value to **update state** in the component:

```ts
const created = await dispatch(saveNewTask(r));
setLocalTasks((tasks) => [...tasks, created]); // ❌ a second copy of the data, outside the store
```

The thunk already put it in the store. The resolved value is for **control flow** (navigate, focus, close a dialog), not for data.

## 4. RTK's version

`createAsyncThunk` (S20) returns a promise that **always resolves** with the final action (fulfilled **or** rejected), plus an `.unwrap()` method that gives you "resolve with the payload, or throw". So `await dispatch(saveNewTask(r)).unwrap()` is RTK's spelling of what TaskFlow's hand-written thunks do today.

## 5. Summary

- `await dispatch(thunk())` gives components completion and results: navigate, show errors, close dialogs.
- Return the promise; resolve with what callers need; choose and document the error contract.
- Use results for control flow; the data already lives in the store.
