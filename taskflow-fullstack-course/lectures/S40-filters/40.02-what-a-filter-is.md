# Lecture 40.02 · What a Filter Is: an Interceptor Around Servlet Execution

> **Section:** S40 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~20 minutes

---

## 1. The chain as nested calls

```text
Tomcat
 └─ encoding.doFilter(req, res, chain)
     └─ chain.doFilter ─► logging.doFilter
                           └─ chain.doFilter ─► securityHeaders.doFilter
                                                 └─ chain.doFilter ─► … csrf.doFilter
                                                                        └─ chain.doFilter ─► TaskListServlet.service
                                                                                              └─ forward ─► list.jsp
                                                 ◄──────────────────────────── returns ────────────────────┘
                           ◄─ logging: status 200, 12 ms ─┘
 ◄─┘
```

Each filter's `doFilter` **calls the next step** through `chain.doFilter(request, response)`, and that call **returns** when everything after it is done. So a filter runs code before the servlet **and** after it, on the same thread, in the same call stack.

## 2. You've seen this shape before

| TaskFlow | Shape |
|---|---|
| Redux middleware (S16) | `store => next => action => { before; const r = next(action); after; return r; }` |
| Axios interceptors (S13, S24) | request interceptors before, response interceptors after |
| Servlet filters | `doFilter(req, res, chain) { before; chain.doFilter(req, res); after; }` |

In all three, a step can **change** what goes in, **observe or change** what comes out, or **stop** the chain.

## 3. What a filter can do

| Where | Example |
|---|---|
| before `chain.doFilter` | set the request encoding; check a CSRF token; check a login (S41); add response headers |
| instead of `chain.doFilter` | answer itself: 403, 503, a redirect to the login page |
| around it | measure time; put a request id in the logging context; catch exceptions |
| after it | read the final status; (with a wrapper, 40.09) change or capture the body |
| pass other objects | `chain.doFilter(wrappedRequest, wrappedResponse)` (40.09) |

## ✅ Recap

A filter wraps the rest of the request's processing. The code before `chain.doFilter` sees the request, the code after sees the result, and not calling it stops the request.
