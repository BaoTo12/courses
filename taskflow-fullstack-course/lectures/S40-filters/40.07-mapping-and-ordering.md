# Lecture 40.07 · Mapping: `@WebFilter` vs `web.xml`; URL Patterns vs Servlet Names; Ordering

> **Section:** S40 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~20 minutes

---

## 📇 API card: declaring filters

**Annotation:**

```java
@WebFilter(urlPatterns = "/*", dispatcherTypes = {DispatcherType.REQUEST}, initParams = @WebInitParam(name = "encoding", value = "UTF-8"))
public class CharacterEncodingFilter implements Filter { … }
```

**`web.xml`:**

```xml
<filter>
  <filter-name>logging</filter-name>
  <filter-class>com.taskflow.web.filters.RequestLoggingFilter</filter-class>
</filter>
<filter-mapping>
  <filter-name>logging</filter-name>
  <url-pattern>/*</url-pattern>          <!-- or <servlet-name>TaskListServlet</servlet-name> -->
  <dispatcher>REQUEST</dispatcher>       <!-- optional: default REQUEST only (40.08) -->
</filter-mapping>
```

| Mapping by | Matches |
|---|---|
| `<url-pattern>` | the same pattern rules as servlets (30.11): `/*`, `/tasks/*`, `*.jsp`, `/exact` |
| `<servlet-name>` | requests that go to that servlet, whatever the URL |

## 1. Ordering

| Declared with | Order |
|---|---|
| `web.xml` | the order of the `<filter-mapping>` elements (URL-pattern mappings first, then servlet-name mappings) |
| `@WebFilter` | **unspecified**: Tomcat happens to use class-scanning order, which can change between builds and servers |
| both | the `web.xml` mappings first |

**For filters whose order matters, use `web.xml`.** For TaskFlow, it always matters (40.14), so all five filters are declared there, and none has `@WebFilter`.

## 2. TaskFlow's filter section

The complete section, with the reason for each position, is in 40.14. In short:

```text
encoding → logging → securityHeaders → maintenance → (S41: authentication) → csrf → servlet
```

## ✅ Recap

Filters map by URL pattern or servlet name. Only `web.xml` gives a defined order, so use it for any chain where order matters.
