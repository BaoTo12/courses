# Lecture 40.03 · The Filter Lifecycle: `init` → `doFilter` per Request → `destroy`

> **Section:** S40 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~15 minutes

---

## 📇 API card: `javax.servlet.Filter`

```java
public interface Filter {
  default void init(FilterConfig filterConfig) throws ServletException {}   // once, at deployment
  void doFilter(ServletRequest request, ServletResponse response, FilterChain chain)
      throws IOException, ServletException;                                  // per request, on the request's thread
  default void destroy() {}                                                   // once, at undeploy
}
```

| `FilterConfig` method | Returns |
|---|---|
| `getFilterName()` | the name from `web.xml` or `@WebFilter` |
| `getInitParameter(name)` | an `<init-param>` of this filter (`CharacterEncodingFilter`'s `encoding`) |
| `getServletContext()` | the application (context params, application attributes: `MaintenanceModeFilter` uses both) |

| Fact | Consequence |
|---|---|
| **one instance** per filter declaration, created at deployment (before the first request, unlike lazily loaded servlets) | like servlets (30.05): no request data in fields; shared state must be thread-safe |
| `init` failure (an exception) | the application doesn't start |
| `doFilter` gets `ServletRequest`/`ServletResponse` | cast to `HttpServletRequest`/`HttpServletResponse` for HTTP (every TaskFlow filter does) |
| `destroy` | release what `init` acquired (threads, files); rare |

Since Servlet 4.0, `init` and `destroy` are `default` methods: a filter only has to implement `doFilter`. For HTTP-only filters, `javax.servlet.http.HttpFilter` (Servlet 4.0) offers `doFilter(HttpServletRequest, HttpServletResponse, FilterChain)` without casts.

## ✅ Recap

Created once, `doFilter` for every matching request on many threads at once, destroyed at undeploy. The same thread-safety rules as servlets.
