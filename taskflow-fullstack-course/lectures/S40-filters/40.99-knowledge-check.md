# Lecture 40.99 · ✅ Knowledge Check: Filters

> **Section:** S40 · **Type:** ✅ Knowledge Check · **Track:** ★ Core · **Time:** ~20 minutes

---

**1. (Concept)** Draw the call stack for a request through 3 filters, a servlet and a forwarded JSP.

<details><summary>Answer</summary>

```text
F1.doFilter
  └ chain.doFilter → F2.doFilter
                       └ chain.doFilter → F3.doFilter
                                            └ chain.doFilter → Servlet.service → doGet
                                                                  └ dispatcher.forward → jsp._jspService (writes the body)
                                                                  ◄ returns
                                            ◄ F3's after-code
                       ◄ F2's after-code
  ◄ F1's after-code
```

One thread, nested calls. The forward doesn't pass through REQUEST-mapped filters again (40.02, 40.08).
</details>

**2. (Code reading)** What happens if a filter calls `chain.doFilter` twice? Never?

<details><summary>Answer</summary>

Twice: the rest of the chain (and the servlet) runs twice for one request, writing twice into one response. The result is duplicated output, or an `IllegalStateException` (e.g. forwarding after the response was committed). Never: the servlet doesn't run, and unless the filter wrote a response itself, the client gets an empty 200 (40.04).
</details>

**3. (Debugging)** The security headers are missing on error pages. Which dispatcher type is missing?

<details><summary>Answer</summary>

`ERROR`. When the container renders an `<error-page>` (S43), it's an ERROR dispatch, and filters mapped only for REQUEST don't run for it. Map the headers filter for `REQUEST` and `ERROR` (40.08).
</details>

**4. (Design)** List TaskFlow's filter order and justify each position.

<details><summary>Answer</summary>

encoding (before any parameter is read) → logging (outermost observer: sees final statuses, times everything) → security headers (on every response, including ones later filters produce) → maintenance (before any work) → authentication (S41: identify the user) → CSRF (guards actions, closest to the servlets) (40.14).
</details>

**5. (Implementation)** A filter that adds `Cache-Control: no-store` to every authenticated page.

<details><summary>Answer</summary>

```java
public class NoStoreFilter implements Filter {
  @Override
  public void doFilter(ServletRequest req, ServletResponse res, FilterChain chain) throws IOException, ServletException {
    HttpServletRequest request = (HttpServletRequest) req;
    HttpSession session = request.getSession(false);
    if (session != null && session.getAttribute("currentUser") != null) {          // S41's attribute
      ((HttpServletResponse) res).setHeader("Cache-Control", "no-store");           // BEFORE the chain: headers first
    }
    chain.doFilter(req, res);
  }
}
```

Mapped after authentication in `web.xml`, `/*`, REQUEST (and ERROR). `no-store` stops browsers and proxies keeping copies of private pages (the Back button after logout shows nothing cached).
</details>
