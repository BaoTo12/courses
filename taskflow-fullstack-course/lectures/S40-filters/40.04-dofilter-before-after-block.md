# Lecture 40.04 · `doFilter`: Before = Request Interception, After = Response Interception, Not Calling = Blocking

> **Section:** S40 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~20 minutes
> Verified: `S40FiltersTest.theCsrfFilterGuardsEveryNonGetRequest` (blocked before the servlet), `.maintenanceModeAnswers503…` (a filter answering with a page)

---

## 📇 API card: `FilterChain.doFilter(request, response)`

| Call | Effect |
|---|---|
| `chain.doFilter(req, res)` | runs the next filter, or the servlet if this is the last filter; **returns** when all of it is done |
| not calling it | the servlet never runs; **this filter must produce the response** (status, error, redirect, forward) |
| calling it with other objects | the rest of the chain sees those (wrappers, 40.09) |
| calling it **twice** | the servlet runs twice and writes twice into one response: garbage or `IllegalStateException`. Never |

## 1. The three shapes in TaskFlow

```java
// before (CharacterEncodingFilter): prepare the request, then continue
if (request.getCharacterEncoding() == null) request.setCharacterEncoding(encoding);
chain.doFilter(request, response);

// block (CsrfFilter): answer, and DON'T continue
if (!SAFE_METHODS.contains(request.getMethod()) && !Csrf.isValid(request)) {
  ((HttpServletResponse) res).sendError(HttpServletResponse.SC_FORBIDDEN, "Invalid or missing CSRF token");
  return;
}
chain.doFilter(req, res);

// around (RequestLoggingFilter): before, continue, after (in finally: also when it throws)
long start = System.nanoTime();
try { chain.doFilter(request, response); status = response.getStatus(); }
finally { log.info("{} {} {} {}ms", …); }
```

## 2. "After" has a catch: the response may already be sent

By the time `chain.doFilter` returns, the JSP has usually written the body and the response may be **committed** (30.18). Headers can't be added any more, and the status can't change. That's why `SecurityHeadersFilter` sets its headers **before** the chain. "After" is for observing (the status, the duration), not for changing headers. To change the output, wrap the response (40.09).

## ✅ Recap

Before = change or check the request. Not calling = answer yourself and stop. After = observe the outcome; changing it needs a wrapper.
