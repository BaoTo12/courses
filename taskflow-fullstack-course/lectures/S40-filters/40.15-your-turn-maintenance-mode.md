## Requirements

1. A context parameter `taskflow.maintenance` (`false` by default) sets the initial state.
2. It can be switched at runtime with `POST /debug/maintenance` (`enabled=true|false`), loopback only like every `/debug` page. It's a POST, so the CSRF filter protects it.
3. While maintenance is **on**, every request gets **503 Service Unavailable**, a `Retry-After: 600` header, and a short "Down for maintenance" page, except:
   - `/static/*` (so the maintenance page has its CSS);
   - `/debug/*` (so it can be switched off).
4. The state lives in **application scope** and must be visible to all request threads as soon as it changes.
5. Place the filter in the chain so that the 503 page still gets the security headers and a log line.

**S41 will add:** logged-in admins pass through. Leave a clear place for that check.

**Tests:** switch on → `/tasks` is 503 with `Retry-After` and the page text, and a `Content-Security-Policy` header; `/static/css/app.css` and `/debug/stats` are 200; switch off → `/tasks` is 200. Switch it off in a `finally`.

## Hints

- The filter's `init(FilterConfig)` can read the context parameter (`config.getServletContext().getInitParameter(…)`) and put the state object in application scope.
- A `volatile boolean` is enough for a flag written by one thread and read by many (38.12's problem is read-modify-write, not a plain write).
- The filter can **forward** to a JSP to render the page. Filters mapped for `REQUEST` only won't run again for that forward.
