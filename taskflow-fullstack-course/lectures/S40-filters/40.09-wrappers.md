# Lecture 40.09 · Wrapping: `HttpServletRequestWrapper` / `HttpServletResponseWrapper`

> **Section:** S40 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~20 minutes

---

## 1. The idea

A filter can't change the container's request or response objects, but it can hand the rest of the chain **different** objects that delegate to the real ones and override a few methods: the decorator pattern.

## 📇 API card: the wrapper classes

| Class | Constructor | Override to… |
|---|---|---|
| `HttpServletRequestWrapper` | `(HttpServletRequest request)` | change what the servlet reads: `getParameter`, `getHeader`, `getRemoteAddr`, `getUserPrincipal`… |
| `HttpServletResponseWrapper` | `(HttpServletResponse response)` | observe or change what the servlet writes: `setStatus`, `sendError`, `setHeader`, `getWriter`, `getOutputStream`… |

Every method you don't override calls the wrapped object.

## 2. Examples

**Capture the status on old containers** (before Servlet 3.0, `getStatus()` didn't exist):

```java
class StatusCapturingResponse extends HttpServletResponseWrapper {
  private int status = 200;
  StatusCapturingResponse(HttpServletResponse response) { super(response); }
  @Override public void setStatus(int sc) { status = sc; super.setStatus(sc); }
  @Override public void sendError(int sc) throws IOException { status = sc; super.sendError(sc); }
  @Override public void sendError(int sc, String msg) throws IOException { status = sc; super.sendError(sc, msg); }
  int getStatus() { return status; }
}
// in the filter: StatusCapturingResponse wrapped = new StatusCapturingResponse(response); chain.doFilter(request, wrapped);
```

**Trim every parameter** (a request wrapper overriding `getParameter`, `getParameterValues` and `getParameterMap`), or **report the real client IP** behind a proxy by overriding `getRemoteAddr` from a trusted `X-Forwarded-For` (Tomcat's `RemoteIpValve` does this properly).

**Change the body** (compress it, add a banner): the wrapper returns a `PrintWriter` over a buffer, and the filter writes the transformed buffer after the chain. That's powerful, easy to get wrong (character encodings, `getOutputStream` vs `getWriter`, content length, flushing), and usually better done by the server (Tomcat's `compression` setting).

## 3. What TaskFlow uses

Nothing yet: Servlet 4's `getStatus()` replaces the capturing wrapper (40.06). S41 uses a request wrapper idea for the logged-in user (`getUserPrincipal`), and S43 shows the same pattern in error handling.

## ✅ Recap

Wrappers let a filter change what later code sees, without touching the container's objects: override the few methods you need.
