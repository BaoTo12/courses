# Lecture 40.11 · 🔓 Clickjacking, and How `frame-ancestors` Stops It

> **Section:** S40 · **Type:** 🔓 Attack Lab (conceptual) · **Track:** ★ Core · **Time:** ~15 minutes
> Verified: `S40FiltersTest.securityHeadersAreOnEveryResponse` (`frame-ancestors 'none'` and `X-Frame-Options: DENY` on every response)

---

## 1. The idea

Any page can embed another site in an `<iframe>`. If TaskFlow Admin can be framed, another page can show it **invisibly** (fully transparent) on top of its own content, positioned so that the victim's click on a harmless-looking button lands on TaskFlow's **Delete** button. The victim is logged in, so the click is a real, authenticated click on TaskFlow's own page, with the CSRF token already inside the form. CSRF tokens don't help: the request really comes from TaskFlow's page.

## 2. Try it safely (your local copy)

1. Before S40, create a local HTML file with `<iframe src="http://localhost:8080/taskflow/tasks" width="800" height="600"></iframe>` and open it: TaskFlow appears inside it.
2. After S40, reload it: the frame stays empty, and DevTools' Console shows the browser refusing because of `frame-ancestors 'none'` (or `X-Frame-Options: DENY`).

That demonstrates the defence without building an attack page.

## 3. The defence

| Header | Meaning |
|---|---|
| `Content-Security-Policy: frame-ancestors 'none'` | no page may frame this one (`'self'` = only our own pages; or a list of origins) |
| `X-Frame-Options: DENY` | the older equivalent (`SAMEORIGIN` also exists); kept for old browsers |

The header must be on **every** HTML response, including error pages, which is why the filter is mapped for `ERROR` too (40.08).

## Lesson

Anything a user can do with a click on your page can be triggered through a frame on someone else's page, unless you forbid being framed.
