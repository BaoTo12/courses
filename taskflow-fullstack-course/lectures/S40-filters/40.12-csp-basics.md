# Lecture 40.12 · 🛡 CSP Basics: `default-src 'self'`, Why Inline Scripts Break, Nonces

> **Section:** S40 · **Type:** 🛡 Defend · **Track:** ★ Core · **Time:** ~25 minutes

---

## 1. What a Content-Security-Policy is

A response header listing **where** each kind of resource may come from. The browser enforces it: anything else is blocked and reported in the Console.

| Directive | Controls | TaskFlow |
|---|---|---|
| `default-src` | the fallback for every `*-src` not listed | `'self'` |
| `script-src` | `<script>`, event handlers, `javascript:` URLs | `'self'` |
| `style-src` | `<link rel=stylesheet>`, `<style>`, `style=""` | `'self'` |
| `img-src` | images | `'self' data:` |
| `object-src` | `<object>`, `<embed>` (plugins) | `'none'` |
| `base-uri` | `<base href>` | `'self'` |
| `form-action` | where forms may submit | `'self'` |
| `frame-ancestors` | who may frame this page | `'none'` (40.11) |

## 2. Why inline code breaks, and why that's the point

Without `'unsafe-inline'`, the browser runs **no** inline `<script>…</script>`, no `onclick="…"`, and applies no `style="…"`. That's exactly what an XSS injection looks like. If 35.14's stored comment ever escaped `<c:out>`, a CSP without `'unsafe-inline'` would still refuse to run it. CSP is the **second lock** behind output encoding (35.15).

So TaskFlow keeps all code in files:
- scripts: `static/js/confirm-delete.js`, reading `data-` attributes (35.17);
- styles: `app.css` + `admin.css` (40.10).

## 3. When you really need inline code: nonces and hashes

| Technique | How |
|---|---|
| **nonce** | the server generates a random value per response: `script-src 'self' 'nonce-r4nd0m'`, and marks allowed inline scripts `<script nonce="r4nd0m">`. An injected script doesn't know the nonce. S49 uses this to pass initial data to the React island |
| **hash** | `script-src 'sha256-…'` of one exact inline script: fine for a fixed snippet |
| `'unsafe-inline'` | allows every inline script: it disables most of CSP's XSS protection. Avoid |

## 4. Rolling out a CSP on an existing app

`Content-Security-Policy-Report-Only` + `report-uri`/`report-to`: the browser **reports** violations without blocking. Collect them, fix the pages, then switch to enforcing.

## ✅ Recap

A CSP tells the browser where code may come from. With `'self'` and no `'unsafe-inline'`, injected markup can't run code. Keep scripts and styles in files, and use nonces for the rare inline need.
