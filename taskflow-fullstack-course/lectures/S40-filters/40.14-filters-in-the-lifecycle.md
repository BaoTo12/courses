## 1. The whole path

```text
browser ─► Tomcat connector ─► engine/host valves (access log, error report…) ─► context (/taskflow)
  ─► REQUEST dispatch: filter chain ─► servlet ─► forward ─► JSP ─► <jsp:include>s
  ◄─ back up the same call stack: JSP returns → servlet returns → each filter's "after" code → Tomcat sends the rest
```

Listeners (38.07) run around this: `requestInitialized` before the first filter, `requestDestroyed` after the last.

## 2. TaskFlow's order, and why

```xml
<filter-mapping><filter-name>encoding</filter-name><url-pattern>/*</url-pattern></filter-mapping>
<filter-mapping><filter-name>logging</filter-name><url-pattern>/*</url-pattern></filter-mapping>
<filter-mapping><filter-name>securityHeaders</filter-name><url-pattern>/*</url-pattern>
  <dispatcher>REQUEST</dispatcher><dispatcher>ERROR</dispatcher></filter-mapping>
<filter-mapping><filter-name>maintenance</filter-name><url-pattern>/*</url-pattern></filter-mapping>
<!-- S41: authentication -->
<filter-mapping><filter-name>csrf</filter-name><url-pattern>/*</url-pattern></filter-mapping>
```

| # | Filter | Must come… | Because |
|---|---|---|---|
| 1 | encoding | before **anything** reads a parameter | the first `getParameter` fixes the encoding for good (40.19); CSRF and maintenance read the request |
| 2 | logging | outside everything else | it must see the **final** status of requests blocked by later filters (403, 503) and time the whole chain |
| 3 | security headers | before any filter that answers by itself | the 403 and 503 answered by later filters need the headers too |
| 4 | maintenance | before authentication and application work | during maintenance nothing else should run; static files and `/debug` pass |
| 5 | authentication (S41) | before CSRF | "who are you" before "is this request really from you"; an anonymous POST → login page, not 403 |
| 6 | CSRF | last before the servlet | it protects the servlets' actions |

## ✅ Recap

The chain is a call stack: early filters wrap later ones. Put the ones that prepare the request first, the ones that observe everything outermost, and the ones that guard actions closest to the servlet.
