# Lecture 40.18 · 🐞 Debug: CSS and Images Fail to Load After Adding a Filter on `/*`

> **Section:** S40 · **Type:** 🐞 Debug · **Track:** ★ Core · **Time:** ~15 minutes

---

## 1. Symptom

After adding a filter that redirects anonymous users to `/login` (a preview of S41), the login page appears **unstyled**. DevTools → Network: `app.css` → `302` → `/login`, and the "stylesheet" received is the login page's HTML. The Console may add "Refused to apply style… MIME type ('text/html') is not a supported stylesheet MIME type" (thanks to `nosniff`, 40.10).

## 2. Cause

`/*` means **every** request, static files included. The browser requests the CSS **without** being logged in (it's the login page), so the filter redirects the CSS request too.

The same happens with the maintenance filter (40.15) if `/static/*` isn't exempt, and with any "block unless…" filter.

## 3. Fixes

| Fix | Notes |
|---|---|
| exempt public paths in the filter: `/static/`, `/login`, `/favicon.ico` | TaskFlow's approach (40.16, S41); keep the list short and explicit |
| map the filter to protected paths only (`/tasks/*`, `/categories/*`) | easy to forget a new path: unprotected by default. Prefer "protect everything, exempt a few" |
| check the path with `getServletPath()` | not `getRequestURI().contains("…")`, which a query string can fool |

## ✅ Takeaway

A `/*` filter sees your CSS, JS, images and favicon too. Decide explicitly what's public.
