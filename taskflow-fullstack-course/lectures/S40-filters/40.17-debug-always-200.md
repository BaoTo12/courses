# Lecture 40.17 · 🐞 Debug: the Logging Filter Always Logs Status 200

> **Section:** S40 · **Type:** 🐞 Debug · **Track:** ★ Core · **Time:** ~15 minutes
> The correct version is checked by `S40FiltersTest.everyRequestIsLoggedWithItsFinalStatusAndAnId` (a 404 is logged as 404).

---

## Variant A: reading the status too early

```java
log.info("{} {} {}", request.getMethod(), request.getRequestURI(), response.getStatus());   // ❌ before the chain
chain.doFilter(request, response);
```

Before the servlet runs, nobody has set a status: it's the default, 200. **Fix:** read it **after** `chain.doFilter` returns.

## Variant B: exceptions

```java
long start = System.nanoTime();
chain.doFilter(request, response);                      // the servlet throws a NullPointerException
log.info("… {} …", response.getStatus());              // ❌ never reached: no log line at all
```

With the log in a `finally`, it runs, but `getStatus()` still says **200**: the servlet never set anything, and Tomcat turns the exception into a 500 **after** the exception has travelled up through the filter. **Fix** (TaskFlow's): start with `status = 500`, and only replace it with `response.getStatus()` if the chain returned normally.

## Variant C: old containers

Before Servlet 3.0, `HttpServletResponse` had no `getStatus()`. The classic fix is a response wrapper that records `setStatus`/`sendError` (40.09). You'll still see such wrappers in older codebases.

## ✅ Takeaway

The status is only known **after** the chain, and not even then if an exception escapes. Log in `finally`, and treat "threw" as 500.
