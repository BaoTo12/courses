# Lecture 40.01 · The Problem: Cross-Cutting Concerns Copied into Every Servlet

> **Section:** S40 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~10 minutes

---

Count what S37–S39's POST servlets start with:

```java
request.setCharacterEncoding("UTF-8");                  // 6 servlets
if (!Csrf.isValid(request)) {                            // 8 servlets
  response.sendError(HttpServletResponse.SC_FORBIDDEN, "Invalid or missing CSRF token");
  return;
}
```

And what's missing everywhere: a log line per request, security headers on every response, a way to take the whole app offline for maintenance, and (S41) "you must be logged in".

These are **cross-cutting concerns**: they're about *every* request, not about tasks or categories.

| Concern | In each servlet | Consequence |
|---|---|---|
| request encoding | 6 copies | a new POST servlet without it garbles Vietnamese text (30.17) |
| CSRF check | 8 copies | one forgotten copy = one unprotected action (37.13 §5) |
| logging, timing | none | no idea which request failed, or how long it took |
| security headers | none | clickjacking, MIME sniffing (40.10) |
| authentication (S41) | would be 20 copies | one forgotten copy = a public page |

The Servlet API's answer is the **filter**: code that runs *around* servlets, configured once, for URL patterns. After S40, the servlets above lose those lines, and a servlet added tomorrow is protected by default.

## ✅ Recap

If code must run for every request, it doesn't belong in each servlet. Filters are where it goes.
