## 1. Why not `fetchBaseQuery`?

RTK Query ships `fetchBaseQuery`, a small wrapper around `fetch`. It is the right default for a **new** app. TaskFlow isn't new: since S13, the Axios instance in `src/api/client.ts` already does the following:

- `baseURL` `/api`, `withCredentials`, and a 10 s timeout;
- a request interceptor that adds an `X-Request-Id` and times each request (13.08);
- a response interceptor that turns *every* failure into an `ApiRequestError` with `kind`, `status`, `code` and `fieldErrors` (13.09).

Rewriting all of that as `fetchBaseQuery` options would duplicate it. Instead, a **custom base query** plugs the instance we have into RTK Query. That is what base queries are for.

## 2. The contract a base query must follow

```ts
type BaseQueryFn<Args, Result, Error> =
  (args: Args, api: BaseQueryApi, extraOptions: {}) =>
    MaybePromise<{ data: Result } | { error: Error }>;
```

Three rules:

1. **Return, never throw.** Success returns `{ data }`, and failure returns `{ error }`. (A throw is treated as an unexpected crash: RTK logs it and rejects without your error shape.)
2. The `error` value ends up **in the Redux state** (`state.api.queries[…].error`). It must be **serialisable**: plain data, not an `Error` instance.
3. `api.signal` is the request's `AbortSignal`. Pass it to your HTTP client, or `abort()` does nothing.

## 3. The code

✍️ `src/api/axiosBaseQuery.ts`

```ts
// S22 (22.03): RTK Query's "base query" = the ONE function every endpoint uses to talk to the server.
// Ours goes through the S13 Axios instance, so the interceptors (request id, timing, error normalisation)
// keep working, and failures reach RTK Query as the same serialisable ApiErrorPayload the thunks used.
import type { BaseQueryFn } from '@reduxjs/toolkit/query';
import type { AxiosRequestConfig } from 'axios';
import { ApiRequestError, toApiErrorPayload } from './api-error';
import type { ApiErrorPayload } from './api-error';
import { api } from './client';

/** What an endpoint's `query()` returns: a description of the HTTP request. */
export interface AxiosQueryArgs {
  url: string;
  method?: 'GET' | 'POST' | 'PUT' | 'PATCH' | 'DELETE';
  /** The JSON body (POST, PUT, PATCH). */
  data?: unknown;
  /** Query-string parameters; Axios drops `undefined` values. */
  params?: AxiosRequestConfig['params'];
  /** A type guard for the response body (13.05): a mismatch becomes an 'unexpected' error, not bad data. */
  validate?: (data: unknown) => boolean;
}

export function axiosBaseQuery(): BaseQueryFn<AxiosQueryArgs, unknown, ApiErrorPayload> {
  return async ({ url, method = 'GET', data, params, validate }, { signal }) => {
    try {
      // `signal` is RTK Query's AbortSignal (22.06): `queryResult.abort()` really aborts the HTTP request.
      const response = await api.request({ url, method, data, params, signal });
      if (validate && !validate(response.data)) {
        const error = new ApiRequestError({ kind: 'unexpected', message: 'The server sent an unexpected response.' });
        return { error: toApiErrorPayload(error) };
      }
      return { data: response.data };
    } catch (error) {
      // The response interceptor already turned any failure into an ApiRequestError (13.08);
      // RTK Query stores `error` in its cache, so it must be plain, serialisable data (20.16).
      return { error: toApiErrorPayload(error) };
    }
  };
}
```

Line by line:

- **`AxiosQueryArgs`** is what each endpoint's `query()` returns (22.04): `{ url, method, data, params }`. These are Axios's names, so the endpoints read like Axios calls.
- **`validate`** is TaskFlow's own addition. S13 checked every response with a type guard (`isTask`, `isPageOf`) before trusting it. The base query keeps that rule: when the guard fails, the result is a normal `{ error }` with `kind: 'unexpected'`. Components show it like any other error, and **no** unchecked data ever reaches the cache.
- **`toApiErrorPayload(error)`** converts the `ApiRequestError` from the interceptor into the plain `ApiErrorPayload` object from 20.09. That satisfies rule 2. It is the same shape `rejectWithValue` used in S20, so `fieldErrorsOf` and `toErrorMessage` keep working unchanged.
- **`signal`** goes to `api.request`. The claims test proves that `dispatch(getTasks.initiate(…)).abort()` cancels the actual Axios request.

## 4. Types flow from here

`BaseQueryFn<AxiosQueryArgs, unknown, ApiErrorPayload>` has three consequences:

- Every endpoint's `query()` **must** return an `AxiosQueryArgs`. A typo in `method: 'PTACH'` is a compile error.
- Every hook's `error` is typed `ApiErrorPayload | SerializedError | undefined`. The `SerializedError` covers crashes inside RTK itself, such as a throwing `transformResponse`. The `fieldErrorsOf` and `toErrorMessage` helpers from 20.09 already accept both shapes.
- The response data is `unknown` at this level. Each endpoint declares its result type (`build.query<Page<Task>, …>`), and `validate` is what makes that declaration honest.

## 📇 API card: base queries

### `BaseQueryApi` (the second argument)

| Field | Type | Meaning |
|---|---|---|
| `signal` | `AbortSignal` | Aborted by `.abort()` on the request, or when RTK cancels it. |
| `abort` | `(reason?) => void` | Abort from inside the base query. |
| `dispatch`, `getState` | store functions | Read a token from the state, dispatch a `loggedOut()` on 401… |
| `extra` | `unknown` | The thunk `extraArgument` (20.10). |
| `endpoint` | `string` | The endpoint's name, e.g. `'getTasks'`. |
| `type` | `'query' \| 'mutation'` | Which kind of endpoint is running. |
| `forced` | `boolean \| undefined` | `true` for a forced refetch (`refetch()`, `forceRefetch`). |
| `queryCacheKey` | `string \| undefined` | Queries only: the cache key, `getTask(5)`. |

### `fetchBaseQuery(options)` (the built-in one)

| Option | Default | Meaning |
|---|---|---|
| `baseUrl` | `''` | Prefix for relative URLs. |
| `prepareHeaders(headers, api)` | — | Add `Authorization`, CSRF… Return the `Headers`. |
| `fetchFn` | global `fetch` | Inject a fetch implementation (tests, SSR). |
| `paramsSerializer` | `URLSearchParams` | How `params` becomes a query string. |
| `credentials`, `mode`, … | `fetch` defaults | Any `RequestInit` option. |
| `timeout` | none | Milliseconds before the request is aborted. |
| `responseHandler` | `'json'` | `'json' \| 'text' \| 'content-type' \| (response) => …`. |
| `validateStatus` | `2xx` is OK | `(response, body) => boolean`. |
| `jsonContentType`, `isJsonContentType`, `jsonReplacer` | — | Fine control over JSON bodies. |

Each request returns `string | { url, method?, body?, params?, headers?, responseHandler?, validateStatus?, timeout? }`. The error shape is `FetchBaseQueryError`: `{ status: number, data }` for an HTTP error, or `{ status: 'FETCH_ERROR' | 'PARSING_ERROR' | 'TIMEOUT_ERROR' | 'CUSTOM_ERROR', error: string }`.

**Minimal example outside TaskFlow:** a base query for a GraphQL-ish backend, where every request is a POST to one URL:

```ts
const rpcBaseQuery: BaseQueryFn<{ method: string; params: unknown }, unknown, { message: string }> =
  async ({ method, params }, { signal }) => {
    try {
      const res = await fetch('/rpc', { method: 'POST', body: JSON.stringify({ method, params }), signal });
      const json = await res.json();
      return res.ok ? { data: json.result } : { error: { message: json.error ?? res.statusText } };
    } catch (e) {
      return { error: { message: e instanceof Error ? e.message : 'Network error' } };
    }
  };
```

**When to use a custom base query:** you already have an HTTP client with interceptors (Axios), a non-REST protocol (RPC, GraphQL without Apollo, Firebase SDK), or a house error shape.

**When not to:** a plain REST API with no client yet → `fetchBaseQuery`. If one endpoint needs to do something special (several requests, local computation), use a per-endpoint **`queryFn`** (22.07); you don't need a new base query.

**Common mistakes:**
- Throwing from the base query instead of returning `{ error }`.
- Returning an `Error` instance or an `AxiosError` as the error. It isn't serialisable, so you get a warning and a DevTools view you can't read.
- Ignoring `signal`. `abort()` then "works" in the state while the HTTP request still runs.
- Using a module-level `baseUrl` that changes at runtime. Read it from `getState()` inside the base query instead.
