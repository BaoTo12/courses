## 1. The five words

| Word | What it is | TaskFlow example |
|---|---|---|
| **API slice** | the object `createApi` returns: a reducer, a middleware, endpoints, hooks, utilities | `apiSlice` in `features/api/apiSlice.ts` |
| **Base query** | the one function that actually performs a request | `axiosBaseQuery()` (22.03), wrapping our Axios instance |
| **Endpoint** | one operation: a **query** (read) or a **mutation** (write) | `getTasks`, `getTask`, `addTask`, `deleteTask`… |
| **Cache entry** | the stored result of **one query endpoint called with one argument** | `getTasks({"size":100})`, `getTask(5)` |
| **Subscription** | "a component (or code) is using this cache entry right now" | every mounted `useGetTasksQuery(LIST_QUERY)` |

```text
component ──useGetTaskQuery(5)──► endpoint getTask ──arg 5──► cache entry "getTask(5)"
                                        │                        ▲ status, data, error
                                        └── query(5) → { url: '/tasks/5' } ── baseQuery ── Axios ──► GET /api/tasks/5
```

## 2. `createApi` generates a whole feature

```ts
import { createApi, fetchBaseQuery } from '@reduxjs/toolkit/query/react';

interface Post { id: number; title: string }

export const blogApi = createApi({
  reducerPath: 'blogApi',
  baseQuery: fetchBaseQuery({ baseUrl: '/api' }),
  tagTypes: ['Post'],
  endpoints: (build) => ({
    getPosts: build.query<Post[], void>({ query: () => '/posts', providesTags: ['Post'] }),
    addPost: build.mutation<Post, Omit<Post, 'id'>>({
      query: (body) => ({ url: '/posts', method: 'POST', body }),
      invalidatesTags: ['Post'],
    }),
  }),
});

export const { useGetPostsQuery, useAddPostMutation } = blogApi;
```

From those lines you get:

- `blogApi.reducer` → mount it at `state.blogApi`.
- `blogApi.middleware` → runs the requests, counts subscriptions, removes unused entries, refetches invalidated ones.
- `blogApi.endpoints.getPosts` → `.initiate(arg)` (a thunk), `.select(arg)` (a selector), `.matchFulfilled` & co. (matchers).
- `useGetPostsQuery`, `useAddPostMutation` → React hooks, **named after the endpoints** (`use` + `GetPosts` + `Query`).
- `blogApi.util` → `invalidateTags`, `resetApiState`, `updateQueryData`, `upsertQueryData`… (22.08, S23).

> ⚠️ Import from **`@reduxjs/toolkit/query/react`** to get the hooks. `@reduxjs/toolkit/query` is the UI-agnostic core: same `createApi`, **no hooks**.

## 3. The cache lives in your store

After `useGetTasksQuery({ size: 100 })` and `useGetTaskQuery(5)` succeed, `state.api` looks like this (trimmed):

```json
{
  "queries": {
    "getTasks({\"size\":100})": {
      "status": "fulfilled", "endpointName": "getTasks", "originalArgs": { "size": 100 },
      "data": { "items": [ … ], "page": 0, "size": 100, "totalItems": 12, "totalPages": 1 },
      "requestId": "…", "startedTimeStamp": 1790000000000, "fulfilledTimeStamp": 1790000000140
    },
    "getTask(5)": { "status": "fulfilled", "data": { "id": 5, … }, … }
  },
  "mutations": {},
  "provided": { … which cache entries provide which tags (22.08) … },
  "subscriptions": { … },
  "config": { "reducerPath": "api", "keepUnusedDataFor": 60, … }
}
```

What the verification tests pinned down:

- **Cache key** = `endpointName(serializedArgs)`. The argument is serialized with sorted object keys, so `{ size: 100, page: 0 }` and `{ page: 0, size: 100 }` are the **same** entry.
- A **pending** entry (first request in flight) has `status: 'pending'` and **no `data` key at all**, not `data: undefined`.
- `state.api.subscriptions` is a **mirror** the middleware syncs lazily (for the DevTools). The middleware keeps the real counts internally, so **never** read subscription counts from the state in app code.

## 4. Subscriptions drive everything

```text
mount  <TasksPage>     useGetTasksQuery(LIST_QUERY)  → subscriptions: 1 → no entry yet → REQUEST
mount  <Dashboard>     useGetTasksQuery(LIST_QUERY)  → subscriptions: 2 → entry exists  → no request (dedupe)
unmount both                                          → subscriptions: 0 → timer starts (keepUnusedDataFor, 60 s)
60 s later, nobody came back                          → entry removed from state.api.queries
```

- Many subscribers, **one** request, one cache entry, one `data` reference.
- An **invalidated** entry (22.08) is refetched **only if it has subscribers**. Unsubscribed entries are just removed.
- Unsubscribing does **not** abort a request that's in flight (verified). The response still lands in the cache; it's then collected after the timer.

## 5. Endpoints are Redux, underneath

Nothing magic happens outside Redux. Every request is a thunk with lifecycle actions you can see in the DevTools:

| Action type | When |
|---|---|
| `api/executeQuery/pending` → `fulfilled` / `rejected` | a query request |
| `api/executeMutation/pending` → `fulfilled` / `rejected` | a mutation request |
| `api/internalSubscriptions/subscriptionsUpdated`, `api/queries/removeQueryResult`, `api/config/middlewareRegistered`… | bookkeeping |

The action's `meta.arg` tells you which endpoint and argument: `meta.arg.endpointName`, `meta.arg.originalArgs`. You won't match on these strings: every endpoint gives you **matchers** (`apiSlice.endpoints.deleteTask.matchFulfilled`, 22.09).

## 📇 API card: `createApi(options)`

```ts
createApi({ reducerPath?, baseQuery, endpoints, tagTypes?, keepUnusedDataFor?, refetchOnMountOrArgChange?,
            refetchOnFocus?, refetchOnReconnect?, serializeQueryArgs?, invalidationBehavior?, extractRehydrationInfo? })
```

| Option | Type | Required | Default | Meaning |
|---|---|---|---|---|
| `baseQuery` | `BaseQueryFn` | ✅ | — | Performs every request. `fetchBaseQuery({ baseUrl })` or your own (22.03). |
| `endpoints` | `(build) => ({ name: build.query(…) \| build.mutation(…) })` | ✅ | — | The operations. The keys become endpoint and hook names. |
| `reducerPath` | `string` | | `'api'` | Where the reducer is mounted. Must be unique if you have several APIs. |
| `tagTypes` | `readonly string[]` | | `[]` | The tag names `providesTags`/`invalidatesTags` may use. Typos become type errors. |
| `keepUnusedDataFor` | `number` (seconds) | | `60` | How long an entry with 0 subscribers is kept. Per-endpoint override too. |
| `refetchOnMountOrArgChange` | `boolean \| number` | | `false` | `true`: refetch whenever a new subscriber mounts; `n`: only if the data is older than `n` seconds. |
| `refetchOnFocus` | `boolean` | | `false` | Refetch subscribed queries when the window regains focus. **Needs `setupListeners(store.dispatch)`.** |
| `refetchOnReconnect` | `boolean` | | `false` | Same, when the network comes back. **Needs `setupListeners`.** |
| `serializeQueryArgs` | `({ queryArgs, endpointName, endpointDefinition }) => string \| object` | | `defaultSerializeQueryArgs` | Custom cache keys (S23: infinite lists). |
| `invalidationBehavior` | `'delayed' \| 'immediately'` | | `'delayed'` | `'delayed'` waits until running queries/mutations settle before refetching invalidated entries (avoids refetching twice). |
| `extractRehydrationInfo` | `(action, { reducerPath }) => …` | | — | SSR / redux-persist rehydration. Not used in TaskFlow. |

(RTK 2.x also accepts schema-validation options, `onSchemaFailure`, `catchSchemaFailure` and `skipSchemaValidation`, for endpoints that declare Standard Schema validators. TaskFlow validates with its own guards in the base query instead, 22.03.)

**Returns** an API slice: `{ reducerPath, reducer, middleware, endpoints, util, injectEndpoints, enhanceEndpoints, use…Query / use…Mutation hooks }`.

**Minimal example (outside TaskFlow):** the `blogApi` in §2.

**When to use:** reading and writing a server's data from a Redux app, especially when several components need the same data.

**When not to:**
- The data is client state (a draft, UI prefs) → `createSlice`.
- One-off async workflows that don't cache anything (e.g. "export a CSV then download it") → a thunk (`createAsyncThunk`, 22.10).
- You don't use Redux at all → TanStack Query fits better than pulling in Redux just for a cache.

**Common mistakes:**
- Calling `createApi` **once per feature** (`tasksApi`, `categoriesApi`…). Tags can't cross APIs, and each API adds its own reducer and middleware. Use **one API slice** and split files with `injectEndpoints` (22.A).
- Forgetting to add `api.middleware` to the store: queries stay `pending` forever, and RTK logs a warning.
- Importing from `@reduxjs/toolkit/query` and wondering where the hooks are.
- Setting `refetchOnFocus: true` and forgetting `setupListeners`: nothing happens, silently.

## ✅ Recap

- `createApi` → reducer + middleware + endpoints + hooks + utils, from a declarative description.
- One **cache entry** per (endpoint, serialized argument). Pending entries have no `data`.
- **Subscriptions** decide what gets fetched, kept, refetched and removed.
- It's all Redux actions underneath; use endpoint **matchers** to react to them.
