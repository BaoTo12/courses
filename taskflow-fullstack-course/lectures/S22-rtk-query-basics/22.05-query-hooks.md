## 1. One line replaces the effect

```tsx
function PostList() {
  const { data: posts = [], isLoading, isFetching, error, refetch } = useGetPostsQuery();
  if (isLoading) return <Spinner />;
  if (error) return <ErrorBanner error={error} onRetry={refetch} />;
  return <ul className={isFetching ? 'is-stale' : ''}>{posts.map((p) => <li key={p.id}>{p.title}</li>)}</ul>;
}
```

On mount, the hook dispatches `initiate(arg)`: it **subscribes**, and fetches if needed. On unmount it unsubscribes. When the argument changes, it unsubscribes from the old entry and subscribes to the new one. The component re-renders when **its** entry changes.

> ⚠️ `data: posts = []` gives a **new** `[]` on every render while there's no data. That's fine for rendering. Don't pass it to a `memo` child or a `useEffect` dependency: use a module-level constant (`NO_TASKS`, 21.02) instead.

## 2. The four status flags, and the one people mix up

| Flag | True when… |
|---|---|
| `isUninitialized` | no request has started (e.g. `skip`) |
| `isLoading` | the **first** request for this hook is in flight: there is **no data yet** |
| `isFetching` | **any** request for the current arg is in flight: the first one, a refetch, or an invalidation refetch |
| `isSuccess` | we have data (possibly being refetched) |
| `isError` | the last request failed |

```text
first load:          isLoading ✔  isFetching ✔  data: undefined
loaded:              isLoading ✘  isFetching ✘  data: {…}
refetch (tag / btn): isLoading ✘  isFetching ✔  data: {…}   ← old data stays on screen
```

**`isLoading` → spinner instead of content. `isFetching` → a subtle "refreshing…" hint on top of content.** Get this wrong and the whole list blinks to a spinner after every save (22.14).

> 🔎 Verified trap: the **cache entry's** `isLoading`, from `endpoint.select(arg)(state)`, means `status === 'pending'`. So it is **true during a refetch**. The **hook's** `isLoading` is false then. The hook adds its own logic: it means "loading *and* no data yet". If you build a loading UI from a selector, test `data === undefined`, not `isLoading`.

## 3. `data` vs `currentData`

When the argument changes (`useGetTaskQuery(5)` → `useGetTaskQuery(7)`):

- `data` keeps showing **the last successful result**, task 5, until task 7 arrives. That avoids a blank screen.
- `currentData` is `undefined` until task 7 arrives. It is only ever data **for the current arg**.

For a details page, showing task 5 under the URL `/tasks/7` would be wrong. Use `currentData`, or key the page by id. For a filtered list, keeping the old rows while the new filter loads is usually what you want, so use `data`.

## 4. Conditional fetching: `skip` and `skipToken`

A route param may be missing or invalid. You can't call a hook conditionally (rules of hooks), so you tell the hook not to run:

```ts
import { skipToken } from '@reduxjs/toolkit/query/react';

const id = parseTaskId(rawId);                  // number | null
const { data } = useGetTaskQuery(id ?? skipToken); // null → no request, isUninitialized: true
```

- `skipToken` in place of the arg **narrows the type**. The endpoint receives a `number`, never `null`.
- The older form `useGetTaskQuery(id!, { skip: id === null })` works, but it needs the `!` lie. Prefer `skipToken`.
- Skipping **unsubscribes** from the previous entry. It doesn't clear `data` from other components.

## 5. `selectFromResult`: subscribe to less

Every consumer of `useGetTasksQuery(LIST_QUERY)` re-renders whenever anything in its result changes: `isFetching` flips twice per refetch. The dashboard only needs to know "still loading?":

```ts
const { isLoading } = useGetTasksQuery(LIST_QUERY, { selectFromResult: ({ isLoading }) => ({ isLoading }) });
```

- The hook compares the returned object **shallowly**. It re-renders only when `isLoading` changes.
- Returning a **new array** each time (`data?.items.filter(…)`) defeats that. Memoize it with `createSelector` (23.03 does it properly).

## 6. Keeping data fresh: polling, focus, reconnect

```ts
useGetTasksQuery(LIST_QUERY, { pollingInterval: 30_000, skipPollingIfUnfocused: true });
useGetTasksQuery(LIST_QUERY, { refetchOnMountOrArgChange: 60 }); // refetch on mount if the data is older than 60 s
useGetTasksQuery(LIST_QUERY, { refetchOnFocus: true });          // needs setupListeners(store.dispatch) once
```

TaskFlow uses none of these yet. Tags (22.08) keep *our own* edits fresh. Other people's edits are the topic of S23 (polling) and S47 (server-sent events).

## 📇 API card: `useXxxQuery(arg, options?)`

```ts
const result = useGetTaskQuery(arg: number | typeof skipToken, options?: UseQueryOptions)
```

| Option | Type | Default | Meaning |
|---|---|---|---|
| `skip` | `boolean` | `false` | Don't subscribe or fetch. Prefer `skipToken` as the arg. |
| `pollingInterval` | `number` (ms) | `0` (off) | Refetch every *n* ms while subscribed. |
| `skipPollingIfUnfocused` | `boolean` | `false` | Pause polling while the window has no focus. |
| `refetchOnMountOrArgChange` | `boolean \| number` (s) | the `createApi` value (`false`) | Refetch when this hook mounts or its arg changes, always or only if older than *n* s. |
| `refetchOnFocus` | `boolean` | the `createApi` value (`false`) | Needs `setupListeners`. |
| `refetchOnReconnect` | `boolean` | the `createApi` value (`false`) | Needs `setupListeners`. |
| `selectFromResult` | `(result) => object` | the whole result | Pick fields; shallow-compared to decide re-renders. |

**Returns** (the fields you'll use):

| Field | Meaning |
|---|---|
| `data` | the latest successful result (may be for a previous arg) |
| `currentData` | the result for the **current** arg, or `undefined` |
| `error` | `ApiErrorPayload \| SerializedError \| undefined` in TaskFlow (the base query's error type) |
| `isUninitialized`, `isLoading`, `isFetching`, `isSuccess`, `isError` | see §2 |
| `refetch()` | force a new request for this arg. Returns a promise with `.unwrap()`. |
| `originalArgs`, `requestId`, `startedTimeStamp`, `fulfilledTimeStamp`, `endpointName` | details of the last request |

**Related hooks** (same endpoint, generated too):

| Hook | Use it for |
|---|---|
| `useLazyGetTaskQuery()` → `[trigger, result, lastPromiseInfo]` | fetch **on an event** (a "Preview" button), not on mount |
| `useGetTaskQueryState(arg)` | read the entry **without** subscribing (another component owns the subscription) |
| `useGetTaskQuerySubscription(arg)` | subscribe/fetch **without** reading (prefetch in a layout) |
| `apiSlice.usePrefetch('getTask')` → `prefetch(id, { ifOlderThan? })` | warm the cache on hover |

**When to use:** any component that needs server data to render.

**When not to:**
- Outside React (thunks, listeners, tests) → `dispatch(endpoint.initiate(arg))` and `endpoint.select(arg)(state)`.
- For a one-shot fetch triggered by a click → the lazy hook.

**Common mistakes:**
- A spinner on `isFetching`: the content blinks on every refetch.
- Calling the hook conditionally (`if (id) useGetTaskQuery(id)`) breaks the rules of hooks. Pass `skipToken` instead.
- Worrying about inline object args. The hook serializes the arg, so `useGetTasksQuery({ size: 100 })` on every render is **not** a refetch loop. Only the content matters. TaskFlow still uses a shared `LIST_QUERY` constant so that every component hits the **same** cache entry.
- `refetchOnFocus: true` without `setupListeners(store.dispatch)`.
- Reading `data` for a details page after an id change and showing the wrong record: use `currentData`.

## ✅ Recap

- Spinner on `isLoading`, "refreshing" hint on `isFetching`.
- `skipToken` for "not yet". `selectFromResult` for "only re-render for what I use".
- `data` survives arg changes; `currentData` doesn't.
