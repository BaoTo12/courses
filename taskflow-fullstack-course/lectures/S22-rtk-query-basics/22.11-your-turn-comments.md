> **Section:** S22 · **Type:** 🎯 Your Turn · **Track:** ★ Core · **Time:** ~75 minutes
> **Project feature:** the details page lists a task's comments, and logged-in users can post one. Posting refreshes **only that task's** comments.
> Solution: [`solutions/S22-rtk-query-basics/22.12-solution.md`](../../solutions/S22-rtk-query-basics/22.12-solution.md)

## The API (already in the mock server)

| Request | Response |
|---|---|
| `GET /api/tasks/{taskId}/comments` | `200` `Comment[]`, oldest first |
| `POST /api/tasks/{taskId}/comments` with body `{ "body": "…" }` (must be logged in) | `201` the created `Comment`; `400` with `fieldErrors.body` if it's blank or longer than 1000 characters |

`Comment` is already in `domain/types.ts`: `{ id, taskId, authorId, body, createdAt }`.

## Requirements

1. **Guard.** Add `isComment(value: unknown): value is Comment` to `domain/guards.ts`, in the style of `isTask`.
2. **Endpoints** in the one `apiSlice`:
   - `getComments`, a query with arg `taskId: number` and result `Comment[]`, validated with your guard;
   - `addComment`, a mutation with arg `{ taskId, body }` and result `Comment`.
   - Tags: adding a comment to task 5 must refetch task 5's comments and **nothing else**. Not task 6's comments, and not the task list.
3. **`<CommentsSection taskId={…} />`** in `src/features/comments/`, rendered at the bottom of `TaskDetailsPage`:
   - a "Comments" heading, and the list (body + date), or "No comments yet.";
   - a loading text on the **first** load only. While a refetch runs, keep the list and show a small "· refreshing…" hint next to the heading (22.05 §2);
   - for **logged-in** users only: a textarea (max 1000 characters) and a "Post comment" button, disabled while posting. A blank (or whitespace-only) comment shows "Write something first." and sends nothing;
   - on success, clear the textarea. On failure, **keep the text**, and show the server's `fieldErrors.body` under the field, or the general error message.
4. **Security:** render comment bodies as **plain text**. Never `dangerouslySetInnerHTML`. The mock server stores bodies **as typed**, HTML included, and you'll attack exactly this in S26's XSS lab. Line breaks may be kept with CSS.
5. **Styles:** a CSS Module `CommentsSection.module.scss`, using the design tokens (`space()`, `theme()`).

## Acceptance tests

Copy `src/features/comments/comments.test.ts` from `reference/taskflow/frontend/` into your project. It runs your endpoints against an in-memory server behind the **real** Axios instance, and it checks two things:

- the exact request sequence: `GET 5`, `GET 6`, `POST 5`, then **only** `GET 5` again;
- that `unwrap()` rejects with `{ status: 400, fieldErrors: { body: … } }` for a 1001-character comment.

Both must pass, along with `tsc -b` and lint.

## Hints (read only if stuck)

<details><summary>Hint 1: the tags</summary>

Static `'Comment'` tags would refetch every task's comments. Use tag **functions**, and use the **task id** as the tag id, on both sides (22.08 §4).
</details>

<details><summary>Hint 2: keeping the text on failure</summary>

`await addComment({ taskId, body }).unwrap()` inside `try`. Clear the state only after the `await` succeeds. In `catch`, read `fieldErrorsOf(err)?.body`.
</details>

<details><summary>Hint 3: the refreshing hint</summary>

`isFetching && !isLoading`.
</details>
