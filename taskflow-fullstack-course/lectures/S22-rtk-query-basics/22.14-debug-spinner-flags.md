# Lecture 22.14 · 🐞 Debug: The List Blinks to a Spinner After Every Toggle

> **Section:** S22 · **Type:** 🐞 Debug · **Track:** ★ Core · **Time:** ~25 minutes
> Verified by: `src/verification/s22-rtk-query.claims.test.ts` (hook `isLoading` is false during a refetch; the cache entry's `isLoading` is true)

---

## 1. The bug report

> "Since the RTK Query migration, every time I tick a task the whole list disappears for a moment, a 'Loading…' text flashes, and my scroll position jumps to the top."

## 2. Reproduce

The teammate's version of `TasksPage` read the flags **through a selector** instead of the hook, "to be consistent with our other selectors":

```tsx
const tasksResult = useAppSelector(selectTasksResult);   // apiSlice.endpoints.getTasks.select(LIST_QUERY)
if (tasksResult.isLoading) return <p className="text-muted">Loading…</p>;
```

Tick a task. The list is replaced by "Loading…" for as long as the refetch takes. Throttle the network to "Slow 4G" in DevTools to see it clearly.

## 3. Investigate

Log the two sources side by side, just once, with the refetch in progress:

```tsx
const hook = useGetTasksQuery(LIST_QUERY);
const entry = useAppSelector(selectTasksResult);
console.log({ hookLoading: hook.isLoading, hookFetching: hook.isFetching, entryLoading: entry.isLoading, hasData: entry.data !== undefined });
// during the refetch after a toggle:
// { hookLoading: false, hookFetching: true, entryLoading: true, hasData: true }
```

- The **cache entry's** `isLoading` is derived from `status === 'pending'`, and a refetch **is** pending.
- The **hook's** `isLoading` means "pending **and** this hook has no data yet". It stays false during a refetch.

The same word means two different things. The code used the one that's true on every refetch.

## 4. Fix

Choose one of these, in order of preference:

1. Use the hook for UI state. It's the same entry, with no extra request:

   ```tsx
   const { isLoading, isFetching, error } = useGetTasksQuery(LIST_QUERY);
   if (isLoading) return <p className="text-muted">Loading…</p>;
   ```

2. If you must use a selector, test the **data**, not the flag: `if (tasksResult.data === undefined && !tasksResult.isError)`.

And show refetches **without** removing content: dim the list, or add a "refreshing…" hint next to the heading, driven by `isFetching`.

## 5. Why the scroll jumped

Returning the spinner **unmounted** the list. When the list came back, every `TaskListItem` mounted fresh: no `memo` benefit, and the scroll position was lost. The spinner-flag bug costs you performance too, not only looks.

## ✅ Takeaways

- **Spinner = `isLoading` from the hook** (no data yet). **Hint = `isFetching`** (data shown, a newer version is on its way).
- The same flag names on `endpoint.select(arg)` results mean **status-based** values. Don't build a spinner from them.
- Never replace loaded content with a spinner during a refetch.
