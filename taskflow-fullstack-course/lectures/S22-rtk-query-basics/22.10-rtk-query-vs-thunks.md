# Lecture 22.10 · RTK Query or `createAsyncThunk`? A Decision Table

> **Section:** S22 · **Type:** 💡 Deep Dive · **Track:** ＋ Extended · **Time:** ~15 minutes
> 🔗 Official companion reading: RTK Query docs, "Comparison with Other Tools" and "Usage Without React Hooks"

*Extended track: outline. The decision table is the lecture; the notes under it are talking points.*

---

| Situation | Use | Why |
|---|---|---|
| Show server data in components | **RTK Query** query | cache, dedupe, status, lifetime for free |
| Create/update/delete something shown by a query | **RTK Query** mutation + tags | the list refreshes itself |
| Several requests that form **one** write (clear completed) | a mutation with **`queryFn`** | one invalidation (22.07) |
| A write that depends on current state (toggle) | a **thunk** that dispatches `endpoint.initiate` | reads `getState()`, keeps the cache as the only data (22.09) |
| A multi-step workflow (upload → poll job → download) with progress in the UI | a **thunk** or a listener + a small slice, then `invalidateTags` at the end | nothing to cache; lots of client state |
| React to "something happened" (toasts, analytics, persistence) | a **listener** on endpoint matchers | decoupled from the pages (22.09) |
| Search-as-you-type hits you don't want to share | a listener + a slice (TaskFlow's quick find), or a **lazy query** | a matter of taste; S23 tries the lazy query |
| Data the client owns (drafts, preferences) | a **slice** | it's not server state (22.01) |

Talking points:

- RTK Query endpoints **are** `createAsyncThunk`s underneath (the `api/executeQuery/*` actions). You aren't choosing between two technologies; you're choosing how much you write by hand.
- Mixing them is normal. A thunk can `await dispatch(endpoint.initiate(arg)).unwrap()`, and it can read `endpoint.select(arg)(getState())`.
- Red flag: a slice that stores a **copy** of query data "for convenience". Derive it with selectors over the cache instead (`taskSelectors.ts`).
- Red flag: a query used for a write ("GET /tasks/5/archive"). The action changes data, so use a mutation. Otherwise dedupe and caching will swallow repeated calls.
