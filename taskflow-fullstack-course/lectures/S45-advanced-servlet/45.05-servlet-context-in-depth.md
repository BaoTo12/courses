# Lecture 45.05 · `ServletContext` in Depth

> **Section:** S45 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~20 minutes

---

One `ServletContext` per web application: the application scope (30.13).

## 📇 API card: `ServletContext`

| Group | Methods | Notes |
|---|---|---|
| attributes | `get/set/removeAttribute`, `getAttributeNames` | shared by all threads: store thread-safe objects (45.02) |
| init params | `getInitParameter(name)`, `getInitParameterNames` | `<context-param>` in `web.xml`: `taskflow.maintenance`, `taskflow.slowRequestMillis` |
| resources | `getResource(path)`, `getResourceAsStream(path)`, `getResourcePaths(dir)` | files **inside** the web app (`/WEB-INF/…` included), whether it's a folder or a WAR |
| `getRealPath(path)` | a filesystem path, **or `null`** | `null` when the WAR isn't unpacked: never rely on it for writing files |
| paths | `getContextPath()` | `/taskflow` |
| dispatch | `getRequestDispatcher(path)`, `getNamedDispatcher(name)` | forward/include (45.11) |
| logging | `log(msg)`, `log(msg, throwable)` | the container's log (TaskFlow uses SLF4J instead) |
| **dynamic registration** (Servlet 3.0) | `addServlet`, `addFilter`, `addListener` (+ the returned `…Registration` for mappings) | only during startup: from a `ServletContainerInitializer` or a declared `ServletContextListener` |
| info | `getServerInfo()`, `getMajorVersion()`, `getEffectiveMajorVersion()` | |
| sessions | `getSessionCookieConfig()`, `setSessionTrackingModes(…)` | the `web.xml` `<session-config>` in code |

## Dynamic registration in TaskFlow

`SessionRegistry` needs an `AuditService` in its constructor. A `@WebListener` is instantiated by the container with **no** arguments, so `AppContextListener` creates and registers it:

```java
SessionRegistry sessions = new SessionRegistry(auditService);
application.addListener(sessions);
application.setAttribute(SESSION_REGISTRY, sessions);
```

This is the Servlet API's form of dependency injection: build objects yourself, then hand them to the container.

## Resources vs files

```java
try (InputStream in = context.getResourceAsStream("/WEB-INF/templates/export-header.txt")) { … }   // ✅ works in a WAR
new File(context.getRealPath("/WEB-INF/…"))                                                        // ⚠️ may be null
```

Uploads and generated files go **outside** the web app (a configured directory): a redeploy replaces the web app's folder.

## ✅ Recap

The context holds application-wide attributes, settings and resources, and at startup lets you register components you constructed yourself.
