# Lecture 45.04 · 🛡 Fix: No Mutable Instance State; Thread-Safe Collections; Immutability

> **Section:** S45 · **Type:** 🛡 Defend · **Track:** ★ Core · **Time:** ~20 minutes

---

## 1. The fix for 45.03

```java
String mine = who;          // a local variable: on THIS thread's stack
pause();
answer = mine;
```

## 2. The rules

| Rule | Example |
|---|---|
| per-request data → **locals** or **request attributes** | the filter, the page number, the user |
| fields only for things set in `init()` and never changed | `private TaskService service;` |
| shared **mutable** state → a thread-safe type | `ConcurrentHashMap`, `LongAdder`, `AtomicInteger`, `CopyOnWriteArrayList` |
| shared state that changes rarely → an **immutable** object behind a `volatile` field, replaced whole | `CategoryCatalog` (38.06), `AccountRegistry` (42.07) |
| compound actions on shared state → one atomic operation | `map.compute(key, …)` not `get` + `put` (41.15) |
| no `SimpleDateFormat` in fields | not thread-safe; `DateTimeFormatter` is (44.13) |

## 3. Why not `synchronized` on `doGet`

```java
protected synchronized void doGet(…)   // ❌
```

It "fixes" 45.03 by letting **one** request into the servlet at a time: every other user waits, including the slow ones (a database call, a big page). Throughput drops to one request per servlet. And it doesn't protect state shared with **other** servlets or listeners. `synchronized` belongs around the smallest possible critical section, on the object being protected, if at all.

`SingleThreadModel` (the old interface for this) is deprecated since Servlet 2.4 for the same reason.

## 4. Review checklist

- [ ] Does any servlet, filter or listener have a non-`final` field written outside `init()`?
- [ ] Is every shared collection a concurrent one, or immutable?
- [ ] Any `static` mutable state?
- [ ] Any `SimpleDateFormat`, `DecimalFormat` or `MessageFormat` stored in a field?

## ✅ Recap

Make per-request data local, shared data immutable or concurrent, and never serialise all requests to hide a race.
