# Lecture 45.03 · 🔓 Lab: A Race Condition: an Instance Field Mixes Up Users' Data

> **Section:** S45 · **Type:** 🔓 Lab · **Track:** ★ Core · **Time:** ~25 minutes
> Verified: `S45AdvancedServletTest.anInstanceFieldMixesUpConcurrentRequests` (20 simultaneous requests: some unsafe answers belong to another request; the safe mode: none)

---

A concurrency bug in your own code, reproduced locally: no attack involved, but in production it **leaks one user's data to another**.

## 1. The broken servlet (📦 provided, loopback only)

```java
package com.taskflow.web.debug;

import java.io.IOException;
import java.net.InetAddress;
import javax.servlet.annotation.WebServlet;
import javax.servlet.http.HttpServlet;
import javax.servlet.http.HttpServletRequest;
import javax.servlet.http.HttpServletResponse;

/**
 * S45 (45.03, 45.04): a DELIBERATELY broken servlet, for the race-condition lab (loopback only).
 *   GET /debug/race?who=alice              → the bug: `who` goes through an INSTANCE field
 *   GET /debug/race?who=alice&mode=safe    → the fix: a local variable
 * There is ONE instance of this class, and every request runs doGet on its own thread at the same time (45.02).
 * The pause stands in for real work (a query, a template) between writing the field and reading it back.
 */
@WebServlet("/debug/race")
public class RaceDemoServlet extends HttpServlet {

  private String currentUser;   // ❌ shared by EVERY request thread

  @Override
  protected void doGet(HttpServletRequest request, HttpServletResponse response) throws IOException {
    if (!InetAddress.getByName(request.getRemoteAddr()).isLoopbackAddress()) {
      response.sendError(HttpServletResponse.SC_NOT_FOUND);
      return;
    }
    String who = request.getParameter("who");
    String answer;
    if ("safe".equals(request.getParameter("mode"))) {
      String mine = who;                  // ✅ a local variable: on THIS thread's stack
      pause();
      answer = mine;
    } else {
      currentUser = who;                  // another thread may overwrite it during the pause…
      pause();
      answer = currentUser;               // …and this request answers with someone else's value
    }
    response.setContentType("text/plain;charset=UTF-8");
    response.getWriter().write("you are " + answer);
  }

  private static void pause() {
    try {
      Thread.sleep(50);
    } catch (InterruptedException e) {
      Thread.currentThread().interrupt();
    }
  }
}
```

## 2. Reproduce it

One request at a time, it's perfect: `/taskflow/debug/race?who=alice` → `you are alice`.

Now 20 at once. The test does it with `HttpClient.sendAsync`; from a shell:

```bash
for i in $(seq 1 20); do curl -s "http://localhost:8080/taskflow/debug/race?who=user$i" & done; wait
```

Typical output: `you are user17` printed for several different requests. Each thread wrote the field, slept 50 ms, and read back whatever the **last** thread had written.

## 3. Why it's dangerous

- It passes every single-user test, and appears only under load.
- In a real servlet the field is a `Task`, a `User`, a `StringBuilder` for the page: one user sees another's data.
- Timing-dependent bugs are hard to reproduce from bug reports.

Now run `?mode=safe`: 20 requests, 20 correct answers. The fix, and its rules: 45.04.
