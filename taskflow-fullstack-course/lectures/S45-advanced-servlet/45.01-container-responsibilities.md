# Lecture 45.01 · The Container's Responsibilities, Revisited

> **Section:** S45 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~15 minutes

---

Part 2 has used every one of these. Here they are in one picture, with where TaskFlow met each.

| Responsibility | What Tomcat does | Where you saw it |
|---|---|---|
| **networking** | a Connector accepts TCP connections, reads HTTP/1.1, keeps connections alive | 29.02, the port in `server.xml` |
| **parsing** | request line, headers, cookies, query string, form bodies (in the right encoding) | `getParameter`, 40.05/40.19 |
| **threading** | a pool of worker threads (`maxThreads`, default 200); one thread per request while it runs | 38.07, 45.02 |
| **lifecycle** | loads the web app, runs listeners, `init`s filters and servlets, `destroy`s them at undeploy | 36.04, 40.03, 45.07 |
| **mapping** | URL → filter chain + one servlet (exact, prefix `/*`, extension `*.jsp`, default `/`) | 30.05, 40.07 |
| **sessions** | `JSESSIONID`, the session map, timeouts, persistence | 41.02–41.04 |
| **dispatching** | `forward`, `include`, error dispatch, async dispatch | 32.05, 39.03, 43.03, 45.11 |
| **JSP** | Jasper translates and compiles JSPs and tag files into classes | 33.03, 44.10 |
| **security plumbing** | cookie flags, `SameSite`, error reports, optional container auth | 41.12, 42.02, 43.10 |
| **resources** | static files (the default servlet), class loading per web app | 40.18, 45.18 |

Everything else (authentication, authorisation, validation, business rules, data access) is the **application's** job, which is why Part 2 built it.

## ✅ Recap

The container turns bytes into request objects, runs your code on its threads within a managed lifecycle, and turns your response back into bytes.
