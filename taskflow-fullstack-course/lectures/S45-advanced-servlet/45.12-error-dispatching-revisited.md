# Lecture 45.12 · Error Dispatching Revisited, with Filters and Dispatcher Types

> **Section:** S45 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~15 minutes

---

TaskFlow's full chain, and what each filter does on each kind of dispatch:

| Filter | REQUEST | ERROR | Why |
|---|---|---|---|
| encoding | ✅ | — | parameters are already parsed by then |
| logging | ✅ | — | the request is logged once, with the final status |
| errors (`ErrorHandlingFilter`) | ✅ | — | an exception **inside** an error page must not loop back into error handling |
| locale | ✅ | — | its request attribute survives into the error dispatch (same request) |
| security headers | ✅ | ✅ | an error page is a page: CSP, `nosniff`, `X-Frame-Options` (40.08) |
| maintenance, authentication, authorization, CSRF | ✅ | — | an error page must show even to anonymous users and in maintenance |

(Every filter is also `async-supported`: 45.13.)

## Three failure paths, end to end

| Path | What happens |
|---|---|
| `throw new NotFoundException()` in a controller | `ErrorHandlingFilter` → `sendError(404)` → chain returns → ERROR dispatch → `404.jsp` (+ headers filter) |
| an exception in a **REQUEST filter** that runs before `ErrorHandlingFilter` (encoding, logging) | not mapped by our filter → Tomcat logs it → `<error-page><exception-type>java.lang.Throwable` → `500.jsp` |
| an exception **inside `500.jsp`** | no recursion: Tomcat gives up on custom pages and uses `ErrorReportValve` (configured to show nothing, 43.10) |
| an exception on an **async** thread (45.14) | no filter is on that thread's stack: catch and log it there, then `complete()` |

## ✅ Recap

Know which filters run on ERROR dispatches: security headers yes, authentication no. Map exceptions early in the chain, and keep a `Throwable` error page and the valve as the last lines of defence.
