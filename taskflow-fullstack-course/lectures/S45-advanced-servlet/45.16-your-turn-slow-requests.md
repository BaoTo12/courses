## Requirements

1. Every request that takes **500 ms or more** creates an audit event `SLOW_REQUEST` with the user (if logged in), the IP, and the details `GET /taskflow/tasks 734ms`.
2. The threshold is a `<context-param>` `taskflow.slowRequestMillis` (500).
3. It's a `ServletRequestListener`: no filter, no servlet changes.
4. It's correct under concurrent requests: no request's start time can be confused with another's.
5. `SLOW_REQUEST` appears in the audit page's type filter.

**Test:** `/debug/slow?ms=10` creates no event, `/debug/slow?ms=700` creates exactly one whose details start with `GET /taskflow/debug/slow `. (📦 `SlowServlet` sleeps for `ms` milliseconds, loopback only.)

## Hints

- Where can a value live that belongs to exactly one request? Not a field (45.02).
- `ServletRequestEvent` gives the request and the context; cast the request to `HttpServletRequest` for the method and URI.
- `requestDestroyed` may run just **after** the client received the response: a test must allow for a small delay.
- The listener is created by the container: how does it reach `AuditService`?
