# Lecture 45.13 · Async Servlets: `startAsync`, `AsyncContext`; Why, When, Pitfalls

> **Section:** S45 · **Type:** 📖 Theory · **Track:** ＋ Extended · **Time:** ~15 minutes

*Extended track: outline.*

---

- **Why:** a request normally holds a container thread from start to finish. A slow job (a report, a call to a slow external service, long polling) holds it while **waiting**. With 200 threads and 200 slow requests, every other user waits. Async hands the work to **your** threads (or to non-blocking I/O) and frees the container thread; the response stays open until `complete()`.
- **📇 API card**
  | Member | Meaning |
  |---|---|
  | `@WebServlet(asyncSupported = true)` / `<async-supported>true` | allowed on this servlet **and every filter on the path**; otherwise `startAsync()` throws `IllegalStateException` |
  | `request.startAsync()` → `AsyncContext` | from now on, returning from `doGet` doesn't end the response |
  | `async.setTimeout(ms)` | then `AsyncListener.onTimeout` / an error response (Tomcat's default 30 s) |
  | `async.getResponse()`, `getRequest()` | use from the worker thread (read what you need from the request **before**) |
  | `async.complete()` | the response is finished; always call it (in `finally`) |
  | `async.dispatch(path)` | continue with a servlet/JSP on a container thread (`DispatcherType.ASYNC`) |
  | `async.start(Runnable)` | run on the container's pool (defeats the purpose for long jobs) |
  | `async.addListener(AsyncListener)` | `onComplete`, `onTimeout`, `onError`, `onStartAsync` |
- **Pitfalls**
  - filters' "after" code runs when `doGet` **returns**, not when the response completes: TaskFlow's logging filter logs the export as `200` in a few milliseconds;
  - the MDC (request id) doesn't follow the work to another thread; copy it explicitly if you need it;
  - exceptions on the worker thread don't reach `ErrorHandlingFilter` (45.12);
  - the session and `CurrentUser` lookup: do them on the request thread;
  - an unbounded executor turns a slow endpoint into an out-of-memory error: a **fixed** pool (TaskFlow: 2 threads), shut down in `contextDestroyed`.
- **When not:** fast pages (the thread switch costs more than it saves). Servlet 3.1's non-blocking I/O (`ReadListener`, `WriteListener`) is the next step for streaming; most teams reach for a reactive framework instead.
