# Lecture 45.06 · `ServletConfig` vs `ServletContext`: Per Servlet vs Per Application

> **Section:** S45 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~10 minutes

---

| | `ServletConfig` | `ServletContext` |
|---|---|---|
| one per | **servlet** declaration | **web application** |
| get it | `getServletConfig()` (or `init(ServletConfig)`); `HttpServlet` implements `ServletConfig` itself, so `getInitParameter(…)` works directly | `getServletContext()` |
| init params from | `<servlet><init-param>` or `@WebServlet(initParams = @WebInitParam(name, value))` | `<context-param>` |
| also has | `getServletName()`, `getServletContext()` | attributes, resources, dispatchers, registration (45.05) |
| filters' equivalent | `FilterConfig` (`getFilterName`, `getInitParameter`, `getServletContext`) | the same context |

## Examples

```xml
<filter>
  <filter-name>encoding</filter-name>
  <filter-class>com.taskflow.web.filters.CharacterEncodingFilter</filter-class>
  <init-param><param-name>encoding</param-name><param-value>UTF-8</param-value></init-param>  <!-- FilterConfig -->
</filter>
<context-param>
  <param-name>taskflow.slowRequestMillis</param-name><param-value>500</param-value>             <!-- ServletContext -->
</context-param>
```

## Choosing

| Setting | Scope |
|---|---|
| only one servlet or filter cares (its encoding, its page size) | `init-param` |
| several components read it (maintenance mode, the slow-request threshold, the bundle) | `context-param` |
| differs between environments (database URL, secrets) | neither: environment variables or system properties (36.03's `DataSourceProvider`) |

The `ServletConfig` is only reliable **after** `init(ServletConfig)` ran: calling `getInitParameter` in a servlet's constructor throws (the config isn't set yet).

## ✅ Recap

`ServletConfig` is one component's settings; `ServletContext` is the whole application's.
