# Lecture 45.07 · Listeners: Which One Fires When

> Verified: `S45AdvancedServletTest.theSessionRegistryKnowsWhoIsLoggedIn` (attribute listener), `.slowRequestsAreAudited` (request listener)

## 📇 API card: the listener interfaces

| Interface | Methods | Fires when | TaskFlow |
|---|---|---|---|
| `ServletContextListener` | `contextInitialized`, `contextDestroyed` | the web app starts / stops (before any filter or servlet `init`; after every `destroy`) | `AppContextListener` (36.04, 45.08) |
| `ServletContextAttributeListener` | `attributeAdded/Removed/Replaced` | a context attribute changes | |
| `ServletRequestListener` | `requestInitialized`, `requestDestroyed` | a request enters / leaves the web app's scope | `StatsListener` (38.07), `SlowRequestListener` (45.16) |
| `ServletRequestAttributeListener` | `attributeAdded/Removed/Replaced` | a request attribute changes | |
| `HttpSessionListener` | `sessionCreated`, `sessionDestroyed` | a session is created / invalidated or times out | `StatsListener`, `SessionRegistry` |
| `HttpSessionAttributeListener` | `attributeAdded/Removed/Replaced` | **any** session's attribute changes | `SessionRegistry` (login/logout) |
| `HttpSessionIdListener` (3.1) | `sessionIdChanged(event, oldId)` | `changeSessionId()` | `SessionRegistry` |
| `HttpSessionActivationListener` | `sessionWillPassivate`, `sessionDidActivate` | the session is serialised / restored (restart, cluster) | *(on the attribute's class)* |
| `HttpSessionBindingListener` | `valueBound`, `valueUnbound` | **this object** is put into / removed from a session | *(on the attribute's class)* |
| `AsyncListener` | `onComplete`, `onTimeout`, `onError`, `onStartAsync` | an async request's life (45.13) | |

## Registering

| Way | When |
|---|---|
| `@WebListener` on the class | the container creates it (no-arg constructor) |
| `<listener><listener-class>` in `web.xml` | same, with a declared order |
| `servletContext.addListener(instance)` | you construct it (dependencies), at startup (45.05) |
| nothing: `HttpSessionBindingListener` / `ActivationListener` | the attribute object itself is notified |

## Ordering and details that matter

- Listeners of the same type run in **declaration** order (`web.xml`, then annotations in unspecified order); `contextDestroyed` and `sessionDestroyed`… run in **reverse** order.
- In Tomcat, `sessionDestroyed` runs **before** the session's attributes are removed (so you can still read them); then each removal fires `attributeRemoved` / `valueUnbound`.
- Session timeouts are processed by a **background thread**: session listeners must not assume there's a current request (no IP, no user interface).
- `attributeReplaced`'s `event.getValue()` is the **old** value.
- Listener methods run on request threads concurrently: 45.02's rules apply.

## ✅ Recap

Context, request and session lifecycles, plus attribute changes, each have a listener. Choose the one that matches the event, and remember which thread calls it.
