# Lecture 45.18 · 🐞 Debug: `DataSource` Leaks on Redeploy

> **Section:** S45 · **Type:** 🐞 Debug · **Track:** ★ Core · **Time:** ~15 minutes

---

## 1. Symptom

After a few redeploys (a new WAR dropped into `webapps/`), MySQL reports "Too many connections", Tomcat's memory keeps growing, and eventually `OutOfMemoryError: Metaspace`. Tomcat's log says, at each undeploy:

```text
WARNING [...] The web application [taskflow] appears to have started a thread named [HikariPool-1 housekeeper] but has failed to stop it. This is very likely to create a memory leak.
WARNING [...] The web application [taskflow] registered the JDBC driver [com.mysql.cj.jdbc.Driver] but failed to unregister it when the web application was stopped.
```

## 2. Cause

Each deploy creates a **new** class loader and a new pool. Nothing closed the old pool:
- its connections stay open in MySQL (the "too many connections");
- its housekeeper thread keeps running, and a running thread keeps its class loader, and with it **every class** of the old web app, in memory (the Metaspace growth).

The same happens with any thread pool (TaskFlow's export executor), timers, a `ThreadLocal` on a container thread, or a static reference held by a library outside the web app.

## 3. Fix: close everything in `contextDestroyed`

```java
@Override
public void contextDestroyed(ServletContextEvent event) {
  if (exportExecutor != null) exportExecutor.shutdownNow();
  if (entityManagerFactory != null) entityManagerFactory.close();
  if (dataSource != null) dataSource.close();
  AbandonedConnectionCleanupThread.checkedShutdown();   // the MySQL driver's own thread
}
```

## 4. How to check

| Check | How |
|---|---|
| Tomcat's own check | Manager app → "Find leaks" after an undeploy |
| the warnings above | the Tomcat log at undeploy |
| MySQL | `SHOW PROCESSLIST;` before and after a redeploy: the count must not grow |
| memory | a heap dump: more than one `WebappClassLoader` for `/taskflow` after a redeploy |

## ✅ Takeaway

Whatever the application starts, it must stop. A `ServletContextListener` has both halves for that reason.
