# Lecture 38.02 · Request Scope: Data for One Request (the Default Choice)

> **Section:** S38 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~10 minutes

---

## 📇 API card: request attributes

| Call | Meaning |
|---|---|
| `request.setAttribute(name, value)` | store for this request (`null` value = remove) |
| `request.getAttribute(name)` | `Object`, or `null` |
| `request.removeAttribute(name)` | |
| `request.getAttributeNames()` | an `Enumeration<String>` (includes container-set ones like `javax.servlet.forward.request_uri`) |
| in EL | `${name}` or `${requestScope.name}` |

**Lives through:** filters → servlet → `forward` → the JSP → its `<jsp:include>`s. **Dies at:** the end of the response, so a **redirect** starts without it (31.06).

## 1. Why it's the default

Almost everything a page shows is computed **for this request**: the tasks matching this filter, today's overdue count, this form's errors. Loading it now means it's current. Throwing it away after means no memory cost, no staleness and no thread-safety concerns.

TaskFlow's controllers put everything in request scope: `tasks`, `stats`, `details`, `form`, `errors`, `pageTitle`, `csrfToken`, `flash`, `recentTasks` (the *list* is request-scoped even though the *ids* live in the session).

## 2. When it's not enough

| Need | Scope |
|---|---|
| survive a redirect (flash) | session, briefly (37.09) |
| remember something for this user across pages | session (38.03) |
| share something between all users | application (38.04) |

## ✅ Recap

Request scope is free, fresh and thread-safe. Use it unless you have a reason not to.
