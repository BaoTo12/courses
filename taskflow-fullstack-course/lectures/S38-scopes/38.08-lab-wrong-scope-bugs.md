# Lecture 38.08 · 🔓 Lab: Wrong-Scope Bugs

> **Section:** S38 · **Type:** 🔓 Lab · **Track:** ★ Core · **Time:** ~30 minutes
> ⚠️ In a lab branch. Reproduce each one with two browsers (a normal and a private window = two sessions).

---

## Bug 1: search results in application scope → users see each other's data

```java
getServletContext().setAttribute("results", service.find(filter));   // ❌ "cache the last search"
request.getRequestDispatcher("/WEB-INF/views/tasks/list.jsp").forward(request, response);
```

Browser A searches "salary". Browser B opens the list a second later and briefly sees A's results, and with bad timing a mix. From S41 on, when results depend on the user, that's a **data leak**. **Fix:** request scope. Results belong to one request.

## Bug 2: the task list in the session → stale data and memory

```java
if (session.getAttribute("tasks") == null) session.setAttribute("tasks", service.find(TaskFilter.all()));  // ❌ "load once"
```

- A task edited by anyone (or in another tab) doesn't change in this user's list until they log out.
- 23 tasks × 200 admins stay in memory for 30 minutes after each one leaves.

**Fix:** request scope, and load per request. If the query becomes slow, cache in the **service** with a deliberate invalidation strategy (38.06), not per user.

## Bug 3: form errors in the session → they show up on another page

```java
session.setAttribute("errors", errors);      // ❌ to "survive the redirect"
response.sendRedirect(ctx + "/tasks/new");   // 37.17's mistake, "fixed" the wrong way
```

The errors stay in the session. The user abandons the form, opens another page with an error area, and sees "must not be blank" there. In a second tab, the other form shows errors it never had. **Fix:** forward with request attributes (37.05). If something really must survive one redirect, it's a flash: put, then consumed exactly once (37.09).

## The pattern behind all three

| Symptom | Scope that's too wide |
|---|---|
| another user's data appears | application |
| data is out of date for one user until they log out | session |
| a message or value appears where it doesn't belong | session (not cleaned up) |

## Lesson

A scope that's too wide never fails a single-user test. Test with two browsers, and ask of every attribute: who else can see this, and for how long?
