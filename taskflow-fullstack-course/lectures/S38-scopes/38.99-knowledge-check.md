# Lecture 38.99 · ✅ Knowledge Check: Scopes

> **Section:** S38 · **Type:** ✅ Knowledge Check · **Track:** ★ Core · **Time:** ~15 minutes

---

**1. (Design)** Request or session scope for: a validation error list, the logged-in user, the current page's tasks, a "selected tasks" set built up over several pages, the language preference?

<details><summary>Answer</summary>

Errors → **request** (forward back, 37.05). Logged-in user → **session** (non-secret fields, 38.09). Current page's tasks → **request** (fresh each time). Selected tasks across pages → **session** (a small set of ids, replaced not mutated, 38.03). Language → neither: a **cookie**, so it outlives the session and the React app can read it (S44). The session may hold a copy for the current visit.
</details>

**2. (Concept)** Why does a request attribute disappear after a redirect but a session attribute doesn't?

<details><summary>Answer</summary>

A redirect makes the browser send a **new** request, with a new `HttpServletRequest` object and no attributes (31.06). The session is found again through the `JSESSIONID` cookie the browser sends with the new request, so its attributes are still there (38.03).
</details>

**3. (Debugging)** Two users see each other's search results. Which scope was misused?

<details><summary>Answer</summary>

**Application** scope: something per-request (the results) was stored where every request of every user reads it. Move it to request scope (38.08, bug 1). The same symptom within one browser's two tabs would point at the session.
</details>

**4. (Concept)** `CategoryCatalog` is read by many threads and refreshed by one. Why is it safe without locks on the read path?

<details><summary>Answer</summary>

The list is immutable (`List.copyOf`) and published through a `volatile` field. A refresh builds a new list and swaps the reference in one write. A reader sees either the complete old list or the complete new one, and `volatile` guarantees it sees the latest reference (38.06).
</details>

**5. (Code reading)** `private int views; … views++;` in an application-scoped object: what goes wrong, and what's the fix?

<details><summary>Answer</summary>

Lost updates under concurrency: `++` is read-modify-write, and two threads can both write the same value. `volatile` doesn't help. Use `AtomicInteger`/`LongAdder` (38.12).
</details>
