# Lecture 38.04 · Application Scope: Shared by All Users and Threads

## 📇 API card: `ServletContext` attributes

| Call | Meaning |
|---|---|
| `getServletContext().setAttribute(name, value)` | shared by every request of every user, until undeploy |
| `getAttribute` / `removeAttribute` | |
| in EL | `${applicationScope.name}` |
| typical writer | a `ServletContextListener` at startup (36.04) |

## 1. What it's for

| Good use | TaskFlow |
|---|---|
| long-lived, stateless services | `TaskService`, `CategoryService` (36.04) |
| read-mostly data that's the same for everyone | `CategoryCatalog` (38.06) |
| global counters and metrics | `AppStats` (38.07) |
| configuration | context params (30.13) |

## 2. The rule: many threads at once

Every request thread can touch an application attribute at the same moment, so the objects must be:

| Kind | Technique | Example |
|---|---|---|
| **immutable** | never changes after construction | `List.copyOf(…)` in `CategoryCatalog` |
| **replaced atomically** | a `volatile` field pointing to an immutable value, swapped on change | `CategoryCatalog.refresh()` |
| **concurrent types** | `AtomicInteger`, `LongAdder`, `ConcurrentHashMap` | `AppStats` |
| **stateless** | no mutable fields at all | `TaskService` |

What goes wrong otherwise: `count++` on an `int` loses updates (38.12), and a `HashMap` modified by two threads can corrupt itself.

## 3. What must never go there

Anything **per user**. Everything in application scope is visible to every request: a "current search", "last error" or "current user" stored there is shown to the next person who loads the page (38.08).

## ✅ Recap

Application scope = one copy, every user, every thread. Only shared, thread-safe data; never anything that belongs to one user.
