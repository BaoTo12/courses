## 📇 API card: `HttpSession`

| Call | Meaning |
|---|---|
| `request.getSession()` | the session, **creating** it (and a `JSESSIONID` cookie) if there's none |
| `request.getSession(false)` | the session, or `null`: never creates one |
| `session.setAttribute(name, value)` / `getAttribute` / `removeAttribute` | per-user state |
| `session.invalidate()` | end it now (logout, S41) |
| `session.getId()` · `getCreationTime()` · `getLastAccessedTime()` | |
| `session.setMaxInactiveInterval(seconds)` | override the `web.xml` timeout (30 min) for this session |
| `request.changeSessionId()` | new id, same data (S41: against session fixation) |
| in EL | `${sessionScope.name}` (⚠ throws in `session="false"` pages: 34.25) |

## 1. How it works

The server keeps a `Map<sessionId, HttpSession>`. The browser keeps only the id, in the `JSESSIONID` cookie (`HttpOnly`, `COOKIE` tracking only: 28.04). Each request's cookie picks the session. "Per user" really means **per browser profile**: two browsers are two sessions, and two tabs of one browser share one.

## 2. The costs

| Cost | Why | TaskFlow's answer |
|---|---|---|
| **memory** | every attribute × every active session, until 30 min after the last request | ids, not objects: `RecentTasks` keeps ≤ 5 `Long`s |
| **staleness** | a `Task` stored in the session doesn't change when the database does | store the id, load the data per request |
| **concurrency** | two tabs → two requests on the **same** session at once | replace values instead of mutating them (`RecentTasks.record` builds a new list) |
| **serialisation** | Tomcat saves sessions to disk at shutdown (`SESSIONS.ser`) and restores them; clusters copy them between servers | only `Serializable` values: `ArrayList<Long>`, `String`, enums |
| **clustering** | with several Tomcats, a session lives on one of them | sticky sessions at the load balancer, or session replication, or a shared store (Redis, Spring Session) |

## 3. What belongs there

Per-user state that must survive between requests and **can't** be cheaply recomputed: the logged-in user's id (S41), the CSRF token (37.13), a flash message (37.09), a short history (`RecentTasks`), a multi-step wizard's progress. Not: lists of tasks, search results, anything you can re-query.

## ✅ Recap

Sessions are per browser, across requests. Keep them small, serialisable and made of ids. Remember they cost memory for every user, and that the same session can be used by two requests at once.
