## Part A: decide (write it in `docs/scopes.md`)

For each item: page, request, session, application, or "not a scope at all" (database, cookie). Write one line of justification each.

1. The tasks shown on the list page.
2. The validation errors of the task form.
3. The CSRF token.
4. "Task created." after a redirect.
5. The category list for dropdowns.
6. The number of requests since startup.
7. The loop variable in `<c:forEach>`.
8. The logged-in user (S41).
9. The last 5 tasks **this** user opened.
10. The 5 tasks **everyone** opened most.
11. The user's language preference (shared with the React app).
12. A draft task being typed in a two-step "new task" wizard.

## Part B: implement two of them

**9. Recently viewed (session):**
- Each successful `GET /tasks/view?id=N` records `N` for this session: most recent first, no duplicates, at most 5.
- Keep **ids only**. The list page shows "Recently viewed: *title* · *title*" (links), with titles loaded fresh; deleted tasks simply don't appear.
- The list page must not **create** a session just to read the history.

**10. Most viewed (application):**
- Count every view of every task since startup, from every user.
- Show the top 5 (title + count) on `/debug/stats`.
- It must be correct under concurrent requests.

**Tests:** two views in one session → both listed, newest first; another browser (a new `HttpClient`) sees no history; three views from another browser → the task appears on `/debug/stats`.

## Hints

- Two requests of the same session can run at once: build a **new** list and `setAttribute` it, rather than changing the stored list in place.
- `ConcurrentHashMap.computeIfAbsent(id, k -> new LongAdder()).increment()` is atomic; `map.put(id, map.get(id) + 1)` isn't.
