# Lecture 38.06 · 🛠 Build: Categories Cached in Application Scope, Refreshed on Change

> **Section:** S38 · **Type:** 🛠 Build · **Track:** ★ Core · **Time:** ~35 minutes
> **Project feature:** categories are loaded once at startup; the list, the form and the details page read the cache; any create/rename/delete refreshes it.
> Verified: `S38ScopesTest.theCategoryCacheIsRefreshedWhenACategoryChanges`, and S36–S37's tests (categories still shown and validated)

## 1. The cache

✍️ `src/main/java/com/taskflow/service/CategoryCatalog.java`

```java
package com.taskflow.service;

import com.taskflow.dao.CategoryDao;
import com.taskflow.model.Category;
import java.util.List;
import java.util.Optional;
import java.util.Set;
import java.util.stream.Collectors;

/**
 * S38 (38.06): the categories, cached for the whole application (application scope).
 * Categories are read on almost every page and change rarely: loading them once and refreshing only when they change
 * saves a query per page. Thread safety: the list is an IMMUTABLE snapshot in a volatile field; a refresh builds a new
 * list and replaces the reference in one step, so readers see either the old list or the new one, never a half-built one.
 */
public class CategoryCatalog {

  private final CategoryDao dao;
  private volatile List<Category> categories;

  public CategoryCatalog(CategoryDao dao) {
    this.dao = dao;
    this.categories = List.copyOf(dao.findAll()); // loaded at startup
  }

  public List<Category> all() {
    return categories;
  }

  public Set<Long> ids() {
    return categories.stream().map(Category::getId).collect(Collectors.toUnmodifiableSet());
  }

  public Optional<Category> byId(long id) {
    return categories.stream().filter(c -> c.getId() == id).findFirst();
  }

  /** After any change to the categories table (CategoryService calls it). */
  public void refresh() {
    categories = List.copyOf(dao.findAll());
  }
}
```

The thread-safety technique is **immutable snapshot + volatile reference**:
- readers take `categories` (one volatile read) and use that list. Nobody can change it (`List.copyOf`);
- `refresh()` builds a **new** list, then swaps the reference in one step.

No locks on the read path, which runs on every page.

## 2. Who uses it

- `TaskService` now takes a `CategoryCatalog` instead of a `CategoryDao`: `categories()`, `categoryIds()` and the category in `details()` come from memory.
- `CategoryService` refreshes it after every successful create, rename and delete.
- `AppContextListener` creates **one** catalogue and gives it to both services. It lives in application scope through them.

```java
CategoryDao categoryDao = new CategoryDao(entityManagerFactory);
CategoryCatalog catalog = new CategoryCatalog(categoryDao);            // S38: loaded once, shared by all (38.06)
TaskService taskService = new TaskService(new TaskDao(entityManagerFactory), catalog, …);
application.setAttribute(CATEGORY_SERVICE, new CategoryService(categoryDao, catalog));
```

## 3. The cost of caching: invalidation

A cache is only correct if **every** change goes through the code that refreshes it. Changes that bypass it: someone edits the table directly in MySQL, a second Tomcat instance (each has its own cache), or a future JSON API that uses the DAO directly. Answers, from simple to robust: route every change through `CategoryService`; add a time-based refresh (every few minutes); or use a shared cache/notifications in a cluster. For a few categories that an admin changes rarely, the first is enough, and it's documented in `docs/scopes.md`.
