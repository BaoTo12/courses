# Lecture 01.01 · Installing Node LTS, VS Code, Git and Browser Extensions

> **Section:** S01 · Frontend Development Environment
> **Type:** 🛠 Build · **Track:** ★ Core · **Time:** ~30 minutes
> **Project feature:** a working toolchain (verified by version checks)

## 1. What you're installing and why

| Tool | What it's for in this course |
|---|---|
| **Node.js 24 LTS** (22 LTS also fine) | Runs the *tools*: the Sass compiler, Vite, TypeScript, Vitest, json-server. Your React app will run in the browser, not in Node (Lecture 01.02 explains). |
| **npm** (comes with Node) | Downloads packages and runs project scripts |
| **Git** | Version control, lab branches, checkpoint tags |
| **VS Code** | Editor with good TS/React/SCSS support |
| **Chrome or Edge** | DevTools (Network, Application, Performance) |
| **React Developer Tools** (browser extension) | Inspect components, props, re-renders (S07+) |
| **Redux DevTools** (browser extension) | Inspect actions, state, time travel (S14+) |

> ⚠️ **Node 20 is end-of-life** (since April 2026). Older tutorials may tell you to install it; don't. Use the current **LTS** ("Long-Term Support") release from nodejs.org.

## 2. Install Node.js (Windows)

**Option A: official installer (simplest)**

1. Go to **nodejs.org** and download the **LTS** Windows installer (`.msi`).
2. Run it with default options. You can leave "Automatically install the necessary tools" **unchecked**; we don't need native build tools.

**Option B: a version manager (recommended if you'll switch Node versions at work)**

- On Windows, use **nvm-windows** or **fnm**. Example with fnm in PowerShell:
  ```powershell
  winget install Schniz.fnm
  fnm install --lts
  fnm use lts-latest
  ```
- A version manager lets you run different projects on different Node versions. That's common in large companies where older services lag behind.

**Verify** (open a *new* terminal after installing):

```bash
node --version
```

```bash
npm --version
```

Expected: `v24.x.x` (or `v22.x.x`) and an npm version like `10.x` / `11.x`.

---

## 3. Install Git

1. Download **Git for Windows** from git-scm.com, or run `winget install Git.Git`.
2. During setup, the defaults are fine. Two choices worth knowing:
   - **Default editor:** pick VS Code if offered.
   - **Line endings:** "Checkout Windows-style, commit Unix-style" is the default and fine. We'll also add an `.editorconfig` and `.gitattributes` so everything stays consistent.

Configure your identity once:

```bash
git config --global user.name "Your Name"
```

```bash
git config --global user.email "you@example.com"
```

```bash
git config --global init.defaultBranch main
```

Verify:

```bash
git --version
```

## 4. Install VS Code + extensions

Install VS Code from code.visualstudio.com (or `winget install Microsoft.VisualStudioCode`).

Extensions (open the Extensions panel with **Ctrl+Shift+X**):

| Extension | Why |
|---|---|
| **ESLint** | Shows lint errors inline (configured in S07) |
| **Prettier – Code formatter** | Consistent formatting |
| **vscode-styled-components** | Syntax highlighting + IntelliSense inside `` styled.div`…` `` (S09) |
| **SCSS IntelliSense** | Autocomplete for variables/mixins (S02) |
| **i18n Ally** (optional) | Inline translation previews (S25) |
| **GitLens** (optional) | Blame and history inline |

Recommended settings: **File → Preferences → Settings**, search and set:
- `Editor: Format On Save` → ✅
- `Editor: Default Formatter` → Prettier

Use **Chrome** or **Edge** (both Chromium-based, same DevTools).

Install from the Chrome Web Store / Edge Add-ons:

- **Redux DevTools**

You won't use them until S07 and S14, but install them now so everything is ready.

## 6. Where to put your project

Create a working folder **outside** this course folder, for example:

```text
C:\dev\taskflow
```

Why outside?
- The course folder holds lectures and solutions; your project is *your* code, with its own git history.
- Avoid paths with spaces or OneDrive-synced folders (like `Desktop` or `Documents` if they're synced). File watchers used by Vite and Sass sometimes misbehave in synced folders, and `node_modules` contains tens of thousands of files you don't want syncing.

## 7. Verify everything

Run each command; all should print a version:

```bash
node --version
```

```bash
npm --version
```

```bash
git --version
```

```bash
code --version
```

If `code` isn't found, open VS Code → **Ctrl+Shift+P** → "Shell Command: Install 'code' command in PATH" (on Windows it's usually added automatically; restart the terminal).

## 8. Common problems

| Symptom | Cause | Fix |
|---|---|---|
| `node` not recognised right after installing | The terminal was opened before installation (old PATH) | Close and reopen the terminal (or VS Code) |
| `npm` scripts fail with "running scripts is disabled on this system" in PowerShell | PowerShell execution policy blocks `npm.ps1` | Use Git Bash or cmd, or run `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` (a user-level setting; your choice) |
| Very slow `npm install` in a Desktop/Documents folder | OneDrive sync or antivirus scanning `node_modules` | Use `C:\dev\…` |

---

## 9. Summary

- Node LTS (24, or 22) runs your **tools**; npm installs packages and runs scripts.
- Git + VS Code + React/Redux DevTools extensions complete the toolchain.
- Keep the project in a short, non-synced path like `C:\dev\taskflow`.
