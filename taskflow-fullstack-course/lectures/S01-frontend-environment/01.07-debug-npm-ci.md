# Lecture 01.07 · 🐞 Debug: "npm install works on my machine but not in CI"

> **Section:** S01 · **Type:** 🐞 Debug · **Track:** ＋ Extended · **Time:** ~15 minutes

---

## Symptom

A teammate opens a pull request that adds a date-formatting helper. It works on their machine. The CI pipeline fails:

```text
$ npm ci
npm ERR! `npm ci` can only install packages when your package.json and
npm ERR! package-lock.json are in sync. Please update your lock file with
npm ERR! `npm install` before continuing.
npm ERR! Missing: date-fns@^4.1.0 from lock file
```

Meanwhile a *different* developer reports that on their fresh clone, the app builds but a date looks wrong, while it looks right on the teammate's machine.

## Investigation checklist (work through it before reading on)

1. What does `npm ci` require that `npm install` doesn't?
2. Which files did the pull request change? Look at the list of files in the diff. Is `package-lock.json` in it?
3. How could two machines with the same `package.json` have different versions of a package?
4. What single command, run by the teammate, fixes both problems? What should they commit?

Write your answers in your notes, then continue.

---

## Explanation

**Cause.** The teammate added `"date-fns": "^4.1.0"` to `package.json` **by hand** (or installed it, then committed only `package.json`), so `package-lock.json` in the PR doesn't mention `date-fns`.

- `npm ci` refuses to run when the two files disagree. That's the CI failure, and it's a *feature*: CI is protecting you from unreviewed version resolution.
- The second developer's fresh `npm install` resolved `^4.1.0` to whatever was newest *that day* (say `4.3.0`), while the teammate had `4.1.0` in their `node_modules`. Different versions, different behaviour.

**Fix.**

```bash
npm install
```

```bash
git add package.json package-lock.json
```

```bash
git commit -m "chore: add date-fns to lockfile"
```

`npm install` resolves the new dependency and **updates the lockfile**. Committing both files makes every machine and CI install the same exact version.

**Prevention.**
- Always add packages with `npm install <pkg>` (never by hand-editing `package.json` alone).
- In code review, if `package.json` changes, the lockfile must change too, and vice versa.
- CI uses `npm ci` (never `npm install`) so drift is caught immediately.

## What this debug lecture trained

Not "npm trivia". It trained this habit: **when two environments behave differently, find what's different between them**, whether that's versions, config, data or environment variables. You'll use the same approach when TaskFlow Admin behaves differently on Tomcat vs in the IDE (S28), or when the mock API and the real API disagree (S48).
