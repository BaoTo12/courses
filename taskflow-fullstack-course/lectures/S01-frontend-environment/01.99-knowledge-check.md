# ✅ S01 Knowledge Check: Frontend Development Environment

## A. Concept

1. Why does a React app need Node during development but not in the browser? [01.02]
2. What's the difference between a git **branch** and a git **tag**? Why do we use tags for checkpoints? [01.05]

## B. Code reading

3. Given `"axios": "^1.7.2"`, which versions can `npm install` pick? Which does `npm ci` pick? [01.04]
4. Given `"json-server": "^0.17.4"`, can `npm install` pick `1.0.0-beta.3`? Why or why not? [01.04]

## C. Debugging

5. A colleague's build uses a different library version than yours. Which file do you check first, and why? [01.04, 01.07]
6. You run `document.cookie` in the Console and don't see `JSESSIONID`, but the Application panel shows it. Bug? [01.06]

## D. Design

7. Why are `node_modules/` and `.env` in `.gitignore`, but `package-lock.json` isn't? [01.03, 01.04]

## E. Implementation

8. Make sure your repo has the skeleton, configs and S00 docs committed, and that `git log --oneline --decorate` shows `s00-end` and `s01-end`.

---

<details>
<summary><b>Answers</b></summary>

1. Node runs the **tools** (Vite dev server, TypeScript, Sass, tests). The app itself is compiled into static JS/CSS files that the **browser** executes; production needs no Node for the frontend.
2. A branch **moves** as you commit; a tag is **fixed** to one commit. Checkpoints must always point to the same known-good state, so tags fit.
3. `npm install` without a lockfile: the highest `1.x.x ≥ 1.7.2`. With a lockfile: the locked version. `npm ci`: **exactly** the lockfile's version (and it fails if the lockfile doesn't match `package.json`).
4. **No.** For `0.x` versions, `^0.17.4` allows only `>=0.17.4 <0.18.0`. Pre-releases of other versions are also excluded by default.
5. **`package-lock.json`** (and whether it's committed/up to date). It records the exact versions installed; differences there explain different behaviour.
6. **Not a bug.** `JSESSIONID` is (and must be) **HttpOnly**; JavaScript can't read HttpOnly cookies, and the browser still sends it with requests.
7. `node_modules` is **generated** (reproducible from the lockfile; huge; platform-specific). `.env` may contain **secrets**. The lockfile is **source of truth** for exact versions and integrity hashes, needed for reproducible and safer builds.
8. Self-check. Output similar to `abc1234 (HEAD -> main, tag: s01-end, tag: s00-end) chore: …`.

</details>
