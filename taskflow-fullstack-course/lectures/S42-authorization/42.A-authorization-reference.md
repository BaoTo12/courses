# 42.A · 📇 Authorization: Reference (S42)

> One page to look things up.

---

## 1. Status codes

| Situation | TaskFlow's answer |
|---|---|
| not logged in (HTML) | 303 → `/login?returnUrl=…` |
| not logged in (JSON API, S46) | 401 |
| logged in, wrong role for `/admin/*` | 403 + `errors/403.jsp` |
| logged in, someone else's task | 404 (existence not confirmed) |
| all denials | audit `ACCESS_DENIED` (username, IP, what) |

## 2. The pieces

| Class | Job |
|---|---|
| `AuthorizationFilter` (`/*`, after authentication) | `/admin` + `/admin/*` need ADMIN → 403; catches `AccessDeniedException` → 404; audits |
| `AccessDeniedException` | thrown by services; message = audit details |
| `TaskService` | every use case takes `AuthUser caller`; the policy = `visible(id, caller)` + `ownerScope(caller)`; `taskForDiagnostics` for `/debug/stats` only |
| `UserAdminService` | `accounts`, `setEnabled`, `changeRole`; `requireAdmin`; no self-changes (`OWN_ACCOUNT`); roles allow-listed; audit + registry refresh |
| `AccountRegistry` | volatile snapshot `id → (enabled, role)`; `refresh()` after changes |
| `AuthenticationFilter` (S42 part) | disabled → invalidate + `SESSION_REVOKED` + login; role changed → `withRole` + `changeSessionId` |
| `AuditService` | `record(type, username, ip, details)` for the web layer |
| 📦 `UserDao` | `findAccounts`, `setEnabled`, `setRole` |
| 📦 `TaskFilter.ownerId`, `TaskDao.countByStatus(ownerId)`, `latestId(ownerId)` | owner-scoped queries |

## 3. Routes added

| Method | Path | Who |
|---|---|---|
| GET | `/admin/users` | ADMIN |
| POST | `/admin/users/enable`, `/admin/users/disable` (`id`) | ADMIN, not on themselves |
| POST | `/admin/users/role` (`id`, `role` ∈ USER, ADMIN) | ADMIN, not on themselves |

## 4. The filter chain now

encoding → logging → security headers → maintenance → authentication → **authorization** → CSRF.

## 5. Audit event types

`LOGIN_OK`, `LOGIN_FAIL`, `LOGIN_THROTTLED`, `LOGOUT` (S41) · `ACCESS_DENIED`, `USER_ENABLED`, `USER_DISABLED`, `ROLE_CHANGED`, `SESSION_REVOKED` (S42).

## 6. Checklist for a new feature

- [ ] Which role may use it? A URL under `/admin/` or a check in the service?
- [ ] Does every use case take the caller, and check it against the **stored** row?
- [ ] Are lists and counts restricted in the query?
- [ ] Which fields can the request change? (42.08)
- [ ] Is the POST tested, not only the page? (42.11)
