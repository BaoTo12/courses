# Lecture 42.08 · 🛡 Privilege Escalation via Form Fields: Mass Assignment Again

> **Section:** S42 · **Type:** 🛡 Defend · **Track:** ★ Core · **Time:** ~15 minutes
> Verified: `S42AuthorizationTest.anEditCannotChangeTheOwner` (`ownerId=2` in the edit form is ignored), `.adminsCannotChangeTheirOwnAccountAndRolesAreAllowListed` (`role=SUPERADMIN` → 400)

---

## 1. The pattern (37.11, now with privileges)

Code that copies **every** request parameter onto an object ("bind all fields") lets the client set fields the form never showed:

| Hidden target | Extra field sent | Effect |
|---|---|---|
| a profile update that binds into `User` | `role=ADMIN` | the user makes themselves an admin |
| a task edit that binds into `Task` | `ownerId=2` | the task moves to Bob (or is taken from him) |
| an account update | `enabled=true` | a disabled account re-enables itself |

Frameworks that bind automatically (Spring's data binding, JSON mappers into entities) make this one line away. Several well-known breaches came from exactly this.

## 2. TaskFlow's defences

| Defence | Where |
|---|---|
| **explicit fields**: the form bean has only what the form shows; `applyTo` copies those five fields | `TaskForm` (37.03) |
| **ownership from the server**: create sets `ownerId` from the session; update keeps the stored owner | `TaskCreateServlet` (41.07), `TaskService.update` (42.05) |
| **privileged fields on privileged pages only**: the role is changed on `/admin/users/role`, behind the filter and `requireAdmin` | 42.07 |
| **allow-lists for values**: a role outside `{USER, ADMIN}` → 400, before the service; the service refuses it again | `AdminUserChangeServlet`, `UserAdminService.ROLES` |
| **no self-service on the account's own privileges** | `Change.OWN_ACCOUNT` |

```java
task.setOwnerId(stored.get().getOwnerId());   // an edit never changes the owner (42.08)
```

## 3. The review question

For every write: *which fields can this request change, and is that list written down in the code?* If the answer is "whatever the client sends", it's a mass-assignment bug.

## ✅ Recap

Bind only the fields the form is meant to change; take identity and privilege fields from the server; allow-list the values of privileged ones.
