# Lecture 42.01 · Authentication vs Authorization; 401 vs 403

> **Section:** S42 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~15 minutes

---

| | Authentication (S41) | Authorization (S42) |
|---|---|---|
| question | **who** are you? | **may** you do this? |
| answered | once, at login | on **every** request, for every resource |
| input | username + password | the logged-in user + what they're asking for |
| TaskFlow | `AuthService`, `AuthenticationFilter` | `AuthorizationFilter` (by URL), `TaskService` (by data) |

## The status codes

| Code | Name | Means | TaskFlow uses it |
|---|---|---|---|
| **401** | Unauthorized (a misnomer: *unauthenticated*) | "I don't know who you are": log in and try again. Must carry `WWW-Authenticate` in HTTP auth schemes | the JSON API (S46): an HTML app redirects to the login page instead (303, 41.09) |
| **403** | Forbidden | "I know who you are, and the answer is no": logging in again won't help | a USER on `/admin/*` (42.03) |
| **404** | Not Found | "there's nothing here" | someone else's task: also a "no", but without confirming it exists (42.05) |

```text
anonymous  GET /admin/users  → 303 /login?returnUrl=…   (authentication missing)
alice      GET /admin/users  → 403 Access denied        (authenticated, not allowed)
alice      GET /tasks/view?id=23 (bob's) → 404          (not allowed, and not told it exists)
admin      GET /admin/users  → 200
```

## Two kinds of rules

| Kind | Example | Needs | Where |
|---|---|---|---|
| **function-level** (by URL / role) | "only admins manage users" | the user's role and the path | a filter (42.03) |
| **object-level** (by data) | "only the owner edits a task" | the user **and the row** | the service (42.05) |

OWASP ranks broken access control first in its Top 10: most failures aren't clever, just a missing check on one path, one method or one id.

## ✅ Recap

Authentication identifies; authorization decides, every time. 401 means "log in", 403 means "no", and 404 can mean "no" without revealing that anything is there.
