# Lecture 42.11 · 🐞 Debug: The Admin Page Is Protected, but `POST /admin/users/disable` Isn't

> **Section:** S42 · **Type:** 🐞 Debug · **Track:** ★ Core · **Time:** ~15 minutes
> Verified: `S42AuthorizationTest.nonAdminsAreDeniedEveryAdminPathAndMethod` (the POST is a 403 too)

---

## 1. Symptom

A USER opening `/admin/users` gets the 403 page. A security review finds that the same user can still disable accounts by posting the form directly.

## 2. Checklist

| # | Cause | Example |
|---|---|---|
| 1 | an **exact** URL pattern where a prefix was meant | `<url-pattern>/admin/users</url-pattern>` protects only that one path, not `/admin/users/disable` |
| 2 | a prefix check without the slash, or with it on the wrong side | `startsWith("/admin/users/")` misses `/admin/users`; `startsWith("/admin")` also catches `/administrator-help` |
| 3 | the check only in `doGet` | the page's servlet checks the role; the action servlet doesn't |
| 4 | the filter's `<dispatcher>` excludes the case | a forward to an admin servlet from a public one (40.08) |
| 5 | method-specific rules | `<http-method>GET</http-method>` in a container `<security-constraint>` restricts **only** GET: every other method is open ("HTTP verb tampering"). Use `<http-method-omission>` or no method at all |
| 6 | path normalisation differences | a check on `getRequestURI()` vs the container's mapping: `/taskflow/admin/../admin/users`, `;jsessionid=`, `%2F`. Check `getServletPath()`, which is what the container mapped (40.18) |

## 3. How TaskFlow avoids it

- One filter on `/*`, checking `path.equals("/admin") || path.startsWith("/admin/")` on `getServletPath()`, for **every** method.
- `UserAdminService.requireAdmin` checks again, whichever URL reached it (42.06).
- The test sends the **POST**, not just the GET.

## ✅ Takeaway

Test access rules with the requests an attacker would send: every method, every sub-path, not just the pages the UI links to.
