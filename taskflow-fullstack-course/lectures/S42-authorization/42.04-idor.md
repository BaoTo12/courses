# Lecture 42.04 · 🔓 IDOR: Insecure Direct Object References (Conceptual)

> **Section:** S42 · **Type:** 🔓 Attack Lab (conceptual) · **Track:** ★ Core · **Time:** ~15 minutes
> Verified: `S42AuthorizationTest.someoneElsesTaskLooksLikeItDoesNotExist` (after the fix: every operation on task 23 as alice → 404)

---

## 1. The flaw

Until this section, TaskFlow checked **that** you were logged in, never **whose** task you were touching. Every task URL carries its id:

```text
/tasks/view?id=5          POST /tasks/edit    id=5
/tasks/edit?id=5          POST /tasks/toggle  id=5
                          POST /tasks/delete  id=5
                          POST /tasks/comment id=5
```

The id is a **direct reference** to a database row, and the only thing between it and the row was "is there a user?". Any logged-in user could therefore read, change or delete any other user's task: seed task 23, "Bob: private salary review", was one number away from Alice's own tasks.

## 2. Why it's so common

- ids are **visible** (URLs, hidden fields, JSON) and often **sequential**;
- the UI only ever shows your own tasks, so nobody notices during normal use;
- every controller needs the check, and one forgotten path is enough;
- POST endpoints are easy to overlook: "the edit **page** checks ownership" means nothing if `POST /tasks/edit` doesn't.

## 3. What doesn't fix it

| Idea | Why it fails |
|---|---|
| random ids (UUIDs) | makes guessing hard, but ids still leak (shared links, logs, `Referer`). It's an extra layer, not the check |
| hiding the Edit button | the request can be sent without the button (42.06) |
| checking in the view (`<c:if test="${task.ownerId == currentUser.id}">`) | the view runs after the data was loaded, and it doesn't run at all for POSTs |
| a filter on `/tasks/*` | the filter doesn't know who owns task 23 without loading it: that's the service's knowledge (42.05) |

## Lesson

An id from the request is a **claim**: "I want row 23". The server must check, for every operation, that this user may touch row 23.
