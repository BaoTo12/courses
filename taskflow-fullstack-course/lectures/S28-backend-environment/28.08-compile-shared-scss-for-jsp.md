# Lecture 28.08 · 🛠 Compile the Shared SCSS for JSP (`npm run styles:jsp`)

> **Section:** S28 · **Type:** 🛠 Build · **Track:** ★ Core · **Time:** ~20 minutes
> Verified: `npm run styles:jsp` writes `backend/src/main/webapp/static/css/app.css` (7.5 KB compressed); the WAR contains `static/css/app.css`.

---

## 1. One design system, two apps

The SCSS you wrote in Part 1a (`taskflow/styles/`: tokens, `.btn`, `.badge`, `.card`, `.form-field`, `.page`) styles TaskFlow Web through Vite. TaskFlow Admin's JSPs use **the same classes**, so both apps look like one product. JSPs can't import SCSS: the browser needs plain CSS, compiled ahead of time.

## 2. The script

In `taskflow/package.json` (the root one, which already has `sass` since S01):

```json
{
  "scripts": {
    "styles:jsp": "sass styles/main.scss backend/src/main/webapp/static/css/app.css --no-source-map --style=compressed --load-path=styles"
  }
}
```

| Flag | Why |
|---|---|
| `styles/main.scss` → `…/webapp/static/css/app.css` | the output lands **inside the WAR's public root** (28.04), at `/taskflow/static/css/app.css` |
| `--style=compressed` | one line, no comments: smaller downloads |
| `--no-source-map` | no `.map` file next to it (don't ship source maps to production by accident) |
| `--load-path=styles` | lets `@use 'abstracts'` resolve the same way it does under Vite |

Run it after changing any SCSS partial:

```bash
npm run styles:jsp
```

During development, `sass --watch …` recompiles on save. With exploded deployment (28.06), a page reload shows the change.

## 3. Using it from a page

`index.html` (and every JSP from S32) links it **relatively**:

```html
<link rel="stylesheet" href="static/css/app.css" />
```

A relative URL keeps working whatever the context path is (`/taskflow` today, maybe `/` in production). S32 switches to `${pageContext.request.contextPath}/static/css/app.css`, the JSP way to build an absolute path that still respects the context (28.10).

## 4. Commit the CSS or not?

Generated files usually aren't committed. But `app.css` must exist for `mvn package` to include it. Options:
- run `npm run styles:jsp` before `mvn package` (TaskFlow's approach; S49 wires both into one build);
- or the `frontend-maven-plugin`, which runs npm during the Maven build.

`http://localhost:8080/taskflow/` shows the "Deployed" badge and a primary button styled exactly like TaskFlow Web's.
