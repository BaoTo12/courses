# Lecture 28.06 · 🛠 Run and Debug Tomcat from the IDE; Hot Redeploy vs Restart

> **Section:** S28 · **Type:** 🛠 Build · **Track:** ★ Core · **Time:** ~40 minutes

---

## 1. IntelliJ IDEA (Community or Ultimate)

**Ultimate:** Run → Edit Configurations → **+** → *Tomcat Server → Local*.
1. *Application server*: point it at your `apache-tomcat-9.0.x` folder.
2. *Deployment* tab: **+** → *Artifact* → `taskflow-backend:war exploded`. Set *Application context* to **`/taskflow`**.
3. *Server* tab: *On 'Update' action* → **Update classes and resources**, and *On frame deactivation* → **Update resources**.
4. Run ▶ or Debug 🐞. The browser opens `http://localhost:8080/taskflow/`.

**Community** (no Tomcat integration): use the Smart Tomcat plugin, **or** run Tomcat yourself and deploy the WAR:

```bash
mvn -q package && copy target\taskflow.war C:\tools\apache-tomcat-9.0.x\webapps\
# debugging: start Tomcat with the debug agent, then IntelliJ → Run → Attach to Process / Remote JVM Debug on port 8000
set JPDA_ADDRESS=*:8000 && C:\tools\apache-tomcat-9.0.x\bin\catalina.bat jpda run
```

**Eclipse (Enterprise Java and Web Developers):** Servers view → *New server* → Apache → **Tomcat v9.0** → *Add* the project → Start in Debug mode.

**Docker Tomcat:** add `JPDA_ADDRESS: "*:8000"` and the command `catalina.sh jpda run` to the compose service, map port 8000, then attach the IDE's *Remote JVM Debug*.

## 2. Exploded vs WAR deployment

| | WAR (`taskflow.war`) | Exploded (`taskflow/` folder) |
|---|---|---|
| What the IDE copies | one ZIP | the folder tree |
| JSP / CSS change | rebuild + redeploy | **visible at once** (Tomcat re-translates changed JSPs, S33) |
| Used for | Docker, production (S49) | day-to-day development |

## 3. What needs what

| You changed… | Needed | Why |
|---|---|---|
| a **JSP**, CSS, HTML | nothing (exploded) / *Update resources* | Jasper checks the JSP's timestamp on the next request (development mode) |
| a method **body** in a servlet | *Update classes* (HotSwap) in debug mode | the JVM can swap method bodies in place |
| a new method, field or class; an annotation (`@WebServlet`) | **redeploy** the app | HotSwap can't change a class's shape; mappings are read at deploy time |
| `web.xml`, `pom.xml` dependencies | **redeploy** | read once at deployment |
| `server.xml`, `conf/*`, JVM options | **restart** Tomcat | server-level configuration |

**Redeploy** = stop and start **one application** (a new class loader): a few seconds. **Restart** = the whole JVM.

⚠️ After many redeploys, some apps leak memory (old class loaders held by threads or drivers). Tomcat warns: "The web application [taskflow] appears to have started a thread … but has failed to stop it". S36 closes the connection pool on shutdown for this reason.

## 4. Breakpoints in a servlet (from S30)

Set a breakpoint in `doGet`, request the URL, and the IDE stops with `request` and `response` inspectable: headers, parameters, attributes. It's the best way to *see* the container at work.

## ✅ Checkpoint

From the IDE (or Docker), `http://localhost:8080/taskflow/` shows "It works." with TaskFlow's styles. Edit `index.html`, reload the page, and it changes (exploded) or changes after a redeploy (WAR).
