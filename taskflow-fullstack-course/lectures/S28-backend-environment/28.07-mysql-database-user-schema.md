## 2. Database and user

```sql
-- S28 (28.07) · PROVIDED. Run as an ADMIN account (root) ONCE. Docker runs it automatically on first start.
-- Creates the database and the LEAST-PRIVILEGE account the application uses. The app never connects as root.

CREATE DATABASE IF NOT EXISTS taskflow
  CHARACTER SET utf8mb4            -- real UTF-8: Vietnamese, emoji (MySQL's old 'utf8' is 3-byte, no emoji)
  COLLATE utf8mb4_0900_ai_ci;      -- accent- and case-INsensitive comparisons (see the unique title rule, 02-schema)

-- ⚠️ Development password. Production: a generated secret, passed by the environment, never committed.
CREATE USER IF NOT EXISTS 'taskflow_app'@'%' IDENTIFIED BY 'taskflow_dev_pw';
-- Its rights are granted in 04-grants.sql, once the tables exist.
```

- **`utf8mb4`**, not `utf8`. MySQL's historical `utf8` stores at most 3 bytes per character, so emoji in a task title fail to save (or get cut). `utf8mb4` is real UTF-8.
- **`utf8mb4_0900_ai_ci`**: comparisons ignore case (`ci`) and accents (`ai`). `'Report' = 'report'`, and also `'Cafe' = 'Café'`.
- **`'taskflow_app'@'%'`**: the user may connect from any host. Docker needs that, because the app connects from another container. On a real server, restrict it (`'taskflow_app'@'10.0.1.%'`).

## 3. The schema

```sql
-- S28 (28.07) · PROVIDED. The TaskFlow schema (02-project-spec §2). MySQL 8, InnoDB, utf8mb4.
USE taskflow;

CREATE TABLE users (
  id            BIGINT       NOT NULL AUTO_INCREMENT PRIMARY KEY,
  username      VARCHAR(50)  NOT NULL,
  email         VARCHAR(255) NOT NULL,
  password_hash CHAR(60)     NOT NULL,              -- bcrypt: "$2a$12$" + 53 chars; NEVER leaves the server (S46)
  display_name  VARCHAR(100) NOT NULL,
  role          ENUM('USER', 'ADMIN') NOT NULL DEFAULT 'USER',
  locale        CHAR(2)      NOT NULL DEFAULT 'en', -- 'en' | 'vi' (S44)
  enabled       BOOLEAN      NOT NULL DEFAULT TRUE,
  created_at    TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP,
  CONSTRAINT uq_users_username UNIQUE (username),
  CONSTRAINT uq_users_email    UNIQUE (email)
);

CREATE TABLE categories (
  id    BIGINT      NOT NULL AUTO_INCREMENT PRIMARY KEY,
  name  VARCHAR(50) NOT NULL,
  color CHAR(7)     NOT NULL,                       -- '#2563eb'
  CONSTRAINT uq_categories_name UNIQUE (name)
);

CREATE TABLE tasks (
  id          BIGINT        NOT NULL AUTO_INCREMENT PRIMARY KEY,
  title       VARCHAR(120)  NOT NULL,               -- TITLE_MAX, same as the SPA and the mock
  description VARCHAR(2000) NOT NULL DEFAULT '',    -- DESCRIPTION_MAX
  status      ENUM('TODO', 'IN_PROGRESS', 'DONE') NOT NULL DEFAULT 'TODO',
  priority    ENUM('LOW', 'MEDIUM', 'HIGH')       NOT NULL DEFAULT 'MEDIUM',
  due_date    DATE          NULL,
  category_id BIGINT        NULL,
  owner_id    BIGINT        NOT NULL,
  created_at  TIMESTAMP     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at  TIMESTAMP     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  CONSTRAINT fk_tasks_category FOREIGN KEY (category_id) REFERENCES categories (id) ON DELETE SET NULL,
  CONSTRAINT fk_tasks_owner    FOREIGN KEY (owner_id)    REFERENCES users (id)      ON DELETE CASCADE,
  -- "A title is unique per owner, case-insensitively" (02-project-spec §5): the _ci collation makes 'Report'
  -- and 'report' EQUAL for this index. The app trims before saving (the collation doesn't ignore spaces).
  CONSTRAINT uq_tasks_owner_title UNIQUE (owner_id, title),
  INDEX ix_tasks_owner_status (owner_id, status),
  INDEX ix_tasks_due_date (due_date)
);

CREATE TABLE comments (
  id         BIGINT        NOT NULL AUTO_INCREMENT PRIMARY KEY,
  task_id    BIGINT        NOT NULL,
  author_id  BIGINT        NOT NULL,
  body       VARCHAR(1000) NOT NULL,                -- COMMENT_MAX. Stored AS TYPED: escaping is the renderer's job (S35)
  created_at TIMESTAMP     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  CONSTRAINT fk_comments_task   FOREIGN KEY (task_id)   REFERENCES tasks (id) ON DELETE CASCADE,
  CONSTRAINT fk_comments_author FOREIGN KEY (author_id) REFERENCES users (id) ON DELETE CASCADE,
  INDEX ix_comments_task (task_id, created_at)
);

CREATE TABLE audit_events (
  id       BIGINT       NOT NULL AUTO_INCREMENT PRIMARY KEY,
  type     VARCHAR(40)  NOT NULL,                   -- LOGIN_OK | LOGIN_FAIL | ACCESS_DENIED | … (S45)
  username VARCHAR(50)  NULL,                       -- NULL when unknown; NOT a foreign key: failed logins name unknown users
  ip       VARCHAR(45)  NOT NULL,                   -- fits IPv6
  at       TIMESTAMP(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  details  VARCHAR(500) NULL,
  INDEX ix_audit_at (at),
  INDEX ix_audit_type_at (type, at)
);
```

Points worth noticing (each is used later):

- **`ENUM`s for status, priority and role**: the database itself refuses `'DELETED'`. They're mapped to Java enums (S36).
- **`password_hash CHAR(60)`**: a bcrypt hash is always 60 characters. There's no password column, anywhere, ever.
- **`UNIQUE (owner_id, title)`** with the `_ci` collation *is* the business rule "a title is unique per owner, case-insensitively" (02-project-spec §5). The database enforces it even if application code forgets, and S46 turns the violation into a `400` with `fieldErrors.title`.
- **`ON DELETE CASCADE`** from users to tasks and comments, and **`SET NULL`** for a deleted category: the task survives, uncategorised.
- **`updated_at … ON UPDATE CURRENT_TIMESTAMP`**: MySQL maintains it.
- **`audit_events.username` is not a foreign key**, because failed logins name users that don't exist. **`TIMESTAMP(3)`** gives millisecond ordering.
- `comments.body` is stored **as typed**. Escaping is the renderer's job (the S35 XSS lab).

## 5. Least privilege: the grants

```sql
-- S28 (28.07) · PROVIDED. Run as root after 02-schema.sql.

-- Only DATA rights (no CREATE/DROP/ALTER/GRANT): a SQL injection can't drop tables or read other databases.
GRANT SELECT, INSERT, UPDATE, DELETE ON taskflow.users      TO 'taskflow_app'@'%';
GRANT SELECT, INSERT, UPDATE, DELETE ON taskflow.categories TO 'taskflow_app'@'%';
GRANT SELECT, INSERT, UPDATE, DELETE ON taskflow.tasks      TO 'taskflow_app'@'%';
GRANT SELECT, INSERT, UPDATE, DELETE ON taskflow.comments   TO 'taskflow_app'@'%';
-- The audit log is APPEND-ONLY for the app: it can write and read events, never change or erase them (S45).
GRANT SELECT, INSERT ON taskflow.audit_events TO 'taskflow_app'@'%';
```

| The app user can | It can't | So a SQL injection (S36 lab) can't… |
|---|---|---|
| read and write rows in its five tables | `CREATE`, `DROP`, `ALTER`, `GRANT`, anything on other databases | drop tables, create a backdoor user, read `mysql.user` |
| **insert** audit events | **update or delete** audit events | erase its own tracks from the audit log (S45) |

`SeedDataTest.theAppUserGetsNoSchemaRightsAndAnAppendOnlyAuditLog` fails if anyone widens these grants carelessly. Schema changes are run by a **separate admin account** (by you now, and by a migration tool in real projects).
