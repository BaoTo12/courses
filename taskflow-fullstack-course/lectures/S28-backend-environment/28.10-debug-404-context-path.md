# Lecture 28.10 · 🐞 Debug: 404 on Every URL: the Wrong Context Path

> **Section:** S28 · **Type:** 🐞 Debug · **Track:** ★ Core · **Time:** ~20 minutes

---

## 1. The report

> "Tomcat says the WAR deployed fine, but `http://localhost:8080/index.html` and `http://localhost:8080/taskflow/` are both 404."

## 2. The context path: where it comes from

A URL on Tomcat is `http://host:port/<context path>/<path inside the app>`. The **context path** is chosen at deployment:

| Deployment | Context path |
|---|---|
| `webapps/taskflow.war` or `webapps/taskflow/` | `/taskflow` (the **file name**) |
| `webapps/taskflow-backend-1.0.0-SNAPSHOT.war` | `/taskflow-backend-1.0.0-SNAPSHOT` |
| `webapps/ROOT.war` | `/` (the root, no prefix) |
| `webapps/app##2.war` | `/app`, version 2 (parallel deployment) |
| IntelliJ/Eclipse | the *Application context* field of the run configuration |

## 3. Investigate

1. **The deploy log:** `Deployment of web application archive [/usr/local/tomcat/webapps/taskflow-backend-1.0.0-SNAPSHOT.war] has finished`. There's the path.
2. **`webapps/`:** which folder did Tomcat unpack? The folder name is the context path.
3. **The Tomcat Manager** (if installed) lists every app with its path.

The cause: `<finalName>` was missing from the pom, so Maven named the WAR `artifactId-version.war`.

## 4. Fix

- Set `<finalName>taskflow</finalName>` (the provided pom has it, 28.05), rebuild, and delete the old WAR **and** its unpacked folder from `webapps/`.
- Or name the WAR `ROOT.war` to serve at `/`. TaskFlow keeps `/taskflow`, so the React app can live next to it (S49).

## 5. Links that survive any context path

The second half of this bug: a page at `/taskflow/` that links `/static/css/app.css` (absolute) loads the CSS from `/static/…`, **outside** the app → 404, and an unstyled page.

| Link | From `/taskflow/` resolves to | OK? |
|---|---|---|
| `href="static/css/app.css"` (relative) | `/taskflow/static/css/app.css` | ✅ (S28's `index.html`) |
| `href="/static/css/app.css"` (root-absolute) | `/static/css/app.css` | ❌ |
| `href="${pageContext.request.contextPath}/static/css/app.css"` | `/taskflow/static/css/app.css` | ✅ (JSP, S32) |

Servlet code does the same with `request.getContextPath()` when building redirects (S31).

## ✅ Takeaway

404 everywhere → check the **context path** in the deploy log first. Never hard-code it into links.
