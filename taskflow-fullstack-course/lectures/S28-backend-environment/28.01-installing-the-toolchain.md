# Lecture 28.01 · 🛠 Installing JDK 17, Tomcat 9, Maven and MySQL 8 (Installers or Docker)

> **Section:** S28 · **Type:** 🛠 Build · **Track:** ★ Core · **Time:** ~60 minutes
> **Welcome to Part 2.** TaskFlow Web (Part 1) keeps running on the mock API. Now you build the **server**: first TaskFlow Admin (JSP pages), then, in Part 3, the JSON API that replaces the mock.

---

## 1. What you need, and why these versions

| Tool | Version | Why this one |
|---|---|---|
| **JDK** | 17 (or 21; the build compiles *for* 17) | the LTS Tomcat 9 and our libraries support; `maven.compiler.release=17` (28.05) |
| **Apache Tomcat** | **9.0.x** | Servlet 4.0 / JSP 2.3 / EL 3.0 with the **`javax.*`** packages (28.02) |
| **Apache Maven** | 3.9.x | builds the WAR, downloads dependencies |
| **MySQL** | 8.x (8.4 LTS) | the database; `utf8mb4` by default |
| An IDE | IntelliJ IDEA (Community is enough) or Eclipse Enterprise | run and debug Tomcat (28.06) |

## 2. Option A: native installers

**JDK 17:** install Eclipse Temurin 17 (adoptium.net). Then check:

```bash
java -version      # openjdk version "17.0.x" (21 also works)
javac -version
```

Set `JAVA_HOME` to the JDK folder, e.g. `C:\Program Files\Eclipse Adoptium\jdk-17…`. Tomcat's scripts and Maven use it.

**Maven:** unzip it to `C:\tools\apache-maven-3.9.x`, and add its `bin` to `PATH`:

```bash
mvn -v            # Apache Maven 3.9.x … Java version: 17…
```

**Tomcat 9:** unzip `apache-tomcat-9.0.x.zip` (the "Core" zip, **not** 10.x or 11.x) to `C:\tools\apache-tomcat-9.0.x`. Don't install it as a Windows service. The IDE starts it (28.06). Check it:

```bash
C:\tools\apache-tomcat-9.0.x\bin\startup.bat     # then open http://localhost:8080 → the Tomcat welcome page
C:\tools\apache-tomcat-9.0.x\bin\shutdown.bat
```

**MySQL 8:** the MySQL Installer, "Server only" plus MySQL Shell or Workbench. Remember the root password. Then run the provided scripts (28.07).

## 3. Option B: Docker (MySQL and Tomcat in containers)

If you have Docker Desktop, the provided `docker-compose.yml` (in your `taskflow/` folder) starts both, already configured:

```bash
docker compose up -d          # MySQL on :3306 (schema + seed loaded), Tomcat 9 on :8080
docker compose ps             # both "running"; mysql "healthy"
docker compose logs -f tomcat
docker compose down           # stop (data kept)   ·   docker compose down -v   # stop AND wipe the database
```

You still need the **JDK and Maven** on your machine, to build the WAR. Tomcat in Docker deploys the WAR that Maven builds (`backend/target/taskflow.war`).

| | Installers | Docker |
|---|---|---|
| Debugging from the IDE | ✅ simplest (the IDE runs Tomcat) | remote debug needed |
| Clean database in one command | manual | `docker compose down -v` |
| Matches production closely | depends | ✅ same images |

The course shows the IDE route for debugging (28.06) and the Docker route for running.

Copy `provided/backend/` into `taskflow/backend/` and `provided/docker-compose.yml` next to it.
