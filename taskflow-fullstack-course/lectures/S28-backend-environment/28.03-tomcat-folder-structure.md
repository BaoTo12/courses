# Lecture 28.03 · Tomcat's Folder Structure: `bin`, `conf`, `webapps`, `work`, `logs`

> **Section:** S28 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~30 minutes
> 🔗 Reference: Tomcat 9 docs, "Introduction" (directories), "Server configuration"

---

## 1. The layout (`CATALINA_HOME`)

```text
apache-tomcat-9.0.x/
├── bin/        startup.bat/.sh, shutdown, catalina.bat/.sh (the real launcher), setenv (your JVM options)
├── conf/       server.xml · web.xml (defaults for ALL apps) · context.xml (defaults) · tomcat-users.xml · logging.properties
├── lib/        JARs shared by all apps and Tomcat itself: servlet-api.jar, jsp-api.jar, el-api.jar, jasper.jar …
├── webapps/    deployed applications: a WAR file or a folder per app (taskflow.war → webapps/taskflow/)
├── work/       Tomcat's scratch space: JSPs translated to .java and compiled to .class (S33)
├── temp/       java.io.tmpdir for the apps
└── logs/       catalina.<date>.log (server) · localhost.<date>.log (app errors) · localhost_access_log (requests)
```

`CATALINA_HOME` is where Tomcat is installed. `CATALINA_BASE` is where an *instance's* `conf/`, `webapps/`, `logs/` and `work/` live. IDEs use a separate `CATALINA_BASE` per project (28.06), and your download stays untouched.

## 2. The three configuration files you'll meet

| File | Scope | Typical content | In TaskFlow |
|---|---|---|---|
| `conf/server.xml` | the whole server | `<Connector port="8080">`, `<Host appBase="webapps" autoDeploy="true">`, the access-log valve | untouched (port 8080) |
| `conf/web.xml` | **defaults for every app** | the `DefaultServlet` (static files), the `JspServlet` (`*.jsp`), MIME types, welcome files | read it once, never edit it |
| `conf/context.xml` | defaults for every app's `<Context>` | the watched resources that trigger a reload | a container-managed DataSource can live in the **app's** `META-INF/context.xml` (JNDI); TaskFlow builds its own pool instead (36.03) |

Your app's own `WEB-INF/web.xml` **adds to and overrides** `conf/web.xml` for that app.

## 3. What happens at startup

```text
catalina start
  → reads server.xml → opens the HTTP connector on :8080
  → Host "localhost" scans webapps/  (autoDeploy)
      taskflow.war → unpacked to webapps/taskflow/ → a Context with path "/taskflow"
      → reads WEB-INF/web.xml → creates listeners, filters, servlets (S30)
  → logs: "Deployment of web application archive [taskflow.war] has finished in [N] ms"
```

## 4. The logs you'll read when something is wrong

| Log | Contains |
|---|---|
| `catalina.<date>.log` (or the IDE/Docker console) | startup, deployment, **"SEVERE" errors deploying an app** |
| `localhost.<date>.log` | exceptions thrown by **your** servlets and filters, with stack traces |
| `localhost_access_log.<date>.txt` | one line per request: IP, time, `GET /taskflow/tasks`, status, bytes |

With Docker: `docker compose logs tomcat`. Files are inside the container at `/usr/local/tomcat/logs`.

## ✅ Recap

`bin` starts it, `conf` configures it, `webapps` holds your WAR, `work` holds compiled JSPs, and `logs` tells you what went wrong. Server-wide defaults live in `conf/web.xml`, and your app's own settings in `WEB-INF/web.xml`.
