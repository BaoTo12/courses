# Lecture 28.02 · `javax` vs `jakarta`: the Namespace History, and Why Tomcat 9 = `javax`

> **Section:** S28 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~20 minutes

---

## 1. The history in five lines

```text
1999–2017  Sun, then Oracle: "Java EE". Packages javax.servlet, javax.servlet.jsp, javax.el …
2017       Oracle gives Java EE to the Eclipse Foundation → renamed "Jakarta EE"
2019       Jakarta EE 8: identical to Java EE 8, STILL javax.*   (Oracle kept the "javax" trademark)
2020       Jakarta EE 9: the big rename javax.* → jakarta.*  (the ONLY change: package names)
2022+      Jakarta EE 10, 11: new features, jakarta.* only
```

## 2. Which Tomcat speaks which

| Tomcat | Servlet | JSP | EL | Packages | Java |
|---|---|---|---|---|---|
| **9.0** | **4.0** | **2.3** | **3.0** | **`javax.*`** | 8+ |
| 10.0 | 5.0 | 3.0 | 4.0 | `jakarta.*` | 8+ |
| 10.1 | 6.0 | 3.1 | 5.0 | `jakarta.*` | 11+ |
| 11.0 | 6.1 | 4.0 | 6.0 | `jakarta.*` | 17+ |

**TaskFlow uses Tomcat 9, and therefore `javax.*`**: `import javax.servlet.http.HttpServlet;`. Why this and not the newest?

- A **huge** share of real-world applications, tutorials and company codebases are still Servlet 4 / `javax`. Your team's included.
- The concepts are **identical**. Moving to Tomcat 10+ later is a package rename, plus dependency versions (see §4).

## 3. The rule you must never break

> The `javax`/`jakarta` choice must match **across the whole application**: your imports, every library (JSTL!), and the container.

| Mismatch | Symptom |
|---|---|
| `jakarta.servlet` imports on Tomcat 9 | `ClassNotFoundException: jakarta.servlet.http.HttpServlet` (28.09) |
| `javax.servlet` imports on Tomcat 10+ | the servlet is loaded as a plain class, so every URL is **404** |
| JSTL 2/3 (`jakarta.servlet.jsp.jstl`) on Tomcat 9 | "The absolute uri … cannot be resolved", `ClassNotFoundException` on tags |

## 4. Migrating later (for your information)

1. Replace imports: `javax.servlet` → `jakarta.servlet` (IDEs and the Eclipse Transformer tool can do it).
2. Dependencies: `jakarta.servlet:jakarta.servlet-api:6.0.0` (provided), and JSTL `jakarta.servlet.jsp.jstl-api` + `org.glassfish.web:jakarta.servlet.jsp.jstl`.
3. `web.xml` namespace: `https://jakarta.ee/xml/ns/jakartaee`.
4. Deploy on Tomcat 10.1+.

## ✅ Recap

Tomcat 9 = Servlet 4.0 = `javax.*`. Everything in one application must use the same namespace. Most "mysterious" deployment errors in tutorials come from mixing them.
