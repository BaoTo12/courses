# Lecture 30.01 · What a Servlet *Is*

> **Section:** S30 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~20 minutes

---

## 1. One sentence

> A **servlet** is a Java object that the **container** (Tomcat) calls to turn an HTTP request into an HTTP response.

```java
public class HelloServlet extends HttpServlet {
  @Override
  protected void doGet(HttpServletRequest request, HttpServletResponse response) throws IOException {
    response.setContentType("text/html;charset=UTF-8");
    response.getWriter().println("<h1>Hello</h1>");
  }
}
```

## 2. What you *don't* write

| You'd expect to write | Who does it |
|---|---|
| `public static void main(String[] args)` | nobody: Tomcat is the program; your class is a plug-in |
| `new ServerSocket(8080)`, reading bytes | Tomcat's connector (29.01) |
| parsing the request line, headers, `?a=1&b=2`, cookies | Tomcat → `HttpServletRequest` |
| `new HelloServlet()` | Tomcat, once (30.05) |
| threads for concurrent users | Tomcat's thread pool (30.03) |
| writing the status line, headers and `Content-Length` | Tomcat, from what you set on `HttpServletResponse` |

This is **inversion of control**: you implement methods, and the framework decides when to call them. React components work the same way (you never call `render` yourself).

## 3. The Servlet API is an interface family

```text
javax.servlet.Servlet                   init(ServletConfig) · service(req, res) · destroy() · …
  └─ javax.servlet.GenericServlet       protocol-independent convenience (log(), getInitParameter())
       └─ javax.servlet.http.HttpServlet  service() → doGet / doPost / doPut / doDelete … (30.07)
            └─ your HelloServlet          overrides doGet (and doPost…)
```

You always extend `HttpServlet`. The container only knows the `Servlet` interface.

## 4. Where servlets sit in TaskFlow

```text
Part 2: browser ──► Tomcat ──► Servlet (controller) ──► service/DAO ──► MySQL
                                   └──forward──► JSP (view) ──► HTML
Part 3: TaskFlow Web ──► Tomcat ──► API Servlet ──► JSON
```

Servlets are the **controllers** from S36 on, and JSPs render the views. In this section a servlet does everything itself, with `println`. S32 shows why that stops scaling.

## ✅ Recap

A servlet is a container-managed object with request-handling methods. No `main`, no sockets, no parsing: you receive a parsed request and fill in a response.
