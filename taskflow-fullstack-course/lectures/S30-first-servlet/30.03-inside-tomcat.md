# Lecture 30.03 · Inside Tomcat: Connector → Engine → Host → Context → Wrapper; the Thread Pool

> **Section:** S30 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~30 minutes
> 🔗 Reference: Tomcat 9 docs, "Architecture overview" and "The HTTP Connector"

---

## 1. The component tree (Catalina)

```text
Server (one JVM, port 8005 for shutdown)
└── Service "Catalina"
    ├── Connector  HTTP/1.1 :8080  (NIO)  ── parses bytes → Request
    │     └── Executor / thread pool: maxThreads=200, acceptCount=100
    └── Engine "Catalina"                  ── picks the Host from the Host header
        └── Host "localhost" (appBase=webapps)
            ├── Context "/taskflow"         ── ONE web app = your WAR (its class loader, web.xml, sessions)
            │   ├── Wrapper "HelloServlet"   ── holds ONE servlet instance
            │   ├── Wrapper "TimeServlet"
            │   ├── Wrapper "default"        ── the DefaultServlet (static files)
            │   └── Wrapper "jsp"            ── the JspServlet
            └── Context "/" (ROOT), …
```

These names appear in `server.xml` and in log lines such as `StandardContext[/taskflow]` and `StandardWrapper`.

## 2. A request's path through it

```text
1. The Acceptor accepts a TCP connection on :8080
2. A Poller notices bytes are ready → hands the socket to a WORKER THREAD from the pool (http-nio-8080-exec-N)
3. The worker parses the request (29.01) → Request/Response objects
4. Engine: Host header "localhost" → Host
5. Host: path "/taskflow/hello" → Context "/taskflow"  (the longest matching context path)
6. Context: "/hello" → Wrapper "HelloServlet"  (the mapping rules, 30.11)
7. Filter chain (S39) → servlet.service(req, res) → your doGet(req, res)   ← on the SAME worker thread
8. The response is flushed; the worker returns to the pool; keep-alive waits for the next request
```

## 3. The thread pool, and what it means for you

| Setting (`<Connector>`) | Default | Meaning |
|---|---|---|
| `maxThreads` | 200 | at most 200 requests **processed** at the same time |
| `acceptCount` | 100 | connections queued when all threads are busy; beyond that, refused |
| `connectionTimeout` | 20000 ms | idle wait for the request bytes |

Consequences:

1. **One servlet instance, many threads at once** (30.05). Fields in a servlet are shared by all concurrent requests: thread-safety matters.
2. **A slow `doGet` holds a thread.** 200 slow requests (a slow database query, S36) = the server stops answering. Keep requests short, and use timeouts (connection pool, S36).
3. **ThreadLocals leak across requests**, because threads are reused. Clear anything you put in them (S43's logging MDC does it in `finally`).

## ✅ Recap

Connector (bytes, threads) → Engine → Host (by `Host` header) → Context (by context path) → Wrapper (by servlet mapping) → your method, on a pooled worker thread.
