# Lecture 30.13 · `ServletContext`: One per Web App; Context Params; a First Look at Application Scope

## 1. The application's object

There is **one `ServletContext` per deployed web app** (per Tomcat `Context`, 30.03), shared by all its servlets, filters, listeners and JSPs.

```xml
<!-- web.xml -->
<context-param>
  <param-name>greeting</param-name>
  <param-value>Xin chào từ TaskFlow!</param-value>
</context-param>
```

```java
String greeting = getServletContext().getInitParameter("greeting");   // any servlet, filter, JSP (${initParam.greeting}, S34)
```

## 📇 API card: `ServletContext`

| Method | Use |
|---|---|
| `getInitParameter(name)` | app-wide configuration (`<context-param>`) |
| `getAttribute` / `setAttribute` / `removeAttribute` | **application scope**: objects shared by all requests and users (S38) |
| `getContextPath()` | `/taskflow` |
| `getRealPath("/static")` | the filesystem path (may be `null` for unexploded WARs; avoid it) |
| `getResourceAsStream("/WEB-INF/…")` | read files packaged in the WAR (works for WARs too) |
| `getRequestDispatcher(path)` / `getNamedDispatcher(name)` | forward/include (S31) |
| `log(msg[, throwable])` | the container log |
| `getMimeType("x.pdf")` | `application/pdf` |
| `getServerInfo()` | `Apache Tomcat/9.0.x` |

## 2. Per servlet or per application?

| Setting | Where | Example |
|---|---|---|
| Only one servlet uses it | init parameter (`ServletConfig`) | `TimeServlet`'s `format` |
| Several components use it | context parameter (`ServletContext`) | `greeting`; later the default page size, a feature flag |
| Shared **objects** built at startup | application attribute, set by a listener | the DAO / DataSource (S36), cached categories (S38) |

## 3. Application scope is shared by everyone

An application attribute is visible to **every user** and **every thread**. Store only thread-safe, non-user-specific things there. "The current user" in application scope is a data leak between users, the server-side twin of 23.10's cache bug.

## ✅ Recap

`ServletContext` = the app. Context params hold app-wide configuration, and attributes are app-wide shared objects (thread-safe, never per-user).
