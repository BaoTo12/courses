# Lecture 30.17 · 🐞 Debug: Vietnamese Characters Show as `?`

> **Section:** S30 · **Type:** 🐞 Debug · **Track:** ★ Core · **Time:** ~20 minutes

---

## 1. The report

> "`/time` shows `Xin ch?o t? TaskFlow!`. The web.xml is fine, and I set UTF-8!"

## 2. The code

```java
protected void doGet(HttpServletRequest request, HttpServletResponse response) throws IOException {
  PrintWriter out = response.getWriter();                // ①
  response.setContentType("text/html;charset=UTF-8");    // ②
  out.println("<h1>" + Html.escape(greeting) + "</h1>");
}
```

## 3. Investigate

1. `curl -i …/time`: the header says `Content-Type: text/html;charset=ISO-8859-1`. Our charset never made it.
2. The body contains literal `?` bytes (0x3F), not mis-decoded UTF-8. So the characters were **lost when encoding**, not when displaying.

Why: **`getWriter()` creates the writer with the charset in effect at that moment.** No charset was set yet, so the Servlet default, **ISO-8859-1**, was used. ISO-8859-1 has no `à` or `ừ`, so the writer replaced them with `?`. Once the writer exists, `setContentType`'s charset is **ignored** for the body (the spec says so), and even for the header, as curl shows.

## 4. Fix

```java
response.setContentType("text/html;charset=UTF-8");    // 1. charset
PrintWriter out = response.getWriter();                 // 2. writer
```

## 5. The other three places Vietnamese gets mangled

| Symptom | Cause | Fix |
|---|---|---|
| `?` in the page | the writer's charset (this lecture) | charset before `getWriter()` |
| `Xin chÃ o` (mojibake) | UTF-8 bytes sent, but the browser was told or assumed ISO-8859-1 | a correct `Content-Type` header; `<meta charset="utf-8">` |
| a **form** value arrives as `CÃ´ng` | the request body was decoded as ISO-8859-1 | `request.setCharacterEncoding("UTF-8")` **before** the first `getParameter` (an encoding filter, S39) |
| `web.xml` or JSP text broken | the source file saved in a legacy encoding | save everything as UTF-8; JSP: `pageEncoding="UTF-8"` (S32) |

## ✅ Takeaway

Set the charset **before** getting the writer. When text breaks, first ask: lost (`?`) or mis-decoded (`Ã`)? Then find which of the four places is wrong.
