# Lecture 30.02 · What a Servlet Container Does

> **Section:** S30 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~25 minutes

---

## The container's jobs, in request order

| # | Job | Details you'll meet |
|---|---|---|
| 1 | **Listen** on a port | the connector on :8080 (`server.xml`), TLS if configured |
| 2 | **Parse** HTTP | request line, headers, cookies, query, body → `HttpServletRequest` |
| 3 | **Map** the URL to a web app, then to a servlet | context path `/taskflow` → the app; `/hello` → `HelloServlet` (30.11) |
| 4 | **Run filters** before the servlet | encoding, auth, CSRF, headers (S39–S41) |
| 5 | **Provide a thread** | one pool thread per request in progress (30.03) |
| 6 | **Manage the lifecycle** | create servlets once, `init`, `service` many times, `destroy` at shutdown (30.05) |
| 7 | **Manage sessions** | `JSESSIONID`, `HttpSession`, timeouts (S38) |
| 8 | **Serialise the response** | status, headers, cookies, the body buffer, `Content-Length` or chunked |
| 9 | **Serve static files and JSPs** | the `DefaultServlet` (`index.html`, CSS); the `JspServlet` (`*.jsp`, S33) |
| 10 | **Handle errors** | `sendError(404)`, uncaught exceptions → error pages (S43) |
| 11 | **Isolate apps** | one class loader per web app; `WEB-INF` protection (28.04) |

## Why a container at all?

Every web app needs 1–11, and none of it is your business logic. The Servlet **specification** standardises the contract, so your WAR runs on any compliant container (Tomcat, Jetty, Undertow, WebLogic…). Spring MVC, Jakarta Faces and Struts are all built **on top of** servlets: Spring's `DispatcherServlet` is one servlet that routes to your controllers.

## Seeing it

`HelloServlet` prints the **thread name** that handled each request (30.04). Reload quickly and watch the names change: `http-nio-8080-exec-1`, `…-exec-7`… Different threads, one servlet object.

## ✅ Recap

The container does the plumbing: sockets, parsing, mapping, threads, lifecycle, sessions, static files, errors. You write what's specific to your app.
