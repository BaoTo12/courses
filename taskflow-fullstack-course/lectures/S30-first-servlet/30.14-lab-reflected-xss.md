# Lecture 30.14 · 🔓 Lab: Reflected XSS from a `println`

> **Section:** S30 · **Type:** 🔓 Attack Lab · **Track:** ★ Core · **Time:** ~30 minutes
> ⚠️ Local only, in a lab branch.
> Verified (the fixed version): `S30ServletsTest.helloEscapesTheNameReflectedXssIsText`

---

## 1. The vulnerable line

In a branch, remove the escaping from `HelloServlet`:

```java
out.println("<h1 class=\"page__title\">Hello, " + who + "!</h1>");      // ❌ lab only
```

## 2. Attack

```text
http://localhost:8080/taskflow/hello?name=<script>alert(document.domain)</script>
http://localhost:8080/taskflow/hello?name=<img src=x onerror=alert(1)>
```

The alert runs. The server **reflected** the input straight into the HTML: that's **reflected XSS** (26.01 §2). The attacker sends a victim this link (in an email or a chat), and the script runs in **TaskFlow's origin**, with the victim's session (26.03 §3 showed what it can do).

Now view the page source: your `<script>` is right there in the HTML the server wrote. There's no React here to save you (26.02). With `println`, **you** are the template engine, so escaping is your job.

Also try the attribute context:

```java
out.println("<input value=\"" + who + "\">");                             // ❌
// ?name=" autofocus onfocus="alert(1)
```

The quote closes the attribute, and the attacker adds an event handler.

## 3. Fix

```java
out.println("<h1 class=\"page__title\">Hello, " + Html.escape(who) + "!</h1>");   // ✅
```

`Html.escape` turns `<` into `&lt;` and `"` into `&quot;`, among others (30.04 §2). The same payloads now display as text. The test posts `<script>alert(1)</script>` and asserts the escaped form is in the body, and the raw one isn't.

## 4. Lessons for Part 2

1. Every value from the request that goes into HTML is escaped **at output**, in its context (text, attribute).
2. `println` HTML is error-prone: one forgotten `escape` is a vulnerability. JSP with `<c:out>` / `${fn:escapeXml(…)}` (S35) makes escaping the normal path, and CSP (S40) is the second wall.
3. **Input validation** helps (a name shouldn't contain `<`), but it's not the defence: legitimate data (a comment about `<div>`s) contains these characters. Escape anyway.

## 5. Clean up

Back to the main branch. The escaped version is the reference code.
