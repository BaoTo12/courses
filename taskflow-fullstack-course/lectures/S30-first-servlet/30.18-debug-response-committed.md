# Lecture 30.18 · 🐞 Debug: `Cannot call sendRedirect() after the response has been committed`

> **Section:** S30 · **Type:** 🐞 Debug · **Track:** ★ Core · **Time:** ~20 minutes

---

## 1. The code

```java
protected void doGet(HttpServletRequest request, HttpServletResponse response) throws IOException {
  response.setContentType("text/html;charset=UTF-8");
  PrintWriter out = response.getWriter();
  out.println("<!doctype html><html><body>");
  for (int i = 0; i < 2000; i++) out.println("<p>Row " + i + "</p>");   // ~30 KB
  if (request.getParameter("name") == null) {
    response.sendRedirect("hello?name=guest");                            // 💥
    return;
  }
  …
}
```

The log shows `java.lang.IllegalStateException: Cannot call sendRedirect() after the response has been committed`. The browser shows half a page.

## 2. Why

- The body went into the **8 KB buffer** (30.09 §2). After about 8 KB, the buffer filled, and Tomcat **flushed** it: the status line `200` and the headers were sent to the browser. The response is now **committed**.
- A redirect is a **status (302) plus a header (`Location`)**. Both would have to be written **before** the body, and that part is already on the wire. The container can't take it back, so it throws.
- With a tiny page, the buffer wouldn't have filled, and the same code would "work": the bug depends on the output size. That's why it hides in development and shows up in production.

## 3. Fix: decide first, write second

```java
if (request.getParameter("name") == null) {
  response.sendRedirect("hello?name=guest");
  return;                              // ← and ALWAYS return after a redirect or sendError
}
response.setContentType("text/html;charset=UTF-8");
PrintWriter out = response.getWriter();
…
```

Two related bugs:
- **A forgotten `return`** after `sendRedirect`: the code continues and writes a body after the redirect. Usually harmless-looking, but it may run actions (a delete!) that the redirect was meant to skip.
- **`forward` after writing** (S31): the same exception family ("Cannot forward after response has been committed").

## 4. Why MVC removes the problem

From S36, a servlet **decides** (validate, load data, choose the view or a redirect) and **then** forwards to a JSP that writes the body. Nothing is written before the decision, so the response can't be committed too early.

## ✅ Takeaway

Status, headers and redirects first; the body last. `return` right after `sendRedirect`/`sendError`. `isCommitted()` tells you whether it's too late.
