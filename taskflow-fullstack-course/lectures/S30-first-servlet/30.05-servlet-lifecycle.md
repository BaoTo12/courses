# Lecture 30.05 · The Lifecycle: Load → `init()` → `service()` Many Times → `destroy()`

> **Section:** S30 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~30 minutes
> 🔗 Reference: Servlet 4.0 specification, chapter 2.3 ("Servlet Life Cycle")

---

## 1. The timeline

```text
deployment ─┬─ load the class, new HelloServlet()        ← ONCE (the no-arg constructor)
            ├─ init(ServletConfig)  → your init()        ← ONCE, before any request; may throw → servlet unavailable
            │
requests ───┼─ service(req, res) → doGet/doPost …        ← MANY times, CONCURRENTLY, one thread per request
            │   (thread exec-1) (thread exec-2) (thread exec-7) … all on the SAME object
            │
undeploy ───└─ destroy()                                 ← ONCE, after in-flight requests finish (or a timeout)
   / stop       then the object is garbage
```

| Method | Called | Use it for | Don't |
|---|---|---|---|
| constructor | once | nothing (the `ServletConfig` isn't available yet) | read init params |
| `init()` | once, before the first request | read configuration, build expensive thread-safe objects (a formatter, a DAO) | per-request work |
| `service`/`doXxx` | per request | handle the request | store per-request data in fields |
| `destroy()` | once, at shutdown | release resources (close pools, stop timers) | expect it to run if the JVM is killed |

## 2. When is the servlet created?

- **Default:** lazily, on the **first request** to it. The first user pays the `init` cost.
- **`loadOnStartup = n`** (≥ 0): at **deployment**, in ascending `n` order. Use it when `init` is slow, or must fail fast (a missing configuration should break the deployment, not the first request).

## 3. How many instances? Usually **one**

For each servlet declaration (an annotation, or a `<servlet>` element), the container creates **one** instance and shares it between all threads. So:

```java
public class BadServlet extends HttpServlet {
  private String currentUser;                         // ❌ SHARED by all concurrent requests
  protected void doGet(HttpServletRequest req, HttpServletResponse res) {
    currentUser = req.getParameter("user");           // thread A writes "alice"
    …                                                 // thread B writes "bob"
    res.getWriter().println("Hi " + currentUser);    // A may print "Hi bob"
  }
}
```

**Rules:**
1. Per-request data lives in **local variables** (each thread has its own stack) or **request attributes** (S31).
2. Fields are only for things that are **immutable or thread-safe**, set in `init()`: a `DateTimeFormatter` (immutable, `TimeServlet`), an `AtomicLong` (`HelloServlet`), a DAO with a connection pool (S36).
3. Never `synchronized doGet`: that serialises every user through one lock.

(`SingleThreadModel`, which promised one thread per instance, was deprecated in Servlet 2.4 and removed in 5.0. Don't use it.)

## 4. `init()` that fails

If `init()` throws `ServletException`, the servlet is **unavailable**: requests get an error (500 or 503, depending on the container), and the log shows why. `TimeServlet` uses this on purpose: an invalid `format` pattern fails at init, visibly (30.16).

## ✅ Recap

One instance, `init` once, `service` concurrently on many threads, `destroy` once. Per-request data never goes in fields.
