# Lecture 30.99 · ✅ Knowledge Check: Your First Servlet

> **Section:** S30 · **Type:** ✅ Knowledge Check · **Track:** ★ Core · **Time:** ~20 minutes

---

**1.** 100 users request `/hello` at the same moment. How many `HelloServlet` objects exist? How many threads?

<details><summary>Answer</summary>

**One** object: one instance per servlet declaration (30.05). Up to **100 threads** run `doGet` on it concurrently, taken from the connector's pool (default `maxThreads` 200, 30.03). Hence the thread-safe `AtomicLong`.
</details>

**2.** Who calls `doGet`? Trace from the TCP connection to your method.

<details><summary>Answer</summary>

The connector accepts the connection → a worker thread parses the bytes into a request → Engine (by `Host`) → Host → Context `/taskflow` (by context path) → Wrapper (by servlet mapping) → the filter chain → `servlet.service(req, res)` (`HttpServlet`) → `doGet(req, res)` because the method is GET (30.03, 30.07).
</details>

**3.** For `/taskflow/tasks/view/5?x=1` mapped to `/tasks/*`, give `getContextPath`, `getServletPath`, `getPathInfo` and `getQueryString`.

<details><summary>Answer</summary>

`/taskflow`, `/tasks`, `/view/5`, `x=1`. And `getRequestURI()` = `/taskflow/tasks/view/5` = context + servlet path + path info (30.08).
</details>

**4.** Two servlets are both mapped to `/tasks`. What happens at deployment?

<details><summary>Answer</summary>

Tomcat refuses to start the application. The deployment fails with an error saying both servlets are mapped to the url-pattern `/tasks`, which is not permitted. Mappings must be unique (30.11).
</details>

**5.** Where do you put a value configured per servlet, and one per application?

<details><summary>Answer</summary>

Per servlet: an **init parameter** (`@WebInitParam` / `<init-param>`, read via `ServletConfig`). Per application: a **context parameter** (`<context-param>`, read via `ServletContext`). Neither holds secrets (30.12, 30.13).
</details>

**6.** Why is `private String currentUser;` in a servlet a bug?

<details><summary>Answer</summary>

The field is shared by every concurrent request (one instance, many threads). One request's user can appear in another's response. Per-request data belongs in local variables or request attributes (30.05 §3).
</details>

**7.** `/hello?name=<script>alert(1)</script>` shows an alert. Name the vulnerability and the fix.

<details><summary>Answer</summary>

**Reflected XSS**: the input is written into HTML unescaped. Fix it by escaping at output (`Html.escape`, later `<c:out>`), and add CSP as a second wall (30.14).
</details>
