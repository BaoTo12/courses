# Lecture 41.13 · 🔓 User Enumeration (Conceptual)

> **Section:** S41 · **Type:** 🔓 Attack Lab (conceptual) · **Track:** ★ Core · **Time:** ~15 minutes

---

## 1. The flaw

A login that answers differently for "no such user" and "wrong password" tells anyone which usernames exist. Common leaks:

| Leak | Example |
|---|---|
| different **messages** | "Unknown user" vs "Wrong password" |
| different **status codes** or redirects | 404 vs 401 |
| different **timing** | an unknown user returns immediately; a known one spends ~0.25 s in BCrypt (41.06) |
| other pages | "reset password: this email isn't registered", a sign-up form saying "username taken" |

## 2. Why it matters

A list of valid usernames turns password guessing from "guess both" into "guess one", focuses phishing on real accounts, and for some systems is sensitive in itself (being a customer of a clinic, for example).

## 3. The timing channel, in numbers

Without precautions: an unknown username → a database lookup and nothing else (a few milliseconds); a known one → the same lookup + a BCrypt check (~250 ms). The difference is visible from anywhere on the internet with a handful of requests.

## Lesson

Every observable difference between "user exists" and "user doesn't exist" is an answer to the question. 41.14 removes them.
