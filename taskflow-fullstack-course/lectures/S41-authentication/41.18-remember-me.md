# Lecture 41.18 · "Remember Me" Designs and Why They're Risky

> **Section:** S41 · **Type:** 📖 Theory · **Track:** ＋ Extended · **Time:** ~10 minutes

*Extended track: outline.*

---

- **The need:** stay logged in for weeks, beyond a 15-minute session.
- **Never:** a cookie with the username and password (or its hash), or a long-lived session id. Whoever copies the cookie owns the account for weeks.
- **The accepted design (split token):** at login with "remember me", create a random `selector` + `validator`; store `selector` and a **hash** of `validator` in a `remember_tokens` table with the user id and an expiry; set a cookie `selector:validator` (`HttpOnly`, `Secure`, `SameSite=Lax`). On a request without a session: look up the selector, compare the hashed validator in constant time, create a fresh session (new id), and **rotate** the token (a new validator each use).
- **Theft detection:** if a selector arrives with the **wrong** validator, someone used a stolen, already-rotated token: delete all the user's tokens and alert.
- **Limits:** "remembered" sessions should not allow sensitive actions (changing the password or email, admin operations) without re-entering the password.
- **Logout** deletes the token row, not just the cookie. "Log out everywhere" deletes all rows for the user.
- TaskFlow doesn't implement it: admins log in daily, and a 15-minute idle timeout is the safer default for an admin portal.
