# Lecture 41.03 · 🛠 Lab: Watch `JSESSIONID` Being Created, Changed and Destroyed

> **Section:** S41 · **Type:** 🛠 Lab · **Track:** ★ Core · **Time:** ~20 minutes
> Verified: `S41AuthenticationTest.aSuccessfulLoginChangesTheSessionIdAndGoesBack`, `.logoutDestroysTheSessionAndPrivatePagesAreNotCached`

---

Open TaskFlow Admin in a private window, with DevTools → **Application → Cookies** and **Network** side by side.

| Step | What you see | Why |
|---|---|---|
| 1. open `/taskflow/tasks` | a **303** to `/taskflow/login?returnUrl=…`; no cookie yet | the filter redirects anonymous users without creating a session (41.09) |
| 2. the login page loads | `Set-Cookie: JSESSIONID=…; Path=/taskflow; HttpOnly; SameSite=Lax` | the login form needs a CSRF token, stored in a (pre-login) session |
| 3. log in as `alice` / `alice123` | a **new** `JSESSIONID` value in the 303's `Set-Cookie` | `changeSessionId()` (41.11) |
| 4. type `document.cookie` in the Console | `tf_theme=…` maybe, but **no** `JSESSIONID` | `HttpOnly` (41.12) |
| 5. edit the cookie's value in DevTools and reload | back to the login page, "Your session has expired" | the id is unknown to the server (41.19) |
| 6. log in again, then **Log out** | yet another `JSESSIONID`: the old session is gone, a new anonymous one carries "You have been logged out." | `invalidate()` + a flash (41.08) |
| 7. Settings → block cookies for `localhost`, reload | you can never stay logged in; no `;jsessionid=` appears in URLs | `COOKIE`-only tracking (41.02 §3) |

Write down the three `JSESSIONID` values from steps 2, 3 and 6: all different. That's the session lifecycle working as designed.
