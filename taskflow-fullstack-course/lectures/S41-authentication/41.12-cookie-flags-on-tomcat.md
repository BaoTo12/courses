# Lecture 41.12 · 🛡 Cookie Flags on Tomcat 9: `HttpOnly`, `Secure`, `SameSite`

> **Section:** S41 · **Type:** 🛡 Defend · **Track:** ★ Core · **Time:** ~20 minutes
> Verified: `S41AuthenticationTest.aSuccessfulLoginChangesTheSessionIdAndGoesBack` (`JSESSIONID` has `HttpOnly` and `SameSite=Lax`)

---

## 1. Where each flag comes from

| Flag | For `JSESSIONID` | For your own cookies |
|---|---|---|
| `HttpOnly` | `web.xml` `<cookie-config><http-only>true</http-only>` (Tomcat's default is also true) | `cookie.setHttpOnly(true)` |
| `Secure` | `<cookie-config><secure>true</secure>`, or automatic when the request came over HTTPS | `cookie.setSecure(true)` |
| `SameSite` | Tomcat's `CookieProcessor` in `context.xml` | the same (Servlet 4.0 has no API for it) |
| `Path` | the context path (`/taskflow`) | `cookie.setPath(…)` |

✍️ TaskFlow's `src/main/webapp/META-INF/context.xml`:

```xml
<Context>
  <JarScanner scanManifest="false"/>
  <!-- S41 (41.12): SameSite=Lax on every cookie Tomcat writes (JSESSIONID, tf_theme): a second layer against CSRF (37.14). -->
  <CookieProcessor sameSiteCookies="lax"/>
</Context>
```

## 2. Choosing the values

| Flag | TaskFlow | Why |
|---|---|---|
| `HttpOnly` on `JSESSIONID` | ✅ | an XSS can't read the session id (it can still act on the page, 35.14) |
| `Secure` | ✅ **in production** (HTTPS), not in local HTTP development | over plain HTTP, `Secure` cookies are never sent back: you'd never stay logged in (41.99 Q4) |
| `SameSite=Lax` | ✅ | cross-site POSTs arrive without the session (37.14); top-level links from emails still work |
| `SameSite=Strict` | ❌ | a user following a link to TaskFlow from their email would look logged out |

## 3. Production additions (outline)

- `<cookie-config><secure>true</secure></cookie-config>` (or rely on HTTPS detection behind a correctly configured proxy: `RemoteIpValve`).
- `Strict-Transport-Security: max-age=31536000` from `SecurityHeadersFilter`, HTTPS only.
- A cookie name prefix `__Host-` (requires `Secure`, `Path=/`, no `Domain`) makes the cookie impossible to set from subdomains, which is a strong defence against 41.10's cookie-setting route.

## ✅ Recap

`HttpOnly` and `SameSite=Lax` everywhere, `Secure` in production. Tomcat 9 sets `SameSite` through its cookie processor.
