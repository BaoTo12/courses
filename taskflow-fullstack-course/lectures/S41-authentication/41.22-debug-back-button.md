# Lecture 41.22 · 🐞 Debug: Logout "Works", but the Back Button Shows Protected Pages

> **Section:** S41 · **Type:** 🐞 Debug · **Track:** ★ Core · **Time:** ~10 minutes
> Verified: `S41AuthenticationTest.logoutDestroysTheSessionAndPrivatePagesAreNotCached` (`Cache-Control: no-store` on a logged-in page)

---

## 1. Symptom

After logging out on a shared computer, the next person presses **Back** and sees the task list, with names and comments. Clicking anything goes to the login page, so the session really is gone.

## 2. Cause

The browser didn't ask the server: it showed the page from its **cache** (the back-forward cache or the HTTP cache). Nothing told it not to keep the page.

## 3. Fix

```java
response.setHeader("Cache-Control", "no-store");   // in AuthenticationFilter, for logged-in, non-static requests
```

| Header | Meaning |
|---|---|
| `Cache-Control: no-store` | don't keep any copy, in memory or on disk; also opts the page out of most back-forward caches |
| `Cache-Control: no-cache` | keep it, but revalidate before use (the page would still be shown by some back-forward caches) |
| `Pragma: no-cache`, `Expires: 0` | HTTP/1.0 leftovers; harmless, not needed for modern browsers |

Static files (CSS, JS) aren't private: they keep normal caching, which is why the filter skips `/static/`.

## ✅ Takeaway

Logging out ends the session on the server; it doesn't erase what the browser kept. Private pages need `no-store`.
