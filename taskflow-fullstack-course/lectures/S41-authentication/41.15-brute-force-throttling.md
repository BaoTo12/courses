# Lecture 41.15 · 🛡 Brute Force: Per-Account and Per-IP Throttling (In Memory, Thread-Safe)

## 1. The throttle

✍️ `src/main/java/com/taskflow/security/LoginThrottle.java`

```java
package com.taskflow.security;

import java.time.Clock;
import java.time.Duration;
import java.time.Instant;
import java.util.concurrent.ConcurrentHashMap;

/**
 * S41 (41.15): slows down password guessing. Failed logins are counted per ACCOUNT and per client IP, in a time
 * window; over the limit, logins are refused (even with the right password) until the window ends.
 * In memory, application-wide, thread-safe (38.04): ConcurrentHashMap.compute is atomic per key.
 * Limits of this design: per server (a cluster needs a shared store), lost on restart, and the map grows with the
 * number of distinct keys (expired windows are dropped when touched).
 */
public class LoginThrottle {

  private record Window(int failures, Instant start) {}

  private final int maxPerAccount;
  private final int maxPerIp;
  private final Duration period;
  private final Clock clock;
  private final ConcurrentHashMap<String, Window> windows = new ConcurrentHashMap<>();

  public LoginThrottle(int maxPerAccount, int maxPerIp, Duration period, Clock clock) {
    this.maxPerAccount = maxPerAccount;
    this.maxPerIp = maxPerIp;
    this.period = period;
    this.clock = clock;
  }

  public boolean isBlocked(String username, String ip) {
    return failures("user:" + username) >= maxPerAccount || failures("ip:" + ip) >= maxPerIp;
  }

  public void recordFailure(String username, String ip) {
    fail("user:" + username);
    fail("ip:" + ip);
  }

  public void recordSuccess(String username) {
    windows.remove("user:" + username);
  }

  public Duration period() {
    return period;
  }

  private void fail(String key) {
    Instant now = clock.instant();
    windows.compute(key, (k, w) -> w == null || expired(w, now) ? new Window(1, now) : new Window(w.failures() + 1, w.start()));
  }

  private int failures(String key) {
    Instant now = clock.instant();
    Window w = windows.get(key);
    if (w == null) return 0;
    if (expired(w, now)) {
      windows.remove(key, w);
      return 0;
    }
    return w.failures();
  }

  private boolean expired(Window w, Instant now) {
    return w.start().plus(period).isBefore(now);
  }
}
```

TaskFlow's settings (in `AppContextListener`): **5** failures per account or **20** per IP address, in a **15-minute** window.

| Key | Stops |
|---|---|
| per **account** | many guesses at one user's password, from any number of machines |
| per **IP** | one machine trying a few passwords on many accounts ("password spraying") |

## 2. Details that matter

- **Blocked means blocked:** during the window, even the **right** password gets 429. Otherwise the attacker learns the password the moment they hit it.
- `ConcurrentHashMap.compute` is atomic per key (38.07's lesson): parallel failures are all counted.
- The `Clock` is injected: a test can move time forward instead of waiting 15 minutes.
- Success resets the account's counter; the IP's counter decays with its window.

## 3. The trade-offs

| Risk | Mitigation |
|---|---|
| **lockout as a weapon**: an attacker locks a real user out on purpose | short windows (15 min), not permanent locks; notify the user; let admins unlock |
| shared IPs (offices, mobile carriers) hit the IP limit | a higher IP limit than the account limit (20 vs 5) |
| a cluster: each server counts separately | a shared store (Redis) or throttling at the proxy |
| memory growth from sprayed usernames | windows are dropped when they expire and are touched; a periodic cleanup for large sites |

## ✅ Recap

Count failures per account and per IP in a window; refuse **all** attempts while over the limit; keep windows short to limit lockout abuse.
