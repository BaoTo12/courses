# Lecture 41.16 · 🔓 Open Redirect via `returnUrl` (Conceptual)

> **Section:** S41 · **Type:** 🔓 Attack Lab (conceptual) · **Track:** ★ Core · **Time:** ~10 minutes

---

## 1. The flaw

A login that redirects to **any** `returnUrl` after success:

```java
response.sendRedirect(request.getParameter("returnUrl"));   // ❌
```

A link like `https://taskflow.example/taskflow/login?returnUrl=<another site>` starts on the **real** TaskFlow domain, shows the **real** login page, takes the user's **real** password, and then sends them somewhere else. That page can say "Session error, please log in again" and collect the password a second time. The trust comes from the first, legitimate domain in the link.

The same applies to every "go back to…" parameter: TaskFlow's theme switch `returnTo` (39.09) and any future "next" or "continue" parameter.

## 2. Forms the target can take

A fully qualified URL, a **protocol-relative** one (`//other.example`), backslash variants some browsers normalise (`/\other.example`), and encoded line breaks that aim at the `Location` header itself. Checking "does it contain `taskflow`?" misses most of these.

## Lesson

A redirect target from the request is user input. Accept only what your application recognises as its own.
