# Lecture 41.04 · Session Lifecycle: Creation, Timeout, `invalidate()`, Persistence Across Restarts

> **Section:** S41 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~15 minutes

---

| Event | How | TaskFlow |
|---|---|---|
| **created** | the first `request.getSession()` | the login page (CSRF token), or a flash |
| **used** | every request with its cookie updates `lastAccessedTime` | |
| **times out** | no request for `<session-timeout>` minutes: Tomcat's background thread expires it (checked about every minute) | 15 minutes (`web.xml`, 41.19) |
| **invalidated** | `session.invalidate()` | logout (41.08) |
| **id changed, data kept** | `request.changeSessionId()` | login (41.11) |
| **listeners** | `HttpSessionListener.sessionCreated/Destroyed` (38.07) | the active-sessions counter |

```xml
<session-config>
  <session-timeout>15</session-timeout>       <!-- minutes; 0 or less = never expires (don't) -->
  <cookie-config><http-only>true</http-only></cookie-config>
  <tracking-mode>COOKIE</tracking-mode>
</session-config>
```

Per session: `session.setMaxInactiveInterval(seconds)`.

## Persistence across restarts

Tomcat's default `StandardManager` **saves** all sessions to `work/…/SESSIONS.ser` at a clean shutdown and reloads them at startup, so users stay logged in across a restart. Consequences:
- every session attribute must be `Serializable` (`AuthUser` is, 41.07), or it's dropped with a warning;
- whatever is in the session ends up **on disk** (38.09);
- to disable it: `<Manager pathname=""/>` in `context.xml`.

In a cluster: sticky sessions, session replication, or a shared store (38.03).

## ✅ Recap

Created on demand, kept alive by requests, ended by timeout, `invalidate()`, or shutdown without persistence. What's inside may be serialised to disk.
