# Lecture 41.02 · How `HttpSession` Works: `JSESSIONID` → a Map in Tomcat's Memory

> **Section:** S41 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~20 minutes

---

## 1. The mechanism

```text
Browser                                     Tomcat
GET /taskflow/login                    ──►  request.getSession() → no session yet → create one:
                                            id = 32 random hex chars (a SecureRandom value)
                                            sessions.put(id, new StandardSession(...))
                                       ◄──  Set-Cookie: JSESSIONID=5F1C…; Path=/taskflow; HttpOnly; SameSite=Lax
POST /taskflow/login  Cookie: JSESSIONID=5F1C…  ──►  sessions.get("5F1C…") → the same HttpSession object
```

| The browser holds | Tomcat holds |
|---|---|
| **only the id**, in a cookie | the session **object** and all its attributes, in memory (`StandardManager`) |

Anyone who has the id **is** that session: that's why the cookie is `HttpOnly` (no script can read it), why it must travel over HTTPS in production (`Secure`, 41.12), and why the id changes at login (41.11).

## 2. `getSession()` vs `getSession(false)` (38.03)

| Call | No session yet | Use it when |
|---|---|---|
| `getSession()` / `getSession(true)` | **creates** one (+ `Set-Cookie`) | you're about to store something (login, CSRF token, flash) |
| `getSession(false)` | returns `null` | you only want to read (`CurrentUser.get`, `Csrf.isValid`, `Flash.consume`) |

Calling `getSession()` "just to check" in a filter on `/*` creates a session for every anonymous visitor, bot and CSS request: memory and cookies for nothing. TaskFlow's `AuthenticationFilter` reads with `getSession(false)`.

## 3. URL rewriting (the fallback)

If a browser refuses cookies, the Servlet API can put the id in URLs: `/taskflow/tasks;jsessionid=5F1C…` (`response.encodeURL`, `<c:url>` does it, 35.11). The id then leaks through `Referer` headers, logs, bookmarks and shared links. TaskFlow's `web.xml` sets `<tracking-mode>COOKIE</tracking-mode>` (28.04): no URL rewriting, ever.

## 4. How the server finds out a session is gone

`request.getRequestedSessionId()` is the id the browser **sent**; `request.isRequestedSessionIdValid()` says whether a live session has it. Sent but not valid = the session expired, or the server restarted without persistence. TaskFlow's filter uses exactly that to show "Your session has expired" (41.19).

## ✅ Recap

The browser has an id; the server has the data. Protect the id, create sessions only when you store something, and never put the id in URLs.
