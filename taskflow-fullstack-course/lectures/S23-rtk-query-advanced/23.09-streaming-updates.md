# Lecture 23.09 · Streaming Updates with `onCacheEntryAdded`

> **Section:** S23 · **Type:** 📖 Theory · **Track:** ＋ Extended · **Time:** ~20 minutes
> 🔗 Official companion reading: RTK Query docs, "Streaming Updates"; Redux Essentials **Part 8** ("Streaming cache updates")

*Extended track: outline. The code is an example outside TaskFlow; TaskFlow gets real-time updates in S47 (server-sent events from the servlet backend).*

---

**The idea.** A cache entry can own a **connection** for its whole lifetime. Open it when the entry is added (first subscriber), push messages into the entry, and close it when the entry is removed (last subscriber + `keepUnusedDataFor`).

```ts
getMessages: build.query<Message[], string>({
  query: (room) => `/rooms/${room}/messages`,              // the initial snapshot, via the base query
  async onCacheEntryAdded(room, { updateCachedData, cacheDataLoaded, cacheEntryRemoved }) {
    const source = new EventSource(`/api/rooms/${room}/stream`);
    try {
      await cacheDataLoaded;                                // wait for the snapshot before applying deltas
      source.onmessage = (event) => {
        const message = JSON.parse(event.data) as Message;  // validate it in real code (06.09)
        updateCachedData((draft) => { draft.push(message); });
      };
    } catch {
      // the entry was removed before the snapshot arrived: nothing to do
    }
    await cacheEntryRemoved;                                // resolves when the entry is garbage-collected
    source.close();
  },
}),
```

**Talking points**

- `onCacheEntryAdded` runs **once per cache entry**, not per request. `onQueryStarted` runs per request (23.04).
- The lifecycle promises are `cacheDataLoaded` (the first data is in; it rejects if the entry is removed first) and `cacheEntryRemoved`.
- `updateCachedData(recipe)` is `updateQueryData` bound to *this* entry.
- Deltas vs invalidation: push **small changes** into the cache (chat, counters, presence). For "something changed, go look", simpler is better: `dispatch(api.util.invalidateTags([{ type: 'Task', id }]))` from the message handler.
- Where it fits in TaskFlow: S47's `/api/events` stream. When another user edits a task, invalidate its id tag, and 23.01's tags do the rest.
- Security: an `EventSource`/WebSocket must be authenticated like any request (the session cookie, S38). After logout, `resetApiState()` removes the entries, `cacheEntryRemoved` resolves, and the connections close (23.10).
