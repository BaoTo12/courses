# Lecture 23.02 · `transformResponse` and `transformErrorResponse`: Adapting API Shapes

> **Section:** S23 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~30 minutes
> 🔗 Official companion reading: RTK Query docs, "Customizing Queries → Customizing query responses with `transformResponse`"; Redux Essentials **Part 8** ("Transforming responses")

---

## 1. Where they run

```text
baseQuery → { data } ──► transformResponse(data, meta, arg) ──► stored in the cache / returned by unwrap()
          → { error } ─► transformErrorResponse(error, meta, arg) ─► stored as `error` / thrown by unwrap()
```

They run **once per response**, before the cache sees it. So components, selectors and tag functions all see the transformed shape.

## 2. Typical uses

```ts
// 1. Unwrap an envelope: the API sends { data: [...], meta: {...} }; the app wants the array.
getInvoices: build.query<Invoice[], void>({
  query: () => '/invoices',
  transformResponse: (response: { data: Invoice[] }) => response.data,
}),

// 2. Convert types once: ISO strings → numbers for sorting (keep it serialisable: no Date objects in state).
getEvents: build.query<CalendarEvent[], void>({
  query: () => '/events',
  transformResponse: (events: ApiEvent[]) => events.map((e) => ({ ...e, startsAt: Date.parse(e.startsAt) })),
}),

// 3. A 204 with no body → a clean `undefined` (TaskFlow's deleteTask, 22.07).
transformResponse: () => undefined,

// 4. Error shape: pull the server's message out of a FetchBaseQueryError.
transformErrorResponse: (error) => ({ status: error.status, message: (error.data as { message?: string })?.message ?? 'Request failed' }),
```

## 3. Normalising with an entity adapter

For big lists that you look up by id, or that you patch often, you can store the response **normalised**:

```ts
const postsAdapter = createEntityAdapter<Post>();

getPosts: build.query<EntityState<Post, number>, void>({
  query: () => '/posts',
  transformResponse: (posts: Post[]) => postsAdapter.setAll(postsAdapter.getInitialState(), posts),
}),

// Reading: the adapter's selectors work on the cached data.
const { selectById } = postsAdapter.getSelectors();
const post = selectById(result.data ?? postsAdapter.getInitialState(), postId);

// Patching (23.04) uses the adapter's methods as mutating helpers:
api.util.updateQueryData('getPosts', undefined, (draft) => {
  postsAdapter.updateOne(draft, { id, changes: { liked: true } });
});
```

**TaskFlow doesn't do this.** Our list is a server **page** (`Page<Task>`: `items`, `totalItems`, …), and the order matters (server-side sorting, 23.07). `selectTaskEntities` (22.09) derives an id lookup where we need one. Normalise when you have many reads by id or frequent single-item patches **on a big collection**, not by default.

## 📇 API card: `transformResponse` / `transformErrorResponse`

| Option | Signature | Default |
|---|---|---|
| `transformResponse` | `(baseQueryReturnValue: unknown, meta, arg) => ResultType \| Promise<ResultType>` | identity |
| `transformErrorResponse` | `(baseQueryError, meta, arg) => ErrorType \| Promise<ErrorType>` | identity |

- `meta` is whatever the base query returned as `meta`. For `fetchBaseQuery`, that's `{ request, response }`, so you can read headers such as `X-Total-Count`.
- Type the **first parameter** to say what the server sends. The endpoint's `ResultType` says what you store.

**When to use:** the server's shape isn't the shape your UI wants, the same way everywhere.

**When not to:**
- One component wants a different view of the data → `selectFromResult` (23.03), or a selector. The cache stays the server's truth.
- Validation → TaskFlow does it in the base query (`validate`, 22.03). A guard inside `transformResponse` that throws gives a `SerializedError` instead of your error shape.

**Common mistakes:**
- Returning non-serialisable values (`Date`, `Map`, class instances). You get warnings, and DevTools can't show them.
- Heavy work per response on a hot endpoint. It runs on **every** refetch.
- Transforming with `providesTags` in mind and forgetting that `result` in tag functions is the **transformed** value.
