# Lecture 17.13 · 🎯 Your Turn: an "N Open" Header Badge and a "Clear Completed" Button; Prove the Badge Re-Renders Only When Needed

> **Section:** S17 · **Type:** 🎯 Your Turn · **Track:** ★ Core · **Time:** ~90 minutes

---

## 1. The task

### A. The badge

1. A component `OpenTasksBadge` in the header (next to the theme toggle) shows **"N open"**: tasks whose status isn't `DONE`.
2. It must re-render **only** when N changes: not on unrelated actions (sort preference, toasts), and not when a task changes in a way that keeps N the same (a title edit).
3. Announce changes politely to screen readers.

### B. "Clear completed"

4. On the list page, a **Clear completed (k)** button, shown only to logged-in users when k > 0.
5. It asks for confirmation, then deletes every DONE task **on the server** (the API has no bulk endpoint: one `DELETE` per task).
6. Then **one** event updates the store: `tasks/completedCleared` with the ids that were **actually** deleted (15.12). If some deletions fail, keep those tasks and tell the user how many failed.
7. Report the result in a toast.

### C. Prove it

8. Measure the badge's renders for: a sort-preference change, a toast, a title edit, marking a task DONE, and marking it back. Write the numbers down.
9. Change the badge's selector to `(state) => state.tasks.items.filter((t) => t.status !== 'DONE')` and use `.length` in the component. Measure again. What does the console say?

## 2. Hints

<details>
<summary>Hint 1: which selector?</summary>

Return a **number** (`selectOpenTaskCount`). A number is `===` to itself when unchanged, whatever happened to the array (17.04).
</details>

<details>
<summary>Hint 2: measuring renders</summary>

Temporarily add `console.count('OpenTasksBadge render')` to the component, then dispatch from the console. Vite serves your modules, so this works:

```js
const { store } = await import('/src/app/store.ts');
const { sortChanged } = await import('/src/features/listPrefs/listPrefsSlice.ts');
store.dispatch(sortChanged('title', 'desc'));
```

⚠️ Reload the page first if you edited any file since it loaded: after hot updates, Vite serves a fresh copy of `store.ts` (`store.ts?t=…`) to the page, and a console `import` gets a **different, empty store** (observed while writing S18).

Or use React DevTools → Profiler → "Highlight updates when components render". In development, StrictMode renders **twice** per real render.
</details>

<details>
<summary>Hint 3: several deletes, some may fail</summary>

`Promise.all` rejects on the **first** failure, and you'd lose the information about which ones succeeded. `Promise.allSettled` returns one result per promise, `{ status: 'fulfilled' | 'rejected' }`, in the same order as the input.
</details>

## 3. Acceptance checklist

- [ ] The header shows "N open"; N matches the list.
- [ ] Measured: **0** badge renders for the sort change, the toast and the title edit; renders only when N changes.
- [ ] The `filter` version re-renders on every unrelated action, and the console shows React-Redux's *"Selector unknown returned a different result…"* warning. Revert it afterwards.
- [ ] Clear completed deletes the DONE tasks on the server (reload: they're gone), shows a toast, and hides the button.
- [ ] `npm test`, `npx tsc -b`, `npm run lint` pass.
