# Lecture 17.11 · 🛠 Build: the Task Form Submits Through the Store

> **Section:** S17 · **Type:** 🛠 Build · **Track:** ★ Core · **Time:** ~25 minutes
> **Project feature:** creating and editing tasks ends with `tasks/taskAdded` / `tasks/taskUpdated` in the store
> Verified in the browser: creating "Created via Redux store" → `POST` 201 → `tasks/taskAdded` → `/tasks/26` showed the task, read from the store.

---

## 1. The flow

```text
TaskForm (local draft, validation, submit lock: S11)
   │ onSubmit(values)
   ▼
NewTaskPage.handleSubmit
   │ create(toCreateRequest(values))          ← useTaskOperations (17.07)
   ▼
POST /api/tasks  ──201──►  dispatch(taskAdded(createdTask))  ──►  tasksReducer adds it
   │
   ▼
toast "Created: …"  +  navigate(`/tasks/${created.id}`, { replace: true })  ← the details page selects it by id
```

`TaskForm` itself doesn't change at all: it still receives `onSubmit` and knows nothing about Redux. That's 17.08 in practice: the form's draft is local, and only the **result** enters the store.

## 2. ✍️ `src/pages/NewTaskPage.tsx`

```tsx
import { useNavigate } from 'react-router';
import { EMPTY_TASK_FORM, toCreateRequest } from '../domain/task-form';
import type { TaskFormValues } from '../domain/task-form';
import { toErrorMessage } from '../domain/guards';
import { useTaskOperations } from '../features/tasks/task-operations';
import { useToast } from '../toast/toast-context';
import { TaskForm } from '../components/TaskForm';

export function NewTaskPage() {
  const { create } = useTaskOperations();
  const { show } = useToast();
  const navigate = useNavigate();

  async function handleSubmit(values: TaskFormValues) {
    try {
      const created = await create(toCreateRequest(values)); // POST /api/tasks → 201
      show({ tone: 'success', message: `Created: ${created.title}` });
      // replace: the form page shouldn't stay in history (Back would re-open a submitted form)
      navigate(`/tasks/${created.id}`, { replace: true });
    } catch (error) {
      show({ tone: 'error', message: toErrorMessage(error) });
    }
  }

  return (
    <>
      <h1 className="page__title">New task</h1>
      <TaskForm mode="create" initialValues={EMPTY_TASK_FORM} onSubmit={handleSubmit} onCancel={() => navigate(-1)} />
    </>
  );
}
```

One line changed from 13.13: `useTaskOperations()` instead of `useTasksContext()`. `EditTaskPage` changes the same way (`update`), plus the selector from 17.07 §5 to find the task.

## 3. Why not dispatch `taskAdded` with the form values?

```ts
dispatch(taskAdded({ ...toCreateRequest(values), id: Date.now(), ownerId: 1, … })); // ❌
```

- The **server** assigns `id`, `ownerId`, `createdAt` and `updatedAt` (06.04), and may normalise fields (trimming). Only the response is the truth.
- If the POST fails, the store would contain a task that doesn't exist.
- `Date.now()` as an id would collide with the server's ids.

Adding a task to the UI **before** the server confirms is an **optimistic update**. It's a legitimate technique, but it needs a temporary id and a rollback on failure. RTK Query does it properly in 23.04.

## 4. Summary

- The form stays local and Redux-free; the page turns its result into an API call and an event.
- Dispatch what the **server** returned, not the form values.
