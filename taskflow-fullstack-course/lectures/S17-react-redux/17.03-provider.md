# Lecture 17.03 · React-Redux: `<Provider>`, and Why Its Context Doesn't Cause Re-Renders

> **Section:** S17 · **Type:** 📖 Theory + 🛠 Build · **Track:** ★ Core · **Time:** ~25 minutes
> 🔗 Official companion reading: Fundamentals Part 5 ("Passing the Store with Provider"); Essentials Part 2

---

## 1. Install

Stop the dev server (09.03), then:

```bash
npm install react-redux@9
```

At the time of writing this installs **react-redux 9.3.0**. It supports React 18 and 19 and ships its own TypeScript types.

## 2. ✍️ `src/main.tsx`: wrap the app

```tsx
import { StrictMode } from 'react';
import { createRoot } from 'react-dom/client';
import { BrowserRouter } from 'react-router';
import { Provider } from 'react-redux';
import '@styles/main.scss';
import { App } from './App';
import { ThemeProvider } from './theme/ThemeProvider';
import { ToastProvider } from './toast/ToastProvider';
import { AuthProvider } from './auth/AuthProvider';
import { store } from './app/store';

const rootElement = document.getElementById('root');
if (!rootElement) {
  throw new Error('#root element missing from index.html');
}

createRoot(rootElement).render(
  <StrictMode>
    {/* The Redux store, above everything else: any component can reach it (17.03) */}
    <Provider store={store}>
      {/* BASE_URL comes from Vite's `base` option: '/' in dev, '/<context>/app/' when deployed in S49 (12.12) */}
      <BrowserRouter basename={import.meta.env.BASE_URL}>
        <ThemeProvider>
          <ToastProvider>
            <AuthProvider>
              <App />
            </AuthProvider>
          </ToastProvider>
        </ThemeProvider>
      </BrowserRouter>
    </Provider>
  </StrictMode>,
);
```

`TasksProvider` is gone: the store replaces it (17.07). `Provider` goes **outermost** (inside `StrictMode`), so everything, including route components and the auth provider in S24, can use the store.

## 3. How the store reaches components

`Provider` puts the **store object** into a React context. `useSelector` and `useDispatch` read the store from that context. It's dependency injection, like 08.09's contexts.

### "Contexts re-render all consumers. Won't this re-render everything?"

No, and understanding why is the key to React-Redux:
- The context value is the **store**, a single object that **never changes** for the life of the app. A context only re-renders consumers when its **value** changes. It never does here.
- **State updates don't go through context at all.** Each `useSelector` call **subscribes** to the store directly (17.02's `useSyncExternalStore`). After a dispatch, each subscriber runs its selector and re-renders its component **only if the selected value changed**.

Compare with TaskFlow's old `TasksProvider` (12.02): its context value **was** the state. Every change produced a new value, and every consumer re-rendered: the list, the dashboard, and any component that only needed `reload`. 17.13 measures the difference.

## 4. Summary

- `<Provider store={store}>` at the root; install `react-redux@9`.
- The context carries the store (constant), not the state; updates arrive via per-component subscriptions.
- That's why React-Redux scales where a big state context doesn't.
