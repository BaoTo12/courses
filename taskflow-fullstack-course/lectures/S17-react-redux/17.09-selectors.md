# Lecture 17.09 · Extracting Selector Functions, Co-Located with the Slice

> **Section:** S17 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~20 minutes
> 🔗 Official companion reading: Essentials Part 4 ("Extracting Selectors"); the Redux docs page "Deriving Data with Selectors"

---

## 1. Inline selectors don't scale

```tsx
useAppSelector((state) => state.tasks.items.filter((t) => t.status !== 'DONE').length); // in the header
useAppSelector((state) => state.tasks.items.filter((t) => t.status !== 'DONE').length); // …and in the dashboard
```

The logic is duplicated, and every component knows the exact state shape. In S19, `state.tasks.items` becomes `state.tasks.ids` + `state.tasks.entities`. Every inline selector breaks.

## 2. Named selectors in the slice file

```ts
export const selectTasks = (state: RootState): Task[] => state.tasks.items;
export const selectTaskById = (state: RootState, id: number): Task | undefined =>
  state.tasks.items.find((task) => task.id === id);
export const selectOpenTaskCount = (state: RootState): number =>
  state.tasks.items.filter((task) => task.status !== 'DONE').length;
```

- **One place knows the shape.** When S19 normalises the state, only these functions change. The components keep calling `selectTaskById(state, id)`.
- **Co-located with the reducer** (the Style Guide's recommendation): the file that defines the state also defines how to read it.
- **Naming convention:** `selectX`. It's recognisable in components and in search results.
- **Explicit return types** document what each selector promises (and 17.04's `===` rule: `selectOpenTaskCount` returns a primitive).

## 3. Selectors with arguments

`selectTaskById(state, id)` needs a second argument. `useSelector` only passes `state`, so wrap it in an inline function:

```tsx
const task = useAppSelector((state) => selectTaskById(state, id));
```

The inline wrapper is recreated on every render, and that's fine. `useSelector` doesn't care about the selector's identity, only about its **result**.

## 4. Selectors are testable, reusable functions

A selector is `(state) → value`, so it runs outside React too: in thunks (`getState()`, S18), in middleware, and in tests:

```ts
expect(selectOpenTaskCount(store.getState())).toBe(17);
```

In S21, expensive selectors (filtering + sorting 500 tasks) become **memoised** with `createSelector`, which returns the same array reference until the inputs change: 17.04's problem, solved properly.

## 5. Summary

- Name selectors, and put them in the slice file.
- Components call selectors; only selectors know the state shape.
- Selectors with arguments: `(state) => selectX(state, arg)`.
