# Lecture 17.05 · `useDispatch`: Dispatching from Event Handlers

> **Section:** S17 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~15 minutes
> 🔗 Official companion reading: Fundamentals Part 5 ("Dispatching Actions with useDispatch")

---

## 1. The hook

```tsx
const dispatch = useAppDispatch();

<button onClick={() => dispatch(sortChanged('title', 'asc'))}>Sort by title</button>
```

`useDispatch()` returns the store's `dispatch`: the version wrapped by the middleware (16.09). The function is **stable**: the same reference on every render, for the life of the store. That's why it's safe in effect dependency lists (`[dispatch]` never triggers a re-run) and in `useMemo`/`useCallback` dependencies.

## 2. Where to dispatch

| Place | OK? | Notes |
|---|---|---|
| Event handlers | ✅ | The normal case: the user did something. |
| Effects | ✅ | "The component mounted, load data" (`AppLayout` loads the tasks). Remember the cleanup (13.09). |
| Async callbacks after `await` | ✅ | After an API call: `dispatch(taskUpdated(saved))`. |
| **During render** | ❌ | Render must be pure (07.04). Dispatching during render updates the store, which re-renders subscribers, possibly this component, and loops. React warns about updating another component while rendering. |

## 3. Dispatching the right thing

Components dispatch **events** (15.03): what happened, not how state should change. They don't compute the new state themselves:

```tsx
// ❌ the component does the reducer's job
dispatch({ type: 'ui/selectedTaskIdsSet', payload: selected.includes(id) ? selected.filter(…) : [...selected, id] });

// ✅ report the event; the reducer decides
dispatch(taskSelectionToggled(id));
```

## 4. TaskFlow's write operations

Most TaskFlow writes need the **server** first. For S17, `useTaskOperations()` (17.07) combines the API call and the dispatch:

```ts
patch: async (id: number, changes: UpdateTaskRequest) => {
  const saved = await patchTask(id, changes);
  dispatch(taskUpdated(saved));
  return saved;
},
```

Notice that this async logic lives in a **hook**, so only components can use it, and every page that writes must remember to use that hook. S18 moves it into **thunks**: functions you `dispatch` like actions, usable from anywhere.

## 5. Summary

- `useDispatch()` returns the store's (middleware-wrapped) `dispatch`; it's stable.
- Dispatch from handlers, effects and async callbacks; never during render.
- Dispatch events, and let reducers compute state.
