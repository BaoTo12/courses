# Lecture 06.02 · 🛠 Build: `findById`, `indexById`, and a Type-Safe `updateTaskField`

## 1. ✍️ `src/generic-utils.ts`

First, add a tiny shared interface to `domain.ts` (06.04 finalises the whole file):

```ts
export interface HasId {
  id: number;
}
```

Then:

```ts
import type { HasId } from './domain';

/** Find an entity by id in any list of things that have an id. */
export function findById<T extends HasId>(items: readonly T[], id: number): T | undefined {
  return items.find((item) => item.id === id);
}

/** Index a list by id: [{id:1,…}] → { 1: {id:1,…} } */
export function indexById<T extends HasId>(items: readonly T[]): Record<number, T> {
  const byId: Record<number, T> = {};
  for (const item of items) {
    byId[item.id] = item;
  }
  return byId;
}
```

`indexById` is a preview of **normalised Redux state** (S19): `{ ids: [1, 2], entities: { 1: …, 2: … } }`. Because it's generic, the same function will index tasks, categories and users.

With `noUncheckedIndexedAccess`, reading `indexById(cats)[1]` gives `Category | undefined`: the id might not be in the map. That's honest, and it's why selectors like `selectTaskById` return `T | undefined`.

## 2. ✍️ Fix `updateTaskField` (from 05.09)

The loose version accepted `('status', 42)`. Make it generic in the **key**:

```ts
export function updateTaskField<K extends keyof Task>(
  tasks: readonly Task[],
  id: number,
  field: K,
  value: Task[K],
): Task[] {
  return tasks.map((task) => (task.id === id ? { ...task, [field]: value } : task));
}
```

Now:

```ts
updateTaskField(tasks, 1, 'title', 'Write Q3 report');   // ✅ K = 'title', value: string
updateTaskField(tasks, 1, 'id', 'oops');
//                              ~~~~~~ error TS2345: Argument of type 'string' is not assignable to parameter of type 'number'.
updateTaskField(tasks, 1, 'status', 'BLOCKED');
//                                  ~~~~~~~~~ error TS2345: Argument of type '"BLOCKED"' is not assignable to parameter of type 'TaskStatus'.
```

### How TypeScript works it out

1. From `field: K` and the argument `'status'`, it infers `K = 'status'`.
2. `value: Task[K]` becomes `Task['status']` = `TaskStatus`.
3. `'BLOCKED'` isn't a `TaskStatus` → error.

This "infer a key, derive the value type" pattern appears constantly in typed code: form change handlers (S11), Redux Toolkit's typed payloads, and libraries like React Hook Form.

## 4. Summary

- `findById<T extends HasId>` and `indexById<T extends HasId>` work for every entity and keep precise types.
- `updateTaskField<K extends keyof Task>(…, field: K, value: Task[K])` ties each field to its value type.
