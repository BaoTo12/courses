# Lecture 06.14 · 🐞 Debug: a New Status Compiles, but the UI Shows `undefined`

> **Section:** S06 · **Type:** 🐞 Debug · **Track:** ★ Core · **Time:** ~15 minutes

---

## Symptom

The backend team adds `BLOCKED` to the Java `TaskStatus` enum. A frontend developer adds it to the union:

```ts
export type TaskStatus = 'TODO' | 'IN_PROGRESS' | 'DONE' | 'BLOCKED';
```

`npm run typecheck` passes, and the build ships. In production, blocked tasks show a badge reading **`undefined`** and a colourless stripe. The label code looks like this:

```ts
const STATUS_LABEL: { [status: string]: string } = {
  TODO: 'To do',
  IN_PROGRESS: 'In progress',
  DONE: 'Done',
};

export function statusLabel(status: TaskStatus): string {
  return STATUS_LABEL[status];
}
```

## Investigation checklist

1. What type does `STATUS_LABEL[status]` have? Why didn't the compiler complain about the missing key?
2. With `noUncheckedIndexedAccess` enabled, would anything change? What would the error be?
3. Which **two** techniques from S06 make a missing key a compile error?
4. What non-TypeScript place also needs updating for the new status?

## Explanation

- `{ [status: string]: string }` is an **index signature**: "any string key → string". The compiler has no idea which keys actually exist, so `STATUS_LABEL['BLOCKED']` type-checks as `string` (without `noUncheckedIndexedAccess`). At runtime it's `undefined`.
- **With `noUncheckedIndexedAccess`**, the lookup would be `string | undefined`, and returning it from a function declared `: string` fails: `Type 'string | undefined' is not assignable to type 'string'`. That's a hint, but it doesn't tell you *which* key is missing.

**Fix 1: `Record` over the union (the missing key becomes an error):**

```ts
const STATUS_LABEL: Record<TaskStatus, string> = {
  TODO: 'To do',
  IN_PROGRESS: 'In progress',
  DONE: 'Done',
};
// error TS2741: Property 'BLOCKED' is missing in type '{ TODO: string; IN_PROGRESS: string; DONE: string; }' but required in type 'Record<TaskStatus, string>'.
```

**Fix 2: exhaustive `switch` + `assertNever`** (06.06/06.13).

**Also update** the SCSS status map (03.07). No compiler checks that, so it belongs on the team's "adding an enum value" checklist.

## Lesson

A type is only as strong as its **weakest annotation**. `string`-keyed index signatures and `Record<string, …>` throw away the union. Whenever keys come from a known set, key the type by that set.
