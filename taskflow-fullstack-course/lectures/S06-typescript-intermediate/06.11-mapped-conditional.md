# Lecture 06.11 · Mapped and Conditional Types: Reading Library Types Without Panic

> **Section:** S06 · **Type:** 📖 Theory · **Track:** ＋ Extended · **Time:** ~25 minutes
> Goal: **read** these, not write complex ones. When you press F12 on a Redux Toolkit or React type, you should be able to follow it.

---

## 1. Mapped types: "for each key, produce a property"

```ts
type Flags<T> = { [K in keyof T]: boolean };
type TaskFlags = Flags<Pick<Task, 'title' | 'dueDate'>>;   // { title: boolean; dueDate: boolean }
```

`[K in keyof T]` iterates over the keys. Modifiers can add or remove `?` and `readonly`:

```ts
type MyPartial<T> = { [K in keyof T]?: T[K] };
type Mutable<T> = { -readonly [K in keyof T]: T[K] };   // remove readonly
type Concrete<T> = { [K in keyof T]-?: T[K] };          // remove ?
```

### Key remapping with `as` and template literal types

```ts
type Getters<T> = { [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K] };
type G = Getters<{ title: string }>;   // { getTitle: () => string }
```

Template literal types build string types from other string types, e.g. `` `tasks/${string}` `` matches any Redux action type in the tasks slice.

## 2. Conditional types: "if T is X, then A, else B"

```ts
type IsString<T> = T extends string ? 'yes' : 'no';
type A = IsString<'TODO'>;   // 'yes'
type B = IsString<42>;       // 'no'
```

### Distribution over unions

When `T` is a union, a conditional type is applied to **each member** and the results are unioned:

```ts
type NonNull<T> = T extends null | undefined ? never : T;
type C = NonNull<string | null>;   // (string → string) | (null → never) = string
```

That's how the built-in `NonNullable`, `Exclude` and `Extract` work.

### `infer`: pulling a type out

```ts
type ElementOf<T> = T extends readonly (infer E)[] ? E : never;
type E1 = ElementOf<Task[]>;               // Task

type MyAwaited<T> = T extends Promise<infer V> ? V : T;
type R = MyAwaited<Promise<Page<Task>>>;   // Page<Task>
```

`infer V` means "capture whatever type is in this position". `ReturnType` is written as `T extends (...args: any) => infer R ? R : any`.

## 3. Reading a real library type

When you hover over Redux Toolkit's `createAsyncThunk` in S20, you'll see something like:

```ts
createAsyncThunk<Returned, ThunkArg = void, ThunkApiConfig extends AsyncThunkConfig = {}>(…)
```

With this lecture's vocabulary: three **generic parameters**, two with **defaults**, one with a **constraint**. The return value's `.fulfilled` action has `payload: Returned`. That's all you need to use it correctly.

## 4. When to write these yourself

Rarely, in application code. Prefer simple interfaces and the built-in utility types. If a type needs a comment to explain it, consider whether a simpler design would do. Library authors need these tools; app developers mostly need to **read** them.

## 5. Summary

- Mapped types: `{ [K in keyof T]: … }` with `?`/`readonly` modifiers and `as` remapping.
- Conditional types: `T extends X ? A : B`, distributive over unions; `infer` captures types.
- Built-ins (`Partial`, `Exclude`, `ReturnType`, `Awaited`) are written with these features.
- Goal: read library types confidently; write simple types yourself.
