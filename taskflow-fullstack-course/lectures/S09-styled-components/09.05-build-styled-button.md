# Lecture 09.05 · 🛠 Build: a Typed `StyledButton` with Variants, Compared with the BEM `Button`

> **Section:** S09 · **Type:** 🛠 Build · **Track:** ★ Core · **Time:** ~30 minutes
> **Project feature:** `src/components/styled/StyledButton.tsx`, a learning comparison. TaskFlow keeps the BEM `Button` (shared with JSP) as its real button.

---

## 1. Why build a button you won't use everywhere?

Buttons are the classic styled-components example, and at work you'll likely meet codebases where **all** components are styled-components. Building the same component both ways teaches the trade-offs better than any table.

## 2. ✍️ `src/components/styled/StyledButton.tsx`

```tsx
import styled, { css } from 'styled-components';

type Variant = 'primary' | 'secondary' | 'danger';
type Size = 'md' | 'sm';

// Transient props ($-prefixed) are used for styling and NOT forwarded to the DOM.
interface StyledButtonProps {
  $variant?: Variant;
  $size?: Size;
}

const variantStyles = {
  primary: css`
    background: var(--color-primary);
    color: var(--color-on-primary);
    &:hover:not(:disabled) {
      background: var(--color-primary-hover);
    }
  `,
  secondary: css`
    background: var(--color-surface);
    color: var(--color-text);
    border-color: var(--color-border);
    &:hover:not(:disabled) {
      background: var(--color-surface-muted);
    }
  `,
  danger: css`
    background: var(--color-danger);
    color: var(--color-on-primary);
    &:hover:not(:disabled) {
      background: var(--color-danger-hover);
    }
  `,
} satisfies Record<Variant, ReturnType<typeof css>>;

/** A styled-components version of the design-system button, for comparison (09.05). */
export const StyledButton = styled.button.attrs({ type: 'button' })<StyledButtonProps>`
  display: inline-flex;
  align-items: center;
  gap: 8px;
  border: 1px solid transparent;
  border-radius: 6px;
  font-weight: 500;
  line-height: 1.25;
  cursor: pointer;
  transition: background-color 150ms ease;
  padding: ${({ $size = 'md' }) => ($size === 'sm' ? '4px 12px' : '8px 16px')};
  font-size: ${({ $size = 'md' }) => ($size === 'sm' ? '0.75rem' : '0.875rem')};

  ${({ $variant = 'secondary' }) => variantStyles[$variant]}

  &:focus-visible {
    outline: 2px solid var(--color-primary);
    outline-offset: 2px;
  }

  &:disabled {
    opacity: 0.5;
    cursor: not-allowed;
  }
`;
```

### Walkthrough

- **`var(--color-primary)` etc.**: the styled button reads the **same CSS custom properties** that `base/_root.scss` emits (03.13). The theme toggle from 08.10 already re-themes it. No ThemeProvider needed yet; S10 formalises this.
- **`css` helper** (09.07): builds reusable style fragments (with nesting and `&`). `variantStyles` is a **variant map**: one entry per variant, picked by `$variant`.
- **`satisfies Record<Variant, …>`** (06.05): forgetting the `danger` entry is a compile error; the map stays typed.
- **`.attrs({ type: 'button' })`** (09.08): sets a default attribute, so a `StyledButton` inside a form won't submit it accidentally (the same default the BEM `Button` applies).
- **Nesting and `&`** work like SCSS: `&:hover:not(:disabled)` compiles to `.hash:hover:not(:disabled)`.

Use it anywhere to compare: `<StyledButton $variant="primary" onClick={…}>Save</StyledButton>`.

## 3. Side-by-side comparison

| | BEM `Button` (07.06) | `StyledButton` |
|---|---|---|
| Where the CSS lives | `styles/components/_button.scss` (shared) | This file (React-only) |
| CSS generated | Build time | Runtime, per variant/size combination |
| Usable by JSP | ✅ `class="btn btn--primary"` | ❌ |
| Variant API | Typed props → class names | Typed transient props → CSS |
| Adding a continuous prop (e.g. exact width) | Needs inline style or a custom property | Natural interpolation |
| Bundle impact | 0 kB JS | Part of the ~14 kB (gzipped) styled-components runtime (shared by all styled components) |

**TaskFlow's conclusion:** shared, finite-variant components stay BEM. styled-components is for components with **dynamic or continuous** styling (priority bar, avatar, progress ring, tags, layout primitives), where it clearly wins.
