# Lecture 09.14 · 🐞 Debug: an Unknown Prop Is Sent Through to the DOM

> **Section:** S09 · **Type:** 🐞 Debug · **Track:** ★ Core · **Time:** ~15 minutes

---

## Symptom

A teammate writes a notice box:

```tsx
const Notice = styled.div<{ variant: 'info' | 'warning'; size: 'sm' | 'lg' }>`
  padding: ${(p) => (p.size === 'sm' ? '4px 8px' : '12px 16px')};
  background: ${(p) => (p.variant === 'info' ? '#e0e7ff' : '#fef3c7')};
`;

<Notice variant="warning" size="lg">Server maintenance at 22:00</Notice>
```

It looks right, but the console shows (actual message from styled-components 6.5):

```text
styled-components: it looks like an unknown prop "variant" is being sent through to the DOM,
which will likely trigger a React console error. …consider using transient props
(`$` prefix for automatic filtering.)
```

In the Elements panel the DOM shows `<div variant="warning" size="lg" class="sc-… …">`.

## Investigation checklist

1. Which props does styled-components v6 forward to a DOM element? (09.04)
2. Is `size` a valid attribute on a `<div>`? On an `<input>`? What would `size="lg"` do on an input?
3. What's the one-character fix?
4. When would `shouldForwardProp` be the better fix?

## Explanation

- styled-components **v6 forwards all props** to DOM elements (v5 used to filter unknown ones).
- `variant` and `size` land in the DOM as attributes. On a `div`, they're meaningless noise. But `size` **is** a real attribute of `<input>` and `<select>` (it controls visible width/rows). If this component were `styled.input`, `size="lg"` would be an **invalid value for a real attribute**.
- For non-string values (e.g. `$filled={true}` without the `$`), React itself also complains about unknown or non-boolean attributes.

**Fix:** transient props:

```tsx
const Notice = styled.div<{ $variant: 'info' | 'warning'; $size: 'sm' | 'lg' }>`
  padding: ${(p) => (p.$size === 'sm' ? '4px 8px' : '12px 16px')};
  background: ${(p) => (p.$variant === 'info' ? '#e0e7ff' : '#fef3c7')};
`;

<Notice $variant="warning" $size="lg">Server maintenance at 22:00</Notice>
```

**When `shouldForwardProp` is better:** when you wrap a **third-party** component whose prop names you can't change (09.08).

## What this trained

Checking what actually reached the **DOM** (Elements panel) instead of trusting the JSX. The same habit matters for XSS (S26): what ends up in the DOM is what counts.
