# Lecture 35.04 · `<c:out>`: Escaping by Default

## 📇 API card: `<c:out>`

```jsp
<c:out value="${expr}" [default="fallback"] [escapeXml="true|false"]/>
<c:out value="${expr}">fallback as body</c:out>
```

| Attribute | Type | Required | Default | Meaning |
|---|---|---|---|---|
| `value` | `Object` | ✅ | — | what to print (`toString()`) |
| `default` | `Object` | | `""` | printed when `value` is **`null`** (the body works too) |
| `escapeXml` | `boolean` | | **`true`** | replace the 5 special characters with entities |

What `escapeXml="true"` produces:

| Character | Written as |
|---|---|
| `<` | `&lt;` |
| `>` | `&gt;` |
| `&` | `&amp;` |
| `"` | `&#034;` |
| `'` | `&#039;` |

Minimal example outside TaskFlow:

```jsp
<p>Hello, <c:out value="${param.name}" default="stranger"/>!</p>
<%-- ?name=<b>Bo</b> → Hello, &lt;b&gt;Bo&lt;/b&gt;!      no name → Hello, stranger! --%>
```

**When to use:** any text that isn't a constant from your own code: user input, database content, request data. It's safe for HTML body **and** quoted attributes.
**When not to:**
- inside `<script>` or `style`: different context (35.17);
- a URL: `<c:url>`/`<c:param>` encode parameters (35.11); validate schemes (26.07);
- HTML you *mean* to render (rich text) → a sanitiser with an allow-list (the Java equivalent of 26.04's DOMPurify), never `escapeXml="false"` on user input.

**Common mistakes:**
- `escapeXml="false"` to "fix" `&amp;` showing up twice. The real bug is **double escaping** (the data was escaped before it was stored: 35.15).
- `default` for `""`: it's only used for `null`. An empty string prints nothing.
- Expecting `${x}` to escape because `<c:out>` does. Plain EL never escapes (34.18).

## 1. `&#034;` vs `&quot;`: both correct

S34's `Html.escape` wrote `"` as `&quot;`, and JSTL writes `&#034;`. Both are valid HTML, and the browser decodes them to the same `"`. When S35 switched the search box to `fn:escapeXml`, `S34ElTest` had to change from one to the other. Tests should check **safety** (no raw `"` in the attribute), not a specific entity spelling. (We assert exact strings to keep the tests readable.)

## 2. `<c:out>` vs `${fn:escapeXml(x)}` vs `${x}`

| | Escapes | Where it can be used |
|---|---|---|
| `<c:out value="${x}"/>` | ✅ | template text **and** inside HTML attribute values (it's a tag inside text) |
| `${fn:escapeXml(x)}` | ✅ | anywhere EL works, including tag attributes and places where a tag reads badly |
| `${x}` | ❌ | numbers, enums, dates, booleans from your own model; constants |

TaskFlow's rule: text from users or the request → `<c:out>` (or `fn:escapeXml` inside attributes). Model values that can't contain markup (`${task.id}`, `${task.status}`) → plain EL.

## ✅ Recap

`<c:out>` is JSP's safe default: it HTML-escapes 5 characters and has a `null` fallback. Use it for every piece of text that isn't yours.
