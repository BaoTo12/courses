## 1. The problem S34 left

S34's `list.jsp` still had a scriptlet, because EL can't loop (34.01), and it used `hidden` because EL can't skip a block. EL **reads** values. Something has to **control** the page: loop, choose, set, build URLs. That's what tags are for.

## 2. JSTL: the JSP Standard Tag Library

A standard set of tags (JSR-52, 2002; version **1.2** for JSP 2.1+, which is what Tomcat 9 uses):

| Library | Prefix (convention) | URI | For |
|---|---|---|---|
| **core** | `c` | `http://java.sun.com/jsp/jstl/core` | `c:out`, `c:if`, `c:choose`, `c:forEach`, `c:set`, `c:url`, `c:param`, … |
| **functions** | `fn` | `http://java.sun.com/jsp/jstl/functions` | `fn:length`, `fn:escapeXml`, `fn:contains`, … (EL functions) |
| fmt | `fmt` | `http://java.sun.com/jsp/jstl/fmt` | dates, numbers, message bundles (S44) |
| sql, xml | `sql`, `x` | … | DB queries and XML **in the view**: never in MVC (35.12) |

## 3. A tag is a Java object

`<c:out value="${details.task.title}"/>` in `view.jsp` became this method in the generated servlet:

```java
private boolean _jspx_meth_c_005fout_005f1(javax.servlet.jsp.PageContext _jspx_page_context) throws java.lang.Throwable {
  javax.servlet.jsp.JspWriter out = _jspx_page_context.getOut();

  org.apache.taglibs.standard.tag.rt.core.OutTag _jspx_th_c_005fout_005f1 = (…) _005fjspx_005ftagPool_…_c_005fout_…get(…);  // a POOLED instance

```

Read it as the **tag lifecycle** (the classic tag API, `javax.servlet.jsp.tagext.Tag`):

```text
get an instance (from a pool) → setPageContext → setParent → setXxx(attributes, EL already evaluated)
  → doStartTag()   → SKIP_BODY | EVAL_BODY_INCLUDE
  → [body… doAfterBody() → EVAL_BODY_AGAIN loops]      (that's how c:forEach repeats)
  → doEndTag()     → EVAL_PAGE | SKIP_PAGE
  → return to the pool
```

`OutTag.doStartTag()` evaluates, escapes, and writes to `out`. `IfTag` returns `SKIP_BODY` when the test is false. `ForEachTag` sets `var` in page scope and returns `EVAL_BODY_AGAIN` until the items run out: exactly the `pageContext.setAttribute("task", task)` bridge you wrote by hand in 34.21.

## 4. Why it exists

- **Well-formed:** `<c:forEach>…</c:forEach>` must close properly. A mismatch is reported **where it is**, not 40 lines later (33.18).
- **No Java in views:** a front-end developer can read and change a JSTL page.
- **Safe output by default:** `<c:out>` escapes (35.04). Scriptlets and plain EL don't.
- **Standard:** the same tags in every servlet container and every JSP project you'll meet.

## 5. Where JSTL comes from

Tomcat 9 does **not** include JSTL. It's a jar in your WAR (`javax.servlet:jstl:1.2`, `compile` scope, since 28.05). TaskFlow's tests find it on the classpath, and a deployed WAR has it in `WEB-INF/lib`. How the container finds the tags: 35.02.

## ✅ Recap

JSTL is a standard tag library: each tag is a Java class, and the generated servlet creates (pools), configures and calls it. EL computes the values it's given.
