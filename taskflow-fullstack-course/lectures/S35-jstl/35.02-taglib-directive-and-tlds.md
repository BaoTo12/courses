## 📇 API card: `<%@ taglib %>`

```jsp
<%@ taglib prefix="c"  uri="http://java.sun.com/jsp/jstl/core" %>
<%@ taglib prefix="fn" uri="http://java.sun.com/jsp/jstl/functions" %>
```

| Attribute | Required | Meaning |
|---|---|---|
| `prefix` | ✅ | the XML-style prefix used in this page: `<c:out>`. Your choice, but `c`/`fn`/`fmt` are universal. Reserved: `jsp`, `jspx`, `java`, `javax`, `servlet`, `sun`, `sunw` |
| `uri` | ✅ (or `tagdir`) | an **identifier** that's matched against the TLDs the container knows. It is **not downloaded** |
| `tagdir` | instead of `uri` | a folder of `.tag` files: `/WEB-INF/tags` (S39) |

Rules:
- It must appear **before** the first use of the prefix in the translation unit (page + static includes).
- The same prefix twice with the **same** URI is fine. TaskFlow's `header.jspf` and its pages both declare `c`, so the fragment doesn't depend on its includer. The same prefix with a **different** URI is a translation error.

## 1. The TLD: a tag library's manifest

A **Tag Library Descriptor** (`.tld`, XML) says which URI the library has, and which Java class implements each tag and function. From the JSTL jar's `META-INF/c.tld` (abridged):

```xml
<taglib …>
  <tlib-version>1.2</tlib-version>
  <short-name>c</short-name>
  <uri>http://java.sun.com/jsp/jstl/core</uri>
  <tag>
    <name>out</name>
    <tag-class>org.apache.taglibs.standard.tag.rt.core.OutTag</tag-class>
    <body-content>JSP</body-content>
    <attribute><name>value</name><required>true</required><rtexprvalue>true</rtexprvalue></attribute>
    <attribute><name>default</name><required>false</required><rtexprvalue>true</rtexprvalue></attribute>
    <attribute><name>escapeXml</name><required>false</required><rtexprvalue>true</rtexprvalue></attribute>
  </tag>
  …
</taglib>
```

`rtexprvalue=true` means "this attribute accepts `${…}`". That's the detail behind 35.20's "wrong URI" error.

## 2. How Tomcat maps a URI to a TLD

At deployment, Jasper's **TldScanner** builds a map `uri → TLD`:

1. `<jsp-config><taglib>` entries in `web.xml` (explicit mappings, rarely needed now);
2. `.tld` files under `WEB-INF/` (not `WEB-INF/classes` or `lib`);
3. `META-INF/**/*.tld` inside every jar in `WEB-INF/lib` **← JSTL is found here**;
4. (embedded/classpath setups, such as TaskFlow's tests) jars on the class path.

That's why the startup log says *"At least one JAR was scanned for TLDs yet contained no TLDs"*: it scans every jar. (Tomcat's `jarsToSkip` in `catalina.properties` speeds this up in production.)

If no TLD has your URI → *"The absolute uri … cannot be resolved"* (35.21).

## 3. Which URI for which stack

| Stack | Core URI |
|---|---|
| JSTL 1.1/1.2 on JSP 2.x (**Tomcat 9, TaskFlow**) | `http://java.sun.com/jsp/jstl/core` |
| JSTL 1.0 (JSP 1.2, 2002) | `http://java.sun.com/jstl/core`, no `/jsp/` (**wrong** for us: 35.20) |
| Jakarta Tags 3.0 (Jakarta EE 10, Tomcat 10.1+) | `jakarta.tags.core` |

## ✅ Recap

`taglib` binds a prefix to a URI. The container maps the URI to a TLD it found in the jars at deployment, and the TLD maps each tag name to a Java class.
