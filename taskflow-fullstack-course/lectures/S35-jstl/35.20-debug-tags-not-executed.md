# Lecture 35.20 · 🐞 Debug: `<c:forEach>` Does Nothing, or the Page Shows `${task.title}` Literally

> **Section:** S35 · **Type:** 🐞 Debug · **Track:** ★ Core · **Time:** ~20 minutes

---

## 1. Three symptoms, three causes

| What View Source shows | Cause |
|---|---|
| `<c:forEach items="…" var="task">` **as text in the HTML**, and one empty row | the page has **no `taglib` directive** for `c`: to Jasper, `<c:forEach>` is plain template text; the browser ignores the unknown tag and renders its body once, with `task` = `null` |
| `${task.title}` **literally** | **EL is ignored**: `isELIgnored="true"`, `<el-ignored>` in `jsp-config`, or a `web.xml` with the **2.3 DTD** (`<!DOCTYPE web-app PUBLIC "-//Sun Microsystems, Inc.//DTD Web Application 2.3//EN" …>`), where EL is off by default |
| a 500: *"According to TLD or attribute directive in tag file, attribute [items] does not accept any expressions"* | the **JSTL 1.0 URI**: `http://java.sun.com/jstl/core` (no `/jsp/`). That TLD declares `rtexprvalue=false` (JSTL 1.0 evaluated EL itself, before JSP 2.0 existed) |

## 2. The checklist

1. **View Source**, not the rendered page: are the tags there as text?
2. Does the page (or the fragment it includes **first**) have `<%@ taglib prefix="c" uri="http://java.sun.com/jsp/jstl/core" %>`? Is the prefix spelled the same as in the tags?
3. Is it the **`/jsp/jstl/core`** URI? For Tomcat 10.1+ it would be `jakarta.tags.core` (35.02 §3).
4. Does `${1 + 1}` print `2`? If not, EL is off: check the page directive, `jsp-config`, and the `web.xml` version (TaskFlow's is 4.0, 28.04).
5. Still wrong after a fix? A stale translation (33.04): touch the JSP or clear `work/`.

## 3. Why the missing taglib fails silently

JSP only treats `<prefix:name>` as an action if `prefix` is declared. Everything else is text to be copied into the response. The browser, a lenient HTML parser, ignores an unknown element and shows its content. Nobody reports an error. A test that renders the page and asserts on the rows (`S35JstlTest`) catches it immediately.

## ✅ Takeaway

Tags printed as text → a missing `taglib`. `${…}` printed literally → EL disabled. "Does not accept any expressions" → the old JSTL 1.0 URI.
