# Lecture 35.10 · `<c:set>` and `<c:remove>`: When Setting Variables in a View Is Fine vs a Smell

> **Section:** S35 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~15 minutes

---

## 📇 API card: `<c:set>`

```jsp
<c:set var="ctx" value="${pageContext.request.contextPath}"/>                 <%-- form 1: a scoped variable --%>
<c:set var="greeting" scope="request">Hello, <c:out value="${name}"/></c:set> <%-- form 2: the body is the value --%>
<c:set target="${task}" property="title" value="New title"/>                 <%-- form 3: a bean property / map entry --%>
```

| Attribute | Type | Meaning |
|---|---|---|
| `var` | `String` | name of the attribute to set |
| `value` | `Object` | the value (or use the body: rendered text, **not escaped** unless you escape inside) |
| `scope` | `page` (default) \| `request` \| `session` \| `application` | where `var` goes |
| `target` | `Object` (bean or `Map`) | with `property`: call `setProperty(value)` or `map.put(property, value)` |
| `property` | `String` | the property/key on `target` |

`value="${null}"` **removes** the attribute from that scope.

## 📇 API card: `<c:remove>`

```jsp
<c:remove var="flash" [scope="session"]/>
```

Without `scope`, it removes `var` from **every** scope. Always pass a scope.

## 1. Fine uses (presentation only)

| Use | Example |
|---|---|
| shorten a long expression used many times | `<c:set var="ctx" value="${pageContext.request.contextPath}"/>` |
| name a sub-object for readability | `<c:set var="owner" value="${details.owner}"/>` |
| build a URL once, use it twice | `<c:url var="statusUrl" …>` (35.11): the same idea, built in |
| pass a value into an included fragment | `<c:set var="pageTitle" value="Tasks" scope="request"/>` before `<jsp:include>` (S39 prefers tag attributes) |

## 2. Smells

| Smell | Why | Instead |
|---|---|---|
| `<c:set target="${task}" property="title" …/>` | the view **changes the model** | the controller/service changes data |
| `<c:set var="total" value="${total + item.price}"/>` in a loop | a computation in the view | the controller computes `total` |
| `scope="session"` or `"application"` from a view | a page render with side effects on other requests | a controller or filter decides what the session holds |
| a "flag" set at the top, tested at the bottom | hidden control flow | a model attribute with a clear name |

## ✅ Recap

`<c:set>` in page scope for display conveniences is fine. Anything that writes to the model, the session or the application from a view is a design smell.
