# Lecture 35.99 · ✅ Knowledge Check: JSTL

> **Section:** S35 · **Type:** ✅ Knowledge Check · **Track:** ★ Core · **Time:** ~20 minutes

---

**1. (Concept)** What does JSTL do that EL cannot, and vice versa?

<details><summary>Answer</summary>

JSTL **controls** the page: loops (`c:forEach`), conditional blocks (`c:if`, `c:choose`), variables (`c:set`), URLs (`c:url`/`c:param`), and escaped output by default (`c:out`). EL has no statements and never escapes (34.01, 34.18). EL **reads and computes values**: scoped attribute lookup, bean properties, map/list access, operators, `empty`. Tags can't do that on their own: their attributes are EL expressions (35.03).
</details>

**2. (Code reading)** `items` has 5 elements `A B C D E`. Output of:

```jsp
<c:forEach items="${items}" var="x" varStatus="s" begin="1" end="3">${s.index}/${s.count}:${x}${s.last ? '' : ', '}</c:forEach>
```

<details><summary>Answer</summary>

`1/1:B, 2/2:C, 3/3:D`. `begin`/`end` are **indexes** into `items` (0-based, `end` inclusive). `index` is the position in `items`, and `count` counts iterations from 1. `last` is true for the last iteration **of the loop** (index 3), not of the list (35.07).
</details>

**3. (Debugging)** `<c:if test="${task.status == DONE}">` never matches. Why?

<details><summary>Answer</summary>

`DONE` without quotes is an EL **identifier**: an attribute named `DONE`, found nowhere → `null`. An enum is never equal to `null`. Write `'DONE'`: the string is coerced to the enum (34.13). A misspelt `'DNOE'` would throw instead of silently being false (35.06).
</details>

**4. (Security)** Stored XSS vs reflected XSS: what's the difference, and why does TaskFlow store comment bodies raw?

<details><summary>Answer</summary>

Reflected: the payload is in a request (a crafted link), and only whoever sends that request is hit. Stored: it's saved, and runs for **everyone** who views the page, admins included (35.14). Bodies are stored raw because the right encoding depends on where they're printed (HTML, attribute, JSON, CSV…): validate shape on input, encode for the context on output (`<c:out>`), every time (35.15).
</details>

**5. (Security)** Why is `onclick="return confirm('<c:out value="${t}"/>')"` unsafe even though `<c:out>` escapes `'`?

<details><summary>Answer</summary>

The browser HTML-decodes attribute values **before** running an event handler as JavaScript: `&#039;` becomes `'` again, and the payload breaks out of the JS string. HTML escaping is the wrong encoding for a JavaScript context. Use a `data-` attribute (HTML context) and a static script that reads `dataset` (35.16, 35.17).
</details>

**6. (Design)** `<c:out value="${x}"/>` or just `${x}`: write your team rule and justify it.

<details><summary>Answer</summary>

One reasonable rule (TaskFlow's): **any text that could come from users, the request or the database** → `<c:out>` in the body, `fn:escapeXml` inside attributes. Plain `${x}` only for values that can't contain markup and come from your own model (ids, enums, numbers, booleans, dates), and for constants. Justification: plain EL never escapes, so escaping must be the visible default, and a reviewer can grep for bare `${…}` in text and check each one. A stricter alternative: `<c:out>` for everything, which is simpler to enforce and more verbose (35.04).
</details>

**7. (Implementation)** A paginated table shows "Showing 21–40 of 134". The controller gives `page` (1-based), `size`, `total`. Write it in EL.

<details><summary>Answer</summary>

```jsp
<c:if test="${total > 0}">
  Showing ${(page - 1) * size + 1}–${page * size > total ? total : page * size} of ${total}
</c:if>
```

For page 2, size 20, total 134: `21–40 of 134`; page 7: `121–134 of 134`. This is at the edge of what belongs in a view: a `Page` object with `getFirstItem()`/`getLastItem()` (computed and unit-tested in Java) would make it `Showing ${page.firstItem}–${page.lastItem} of ${page.total}`.
</details>

**8. (Debugging)** "The absolute uri: [http://java.sun.com/jsp/jstl/core] cannot be resolved": the directive is copied from a working project. Where do you look?

<details><summary>Answer</summary>

At the **jar**, not the page: is a JSTL implementation in `WEB-INF/lib`? Its Maven scope isn't `provided`, it's not only the API jar, it's `javax` (not Jakarta) for Tomcat 9, and it isn't in `jarsToSkip` (35.21).
</details>
