# Lecture 35.22 · 🐞 Debug: A Space Disappears After `<c:if>` (a Real One from This Course)

> **Section:** S35 · **Type:** 🐞 Debug · **Track:** ★ Core · **Time:** ~20 minutes
> This happened while building 35.19's solution. `S35JstlTest` caught it. Verified by comparing the generated servlet with `trimDirectiveWhitespaces` on and off.

---

## 1. Symptom

The author cell was written as:

```jsp
<td class="comment__author"><c:out value="${item.author.displayName}" default="Deleted user"/><c:if test="${item.author.admin}"> <span class="badge">Admin</span></c:if></td>
```

The test expected `Admin <span class="badge">Admin</span>`. The page had `Admin<span class="badge">Admin</span>`: the name and the badge were glued together.

## 2. Investigate: the generated servlet

In `view_jsp.java`, the body of that `<c:if>`:

```java
do {
  out.write("<span class=\"badge\">Admin</span>");          // ← no leading space
```

The same page, with `trimDirectiveWhitespaces="false"` (in the page **and** the `web.xml` property group, for the experiment):

```java
do {
  out.write(" <span class=\"badge\">Admin</span>");         // ← the space is back
```

So the space is removed **at translation** by TaskFlow's own S33 setting (33.10: `trimDirectiveWhitespaces`, which removes blank lines left by directives).

But the list page has `<c:if test="${task.isOverdue(today)}"> ⚠</c:if>`, and its generated code keeps the space:

```java
do {
  out.write(' ');
  out.write('⚠');
```

## 3. Cause (what we observed, and the likely mechanism)

- **Observed:** with trimming on, a space immediately followed by markup (`<span`) at the start of a tag body was removed, and a space followed by plain text (`⚠`) was kept.
- **Likely mechanism:** Jasper's parser splits template text at every `<` (it must check whether it's a JSP element). The body `" <span …>"` becomes two text pieces, `" "` and `"<span …>"`. The first is **whitespace-only**, and `trimDirectiveWhitespaces` drops whitespace-only template text next to JSP elements. `" ⚠"` stays in one piece that isn't whitespace-only, so it isn't touched.

The practical rule doesn't depend on the exact mechanism: **with `trimDirectiveWhitespaces`, don't rely on a lone space next to a tag.**

## 4. Fixes, and how to check

| Fix | Output | Note |
|---|---|---|
| `<c:if …>${' '}<span …>` | a space | an EL value, never trimmed. TaskFlow uses this |
| `&#32;<span …>` or `&nbsp;` | a space / a non-breaking space | entities aren't whitespace to Jasper |
| CSS: `.badge { margin-left: .25rem }` | no text space | the visual gap without a character; changes the `textContent` |
| turn off `trimDirectiveWhitespaces` | spaces kept | and blank lines come back everywhere (33.10) |

To check any suspicious spacing: open the generated servlet in `target/tomcat/work/…/org/apache/jsp/…` (33.03) and search for the `out.write` of that text.

## ✅ Takeaways

- A whitespace setting that "only affects directives" also affected whitespace-only text next to tags.
- The generated servlet is the ground truth for what the page will output. When the HTML surprises you, read it before guessing.
- Assert on exact output in tests: this was a one-character difference, found at build time.
