# Lecture 35.07 · `<c:forEach>`: `items`, `var`, `varStatus`, `begin`/`end`/`step`, Maps

> Verified: `S35JstlTest` (row numbers from `varStatus.count`; zebra rows; `${header}` and `${cookie}` iterated as maps on the debug page)

## 📇 API card: `<c:forEach>`

```jsp
<c:forEach items="${tasks}" var="task" varStatus="row" [begin="0"] [end="…"] [step="1"]>
  <td>${row.count}</td><td><c:out value="${task.title}"/></td>
</c:forEach>

<c:forEach begin="1" end="5" var="i">${i} </c:forEach>        <%-- a counting loop: 1 2 3 4 5 --%>
```

| Attribute | Type | Meaning |
|---|---|---|
| `items` | `Collection`, `Iterator`, `Enumeration`, `Map`, array, or a comma-separated `String` | what to iterate. `null` → **zero iterations**, no error |
| `var` | `String` | name of the current item, a **page-scope** attribute during the body (removed afterwards) |
| `varStatus` | `String` | name of a `LoopTagStatus` object (below) |
| `begin` | `int` | first **index** (0-based) of `items`, or the first number without `items` |
| `end` | `int` | last index, **inclusive** |
| `step` | `int` ≥ 1 | every n-th item |

### `LoopTagStatus` (the `varStatus` object)

| Property | Meaning | For the 1st of `items` |
|---|---|---|
| `index` | the index in the underlying collection | `0` (or `begin`) |
| `count` | 1-based count of **iterations** done | `1` |
| `first` / `last` | booleans | `true` / (only on the last) |
| `current` | the current item (same as `var`) | |
| `begin` / `end` / `step` | the attributes as given (or `null`) | |

Example: `items` has 5 elements, `begin="1" end="3"`: the body runs for indexes **1, 2, 3**; `index` = 1, 2, 3; `count` = 1, 2, 3; `first` is true at index 1, and `last` is true at index 3.

**When to use:** every loop in a view.
**When not to:** "loops" that compute something (a total, a filter). The controller computes; the view displays.

**Common mistakes:**
- `items="tasks"` (no `${}`) → iterates the **string** `"tasks"` (one item) instead of the list.
- Using `index` for human row numbers → starts at 0. Use `count`.
- Expecting `var` to exist after the loop: it's removed.
- A `Map` gives `Map.Entry` objects: `${entry.key}`, `${entry.value}`, not the values directly.

## 1. Maps

```jsp
<c:forEach items="${header}" var="h">
  <tr><td><c:out value="${h.key}"/></td><td><c:out value="${h.value}"/></td></tr>
</c:forEach>

<c:forEach items="${cookie}" var="entry">           <%-- Map<String, Cookie> --%>
  <tr><td><c:out value="${entry.key}"/></td><td><c:out value="${entry.value.value}"/></td></tr>
</c:forEach>
```

`entry.value.value`: the entry's value is a **`Cookie`**, and its `getValue()` is the text (34.14). The debug page (34.16) now lists every header and cookie this way, and `S35JstlTest` sends `tf_lang=vi; theme=dark` and finds both rows.

## 2. Zebra rows and row numbers

```jsp
<c:forEach items="${details.comments}" var="item" varStatus="row">
  <tr class="${row.count % 2 == 0 ? 'comment--even' : 'comment--odd'}">
    <td class="row-number">#${row.count}</td> …
```

## 3. What it does internally

`ForEachTag` is an **iteration tag**: `doStartTag()` sets `var` (and `varStatus`) in **page scope** and returns `EVAL_BODY_INCLUDE`. After each body, `doAfterBody()` advances and returns `EVAL_BODY_AGAIN`, until the items run out. That's the same `pageContext.setAttribute("task", task)` bridge as 34.21's scriptlet, written once, correctly, in a library.

## ✅ Recap

`items` + `var` loop over anything iterable (`null` = no iterations). `varStatus` gives `index`/`count`/`first`/`last`. Maps give entries (`key`/`value`).
