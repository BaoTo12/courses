# Lecture 35.21 · 🐞 Debug: "The absolute uri: [http://java.sun.com/jsp/jstl/core] cannot be resolved"

> **Section:** S35 · **Type:** 🐞 Debug · **Track:** ★ Core · **Time:** ~15 minutes

---

## 1. The error

A 500 on the first page that uses JSTL:

```text
org.apache.jasper.JasperException: The absolute uri: [http://java.sun.com/jsp/jstl/core] cannot be resolved
    in either web.xml or the jar files deployed with this application
```

## 2. What it means

The `taglib` directive is fine. Tomcat's TLD scanner (35.02 §2) found **no TLD with that URI**. In practice: **the JSTL jar isn't deployed**.

## 3. Checklist

| # | Check | Typical cause |
|---|---|---|
| 1 | `WEB-INF/lib/` inside the deployed app (or `jar tf target/taskflow.war \| grep jstl`) | no JSTL jar at all |
| 2 | `pom.xml` scope of `javax.servlet:jstl` | **`provided`**: copied from a GlassFish/WildFly project, where the server includes JSTL. **Tomcat doesn't**: it must be `compile` (28.05) |
| 3 | which jar | only the **API** jar (`javax.servlet.jsp.jstl-api`) without an **implementation** (`org.glassfish.web:javax.servlet.jsp.jstl`, or Apache `taglibs-standard-impl`). The TLDs live in the implementation |
| 4 | Jakarta vs javax | a JSTL **2.0/3.0** (Jakarta) jar on Tomcat 9: its TLD has a `jakarta.tags.core` URI and `jakarta.*` classes → wrong for `javax` Tomcat 9 |
| 5 | Tomcat's `jarsToSkip` (`catalina.properties`) | someone added `jstl*.jar` to the skip list to speed up startup |
| 6 | IDE deployments | the IDE's artifact doesn't include Maven dependencies ("exploded" artifact misconfigured) |

## 4. TaskFlow's setup

```xml
<dependency>
  <groupId>javax.servlet</groupId>
  <artifactId>jstl</artifactId>
  <version>1.2</version>          <!-- compile scope (the default): bundled into WEB-INF/lib -->
</dependency>
```

That one jar holds both the TLDs (`META-INF/c.tld`, `fn.tld`, …) and the tag classes (`org.apache.taglibs.standard…`). In the tests, the embedded Tomcat finds it on the class path.

## ✅ Takeaway

"Absolute uri cannot be resolved" is about the **jar**, not the directive. Tomcat doesn't ship JSTL: bundle an implementation that matches your namespace (`javax` for Tomcat 9).
