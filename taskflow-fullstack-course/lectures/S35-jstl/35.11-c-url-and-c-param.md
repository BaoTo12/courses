## 📇 API card: `<c:url>` and `<c:param>`

```jsp
<a href="<c:url value='/tasks/view?id=${task.id}'/>">…</a>                 <%-- inline --%>

<c:url var="statusUrl" value="/tasks">                                       <%-- into a variable --%>
  <c:param name="status" value="${status}"/>
  <c:param name="q" value="${param.q}"/>
</c:url>
<a href="${fn:escapeXml(statusUrl)}">…</a>
```

| `<c:url>` attribute | Meaning |
|---|---|
| `value` | the URL. Starting with `/` → **the context path is prepended** (`/taskflow/tasks`). Relative (`view?id=1`) or absolute (`https://…`) → left as is |
| `context` | another web app's context path (`/reports`) when `value` starts with `/` |
| `var`, `scope` | store the result instead of printing it (default scope `page`) |

| `<c:param>` attribute | Meaning |
|---|---|
| `name`, `value` | appended as `?name=value` / `&name=value`, **both URL-encoded** (with the response's character encoding, UTF-8 here) |

What `<c:url>` does, in order:
1. prepend the context path (for `/…`);
2. append each `<c:param>`, URL-encoded;
3. call `response.encodeURL(url)`: adds `;jsessionid=…` **if** the session is tracked by URL (cookies disabled). TaskFlow's `web.xml` allows only `COOKIE` tracking (28.04), so this never happens, which is good, because a session id in a URL leaks through `Referer` headers, logs and shared links (S41).

**When to use:** every internal link and form `action`.
**When not to:** external links (no context path, no session id): write them as they are, and validate them if they come from users (26.07).

**Common mistakes:**
- Building query strings by hand: `value="/tasks?q=${param.q}"` → no URL encoding. `&`, `#` and spaces break the URL, and `"` breaks the attribute.
- Forgetting that the result isn't **HTML**-escaped. Inside `href="…"`, the `&` between parameters should be `&amp;`: use `var` + `fn:escapeXml`, as TaskFlow does. (Browsers tolerate a bare `&` in most cases, but `&copy=…` has historically been read as `©`.)
- `<c:param>` values in the `value` attribute **and** as `?x=` in `value`: both are kept; you get duplicated parameters.

## 1. In TaskFlow

The status filter links keep the current search:

```jsp
<c:forEach items="${statuses}" var="status">
  <c:url var="statusUrl" value="/tasks">
    <c:param name="status" value="${status}"/>
    <c:if test="${not empty param.q}"><c:param name="q" value="${param.q}"/></c:if>
  </c:url>
  · <a class="${statusFilter == status ? 'is-active' : ''}" href="${fn:escapeXml(statusUrl)}">${status}</a>
</c:forEach>
```

`<c:param>` inside `<c:if>` inside `<c:url>` works: a `<c:param>` looks for its nearest `<c:url>` **ancestor**, not only its direct parent.

For a search `a&b"`: `q=a%26b%22` (URL-encoded by `<c:param>`), and the `&` before `q` becomes `&amp;` (HTML-escaped by `fn:escapeXml`).

## ✅ Recap

`<c:url>` = context path + encoded parameters + (optional) session id. Store it with `var`, and HTML-escape it when it goes into an attribute.
