## 1. The pattern: data in HTML, code in a static file

The delete form carries the title as data:

```jsp
<form method="post" action="<c:url value='/tasks/delete'/>" style="display:inline" data-confirm-title="${fn:escapeXml(task.title)}">
```

The script reads it:

✍️ `src/main/webapp/static/js/confirm-delete.js`

```js
// S35 (35.17): "Delete "<title>"?" before a delete form is submitted.
// The title comes from the form's data-confirm-title attribute, which the JSP wrote with fn:escapeXml:
// an HTML-attribute context, decoded by the browser into plain text here. No server data inside <script>.
document.addEventListener('submit', (event) => {
  const form = event.target;
  if (!(form instanceof HTMLFormElement) || !form.dataset.confirmTitle) return;
  if (!window.confirm(`Delete "${form.dataset.confirmTitle}"?`)) event.preventDefault();
});
```

…and the footer loads it once:

```jsp
<script src="<c:url value='/static/js/confirm-delete.js'/>" defer></script>
```

Why it's safe:
1. `data-confirm-title="…"` is a **quoted HTML attribute**, exactly the context `fn:escapeXml` is made for.
2. The browser decodes the entities when it builds the DOM. `form.dataset.confirmTitle` is the **original text**, as a string value, never parsed as code.
3. The JavaScript is a **static file**: no server data is ever glued into code. Nothing to escape, nothing to get wrong.
4. It's CSP-friendly: S42's `Content-Security-Policy: script-src 'self'` allows this file, and forbids every inline `onclick`/`<script>`, so 35.16's mistakes would be blocked even if written.

## 2. When a script needs a lot of data: JSON in a non-executable script block

```jsp
<script type="application/json" id="task-data">${taskJson}</script>
<script src="<c:url value='/static/js/task-page.js'/>" defer></script>
```

```js
const task = JSON.parse(document.getElementById('task-data').textContent);
```

- `type="application/json"` → the browser doesn't execute it.
- `taskJson` is produced by **Jackson in the controller** (S46), with `<`, `>` and `&` written as `<`, `>`, `&` so the text can never contain `</script>`. That's a JSON encoder configured for HTML embedding, not `fn:escapeXml` (entities aren't decoded inside `<script>`).
- S49 uses this pattern to pass initial data to a React island inside a JSP.

## 3. The checklist (extends 34.19's)

| Do | Don't |
|---|---|
| quote every attribute: `value="${fn:escapeXml(x)}"` | `value=${x}` |
| pass data in `data-*` attributes, read with `dataset` | `onclick="…${x}…"` |
| JSON in `<script type="application/json">`, HTML-safe encoded | `<script>var x = '${x}'</script>` |
| static `.js` files | inline event handlers and inline scripts |
| `<c:url>`/`<c:param>` for links; validate URL schemes | `href="${userUrl}"` |
