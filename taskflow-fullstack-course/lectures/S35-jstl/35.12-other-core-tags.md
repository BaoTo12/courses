# Lecture 35.12 · `<c:redirect>`, `<c:import>`, `<c:catch>`, `<c:forTokens>`: Why Most Are Rarely Appropriate in MVC Views

> **Section:** S35 · **Type:** 📖 Theory · **Track:** ＋ Extended · **Time:** ~10 minutes

*Extended track: outline.*

---

```jsp
<c:redirect url="/login"/>                                      <%-- response.sendRedirect(ctx + "/login") --%>
<c:import url="https://example.com/banner.html" var="banner"/>   <%-- fetch a URL (even external) into a variable --%>
<c:catch var="err"> ${task.titel} </c:catch>                     <%-- swallow any Throwable from the body --%>
<c:forTokens items="a,b;c" delims=",;" var="t">${t} </c:forTokens> <%-- split a string: a b c --%>
```

- **`<c:redirect>`:** a redirect is a **controller decision** (status, `Location`), and by the time a view runs, the response may already be committed (30.18) → `IllegalStateException`. Do it in the servlet (or a filter, S42).
- **`<c:import>`:** like `<jsp:include>`, but it can fetch **any URL**, external ones included, during rendering. It's slow, can fail, and becomes a **server-side request forgery** hole if the URL comes from input. Use `<jsp:include>` for your own fragments (S39).
- **`<c:catch>`:** hides exceptions (and so bugs) from logs and error pages (S43). Legitimate only around optional, known-flaky output, with the error logged.
- **`<c:forTokens>`:** splitting strings is data preparation → the controller gives the view a `List`.
- Also in the core library: `<c:when>`/`<c:otherwise>` (35.06) and `<c:param>` (35.11). The **sql** and **xml** libraries run queries and XML transforms in the view: never in MVC.
