# Lecture 35.16 · 🔓 Lab: XSS in Attribute and JavaScript Contexts

> **Section:** S35 · **Type:** 🔓 Attack Lab · **Track:** ★ Core · **Time:** ~30 minutes
> ⚠️ Local only, in a lab branch.

---

Output encoding must match the **context** (34.19). Here are three places where a developer who "knows about `<c:out>`" still gets it wrong.

## 1. An unquoted attribute

```jsp
<input name="q" value=<c:out value="${param.q}"/>>
```

`<c:out>` escapes `< > & " '`, but an **unquoted** attribute value ends at a **space**:

```text
?q=x onfocus=alert(1) autofocus
→ <input name="q" value=x onfocus=alert(1) autofocus>
```

No escaped character was needed: the payload adds new attributes. **Always quote attributes.**

## 2. Data inside `<script>`

A developer wants the delete button to confirm with the task's title:

```jsp
<button onclick="return confirm('Delete <c:out value="${task.title}"/>?')">Delete</button>
```

or:

```jsp
<script>
  const title = '<c:out value="${task.title}"/>';
</script>
```

- In `onclick="…"`, the browser first **HTML-decodes** the attribute, then runs it as JavaScript. `&#039;` turns back into `'` **before** the JS parser sees it. A title `'); alert(1); ('` → `confirm('Delete '); alert(1); ('?')`. **HTML-escaping doesn't protect JavaScript in event-handler attributes.**
- In `<script>`, entities aren't decoded, so the quote is safe. A backslash isn't: 34.19 §3 showed how `\` swallows a quote when two values share a line. And a future edit that uses `${task.title}` without `<c:out>` gives `</script><script>…` a way out.

## 3. A `data-` attribute with a number that isn't one

```jsp
<tr data-user-id=${param.userId}>
```

"It's just an id" → unquoted, unescaped, from the request: `?userId=1 onmouseover=alert(1)`.

## 4. Why these happen

Each example uses **one** encoding for a place that needs another, or none at all:

| Context | Needs |
|---|---|
| quoted HTML attribute | HTML-escape ✅ (`<c:out>`, `fn:escapeXml`) |
| unquoted attribute | quoting it first |
| event-handler attribute (`onclick`) | JavaScript escaping **and then** HTML escaping; in practice: **don't** |
| `<script>` block | JavaScript/JSON escaping; in practice: **don't** |

## 5. Fix

35.17: quote every attribute, and don't generate JavaScript: pass data through escaped `data-` attributes (or a JSON block) and keep the JS static.
