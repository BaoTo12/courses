# Lecture 41.09 · 🛠 Build: `AuthenticationFilter`: a Public-Path Allow-List, Everything Else Needs a User

> **Section:** S41 · **Type:** 🛠 Build · **Track:** ★ Core · **Time:** ~40 minutes
> **Project feature:** the whole Admin Portal requires login, except a short list of public paths.
> Verified: `S41AuthenticationTest.anonymousRequestsAreSentToTheLoginPageWithTheirReturnUrl`, and all older tests (logged in by the harness)

---

## 1. The filter

✍️ `src/main/java/com/taskflow/web/filters/AuthenticationFilter.java`

{{file:@reference/taskflow/backend/src/main/java/com/taskflow/web/filters/AuthenticationFilter.java:java}}

| Design choice | Why |
|---|---|
| **deny by default**, allow-list public paths | a servlet added tomorrow is protected on day one (the same reasoning as 40.13) |
| `getServletPath()` for the check | not `getRequestURI().contains(…)`, which a query string can fool (40.18) |
| `/static/*` public | the login page needs its CSS (40.18) |
| `/debug/*` public | those pages answer only loopback requests anyway (30.10) |
| `CurrentUser.get` uses `getSession(false)` | anonymous requests don't create sessions (41.02) |
| `request.setAttribute("currentUser", user)` | views are `session="false"`: they read the request attribute (34.25) |
| `Csrf.prepare` for every logged-in page | every page's nav has POST forms now (logout, theme); the controllers' own `prepare` calls are removed |
| `Cache-Control: no-store` | 41.22 |
| `returnUrl` only for GET | returning to a POST URL makes no sense after login |

## 2. Its place in the chain

✍️ in `web.xml`, between maintenance and CSRF (40.14):

```xml
<filter>
  <filter-name>authentication</filter-name>
  <filter-class>com.taskflow.web.filters.AuthenticationFilter</filter-class>
</filter>
…
<filter-mapping><filter-name>authentication</filter-name><url-pattern>/*</url-pattern></filter-mapping>
<filter-mapping><filter-name>csrf</filter-name><url-pattern>/*</url-pattern></filter-mapping>
```

Before CSRF: an anonymous POST (a form submitted after the session expired) is sent to the login page, rather than answered with a confusing 403.

The maintenance filter now lets **admins** through (40.15's promise): it reads `CurrentUser.get(request)` itself, since it runs first.

## 3. The tests had to log in

`TomcatTest` now logs in as alice right after starting Tomcat, and offers `loggedInClient(user, password)` for a second browser (S38's "other user" tests use bob and admin). Every earlier test then passed unchanged, which shows that authentication was added **around** the application, not inside it.

## ✅ Checkpoint

`mvn package` → green. In a private window, any TaskFlow URL sends you to the login page, and after login you land where you wanted to go.
