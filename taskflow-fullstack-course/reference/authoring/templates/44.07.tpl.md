## 1. The filter

✍️ `src/main/java/com/taskflow/web/filters/LocaleFilter.java`

{{file:@reference/taskflow/backend/src/main/java/com/taskflow/web/filters/LocaleFilter.java:java}}

| Decision | Why |
|---|---|
| cookie → `Accept-Language` → `en` | the same order as the React app's i18next detector (25.05): an explicit choice beats the browser's default |
| allow-list `en`, `vi` | the cookie is input; `tf_lang=fr` or `tf_lang=<script>` is ignored |
| `Accept-Language` only if the header **exists** | without it, `request.getLocales()` returns the **server's** default locale: a Vietnamese server would answer a curl request in Vietnamese |
| `Config.set(request, Config.FMT_LOCALE, locale)` | where every `fmt` tag (and our custom tags) look first in request scope |
| `lang` attribute | `<html lang="${lang}">` in `header.jspf`: screen readers pronounce the page correctly |

## 📇 API card: `javax.servlet.jsp.jstl.core.Config`

| Member | Meaning |
|---|---|
| `Config.set(request \| session \| context \| pageContext, name, value)` | set a JSTL configuration variable in that scope |
| `Config.find(pageContext, name)` | look it up: page → request → session → application → context init param |
| `FMT_LOCALE` (`javax.servlet.jsp.jstl.fmt.locale`) | the formatting and message locale |
| `FMT_LOCALIZATION_CONTEXT`, `FMT_FALLBACK_LOCALE`, `FMT_TIME_ZONE` | the bundle, the fallback locale, the time zone |

`Config.set(request, …)` stores the attribute `javax.servlet.jsp.jstl.fmt.locale.request`: scoped names get a suffix per scope.

## 2. Its place in the chain

```xml
<filter-mapping><filter-name>errors</filter-name><url-pattern>/*</url-pattern></filter-mapping>
<filter-mapping><filter-name>locale</filter-name><url-pattern>/*</url-pattern></filter-mapping>
```

Early: every page after it, including the maintenance page (503), the login page and the error pages (the ERROR dispatch reuses the request, whose attribute is already set: 43.03), renders in the right language.

## ✅ Checkpoint

`curl -H "Accept-Language: vi" …` (or the browser's language settings) → `<html lang="vi">` and Vietnamese labels. Set the cookie to `en` and the header loses.
