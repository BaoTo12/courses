## 2. The filter

- `init` runs once, at deployment: it reads the context parameter and **publishes** the state object for the switch.
- `getServletPath()` is safe here: on a `REQUEST` dispatch it's the path the user asked for (39.08 was about **forwards**).
- `setStatus(503)` + `Retry-After`, then a **forward** to the page. `setStatus` (not `sendError`), because we render our own body.

## 4. Its place in the chain (`web.xml`)

After `securityHeaders` (the 503 needs the headers, which the test checks) and `logging` (the 503 is logged), before authentication and CSRF (nothing else should run). The `context-param` sits next to the others.

### Wrong approaches

| Attempt | Problem |
|---|---|
| a `static boolean` in the filter class | not per application; survives redeploys in odd ways; can't be set from a servlet cleanly |
| a plain (non-volatile) `boolean` | a switched state may not be seen by other threads right away |
| exempting nothing | the maintenance page has no CSS, and nobody can switch it off without a restart |
| `response.sendError(503)` | the container's error page instead of ours (S43 lets you customise that) |
| checking `request.getRequestURI().contains("/static/")` | `/taskflow/tasks?x=/static/` would pass; use the servlet path |
