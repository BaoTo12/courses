## 2. Where the database comes from

| Running… | Database |
|---|---|
| `mvn package` (tests) | `TestDatabase` starts one `mysql:8.4` container and runs `db/01–04` in it, exactly like docker-compose. **Docker must be running.** |
| `docker compose up -d` | the `mysql` service; Tomcat receives `TASKFLOW_DB_URL`, `TASKFLOW_DB_USER`, `TASKFLOW_DB_PASSWORD` (28.09) |
| an IDE | the defaults: MySQL on `localhost:3306`, user `taskflow_app` |

This is also the first time S28's scripts ran for real in this course: the charset, the seed and the grants (36.10) are now checked on every build.

## 3. What you use: `TaskService`

📦 `src/main/java/com/taskflow/service/TaskService.java`

{{file:@reference/taskflow/backend/src/main/java/com/taskflow/service/TaskService.java:java}}

| Method | Controller use |
|---|---|
| `find(TaskFilter)` | the list (status, search text, category, sort) |
| `countByStatus()` · `categories()` · `today()` | the list's stats box, category options, overdue checks |
| `details(id)` | the details page: `Optional.empty()` → 404 |
| `create(task)` · `toggle(id)` · `delete(id)` · `latestId()` · `addComment(…)` | the write actions; `false`/empty → 404 |

Notice what it *isn't*: no `HttpServletRequest`, no status codes, no JSP names. The controller turns its results into HTTP (404, redirect, view).
