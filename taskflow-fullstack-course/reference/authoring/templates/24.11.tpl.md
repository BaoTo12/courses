# Lecture 24.11 · 🛠 Build: The CSRF Header on Every Unsafe Request

> **Section:** S24 · **Type:** 🛠 Build · **Track:** ★ Core · **Time:** ~35 minutes
> **Project feature:** POST, PUT, PATCH and DELETE carry `X-XSRF-TOKEN` from the `XSRF-TOKEN` cookie. If there's no token yet, one is fetched first.
> Verified: `src/api/cookies.test.ts` ("CSRF header": only unsafe methods get it; with no cookie, `GET /auth/csrf` runs first; jsdom), `tsc`, lint.

## 1. From here on, run the mock in secure mode

```bash
cd provided/mock-api
node server.mjs --secure
```

The start-up line says `secure mode: ON`. Every `/api` call now needs a session, and every write needs the CSRF header. Before this lecture's code, try adding a task: **403 `CSRF_TOKEN_INVALID`**.

## 2. The interceptor

✍️ `src/api/client.ts` (the full file)

{{file:api/client.ts:ts}}

Walk through the new block:

- **`UNSAFE_METHODS`**: writes only (24.10 §4). Axios's `config.method` is lower-case after merging, but the code lower-cases anyway.
- **`readCsrfToken()`** comes from `cookies.ts` (24.05), which stays the only module that touches cookies.
- **No token yet** (a fresh browser, or cookies cleared): the interceptor **awaits** `GET /auth/csrf`. Request interceptors may be `async`, and Axios waits for them. It's a GET, so the interceptor doesn't recurse. The response's `Set-Cookie` stores the token, and we read it back from the cookie jar, never from the response body.
- **`typeof document !== 'undefined'`**: in Node (tests, and SSR in other apps) there's no cookie jar, so there's nothing to fetch.
- **Token rotation is automatic.** After login, the server sets a new `XSRF-TOKEN`, and the next write reads the new value, because we read the cookie **per request** and never cache it in a variable.

## 3. Watch it work

Network tab, secure mode, fresh browser:

```text
GET  /api/auth/me       401          (anonymous: fine, 24.12)
GET  /api/auth/csrf     204  Set-Cookie: XSRF-TOKEN=…
POST /api/auth/login    200  request header X-XSRF-TOKEN: … (same value as the cookie)
```
