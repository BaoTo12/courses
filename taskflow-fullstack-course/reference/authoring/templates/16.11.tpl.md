# Lecture 16.11 · 🛠 Redux DevTools: the Extension Enhancer, and TaskFlow's `store.ts`

> ℹ️ As in 14.11, the extension's UI can't be verified in the course's automated browser; the wiring below is verified by `tsc` and the tests (the store runs in Node, where `window` doesn't exist).

## 1. Middleware and DevTools together

In 14.10 the DevTools extension was the store's only enhancer. Now TaskFlow has two: `applyMiddleware(…)` and the DevTools. `createStore` accepts **one** enhancer, so they must be composed. The extension provides its own `compose` for this, `window.__REDUX_DEVTOOLS_EXTENSION_COMPOSE__`, which composes like Redux's **and** connects the extension:

```ts
const composeEnhancers = window.__REDUX_DEVTOOLS_EXTENSION_COMPOSE__ ?? compose;
const store = createStore(rootReducer, composeEnhancers(applyMiddleware(...middleware)));
```

With the extension's compose, the DevTools see actions **after** the middleware chain has processed them (a transformed action appears in its transformed form).

### Design decisions

- **`declare global { interface Window { … } }`**: declaration merging (06.10) to type the global the extension injects. Optional (`?`), because most users don't have the extension.
- **DevTools only in development** (`import.meta.env.DEV`): the 14.11 §5 discussion, decided. Production users can't inspect or dispatch through the extension.
- **`typeof window !== 'undefined'`**: the store module also runs in **Vitest under Node**, where `window` doesn't exist. Without this guard, importing `store.ts` in a test crashes with *"window is not defined"*.
- **A `makeStore()` factory** plus a `store` singleton. The app uses the singleton; tests call `makeStore(preloadedState)` for a fresh, isolated store each time. (Module-level singletons shared between tests leak state from one test to the next.)
- **`preloadedState?: Partial<RootState>`**: each slice not provided starts from its initial state (combineReducers' behaviour).
- **Middleware order:** crash reporter first (it wraps everything), logger in development only, analytics last. You'll write the crash reporter and analytics middleware in 16.12; until then, keep only the logger.
- **`AppStore` and `AppDispatch` types** are derived from the factory. React-Redux's typed hooks use them in S17.

## 3. Use the DevTools with the real store

The store isn't connected to React until S17. To see it in the DevTools now, temporarily import it in `main.tsx`, and dispatch from the console:

```ts
// main.tsx (temporary)
import { store } from './app/store';
Object.assign(window, { store });
```

```js
store.dispatch({ type: 'listPrefs/sortChanged', payload: { key: 'title', direction: 'desc' } });
```

In the extension: the action appears in the list; the **Diff** tab shows only `listPrefs.sort` changing; with `trace` enabled, the **Trace** tab shows the console as the origin. The console also shows the logger's `[redux] listPrefs/sortChanged` (enable the "Verbose" level to see `console.debug`). Remove the two lines afterwards.

## 4. Summary

- Several enhancers → compose them. The extension's compose also connects the DevTools.
- TaskFlow's store: a `makeStore()` factory, DevTools in development only, safe to import in Node tests.
- `AppStore`/`AppDispatch` types derive from the factory.
