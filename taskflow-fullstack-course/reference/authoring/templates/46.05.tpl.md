## 2. The request body: `TaskInput`

✍️ `src/main/java/com/taskflow/web/api/TaskInput.java`

{{file:@reference/taskflow/backend/src/main/java/com/taskflow/web/api/TaskInput.java:java}}

| Case | Body | Result |
|---|---|---|
| POST | `{}` | errors for `title`, `status`, `priority` |
| PATCH | `{}` | no errors, nothing changes |
| PATCH | `{"dueDate": null}` | the due date is **cleared** |
| PUT | without `description` | description becomes `""` (a PUT replaces the whole representation) |
| any | `"dueDate": "2026-02-30"` | `must be null or YYYY-MM-DD` (parsed, not just pattern-matched) |

## 3. The servlet

✍️ `src/main/java/com/taskflow/web/api/TaskApiServlet.java`

{{file:@reference/taskflow/backend/src/main/java/com/taskflow/web/api/TaskApiServlet.java:java}}

| Detail | Why |
|---|---|
| `task.setOwnerId(user.getId())` | the owner comes from the session (42.08) |
| `DuplicateKeyException` → `fieldErrors.title` | the database's `UNIQUE (owner_id, title)` is the source of truth; the message is the one React's form already shows (19.09) |
| re-read after update | `updated_at` is set by MySQL (`ON UPDATE CURRENT_TIMESTAMP`) |
| 204 with **no** body | `setStatus(204)` and nothing written |
| `sort=priority,asc` → `TaskSort.PRIORITY` descending | the HTML list ranks HIGH first; the API contract's ascending is LOW → HIGH |
