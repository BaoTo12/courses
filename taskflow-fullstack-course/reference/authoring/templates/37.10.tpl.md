# Lecture 37.10 · 🛠 Build: Edit (`/tasks/edit?id=`) and Delete (POST with a Confirm)

> **Section:** S37 · **Type:** 🛠 Build · **Track:** ★ Core · **Time:** ~45 minutes
> **Project feature:** an Edit button and a Delete button on the details page; delete asks for confirmation.
> Verified: `S37FormsTest.editIsPrefilledAndSavesOnlyTheFormFields`, `.deleteIsAPostWithAFlashAndA303`

---

## 1. Edit

✍️ `src/main/java/com/taskflow/web/tasks/TaskEditServlet.java`

{{file:@reference/taskflow/backend/src/main/java/com/taskflow/web/tasks/TaskEditServlet.java:java}}

- **GET** loads the stored task and pre-fills the form with `TaskForm.of(task)`. The page is the same `form.jsp`, with `taskId` set.
- **POST** starts again from the **stored** task (loaded by id), and `form.applyTo` changes only the five form fields. The id comes from a hidden field, so it's re-validated: it must be a positive number of an existing task.
- A task deleted by someone else between GET and POST → 404, not a crash.

## 2. Delete from the details page

In `view.jsp`, next to Edit:

```jsp
<form method="post" action="<c:url value='/tasks/delete'/>" style="display:inline" data-confirm-title="${fn:escapeXml(details.task.title)}">
  <input type="hidden" name="_csrf" value="${csrfToken}">
  <input type="hidden" name="id" value="${details.task.id}">
  <button class="btn btn--secondary btn--sm" type="submit">Delete</button>
</form>
```

- A **form** with a button, never a link (37.02).
- The confirmation is 35.17's `confirm-delete.js`, reading the escaped `data-confirm-title`. It's UX: the server doesn't rely on it.
- `TaskDeleteServlet` checks the token, deletes, puts "Task deleted." and answers 303 → `/tasks`. The toggle and comment servlets got the same three changes: token check, flash, 303.

## ✅ Checkpoint

`mvn package` → green. Edit a task's title, save: back on the task with "Task saved.". Delete it: back on the list with "Task deleted.", and its URL is now 404.
