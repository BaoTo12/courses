## 1. The form bean keeps what the user TYPED

✍️ `src/main/java/com/taskflow/web/tasks/TaskForm.java`

{{file:@reference/taskflow/backend/src/main/java/com/taskflow/web/tasks/TaskForm.java:java}}

Why strings, and not a `Task`? A `Task` can't hold `"2026-02-30"` as a due date or `"URGENT"` as a priority, but the form must show the user **exactly** what they typed next to the error. So the bean stores raw strings, and `validate()` converts them (keeping the parsed values for `applyTo`).

## 2. Errors: field name → message

```java
Map<String, String> errors = form.validate(service.categoryIds());   // {"priority": "must be one of …", …}
```

- A `LinkedHashMap`: the errors keep the form's order.
- The view reads `${errors.title}`: `null` (no error) prints nothing, and `empty errors.title` is true (34.12).

## 3. On failure: FORWARD, with status 400

```java
response.setStatus(HttpServletResponse.SC_BAD_REQUEST);
TaskFormPage.show(request, response, service, form, errors, null);   // request attributes → form.jsp
```

| On failure… | Forward (✅) | Redirect (❌) |
|---|---|---|
| request attributes (`form`, `errors`) | still there: same request | **gone**: a new request (31.06) |
| the URL | stays `/tasks/new` | whatever you redirect to |
| Reload | re-submits the invalid form (harmless: nothing was saved) | — |
| status | 400: honest for tools and tests | 303 then 200 |

On success it's the opposite: **redirect** (37.08). The asymmetry is the heart of form handling: *invalid → forward and show; valid → save and redirect.* 37.17 is what happens when someone redirects on failure.

## ✅ Recap

Keep the input as typed in a form bean, and the problems in an `errors` map, both as request attributes. On failure, set 400 and **forward** back to the form.
