## 5. The session problem, and the registry

Bob is logged in. An admin disables him. Bob's session still holds the `AuthUser` copied at login, so without more code he keeps working until his session ends. The same for a demotion from ADMIN.

✍️ `src/main/java/com/taskflow/service/AccountRegistry.java`

{{file:@reference/taskflow/backend/src/main/java/com/taskflow/service/AccountRegistry.java:java}}

✍️ in `AuthenticationFilter`, for every logged-in request:

```java
Optional<AccountRegistry.State> account = accounts.state(user.getId());
if (account.isEmpty() || !account.get().enabled()) {       // disabled by an admin since this login (42.07)
  audit.record("SESSION_REVOKED", user.getUsername(), request.getRemoteAddr(), "account disabled");
  request.getSession().invalidate();
  Flash.put(request, "Your session has ended. Please log in again.");
  Http.seeOther(response, request.getContextPath() + "/login");
  return;
}
if (!account.get().role().equals(user.getRole())) {        // promoted or demoted since this login
  user = user.withRole(account.get().role());
  request.changeSessionId();
  request.getSession().setAttribute(CurrentUser.SESSION_KEY, user);
}
```

| Option | Cost per request | Takes effect |
|---|---|---|
| nothing (the session copy) | 0 | at the session's end (up to 15 minutes, or never with "remember me") |
| query the `users` row every request | one query | immediately |
| **an in-memory snapshot, refreshed on change** (TaskFlow) | a map lookup | at the next request, on this server |
| track sessions per user, invalidate them on change | a registry of sessions (listeners, 45.09) | immediately, including idle sessions |

A role change is a privilege change, so the session gets a **new id** (the login rule of 41.11).
