## 1. What the container gives you

For `@WebServlet("/api/tasks/*")`:

| Request | `getServletPath()` | `getPathInfo()` |
|---|---|---|
| `/taskflow/api/tasks` | `/api/tasks` | `null` |
| `/taskflow/api/tasks/` | `/api/tasks` | `/` |
| `/taskflow/api/tasks/5` | `/api/tasks` | `/5` |
| `/taskflow/api/tasks/5/comments` | `/api/tasks` | `/5/comments` |
| `/taskflow/api/tasks/abc` | `/api/tasks` | `/abc` |

Mapping precedence: exact (`/api/categories`) → longest prefix (`/api/tasks/*` before `/api/*`) → extension (`*.jsp`) → default (`/`).

## 2. Why override `service()`

`HttpServlet.service()` dispatches to `doGet`, `doPost`, `doPut`, `doDelete`… and:
- has **no `doPatch`**: PATCH gets `501 Not Implemented`;
- answers a method you didn't override with `sendError(405)`: TaskFlow's **HTML** error page (43.02).

A JSON API needs neither. The base class takes over `service()` completely:

## 4. The routing table, in `TaskApiServlet.route`

| `segments` | GET | POST | PUT | PATCH | DELETE |
|---|---|---|---|---|---|
| `[]` | list | create | — | — | — |
| `[id]` | read | — | replace | update | delete |
| `[id, "comments"]` | comments | add comment | — | — | — |
| anything else | 404 `No endpoint …` | | | | |

`"abc"` as an id → 404 `Task not found`, like a missing task.

## 5. Hardening: which path?

The CSRF filter must recognise API requests (it applies other rules to them). `Api.isApiRequest` uses `servletPath + pathInfo`, the **normalised** path the container mapped, never `getRequestURI()`: a raw `/taskflow/api/../tasks/delete` starts with `/api/` but is served by `/tasks/delete`.

## ✅ Recap

Map a prefix, split `pathInfo`, dispatch on method + segments, and answer everything else with JSON. Frameworks (JAX-RS `@Path`, Spring's `@GetMapping`) generate exactly this table from annotations.
