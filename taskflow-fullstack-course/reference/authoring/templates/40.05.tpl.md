## 1. The filter

✍️ `src/main/java/com/taskflow/web/filters/CharacterEncodingFilter.java`

{{file:@reference/taskflow/backend/src/main/java/com/taskflow/web/filters/CharacterEncodingFilter.java:java}}

- It only sets the encoding **if the client didn't declare one** (`Content-Type: …; charset=…`). Browsers don't send a charset for form posts, so this almost always applies.
- It doesn't touch the **response** encoding: every JSP declares `contentType="text/html;charset=UTF-8"`.
- The encoding is an `<init-param>`, so it's configurable without recompiling.

## 2. Declaring it

✍️ in `WEB-INF/web.xml` (the full filter section is in 40.07):

```xml
<filter>
  <filter-name>encoding</filter-name>
  <filter-class>com.taskflow.web.filters.CharacterEncodingFilter</filter-class>
  <init-param><param-name>encoding</param-name><param-value>UTF-8</param-value></init-param>
</filter>
<filter-mapping><filter-name>encoding</filter-name><url-pattern>/*</url-pattern></filter-mapping>
```

## 3. Delete the copies

Remove `request.setCharacterEncoding("UTF-8");` from `TaskCreateServlet`, `TaskEditServlet`, `TaskCommentServlet` and `CategorySaveServlet`. The tests that post Vietnamese titles keep passing: the filter did it before the servlet ran.

**Why it must be the first filter:** 40.19.
