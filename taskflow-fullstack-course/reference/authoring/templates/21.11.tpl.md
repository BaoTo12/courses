# Lecture 21.11 · 🛠 Build: `TaskListItem` Connected by Id, Memoized; the Board's Columns

> **Section:** S21 · **Type:** 🛠 Build · **Track:** ★ Core · **Time:** ~60 minutes
> **Project feature:** toggling one task re-renders one card; sorting re-renders none; the board's columns select their own ids.
> Verified: `tsc`, lint, all tests; measured in the browser with a temporary counter (21.03): toggle → **1** card (was 22 in S20), sort change → **0** cards, toast → 0. Removing `memo` or `useCallback` brings it back to 22 (21.10 §4).

---

## 1. The plan

| Component | Before (S20) | After |
|---|---|---|
| `TaskList` | received `tasks: Task[]`, rendered `TaskCard`s | receives `taskIds`, renders `TaskListItem`s |
| `TaskListItem` (new) | — | `memo`; selects **its own** task by id; renders `TaskCard` |
| `Board` | received `tasks`, grouped them in render | each column selects its ids with its **own** selector instance |
| `TaskCard` | unchanged (a presentational component with props) | unchanged, except the title check from 21.05 |

## 2. ✍️ `src/features/tasks/TaskListItem.tsx`

{{file:features/tasks/TaskListItem.tsx:tsx}}

- It lives in `features/tasks/` because it uses the store; `TaskCard` stays in `components/`, props only (19.10).
- `if (!task) return null` covers one render in which the id is still in the parent's list but the task is gone. React-Redux re-renders parents before children, so in practice the parent's new ids arrive in the same pass.

## 4. ✍️ `src/components/Board.tsx`

{{file:components/Board.tsx:tsx}}

- The board used to receive **all** tasks and group them in render: any task change re-rendered all three columns and every card.
- Now each column selects `taskIds` for its status through its own selector instance (21.07). `keepSameIds` (21.08) means a column whose ids didn't change gets the **same** array and skips rendering (it's `memo`, and its props are stable).
- `useMemo(() => makeSelectTaskIdsByStatus(), [])`: the arrow is required by the `react/use-memo` lint rule (21.07).
