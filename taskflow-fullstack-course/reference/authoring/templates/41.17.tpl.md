| Rule | Rejects |
|---|---|
| must start with `contextPath + "/"` (`/taskflow/`) | absolute URLs, other apps on the same server, relative paths |
| no `//` at the start | protocol-relative URLs (matters when the context path is empty) |
| no `\` | browsers that treat `/\host` like `//host` |
| no CR/LF | header injection into `Location` |

It's used in **one** place per feature, and nowhere else builds redirects from input:
- `LoginServlet`: `Redirects.safeLocalPath(request, returnUrl, contextPath + "/tasks")`, and the hidden field is re-checked before being written into the form;
- `ThemeServlet` (39.09): the same method (its private copy was removed).

**Stronger alternatives:** store the target server-side (in the session before redirecting to login) instead of a parameter, or map short keys to fixed paths (`?next=tasks`). TaskFlow's allow-list of "our own paths" is the common middle ground.

## ✅ Recap

A redirect target from the request must be a path of this application. One helper decides, and every redirect-from-input uses it.
