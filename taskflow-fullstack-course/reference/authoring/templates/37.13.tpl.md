# Lecture 37.13 · 🛡 Defend: the Synchroniser Token Pattern

> **Section:** S37 · **Type:** 🛡 Defend · **Track:** ★ Core · **Time:** ~35 minutes
> **Project feature:** every POST form carries `_csrf`; every POST servlet checks it first (403 otherwise).
> Verified: `S37FormsTest.theNewTaskFormCarriesACsrfTokenFromTheSession` (43-character token, `JSESSIONID` cookie `HttpOnly`), `.postsWithoutTheRightTokenAreRefused`, `S37CategoriesTest.everyWriteNeedsTheToken`

---

## 1. The idea

```text
GET  /tasks/new      server: session.csrf = "k3J…9Qa" (random, once per session)
                     page:   <input type="hidden" name="_csrf" value="k3J…9Qa">
POST /tasks/new      _csrf=k3J…9Qa + cookie JSESSIONID  → equal to session.csrf? ✅ proceed
forged POST          no _csrf, or a guess                 → ❌ 403
```

The attacker's page can make the browser send the cookie, but it can't **read** a TaskFlow page (same-origin policy), so it can't learn the token.

## 2. The code

✍️ `src/main/java/com/taskflow/web/Csrf.java`

{{file:@reference/taskflow/backend/src/main/java/com/taskflow/web/Csrf.java:java}}

| Detail | Why |
|---|---|
| `SecureRandom`, 32 bytes | unguessable (`Math.random`/`Random` are predictable) |
| Base64-URL, no padding | 43 safe characters for an HTML attribute and a form body |
| stored in the **session** | tied to this user's login; S41 creates a **new** session (and so a new token) at login |
| `MessageDigest.isEqual` | constant-time comparison: timing doesn't reveal how many characters matched |
| `isValid` uses `getSession(false)` | a forged request without a session doesn't create one |

## 3. Using it

Pages with POST forms (list, view, the task form, categories) call `Csrf.prepare(request)` in their GET controller, and every form includes:

```jsp
<input type="hidden" name="_csrf" value="${csrfToken}">
```

Every POST servlet starts with:

```java
if (!Csrf.isValid(request)) {
  response.sendError(HttpServletResponse.SC_FORBIDDEN, "Invalid or missing CSRF token");
  return;
}
```

## 4. A consequence: pages now create sessions

`Csrf.prepare` calls `request.getSession()`, so visiting `/tasks` now sets a `JSESSIONID` cookie. That's deliberate. The JSPs still say `session="false"`: it's the **controller** that decides to use the session. `S33JspFundamentalsTest`'s "no cookie" check now uses `/debug/el`, a page without forms.

## 5. Forgetting the check

Six servlets, six copies of the same three lines: one forgotten copy is a hole. S40 moves the check into a **filter** that runs before every POST. The test for that will be: *every* POST without a token → 403.

## ✅ Takeaways

- A random per-session token in a hidden field, checked on every state-changing request.
- It works because other sites can **send** requests with your cookies but can't **read** your pages.
- Centralise the check (S40): a defence each servlet must remember is a defence that will be forgotten.
