## 3. Its place

```xml
<filter-mapping><filter-name>errors</filter-name><url-pattern>/*</url-pattern></filter-mapping>
<filter-mapping><filter-name>locale</filter-name><url-pattern>/*</url-pattern></filter-mapping>
<filter-mapping><filter-name>api</filter-name><url-pattern>/api/*</url-pattern></filter-mapping>
```

**Inside** the global `errors` filter: an exception from an API servlet reaches `ApiExceptionFilter` first (the innermost `catch` wins, 40.02), so API clients never see an HTML error page. Everything after it (maintenance, authentication, authorisation) is covered too.

## 4. Compared with `ErrorHandlingFilter` (43.08)

| | Pages | API |
|---|---|---|
| response | `sendError(status)` → an error **page** | `Json.write(status, ApiError)` directly |
| not found / denied | 404 page | `{"error":"NOT_FOUND"}` |
| bug | 500 page + request id | `{"error":"INTERNAL_ERROR","message":"Unexpected server error"}` (the `X-Request-Id` header still identifies it) |
| log | the same: stack trace with the request id | |
