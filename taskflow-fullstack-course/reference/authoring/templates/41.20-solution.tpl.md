`${currentUser}` is the request attribute the filter sets. `<c:out>` escapes the display name: it's user data. Log out is a form (POST + token), styled as a button.

## 2. Making the token available on every page

In `AuthenticationFilter`, for logged-in requests (not static files):

```java
request.setAttribute("currentUser", user);
if (!path.startsWith("/static/")) {
  Csrf.prepare(request);
  response.setHeader("Cache-Control", "no-store");   // private pages: not kept in the browser's history cache
}
```

A logged-in user already has a session, so preparing the token costs nothing, and every page's nav can post. The `Csrf.prepare` calls in individual controllers became redundant and were removed.

## 3. Detecting an expired session

```java
if (request.getRequestedSessionId() != null && !request.isRequestedSessionIdValid()) {
  login.append(separator).append("expired=1");         // the browser sent a session id we no longer know (41.19)
}
```

`LoginServlet.doGet` turns the parameter into the `expired` attribute, and `login.jsp` shows the message. It's shown for any unknown id: an expired session, a server restart without persistence, or a tampered cookie. From the server's point of view they're the same.

### Wrong approaches

| Attempt | Problem |
|---|---|
| `${sessionScope.currentUser.displayName}` in the nav | throws in `session="false"` pages (34.25) |
| a `<a href="/logout">` link | a GET that changes state: any page can log users out (37.02) |
| `${currentUser.displayName}` without `<c:out>` | a display name like `<script>` would run (34.18) |
| detecting "expired" with `getSession(false) == null` | also true for someone who never had a session: they'd see "expired" on their first visit |
| a JavaScript timer that redirects after 15 minutes | UX only; the server must enforce the timeout |
