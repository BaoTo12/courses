# Lecture 24.05 · 🛠 Build: A Typed `cookies.ts` Wrapper with Safe Defaults

> **Section:** S24 · **Type:** 🛠 Build · **Track:** ★ Core · **Time:** ~30 minutes
> **Project feature:** the only module in TaskFlow that touches cookies. It has known cookie names, safe attributes by default, and no raw js-cookie calls anywhere else.
> Verified: `src/api/cookies.test.ts` ("cookies.ts": write/read/remove; jsdom), `tsc`, lint.

---

## 1. Install

```bash
npm install js-cookie
npm install -D @types/js-cookie jsdom
```

`jsdom` is for the tests. Vitest runs in Node by default, and Node has no `document.cookie`. One comment at the top of a test file switches that file to a browser-like environment: `// @vitest-environment jsdom`.

## 2. The wrapper

✍️ `src/api/cookies.ts`

{{file:api/cookies.ts:ts}}

Design decisions:

- **`COOKIE_NAMES`** with `as const` + `keyof typeof`: callers write `readCookie('theme')`, and `readCookie('tehme')` doesn't compile. The real names carry a `tf_` prefix, so they can't collide with other apps on `localhost`.
- **`Cookies.withAttributes(...)` once**: every write gets `path: '/'`, `sameSite: 'lax'` and `secure` on HTTPS. Nobody can forget them, and `remove` uses the same path automatically.
- **`secure` from `window.location.protocol`**: `true` in production (HTTPS), `false` on `http://localhost`. With `true` on plain HTTP, the browser would silently **drop** the cookie.
- **`days` optional**: with a number you get a persistent cookie (`Expires`), without it a session cookie. The call site shows which one it is.
- **`readCsrfToken` is separate**: the server owns that cookie and its name. We only read it (24.10).
- **`JSESSIONID` is absent on purpose.** The comment says why (24.07).

## 3. The rule for the rest of the codebase

> Nothing outside `src/api/cookies.ts` imports `js-cookie` or touches `document.cookie`.

The same rule as "nothing imports axios except `client.ts`" (13.03). One place to audit, one place to change.

## ✅ Checkpoint

`npx vitest run src/api/cookies.test.ts` is green. It writes `tf_theme=dark`, reads it back, and removes it.
