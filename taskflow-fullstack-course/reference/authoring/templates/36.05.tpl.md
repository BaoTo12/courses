# Lecture 36.05 · 🛠 Build: Controllers Calling `TaskService`; Request Attributes → JSP

> **Section:** S36 · **Type:** 🛠 Build · **Track:** ★ Core · **Time:** ~45 minutes
> **Project feature:** every task page reads and writes MySQL through `TaskService`; the in-memory stores are deleted; views can no longer contain Java.
> Verified: S31–S35's tests on MySQL, `S36MvcDatabaseTest.theListAndTheCategoriesComeFromMySql`

---

## 1. The pattern for every controller

```text
1. parse + validate the request into typed values          (400 if impossible)
2. call ONE service method                                  (404 if it says "not found")
3. put the result in request attributes, forward to a view  (or redirect after a change)
```

## 2. The details page

✍️ `src/main/java/com/taskflow/web/tasks/TaskViewServlet.java`

## 3. A write: toggle

✍️ `src/main/java/com/taskflow/web/tasks/TaskToggleServlet.java`

{{file:@reference/taskflow/backend/src/main/java/com/taskflow/web/tasks/TaskToggleServlet.java:java}}

The rule "DONE ↔ TODO" moved out of the servlet into `TaskService.toggle`. The servlet only maps `false` → 404.

## 4. The rest

Same change in `TaskCreateServlet` (`service.create(task)`), `TaskDeleteServlet` (`service.delete(id)`), `TaskLatestServlet` (`service.latestId()`: `SELECT MAX(id)` instead of loading every task), and `TaskCommentServlet` (`service.addComment(…)`). The list, before your 36.11 changes:

```java
TaskFilter filter = new TaskFilter(TaskStatus.parse(request.getParameter("status")), normalise(request.getParameter("q")));
List<Task> tasks = service.find(filter);
…
request.setAttribute("categories", service.categories());     // the filter's options, from MySQL (36.11)
```

Then **delete** `store/InMemoryTaskStore`, `InMemoryCommentStore` and `InMemoryDirectory`. The compiler finds anything that still uses them.

## 5. Views: Java is now forbidden

✍️ in `WEB-INF/web.xml`, inside the `jsp-property-group`:

```xml
      <!-- S36 (33.14): every view is EL + JSTL only (35.08). From now on, Java in a JSP is a TRANSLATION ERROR. -->
      <scripting-invalid>true</scripting-invalid>
```

`S35JstlTest.noViewContainsJavaAnymore` checked it by reading files. Now the container refuses to translate a page with `<% %>`.

## 6. Data changes the tests see

The seed now comes from `db/03-seed.sql` (23+ tasks, 4 categories, 3 users). Three older assertions changed to match it (for example "Book flights for the offsite" → "Plan team offsite"), and S34's null-safety test creates its own task without a category, since every seeded task has one. All test classes share **one** database, so tests that change data create their own rows (36.14).

## ✅ Checkpoint

`mvn package` (Docker running) → all tests green. With `docker compose up -d`, `/taskflow/tasks` lists the 23+ seeded tasks, and a toggle survives a Tomcat restart.
