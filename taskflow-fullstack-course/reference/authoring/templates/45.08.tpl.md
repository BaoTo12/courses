## Why a listener, and not a servlet's `init()`

| | `ServletContextListener` | a servlet's `init()` |
|---|---|---|
| runs | before **any** filter or servlet | when that servlet is first used (or at startup with `load-on-startup`) |
| order | defined (before everything) | depends on which servlet loads first |
| filters | can use the services in their `init()` | filters initialise before servlets: the services wouldn't exist yet |
| shutdown | `contextDestroyed`, after everything | `destroy()` of one servlet |
| failure | the web app doesn't start (fail fast: no half-working app) | one servlet fails; the rest serves errors |

## What happens at startup and shutdown

```text
contextInitialized                                  contextDestroyed
  1. DataSource (Hikari) — fails fast if MySQL is down    1. export threads: shutdownNow()
  2. EntityManagerFactory (📦 JPA)                         2. EntityManagerFactory.close()
  3. DAOs → services → caches                             3. Hikari pool close()
  4. context attributes (the "registry")                  4. the MySQL driver's cleanup thread
  5. addListener(SessionRegistry)
  6. the export thread pool
```

Everything created at startup is closed at shutdown, in reverse order. Anything left running (a pool, a thread, a driver) keeps the old web app's classes in memory after a redeploy: 45.18.
