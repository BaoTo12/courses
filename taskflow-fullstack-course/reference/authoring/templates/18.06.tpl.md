## 3. ✍️ `fetchTasks()` (in `src/features/tasks/tasksThunks.ts`)

A first version, before 18.11 adds request ids and cancellation:

```ts
/** Until pagination arrives (S23), the list loads the first 100 tasks: the API's maximum page size. */
const DEFAULT_QUERY: TaskQuery = { size: 100 };

export const fetchTasks =
  (query: TaskQuery = DEFAULT_QUERY): AppThunk<Promise<void>> =>
  async (dispatch, _getState, { api }) => {
    dispatch(fetchStarted());
    try {
      const page = await api.getTasks(query);
      dispatch(fetchSucceeded(page.items));
    } catch (error) {
      dispatch(fetchFailed(toErrorMessage(error)));
    }
  };
```

- The same three lifecycle events as S15–S17, now dispatched from a thunk.
- **It never rejects**: failures become `tasks/fetchFailed`, and the page renders the error from state (17.07). Callers can `await` it without `try/catch`.
- `_getState`: the leading underscore marks an unused parameter (TypeScript's `noUnusedParameters` accepts it).

## 4. ✍️ The layout loads with a thunk

```tsx
useEffect(() => {
  void dispatch(fetchTasks());
}, [dispatch]);
```

That replaces S17's `loadTasks(dispatch, signal)`. With StrictMode, this effect runs twice, so two loads start. 18.09 fixes that with `fetchTasksIfNeeded()`, and 18.11 makes overlapping loads safe.
