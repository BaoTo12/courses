## 1. The idea

**Memoization** = remembering a function's result for given arguments, and returning the remembered result when the same arguments come again, without running the function.

It only makes sense for **pure** functions (same arguments → same result, no side effects): if the function read the clock or the network, the remembered result could be wrong.

Two questions define every memoizer:

1. **"Same arguments"**: compared how? By value (deep equality: expensive) or by reference (`===` / `Object.is`: instant)?
2. **How many results** are remembered? Only the last one, all of them, the last N?

reselect (and so `createSelector`) is a memoizer. Before using its options (21.08), write the two classic ones yourself.

## 2. ✍️ `src/domain/memoize.ts`

{{file:domain/memoize.ts:ts}}

- **`sameArgs`** compares by **reference** (`Object.is`, like `===` except for `NaN` and `-0`). That's the only comparison cheap enough to run on every call. It also means: an array with the same **content** but a new **reference** is a different argument.
- **`memoizeOne`** keeps one entry. Perfect when calls repeat with the same arguments (a selector called on every render with the same state), useless when arguments alternate.
- **`memoize`** keeps every entry. Alternating arguments hit, but the cache **never shrinks**: memoize a function of the search text, and every text ever typed stays in memory.

## 3. The tests prove each property

Read the four results together:

| Calls | `memoizeOne` | `memoize` |
|---|---|---|
| `(list, 5)` twice | 1 call of `fn`, the **same** array returned | same |
| `([1,5,9], 5)` with a **new** array of equal content | a miss | a miss |
| `1, 2, 1, 2` | **4** calls (each call evicts the other) | **2** calls |
| 1000 distinct texts | 1 entry | **1000** entries |

## 4. Why this matters for Redux

A selector is a function of `(state, ...args)`. React-Redux calls it after **every** dispatch and on every render (17.04). Without memoization, `state.tasks.filter(...)` returns a new array each time, and `useSelector` (which compares with `===`) re-renders the component on **every** action. You saw this in 17.15; 21.02 revisits it with numbers.

The three cache trade-offs you just coded are exactly the ones in reselect:

- reselect 4's default = `memoizeOne` semantics (called `defaultMemoize`, now `lruMemoize` with `maxSize: 1`);
- reselect 5's default `weakMapMemoize` = "remember every argument", but keyed by **reference** in `WeakMap`s where possible, so entries for objects that are garbage-collected disappear (21.08).

## 5. Summary

- Memoize **pure** functions only; compare arguments by reference.
- Cache size is a choice: 1 (thrashes on alternating arguments) vs all (grows).
- Selectors are memoized so that they return the **same reference** when nothing changed, which is what stops React-Redux from re-rendering.
