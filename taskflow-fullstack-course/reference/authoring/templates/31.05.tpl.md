## Walkthrough

**`doGet`** renders an empty form. **`doPost`**:

1. **`request.setCharacterEncoding("UTF-8")`** before any `getParameter`, so Vietnamese titles survive (31.02 §3).
2. **Read and validate everything**: title (not blank, ≤ 120 after trimming), priority (an allow-list via `Priority.parse`), due date (an optional ISO date). `maxlength` in the HTML is a courtesy, and curl ignores it (29.09).
3. **Errors → `setStatus(400)` + the form again**, with:
   - a message per field (`form-field--error`, the same CSS as TaskFlow Web);
   - the user's **own input** echoed back, **escaped**, because it goes into `value="…"` attributes. The test posts `"><script>x</script>` and finds `value="&quot;&gt;&lt;script&gt;…"`. A form that reflects input unescaped is a reflected-XSS hole (30.14).
4. **Success → `store.save` → `sendRedirect(ctx + "/tasks/view?id=" + id)`**: the browser GETs the new task's page. Reload is now harmless (31.04).
5. **`setOwnerId(1)`** is a placeholder. The owner **must** come from the logged-in session, never from a form field (S41; 29.09 §2).

## Why `setStatus(400)` and not `sendError(400)` here

`sendError` would replace our page with the container's error page. Here we want **our** page (the form with errors) **and** the right status for it, so it's `setStatus` + write (31.03's card).

## Duplication alert

The field markup and the escaping are repeated for every input. In S37, JSP tags (`<c:out>`, a tag file for form fields) make this readable.

## ✅ Checkpoint

- Submit a Vietnamese title: you land on `/tasks/view?id=N`, and the title is intact.
- Submit an empty title and priority `URGENT` (edit the `<option>` in DevTools): 400, two messages, your text kept.
- Reload the success page: no second task.
