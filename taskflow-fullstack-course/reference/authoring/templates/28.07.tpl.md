## 1. Four scripts, in order

| Script | Run as | Does |
|---|---|---|
| `db/01-database-and-user.sql` | root | creates the `taskflow` database (utf8mb4) and the `taskflow_app` user |
| `db/02-schema.sql` | root | the five tables |
| `db/03-seed.sql` | root | demo users, categories, 25 tasks, comments |
| `db/04-grants.sql` | root | the app user's (few) rights |

**Docker:** they run automatically, in name order, the first time the MySQL volume is empty (`/docker-entrypoint-initdb.d`). To run them again: `docker compose down -v && docker compose up -d`.

**Native MySQL:**

```bash
mysql -u root -p < db/01-database-and-user.sql
mysql -u root -p < db/02-schema.sql
mysql -u root -p < db/03-seed.sql
mysql -u root -p < db/04-grants.sql
mysql -u taskflow_app -ptaskflow_dev_pw taskflow -e "SELECT username, role FROM users"
```

## 2. Database and user

{{file:@reference/taskflow/backend/db/01-database-and-user.sql:sql}}

- **`utf8mb4`**, not `utf8`. MySQL's historical `utf8` stores at most 3 bytes per character, so emoji in a task title fail to save (or get cut). `utf8mb4` is real UTF-8.
- **`utf8mb4_0900_ai_ci`**: comparisons ignore case (`ci`) and accents (`ai`). `'Report' = 'report'`, and also `'Cafe' = 'Café'`.
- **`'taskflow_app'@'%'`**: the user may connect from any host. Docker needs that, because the app connects from another container. On a real server, restrict it (`'taskflow_app'@'10.0.1.%'`).

## 3. The schema

{{file:@reference/taskflow/backend/db/02-schema.sql:sql}}

Points worth noticing (each is used later):

- **`ENUM`s for status, priority and role**: the database itself refuses `'DELETED'`. They're mapped to Java enums (S36).
- **`password_hash CHAR(60)`**: a bcrypt hash is always 60 characters. There's no password column, anywhere, ever.
- **`UNIQUE (owner_id, title)`** with the `_ci` collation *is* the business rule "a title is unique per owner, case-insensitively" (02-project-spec §5). The database enforces it even if application code forgets, and S46 turns the violation into a `400` with `fieldErrors.title`.
- **`ON DELETE CASCADE`** from users to tasks and comments, and **`SET NULL`** for a deleted category: the task survives, uncategorised.
- **`updated_at … ON UPDATE CURRENT_TIMESTAMP`**: MySQL maintains it.
- **`audit_events.username` is not a foreign key**, because failed logins name users that don't exist. **`TIMESTAMP(3)`** gives millisecond ordering.
- `comments.body` is stored **as typed**. Escaping is the renderer's job (the S35 XSS lab).

## 4. Seed data

The first lines of `db/03-seed.sql`:

```sql
-- Demo passwords (development only!): alice / alice123 · bob / bob123 · admin / admin123 — stored as bcrypt hashes (cost 12).
INSERT INTO users (id, username, email, password_hash, display_name, role, locale, enabled) VALUES
  (1, 'alice', 'alice@taskflow.test', '$2a$12$oBJehHL5…', 'Alice Nguyen', 'USER', 'en', TRUE),
  …
```

- The same people, categories, tasks and comments as the mock API, so TaskFlow Web shows identical data in Part 3.
- `.test` email addresses: a reserved top-level domain, so no email can ever reach a real person.
- The hashes are real bcrypt (cost 12). `SeedDataTest` re-checks every one against its documented password on each `mvn package`.

## 5. Least privilege: the grants

{{file:@reference/taskflow/backend/db/04-grants.sql:sql}}

| The app user can | It can't | So a SQL injection (S36 lab) can't… |
|---|---|---|
| read and write rows in its five tables | `CREATE`, `DROP`, `ALTER`, `GRANT`, anything on other databases | drop tables, create a backdoor user, read `mysql.user` |
| **insert** audit events | **update or delete** audit events | erase its own tracks from the audit log (S45) |

`SeedDataTest.theAppUserGetsNoSchemaRightsAndAnAppendOnlyAuditLog` fails if anyone widens these grants carelessly. Schema changes are run by a **separate admin account** (by you now, and by a migration tool in real projects).

## ✅ Checkpoint

```bash
mysql -h 127.0.0.1 -u taskflow_app -ptaskflow_dev_pw taskflow -e "SELECT COUNT(*) FROM tasks"          # 25
mysql -h 127.0.0.1 -u taskflow_app -ptaskflow_dev_pw taskflow -e "DROP TABLE comments"                # ERROR 1142: DROP command denied
mysql -h 127.0.0.1 -u taskflow_app -ptaskflow_dev_pw taskflow -e "DELETE FROM audit_events"           # ERROR 1142: DELETE command denied
```
