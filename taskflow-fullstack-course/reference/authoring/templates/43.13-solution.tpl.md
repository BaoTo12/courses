## 4. The reference on 500

In `RequestLoggingFilter`, next to the MDC and the header:

```java
response.setHeader("X-Request-Id", requestId);
request.setAttribute("requestId", requestId);    // S43: for the 500 page's reference (43.12), which runs after we return
```

{{file:@reference/taskflow/backend/src/main/webapp/WEB-INF/views/errors/500.jsp:jsp}}

The error dispatch reuses the **same request object** (43.03), so the attribute is there; the MDC isn't (the filter's `finally` cleared it).

### Wrong approaches

| Attempt | Problem |
|---|---|
| `"Invalid id: " + raw` | echoes attacker input (escaped or not, it's their text on your page) |
| `${requestScope['javax.servlet.error.exception'].message}` on the 500 page | shows internal details (43.09) |
| a new random id generated in `500.jsp` | it matches nothing in the logs |
| `MDC.get("requestId")` in the page | cleared before the error dispatch: empty |
| catching `NumberFormatException` in each controller | back to one `try`/`catch` per controller |
