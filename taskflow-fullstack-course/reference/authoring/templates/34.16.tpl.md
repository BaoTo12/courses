# Lecture 34.16 · 🛠 Build: the EL Debug Page (Development Only)

> **Section:** S34 · **Type:** 🛠 Build · **Track:** ★ Core · **Time:** ~30 minutes
> **Project feature:** `/taskflow/debug/el` shows what `param`, `paramValues`, `header`, `cookie`, `initParam`, `pageContext` and the scopes contain for the current request, next to the expression that reads each one.
> Verified: `S34ElTest.theElDebugPageShowsImplicitObjectsAndCoercions` (a request with `?q=<b>hi&tag=a&tag=b`, a `User-Agent` and a `tf_lang=vi` cookie; every row checked, no `Set-Cookie`)

---

## 1. The controller: loopback only

✍️ `src/main/java/com/taskflow/web/debug/ElDebugServlet.java`

{{file:@reference/taskflow/backend/src/main/java/com/taskflow/web/debug/ElDebugServlet.java:java}}

- The same guard as `RequestInfoServlet` (30.10): the page shows headers and cookies, so it answers only requests from this machine, and 404s for everyone else.
- `scopeDemo` is set in **two** scopes on purpose, to show 34.03's search order on screen.

## 2. The view

✍️ `src/main/webapp/WEB-INF/views/debug/el.jsp`

{{file:@reference/taskflow/backend/src/main/webapp/WEB-INF/views/debug/el.jsp:jsp}}

| Row | What it demonstrates |
|---|---|
| `\${param.q}` with `?q=<b>hi` | shows `&lt;b&gt;hi` in the HTML source: escaped, so the browser shows the text `<b>hi` |
| `\${paramValues.tag[1]}` | the second value of a repeated parameter (34.10) |
| `\${param.page + 1}` | `1` without a `page` parameter: `null` → `0` (34.13) |
| `\${header['User-Agent']}` | brackets for a dashed key (34.10) |
| `\${cookie.tf_lang.value}` | a `Cookie` object, then `getValue()` (34.14) |
| `\${initParam.greeting}` | the `<context-param>` from 30.13, UTF-8 intact |
| `\${scopeDemo}` | `request`, although `application` has one too (34.03) |
| `\${empty pageContext.session}` | `true`: this page has no session, and **didn't create one**. Why it's not `sessionScope`: 34.25 |
| `\${'5' == 5}` | `true` (34.13) |

## 3. Why no loop over all headers?

EL can't loop (34.01). Listing **every** header and cookie needs `<c:forEach items="${header}" var="h">`, which S35 adds to this page. For now, the debug page shows one well-chosen example of each object.

## ✅ Checkpoint

`mvn package` → green. Open `http://localhost:8080/taskflow/debug/el?q=%3Cb%3Ehi&tag=a&tag=b`. Then set a cookie in DevTools (`document.cookie = "tf_lang=vi; path=/"`) and reload: the cookie row shows `vi`.
