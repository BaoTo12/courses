## 1. `src/app/middleware/crash-reporter.ts`

{{file:app/middleware/crash-reporter.ts:ts}}

- `try { return next(action); }` covers **everything downstream**: later middleware, the store's dispatch, every reducer, and (since `dispatch` is synchronous, 16.04) every subscriber. That includes React-Redux's subscription in S17. Errors thrown **asynchronously** (in a promise, a timer) aren't caught here: thunks handle those (S18), and a global `unhandledrejection` handler is the last resort (S27).
- **`throw error`** after reporting: the caller still fails. A crash reporter that swallowed errors would turn crashes into silent corruption.
- The outer `() =>` ignores `storeAPI`: this middleware doesn't need state. (Some reporters attach a redacted state snapshot. Consider the size and the privacy cost before doing that.)

## 2. `src/app/middleware/analytics.ts`

{{file:app/middleware/analytics.ts:ts}}

- **Allowlist** (`TRACKED_ACTIONS`): new action types are untracked by default. When S24 adds `auth/loggedIn` with a user object, nothing leaks, because nobody added it.
- **Type and timestamp only**: even for tracked actions, the payload never leaves the browser. "Someone created a task" is useful product data; the task's title isn't ours to collect.
- **After `next`**: failed actions aren't counted as successes.
- **`now` injected**: the test passes `() => 'T'` and asserts exact events.
- A `Set` here is fine: it's module configuration, not Redux state.

### Test techniques used

- **`vi.fn()`** records calls: `log.mock.calls[0]` is the first call's arguments.
- **`vi.spyOn(console, 'info').mockImplementation(() => {})`** checks that `makeStore`'s placeholder analytics sink ran, without printing during the test. `mockRestore()` puts the real `console.info` back.
- **A throwing middleware** (`() => () => () => { throw … }`) simulates a reducer bug without breaking the real reducers.
- **Asserting what's absent**: `expect(JSON.stringify(send.mock.calls)).not.toContain('Secret project')`. Security tests often check what must **not** happen.

## 5. Common wrong approaches

| Approach | Problem |
|---|---|
| Crash reporter that catches and doesn't re-throw | The UI continues on a half-updated state; the user never sees the error. |
| Crash reporter registered last | It only wraps the store's dispatch; errors in earlier middleware escape it. |
| `send({ name: action.type, payload: action.payload })` | Sends user content (titles, comments, later credentials) to a third party. |
| Denylist `if (!action.type.startsWith('auth/'))` | Tomorrow's `profile/passwordChanged` is tracked automatically. |
| Sending before `next` | Counts actions that crashed the reducers. |
| `store.ts` touching `window` at import | Every test importing the store crashes in Node. |
