## 1. The direction, allow-listed (📦 provided data layer)

{{file:@reference/taskflow/backend/src/main/java/com/taskflow/dao/TaskSort.java:java}}

Each direction is a **fixed** string; the request only picks `true` or `false`. "Due date, descending" keeps tasks without a due date last, a decision a naive `+ " desc"` would get wrong.

## 2. The controller

```java
TaskSort.parse(request.getParameter("sort")),            // not in the allow-list → the default (36.09)
"desc".equals(request.getParameter("dir")),              // S44: anything but "desc" → ascending
```

and `request.setAttribute("descending", filter.descending())` for the view.

## 3. The tag

{{file:@reference/taskflow/backend/src/main/webapp/WEB-INF/tags/sortHeader.tag:jsp}}

## 4. The header row

```jsp
<th><t:sortHeader column="title" current="${sort.param}" descending="${descending}" keep="q,status,category"><fmt:message key="tasks.col.title"/></t:sortHeader></th>
<th><fmt:message key="tasks.col.status"/></th>
<th><t:sortHeader column="priority" current="${sort.param}" descending="${descending}" keep="q,status,category"><fmt:message key="tasks.col.priority"/></t:sortHeader></th>
<th><t:sortHeader column="due" current="${sort.param}" descending="${descending}" keep="q,status,category"><fmt:message key="tasks.col.due"/></t:sortHeader></th>
```

The status links (`Show: All · To do · …`) and the pagination keep `dir` too (`keep="q,status,category,sort,dir"`).

### Wrong approaches

| Attempt | Problem |
|---|---|
| `"order by " + sort + " " + request.getParameter("dir")` | injectable (36.08): `dir=, (select …)` |
| `href="/taskflow/tasks?sort=title&dir=desc&q=${param.q}"` | `q` not URL-encoded (44.19), and `&` not HTML-escaped |
| keeping `page` in the sort links | page 3 of a different order is arbitrary rows |
| toggling in JavaScript | the server renders the list: the URL must carry the state (bookmarks, back button) |
