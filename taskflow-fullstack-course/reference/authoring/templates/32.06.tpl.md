## 2. The view

{{file:@reference/taskflow/backend/src/main/webapp/WEB-INF/views/tasks/list.jsp:jsp}}

What's in it:

| Syntax | Meaning (details in S33) |
|---|---|
| `<%-- … --%>` | a JSP comment: removed at translation, never sent to the browser |
| `<%@ page … %>` | a directive: the content type, the file's encoding, Java imports |
| `<% … %>` | a **scriptlet**: Java statements (the cast, `if`, `for` with `{` `}` spanning HTML) |
| `<%= … %>` | an **expression**: the value is written into the HTML at that spot |

It's still Java-heavy, with the `@SuppressWarnings` cast and braces spread over lines. S34 (EL) and S35 (JSTL) turn it into `<c:forEach items="${tasks}" var="task">`. For now, notice that the file **reads like the page**.

## 3. The S31 tests still pass

`S31TaskServletsTest` checks the list's content and escaping over HTTP. It doesn't care whether `println` or a JSP wrote the HTML. That's the value of testing **behaviour** at the HTTP level: refactor the inside, and keep the outside.
