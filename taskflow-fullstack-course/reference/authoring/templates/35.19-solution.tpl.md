## 3. The view

{{file:@reference/taskflow/backend/src/main/webapp/WEB-INF/views/tasks/view.jsp:jsp}}

Line by line, the decisions:

| Line | Why |
|---|---|
| `Comments (${fn:length(details.comments)})` | `fn:length` is null-safe and works on any collection; `${details.comments.size()}` would work too (a method call, 34.07) |
| `<c:choose>` around the table | the table isn't rendered at all when there's nothing to show |
| `${row.count % 2 == 0 ? 'comment--even' : 'comment--odd'}` | `count` starts at 1, so the first row is "odd", as humans count. `index % 2` would start at 0 |
| `<c:out … default="Deleted user"/>` | `item.author` may be `null` → the chain gives `null` → the default |
| `${' '}` before the Admin badge | a plain space there is **deleted** by `trimDirectiveWhitespaces` (35.22) |
| `<c:out value="${item.comment.body}"/>` | the stored-XSS defence (35.15) |
| `${item.comment.createdAt}` | an `Instant` prints as ISO-8601 (`2026-09-03T10:30:00Z`). S44 formats it for the user's locale and timezone |

### Wrong approaches

| Attempt | Problem |
|---|---|
| `${item.comment.body}` | stored XSS (35.14) |
| `<c:if test="${empty details.comments}">…</c:if>` + `<c:if test="${not empty …}">` | works, but it's two conditions to keep in sync: `<c:choose>` |
| `class="${row.index % 2 == 0 ? 'odd' : 'even'}"` | correct by accident only if you define "odd" as index 0: confusing |
| `<c:out value="${item.author.displayName}"/> <c:if …>` (the space outside) | a whitespace-only text node between two tags: the same trimming risk. Not verified here; 35.22 §4 shows how to check in the generated servlet |
| looking up authors in the JSP (`<c:set var="author" value="${directory…}"/>`) | a view doing data access; the controller assembles `CommentDetails` |
