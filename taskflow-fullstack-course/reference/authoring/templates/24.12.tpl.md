## 1. The endpoints

✍️ `src/features/auth/authApi.ts`

{{file:features/auth/authApi.ts:ts}}

- **Injected** into the one API slice (23.08), like the comments.
- **`getMe`** uses a `queryFn` so a **401 becomes `data: null`** (24.09 §5). `result.data as User` is safe because the base query already ran `isUser` (22.03). The cast only tells TypeScript what `validate` checked.
- **`login`** is pessimistic (23.06): the server's answer **is** the new "me", written with `upsertQueryData`, so there's no extra `GET /auth/me`. The test asserts that request never happens.
- **`logout`** clears everything **even if the request fails**, with `queryFulfilled.catch(() => undefined)`. If the user is offline, they must still be logged out *locally*. Then `getMe` is set to `null`. `clearUserData` (23.11) now also removes the user's cookies (24.16).

New guard in `src/domain/guards.ts`:

```ts
/** The user from POST /api/auth/login and GET /api/auth/me (24.12). */
export function isUser(value: unknown): value is User {
  return (
    isObject(value) &&
    typeof value.id === 'number' &&
    typeof value.username === 'string' &&
    typeof value.displayName === 'string' &&
    (value.role === 'USER' || value.role === 'ADMIN') &&
    (value.locale === 'en' || value.locale === 'vi')
  );
}
```

## 3. One guard for every page

✍️ `src/auth/RequireAuth.tsx`

{{file:auth/RequireAuth.tsx:tsx}}

✍️ `src/App.tsx`

{{file:App.tsx:tsx}}

- **A layout route** (`<Route element={<RequireAuth />}>`, rendering `<Outlet />`) guards **every** child route. A page added later is protected by default. That's safer than wrapping pages one by one, where one can be forgotten.
- **`isChecking` first:** on a reload, the session cookie is probably still valid, but `/auth/me` hasn't answered yet. Redirecting to `/login` at that moment would bounce logged-in users. Show "Checking your session…" instead.
- `/login` stays outside the guard, but inside `AppLayout`, so it keeps the header.

In `src/layouts/AppLayout.tsx`, the app-wide subscriptions and header widgets now need a user:

```ts
  // S24: only with a session. Anonymous requests would answer 401 → sessionExpired (24.13).
  useGetTasksQuery(user ? LIST_QUERY : skipToken);
  useGetCategoriesQuery(user ? undefined : skipToken);
```

`QuickFind` and `OpenTasksBadge` render only for `user`. Logout awaits the server, then navigates to `/login`.

## 4. The login page

✍️ `src/pages/LoginPage.tsx`

{{file:pages/LoginPage.tsx:tsx}}

- **`autoComplete="username"` / `"current-password"`** let password managers fill the form correctly.
- **One error message** for both failures, straight from the server (`toErrorMessage`). The server deliberately doesn't say which part was wrong, so we don't either.
- **The password is cleared** after a failure. The username stays.
- **Already logged in?** `<Navigate to={returnTo} />`, e.g. after pressing Back from the app to `/login`.
- **`safeReturnTo`** validates the redirect target (24.14).
