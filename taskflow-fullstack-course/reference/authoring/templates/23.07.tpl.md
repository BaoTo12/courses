# Lecture 23.07 · 🛠 Build: Server-Side Pagination, Keeping the Previous Page While the Next Loads

> **Section:** S23 · **Type:** 🛠 Build · **Track:** ★ Core · **Time:** ~75 minutes
> **Project feature:** the list view asks the server for **one page**, filtered and sorted **there**. The page is in the URL (`?page=2`), and the page size is a saved preference (`listPrefs.pageSize`). While the next page loads, the current one stays on screen, dimmed.
> Verified: `tsc`, lint, and `src/features/tasks/taskListSelectors.test.ts` (updated: filtering moved to the server). The server's paging is the mock API's contract (02-project-spec §5).

---

## 1. Why the server, now

Since S19 the list loaded `size: 100` and filtered in the browser. That works for 12 tasks, but not for 10,000:

- the payload grows with the data, not with the screen;
- `size` is capped at 100 by the API, so task 101 was **silently missing**.

`GET /api/tasks` already accepts `q`, `status`, `categoryId`, `sort=field,dir`, `page` (0-based) and `size` (1–100). It returns `{ items, page, size, totalItems, totalPages }`.

**What stays in the browser:** the app-wide `getTasks(LIST_QUERY)` subscription in `AppLayout`. The progress ring, "Clear completed", the header badge, the dashboard and the **board** view still read it. The board shows everything by design, and 100 tasks is its documented limit (S46 revisits it).

## 2. The page argument is the cache key

✍️ `src/pages/TasksPage.tsx`

{{file:pages/TasksPage.tsx:tsx}}

Walk through the new parts:

- **`pageQuery`** is built from the URL (`q`, `status`, `category`, `page`) and from `listPrefs` (`sort`, `pageSize`). Every distinct combination is its **own cache entry**, so going back to page 1 or to a previous filter is instant for 60 s (22.06).
- **`q: debouncedQ || undefined`**: an empty search must be *absent*, not `q=""`. Undefined fields disappear from the cache key **and** from the URL Axios sends.
- **`?page=2` is 1-based**, for humans, and is converted to the API's 0-based `page`. It is validated like every URL value (12.03): `?page=abc` becomes page 0.
- **`setParam` deletes `page` whenever another parameter changes.** A new filter on page 7 would otherwise show an empty page.
- **`useGetTasksQuery(view === 'list' ? pageQuery : skipToken)`**: the board doesn't need a page, so the hook is skipped (22.05 §4).
- **`const shown = pageResult.data`**, not `currentData`. When the argument changes, `data` keeps the **previous page** until the new one arrives (22.05 §3), and the wrapper dims it with `opacity` while `isFetching`. The list never blinks to "Loading…" after the first load.
- The **page size** changes `listPrefs` (a preference, saved to a cookie in S24) and resets to page 1.

## 3. The pager

✍️ `src/components/Pager.tsx`

{{file:components/Pager.tsx:tsx}}

- It is presentational: numbers in, callbacks out. The page decides that the page lives in the URL and the size in Redux.
- `PAGE_SIZES.find(...)` validates the `<select>` value (a string) back to the `PageSize` union without a cast.
- `Math.max(totalPages - 1, 0)`: an empty result has `totalPages: 0`, but we still show "Page 1 of 1".

## 4. The list receives task objects now

✍️ `src/components/TaskList.tsx`

{{file:components/TaskList.tsx:tsx}}

In S21, `TaskListItem` selected its task **by id from the app-wide list**. A server page can contain a task that isn't in that list (task 101), so the page's own objects are now the source.

- `memo(TaskCard)` compares `task` **by reference**. Structural sharing and Immer patches keep unchanged tasks identical, so a toggle still re-renders **one card** (22.06, 23.05).
- The **board** keeps `TaskListItem` (by id, from the app-wide list), because that's what it displays.
- `selectVisibleTaskIds` (21.05) was deleted: filtering is the server's job now. Its tests were rewritten for `selectSortedTasks` and the board's `makeSelectTaskIdsByStatus`.
- `onHoverTask` is 23.13's prefetch.

## 5. Edge cases to try

| Do | Expect |
|---|---|
| go to page 2, then filter "Done" | back to page 1 (the `page` param is removed) |
| open `?page=99` | "No tasks match this filter." and "Page 1 of 1" (the pager clamps the label). ‹ Previous steps back **one** page at a time: a rough edge that 23.13's stretch goal fixes. |
| delete the last task of page 2 | the optimistic patch removes it at once; the refetch (`TASK_LIST`) brings the right page contents |
| click Next quickly 3 times on Slow 4G | page 1 dimmed until page 4 arrives; pages 2–3 are cached too |
