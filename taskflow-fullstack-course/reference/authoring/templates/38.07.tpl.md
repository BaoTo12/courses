## 1. The counters

✍️ `src/main/java/com/taskflow/web/AppStats.java`

{{file:@reference/taskflow/backend/src/main/java/com/taskflow/web/AppStats.java:java}}

| Field | Type | Why that type |
|---|---|---|
| requests | `LongAdder` | incremented by every request, read rarely: spreads contention across cells, faster than `AtomicLong` under load |
| activeSessions | `AtomicInteger` | goes up **and** down; read often enough |
| taskViews | `ConcurrentHashMap<Long, LongAdder>` + `computeIfAbsent` | "create the counter if missing" must be atomic, or two threads create two counters and one count is lost |

## 2. Who updates them: listeners

✍️ `src/main/java/com/taskflow/web/StatsListener.java`

{{file:@reference/taskflow/backend/src/main/java/com/taskflow/web/StatsListener.java:java}}

### 📇 API card: the two listener interfaces

| Interface | Methods | Called |
|---|---|---|
| `ServletRequestListener` | `requestInitialized(ServletRequestEvent)`, `requestDestroyed(…)` | around **every** request, on its thread |
| `HttpSessionListener` | `sessionCreated(HttpSessionEvent)`, `sessionDestroyed(…)` | when a session starts, and when it's invalidated or times out |

Registered by `@WebListener` (or `<listener>` in `web.xml`). One class can implement several. S40 adds filters, which can do what a request listener does **and** change the request or response.

`AppContextListener` creates the `AppStats` in application scope **before** any request arrives, so the listener always finds it.

## 3. The page

`StatsServlet` (`/debug/stats`, loopback only) looks up the titles of the 5 most viewed tasks through the service (deleted ones are skipped) and forwards to `debug/stats.jsp`. `TaskViewServlet` calls `taskViewed(id)` for each view.
