{{file:@reference/taskflow/backend/src/main/java/com/taskflow/web/api/AuthApiServlet.java:java}}

| Detail | Why |
|---|---|
| the same `AuthService.login` as `LoginServlet` | throttling, BCrypt, `burnTime`, audit: written once (41.07) |
| `if (getSession(false) != null) changeSessionId()` | an SPA may have no session yet (the CSRF endpoint doesn't create one); `changeSessionId()` without a session throws `IllegalStateException` |
| `Csrf.reset` **and** a new `XSRF-TOKEN` | both CSRF tokens change at the privilege boundary (41.11) |
| `profile(user)` reads the `User` | `locale` isn't in the session's `AuthUser`; `UserDto` has no email or hash (46.09) |
| `/me` answers 401 itself | it's a public path for the filter, so it can say "not logged in" as data |
| `logout` removes the user, then invalidates | recorded as a logout, not a timeout (45.09) |

In `AuthenticationFilter`, the four `/api/auth/…` paths are public (checked on `servletPath + pathInfo`: the servlet is mapped to `/api/auth/*`).

## ✅ Checkpoint

```bash
curl -i -c jar -b jar http://localhost:8080/taskflow/api/auth/csrf
```

Then post the login with the token from the jar, `-H "X-XSRF-TOKEN: <value>"`, and `GET /api/auth/me` with the same jar → 200 alice.
