## 1. The setup

📦 A lab filter rewrites every `/api/*` response to break the contract in six ways, the way a backend change nobody announced would. The API code stays correct; switching the filter off restores everything.

1. Log in to the **Admin Portal** (it needs a CSRF token for the switch), open `/taskflow/debug/stats`, click **Contract drift ON**.
2. Use TaskFlow Web: list, filter, open a task, edit, delete, submit an invalid form.
3. For each symptom, find the cause with the **Network** tab (the Response / Preview panels) and **Redux DevTools** (the `api` slice: what got cached).

## 3. The six, and how they show up

<details><summary>Answers</summary>

| # | Mismatch | Likely symptom (expected from the code; what you see depends on the screen) | Where to see it |
|---|---|---|---|
| 1 | dates `"03/10/2026"` instead of `"2026-10-03"` | "Invalid Date", or wrong "overdue" markers; the date input stays empty | Response: `dueDate` |
| 2 | enums lower-case (`"in_progress"`) | badges without colour, status filters show nothing, the edit form's `<select>` falls back to its first option | Response: `status`, `priority`; Redux DevTools: cached tasks |
| 3 | `total` instead of `totalItems` | the counter shows `(NaN)` or `(undefined)`, pagination disappears | Response: the page envelope |
| 4 | error `{"code","detail"}` instead of `{status,error,message,fieldErrors}` | validation errors no longer appear next to fields; a generic toast instead (the guard `isApiError` rejects the shape) | Response of a 400 |
| 5 | `200 {"ok":true}` instead of `204` for deletes and logout | often **nothing** visible: the client ignores the body. A contract test would flag it | Status column |
| 6 | ids as strings (`"5"`) | selection and "is this the open task?" comparisons fail (`"5" === 5` is false); entity lookups by number miss; links still work (they're strings in URLs anyway) | Response: `id`, `taskId`… |

## 4. The mismatches that were real

Building S46–S48 hit three genuine contract gaps, none of them in the JSON:
- **the cookie path**: `JSESSIONID; Path=/taskflow` behind a proxy that exposes `/api` → fixed with `cookiePathRewrite` (48.02);
- **the request id**: the client sent `X-Request-Id` since Part 1, and the server ignored it → adopted when well-formed (48.08);
- **the CSRF header on every write**: S46's API tests passed without it, until S47 enforced the header the React app had been sending all along.
