## 2. Telling the three endings apart

| Ending | Who invalidates | What we do first | Event |
|---|---|---|---|
| logout | `LogoutServlet` | `removeAttribute(currentUser)` → the registry forgets the session | `LOGOUT` (41.08) |
| disabled by an admin | `AuthenticationFilter` | the same | `SESSION_REVOKED` (42.07) |
| timeout | Tomcat's background thread | nothing: the user is still in the session when `sessionDestroyed` runs | `SESSION_EXPIRED` |

```java
if (session != null) {
  session.removeAttribute(CurrentUser.SESSION_KEY);   // S45: a LOGOUT, so SessionRegistry won't report a timeout (45.09)
  session.invalidate();
}
```

A timeout has no request, so no IP: `LoginServlet` stores `loginIp` in the session at login, for this event.

## 3. Registration

In `AppContextListener` (45.05): `application.addListener(sessions)`. One object implements three listener interfaces: the container calls each method on the matching event.
