## 2. What changed, line by line

| S20 | S21 | Why |
|---|---|---|
| `interface TasksState extends Normalized<Task>` | `extends ReturnType<typeof tasksAdapter.getInitialState>` | the adapter's `EntityState<Task, number>`: the same `{ ids, entities }` |
| a literal initial state | `tasksAdapter.getInitialState({ status, error, … })` | extra fields passed in |
| `normalize` + assigning `ids` and `entities` | `tasksAdapter.setAll(state, tasks)` | the server's full list, in its order |
| `upsert(state, task)` helper | `tasksAdapter.setOne(state, task)` | the server returns the **complete** task: replace, don't merge (21.12 §3) |
| `removeMany(state, ids)` helper | `tasksAdapter.removeOne` / `removeMany` | |
| a loop assigning `status` and `updatedAt` | `tasksAdapter.updateMany(state, open.map(…))` | changes to entities that exist |
| `selectTasks = createSelector(… denormalize …)` | `adapterSelectors.selectAll` | memoized by the adapter |
| `selectTaskById = (state, id) => state.tasks.entities[id]` | `adapterSelectors.selectById` | same behaviour |
| — | `selectTaskCount` (`selectTotal`) | used by the dashboard (21.17) |

The **exported names stay the same** (`selectTasks`, `selectTaskById`, `selectTaskIds`), so no component or selector outside the slice changed. That's the payoff of accessing state only through selectors (21.06).

`normalize.ts` stays: the categories slice still uses it (RTK Query replaces that slice in S22).
