## 3. `sendError`: the right status, and the container's error page

```java
response.sendError(HttpServletResponse.SC_BAD_REQUEST, "Parameter 'id' must be a positive number");
return;
```

- It sets the status, clears the buffer, and renders the container's **error page**: Tomcat's default HTML for now, TaskFlow's own 400/404/500 pages in S43. It **commits** the response (30.18), so nothing may be written after it: hence the `return`.
- **400 vs 404:** a *malformed* request (not a number) is the client's mistake in the request itself → 400. A *well-formed* request for something that doesn't exist → 404. Later, another user's task will also answer 404 (S42).
- The message can reach the error page. Don't put internal details there, and never echo user input into it unescaped.

## 📇 API card: `sendError` vs `setStatus`

| | `sendError(sc[, msg])` | `setStatus(sc)` |
|---|---|---|
| Body | the container's **error page** for that status | **yours**: you write it |
| Commits | yes | no |
| Use | "stop here, show the error page" | "this is the status of the page I'm about to write" (e.g. 400 + the form with errors, 31.05) |
