## 2. Walkthrough

- **`StoreEnhancer<{ getDispatchStats: … }>`**: Redux's enhancer type takes the **extension** as a type argument. The store returned by `createStore(rootReducer, dispatchStatsEnhancer)` is then typed with the extra method, and `store.getDispatchStats()` autocompletes.
- **`timedReducer: typeof reducer`** wraps the reducer: the store only ever sees the wrapped one, so **every** reducer call is timed, including Redux's init call. Only an enhancer can do this; middleware never touches the reducer.
- **`dispatch: typeof store.dispatch`** wraps `dispatch`, and the returned object replaces it: `{ ...store, dispatch, getDispatchStats }`.
- **`getDispatchStats: () => ({ ...stats })`** returns a **copy**. Callers can't mutate the enhancer's internal counters.
- `performance.now()` exists in browsers and in Node (so the Vitest tests run unchanged).

### A detail the test revealed

```ts
const store = createStore(rootReducer, dispatchStatsEnhancer);
store.dispatch(sortChanged('title', 'desc'));
store.dispatch(sortChanged('title', 'asc'));
store.getDispatchStats().dispatches; // 2, not 3
```

Redux's init dispatch happens **inside** `createStore`, with the store's **own** `dispatch`, before our wrapper exists. Our wrapper only counts dispatches that go through the returned store. The reducer timer, however, **did** see the init call, because the reducer was wrapped before the store was created. Where you wrap decides what you observe.

## 3. ✍️ Tests (in `src/app/middleware/middleware.test.ts`)

```ts
describe('dispatchStatsEnhancer (16.06)', () => {
  it('counts dispatches and adds a store method', () => {
    const store = createStore(rootReducer, dispatchStatsEnhancer);
    store.dispatch(sortChanged('title', 'desc'));
    store.dispatch(sortChanged('title', 'asc'));
    const stats = store.getDispatchStats();
    expect(stats.dispatches).toBe(2); // Redux's own init dispatch happens inside createStore, not through our wrapper
    expect(stats.slowestActionType).not.toBeNull();
  });

  it('composes with applyMiddleware (16.05): both layers are active', () => {
    const log = vi.fn();
    // Redux's compose can't infer through generic enhancers (it returns unknown): state the result type.
    const enhancer = compose(applyMiddleware(createLoggerMiddleware(log)), dispatchStatsEnhancer) as typeof dispatchStatsEnhancer;
    const store = createStore(rootReducer, enhancer);
    store.dispatch(sortChanged('title', 'desc'));
    expect(log).toHaveBeenCalledTimes(1);
    expect(store.getDispatchStats().dispatches).toBe(1);
  });
});
```

## 4. Would you ship this?

Not as is. It's a learning tool: it shows everything an enhancer can do in 30 lines. For real performance work, the browser's **Performance** panel and the React Profiler (S21) give better data. But the same technique powers real libraries: the DevTools enhancer wraps the reducer to support time travel, and persistence libraries wrap `createStore` to restore saved state.

## 5. Summary

- An enhancer can wrap the reducer, wrap `dispatch`, and add typed store methods (`StoreEnhancer<Ext>`).
- Where you wrap determines what you see: the wrapped reducer sees the init call; the wrapped dispatch doesn't.
- Composing enhancers needs a type annotation with Redux's `compose`.
