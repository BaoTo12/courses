## 1. Source layout (Maven) → WAR layout

```text
backend/                                   taskflow.war
├── pom.xml                                ├── index.html                 ← PUBLIC (served as-is)
├── db/            (not in the WAR)        ├── static/css/app.css         ← PUBLIC
└── src/                                   └── WEB-INF/                   ← PRIVATE: never served to a browser
    ├── main/java/…      ──compiled──►         ├── web.xml
    ├── main/resources/  ──copied───►          ├── classes/   (your .class files + resources)
    ├── main/webapp/     ──copied───►          └── lib/       (bundled JARs: JSTL, JDBC driver, …)
    │   ├── index.html
    │   ├── static/css/app.css
    │   └── WEB-INF/web.xml
    └── test/java/…      (run by Maven, never in the WAR)
```

A **WAR** (Web ARchive) is a ZIP with a fixed structure the Servlet spec defines. Everything is at the root, **except** `WEB-INF/` (and `META-INF/`).

## 3. The rule that shapes the whole project

> The container serves files from the WAR root, and **refuses** any request for `/WEB-INF/…` or `/META-INF/…`: a **404**. The Servlet specification requires it.

| Request | Result |
|---|---|
| `GET /taskflow/static/css/app.css` | 200: the file |
| `GET /taskflow/WEB-INF/web.xml` | **404** |
| `GET /taskflow/WEB-INF/views/tasks.jsp` | **404**, and that's why all JSPs will live there (S36) |
| `GET /taskflow/WEB-INF/lib/mysql-connector-j-8.4.0.jar` | 404 |

Code **inside** the app can still use those files: a servlet can `forward` to `/WEB-INF/views/tasks.jsp` (S31), and the class loader reads `WEB-INF/classes` and `WEB-INF/lib`. The browser can't.

**Why it matters:** anything placed at the root is downloadable by anyone. A `config.properties` with the database password at the root would be public, and one in `WEB-INF/classes` isn't. JSPs at the root could be requested directly, bypassing the servlet that checks permissions (S36, S42).

## ✅ Recap

A WAR is a ZIP. The root is public, and `WEB-INF/` is private but usable by the app. Secrets and views go under `WEB-INF`.
