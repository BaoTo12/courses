## 1. The problem in our own code

`TaskForm` (11.05) has two selects that are the same code twice:

```tsx
<FormField label="Status">
  {(control) => (
    <select {...control} className="form-field__input" value={values.status}
      onChange={(e) => { if (isTaskStatus(e.target.value)) setField('status', e.target.value); }}>
      {TASK_STATUSES.map((s) => <option key={s} value={s}>{statusLabel(s)}</option>)}
    </select>
  )}
</FormField>
// …and again for Priority, with isPriority, PRIORITIES and PRIORITY_TEXT
```

Enterprise codebases have dozens of these: a status select, a role select, a country select, a sort-order select. Each copy is a chance to forget the guard and write `setField('status', e.target.value as TaskStatus)`. That cast is a lie (06.09): a browser extension, a DevTools edit or a stale option can put any string in the DOM.

We want **one** component with this contract:

```tsx
<SelectField label="Status" options={TASK_STATUSES} value={values.status}
  getLabel={statusLabel} onChange={(status) => setField('status', status)} />
//                                  ^? TaskStatus, not string
```

## 2. ✍️ Step 1: a generic guard, `isOneOf` (`src/domain/guards.ts`)

We already have `isTaskStatus` and `isPriority`. Both are "is this string in that list?". Generalise it, next to them:

```ts
/**
 * Generic guard built from a runtime list (13B.05): `isOneOf(TASK_STATUSES, x)` narrows x to TaskStatus.
 * `const T` makes an inline array literal infer its literal types: isOneOf(['a', 'b'], x) → x is 'a' | 'b'.
 */
export function isOneOf<const T extends string>(options: readonly T[], value: unknown): value is T {
  return typeof value === 'string' && (options as readonly string[]).includes(value);
}
```

Line by line:
- **`value is T`**: a type predicate (06.08). When it returns `true`, the caller's variable is narrowed to `T`.
- **`<const T extends string>`**: a *const type parameter* (TypeScript 5.0). Without `const`, `isOneOf(['list', 'board'], v)` would infer `T = string` and narrow to nothing useful. With it, `T = 'list' | 'board'`. For `TASK_STATUSES` it changes nothing: that array is already `as const` (06.05).
- **`readonly T[]`**: accepts both mutable arrays and `as const` tuples. A `T[]` parameter would reject `TASK_STATUSES`, because a readonly tuple is not assignable to a mutable array.
- **`(options as readonly string[]).includes(value)`**: the one justified assertion. `Array<T>.includes` only accepts a `T`, and `value` is still a plain `string` here, so we widen the array (safe: a `readonly T[]` IS a `readonly string[]`). This is the same trick `isTaskStatus` already uses.

Pinned by the tests:

```ts
expect(isOneOf(TASK_STATUSES, 'done')).toBe(false);            // case-sensitive: the API's values only
if (isOneOf(TASK_STATUSES, fromUrl)) expectTypeOf(fromUrl).toEqualTypeOf<TaskStatus>();
if (isOneOf(['list', 'board'], inline)) expectTypeOf(inline).toEqualTypeOf<'list' | 'board'>();
```

## 3. ✍️ Step 2: `src/components/forms/SelectField.tsx`

{{file:@reference/snapshots/s13b-end/frontend/src/components/forms/SelectField.tsx:tsx}}

### How the type parameter flows

```text
options={TASK_STATUSES}  ──infers──▶  T = 'TODO' | 'IN_PROGRESS' | 'DONE'
                                        │
      ┌──────────────────┬──────────────┼───────────────────────┐
      ▼                  ▼              ▼                       ▼
value: NoInfer<T>   getLabel(option: T)   onChange(value: T)   <option value={option}>
(checked, not         (statusLabel fits)   (setField('status',
 used for inference)                         status) type-checks)
```

### Design decisions

- **`function SelectField<T extends string>(…)`**: a generic *component* is just a generic function whose props mention `T`. At the call site you never write `<SelectField<TaskStatus> …>`: TypeScript infers `T` from the props, exactly like it infers `T` for `useState(0)`.
- **`T extends string`**: `<option value>` and `e.target.value` are strings, so non-string unions (numbers, objects) make no sense here. The constraint documents that and rejects `options={[1, 2]}`.
- **`NoInfer<T>` on `value`** (TypeScript 5.4). Without it, `value` is a *second inference site*: TypeScript collects `'BLOCKED'` as a candidate for `T` alongside the options, which is not what we mean ("the options define `T`; the value must be one of them"). `NoInfer` removes `value` from inference: `T` comes from `options` only, and `value` is merely **checked** against it. The test pins the result:
  ```tsx
  // @ts-expect-error: 'BLOCKED' is not a TaskStatus; NoInfer stops it from widening T
  <SelectField label="Status" options={TASK_STATUSES} value="BLOCKED" getLabel={statusLabel} onChange={noop} />
  ```
- **`extends NativeSelectProps`**: callers can still pass `disabled`, `required`, `name`, `autoFocus`, `aria-*`… (13B.03). The props SelectField owns are removed with `Omit` first, so nobody can pass a conflicting `value` or `onChange` with the DOM's signature.
- **`'id'` is omitted too**: `FormField` generates the id with `useId` and wires the label to it. Letting callers override it would silently break the `<label for>` link.
- **`{...rest}` before `{...control}`**: the later spread wins. Accessibility wiring (`id`, `aria-invalid`, `aria-describedby`) must not be overridable by accident.
- **The guard in `onChange`** is the reason this component exists: the DOM hands us `string`; the callback promises `T`. `isOneOf` is the bridge, so no `as` appears anywhere.

## 4. ✍️ Step 3: use it in `TaskForm`

Remove the `isPriority, isTaskStatus` import, import `SelectField`, and replace both `FormField` + `select` blocks:

```tsx
{/* 13B.05: one generic component; T = TaskStatus, then T = Priority, inferred from `options` */}
<SelectField
  label="Status"
  options={TASK_STATUSES}
  value={values.status}
  getLabel={statusLabel}
  onChange={(status) => setField('status', status)}
/>

<SelectField
  label="Priority"
  options={PRIORITIES}
  value={values.priority}
  getLabel={(priority) => PRIORITY_TEXT[priority]}
  onChange={(priority) => setField('priority', priority)}
/>
```

Hover `status` in your editor: it's `"TODO" | "IN_PROGRESS" | "DONE"`. And `setField('status', status)` still uses 11.05's `setField<K extends keyof TaskFormValues>(field: K, value: TaskFormValues[K])`, so passing a `priority` to the `'status'` field is a compile error. Two generics cooperate: one infers from `options`, the other checks the value against the form's field type.

## 5. Tests (`src/components/react-types.test.tsx`, excerpt)

```tsx
it('renders every option with its label and selects the value', () => {
  const html = renderToStaticMarkup(
    <SelectField label="Status" options={TASK_STATUSES} value="IN_PROGRESS" getLabel={statusLabel} onChange={noop} />,
  );
  expect(html).toContain('<option value="TODO">To do</option>');
  expect(html).toContain('<option value="IN_PROGRESS" selected="">In progress</option>');
  expect(html).toMatch(/<label class="form-field__label" for="([^"]+)">Status<\/label><select id="\1"/);
});
```

- **`renderToStaticMarkup`** (from `react-dom/server`) renders a component to an HTML string, with hooks (`useId`, `useState`) working normally. No browser, no jsdom. It's the cheapest way to test *what a component renders*. (Testing *interaction*, like clicking, needs a DOM: S27.)
- The regex with a back-reference (`\1`) checks that the label's `for` equals the select's `id`, whatever `useId` generated.

The compile-time half is explained in 13B.14.

## 8. Summary

- A generic component is a generic function; `T` is inferred from props, never written at the call site.
- Put the inference on the prop that *defines* the set (`options`); `NoInfer` on props that must only be *checked* (`value`).
- DOM values are strings: a generic guard (`isOneOf`) turns them into your union without `as`.
- `Omit` the native props you take over; spread accessibility wiring last.
