## 1. The selector (end of `src/features/categories/categoriesSlice.ts`)

```ts
export interface TaskCountsByCategory {
  byCategory: Record<number, number>;
  uncategorized: number;
}

/**
 * Task counts per category (19.11), MEMOISED on the task list: the same object until tasks change,
 * so the sidebar doesn't re-render for unrelated actions (toasts, sort preference…).
 */
export const selectTaskCountsByCategory = createSelector([selectTasks], (tasks): TaskCountsByCategory => {
  const byCategory: Record<number, number> = {};
  let uncategorized = 0;
  for (const task of tasks) {
    if (task.categoryId === null) uncategorized += 1;
    else byCategory[task.categoryId] = (byCategory[task.categoryId] ?? 0) + 1;
  }
  return { byCategory, uncategorized };
});
```

- **One pass** over the tasks, O(n), instead of one `filter` per category (O(n × categories)).
- **Built on `selectTasks`**, which is itself memoised: the chain recomputes only when `ids` or `entities` change.
- It lives in the **categories** slice file because it answers a question about categories. It imports `selectTasks` from the tasks slice: selectors may read across slices (reducers may not, 15.10).

## 3. Parsing the URL (`src/pages/list-link.ts`)

```ts
/** `?category=` from the URL: a positive integer, or null (all categories). Validated like any input (12.03). */
export function parseCategoryParam(raw: string | null): number | null {
  return parseTaskId(raw ?? undefined); // same rule as task ids: digits only, safe, > 0
}
```

Tested with `'4'` → 4 and `null`, `''`, `'abc'`, `'-1'`, `'0'`, `'2.5'` → `null`.

## 4. Filtering (`src/domain/task-utils.ts`)

```ts
export function filterTasks(tasks: readonly Task[], { status, priority, categoryId, q }: TaskFilter = {}): Task[] {
  const query = q?.trim().toLowerCase();
  return tasks.filter(
    (task) =>
      (!status || task.status === status) &&
      (!priority || task.priority === priority) &&
      (categoryId === undefined || task.categoryId === categoryId) &&
      (!query || task.title.toLowerCase().includes(query)),
  );
}
```

`categoryId === undefined`, not `!categoryId`: ids are numbers, and a falsy check would treat a hypothetical category 0 as "no filter". Be explicit with numbers.

## 7. Common wrong approaches

| Approach | Problem |
|---|---|
| Storing counts in the categories slice and updating them in reducers | Derived data in state (15.01): every task action must remember to update the counts. |
| `categories.map((c) => tasks.filter((t) => t.categoryId === c.id).length)` in render | Correct, but O(n × m) on every render, and no memoisation. |
| Selecting `Object.entries(state.categories.entities)` | Loses the server's order (and returns a new array every time: 17.04). Use `ids`. |
| A `useState` for the selected category | Lost on reload, not shareable, out of sync with Back/Forward (12.03). |
| `if (!categoryId)` in `filterTasks` | Treats 0 as "no filter". |
