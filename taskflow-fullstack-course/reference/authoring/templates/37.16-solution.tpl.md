## 1. The service owns the rule

{{file:@reference/taskflow/backend/src/main/java/com/taskflow/service/CategoryService.java:java}}

`delete` returns **what happened** (an enum), not a boolean: "not found" and "in use" need different answers (404 vs a flash). The schema alone would allow the delete (`ON DELETE SET NULL`), so the rule is a business decision and belongs in the service, where the JSON API will obey it too.

### Wrong approaches

| Attempt | Problem |
|---|---|
| deleting and letting the tasks' category become `NULL` silently | the business rule says no; the user loses information without being told |
| checking "in use" in the servlet | the JSON API (S46) would need to copy it |
| a GET link `/categories/delete?id=4` | 37.02: prefetchers, `<img>` tags, and CSRF without even a form |
| redirecting after a duplicate name | the error and the typed name are lost (37.17) |
| `${counts[category.id]}` with a `Map<Integer, …>` | EL passes a `Long`: no match, the count is blank (34.10 §3) |
