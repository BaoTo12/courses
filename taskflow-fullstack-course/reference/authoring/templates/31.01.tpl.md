## 1. Provided: the model and an in-memory store

Until the database arrives (S36), tasks live in memory. Read these; you don't write them.

✍️ `com/taskflow/model/Task.java`, `TaskStatus.java`, `Priority.java` (provided): a JavaBean with getters and setters (why that shape matters: S34), and two enums with a safe `parse(String)` that returns `null` for anything unknown.

✍️ `com/taskflow/store/InMemoryTaskStore.java` (provided)

{{file:@reference/taskflow/backend/src/main/java/com/taskflow/store/InMemoryTaskStore.java:java}}

What to notice: it's **thread-safe** (servlets are called concurrently, 30.05), it returns **copies**, and there's **one shared instance** (`shared()`). S38 replaces the static singleton with an application attribute set by a listener, and S36 replaces the store with a DAO.

## 2. The page frame, written once

✍️ `com/taskflow/web/Layout.java`

{{file:@reference/taskflow/backend/src/main/java/com/taskflow/web/Layout.java:java}}

- It sets the content type **first**, then gets the writer (30.17).
- Links are built from `request.getContextPath()`, so they work at `/taskflow` or anywhere else (28.10, 31.11).
- The title is **escaped**: a task title is user input.

## 3. The list servlet

✍️ `com/taskflow/web/tasks/TaskListServlet.java`

{{file:@reference/taskflow/backend/src/main/java/com/taskflow/web/tasks/TaskListServlet.java:java}}

- **`TaskStatus.parse(request.getParameter("status"))`**: `null` for a missing or unknown value → show everything. A **filter** that doesn't match is ignored, while an unknown **id** is a 404 (31.03). That's a design decision; the test pins it (`?status=DELETED` → 200).
- **Every title is escaped.** The test creates a task titled `<img src=x onerror=alert(1)>` and checks the list shows it as text.
- The **toggle and delete buttons** are tiny POST forms, not links (29.03). They're 31.13's Your Turn, shown here because this is the file at the end of the section.
- The store is a **field**: safe, because it's thread-safe and shared on purpose (30.05 §3).

## 4. Feel the pain

Count what's wrong with writing HTML this way:

1. HTML is buried in Java strings: `\"` everywhere, no syntax highlighting, no HTML validation.
2. A designer can't change the page without editing Java, recompiling and redeploying.
3. One forgotten `Html.escape` = XSS.
4. The logic ("which tasks?") and the presentation ("which `<td>`?") are tangled in one method.

S32 moves the HTML into a JSP, and S36 separates the "which tasks" part cleanly (MVC).

`http://localhost:8080/taskflow/tasks` shows four seeded tasks. `?status=DONE` shows one. `mvn package` → `S31TaskServletsTest` passes.
