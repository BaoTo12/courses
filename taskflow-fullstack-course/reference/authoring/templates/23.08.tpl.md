## 1. `injectEndpoints`: one API, many files

`apiSlice.ts` grows with every feature. Splitting it into several `createApi`s would break tags and double the middleware (22.02). Instead, feature files **inject** endpoints into the one API:

✍️ `src/features/comments/commentsApi.ts`

{{file:features/comments/commentsApi.ts:ts}}

- `apiSlice.injectEndpoints({ endpoints })` returns the **same** API object, typed with the extra endpoints. Import hooks and `endpoints` from **`commentsApi`**: `apiSlice.endpoints.getComments` doesn't exist in `apiSlice`'s *type*.
- Tag types must still be declared in the base `createApi` (`tagTypes: ['Task', 'Category', 'Comment']`). An injected endpoint can't add new ones. (`apiSlice.enhanceEndpoints({ addTagTypes: [...] })` can, when you really need it.)
- It's **code splitting** when the injecting file is lazy-loaded: the endpoints exist only once the feature's chunk runs. In TaskFlow it's organisation for now. S46 lazy-loads the routes.
- Change the imports in `CommentsSection.tsx` and `comments.test.ts` from `../api/apiSlice` to `./commentsApi`.

> ⚠️ An endpoint name injected twice is **ignored**, with a console error in development, unless you pass `overrideExisting: true`. Keep endpoint names unique across files.

## 2. Prefetching: fetch *before* the user asks

```ts
const prefetchComments = commentsApi.usePrefetch('getComments');   // in TasksPage
<TaskList … onHoverTask={prefetchComments} />                     // mouse enters a card → getComments(id) starts
```

- `usePrefetch(endpointName, options?)` returns `prefetch(arg, options?)`. Calling it starts the query **without subscribing**, like a subscription that ends immediately. The entry is kept for `keepUnusedDataFor` (60 s), which is plenty for the click that follows.
- If the entry already exists and is fresh enough, nothing is sent.

| Option | Meaning |
|---|---|
| `ifOlderThan: n` (seconds) | refetch only if the cached data is older than *n* s; otherwise do nothing |
| `force: true` | always refetch |
| *(neither)* | fetch only if there's no entry yet |

**Why comments and not the task?** `getTask(id)` is already **seeded** from the list (23.06), so prefetching it would do nothing. Comments are the one request left when opening a task. After a hover, the details page shows them with no "Loading comments…".

Outside React: `dispatch(apiSlice.util.prefetch('getTask', 7, { ifOlderThan: 30 }))`.

## 3. What about the quick-find listener?

Since 21.15, quick find uses a listener, a slice and `extra.api.getTasks`: it debounces, cancels, and keeps its own status. With RTK Query, the alternative is a **lazy query**:

```ts
const [search, { data, isFetching }] = useLazyGetTasksQuery();
useEffect(() => { if (debounced) void search({ q: debounced, size: 5 }, true); }, [debounced, search]);
```

| | Listener + slice (current) | Lazy query |
|---|---|---|
| Debounce and cancel stale requests | ✅ built in (`cancelActiveListeners`, `signal`) | debounce in the component; stale responses are ignored per entry |
| Cache | none (throw-away hits) | one entry per search text; repeated searches are instant |
| Invalidation | results can go stale during a session | `TASK_LIST`/id tags refresh them automatically |
| Code | more, but already written and tested | less |

Both are valid. TaskFlow keeps the listener: it's the S21 lesson, and search hits are throw-away. For a search **page** (bookmarkable, refreshable), the lazy query, or a normal query keyed by the URL, would win.

## 📇 API card: `injectEndpoints` · `usePrefetch` · `util.prefetch`

| API | Signature | Returns |
|---|---|---|
| `api.injectEndpoints` | `({ endpoints: (build) => ({…}), overrideExisting?: boolean \| 'throw' })` | the same API, with the new endpoints and hooks in its type |
| `api.enhanceEndpoints` | `({ addTagTypes?, endpoints?: { name: { providesTags?, … } } })` | adds tag types or overrides endpoint options (e.g. for generated APIs) |
| `api.usePrefetch` | `(endpointName, { ifOlderThan?, force? }?)` | `(arg, { ifOlderThan?, force? }?) => void` |
| `api.util.prefetch` | `(endpointName, arg, { ifOlderThan?, force? })` | a thunk |

**When to use `injectEndpoints`:** as soon as more than one feature has endpoints, and always with lazy-loaded routes.

**When to prefetch:** a highly likely next step (hover, focus, "next page" of a pager), where the request is cheap.

**When not to prefetch:** on every mouse move over a long list of expensive requests. Debounce the hover, or prefetch on `focus`/`pointerdown` instead.

**Common mistakes:**
- Importing an injected endpoint's hook from the base file. It's undefined at runtime if the injecting module never ran.
- A second `createApi` "for comments". Its tags can't reach the tasks API.
- `prefetch` in render. Use event handlers or effects.
