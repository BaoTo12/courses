# Lecture 36.04 · Where Objects Live: Create Services Once (a Listener), Share Them via `ServletContext`

> **Section:** S36 · **Type:** 📖 Theory + 🛠 · **Track:** ★ Core · **Time:** ~30 minutes
> Verified: every `TomcatTest` subclass: the listener builds the pool and the service before the first request

---

## 1. The question

A `TaskService` needs DAOs, which need a `DataSource`, which is a pool of up to 10 connections. Who creates them, when, how many times, and how do servlets get them?

| Option | Problem |
|---|---|
| `new TaskService(new TaskDao(DataSourceProvider.create()), …)` in each `doGet` | a **new pool per request**: hundreds of connections, then MySQL refuses more |
| in each servlet's `init()` | one pool **per servlet**: 6 servlets × 10 connections, and nobody closes them |
| a `static` singleton (S31's `InMemoryTaskStore.shared()`) | lives in the class, not the application: survives redeploys in odd ways, can't be closed at shutdown, hard to replace in tests |
| **created once at application startup, stored in application scope, closed at shutdown** | ✅ |

## 2. `ServletContextListener`: the application's lifecycle

```java
public interface ServletContextListener extends EventListener {
  default void contextInitialized(ServletContextEvent sce) {}   // before ANY filter or servlet serves a request
  default void contextDestroyed(ServletContextEvent sce) {}     // after the last request, on undeploy/shutdown
}
```

Register it with `@WebListener` (scanned like `@WebServlet`) or `<listener>` in `web.xml`. If `contextInitialized` throws, **the application doesn't start**: Tomcat logs the error and the context stays unavailable (404). That's a feature: better no app than an app that 500s on every page because MySQL is unreachable.

## 3. TaskFlow's listener

✍️ `src/main/java/com/taskflow/web/AppContextListener.java`

{{file:@reference/taskflow/backend/src/main/java/com/taskflow/web/AppContextListener.java:java}}

- **Wiring by hand:** `new TaskDao(entityManagerFactory)`… (the data layer's internals are provided, 36.03). This is what a dependency-injection container (Spring, CDI) does for you. Here it's 5 lines, and you can see every dependency.
- **The attribute name** is the class name, a common convention that avoids collisions.
- **Shutdown:** closing the data layer and the pool releases the database connections; the last line stops a thread the MySQL driver starts. Without it, Tomcat logs *"appears to have started a thread named [mysql-cj-abandoned-connection-cleanup] but has failed to stop it"* on every redeploy: a class-loader memory leak.

## 4. Servlets fetch it in `init()`

```java
private TaskService service;

@Override
public void init() {
  service = AppContextListener.taskService(getServletContext());
}
```

Storing it in a servlet **field** is safe, although servlets are shared by all threads (30.05): the field is written once in `init()`, and `TaskService` has **no per-request state** (its fields are the DAOs and a `Clock`, never "the current task"). The rule from 30.05 still holds: request data in local variables, never in fields.

## ✅ Recap

Long-lived objects are created once in `contextInitialized`, shared through `ServletContext` attributes, fetched in `init()`, and closed in `contextDestroyed`.
