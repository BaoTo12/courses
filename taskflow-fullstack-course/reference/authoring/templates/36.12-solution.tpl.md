## 1. The provided allow-list (read it)

{{file:@reference/taskflow/backend/src/main/java/com/taskflow/dao/TaskSort.java:java}}

- `orderBy()` is **package-private**: the controller and the view see `param` and `label`; only the data layer sees query text.
- `parse` compares against the known values. There's no `valueOf(param.toUpperCase())`, which would throw on unknown input (a 500).

## 2. The controller

{{file:@reference/taskflow/backend/src/main/java/com/taskflow/web/tasks/TaskListServlet.java:java}}

Every parameter is turned into a **typed** value (an enum, a `Long`, a trimmed string or `null`) before anything else sees it. An invalid category or sort isn't an error: filters are optional, so the page falls back to "all" and "default".

## 3. The view

{{file:@reference/taskflow/backend/src/main/webapp/WEB-INF/views/tasks/list.jsp:jsp}}

- `category.id == categoryFilter`: `long` vs `Long`/`null` → `false` when no filter (34.13).
- `option == sort`: two enums.
- `<c:if test="${sort != 'ID'}">`: the default isn't repeated in URLs.
- The category **names** come from the database, so they're escaped with `<c:out>`.

### Wrong approaches

| Attempt | Problem |
|---|---|
| passing `request.getParameter("sort")` down to be pasted into the query | injectable (36.08) |
| `TaskSort.valueOf(param.toUpperCase())` | unknown input → `IllegalArgumentException` → 500 |
| `Long.parseLong(request.getParameter("category"))` | `?category=abc` → 500 (31.16) |
| filtering by category in the controller after loading every task | works, but it loads the whole table for every page view |
