## 1. The listener

{{file:@reference/taskflow/backend/src/main/java/com/taskflow/web/SlowRequestListener.java:java}}

| Requirement | How |
|---|---|
| per-request start time | a **request attribute**, with a class-qualified name so it can't collide |
| thread safety | no field is written after construction; the request is per-thread; `AuditService` is stateless |
| the service | looked up from the context in `requestDestroyed` (a `@WebListener` has no constructor arguments; `addListener` in `AppContextListener` would be the other option, 45.09) |
| a failed startup | `audit == null` → skip, rather than throwing from a listener |

## 2. Configuration

```xml
<context-param>
  <param-name>taskflow.slowRequestMillis</param-name>
  <param-value>500</param-value>
</context-param>
```

and `"SLOW_REQUEST"` added to `AuditService.TYPES` (the page's filter).

## 3. What it caught

During the test run, the first requests of each page were slow: Jasper compiling `list.jsp` or `audit.jsp` on first use (`GET /taskflow/admin/audit 1175ms`, `GET /taskflow/tasks 966ms` in the log). That's real information: precompiling JSPs at build time (the `jspc` Maven plugin) removes it in production.

### Wrong approaches

| Attempt | Problem |
|---|---|
| `private long started;` in the listener | one instance for all requests: 45.03's race |
| `ThreadLocal<Long>` | works, but must be cleared in `requestDestroyed`, or the pooled thread carries it into the next request (and it breaks with async) |
| a `Map<ServletRequest, Long>` field | needs cleanup and a concurrent map for no benefit over a request attribute |
| measuring in a servlet | only that servlet's requests |
| logging the query string | may contain personal data; the method and path are enough (43.11) |
