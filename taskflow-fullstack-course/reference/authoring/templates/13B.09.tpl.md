# Lecture 13B.09 · 🛠 Build: `Button` with `ref`, and a Typed `ButtonLink`

> **Section:** S13B · **Type:** 🛠 Build · **Track:** ★ Core · **Time:** ~40 minutes
> **Project feature:** `Button` accepts every native prop including `ref`; `ButtonLink` replaces five hand-written `className="btn btn--… btn--sm"` links; one `buttonClasses()` helper owns the class logic
> Verified: `src/components/react-types.test.tsx` (class building, `ButtonLink` markup inside a `MemoryRouter`, `ref` + native props accepted, `variant` typo and missing `to` rejected); `tsc -b`, `npm run lint`

---

## 1. Two smells in the current code

**Smell 1: the same class string, typed by hand, five times.**

```tsx
<Link className="btn btn--primary btn--sm" to="/tasks/new">+ New task</Link>        {/* TasksPage */}
<Link className="btn btn--secondary btn--sm" to={`/tasks/${task.id}/edit`} …>Edit</Link> {/* TaskCard */}
{/* …and NotFoundPage, twice in TaskDetailsPage */}
```

`Button` turned the BEM modifiers into a checked API in 07.06 (`variant="primay"` is an error). Links styled as buttons bypass that check: `className="btn btn--primay"` compiles and renders an unstyled link.

**Smell 2: `Button` can't take a `ref`.** Its props were `ButtonHTMLAttributes<HTMLButtonElement>`, the attribute list **without** `ref`. The day someone needs to focus a button (after closing a dialog, after an error), they'd have to rewrite `Button`. In an enterprise design system, *every* primitive component forwards `ref`: focus management is an accessibility requirement, not a nice-to-have.

## 2. ✍️ Step 1: one owner for the class logic (`src/components/button-classes.ts`)

{{file:@reference/snapshots/s13b-end/frontend/src/components/button-classes.ts:ts}}

- **A plain `.ts` module**, because both `Button.tsx` and `ButtonLink.tsx` need it, and a component file should export only components (Fast Refresh, 07.06).
- **`ButtonStyleProps` is exported**: it's the reusable "style contract" both components intersect with their element's props (13B.03).
- Defaults live in the destructuring (`variant = 'secondary'`), so `buttonClasses({})` gives `'btn btn--secondary'` (pinned by a test).

## 3. ✍️ Step 2: `Button` (`src/components/Button.tsx`)

{{file:@reference/snapshots/s13b-end/frontend/src/components/Button.tsx:tsx}}

What changed and why:

| Before (07.06) | After | Why |
|---|---|---|
| `interface ButtonProps extends ButtonHTMLAttributes<HTMLButtonElement>` | `type ButtonProps = ComponentPropsWithRef<'button'> & ButtonStyleProps` | Reads the props from the **element** (`'button'`), including `ref` (13B.03) |
| no `ref` | `ref` arrives in `...rest` and is spread onto `<button>` | React 19: `ref` is an ordinary prop for function components. No `forwardRef` (13B.17 shows the old way) |
| class logic inline | `buttonClasses(…)` | shared with `ButtonLink` |
| `ButtonProps` not exported | exported | other components (a `ConfirmButton`, an `IconButton`) can extend it |

`type` instead of `interface`: an intersection of two existing types reads naturally as `A & B`. `interface ButtonProps extends ComponentPropsWithRef<'button'>, ButtonStyleProps {}` would work too; enterprise style guides usually pick one convention per purpose (13B.13).

The call sites don't change. Now this compiles too:

```tsx
const retryRef = useRef<HTMLButtonElement>(null);
<Button ref={retryRef} onClick={reload}>Try again</Button>
// later, in an effect or handler: retryRef.current?.focus();
```

## 4. ✍️ Step 3: `ButtonLink` (`src/components/ButtonLink.tsx`)

{{file:@reference/snapshots/s13b-end/frontend/src/components/ButtonLink.tsx:tsx}}

- **`ComponentProps<typeof Link>`** reads the props from React Router's `Link` *component* (13B.03): `to` (required), `replace`, `state`, every `<a>` attribute… We re-declare none of them. When React Router adds a prop in a minor version, `ButtonLink` gets it for free; when it removes one, our call sites fail to compile. That's the right direction of coupling.
- **`typeof Link`**: `Link` is a *value* (a component). `ComponentProps` needs a *type*, and `typeof` turns the value into its type (06.05).
- **Semantics stay right**: it renders an `<a href>`, so middle-click, "open in new tab" and screen readers treat it as a link (12.02 §7). Only the look is a button's.

## 5. ✍️ Step 4: replace the hand-written links

In `TasksPage`, `TaskCard`, `TaskDetailsPage` (two) and `NotFoundPage`:

```tsx
// before
<Link className="btn btn--primary btn--sm" to="/tasks/new">+ New task</Link>
// after
<ButtonLink variant="primary" size="sm" to="/tasks/new">+ New task</ButtonLink>

// before
<Link className="btn btn--secondary btn--sm" to={`/tasks/${task.id}/edit`} state={linkState}>Edit</Link>
// after (secondary is the default variant)
<ButtonLink size="sm" to={`/tasks/${task.id}/edit`} state={linkState}>Edit</ButtonLink>
```

Remove the `Link` import where it's no longer used (`noUnusedLocals` will tell you). `TaskCard` and `TaskDetailsPage` still use `Link` for the title and the breadcrumb.

## 6. Tests (`src/components/react-types.test.tsx`, excerpt)

```tsx
it('ButtonLink renders a real link with button classes', () => {
  const html = renderToStaticMarkup(
    <MemoryRouter>
      <ButtonLink variant="primary" size="sm" to="/tasks/new">+ New task</ButtonLink>
    </MemoryRouter>,
  );
  expect(html).toBe('<a class="btn btn--primary btn--sm" href="/tasks/new" data-discover="true">+ New task</a>');
});
```

- **`MemoryRouter`**: `Link` needs a router above it (12.02's runtime error). `MemoryRouter` keeps the location in memory, perfect for tests.
- **`data-discover="true"`**: React Router 8 adds this attribute to rendered links (it's used by its framework mode). Harmless here; the test pins the exact output, so an upgrade that changes the markup is noticed.

And the compile-time half:

```tsx
{/* @ts-expect-error: typo in a variant is a compile error */}
<Button variant="primay">Save</Button>
{/* @ts-expect-error: ButtonLink requires Link's `to` prop */}
<ButtonLink variant="primary">Nowhere</ButtonLink>
```

## 8. Summary

- Derive props from the element (`ComponentPropsWithRef<'button'>`) or the component (`ComponentProps<typeof Link>`); add only what's yours.
- React 19: `ref` is a prop. A design-system primitive that drops it is a bug waiting for the first focus requirement.
- One helper owns the class logic; typed style props replace hand-typed class strings.
