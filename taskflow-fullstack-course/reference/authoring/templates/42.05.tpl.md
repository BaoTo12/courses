# Lecture 42.05 · 🛡 Defend: The Ownership Check in `TaskService`; Why the Filter Can't Do It

> **Section:** S42 · **Type:** 🛡 Defend · **Track:** ★ Core · **Time:** ~45 minutes
> **Project feature:** users can only reach their own tasks; admins can reach all of them.
> Verified: `S42AuthorizationTest.someoneElsesTaskLooksLikeItDoesNotExist` (view, edit page, edit POST, toggle, comment, delete → 404; audited; the task is untouched)

---

## 1. Where the rule belongs

| Layer | Knows the user? | Knows the task's owner? | Runs for every path to the data? |
|---|---|---|---|
| filter | ✅ | ❌ (it would have to load the task) | only if every URL is listed |
| controller | ✅ | ✅ after loading | only if every controller remembers |
| **service** | ✅ (passed in) | ✅ | ✅: every controller, and later the JSON API (S46), goes through it |

So `TaskService` takes the **caller** in every use case and decides there.

## 3. The controllers pass the caller

```java
Optional<TaskDetails> details = service.details(id, CurrentUser.get(request)); // S42: someone else's task → AccessDeniedException
```

The same one-argument change in `TaskEditServlet`, `TaskToggleServlet`, `TaskDeleteServlet`, `TaskCommentServlet`, `TaskLatestServlet`. None of them contains the rule.

## 4. Turning the decision into a response: the filter's second half

In `AuthorizationFilter` (42.03):

```java
try {
  chain.doFilter(req, res);
} catch (AccessDeniedException e) {
  denied(request, user, e.getMessage());        // audit: ACCESS_DENIED, alice, "task 23"
  if (response.isCommitted()) throw e;
  response.resetBuffer();
  response.sendError(HttpServletResponse.SC_NOT_FOUND);
}
```

- The exception travels **up** from the service, through the controller, out of `chain.doFilter` (40.02: the chain is nested calls), into the filter.
- **404, not 403:** "not yours" and "doesn't exist" get the same answer, so ids can't be probed for existence.
- One `catch` covers every controller. S43 generalises it into an exception-to-status mapping.
