## 1. The contract

`combineReducers({ tasks: tasksReducer, listPrefs: listPrefsReducer, ui: uiReducer })` returns a root reducer that:
1. calls **every** slice reducer with **its** part of the state and the **same** action;
2. builds the root object from the results;
3. returns the **previous root object** if no slice changed (15.08 §3);
4. on the first call (`state === undefined`), lets each slice produce its initial state.

## 2. ✍️ `src/app/combine-slice-reducers.ts`

{{file:app/combine-slice-reducers.ts:ts}}

### The runtime logic (the part that matters)

The loop is the whole algorithm: for each key, call the slice reducer with `state?.[key]` (which is `undefined` on the first call, so its default parameter kicks in), store the result, and remember whether **any** slice returned a different reference. At the end, return the new object only if something changed.

Redux's real implementation (read `node_modules/redux/dist/redux.mjs`, function `combineReducers`) does the same, plus development-only checks:
- a slice returning `undefined` → a descriptive error (15.15);
- unexpected keys in the state passed in → a warning;
- a startup check that sends each slice the init action **and** a random `@@redux/PROBE_UNKNOWN_ACTION…` action, to make sure every slice returns a state for types it doesn't know.

### The types (the part that's harder than the logic)

My first version typed it as `combineSliceReducers<S, A>(reducers: { [K in keyof S]: SliceReducer<S[K], A> })`, and TypeScript failed to infer `A`. The test file didn't compile (verified): *"Type 'unknown' is not assignable to type 'AppAction'"*. Inferring two type parameters through a mapped type is beyond what TypeScript does. The working version infers from the **reducers themselves**:
- `R extends Record<string, AnySliceReducer>` captures the exact object you pass;
- `CombinedState<R>` maps each key to `ReturnType<R[K]>` (06.03, 06.11);
- `CombinedAction<R>` takes the second parameter type with `Parameters<…>[1]`.

`AnySliceReducer = (state: never, action: never) => unknown` is a trick worth remembering: because parameter types are checked **contravariantly**, a function with `never` parameters is the supertype of every function with the same arity. It's the type-safe way to say "any function of this shape" without `any`.

## 3. ✍️ `src/app/rootReducer.ts`: the real one

{{file:app/rootReducer.ts:ts}}

`RootState = ReturnType<typeof rootReducer>`: the state type is **derived** from the reducers. Add a slice to `combineReducers`, and `RootState` updates itself. That's the pattern the official TypeScript guide recommends, and the one RTK uses in S20 (`ReturnType<typeof store.getState>`).

(`listPrefsReducer` and `uiReducer` are written in 15.12. Until then, combine only `tasks`.)

## 4. ✍️ Prove they behave the same

In `src/app/rootReducer.test.ts`, the comparison test (the whole file is in the 15.13 solution):

```ts
describe('combineSliceReducers (our own, 15.09) behaves like Redux combineReducers', () => {
  const ours = combineSliceReducers(reducers);
  const theirs = combineReducers(reducers);
  const init = { type: '@@init' } as never; // not an AppAction: like Redux's own init action
  const actions = [
    taskSelectionToggled(3),
    sortChanged('priority', 'desc'),
    taskDeleted(3),
    sortChanged('priority', 'desc'),
    loggedOut(),
  ];

  it('produces equal states, and preserves references the same way', () => {
    let a = ours(undefined, init);
    let b = theirs(undefined, init);
    expect(a).toEqual(b);
    for (const action of actions) {
      const nextA = ours(deepFreeze(a), action);
      const nextB = theirs(deepFreeze(b), action);
      expect(nextA).toEqual(nextB);
      expect(nextA === a).toBe(nextB === b); // both return the same object when nothing changed
      a = nextA;
      b = nextB;
    }
  });
});
```

The second `sortChanged('priority', 'desc')` is the interesting step: the sort is already `priority`/`desc`, so `listPrefsReducer` returns its same state, every other slice does too, and **both** combiners return the same root object. Verified: the test passes.

## 5. Summary

- `combineReducers` = call every slice reducer with its part of the state; rebuild the root only if something changed.
- The hard part is the typing: infer state and action types from the reducer object (`ReturnType`, `Parameters`).
- Derive `RootState` from the root reducer; never hand-write it.
