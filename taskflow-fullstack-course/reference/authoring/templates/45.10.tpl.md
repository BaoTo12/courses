`AuditDao.find(type, username, offset, limit)` and `count(type, username)`: newest first, both filters optional, every value a named query parameter. `AuditDao.Event` is a record with getters for EL (`getAt()` → `2026-09-26 22:35:44`, UTC).

## 3. The controller

✍️ `src/main/java/com/taskflow/web/admin/AdminAuditServlet.java`

{{file:@reference/taskflow/backend/src/main/java/com/taskflow/web/admin/AdminAuditServlet.java:java}}

A real bug caught while building it: the first version was `AuditService.TYPES.contains(request.getParameter("type"))`, and `/admin/audit` without a `type` answered **500**. `List.of(…)` collections **reject null** even in `contains` (`NullPointerException`). The fix checks for null first. (The 500 page's reference led straight to the stack trace in the log: 43.10 at work.)

## 4. The view

✍️ `src/main/webapp/WEB-INF/views/admin/audit.jsp`

{{file:@reference/taskflow/backend/src/main/webapp/WEB-INF/views/admin/audit.jsp:jsp}}

- `<t:pagination of="${auditPage}" path="/admin/audit" keep="type,user"/>`: the S44 component, with another page type and other parameters.
- **Escape everything**: `LOGIN_FAIL` rows contain whatever was typed into the username field, so the audit page is a place stored XSS would target (an attacker "logs in" as `<script>…`, an admin opens the log).

The nav gets an **Audit log** link for admins (`nav.audit` in both bundles).

## ✅ Checkpoint

As admin, filter `LOGIN_FAIL`: every failed attempt, newest first, with IPs. Go to page 2: the filter stays.
