# Lecture 09.02 · How styled-components Works Internally: Tagged Templates → Class Names → `<style>` Injection

> **Section:** S09 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~25 minutes

---

## 1. Recap: tagged templates (04.09)

`` styled.button`…${fn}…` `` is a **function call**: `styled.button(strings, fn)`. The tag receives the static CSS text and your interpolations **as values**, including **functions**. You built a 15-line version of this idea in 04.09.

## 2. What `styled.button` returns

A **React component**. Defining it does very little: it stores your template pieces and assigns a stable **component ID**.

```tsx
const Segment = styled.span<{ $filled: boolean; $color: string }>`
  flex: 1;
  background: ${({ $filled, $color }) => ($filled ? $color : 'var(--color-border)')};
`;
```

## 3. What happens when it renders

```text
<Segment $filled $color="#ef4444" />
   │
   ├─ 1. Call every interpolation with the props (and theme):
   │      background: #ef4444
   ├─ 2. Build the final CSS text for THIS combination of props
   ├─ 3. Hash the CSS text → a short class name, e.g. "lkDdMB"
   ├─ 4. If that class isn't in the stylesheet yet, INSERT the rule into the <style data-styled> tag
   └─ 5. Render the real element: <span class="sc-hKwBjT lkDdMB">
```

Two class names, both observed in TaskFlow's reference app:
- **`sc-…` (e.g. `sc-hKwBjT`)**: the **component ID**, the same for every instance of `Segment`. It's used for targeting (`${Segment}:hover &`, 09.10) and debugging.
- **The hash (e.g. `lkDdMB`)**: identifies the **computed style**. Different props that produce **different CSS** give **different classes**; identical CSS reuses the same class.

So a `PriorityBar` renders three segments. Filled and empty segments produce two distinct CSS results, and therefore two classes, shared by all bars on the page.

## 4. See it in DevTools

1. Elements: select a priority bar segment. Its `class` looks like `sc-hKwBjT lkDdMB`.
2. Elements, inside `<head>`: a `<style data-styled="active" data-styled-version="6.5.3">` tag.
3. That tag looks **empty** in the Elements panel. styled-components inserts rules through the **CSSOM API** (`sheet.insertRule`), which is faster than writing text. In the reference app's dev server, the tag's `textContent` was `""`, but `style.sheet.cssRules.length` was **13**. The **Styles** pane still shows the rules for the selected element, and you can list them from the console: `[...document.querySelector('style[data-styled]').sheet.cssRules].map(r => r.cssText)`.

## 5. Consequences you should know

- **Styles are created lazily**: a rule appears only when a component with those props first renders.
- **Continuous values create many classes**: if an interpolation produces a new value on every render (e.g. a drag position), styled-components generates a new class **each time**, which is slow and grows the stylesheet. Use the `style` prop or a CSS custom property for high-frequency values (09.11).
- **Order of injection** affects the cascade when styled rules and global SCSS rules have equal specificity (10.15).
- **Everything happens in the browser**: the JSP portal, which renders HTML on the server with no React, can't use any of this (10.08).

## 6. Summary

- `styled.x` returns a component; rendering evaluates interpolations with props → CSS text → hash → injected rule → class names.
- Each element gets a stable component ID class (`sc-…`) plus a style-hash class.
- Rules are inserted lazily, often via CSSOM (so the `<style>` tag may look empty).
- Frequently changing values create many classes: use `style` or custom properties for those.
