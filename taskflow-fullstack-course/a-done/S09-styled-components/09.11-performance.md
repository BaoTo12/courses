# Lecture 09.11 · Performance Rules: Never Define Styled Components in Render; Interpolation vs `style`

> **Section:** S09 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~20 minutes

---

## Rule 1: define styled components at module level, never inside a component

```tsx
// ❌
function SearchField() {
  const [value, setValue] = useState('');
  const Input = styled.input`border: 2px solid hotpink;`;   // a NEW component type every render
  return <Input value={value} onChange={(e) => setValue(e.target.value)} />;
}
```

Every render creates a **new component type**. React's reconciliation (07.04) sees a *different type* at the same position, so it **unmounts** the old `<input>` and **mounts** a new one on every keystroke. Observed in TaskFlow's reference app after typing one character:

```text
sameElement: false     ← a brand-new <input> DOM node
activeTag: "BODY"      ← focus lost: the user must click again after every keystroke
```

styled-components also warns in development:

```text
The component styled.input with the id of "sc-furwPO" has been created dynamically.
You may see this warning because you've called styled inside another component.
To resolve this only create new StyledComponents outside of any render method and function component.
```

Fix: move `const Input = styled.input…` **outside** the function. Dynamic values go through **props**, not by redefining the component. You'll debug exactly this in 09.15.

## Rule 2: high-frequency values → `style` or a CSS custom property

Each distinct CSS result creates a new class and a new injected rule (09.02). For values that change **continuously** (drag positions, scroll progress, animation frames, mouse coordinates), interpolation floods the stylesheet:

```tsx
// ❌ a new CSS class for every pixel of movement
const Draggable = styled.div<{ $x: number; $y: number }>`
  transform: translate(${(p) => p.$x}px, ${(p) => p.$y}px);
`;

// ✅ static class + inline style for the changing part
const Draggable = styled.div`
  position: absolute;
  cursor: grab;
`;
<Draggable style={{ transform: `translate(${x}px, ${y}px)` }} />

// ✅ or a custom property the static CSS reads
const Bar = styled.div`
  width: var(--progress);
`;
<Bar style={{ '--progress': `${percent}%` } as React.CSSProperties} />
```

Interpolation is perfect for **a small, finite set of values** (variants, sizes, priorities, on/off states).

## Rule 3: keep interpolation functions cheap

They run on **every render** of every instance. Compute expensive values once (module constants, `useMemo` in the parent) and pass the result as a prop.

## Summary

- Styled components at **module level**; dynamic values via props.
- Continuous values → `style` prop or CSS custom properties; finite values → interpolation.
- Keep interpolations cheap.
