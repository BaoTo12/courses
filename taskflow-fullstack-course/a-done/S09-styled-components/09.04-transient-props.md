# Lecture 09.04 · Props-Based Styling and Transient Props (`$variant`) in v6

> **Section:** S09 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~20 minutes

---

## 1. Props flow into styles

Every prop you pass to a styled component is available in its interpolations:

```tsx
const Circle = styled.span<{ $size: number; $color: string }>`
  width: ${({ $size }) => $size}px;
  height: ${({ $size }) => $size}px;
  background: ${({ $color }) => $color};
`;

<Circle $size={32} $color="#4f46e5" />
```

## 2. But where else do the props go?

A styled component renders a real DOM element and **forwards props to it**. For a component wrapping a DOM element, styled-components v6 forwards **all** props by default (v5 filtered them through an HTML attribute list; v6 stopped doing that).

So a styling prop like `variant` ends up **as an HTML attribute**:

```tsx
const Box = styled.div<{ variant: 'a' | 'b' }>`
  color: ${(p) => (p.variant === 'a' ? 'red' : 'blue')};
`;
<Box variant="a">probe</Box>
```

Observed in TaskFlow's reference app: the DOM got `<div variant="a" class="sc-iCfNyT IHDRC">`, and styled-components logged:

```text
styled-components: it looks like an unknown prop "variant" is being sent through to the DOM,
which will likely trigger a React console error. If you would like automatic filtering of unknown
props, you can opt-into that behavior via `<StyleSheetManager shouldForwardProp={...}>` (connect an
API like `@emotion/is-prop-valid`) or consider using transient props (`$` prefix for automatic filtering.)
```

Why it matters:
- Invalid HTML attributes pollute the DOM. Some trigger React errors (non-string values, camelCase names on DOM elements).
- Some names **collide** with real attributes. A prop named `color`, `size`, `width` or `disabled` meant only for styling can change the element's actual behaviour.
- **Security note:** props are serialised into the DOM, where anything on the page (including injected scripts) can read them. Don't forward data you didn't mean to expose.

## 3. Transient props: the `$` prefix

A prop whose name starts with **`$`** is **transient**: available to your interpolations, **never** forwarded to the DOM.

```tsx
const Box = styled.div<{ $variant: 'a' | 'b' }>`
  color: ${(p) => (p.$variant === 'a' ? 'red' : 'blue')};
`;
<Box $variant="a">ok</Box>        // DOM: <div class="…">ok</div>
```

**TaskFlow rule: every styling-only prop on a styled component starts with `$`.** Real attributes (`disabled`, `type`, `aria-*`, `onClick`) keep their normal names.

## 4. Public props vs styled props

A common pattern: the **public** React component takes clean props (`size="sm"`), and maps them to transient props on an internal styled element:

```tsx
export function Avatar({ name, size = 'md' }: AvatarProps) {
  return <Circle $size={SIZE_PX[size]} $color={colorFor(name)} … />;
}
```

Consumers never see `$` props; the styling mechanism stays an implementation detail.

## 5. Summary

- Interpolations receive all props; v6 forwards all props to DOM elements by default.
- Styling-only props → **`$` transient props** (not forwarded). This avoids DOM pollution, collisions and warnings.
- Wrap styled internals in a clean public component API when useful.
