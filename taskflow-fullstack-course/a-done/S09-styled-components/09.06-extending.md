# Lecture 09.06 · Extending Styles: `styled(Component)` and `className` Forwarding

> **Section:** S09 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~20 minutes

---

## 1. Extending a styled component

```tsx
const DangerOutlineButton = styled(StyledButton)`
  background: transparent;
  color: var(--color-danger);
  border-color: var(--color-danger);
`;
```

`styled(X)` creates a new component that renders `X` with **additional** styles. The new rules are injected **after** the base component's rules, and they win at equal specificity. Props (including transient ones) still reach the base component's interpolations.

## 2. Styling *your own* React components

`styled()` works on **any** component, but only if that component **accepts and applies `className`**:

```tsx
// ❌ ignores className → styled(Card) has no effect
function Card({ children }: { children: ReactNode }) {
  return <article className="card">{children}</article>;
}

// ✅ merges the generated class with its own
function Card({ className, children }: { className?: string; children: ReactNode }) {
  return <article className={['card', className].filter(Boolean).join(' ')}>{children}</article>;
}

const HighlightedCard = styled(Card)`
  outline: 2px solid var(--color-primary);
`;
```

How it works: `styled(Card)` renders `<Card className="sc-… hash">`. If `Card` drops `className`, the generated class never reaches the DOM.

TaskFlow's BEM `Button` (07.06) already merges `className`, so `styled(Button)` works on it, **bridging** the two systems when a one-off tweak is needed.

## 3. Extending vs variants vs composition

| Need | Prefer |
|---|---|
| A few known looks of the same component | **Variant prop** (`$variant`) with a variant map (09.05, 10.09) |
| A specialised version used in one context | **`styled(Base)`** |
| Different *structure*, not just style | A new component composing the base (07.13) |

Deep chains (`styled(styled(styled(X)))`) become hard to follow; a variant is usually clearer.

## 4. Summary

- `styled(Component)` adds styles on top; rules come later in the cascade.
- Your components must accept and apply `className` to be stylable.
- Variants for known looks; extension for one-off specialisations.
