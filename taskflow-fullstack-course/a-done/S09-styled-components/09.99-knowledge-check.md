<details>
<summary><b>Answers</b></summary>

1. **Runtime**, in the browser: interpolations run on render, CSS is hashed and injected. SCSS modules are compiled at **build time** into static CSS with renamed classes; there's no runtime work.

2. `sc-…` is the **component ID**, the same for every instance of that styled component (used for component selectors). The other is the **style hash**: it identifies the computed CSS for a particular prop combination and is shared by any element with identical CSS.

3. Props prefixed with `$` are used for styling but **not forwarded** to the DOM. v6 forwards all props by default, so without `$` your styling props become DOM attributes (noise, invalid values, collisions like `size`, warnings).

4. **Three** style-hash classes (one per distinct CSS result: 3 variants × 1 size), plus the shared component-ID class.

5. The component's stable selector (its `sc-…` class), so you can write `&:hover ${Actions} { … }`.

6. Each render creates a **new component type**; reconciliation sees a different type at the same position, so it unmounts the old subtree and mounts a new one (losing DOM state like focus and input values).

7. styled-components inserts rules via the **CSSOM** (`sheet.insertRule`), not as text. The rules exist in `style.sheet.cssRules` and apply normally.

8. **Inline `style`** (or a CSS custom property). Interpolation would generate a new class and rule for every distinct value, flooding the stylesheet.

9. Shared `.btn` → **global SCSS** (JSP uses it too). Board column layout → **CSS Module** (React-only, static). Avatar with variable size/colour → **styled-components**. Task card used by both → **global SCSS** (BEM), wrapped by a React component.

10. One solution (`src/domain/color.ts` + `src/components/styled/Tag.tsx`):
    ```ts
    /** Strict #rrggbb check. Anything else (named colours, url(), expressions, `;`) is rejected. */
    const HEX_COLOR = /^#[0-9a-fA-F]{6}$/;

    export function isSafeHexColor(value: string): boolean {
      return HEX_COLOR.test(value);
    }

    /** Returns black or white, whichever is more readable on the given #rrggbb background. */
    export function contrastText(hex: string): '#000000' | '#ffffff' {
      const r = parseInt(hex.slice(1, 3), 16);
      const g = parseInt(hex.slice(3, 5), 16);
      const b = parseInt(hex.slice(5, 7), 16);
      const luminance = 0.299 * r + 0.587 * g + 0.114 * b;   // perceived brightness, 0..255
      return luminance > 150 ? '#000000' : '#ffffff';
    }
    ```
    ```tsx
    import styled from 'styled-components';
    import { contrastText, isSafeHexColor } from '../../domain/color';

    const FALLBACK = '#64748b';

    const Chip = styled.span<{ $bg: string; $fg: string }>`
      display: inline-flex;
      align-items: center;
      padding: 2px 8px;
      border-radius: 999px;
      font-size: 0.75rem;
      font-weight: 600;
      background: ${({ $bg }) => $bg};
      color: ${({ $fg }) => $fg};
    `;

    export function Tag({ label, color }: { label: string; color: string }) {
      const bg = isSafeHexColor(color) ? color : FALLBACK;
      return <Chip $bg={bg} $fg={contrastText(bg)}>{label}</Chip>;
    }
    ```
    **Why validate:** the value is interpolated **into CSS text**. An API value like `red; background-image: url(https://evil.example/track)` could inject extra CSS declarations. An **allow-list** pattern (`#rrggbb` only) makes that impossible. 10.10 covers CSS injection in detail.

</details>
