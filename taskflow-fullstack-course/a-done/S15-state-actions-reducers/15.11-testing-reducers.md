## 1. Why reducers are the easiest code to test

A reducer is a pure function: `(state, action) → state`. A test is three lines: build a state, call the reducer with an action, compare the result. No DOM, no network, no mocks, no timers. The official docs call reducers the best candidates for unit tests, and they're right: TaskFlow's reducer tests run in milliseconds.

Vitest is already set up in the frontend (12.10: `npm install -D vitest` and a `"test": "vitest"` script).

## 2. ✍️ The mutation detector: `src/test/deep-freeze.ts`

```ts
/**
 * Recursively freezes an object graph. In tests, pass frozen state to a reducer:
 * any mutation then THROWS (ES modules are strict mode), instead of silently corrupting state.
 */
export function deepFreeze<T>(value: T): T {
  if (typeof value === 'object' && value !== null && !Object.isFrozen(value)) {
    Object.freeze(value);
    for (const key of Reflect.ownKeys(value)) {
      deepFreeze((value as Record<PropertyKey, unknown>)[key]);
    }
  }
  return value;
}
```

Pass a frozen state to the reducer, and any mutation **throws**. ES modules run in strict mode, where writing to a frozen object is an error instead of a silent no-op. Verified messages on frozen state:

| Mutation | Error |
|---|---|
| `state.items.sort(…)` | *Cannot assign to read only property '0' of object '[object Array]'* |
| `state.items.push(x)` | *Cannot add property 2, object is not extensible* |
| `state.items[0].title = 'x'` | *Cannot assign to read only property 'title' of object '#<Object>'* |
| `state.status = 'loading'` | *Cannot assign to read only property 'status' of object '#<Object>'* |
| `state.items.toSorted(…)` | no error: it returns a copy |

`Reflect.ownKeys` also covers symbol keys. `Object.isFrozen` stops the recursion on already-frozen objects, which also handles shared references.

## 3. ✍️ `src/features/tasks/tasksSlice.test.ts`

```ts
import { describe, expect, it } from 'vitest';
import type { Task } from '../../domain/types';
import { deepFreeze } from '../../test/deep-freeze';
import { loggedOut } from '../auth/authActions';
import {
  allCompleted,
  completedCleared,
  fetchFailed,
  fetchStarted,
  fetchSucceeded,
  initialTasksState,
  taskAdded,
  taskDeleted,
  taskUpdated,
  tasksReducer,
} from './tasksSlice';
import type { TasksState } from './tasksSlice';

const task = (id: number, overrides: Partial<Task> = {}): Task => ({
  id,
  title: `Task ${id}`,
  description: '',
  status: 'TODO',
  priority: 'MEDIUM',
  dueDate: null,
  categoryId: null,
  ownerId: 1,
  createdAt: '2026-09-01T08:00:00Z',
  updatedAt: '2026-09-01T08:00:00Z',
  ...overrides,
});

/** A loaded, FROZEN state: any mutation in the reducer throws. */
const loaded = (...items: Task[]): TasksState => deepFreeze({ items, status: 'succeeded', error: null });

describe('tasksReducer', () => {
  it('returns the initial state for an unknown action (including Redux init)', () => {
    expect(tasksReducer(undefined, { type: '@@redux/INITx.y.z' } as never)).toBe(initialTasksState);
  });

  it('returns the SAME state object for actions it does not handle', () => {
    const state = loaded(task(1));
    expect(tasksReducer(state, { type: 'ui/selectionCleared' })).toBe(state);
  });

  it('tracks the fetch lifecycle and keeps items while reloading', () => {
    const reloading = tasksReducer(loaded(task(1)), fetchStarted());
    expect(reloading).toEqual({ items: [task(1)], status: 'loading', error: null });

    const failed = tasksReducer(deepFreeze(reloading), fetchFailed('Boom'));
    expect(failed.status).toBe('failed');
    expect(failed.error).toBe('Boom');

    const done = tasksReducer(deepFreeze(failed), fetchSucceeded([task(2)]));
    expect(done).toEqual({ items: [task(2)], status: 'succeeded', error: 'Boom' });
    // …the old error is only cleared by the next fetchStarted. Deliberate? See 15.13 §3.
  });

  it('adds, updates and deletes without mutating', () => {
    const state = loaded(task(1), task(2));

    const added = tasksReducer(state, taskAdded(task(3)));
    expect(added.items.map((t) => t.id)).toEqual([1, 2, 3]);

    const updated = tasksReducer(state, taskUpdated(task(2, { title: 'Renamed' })));
    expect(updated.items[1]?.title).toBe('Renamed');
    expect(updated.items[0]).toBe(state.items[0]); // untouched items keep their identity

    const deleted = tasksReducer(state, taskDeleted(1));
    expect(deleted.items.map((t) => t.id)).toEqual([2]);
  });

  it('allCompleted uses the timestamp from the action, and leaves DONE tasks untouched', () => {
    const doneAlready = task(1, { status: 'DONE' });
    const state = loaded(doneAlready, task(2));
    const next = tasksReducer(state, allCompleted('2026-10-01T10:00:00Z'));
    expect(next.items[0]).toBe(doneAlready);
    expect(next.items[1]).toMatchObject({ status: 'DONE', updatedAt: '2026-10-01T10:00:00Z' });
  });

  it('completedCleared removes exactly the listed ids', () => {
    const state = loaded(task(1), task(2), task(3));
    expect(tasksReducer(state, completedCleared([1, 3])).items.map((t) => t.id)).toEqual([2]);
  });

  it('resets on auth/loggedOut', () => {
    expect(tasksReducer(loaded(task(1)), loggedOut())).toBe(initialTasksState);
  });
});
```

(The `allCompleted` and `completedCleared` tests belong to the 15.12 exercise. Leave them out until then.)

## 4. What to test, and how

- **A factory for domain objects** (`task(id, overrides)`): each test states only what matters to it, and a change to the `Task` type is fixed in one place.
- **Freeze every input state.** `loaded(…)` freezes; for the multi-step test, each intermediate result is frozen before the next call.
- **Test identity, not just equality:**
  - `toBe(state)` for "unhandled action returns the **same** object" (15.07's `default` branch; 15.09's "nothing changed");
  - `expect(updated.items[0]).toBe(state.items[0])` for "untouched items keep their identity" (14.06 §4: that's what lets React skip re-renders).
  `toEqual` alone would pass even if the reducer copied everything.
- **The init call:** `tasksReducer(undefined, { type: '@@redux/INITx.y.z' } as never)` must return the initial state. `as never` is needed because that type isn't an `AppAction`, which is exactly what Redux sends.
- **Action creators are tested through the reducer.** A separate "creator returns this object" test adds little; "dispatching `taskDeleted(1)` removes task 1" tests both at once.
- **Deterministic input:** `allCompleted('2026-10-01T10:00:00Z')` passes the timestamp explicitly. That's possible only because the clock lives in the action creator (15.04).

A test also documents a design question: `fetchSucceeded` after `fetchFailed` keeps the old `error` (`'Boom'`). The test pins down the current behaviour, and 15.13 discusses whether it's right.

## 6. Summary

- Reducer tests: build state → call reducer → assert. No mocks.
- Deep-freeze inputs so mutations throw.
- Assert identity (`toBe`) where it matters, not only equality.
- Keep non-determinism out of reducers, and tests stay exact.
