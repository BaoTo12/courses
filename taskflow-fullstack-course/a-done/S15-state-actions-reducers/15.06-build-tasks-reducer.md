## 3. ✍️ `src/features/tasks/tasksSlice.ts`

This first version handles six events. The 15.12 exercise adds two more (`allCompleted`, `completedCleared`). The `AppAction` import is explained in 15.07; create `src/app/app-action.ts` from there now.

```ts
// Hand-written Redux "slice" (S15): state type, action types, action creators and reducer in one file.
// S20 replaces all of this with RTK's createSlice; the behaviour stays the same.
import type { Task } from '../../domain/types';
import type { AppAction } from '../../app/app-action';

export type LoadStatus = 'idle' | 'loading' | 'succeeded' | 'failed';

export interface TasksState {
  /** A plain array for now; normalised into ids + entities in S19. */
  items: Task[];
  status: LoadStatus;
  error: string | null;
}

export const initialTasksState: TasksState = { items: [], status: 'idle', error: null };

// ── Actions: past-tense EVENTS, typed as a discriminated union (06.06) ───────
export type TasksAction =
  | { type: 'tasks/fetchStarted' }
  | { type: 'tasks/fetchSucceeded'; payload: Task[] }
  | { type: 'tasks/fetchFailed'; payload: string }
  | { type: 'tasks/taskAdded'; payload: Task }
  | { type: 'tasks/taskUpdated'; payload: Task }
  | { type: 'tasks/taskDeleted'; payload: number };

/** The member of the union with this `type` (Extract, 06.03). */
type TasksActionOf<T extends TasksAction['type']> = Extract<TasksAction, { type: T }>;

// ── Action creators ───────────────────────────────────────────────────────────
export const fetchStarted = (): TasksActionOf<'tasks/fetchStarted'> => ({ type: 'tasks/fetchStarted' });
export const fetchSucceeded = (tasks: Task[]): TasksActionOf<'tasks/fetchSucceeded'> => ({
  type: 'tasks/fetchSucceeded',
  payload: tasks,
});
export const fetchFailed = (message: string): TasksActionOf<'tasks/fetchFailed'> => ({
  type: 'tasks/fetchFailed',
  payload: message,
});
export const taskAdded = (task: Task): TasksActionOf<'tasks/taskAdded'> => ({ type: 'tasks/taskAdded', payload: task });
export const taskUpdated = (task: Task): TasksActionOf<'tasks/taskUpdated'> => ({
  type: 'tasks/taskUpdated',
  payload: task,
});
export const taskDeleted = (id: number): TasksActionOf<'tasks/taskDeleted'> => ({ type: 'tasks/taskDeleted', payload: id });

// ── Reducer ───────────────────────────────────────────────────────────────────
export function tasksReducer(state: TasksState = initialTasksState, action: AppAction): TasksState {
  switch (action.type) {
    case 'tasks/fetchStarted':
      // Keep the current items while reloading (the list doesn't blink); clear the old error.
      return { ...state, status: 'loading', error: null };
    case 'tasks/fetchSucceeded':
      return { ...state, status: 'succeeded', items: action.payload };
    case 'tasks/fetchFailed':
      return { ...state, status: 'failed', error: action.payload };
    case 'tasks/taskAdded':
      return { ...state, items: [...state.items, action.payload] };
    case 'tasks/taskUpdated':
      return {
        ...state,
        items: state.items.map((task) => (task.id === action.payload.id ? action.payload : task)),
      };
    case 'tasks/taskDeleted':
      return { ...state, items: state.items.filter((task) => task.id !== action.payload) };
    case 'auth/loggedOut':
      return initialTasksState; // another user may log in next: forget everything (15.10)
    default:
      // Not an error: other slices' actions and Redux's own init action arrive here (15.07).
      return state;
  }
}
```

## 4. Design notes

- **One file per feature**: state type, action types, creators and reducer (15.02). S20's `createSlice` generates the creators and the union for you.
- **`state = initialTasksState`**: the default parameter provides the initial state when Redux calls the reducer with `undefined` (14.07).
- **`fetchStarted` keeps `items`.** During a reload, the old list stays visible, with a loading indicator on top. Clearing it would make the list blink empty. That's a UX choice encoded in the reducer.
- **`fetchStarted` clears `error`**; `fetchSucceeded` doesn't. You'll question that in 15.13.
- **`taskUpdated` replaces the whole task** with the server's version (13.13 §1: the server may have changed more than we sent). Other tasks keep their identity.
- **`auth/loggedOut` returns `initialTasksState`**: the same object as the initial state, which is fine because nobody mutates it.
- **`default: return state`**: required. The next lecture shows what happens with `assertNever` here.

This reducer is the Redux version of `hooks/tasks-reducer.ts` (08.07, 13.12). Compare them: same events, same updates. What changed is the **naming** (`domain/event` + `payload`), where the state lives (a store instead of a component), and the `default` branch.
