# Lecture 15.15 · 🐞 Debug: A Reducer Returns `undefined` (Missing Initial State)

> **Section:** S15 · **Type:** 🐞 Debug · **Track:** ★ Core · **Time:** ~20 minutes
> Error messages captured with redux 5.0.1 (development build, in Node).

---

## Symptom

A new `notificationsReducer` is added to `combineReducers`, and the app crashes on startup:

```text
The slice reducer for key "notifications" returned undefined during initialization. If the state passed to the
reducer is undefined, you must explicitly return the initial state. The initial state may not be undefined. If you
don't want to set a value for this reducer, you can use null instead of undefined.
```

The reducer:

```ts
function notificationsReducer(state: Notification[], action: AppAction) {
  switch (action.type) {
    case 'notifications/received':
      return [...state, action.payload];
  }
}
```

A second teammate has a different crash, only after a specific action:

```text
When called with an action of type "x", the slice reducer for key "c" returned undefined. To ignore an action,
you must explicitly return the previous state. If you want this reducer to hold no value, you can return null
instead of undefined.
```

## Investigation checklist

1. What does Redux pass as `state` on the very first call? (14.07, 15.08)
2. What does this function return for an action it doesn't handle?
3. Why did TypeScript not complain? (Check the compiler options and the function's return type.)
4. Why does the error come from `combineReducers`, and what would a bare `createStore(notificationsReducer)` have done? (14.10 §5)

## Explanation

1. On the first call, `state` is `undefined`, and there's **no default parameter**, so there's no initial state.
2. There's no `default` branch: the `switch` falls through, and the function returns `undefined`. For Redux's init and probe actions (15.07), that's every call at startup.
3. The return type is **inferred** (`Notification[] | undefined`), and nothing forces it to be the state type. With an explicit return type (`: Notification[]`), TypeScript reports *"Function lacks ending return statement and return type does not include 'undefined'"*.
4. `combineReducers` checks every slice at startup (the init action **and** a random `@@redux/PROBE_UNKNOWN_ACTION…` action) and throws those descriptive messages. A **bare** `createStore` has no such check: verified in 14.10, `createStore((state, action) => state).getState()` is just `undefined`, silently. That's one more reason to always use `combineReducers` (or RTK's `configureStore`, which uses it).

The second crash is the same bug in another place: a `case` that returns nothing (a missing `return`, or an `if` without an `else`) for one specific action.

## Fix

```ts
const initialNotificationsState: Notification[] = [];

function notificationsReducer(
  state: Notification[] = initialNotificationsState,
  action: AppAction,
): Notification[] {
  switch (action.type) {
    case 'notifications/received':
      return [...state, action.payload];
    default:
      return state;
  }
}
```

Three habits that make this bug impossible:
1. A **default parameter** with the initial state.
2. A **`default: return state`** branch (never `assertNever` in Redux: 15.07).
3. An **explicit return type** on every reducer.

"No value" is `null`, never `undefined`, as the error message itself suggests.

## Lessons

- `undefined` is reserved by Redux to mean "not initialised yet". A reducer must never return it.
- Let `combineReducers` validate your slices; a bare `createStore` won't.
- Explicit return types turn a runtime crash into a compile error.
