## 1. React's hook for external stores

React 18 added `useSyncExternalStore(subscribe, getSnapshot)`: the official way to read from a store that lives **outside** React. React-Redux's `useSelector` is built on it.

- `subscribe(callback)`: React calls it once to start listening, and calls the returned function to stop. Our store's `subscribe` already has exactly this shape (16.03).
- `getSnapshot()`: returns the current value. React calls it during render **and** after every notification, and re-renders only if the value **changed** (`Object.is`, the same check as `===` except for `NaN` and `-0`).

It also guarantees that every component rendered in one pass sees the same snapshot, even with concurrent rendering (no "tearing").

## 2. ✍️ `src/app/mini-redux/use-mini-selector.ts`

```ts
// 17.02 (＋): connecting a store to React by hand, with React's own external-store hook.
// React-Redux's useSelector is built on the same primitive, plus equality checks and dev warnings.
import { useSyncExternalStore } from 'react';
import type { MiniAction, MiniStore } from './create-mini-store';

export function useMiniSelector<S, A extends MiniAction, T>(store: MiniStore<S, A>, selector: (state: S) => T): T {
  // subscribe: how React listens for changes; getSnapshot: how it reads the current value.
  // React re-renders when getSnapshot() returns a value that is !== the previous one (Object.is).
  return useSyncExternalStore(store.subscribe, () => selector(store.getState()));
}
```

Three lines of real code. Used like this:

```tsx
const store = createMiniStore(rootReducer);

function SelectedCount() {
  const count = useMiniSelector(store, (s) => s.ui.selectedTaskIds.length);
  return <span>{count} selected</span>;
}
```

## 3. 🔬 What happened when I rendered it

| Step | Text | Total renders |
|---|---|---|
| Mount | `0 selected` | 1 |
| `dispatch(taskSelectionToggled(3))` | `1 selected` | 2 |
| `dispatch(toastShown(…))` (unrelated) | `1 selected` | **2**: no re-render |

The unrelated toast notified the subscriber, React called `getSnapshot()`, got `1` again, and skipped the render. That's per-component change detection in one hook.

### The trap: a selector that returns a new object

```tsx
const ids = useMiniSelector(store, (s) => [...s.ui.selectedTaskIds]); // a NEW array every call
```

Verified: React logged *"The result of getSnapshot should be cached to avoid an infinite loop"*, then threw *"Maximum update depth exceeded…"*. Every `getSnapshot()` call returns a different array, so React believes the store changed on every check, re-renders, checks again… forever.

Remember this. It's the root of 17.15's bug. React-Redux's `useSelector` is more forgiving: it compares **selector results** and keeps rendering, but the same mistake still causes a re-render after **every** action (17.04, 17.15).

## 4. What React-Redux adds on top

| Concern | Our hook | React-Redux |
|---|---|---|
| Store access | We pass `store` explicitly | `<Provider>` + context (17.03) |
| Change detection | `Object.is` on the snapshot | `===` on the selector result, or a custom equality function (`shallowEqual`) |
| New-reference selectors | Infinite loop | Works, with a dev-mode warning (17.15) |
| Selector bugs | Nothing | Dev checks: selectors that return different results for the same state; selectors that return the whole state |
| Typed hooks | Generic parameters | `useSelector.withTypes<RootState>()` (17.06) |
| Nested subscription ordering, batching with React | No | Yes |

## 5. Summary

- `useSyncExternalStore(subscribe, getSnapshot)` is React's primitive for external stores; three lines give a working `useSelector`.
- Change detection is `Object.is` on what the selector returns: new objects mean "changed".
- React-Redux adds context-based store access, safer equality handling, dev checks and typing.
