# Lecture 17.16 · 🐞 Debug: "could not find react-redux context value"

> **Section:** S17 · **Type:** 🐞 Debug · **Track:** ★ Core · **Time:** ~15 minutes
> Reproduced in the reference app by rendering `OpenTasksBadge` into a separate React root without a `<Provider>`.

---

## Symptom

Three different teammates hit the same error:

```text
could not find react-redux context value; please ensure the component is wrapped in a <Provider>
```

- **A** added a "quick add" widget, rendered with its own `createRoot(document.getElementById('quick-add'))` next to the main app (the "React island" pattern you'll use in S49).
- **B** wrote a component test that renders `<OpenTasksBadge />` directly.
- **C** moved `<Provider>` inside `<App />`, below `AppLayout`, "to keep main.tsx short". Now the layout crashes on load.

## Investigation checklist

1. How does `useSelector` find the store? (17.03)
2. Is a React **root** created with a separate `createRoot` part of the same tree as the main app?
3. Where must `<Provider>` be, relative to every component that calls a React-Redux hook?

## Explanation

The hooks read the store from **React context**, and context flows **down the tree** from the provider. A component outside that subtree gets the default value (`null`), and React-Redux throws this error.

- **A:** each `createRoot` starts a **new, independent tree**. The widget isn't below the main app's `<Provider>`.
- **B:** a test renders the component alone: no provider above it.
- **C:** `AppLayout` uses `useAppDispatch` (to load tasks) but is now **above** the provider.

This is the same family of error as 12.02's *"useRoutes() may be used only in the context of a <Router> component"*: a hook needs a provider above it, and TypeScript can't check the tree structure.

## Fixes

- **A:** wrap the island in its own `<Provider store={store}>`, using the **same** `store` import. Both trees then share one store, and dispatches in either update both. That's exactly how S49's JSP page with a React island will share state.
- **B:** tests render with a provider and a **fresh** store:
  ```tsx
  render(
    <Provider store={makeStore({ /* preloaded state */ })}>
      <OpenTasksBadge />
    </Provider>,
  );
  ```
  (That's why `store.ts` exports `makeStore`, 16.11.)
- **C:** move `<Provider>` back to the top of `main.tsx`, above everything that could use it.

## Lessons

- React-Redux hooks need `<Provider>` **above** them in the **same** React tree.
- Separate roots need their own `<Provider>` (sharing the same store object if they should share state).
- Tests: provide a fresh store per test with `makeStore`.
