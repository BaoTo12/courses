<summary><b>Answers</b></summary>

1. `StyledThemeProvider` puts the `theme` object into React context → when a styled component renders, it reads the context and passes `theme` to each interpolation → `theme.colors.primary` is the string `'var(--color-primary)'` → it's written into the generated CSS rule → the **browser** resolves `var(--color-primary)` from the nearest element defining it (`:root` / `[data-theme]` blocks emitted by SCSS).

2. (a) **One source of truth**: values live only in SCSS, which the JSP portal also uses. (b) **No re-render on theme switch**: the object never changes; the browser re-resolves variables. (c) **"System" theme handled by CSS** from first paint, with no `matchMedia` effect and no flicker. (Also: no token build step needed.)

3. styled-components is a **runtime JS library** that generates CSS while React renders in the browser; JSP pages are **server-rendered HTML** with static CSS and no React bundle. Shareable: compiled SCSS, CSS custom properties, BEM class names.

4. Equal specificity → the **later** rule in document order wins. Usually styled-components (inserted last), but lazily loaded CSS appended later can flip it.

5. It repeats the generated class (`.hash.hash`), doubling specificity to (0,2,0). A deliberate, local way to win over single-class global rules.

6. The **`DefaultTheme` module augmentation** (`declare module 'styled-components' { export interface DefaultTheme extends AppTheme {} }`), or the file isn't included by `tsconfig`.

7. **Two sources of truth**: hex values duplicated in TS theme objects were not updated with the SCSS tokens. Fix: theme of `var()` references.

8. Example: (1) Tokens live in SCSS; never hard-code values. (2) Shared components are SCSS/BEM wrapped by typed React components. (3) React-only static structure uses CSS Modules. (4) Dynamic prop-driven components use styled-components with `$` props, defined at module level. (5) Never style one element with both systems; untrusted values are allow-list validated before reaching CSS.

9. Toast tone → **variant map** of `css` fragments with a union prop. Drag position → **`style` prop** (or a custom property). Category colour from API → **allow-list validation** then interpolation (or a validated custom property). Page reset → **SCSS `base/`** (not `createGlobalStyle`).

10. Use `Tag` + `isSafeHexColor` + `contrastText` from 09.99. In `TaskCard`: `const category = CATEGORIES[task.categoryId ?? -1]; {category && <Tag label={category.name} color={category.color} />}` with a provided `CATEGORIES: Record<number, Category>`. Test: see 10.11 §1. Real categories come from the API in S13 and are normalised in Redux in S19.
