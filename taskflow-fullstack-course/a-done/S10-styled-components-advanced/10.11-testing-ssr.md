## 1. What to test (and what not to)

Most style bugs are **visual**, and unit tests are poor at catching them. A practical split:

| Concern | Best tool |
|---|---|
| **Logic that decides styles** (`ringColor(percent)`, `contrastText(hex)`, `isSafeHexColor`) | **Unit tests** on the pure functions (Vitest), which is why TaskFlow keeps them pure and in `domain/` |
| **Behaviour and accessibility** (a toast appears with `role="status"`, disappears after 4 s, the dismiss button works) | **Component tests** with Testing Library (query by role/label, not by class) |
| **"Does it look right?"** across themes and breakpoints | **Visual regression** (screenshot comparison, e.g. Playwright or Storybook-based tools) |
| **"Did this prop produce that CSS rule?"** | Occasionally useful: the `jest-styled-components` package adds a `toHaveStyleRule` matcher (check its docs for Vitest setup) |

Example of a valuable pure-function test (works with the Vitest setup you'll add in S15):

```ts
import { describe, expect, it } from 'vitest';
import { contrastText, isSafeHexColor } from './color';

describe('color helpers', () => {
  it('accepts only #rrggbb', () => {
    expect(isSafeHexColor('#4f46e5')).toBe(true);
    expect(isSafeHexColor('red')).toBe(false);
    expect(isSafeHexColor('#fff; position: fixed')).toBe(false);
  });

  it('picks readable text colours', () => {
    expect(contrastText('#ffffff')).toBe('#000000');
    expect(contrastText('#4f46e5')).toBe('#ffffff');
  });
});
```

That second test file covers the security-relevant rule from 10.10, and it runs in milliseconds.

## 2. Server-side rendering (SSR) note

TaskFlow Web is client-rendered, so this doesn't affect us. In SSR frameworks, runtime CSS-in-JS needs extra work: the server must **collect** the CSS generated during rendering (`ServerStyleSheet` in styled-components) and inline it into the HTML, or the page flashes unstyled until JS runs.

## 3. React Server Components (RSC) note

Components that run **only on the server** (RSC) can't use React context or runtime style injection, so runtime CSS-in-JS libraries like styled-components work only in **client components** there. This is a major reason the ecosystem is moving towards **zero-runtime** approaches (CSS Modules, compile-time CSS-in-JS). It's worth knowing when you evaluate a new stack. For TaskFlow's Vite SPA, styled-components works fully.

## 4. Summary

- Unit-test the pure functions behind styling; test behaviour and accessibility with Testing Library; use visual regression for appearance.
- SSR needs style collection; RSC doesn't support runtime CSS-in-JS in server components.
