# Lecture 10.14 · 🐞 Debug: Dark Mode Updates Styled Components but Not SCSS Cards (Two Sources of Truth)

> **Section:** S10 · **Type:** 🐞 Debug · **Track:** ★ Core · **Time:** ~20 minutes

---

## Symptom

A teammate on another project (which copied the 10.03 "two theme objects" approach) reports:

1. The designer changes the brand primary from indigo `#4f46e5` to teal `#0d9488` **in the SCSS tokens**.
2. After deploying: the **cards, badges and form fields** (SCSS) are teal, but the **priority bars, toasts and styled buttons** are still indigo.
3. Worse, in dark mode, switching themes briefly shows **light** styled components on a **dark** page before they catch up. Some users say "the colours flicker when I load the page".

## Investigation checklist

1. Where does each component get its primary colour? Grep for `#4f46e5` across `styles/` **and** `src/`.
2. Which code decides light vs dark for SCSS components? For styled components?
3. When does each decision happen (CSS evaluation vs a React effect after first render)?
4. Is the styled-components theme object a module constant, or does it change on toggle?

## Explanation

**Two sources of truth.** The project has:
- SCSS `$themes` maps → `--color-*` custom properties (updated by the designer), and
- `lightTheme` / `darkTheme` **TypeScript objects with hex values** (nobody updated them).

Each system is internally consistent, but they disagree with each other.

**Two theme-switching mechanisms.** SCSS switches via `[data-theme]` and `prefers-color-scheme`, **in CSS**, from the very first paint. The TS version resolves "system" in a **React effect** (`matchMedia`) after the first render and swaps theme objects, which re-renders every styled component with new classes. Until that effect runs, styled components render with the default (light) object: that's the **flicker**.

## Fix

Adopt 10.04 **Option A** (what TaskFlow does in 10.05):
1. Delete `lightTheme` / `darkTheme` hex objects.
2. One `theme` object whose colours are **`var(--color-…)` references**.
3. Remove the `matchMedia` logic: CSS already handles "system".

Afterwards, a designer changing one SCSS token updates everything, and switching themes involves no React re-render (verified in 10.05: class names unchanged).

## How to prevent it

- A lint rule or CI grep that fails on hex colours in `src/**/*.ts(x)` outside approved files (e.g. `domain/color.ts` fallbacks).
- The `STYLING.md` rule #1 from 10.07: "Tokens live in SCSS."
