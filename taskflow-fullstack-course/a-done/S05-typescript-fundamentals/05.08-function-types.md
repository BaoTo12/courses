# Lecture 05.08 · Function Types: Parameters, Returns, Optional/Default Parameters, Callbacks

> **Section:** S05 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~20 minutes

---

## 1. Annotating functions

```ts
function sortTasks(tasks: readonly Task[], key: SortKey, direction: SortDirection = 'asc'): Task[] {
  // …
}

const isDone = (task: Task): boolean => task.status === 'DONE';
```

- **Parameters:** always annotated (except contextually typed callbacks).
- **Return type:** inferred if omitted; annotate it on exported functions as a contract.
- **Default parameters** (`direction = 'asc'`) make the parameter optional, and its type is inferred from the default.
- **Optional parameters** (`q?: string`) must come after required ones, and have type `string | undefined` inside.

## 2. Wrong calls are caught

```ts
function total(a: number, b: number) { return a + b; }
total('1', 2);
//    ~~~ error TS2345: Argument of type 'string' is not assignable to parameter of type 'number'.
```

And parameters without types (under `strict`):

```ts
function f(x) { return x; }
//         ~ error TS7006: Parameter 'x' implicitly has an 'any' type.
```

## 3. Function types (for callbacks and props)

```ts
type TaskPredicate = (task: Task) => boolean;
type ToggleHandler = (id: number) => void;

function countWhere(tasks: readonly Task[], predicate: TaskPredicate): number {
  return tasks.filter(predicate).length;
}

// React props preview (S07):
interface TaskCardProps {
  task: Task;
  onToggle: (id: number) => void;
}
```

`=> void` for callbacks means "the caller ignores the return value". A function returning something *is* assignable to a `void`-returning callback type, which is why `tasks.forEach((t) => list.push(t))` is fine even though `push` returns a number.

## 4. Destructured parameters

```ts
function filterTasks(tasks: readonly Task[], { status, priority, q }: TaskFilter = {}): Task[] { … }
```

The type annotation goes **after the whole pattern**, not inside it. `{ status: TaskStatus }` inside a pattern would **rename** `status` to a variable called `TaskStatus` (destructuring syntax, 04.04). That's a classic confusion.

## 5. Rest parameters and overloads (briefly)

```ts
function logAll(prefix: string, ...messages: string[]): void { … }
```

**Overloads** let one function have several call signatures. They're useful in libraries (you'll see them in React and Axios type definitions), rarely needed in app code. Prefer unions or separate functions.

## 6. `this`, generics and more

Functions can also be **generic** (`<T>`), which lets `findById` work for tasks *and* categories while keeping precise types. That's the first topic of S06.

## 7. Summary

- Annotate parameters; annotate exported return types; defaults and `?` make parameters optional.
- Function types `(args) => Result` describe callbacks and component props.
- Destructured parameter types go after the pattern.
- `=> void` callbacks accept functions that return values.
