# Lecture 05.07 · Narrowing: `typeof`, `in`, Equality, Truthiness, and Control-Flow Analysis

> **Section:** S05 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~25 minutes

---

## 1. What narrowing is

A value typed as a union (`string | null`, `number | string`, `unknown`) can be used only in ways valid for **all** alternatives. **Narrowing** is how TypeScript learns, from your **runtime checks**, which alternative you have **at a given point in the code**.

```ts
function formatDue(dueDate: string | null): string {
  if (dueDate === null) {
    return 'No due date';          // here: dueDate is null
  }
  return dueDate.toUpperCase();    // here: dueDate is string (null was ruled out)
}
```

TypeScript performs **control-flow analysis**: it follows `if`, `return`, `throw`, `switch`, `&&`, `||` and `?:`, and tracks the possible type of each variable at each point.

> 🧠 Narrowing isn't magic: the **check** runs at runtime (it's normal JavaScript), and the **type** follows at compile time. Types never do the checking for you.

## 2. The narrowing tools

### `typeof` (for primitives)

```ts
function formatId(id: number | string) {
  if (typeof id === 'number') return `#${id.toFixed(0)}`;   // number
  return id.trim();                                          // string
}
```

`typeof` returns `'string' | 'number' | 'bigint' | 'boolean' | 'symbol' | 'undefined' | 'object' | 'function'`. Note `typeof null === 'object'`, a historical JS quirk, so check `!== null` too.

### Equality (`===`, `!==`, `switch`)

```ts
function label(status: TaskStatus) {
  if (status === 'DONE') return '✔';   // status: 'DONE'
  return status;                        // status: 'TODO' | 'IN_PROGRESS'
}
```

### Truthiness

```ts
function greet(name: string | undefined) {
  if (name) return `Hi ${name}`;   // string (non-empty!)
  return 'Hi there';
}
```

⚠️ Truthiness excludes `''` and `0` too. For `count: number | undefined`, `if (count)` wrongly treats `0` as missing. Use `count !== undefined`.

### `in` (property existence)

```ts
type ApiError = { error: string; status: number };
function handle(result: Task[] | ApiError) {
  if ('error' in result) {
    return showError(result.error);   // ApiError
  }
  return render(result);              // Task[]
}
```

### `instanceof` (class instances)

```ts
if (error instanceof Error) console.log(error.message);
```

### `Array.isArray`

```ts
function toList(x: Task | Task[]): Task[] {
  return Array.isArray(x) ? x : [x];
}
```

### Early returns and `throw`

```ts
function requireTask(t: Task | undefined): Task {
  if (!t) throw new Error('Task not found');
  return t;   // Task
}
```

## 3. Narrowing `unknown` step by step

```ts
function titleOf(value: unknown): string {
  if (
    typeof value === 'object' &&
    value !== null &&
    'title' in value &&
    typeof value.title === 'string'
  ) {
    return value.title;   // string
  }
  return '(untitled)';
}
```

Each condition narrows further: `unknown` → `object | null` → `object` → `object & Record<'title', unknown>` → `title` is `string`. Verbose, but safe. In 06.08 you'll package checks like this into reusable **type guard** functions.

## 4. Where narrowing is lost

Narrowing applies to the **current flow**. It can be lost when TypeScript can't prove the value didn't change:

```ts
const task: { dueDate: string | null } = get();
if (task.dueDate !== null) {
  setTimeout(() => {
    task.dueDate.toUpperCase();   // may error: the callback runs later, and dueDate could have changed
  });
}
```

Fix: copy into a `const` inside the narrowed block: `const due = task.dueDate;` then use `due`.

## 5. Summary

- Narrowing = runtime checks that TypeScript tracks through control flow.
- Tools: `typeof`, `===`/`switch`, truthiness (careful with `0`/`''`), `in`, `instanceof`, `Array.isArray`, early `return`/`throw`.
- `unknown` must be narrowed step by step before use.
- Callbacks may lose narrowing; capture narrowed values in a `const`.
