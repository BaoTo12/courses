# Lecture 16.05 · ＋ Store Enhancers: Wrapping `createStore` Itself

> **Section:** S16 · **Type:** 📖 Theory · **Track:** ＋ Extended · **Time:** ~25 minutes
> 🔗 Official companion reading: Fundamentals Part 4 ("Configuring the Store": enhancers)

---

## 1. What an enhancer is

An enhancer is a function that takes `createStore` and returns a **new, better** `createStore`:

```ts
const enhancer = (createStore) => (reducer, preloadedState) => {
  const store = createStore(reducer, preloadedState); // make a normal store…
  return { ...store /* …and change or add things */ };
};
```

Because it controls store creation, an enhancer can:
- **wrap the reducer** before the store sees it (timing, logging every reducer call);
- **wrap `dispatch`**, `getState` or `subscribe`;
- **add new methods** to the store (`store.getDispatchStats()`);
- change the preloaded state (restore from `localStorage`).

## 2. How Redux uses it

```ts
createStore(rootReducer, preloadedState, enhancer);
```

When an enhancer is passed, Redux's `createStore` hands control over to it: it calls `enhancer(createStore)(reducer, preloadedState)` and returns whatever that produces. The enhancer receives the **original** `createStore` to call inside.

You already know two enhancers:
- **`applyMiddleware(…)`** is an enhancer. It creates a store, then replaces its `dispatch` with the middleware chain (16.09).
- **`window.__REDUX_DEVTOOLS_EXTENSION__()`** is an enhancer. It reports every action and state to the extension, and lets the extension replace the state (time travel, 14.11).

## 3. Combining several enhancers: `compose`

`createStore` accepts **one** enhancer. To use several, compose them into one:

```ts
const enhancer = compose(applyMiddleware(logger), dispatchStatsEnhancer);
```

`compose(f, g)(createStore)` = `f(g(createStore))`. The rightmost enhancer wraps the real `createStore` first, and the leftmost is the outermost layer. You'll write `compose` in 16.09.

⚠️ TypeScript detail (verified with redux 5.0.1): Redux's `compose` can't infer through **generic** enhancer functions, so the composed result is typed `(...args: any[]) => unknown`. `createStore` then rejects it (*"No overload matches this call"*), and methods added by an enhancer disappear from the store type. State the result type once:

```ts
const enhancer = compose(applyMiddleware(logger), dispatchStatsEnhancer) as typeof dispatchStatsEnhancer;
const store = createStore(rootReducer, enhancer);
store.getDispatchStats(); // typed
```

(With a **single** enhancer, as in TaskFlow's `store.ts`, no annotation is needed. RTK's `configureStore` in S20 composes enhancers with full types.)

## 4. Enhancer vs middleware: which one?

| Need | Use |
|---|---|
| React to or change **actions** as they're dispatched | **Middleware** (simpler, and the common case) |
| Change the **reducer**, the **store's methods**, or **store creation** | **Enhancer** |

In application code, you'll write middleware often and enhancers rarely. Libraries (DevTools, persistence) ship enhancers. You're learning enhancers so you can read that code and understand where `applyMiddleware` fits.

## 5. Summary

- Enhancer: `createStore => newCreateStore`. It can wrap the reducer, wrap store methods and add new ones.
- `applyMiddleware` and the DevTools are enhancers; combine several with `compose`.
- Write middleware for action logic; enhancers for store-level behaviour.
