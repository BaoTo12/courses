# Lecture 08.11 · Custom Hooks: Extracting Logic, Naming, Composition

> **Section:** S08 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~20 minutes
> 🔗 Official reading: react.dev → Learn → "Reusing Logic with Custom Hooks"

---

## 1. What a custom hook is

A **function whose name starts with `use` and that calls other hooks.** That's all. There's no special API.

```ts
export function useDebounce<T>(value: T, delayMs = 300): T {
  const [debounced, setDebounced] = useState(value);
  useEffect(() => {
    const timer = setTimeout(() => setDebounced(value), delayMs);
    return () => clearTimeout(timer);
  }, [value, delayMs]);
  return debounced;
}
```

You've already written two: `useTasks` (08.04) and `useTheme` (08.10).

## 2. Why the `use` prefix matters

- It tells **linters** to apply the Rules of Hooks inside it and at its call sites (08.01).
- It tells **readers** "this may hold state or effects; call it unconditionally at the top level".

## 3. Custom hooks share *logic*, not *state*

Each component that calls `useDebounce` gets **its own** state and effect, because the hook's `useState`/`useEffect` calls are part of **that component's** hook list. Two components calling `useTasks()` would each fetch and hold their **own** copy of the tasks.

That's a crucial difference from Context and Redux:

| | Custom hook | Context / Redux |
|---|---|---|
| Shares | **Logic** (how to fetch, debounce, persist) | **State** (one value seen by many components) |
| Two callers | Two independent states | One shared state |

When TaskFlow's dashboard and task list both need **the same** tasks, `useTasks` in each would fetch twice and drift apart. That's the problem Redux (S14+) and RTK Query's cache (S22) solve.

## 4. Designing good hooks

- **One job**, named after what it provides (`useDebounce`, `useLocalStorage`, `useTheme`), not how (`useTimeoutEffect`).
- **Return shape:** a single value (`useDebounce`), a tuple like `useState` (`useLocalStorage` → `[value, setValue]`), or an object when there are several named things (`useTasks` → `{ state, toggle, reload }`).
- **Hide the plumbing**: components shouldn't know about `AbortController` or `localStorage` exceptions.
- **Compose**: hooks can call other hooks (`ThemeProvider` uses `useLocalStorage`, which uses `useState` + `useEffect`).
- **Keep pure logic outside**: reducers and helpers in plain `.ts` modules, testable without React (08.08).

## 5. Summary

- Custom hook = `use…` function calling hooks; it follows the Rules of Hooks.
- Hooks reuse **logic**; each caller gets **independent state**.
- Shared state needs Context/Redux/RTK Query.
