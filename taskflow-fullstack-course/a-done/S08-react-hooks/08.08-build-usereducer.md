## 1. ✍️ `src/hooks/tasks-reducer.ts`

```ts
import type { Task } from '../domain/types';
import type { RequestState } from '../domain/api-types';
import { toggleTask } from '../domain/task-utils';
import { assertNever } from '../domain/guards';

export type TasksState = RequestState<Task[]>;

// Actions describe EVENTS that happened (past tense), not "set X" commands.
export type TasksAction =
  | { type: 'fetchStarted' }
  | { type: 'fetchSucceeded'; tasks: Task[] }
  | { type: 'fetchFailed'; error: string }
  | { type: 'taskToggled'; id: number };

export const initialTasksState: TasksState = { status: 'idle' };

/** Pure: (state, action) → new state. No fetching, no mutation, no randomness. */
export function tasksReducer(state: TasksState, action: TasksAction): TasksState {
  switch (action.type) {
    case 'fetchStarted':
      return { status: 'loading' };
    case 'fetchSucceeded':
      return { status: 'succeeded', data: action.tasks };
    case 'fetchFailed':
      return { status: 'failed', error: action.error };
    case 'taskToggled':
      if (state.status !== 'succeeded') return state;
      return { status: 'succeeded', data: toggleTask(state.data, action.id) };
    default:
      return assertNever(action);
  }
}
```

Why a separate `.ts` file? The reducer has **no React in it**. It's pure TypeScript, testable with Vitest exactly like `task-utils` (you'll set up Vitest in the frontend in S15). Keeping it free of React also makes it trivially portable into a Redux slice later.

## 2. ✍️ `src/hooks/useTasks.ts`

```ts
import { useCallback, useEffect, useReducer, useState } from 'react';
import { fetchTasks } from '../data/fetch-tasks';
import { toErrorMessage } from '../domain/guards';
import { initialTasksState, tasksReducer } from './tasks-reducer';

/** Loads tasks on mount (and on reload) and exposes the state plus event functions. */
export function useTasks() {
  const [state, dispatch] = useReducer(tasksReducer, initialTasksState);
  const [reloadCount, setReloadCount] = useState(0);

  useEffect(() => {
    const controller = new AbortController();
    dispatch({ type: 'fetchStarted' });

    fetchTasks(controller.signal)
      .then((tasks) => dispatch({ type: 'fetchSucceeded', tasks }))
      .catch((error: unknown) => {
        if (controller.signal.aborted) return; // cancelled on purpose: not an error
        dispatch({ type: 'fetchFailed', error: toErrorMessage(error) });
      });

    return () => controller.abort(); // cleanup: runs before re-running and on unmount
  }, [reloadCount]);

  const toggle = useCallback((id: number) => dispatch({ type: 'taskToggled', id }), []);
  const reload = useCallback(() => setReloadCount((n) => n + 1), []);

  return { state, toggle, reload };
}
```

### What changed and why

- **All state transitions live in the reducer.** The hook only decides *when* events happen (effect lifecycle, user calls).
- **`reload`**: bumping `reloadCount` changes the effect's dependency, so the effect **cleans up** (aborting any in-flight request) and **re-runs** (a new fetch). This is "synchronise with `reloadCount`", the effect mental model from 08.03.
- **`dispatch` needs no dependency.** React guarantees it's stable. That's why `toggle`'s `useCallback` has `[]` (08.13 explains `useCallback`).

## 3. ✍️ A "Try again" button in `App.tsx`

```tsx
const { state, toggle, reload } = useTasks();
// …
case 'failed':
  content = (
    <div role="alert">
      <p className="text-danger">{state.error}</p>
      <Button onClick={reload}>Try again</Button>
    </div>
  );
  break;
```

## 4. Replay the reducer by hand (a mental-model exercise)

In the browser console of your dev server, or in a scratch test file:

```ts
const actions: TasksAction[] = [
  { type: 'fetchStarted' },
  { type: 'fetchSucceeded', tasks: SAMPLE_TASKS },
  { type: 'taskToggled', id: 3 },
  { type: 'taskToggled', id: 3 },
];
const finalState = actions.reduce(tasksReducer, initialTasksState);
```

Same actions → same final state, every time. That determinism is what makes Redux DevTools' "time travel" possible (S16): replay the recorded actions, get the same states.

## 6. Summary

- The reducer (pure, React-free) holds every transition; the hook wires events to `dispatch`.
- Effect dependencies drive reloads; cleanup aborts stale requests.
- `dispatch` is stable; actions are typed discriminated unions with `assertNever`.
