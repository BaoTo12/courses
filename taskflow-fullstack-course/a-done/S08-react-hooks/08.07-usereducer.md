# Lecture 08.07 · `useReducer`: `(state, action) => newState`, the Direct Bridge to Redux

> **Section:** S08 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~30 minutes
> 🔗 Official reading: react.dev → Learn → "Extracting State Logic into a Reducer"

---

## 1. The problem

`useTasks` from 08.04 has update logic scattered across the hook: `setState({ status: 'loading' })` in the effect, another `setState` in `.then`, another in `.catch`, another in `toggle`, and soon `editTitle`, `delete`, `add`… Each setter call encodes *how* state changes, in a different place. As logic grows, it's hard to see all the ways state can change, and hard to test.

## 2. The idea: describe *what happened*, compute the new state in one place

```ts
type TasksAction =
  | { type: 'fetchStarted' }
  | { type: 'fetchSucceeded'; tasks: Task[] }
  | { type: 'fetchFailed'; error: string }
  | { type: 'taskToggled'; id: number };

function tasksReducer(state: TasksState, action: TasksAction): TasksState {
  switch (action.type) {
    case 'fetchStarted':   return { status: 'loading' };
    case 'fetchSucceeded': return { status: 'succeeded', data: action.tasks };
    case 'fetchFailed':    return { status: 'failed', error: action.error };
    case 'taskToggled':
      if (state.status !== 'succeeded') return state;
      return { status: 'succeeded', data: toggleTask(state.data, action.id) };
    default:
      return assertNever(action);
  }
}
```

```tsx
const [state, dispatch] = useReducer(tasksReducer, initialTasksState);

dispatch({ type: 'taskToggled', id: 3 });
```

- An **action** is a plain object describing **an event that happened** (`taskToggled`), not a command (`setTasks`).
- The **reducer** is a **pure function** `(state, action) → newState` (04.06): no fetching, no mutation, no randomness, no `Date.now()`.
- **`dispatch(action)`** hands the action to React; on the next render, React calls `reducer(currentState, action)` and stores the result.

The name comes from `Array.prototype.reduce`: a reducer folds a sequence of actions into a state, just as `reduce` folds array items into a value.

```ts
[{ type: 'fetchStarted' }, { type: 'fetchSucceeded', tasks }, { type: 'taskToggled', id: 3 }]
  .reduce(tasksReducer, initialTasksState);   // → the final state (really works!)
```

## 3. Why this matters

| Benefit | Because |
|---|---|
| **All transitions in one place** | Read the reducer = know every way state can change |
| **Testable without React** | `expect(tasksReducer(state, action)).toEqual(…)`: pure functions (S15 does exactly this) |
| **Typed events** | Discriminated union actions (06.06): each `case` sees the right payload; `assertNever` catches unhandled actions |
| **Handlers get simpler** | `onToggle={(id) => dispatch({ type: 'taskToggled', id })}` |
| **`dispatch` is stable** | Same function identity across renders: safe to pass down or use in effects without re-subscribing |

## 4. `useState` vs `useReducer`

| Prefer `useState` when… | Prefer `useReducer` when… |
|---|---|
| Independent simple values (`isOpen`, `query`) | Several values change together (status + data + error) |
| Updates are trivial (`setX(v)`) | Many different events update the same state |
| | You want the logic tested in isolation |

They're interchangeable in power; `useState` is actually implemented as a built-in reducer internally.

## 5. The bridge to Redux

Look at what you now have:

```text
component ──dispatch(action)──▶ reducer(state, action) ──▶ new state ──▶ re-render
```

**That is Redux's data flow**, scoped to one component. Redux (S14+) moves this same pattern to a **global store**: one state tree for the app, reducers combined per feature, `dispatch` available to any component, middleware between dispatch and reducer (for logging, async work…), selectors to read state, and DevTools to watch every action. Everything you write in this section carries over directly: the action design, reducer purity, immutable updates, exhaustive switches.

## 6. Summary

- `useReducer(reducer, initialState)` → `[state, dispatch]`.
- Actions describe **events**; the reducer computes the next state **purely**.
- Centralised, testable, typed state transitions; stable `dispatch`.
- It's Redux's core loop at component scale.
