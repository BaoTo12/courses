# Lecture 08.13 · `useMemo`, `useCallback`, `React.memo`: a First Look

> **Section:** S08 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~25 minutes
> The deep dive, with profiling and reselect, is S21. This lecture gives you the vocabulary.

---

## 1. The problem: new references on every render

Every render re-runs your component function, so every object, array and function **created in the body is new** (04.03):

```tsx
function App() {
  const visible = filterTasks(tasks, filter);        // new array every render
  const handleToggle = (id: number) => { … };        // new function every render
  const options = { dense: true };                   // new object every render
}
```

Usually that's fine. It matters when a new reference:
1. is a **dependency** of an effect (the effect re-runs every render: 08.17's infinite loop),
2. is a **context value** (all consumers re-render: 08.09),
3. is a **prop of a memoised child** (the memoisation is defeated),
4. or the computation itself is **expensive**.

## 2. `useMemo`: cache a computed value

```tsx
const visible = useMemo(
  () => filterTasks(tasks, { status: statusFilter ?? undefined, q: debouncedQuery }),
  [tasks, statusFilter, debouncedQuery],
);
```

React re-runs the function only when a dependency changes (by `Object.is`); otherwise it returns the **same** cached array. That gives stable references and skips the recomputation.

## 3. `useCallback`: cache a function

```tsx
const toggle = useCallback((id: number) => dispatch({ type: 'taskToggled', id }), []);
```

`useCallback(fn, deps)` is `useMemo(() => fn, deps)`: it returns the **same function object** until a dependency changes. `useTasks` (08.08) uses it so callers get stable `toggle`/`reload` functions.

## 4. `React.memo`: skip re-rendering a component when its props are unchanged

```tsx
export const TaskCard = memo(function TaskCard({ task, onToggle }: TaskCardProps) { … });
```

A memoised component re-renders only if some prop changed by `Object.is`. It works together with the tools above: if `onToggle` is a **new function every render**, `memo` never helps. With `useCallback` and immutable updates (unchanged tasks keep their reference, 04.05), toggling one task re-renders **one** card instead of all of them.

## 5. Don't memoise everything

Memoisation has costs: extra memory, dependency comparisons, and more complex code that's easy to get wrong (a missing dependency = stale value). The rule in this course:

> **Measure first (React DevTools Profiler, S21), then memoise where it removes real work, or where a stable reference is required** (effect dependencies, context values, props of memoised children).

(The **React Compiler** can add memoisation automatically at build time. It's an optional build plugin. Knowing the manual tools still matters for reading existing code and understanding what the compiler does.)

## 6. Summary

- Every render creates new objects/functions; sometimes identity matters.
- `useMemo` caches values; `useCallback` caches functions; `memo` skips re-renders on equal props.
- They only pay off together with immutable updates and stable references.
- Measure first; S21 goes deep (Profiler, reselect, selector factories).
