## E. Implementation

12. Write `usePrevious<T>(value: T): T | undefined` that returns the value from the **previous** render. Which hooks do you need, and why not `useState`?

---

<details>
<summary><b>Answers</b></summary>

1. By **call order** within the component instance's hook list. Therefore hooks must be called unconditionally, at the top level, in the same order every render (Rules of Hooks).

2. Dependencies are compared with `Object.is`; a new object literal is a different reference each render, so React sees a change every time.

3. Custom hooks share **logic**, not **state**. Two components calling `useTasks()` each fetch and hold separate copies that can drift, which is why shared task data needs Context/Redux/RTK Query.

4. `useReducer` gives good update logic but is local to one component. Context can share it, but every consumer re-renders on every change, and large frequently-changing state in context gets slow and tangled. Redux keeps one store with **selective subscriptions** (components re-render only when their selected data changes), middleware and DevTools. For TaskFlow's app-wide tasks: Redux (and later RTK Query for server data).

5. `1`, and with `setCount(c => c + 1)` twice: `2`.

6. An `async` function returns a **Promise**, but an effect must return nothing or a **cleanup function**. Also there's no abort/ignore handling. Use `.then` or an inner async function, plus an `AbortController` cleanup.

7. **`1`**. The interval callback closed over `n = 0` from the first render (stale closure) and the effect never re-runs. Fix: `setN((x) => x + 1)`.

8. **Feature**: StrictMode's dev-only mount→cleanup→mount. Ensure the cleanup undoes the effect.

9. Out-of-order responses: an older, slower request resolves last and overwrites newer results. Fix with an `AbortController` cleanup (abort previous) or an `ignore` flag; also debounce to reduce requests.

10. The effect's **dependency array**: is something recreated every render (object/array/function) and does the effect set state?

11. Search text → `useState` (controlled input). Debounce timer ID → `useRef` (not rendered). Tasks + loading/error → `useReducer` (in `useTasks`; later Redux/RTK Query). Filtered list → **derived** (compute in render, memoise if needed). Theme preference → **Context** (+ persisted). "Is editing" of one card → `useState` local to the card.

12.
    ```ts
    export function usePrevious<T>(value: T): T | undefined {
      const ref = useRef<T | undefined>(undefined);
      useEffect(() => {
        ref.current = value;   // runs AFTER render, so during render ref still holds the previous value
      }, [value]);
      return ref.current;
    }
    ```
    A ref, because updating it must **not** trigger another render (with `useState` you'd cause an extra render on every change). Note: this reads `ref.current` during render, an accepted exception for this small pattern.

</details>
