# Lecture 08.06 · `useRef`: Mutable Boxes, DOM References, and Refs vs State

> **Section:** S08 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~20 minutes

---

## 1. What a ref is

```tsx
const ref = useRef(initialValue);   // { current: initialValue }
```

`useRef` returns the **same object** on every render. You can read and write `ref.current` freely, and **changing it does not trigger a re-render**.

| | `useState` | `useRef` |
|---|---|---|
| Survives re-renders | ✅ | ✅ |
| Changing it re-renders | ✅ | ❌ |
| Read during render | ✅ (snapshot) | ⚠️ avoid (not a snapshot; can be stale or inconsistent) |
| Typical use | Data shown in the UI | DOM nodes, timer IDs, "latest value" for callbacks, instance variables |

Rule of thumb: **if it affects what's rendered, it's state. If it's only for event handlers and effects, it can be a ref.**

## 2. DOM references

```tsx
const inputRef = useRef<HTMLInputElement>(null);

<input ref={inputRef} … />

// later, in an effect or handler:
inputRef.current?.focus();
inputRef.current?.select();
```

- React sets `ref.current` to the DOM element **after commit** and back to `null` on unmount.
- The type is `RefObject<HTMLInputElement | null>`, so use `?.`.
- Use refs for **imperative** DOM APIs React doesn't model: focus, selection, scrolling, measuring, media playback, integrating non-React libraries.

TaskFlow's inline title editing (08.15) focuses and selects the input when editing starts, using exactly this.

## 3. Storing non-rendered values

```tsx
const timerRef = useRef<number | null>(null);

function start() {
  timerRef.current = window.setTimeout(save, 1000);
}
function cancel() {
  if (timerRef.current !== null) clearTimeout(timerRef.current);
}
```

Putting the timer ID in state would cause a pointless re-render every time it changes.

### The "latest value" ref (a fix for stale closures)

```tsx
const latestQuery = useRef(query);
latestQuery.current = query;   // updated during render: acceptable for this narrow pattern

useEffect(() => {
  const id = setInterval(() => {
    console.log('polling for', latestQuery.current);   // always fresh, without re-subscribing
  }, 5000);
  return () => clearInterval(id);
}, []);
```

## 4. Don't

- **Don't mutate refs to drive the UI.** The screen won't update.
- **Don't read `ref.current` during render** to decide what to show (except for lazy initialisation patterns).
- **Don't reach into the DOM to change content React owns** (`ref.current.textContent = …`). React will overwrite it, or get confused. Change state instead.

## 5. Summary

- `useRef` = a persistent `{ current }` box; changes don't re-render.
- DOM refs for focus/scroll/measure; `?.` because they're `null` before mount.
- Refs for timer IDs and "latest value" patterns; state for anything rendered.
