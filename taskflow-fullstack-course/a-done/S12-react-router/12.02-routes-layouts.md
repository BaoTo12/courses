# Lecture 12.02 · 🛠 Routes, Layouts, `<Outlet>`, and `<Link>` vs `<a>`

> **Section:** S12 · **Type:** 🛠 Build · **Track:** ★ Core · **Time:** ~50 minutes
> **Project feature:** React Router 8 installed; a route table; a shared layout; tasks state shared by all pages via a `TasksProvider`

## 1. Install

Stop the dev server (09.03's lesson), then:

```bash
npm install react-router
```

At the time of writing this installs **React Router 8**. Two things to know:
- Everything is imported from **`react-router`**. The old `react-router-dom` package stopped at v7; you'll still see it in existing codebases (same components, different package name).
- v8 requires **React ≥ 19.2.7** and **Node ≥ 22.22**.

React Router has several "modes" (declarative, data, framework). We use **declarative mode**: `<BrowserRouter>`, `<Routes>`, `<Route>`. It's the simplest mode, and the most common in existing codebases.

## 2. A new problem: several pages need the same tasks

Until now, `App` called `useTasks()` and passed data down. With routes, the list page, details page, edit page and dashboard **all** need the same tasks. Remember 08.11: calling `useTasks()` in each page would fetch separately and give **separate copies**. So lift it into a **context provider** (08.09):

`src/tasks/tasks-context.ts`:

```ts
import { createContext, useContext } from 'react';
import type { useTasks } from '../hooks/useTasks';

/** Everything useTasks() returns, shared with every page (replaced by Redux in S17). */
export type TasksContextValue = ReturnType<typeof useTasks>;

export const TasksContext = createContext<TasksContextValue | null>(null);

export function useTasksContext(): TasksContextValue {
  const context = useContext(TasksContext);
  if (context === null) {
    throw new Error('useTasksContext must be used inside <TasksProvider>');
  }
  return context;
}
```

`src/tasks/TasksProvider.tsx`:

```tsx
import type { ReactNode } from 'react';
import { useTasks } from '../hooks/useTasks';
import { TasksContext } from './tasks-context';

/** One useTasks() instance for the whole app: pages share the same tasks (08.11). */
export function TasksProvider({ children }: { children: ReactNode }) {
  const tasks = useTasks();
  return <TasksContext.Provider value={tasks}>{children}</TasksContext.Provider>;
}
```

`ReturnType<typeof useTasks>` (06.03) derives the context type from the hook, so there's no duplicate interface. Note the context re-renders all consumers whenever tasks change (08.09 §4). Acceptable for now; Redux fixes it in S17.

## 3. ✍️ `src/main.tsx`: the router wraps everything

```tsx
import { StrictMode } from 'react';
import { createRoot } from 'react-dom/client';
import { BrowserRouter } from 'react-router';
import '@styles/main.scss';
import { App } from './App';
import { ThemeProvider } from './theme/ThemeProvider';
import { ToastProvider } from './toast/ToastProvider';
import { AuthProvider } from './auth/AuthProvider';
import { TasksProvider } from './tasks/TasksProvider';

const rootElement = document.getElementById('root');
if (!rootElement) {
  throw new Error('#root element missing from index.html');
}

createRoot(rootElement).render(
  <StrictMode>
    <BrowserRouter>
      <ThemeProvider>
        <ToastProvider>
          <AuthProvider>
            <TasksProvider>
              <App />
            </TasksProvider>
          </AuthProvider>
        </ToastProvider>
      </ThemeProvider>
    </BrowserRouter>
  </StrictMode>,
);
```

(`AuthProvider` is built in 12.06; create it now or add it then.)

> ⚠️ **Pitfall observed while building this lecture:** with a stale `main.tsx` that lacked `<BrowserRouter>`, **the TypeScript build still passed**, but the page crashed at runtime with *"useRoutes() may be used only in the context of a `<Router>` component."* Router hooks and components depend on a provider **above** them, and the type system can't see that. If you see this error, check that `<BrowserRouter>` wraps the component tree.

## 4. ✍️ `src/App.tsx`: the route table

```tsx
import { Navigate, Route, Routes } from 'react-router';
import { AppLayout } from './layouts/AppLayout';
import { TasksPage } from './pages/TasksPage';
import { TaskDetailsPage } from './pages/TaskDetailsPage';
import { NotFoundPage } from './pages/NotFoundPage';

export function App() {
  return (
    <Routes>
      <Route element={<AppLayout />}>
        <Route index element={<Navigate to="/tasks" replace />} />
        <Route path="tasks" element={<TasksPage />} />
        <Route path="tasks/:id" element={<TaskDetailsPage />} />
        <Route path="*" element={<NotFoundPage />} />
      </Route>
    </Routes>
  );
}
```

(More routes are added in 12.05–12.09.)

- **`<Routes>`** picks the **best-matching** `<Route>` for the current URL (by specificity, not by order).
- **A layout route** (`<Route element={<AppLayout/>}>` without a `path`) wraps its children: every page renders **inside** the layout.
- **`index`** = the child for the parent's own path (`/`). Here it redirects to `/tasks`. `replace` so `/` doesn't remain in history.
- **`:id`** is a **URL parameter** (12.03).
- **`*`** matches anything else, giving a 404 page.

## 5. ✍️ `src/layouts/AppLayout.tsx`: the shell with `<Outlet>`

Move the header/footer from the old `PageLayout` into a layout route (then delete `PageLayout.tsx`):

```tsx
import { NavLink, Outlet } from 'react-router';
import { ThemeToggle } from '../components/ThemeToggle';
import { Stack } from '../components/styled/Stack';

/** NavLink passes { isActive } so the active link gets the design system's modifier class. */
const navClass = ({ isActive }: { isActive: boolean }) =>
  `page__nav-link${isActive ? ' page__nav-link--active' : ''}`;

/** The shell shared by every page: header + nav, the current page (<Outlet/>), footer. */
export function AppLayout() {
  return (
    <div className="page">
      <header className="page__header">
        <span className="page__brand">TaskFlow</span>
        <nav className="page__nav" aria-label="Main">
          <NavLink className={navClass} to="/tasks">
            Tasks
          </NavLink>
        </nav>
        <Stack $direction="row" $gap={3} $align="center" style={{ marginLeft: 'auto' }}>
          <ThemeToggle />
        </Stack>
      </header>
      <main className="page__main">
        <Outlet />
      </main>
      <footer className="page__footer">TaskFlow Web</footer>
    </div>
  );
}
```

- **`<Outlet />`** is the slot where the matched child route renders. Navigating between pages swaps only what's inside; the header stays mounted (its state survives).
- **`NavLink`** is a `Link` that knows whether it's active. Its `className` can be a **function** receiving `{ isActive }`, which maps neatly to our BEM modifier (`page__nav-link--active`, 02.09). NavLink also sets `aria-current="page"` on the active link automatically.

## 6. `<Link>` vs `<a>`

```tsx
<Link to="/tasks/5">Details</Link>     // client-side: pushState, no page load
<a href="/tasks/5">Details</a>          // full page load: the whole app restarts, state is lost
```

`<Link>` renders a real `<a href>` (so middle-click, "open in new tab" and accessibility still work) but intercepts normal clicks. Use `<a>` only for **external** sites or non-app URLs (e.g. downloading a file).

## 7. Pages

Move the task list UI from `App` into `src/pages/TasksPage.tsx` (12.04 shows the URL-driven version), and create a simple `src/pages/NotFoundPage.tsx`:

```tsx
import { Link } from 'react-router';

export function NotFoundPage() {
  return (
    <>
      <h1 className="page__title">Page not found</h1>
      <p className="text-muted">The page or task you're looking for doesn't exist (or was deleted).</p>
      <Link className="btn btn--primary btn--sm" to="/tasks">
        Go to tasks
      </Link>
    </>
  );
}
```

`className="btn btn--primary btn--sm"` on a `Link`: a navigation that **looks** like a button is still a link (semantics: it goes somewhere), and the BEM classes work on any element.

## 8. Summary

- `<BrowserRouter>` at the root; `<Routes>`/`<Route>` table; layout routes + `<Outlet/>`; `index`, `:params`, `*`.
- Shared page data moves into a context provider (`TasksProvider`).
- `<Link>`/`<NavLink>` for in-app navigation; `<a>` for external.
- Missing router provider = a runtime error the compiler can't catch.
