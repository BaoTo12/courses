# Lecture 12.01 · Client-Side Routing: the History API, and Why No Request Reaches the Server

> **Section:** S12 · 🧩 React Router (just-in-time)
> **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~20 minutes
> 🔗 Official reading: reactrouter.com (declarative mode: "Routing", "Navigating")

---

## 1. The problem

TaskFlow Web is one page (`index.html`) showing different "screens": the task list, a task's details, a form, a dashboard. Users expect real URLs:
- **Shareable**: send `…/tasks/5` to a colleague.
- **Bookmarkable**, with filters: `…/tasks?status=DONE`.
- **Back/Forward** buttons that work.

## 2. Two ways to change "the page"

### Server-side navigation (what JSP will do in Part 2)

```text
click <a href="/tasks/5">
  → browser sends GET /tasks/5 → server renders HTML → browser REPLACES the whole page
```

Every navigation is a full request/response and a full page load (00.04).

### Client-side navigation (what React Router does)

```text
click <Link to="/tasks/5">
  → JavaScript calls history.pushState(…, '/tasks/5')   ← URL bar changes, NO request
  → React Router notices the new location → renders <TaskDetailsPage/> → React updates the DOM
```

The **History API** (`history.pushState`, `history.replaceState`, the `popstate` event for Back/Forward) lets JavaScript change the URL **without** loading a page. React Router listens to it and picks which components to render for the current URL.

Verified in TaskFlow's reference app: clicking a task title changed the URL to `/tasks/3` and rendered the details page with **0** new navigation entries (`performance.getEntriesByType('navigation')`): no document request was sent.

## 3. What still reaches the server

- The **first** load of any URL (typing it, refreshing, opening a bookmark). The server must return `index.html` for **every** app path, or you get a 404 (12.08, 12.12).
- **Data** requests (JSON via Axios, S13), which are separate from navigation.
- Lazy-loaded **code chunks** (12.09).

## 4. Summary

- Client-side routing = the URL changes via the History API; React renders the matching screen; no page request.
- Server-side navigation (JSP) = a full request and page per click.
- The server still serves `index.html` for first loads of deep URLs.
