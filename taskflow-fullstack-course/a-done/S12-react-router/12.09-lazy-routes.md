# Lecture 12.09 · ＋ Lazy Routes and Code Splitting

> **Section:** S12 · **Type:** 📖 Theory + 🛠 Build · **Track:** ＋ Extended · **Time:** ~30 minutes
> **Project feature:** a `/dashboard` page whose code is downloaded only when first visited
> Verified: `npm run build` produced a separate `DashboardPage-*.js` chunk (0.65 kB), requested only when navigating to `/dashboard`.

---

## 1. The problem

By default, Vite bundles **all** your code into one JavaScript file. Every user downloads every page's code on the first visit, including pages they may never open (an admin screen, a heavy charts page). The bigger the app, the slower the first load.

**Code splitting** cuts the bundle into chunks that load on demand. The natural split points are **routes**: a user on `/tasks` doesn't need the dashboard's code yet.

## 2. The building blocks

### Dynamic `import()`

```ts
import('./pages/DashboardPage'); // returns a Promise of the module
```

A static `import … from` at the top of a file is resolved at build time and bundled together. A dynamic `import()` expression tells the bundler: *"put this module (and whatever only it uses) in a separate file, and fetch it when this code runs."*

### `React.lazy`

```tsx
const DashboardPage = lazy(() => import('./pages/DashboardPage'));
```

`lazy` takes a function that returns a Promise of a module **with a default export that is a component**. It returns a component you can render like any other. The first time it renders, React calls the function, starts the download, and **suspends**.

### `<Suspense>`

While a lazy component is loading, React looks for the nearest `<Suspense>` boundary above it and shows its `fallback`:

```tsx
<Suspense fallback={<p className="text-muted">Loading dashboard…</p>}>
  <DashboardPage />
</Suspense>
```

When the chunk arrives, React renders the real component. On later visits, the module is cached, so there's no fallback flash.

## 3. The named-export snag

TaskFlow uses **named exports** everywhere (`export function DashboardPage`). They're refactor-friendly and match the Fast Refresh rule (07.06). But `lazy` requires a **default** export. Adapt the module in the loader function:

```tsx
const DashboardPage = lazy(() =>
  import('./pages/DashboardPage').then((module) => ({ default: module.DashboardPage })),
);
```

The `.then` turns `{ DashboardPage }` into `{ default: DashboardPage }`, the shape `lazy` expects. TypeScript checks it: misspell `module.DashbordPage` and the build fails.

## 4. ✍️ Build the dashboard

`src/pages/DashboardPage.tsx`:

```tsx
import { useTasksContext } from '../tasks/tasks-context';
import { groupByStatus } from '../domain/task-utils';
import { statusLabel } from '../domain/labels';
import { TASK_STATUSES } from '../domain/types';
import { ProgressRing } from '../components/styled/ProgressRing';
import { Stack } from '../components/styled/Stack';

/** Loaded lazily (12.09): its code is a separate chunk, downloaded on first visit. */
export function DashboardPage() {
  const { state } = useTasksContext();
  if (state.status !== 'succeeded') return <p className="text-muted">Loading…</p>;

  const groups = groupByStatus(state.data);
  return (
    <>
      <h1 className="page__title">Dashboard</h1>
      <Stack $direction="row" $gap={6} $align="center" $wrap>
        <ProgressRing done={groups.DONE.length} total={state.data.length} />
        <dl>
          {TASK_STATUSES.map((s) => (
            <div key={s}>
              <dt className="text-muted">{statusLabel(s)}</dt>
              <dd>{groups[s].length}</dd>
            </div>
          ))}
        </dl>
      </Stack>
    </>
  );
}
```

`groupByStatus` is the utility from 04.06 (typed in 05.09; it returns a `Record<TaskStatus, Task[]>` with every status present). Iterating `TASK_STATUSES` (the `as const` array) keeps the display order fixed and type-safe.

In `App.tsx`:

```tsx
import { lazy, Suspense } from 'react';
// …

// Code splitting (12.09): the dashboard's code is downloaded on first visit.
// React.lazy expects a default export; our modules use named exports, so we adapt it.
const DashboardPage = lazy(() =>
  import('./pages/DashboardPage').then((module) => ({ default: module.DashboardPage })),
);

// inside <Route element={<AppLayout />}>:
<Route
  path="dashboard"
  element={
    <RequireAuth>
      <Suspense fallback={<p className="text-muted">Loading dashboard…</p>}>
        <DashboardPage />
      </Suspense>
    </RequireAuth>
  }
/>
```

Rules:
- Call `lazy` at **module top level**, never inside a component. Inside a component, each render would create a new lazy component type, so React would unmount and reload it every time (the same "component defined inside a component" bug as 09.15).
- Put `Suspense` **inside** `RequireAuth`: an anonymous user is redirected before the chunk is even requested.
- **Don't** statically import `DashboardPage` anywhere else. One static import and the bundler puts it back into the main chunk. Verified by adding a static import in `AppLayout`: the separate chunk disappeared, and Vite 8 printed `[INEFFECTIVE_DYNAMIC_IMPORT] src/pages/DashboardPage.tsx is dynamically imported by src/App.tsx but also statically imported by src/layouts/AppLayout.tsx, dynamic import will not move module into another chunk.`

## 6. Honest trade-offs

- **0.65 kB isn't worth splitting.** Our dashboard is tiny; this is a demonstration. In real apps, split pages that pull in **heavy dependencies** (charts, editors, date pickers) or that most users never open (admin screens). Measure before and after.
- **A waterfall on navigation**: the user clicks, *then* the download starts. Frameworks and the router's data mode can **preload** on hover. With plain `lazy`, you can call the `import()` early yourself (for example on `onMouseEnter` of the nav link).
- **Deploys can break old chunks**: a user with an old `index.js` open requests `DashboardPage-OLDHASH.js` after a new deploy has deleted it → the import fails. Keep old assets for a while, or catch the error with an error boundary (S27) and offer a reload. Also, the server must return a real **404** for a missing asset, not `index.html` (12.08 §3).
- **Security reminder (12.07):** a lazy chunk is not hidden. Anyone can download it.

## 7. Summary

- `import()` creates a split point; `lazy` turns it into a component; `<Suspense fallback>` shows something while it loads.
- `lazy` needs a default export: adapt named exports with `.then(m => ({ default: m.X }))`.
- Split by route, for pages that are heavy or rarely used. Measure.
