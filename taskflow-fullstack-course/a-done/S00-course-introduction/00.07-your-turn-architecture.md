> **Deliverables:** `docs/architecture.md` and `docs/security/threat-notes.md`

## 1. The task

Without looking back at the previous lectures (try it from memory first; peek only if stuck), produce two short documents.

### Part A: `docs/architecture.md`

Draw TaskFlow's architecture. ASCII art, a hand drawing (photo), or a diagram tool are all fine. Your diagram must include:

- [ ] The **browser**, with **both** clients (TaskFlow Web, TaskFlow Admin)
- [ ] **Tomcat** with: filters, page Servlets, API Servlets, JSP
- [ ] The **service layer**, **DAO layer**, and **MySQL**
- [ ] What travels on each arrow (**HTML**, **JSON**, **SQL**, **static files**)
- [ ] Where **build-time** tools act (Sass, TypeScript/Vite, Maven, Jasper)
- [ ] The **session cookie** and the **`lang` cookie**: who sets them, who sends them

Then write **one paragraph** under the diagram answering: *"What's different about how the two clients get their HTML?"*

### Part B: `docs/security/threat-notes.md`

Use this template:

---

## 2. Acceptance criteria

Your work is "done" when:

1. Someone who has never seen TaskFlow could look at your diagram and say which parts run in the browser and which run on the server.
2. The trust boundary is drawn **at the right place** (hint: where exactly does "untrusted" end?).
3. Every arrow is labelled with *what* travels on it.
4. Your threat notes have at least 5 assets, 6 entry points and 5 "things that could go wrong".

---

## 3. Hints (open only if stuck)

<details>
<summary>Hint 1: where is the boundary?</summary>

Ask: "Which of these can the user modify?" If the user can modify it (including your React code running in their browser), it's on the untrusted side.
</details>

<details>
<summary>Hint 2: arrows people forget</summary>

- The browser downloading the React **JavaScript bundle** and the **CSS**.
- The browser sending **cookies** automatically.
- The Admin Portal's forms **posting** back to Servlets.
- Build tools producing the files that Tomcat or the static server serves.
</details>

<details>
<summary>Hint 3: entry points people forget</summary>

Headers, cookies, and **data other users wrote earlier** (comments) that comes back out of the database.
</details>

---

## 4. Self-review questions (answer before opening the solution)

- Did you put the React app inside the trusted zone? (Common mistake. Why is it wrong?)
- Did you put MySQL on its own, reachable from the browser? (Why is it wrong?)
- Is there any arrow where a *Java object* crosses to the browser? (Why can't that happen?)
