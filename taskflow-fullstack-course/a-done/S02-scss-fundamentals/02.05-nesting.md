# Lecture 02.05 · Nesting and `&`: Parent Selectors, Modifiers, and the Specificity Trap

> **Section:** S02 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~25 minutes

---

## 1. The problem nesting solves

```css
.card { … }
.card .card__title { … }
.card .card__title a { … }
.card .card__title a:hover { … }
```

The selector `.card` is repeated, and the structure (title *inside* card, link *inside* title) is only implied. Nesting makes the structure visible and removes repetition.

---

## 2. Basic nesting

```scss
.card {
  padding: 16px;

  .card__title {
    font-size: 18px;

    a {
      color: blue;
    }
  }
}
```

Compiles to **descendant selectors**:

```css
.card { padding: 16px; }
.card .card__title { font-size: 18px; }
.card .card__title a { color: blue; }
```

Internally, Sass joins each nested selector to its parent's selector with a space (the descendant combinator) and flattens everything.

---

## 3. The parent selector `&`

`&` means "the parent selector, exactly here". It lets you attach things to the parent instead of creating a descendant.

### Pseudo-classes and pseudo-elements

```scss
.btn {
  background: $color-primary;

  &:hover     { background: $color-primary-dark; }
  &:disabled  { opacity: 0.5; }
  &::after    { content: ''; }
}
```

```css
.btn { background: #4f46e5; }
.btn:hover { background: #4338ca; }
.btn:disabled { opacity: 0.5; }
.btn::after { content: ""; }
```

> ⚠️ Without `&`, `:hover { … }` nested inside `.btn` would compile to `.btn :hover` (with a **space**), meaning "any hovered descendant of `.btn`". A classic bug.

### BEM suffixes

```scss
.card {
  &__title { … }       // .card__title
  &__meta  { … }       // .card__meta
  &--priority-high { … }   // .card--priority-high
}
```

`&__title` concatenates text onto the parent selector, producing a **single class** `.card__title`, not a descendant. This keeps specificity low (see below) while keeping the code grouped.

### Compound selectors and context

```scss
.btn {
  &.is-loading { … }        // .btn.is-loading  (both classes on the same element)
  .toolbar & { … }          // .toolbar .btn    (btn inside a toolbar)
  & + & { margin-left: 8px; }   // .btn + .btn   (a btn directly after another btn)
}
```

`&` can appear **anywhere** in the selector. `.toolbar &` puts the parent at the end, which is useful for "this component looks different in that context".

## 4. Nesting media queries and other at-rules

```scss
.task-grid {
  display: grid;
  gap: $space-4;

  @media (min-width: $bp-md) {
    grid-template-columns: repeat(2, 1fr);
  }
}
```

```css
.task-grid { display: grid; gap: 16px; }
@media (min-width: 768px) {
  .task-grid { grid-template-columns: repeat(2, 1fr); }
}
```

Sass "bubbles" the media query to the top level and puts the selector inside it. This keeps all of a component's responsive behaviour in one place. In S03 you'll wrap this in a `respond-to` mixin.

## 5. The specificity trap

### Quick specificity refresher

When two rules set the same property on an element, the browser uses the one with higher **specificity** (and, if equal, the later one). Roughly, count (IDs, classes/attributes/pseudo-classes, elements):

| Selector | Specificity |
|---|---|
| `a` | (0,0,1) |
| `.btn` | (0,1,0) |
| `.card .card__title a` | (0,2,1) |
| `.card .card__title a:hover` | (0,3,1) |
| `#main .card a` | (1,1,1) |

### How deep nesting hurts

Every nesting level (without `&`) adds to the selector, and **specificity grows**:

```scss
.page {
  .page__main {
    .card {
      .card__title {
        a { color: $color-primary; }   // .page .page__main .card .card__title a → (0,4,1)
      }
    }
  }
}
```

Later, you add a utility class `.text-danger { color: red; }` (0,1,0) to that link. **It loses.** (0,1,0) can't beat (0,4,1). So people reach for `!important`, then the next person needs `!important` to beat that, and the stylesheet spirals.

Deep nesting also couples CSS to HTML structure: move the card outside `.page__main` and it loses its styles.

### Rules of thumb

1. **Nest at most ~3 levels**, and prefer `&`-based nesting (which creates single classes) over descendant nesting.
2. With BEM (`&__title`), most selectors stay at **one class**: `.card__title a` rather than `.page .page__main .card .card__title a`.
3. Nest pseudo-classes (`&:hover`), modifiers (`&--x`), elements (`&__x`) and media queries. Avoid nesting **structural** descendants just because the HTML is nested.

---

## 6. A note on native CSS nesting

Modern browsers support CSS nesting natively (`.card { &:hover { … } }`). It looks similar, but details differ (e.g. native nesting doesn't support `&__title` suffix concatenation the way Sass does). Since Sass compiles nesting away, your output works in every browser regardless. More in Lecture 03.17.

---

## 7. Summary

- Nesting without `&` = **descendant** selectors (adds a space).
- `&` = the parent selector exactly here: `&:hover`, `&::after`, `&__elem`, `&--mod`, `&.state`, `.context &`, `& + &`.
- Media queries can be nested; Sass bubbles them out.
- **Deep nesting inflates specificity** and couples CSS to HTML. Keep it shallow, and prefer `&`.

```scss
.badge {

  &--done { color: green; }
  .icon + & { margin-left: 4px; }
  span { font-weight: bold; }
  :hover { opacity: .8; }
}
```

<details>
<summary>Answer</summary>

```css
.badge { padding: 2px 8px; }
.badge--done { color: green; }
.icon + .badge { margin-left: 4px; }
.badge span { font-weight: bold; }
.badge :hover { opacity: 0.8; }
```

The last rule is almost certainly a bug: it targets hovered *descendants* of `.badge`, not the badge itself. It should be `&:hover`.
