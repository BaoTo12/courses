# Lecture 03.16 · 🐞 Debug: `@extend` Inside a Media Query Won't Compile

> **Section:** S03 · **Type:** 🐞 Debug · **Track:** ＋ Extended · **Time:** ~15 minutes

---

## Symptom

A developer wants cards to gain a border only on medium screens and up. They reuse a placeholder:

```scss
%card-base {
  border: 1px solid theme('border');
}

.card {
  @include respond-to('md') {
    @extend %card-base;
  }
}
```

Compilation fails:

```text
Error: From line 1, column 1 of styles/components/_card.scss:
  ╷
1 │ %card-base {
  │ ^^^^^^^^^^^
  ╵
You may not @extend selectors across media queries.
```

## Investigation checklist

1. Recall 03.08: what does `@extend` do to the output? Where does the combined rule end up?
2. `%card-base` is defined **outside** any media query. `.card` extends it from **inside** `@media (min-width: 768px)`. If Sass grouped `.card` onto `%card-base`'s rule, would the border apply at all widths or only ≥ 768px?
3. What tool from 03.01 copies declarations *into the place you write it*?

## Explanation

`@extend` works by **adding your selector to the extended rule where that rule lives**. `%card-base`'s rule lives at the top level (no media query). If Sass added `.card` there, the border would apply at **every** width, ignoring the media query you wrote. That silently changes meaning, so Sass refuses.

**Fix: use a mixin.** A mixin copies declarations **into** the media query:

```scss
@mixin card-border {
  border: 1px solid theme('border');
}

.card {
  @include respond-to('md') {
    @include card-border;
  }
}
```

```css
@media (min-width: 768px) {
  .card { border: 1px solid var(--color-border); }
}
```

This is exactly why 03.08 recommends mixins over `@extend`: mixins work in every context, and their output appears where you wrote it.

## What this trained

Reading a compiler error **in terms of the mental model** ("where does `@extend` put things?") instead of searching for the message online. The same skill applies when you read React warnings (S07) or JSP compilation errors (S33).
