# Lecture 03.06 · Control Flow: `@each`, `@for`, `@if`/`@else`, Interpolation

> **Section:** S03 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~25 minutes

---

## 1. Why a stylesheet needs loops and conditions

Because CSS is full of **families** of rules: one class per status, per priority, per size, per breakpoint, per theme. Writing each by hand means the list of statuses lives in many places. Control flow lets you write the rule **once** and generate the family **from data** (maps from 03.05).

All of this runs at **compile time**. The output is ordinary CSS rules. The browser never loops.

---

## 2. `@each`: iterate lists and maps

### Over a list

```scss
$sizes: 'sm', 'md', 'lg';

@each $size in $sizes {
  .icon--#{$size} { /* … */ }
}
```

### Over a map (key + value)

```scss
@each $priority, $color in $priority-colors {
  .card--priority-#{$priority}::before {
    background: $color;
  }
}
```

```css
.card--priority-low::before { background: #14b8a6; }
.card--priority-medium::before { background: #f59e0b; }
.card--priority-high::before { background: #ef4444; }
```

### Over a nested map (destructuring the inner map)

```scss
@each $status, $colors in $status-colors {
  .badge--#{$status} {
    background: map.get($colors, 'bg');
    color: map.get($colors, 'fg');
  }
}
```

---

## 3. Interpolation `#{…}`: building names

Interpolation inserts a value **as text** into places where Sass would otherwise not evaluate expressions:

| Where | Example | Output |
|---|---|---|
| Selectors | `.badge--#{$status}` | `.badge--in-progress` |
| Property names | `margin-#{$side}: 0` | `margin-left: 0` |
| Custom property values | `--color-#{$name}: #{$value}` | `--color-primary: #4f46e5` |
| Media queries | `@media (min-width: #{$bp})` | `@media (min-width: 768px)` |
| Strings / messages | `@error 'Bad value #{$x}'` | readable error text |
| `url()` | `url('/img/#{$name}.svg')` | `url('/img/logo.svg')` |

Inside normal property **values** (`padding: $x * 2`) you don't need interpolation; Sass evaluates them already. Using `#{}` there turns numbers into unquoted strings and can break math. Use it only where needed.

---

## 4. `@for`: numeric ranges

```scss
@for $i from 1 through 4 {
  .mt-#{$i} { margin-top: space($i); }
}
```

- `from 1 through 4` → 1, 2, 3, 4 (inclusive).
- `from 1 to 4` → 1, 2, 3 (**exclusive** of the end).

Useful for scales (spacing utilities, heading sizes). Be careful not to generate hundreds of unused classes; every generated rule ships to the user.

---

## 5. `@if` / `@else if` / `@else`

```scss
@mixin button-variant($variant) {
  @if $variant == 'primary' {
    background: var(--color-primary);
    color: #fff;
  } @else if $variant == 'secondary' {
    background: var(--color-surface);
    border-color: var(--color-border);
  } @else {
    @error 'Unknown button variant "#{$variant}".';
  }
}
```

Conditions use `==`, `!=`, `<`, `>`, `and`, `or`, `not`. **Truthiness:** only `false` and `null` are falsy; `0`, `''` and empty lists are **truthy** (unlike JavaScript, where `0` and `''` are falsy; you'll compare the two in S04).

The `if()` **function** is an inline ternary: `color: if($dark, #fff, #000);`.

---

## 6. `@while`

Exists; rarely needed. `@each` and `@for` cover almost everything, and are harder to turn into infinite loops.

---

## 7. How much logic belongs in stylesheets?

Control flow is powerful and easy to overuse. Guidelines:

- ✅ Generating **variants from token maps** (statuses, priorities, themes, breakpoints).
- ✅ **Validation** with `@error` in mixins/functions.
- ⚠️ Generating large **utility-class** sets: fine in moderation; utility frameworks exist for that.
- ❌ Complex algorithms that nobody can read. If a reviewer can't predict the output, simplify.

Always check the **compiled CSS** after writing a loop. It's the ground truth.

---

## 8. Summary

- `@each` over lists and maps (with key/value destructuring) generates rule families from data.
- `#{}` interpolation builds selectors, property names, custom properties, media queries and messages.
- `@for … through` (inclusive) vs `@for … to` (exclusive).
- `@if`/`@else`; only `false`/`null` are falsy in Sass.
- Logic runs at compile time; check the output; don't over-engineer.

## 9. Check yourself

1. How many rules does `@for $i from 0 to 3 { .p-#{$i} { padding: space($i); } }` generate, and with which class names?
2. Is `@if 0 { … }` executed?
3. Why is `padding: #{$x * 2};` worse than `padding: $x * 2;`?

<details>
<summary>Answers</summary>

1. **Three**: `.p-0`, `.p-1`, `.p-2` (`to` excludes 3).
2. **Yes.** `0` is truthy in Sass.
3. It's unnecessary, and interpolation converts the result into an unquoted string, so you lose it as a number for further math, and type errors show up later and are harder to understand.

</details>
