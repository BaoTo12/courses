# Lecture 03.17 · Modern CSS vs Sass: What Sass Still Gives You

> **Section:** S03 · **Type:** 📖 Theory · **Track:** ＋ Extended · **Time:** ~20 minutes

---

## 1. Why this lecture

You'll hear "you don't need Sass anymore, CSS has variables and nesting now". It's half true. Understanding **exactly** what overlaps and what doesn't lets you make (and defend) the choice on a real team.

## 2. Feature-by-feature

| Need | Modern CSS | Sass | Notes |
|---|---|---|---|
| Variables | ✅ Custom properties (runtime, cascade, JS-accessible) | ✅ `$vars` (compile time) | Different tools; TaskFlow uses **both** (03.12) |
| Nesting | ✅ Native nesting (widely supported) | ✅ | Sass supports **suffix concatenation** `&__title`; native nesting doesn't (`&__title` isn't valid native CSS). Important for BEM. |
| Colour manipulation | ✅ `color-mix(in srgb, var(--color-primary), black 15%)`, relative colour syntax | ✅ `color.scale`, `color.mix` | CSS versions work at **runtime** with custom properties, so they can derive hover colours from the *current* theme. |
| Math | ✅ `calc()`, `min()`, `max()`, `clamp()`, `round()`, `mod()`, `rem()` | ✅ compile-time math with unit checks | Runtime math can mix `%`, `vw` and `px`; Sass can't. |
| Modules / file splitting | ⚠️ `@import url()` = extra HTTP requests (bundlers can inline) | ✅ `@use`/`@forward`, namespaces, privacy | Sass bundles into one file |
| Loops, maps, conditionals | ❌ | ✅ | Generating variants from data (03.07) |
| Mixins with parameters | ❌ (proposals exist) | ✅ | |
| Compile-time validation (`@error`) | ❌ | ✅ | Typos fail the build (03.02, 03.12) |
| Cascade layers | ✅ `@layer` | (outputs it fine) | `@layer base, components, utilities;` makes cascade order explicit, independent of specificity |
| Container queries | ✅ `@container` | (outputs it fine) | Components respond to their **container's** size, not the viewport |

## 3. A quick taste of the modern CSS features

```css
/* Runtime-derived hover colour that follows the current theme */
.btn--primary:hover {
  background: color-mix(in srgb, var(--color-primary), black 15%);
}

/* Cascade layers: order, not specificity, decides between layers */
@layer reset, base, components, utilities;

/* Container query: a card adapts to its column width */
.task-grid { container-type: inline-size; }
@container (min-width: 400px) {
  .card__meta { flex-direction: row; }
}
```

You can write all of these inside SCSS files. Sass passes them through untouched.

## 4. The pragmatic position for TaskFlow (and most teams)

- Use **Sass for authoring**: modules, maps, loops, mixins, compile-time checks, BEM suffix nesting.
- Use **modern CSS for runtime behaviour**: custom properties for theming, `calc()`/`clamp()` for fluid layouts, `color-mix()` when a value must follow the runtime theme, container queries where component-level responsiveness matters.
- Keep an eye on the platform. As native CSS gains mixins and functions, some Sass features will become unnecessary, just as `@import` did.

## 5. Check yourself

1. Why can't native CSS nesting replace Sass's `&__title` for BEM?
2. When is `color-mix()` better than `color.scale()`?

<details>
<summary>Answers</summary>

1. Native nesting treats `&` as a selector reference, not a text prefix; `&__title` (string concatenation) isn't valid there. Sass concatenates text at compile time.
2. When the base colour is a **runtime** value (a custom property that changes with the theme). `color.scale` only works on colours known at compile time.

</details>
