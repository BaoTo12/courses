# Lecture 03.02 · 🛠 Build: the `respond-to($breakpoint)` Mixin

> **Section:** S03 · **Type:** 🛠 Build · **Track:** ★ Core · **Time:** ~25 minutes
> **Project feature:** `styles/abstracts/_mixins.scss` with `respond-to`, `focus-ring` and `truncate`; a breakpoint map in `styles/abstracts/_tokens.scss`

---

## 1. Why a breakpoint mixin

Right now, `_page.scss` has:

```scss
@media (min-width: $bp-md) {
  grid-template-columns: repeat(2, 1fr);
}
```

Problems as the app grows:
- Every developer picks their own breakpoints (`760px`, `768px`, `48em`…).
- Typos like `$bp-mdd` fail, but `@media (min-width: 786px)` silently "works".
- Changing the breakpoint strategy (e.g. `px` → `em`) means editing every media query.

A mixin gives **named breakpoints**, **one definition**, and **compile-time errors** for unknown names.

---

## 2. ✍️ Create the tokens file with a breakpoint map

Create `styles/abstracts/_tokens.scss`:

```scss
// Design tokens that are STRUCTURED DATA (maps). More are added in 03.05 and 03.12.
$breakpoints: (
  'sm': 480px,
  'md': 768px,
  'lg': 1024px,
  'xl': 1280px,
);
```

A **map** is a key → value collection. Lecture 03.05 covers maps in depth; for now you need one function: `map.get($map, $key)` returns the value for a key, or `null` if there isn't one.

---

## 3. ✍️ Create the mixins file

Create `styles/abstracts/_mixins.scss`:

```scss
@use 'sass:map';
@use 'tokens' as *;

/// Mobile-first media query for a named breakpoint.
/// @param {String} $breakpoint - one of the keys in $breakpoints
@mixin respond-to($breakpoint) {
  @if not map.has-key($breakpoints, $breakpoint) {
    @error 'Unknown breakpoint "#{$breakpoint}". Use one of: #{map.keys($breakpoints)}';
  }

  @media (min-width: map.get($breakpoints, $breakpoint)) {
    @content;
  }
}

/// Visible keyboard focus indicator.
@mixin focus-ring($color: var(--color-primary), $offset: 2px) {
  outline: 2px solid $color;
  outline-offset: $offset;
}

/// Single-line ellipsis, or multi-line clamp when $lines > 1.
@mixin truncate($lines: 1) {
  @if $lines == 1 {
    overflow: hidden;
    white-space: nowrap;
    text-overflow: ellipsis;
  } @else {
    display: -webkit-box;
    -webkit-line-clamp: $lines;
    -webkit-box-orient: vertical;
    overflow: hidden;
  }
}
```

### Line by line

- **`@use 'tokens' as *;`**: the mixins module depends on the tokens module. Remember from 02.12: every module loads what it uses.
- **`map.has-key` + `@error`**: `@include respond-to('tablet')` now **fails the build** with a helpful message:
  ```text
  Error: 'Unknown breakpoint "tablet". Use one of: sm, md, lg, xl'
  ```
  That's the power of compile time: mistakes are caught on your machine, not by a user on a phone.
- **`#{map.keys($breakpoints)}`**: interpolating a list prints it comma-separated inside the message.
- **Mobile-first `min-width`**: base styles target small screens; each breakpoint *adds* rules for larger screens. It's simpler to reason about than a mix of `min-width` and `max-width` queries.
- **`focus-ring($color: var(--color-primary))`**: the default is a CSS custom property (runtime value). We'll emit `--color-primary` in 03.12. Until then, you can pass `$color-primary` explicitly, or keep reading; it'll work after 03.12. Mixing compile-time structure with runtime values is exactly the pattern this section builds towards.

## 4. Use it

In `styles/layout/_page.scss`, load the new modules and replace the raw media query:

```scss
@use '../abstracts/variables' as *;
@use '../abstracts/mixins' as *;

// …

.task-grid {
  display: grid;
  gap: $space-4;
  grid-template-columns: 1fr;

  @include respond-to('md') {
    grid-template-columns: repeat(2, 1fr);
  }
}
```

Compiled output:

```css
.task-grid {
  display: grid;
  gap: 16px;
  grid-template-columns: 1fr;
}
@media (min-width: 768px) {
  .task-grid {
    grid-template-columns: repeat(2, 1fr);
  }
}
```

Also use `truncate` for card titles in `_card.scss` (load `../abstracts/mixins` there too):

```scss
&__title {
  // …
  @include truncate(2);
}
```

And `focus-ring` in `_button.scss`:

```scss
&:focus-visible {
  @include focus-ring($color-primary);   // explicit colour until 03.12 emits --color-primary
}
```

Now try a typo: `@include respond-to('mdd')`. Read the error, then fix it.

> 🔜 Loading `variables` **and** `mixins` in every file is getting repetitive. In 03.10 an `abstracts/_index.scss` will `@forward` everything so each component needs a single line.

## 6. Summary

- Breakpoints live in **one map**; `respond-to('md')` wraps content in the right media query.
- `@error` turns typos into **build failures** with helpful messages.
- Mobile-first: base styles for small screens, `min-width` queries add larger layouts.
- `focus-ring` and `truncate` remove repeated declaration groups.
