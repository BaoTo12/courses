# Lecture 03.05 · Maps and `sass:map`: Modelling Design Tokens as Data

> **Section:** S03 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~25 minutes

---

## 1. The problem

In S02 you wrote:

```scss
$color-status-todo-bg: #e0e7ff;
$color-status-todo-fg: #3730a3;
$color-status-in-progress-bg: #fef3c7;
$color-status-in-progress-fg: #92400e;
$color-status-done-bg: #dcfce7;
$color-status-done-fg: #166534;
```

and six nearly identical badge blocks. The **structure** of the data ("each status has a background and a foreground") exists only in variable names. Sass can't loop over variable names. It *can* loop over a **map**.

---

## 2. What a map is

A map is a collection of **key → value** pairs, like a `Map` in Java or an object in JavaScript:

```scss
$priority-colors: (
  'low': #14b8a6,
  'medium': #f59e0b,
  'high': #ef4444,
);
```

- Parentheses, `key: value` pairs, commas between pairs (a trailing comma is allowed and recommended for clean diffs).
- **Quote string keys** (`'in-progress'`). Unquoted keys work too, but quoting avoids surprises: `(red: …)` would make the key the *colour* red, not the string `'red'`.
- Values can be anything, **including other maps** (nested maps):

```scss
$status-colors: (
  'todo':        ('bg': #e0e7ff, 'fg': #3730a3),
  'in-progress': ('bg': #fef3c7, 'fg': #92400e),
  'done':        ('bg': #dcfce7, 'fg': #166534),
);
```

Now the structure is explicit, and the key names match the Java/TS enum values (lower-cased, hyphenated): `TODO` → `'todo'`, `IN_PROGRESS` → `'in-progress'`. That consistency pays off when JSP and React build class names like `badge--${status}`.

## 3. The `sass:map` module

```scss
@use 'sass:map';

map.get($priority-colors, 'high')                    // #ef4444
map.get($status-colors, 'todo', 'fg')                // #3730a3  (nested lookup with extra keys)
map.get($priority-colors, 'urgent')                  // null (missing key)
map.has-key($priority-colors, 'urgent')              // false
map.keys($priority-colors)                           // 'low', 'medium', 'high'
map.values($priority-colors)                         // #14b8a6, #f59e0b, #ef4444
map.merge($priority-colors, ('critical': #7f1d1d))   // a NEW map with 4 entries
map.remove($priority-colors, 'low')                  // a NEW map without 'low'
map.deep-merge($a, $b)                               // merges nested maps too
```

Two important properties:

1. **Maps are immutable.** `map.merge` returns a *new* map; the original is unchanged. To "update" a variable you reassign: `$m: map.merge($m, (…));`. (You'll meet exactly the same idea in JavaScript/Redux in S04 and S15: *create new values instead of modifying old ones*.)
2. **Missing keys return `null`**, and a declaration with a `null` value is **omitted** from the output. So `color: map.get($m, 'typo');` silently produces nothing. That's why TaskFlow's lookup helpers use `map.has-key` + `@error`.

> ⚠️ The old global function `map-get()` still works but is **deprecated** (Sass warns: *"Global built-in functions are deprecated… Use map.get instead."*). Use `map.get` with `@use 'sass:map';`.

## 4. Where maps shine in a design system

| Map | Used for |
|---|---|
| `$breakpoints` | `respond-to()` (03.02) |
| `$status-colors`, `$priority-colors` | Generating badge/card variants with loops (03.07) |
| `$themes: ('light': (…), 'dark': (…))` | Emitting CSS custom properties per theme (03.12–03.13) |
| `$z-layers: ('dropdown': 100, 'modal': 1000, 'toast': 1100)` | A `z()` function so nobody writes `z-index: 99999` |

Single source of truth + loops = add a new status in **one place**, and every class that depends on it is generated.

---

## 6. Summary

- Maps = key → value data; nested maps model structured tokens.
- `sass:map`: `get` (with nested keys), `has-key`, `keys`, `values`, `merge`, `remove`, `deep-merge`.
- Maps are **immutable**; missing keys return **`null`**, which silently drops the declaration. Guard with `has-key` + `@error`.
- Use maps for anything you'll loop over or look up by name.

## 7. Check yourself

1. What does `map.get($status-colors, 'done', 'bg')` return?
2. `$m: ('a': 1); $n: map.merge($m, ('b': 2));`. What's in `$m` afterwards?
3. What CSS does `.x { color: map.get($priority-colors, 'urgent'); }` produce?

<details>
<summary>Answers</summary>

1. `#dcfce7`
2. Still only `('a': 1)`. Maps are immutable; `$n` is a new map `('a': 1, 'b': 2)`.
3. **Nothing** for that declaration (the value is `null`, so Sass omits it). An empty rule is dropped entirely, which is a silent failure worth guarding against.

</details>
