# Lecture 04.08 · Functions as Values: Arrow Functions, Closures, Higher-Order Functions, Currying

> **Section:** S04 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~35 minutes
> This lecture is the foundation for React hooks (S08), Redux middleware (S16) and thunks (S18).

---

## 1. Functions are values

In JavaScript a function is an object like any other. You can store it in a variable, put it in an array, pass it as an argument, and return it from another function.

```js
const isDone = (task) => task.status === 'DONE';   // stored in a variable
tasks.filter(isDone);                              // passed as an argument
const handlers = { onToggle: toggleTask };         // stored in an object
```

## 2. Arrow functions vs `function`

```js
function add(a, b) { return a + b; }
const add2 = (a, b) => a + b;              // implicit return
const square = (x) => x * x;
const makeTask = (title) => ({ title });   // object literal: parentheses!
const log = () => { console.log('hi'); };  // block body: explicit return needed if any
```

Differences that matter:
- Arrow functions **don't have their own `this`** (they use the surrounding one). See 04.10.
- They can't be used with `new`, and have no `arguments` object (use rest `...args`).
- `function` declarations are **hoisted** (callable before their line); `const f = () => …` isn't.

In React/Redux code you'll mostly see arrow functions and `function` components; either style is fine.

## 3. Closures

> **A closure is a function together with the variables it captured from the scope where it was created. Those variables stay alive as long as the function does.**

```js
function makeCounter() {
  let count = 0;                 // local to this call of makeCounter
  return () => {
    count += 1;                  // the inner function "closes over" count
    return count;
  };
}

const next = makeCounter();
next(); // 1
next(); // 2
const other = makeCounter();
other(); // 1: a separate call, a separate `count`
```

What's happening internally: each call to `makeCounter` creates a new **scope** (an environment record holding `count`). The returned arrow function keeps a reference to that scope. Normally the scope would be garbage-collected when `makeCounter` returns, but because the function still references it, it survives.

### Why closures matter in this course

| Where | What's being closed over |
|---|---|
| React event handlers | The props/state of **the render that created them** (S07–S08) |
| React hooks & **stale closures** | An effect or callback captured an *old* state value (S08 debug lecture) |
| Redux middleware `store => next => action` | `store` and `next` captured by the inner functions (S16) |
| Redux thunks | `dispatch`/`getState` given to the function you return (S18) |
| Memoization | The cache captured by the memoised function (S21) |
| Axios interceptors | Config captured when the instance was created (S13) |

### Stale closure preview

```js
function makeGreeter(name) {
  return () => `Hello ${name}`;
}
let user = 'An';
const greet = makeGreeter(user);
user = 'Binh';
greet();   // 'Hello An': captured the VALUE passed at creation time
```

In React, every render creates new handler functions capturing **that render's** state. If you keep an old function around (in an effect, a timer, a subscription), it sees old state. You'll debug exactly this in S08.

## 4. Higher-order functions (HOFs)

A **higher-order function** takes a function as an argument and/or returns a function.

```js
// takes a function
tasks.map(fn); tasks.filter(fn);

// returns a function
const byStatus = (status) => (task) => task.status === status;
tasks.filter(byStatus('DONE'));
tasks.filter(byStatus('TODO'));
```

`byStatus` is a **function factory**. It captures `status` in a closure and returns a predicate. You'll write selector factories exactly like this (S21).

### Wrapping behaviour: the decorator pattern

```js
function withLogging(fn) {
  return (...args) => {
    console.log('calling', fn.name, args);
    const result = fn(...args);
    console.log('result', result);
    return result;
  };
}

const loggedToggle = withLogging(toggleTask);
```

`withLogging` adds behaviour **around** a function without changing it. Keep this shape in mind: **Redux middleware wraps `dispatch` the same way** (S16), and **Servlet filters wrap request handling the same way** (S40). It's one of the most reused ideas in the course.

## 5. Currying

**Currying** turns a function of several arguments into a chain of functions of one argument each:

```js
const add = (a, b) => a + b;
const curriedAdd = (a) => (b) => a + b;

curriedAdd(2)(3);          // 5
const add10 = curriedAdd(10);
add10(5);                  // 15: `a` is remembered via closure
```

Why would anyone do this? Because it lets you supply arguments **at different times**. Each level can be called by a different piece of code.

### The one you'll meet in S16: Redux middleware

```js
const logger = (store) => (next) => (action) => {
  console.log('dispatching', action);
  const result = next(action);
  console.log('next state', store.getState());
  return result;
};
```

Read it as three moments in time:
1. When the store is created: `logger(store)` is called once, capturing `store`.
2. When middleware is chained: `(next) => …` is called once, capturing the next function in the chain.
3. On every dispatch: `(action) => …` runs, with `store` and `next` available via closures.

Right now this may look cryptic. By S16, after you've written it yourself, it'll feel natural. The important point today: **there's nothing magic in it, only closures and currying.**

## 6. Callbacks and pure vs impure functions

A **callback** is a function passed to be called later (`onClick`, `then`, `setTimeout`). Passing callbacks is how components communicate upward in React (`<TaskCard onToggle={handleToggle} />`).

Be deliberate about purity:
- Functions passed to `map`/`filter`/`reduce`/selectors/reducers → **pure**.
- Event handlers, effects, thunks, middleware → **allowed side effects** (that's their job).

## 7. Summary

- Functions are values: store, pass, return them.
- Arrow functions: concise, no own `this`; object literals need `=> ({ … })`.
- **Closures** keep captured variables alive; they power hooks, middleware, thunks and memoization, and cause stale-state bugs.
- **Higher-order functions** take/return functions (factories, decorators). Middleware and filters are decorators.
- **Currying** splits arguments across calls made at different times: `store => next => action`.

<details>
<summary>Answers</summary>

1. `[0, 10, 20]`. Each iteration's `let i` is a separate binding captured by its closure. (With `var i` it would be `[30, 30, 30]`.)
