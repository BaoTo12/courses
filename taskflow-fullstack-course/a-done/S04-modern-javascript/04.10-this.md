# Lecture 04.10 · `this`: the One Lecture You Need

> **Section:** S04 · **Type:** 📖 Theory · **Track:** ＋ Extended · **Time:** ~15 minutes

---

## 1. Why this lecture is short

Modern React (function components + hooks) and Redux (plain functions) almost never use `this`. But you'll read older class components, library code and Java-influenced JS, and `this` bugs are confusing when you meet them. One rule covers 95% of cases.

## 2. The rule

> **For a normal `function`, `this` is decided by *how the function is called*, not where it's defined.**
> **For an arrow function, `this` is whatever `this` was *where the arrow was created*.**

```js
const board = {
  name: 'Sprint 12',
  normal() { return this.name; },
  arrow: () => this?.name,
};

board.normal();            // 'Sprint 12': called as board.normal(), so this = board
const f = board.normal;
f();                       // ❌ TypeError: Cannot read properties of undefined (reading 'name')
                           //    called bare → in strict mode (all ES modules) this = undefined
board.arrow();             // undefined: the arrow uses the module's this, which is undefined in ESM
```

(In old non-module "sloppy" scripts, a bare call sets `this` to the global `window` instead, so `f()` would silently read `window.name`. That's even more confusing, and one reason strict mode exists.)

## 3. The classic bug: losing `this` in callbacks

```js
class Timer {
  seconds = 0;
  start() {
    setInterval(function () {
      this.seconds++;          // ❌ `this` is not the Timer (the callback is called bare)
    }, 1000);
  }
}
```

Fixes:
```js
setInterval(() => { this.seconds++; }, 1000);           // ✅ arrow: uses start()'s this
setInterval(function () { this.seconds++; }.bind(this), 1000); // ✅ explicit bind
```

In old React class components you'd see `this.handleClick = this.handleClick.bind(this)` in constructors. That's this exact problem. Function components removed it: there's no `this`, only closures (04.08).

## 4. The four call styles (for reference)

| Call | `this` |
|---|---|
| `obj.method()` | `obj` |
| `fn()` | `undefined` in strict mode / modules (the global object in sloppy scripts) |
| `fn.call(x)`, `fn.apply(x)`, `fn.bind(x)()` | `x` |
| `new Fn()` | The new object |
| Arrow function | Inherited from the enclosing scope, and **can't** be changed by call/bind |

## 5. Summary

- `function`: `this` = how it's called. Arrow: `this` = where it's created.
- Passing `obj.method` as a callback loses `this`; use arrows or `bind`.
- Function components and hooks make `this` mostly irrelevant; closures replace it.
