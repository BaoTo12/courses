# Lecture 04.14 · 🎯 Your Turn: `updateTaskField` and `groupByStatus`

## 1. The task

Make the two failing test groups from 04.06 pass by adding these exports to `playground/js/task-utils.js`.

### `updateTaskField(tasks, id, field, value)`

Returns a **new array** where the task with `id` has `field` set to `value`.

```js
updateTaskField(tasks, 1, 'title', 'Write Q3 report');
updateTaskField(tasks, 2, 'priority', 'HIGH');
```

### `groupByStatus(tasks)`

Returns an object with **exactly** the keys `TODO`, `IN_PROGRESS`, `DONE` (in that order), each holding an array of that status's tasks, **even when a group is empty**.

```js
groupByStatus(tasks);
// { TODO: [t1, t5], IN_PROGRESS: [t2], DONE: [t3] }
groupByStatus([]);
// { TODO: [], IN_PROGRESS: [], DONE: [] }
```

## 2. Requirements

1. Both functions are **pure**: the frozen fixtures must not throw.
2. `updateTaskField`: unchanged tasks keep **the same reference** (`toBe`).
3. `groupByStatus`: no `Object.groupBy` (it omits empty groups; see 04.07). Think about why the key order matters to a UI that renders three columns.
4. `npm test` → **8 passed**.

## 3. Then use them (stretch)

In `main.js`, render the tasks as **three columns** (To do / In progress / Done) using `groupByStatus`, instead of one grid. Each column shows its count. Keep `textContent` for all user data.
