## 1. The problem left open in 05.12

`loadTasks` checked that `data.tasks` is an array, but not that each **element** is a `Task`. The narrowing chain from 05.07 works, but it's long, and we'd have to repeat it in every place data enters the app.

## 2. User-defined type guards: `value is T`

A **type guard** is a function returning `boolean` whose return type is a **type predicate**:

```ts
export function isTaskStatus(value: unknown): value is TaskStatus {
  return typeof value === 'string' && (TASK_STATUSES as readonly string[]).includes(value);
}
```

- `value is TaskStatus` tells the compiler: *"if this function returns `true`, treat `value` as a `TaskStatus` in the caller's `if` branch."*
- The **runtime check** inside must actually be correct. TypeScript trusts your predicate; a wrong guard is as dangerous as `as` (05.13).
- `(TASK_STATUSES as readonly string[])` widens the tuple so `.includes` accepts any string. `includes` on a `readonly ['TODO', …]` only accepts those literals. This is one of the few reasonable uses of `as`: widening a type we control, not asserting external data.

Usage:

```ts
const raw: unknown = new URLSearchParams(location.search).get('status');
if (isTaskStatus(raw)) {
  filterTasks(tasks, { status: raw });   // raw: TaskStatus
}
```

## 3. ✍️ `src/guards.ts`

```ts
import { PRIORITIES, TASK_STATUSES } from './domain';
import type { Priority, Task, TaskStatus } from './domain';
import type { ApiError } from './api-types';

/** Compile-time exhaustiveness helper: only callable with `never`. */
export function assertNever(value: never): never {
  throw new Error(`Unexpected value: ${JSON.stringify(value)}`);
}

export function isTaskStatus(value: unknown): value is TaskStatus {
  return typeof value === 'string' && (TASK_STATUSES as readonly string[]).includes(value);
}

export function isPriority(value: unknown): value is Priority {
  return typeof value === 'string' && (PRIORITIES as readonly string[]).includes(value);
}

const isObject = (value: unknown): value is Record<string, unknown> =>
  typeof value === 'object' && value !== null;

const isStringOrNull = (value: unknown): value is string | null =>
  value === null || typeof value === 'string';

export function isTask(value: unknown): value is Task {
  return (
    isObject(value) &&
    typeof value.id === 'number' &&
    typeof value.title === 'string' &&
    typeof value.description === 'string' &&
    isTaskStatus(value.status) &&
    isPriority(value.priority) &&
    isStringOrNull(value.dueDate) &&
    (value.categoryId === null || typeof value.categoryId === 'number') &&
    typeof value.ownerId === 'number' &&
    typeof value.createdAt === 'string' &&
    typeof value.updatedAt === 'string'
  );
}

export function isApiError(value: unknown): value is ApiError {
  return (
    isObject(value) &&
    typeof value.status === 'number' &&
    typeof value.error === 'string' &&
    typeof value.message === 'string'
  );
}

/** Assertion function: returns normally only if value is a Task; narrows the caller's variable. */
export function assertIsTask(value: unknown): asserts value is Task {
  if (!isTask(value)) {
    throw new Error('Invalid task payload');
  }
}

/** Turn anything thrown into a readable message. `catch (e)` gives `unknown` under strict. */
export function toErrorMessage(error: unknown): string {
  if (isApiError(error)) return error.message;
  if (error instanceof Error) return error.message;
  if (typeof error === 'string') return error;
  return 'Unexpected error';
}
```

Notes:
- **`isObject` returns `value is Record<string, unknown>`**, so after it you can read `value.id` etc. (each is `unknown`) and check each field. Small guards compose into bigger ones.
- **`isApiError` checks only the fields the UI needs.** A guard doesn't have to validate everything; it has to validate everything **you rely on**.
- **Assertion functions** (`asserts value is Task`) narrow by **not throwing**:

```ts
const body: unknown = await response.json();
assertIsTask(body);
body.title;   // Task from here on
```

## 4. ✍️ Upgrade `loadTasks` (`src/api.ts`)

```ts
import type { Task } from './domain';
import { isApiError, isTask } from './guards';

/**
 * Load tasks from a JSON document shaped like { "tasks": [ ... ] }.
 * The response body is untrusted: treated as `unknown` and fully validated (06.08).
 */
export async function loadTasks(url: string): Promise<Task[]> {
  const response = await fetch(url);
  const data: unknown = await response.json();

  if (!response.ok) {
    const detail = isApiError(data) ? data.message : `HTTP ${response.status}`;
    throw new Error(`Failed to load tasks: ${detail}`);
  }

  if (typeof data === 'object' && data !== null && 'tasks' in data && Array.isArray(data.tasks)) {
    const items: unknown[] = data.tasks;
    if (items.every(isTask)) {
      return items; // narrowed to Task[] by the type guard
    }
  }

  throw new Error('Invalid response: expected { tasks: Task[] }');
}
```

Key details:
- **`const items: unknown[] = data.tasks`** downgrades `any[]` (from `Array.isArray`) to `unknown[]`, so nothing slips through unchecked.
- **`items.every(isTask)`**: `Array.prototype.every` has an overload that accepts a type predicate, so `every(isTask)` returning `true` narrows `items` to `Task[]`. No cast needed.
- **Error bodies**: on non-2xx the server sends an `ApiError`; we surface its human-readable `message` ("Session expired") instead of just "HTTP 401".

(Note: `response.json()` throws if the body isn't JSON at all, e.g. an HTML error page from a proxy. S13's Axios layer handles that case too.)

## 5. Guards vs schema libraries

Hand-written guards are fine for a handful of types, and writing them teaches you what validation really involves. At scale, teams use schema libraries (**zod**, valibot, …) that define the schema **once** and derive both the runtime validator and the TypeScript type:

```ts
// zod, for comparison only (not used in TaskFlow)
const TaskSchema = z.object({ id: z.number(), title: z.string(), status: z.enum(TASK_STATUSES), … });
type Task = z.infer<typeof TaskSchema>;
const task = TaskSchema.parse(unknownData);   // throws with detailed errors, returns Task
```

> 🛡 **Client-side validation of server responses is about robustness, not security.** It makes the UI fail clearly instead of crashing. Security validation of *requests* happens on the server (S37, S46).

## 6. Summary

- `value is T` type guards package runtime checks and narrow in the caller.
- `asserts value is T` narrows by not throwing.
- Compose small guards (`isObject`, `isTaskStatus`) into entity guards (`isTask`).
- `every(isTask)` narrows arrays; downgrade `any[]` to `unknown[]` first.
- A wrong guard is a lie like `as`; keep guards simple and tested.
