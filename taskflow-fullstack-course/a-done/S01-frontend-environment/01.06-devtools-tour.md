# Lecture 01.06 · DevTools Tour: Elements, Console, Network, Application, Performance

> **Section:** S01 · **Type:** 📖 Theory (hands-on) · **Track:** ★ Core · **Time:** ~30 minutes

---

## 1. Why DevTools is the most important tool in this course

Almost every debugging lecture in this course starts in DevTools. It lets you **see** what's normally invisible: the exact HTTP messages, the cookies, the live DOM, the order things happen. Engineers who debug fast don't guess; they look.

Open DevTools with **F12** (or **Ctrl+Shift+I**). Dock it to the right or bottom (⋮ menu → Dock side).

Practice on any website while reading this lecture.

---

## 2. Elements: the live DOM

- Shows the **current** DOM, which may differ from the HTML the server sent (JavaScript can change it). Compare with **View Source** (Ctrl+U), which shows the original bytes.
- **Styles pane:** every CSS rule applied to the selected element, in specificity order, with crossed-out rules that lost. You'll use this to debug SCSS specificity (Lecture 02.13) and SCSS-vs-styled-components conflicts (10.15).
- **Computed pane:** the final value of each property and which rule produced it.
- With source maps (S02), rules link back to your `.scss` file and line.

Try: right-click any element → **Inspect**; toggle a CSS property off with its checkbox.

---

## 3. Console: messages and a JavaScript REPL

- Shows `console.log` output, errors, warnings (React warnings will appear here).
- It's also a REPL: type JavaScript and it runs **in the page**. Try `document.cookie`, `location.href`, `document.title = "hi"`.
- 🛡 Note what `document.cookie` shows: only cookies **not** marked HttpOnly. You'll rely on this fact in S24.

> ⚠️ Never paste code into the Console because a website or a stranger tells you to. It runs with full access to that page and your logged-in session. This is a real social-engineering attack ("self-XSS").

---

## 4. Network: the HTTP truth

This panel shows every HTTP request the page makes. It's the single most useful panel for this course.

Setup habits:
- ✅ **Preserve log** (keeps requests across page navigations and redirects, essential for seeing redirect chains in S31 and S37)
- ✅ **Disable cache** (while DevTools is open, so you always see real requests)

For each request, click it and look at:

| Tab | What you learn |
|---|---|
| **Headers** | Request URL, method, **status code**, request headers (incl. `Cookie`), response headers (incl. `Set-Cookie`, `Location`, `Content-Type`) |
| **Payload** | Query string parameters, form data, JSON body sent |
| **Preview / Response** | What the server returned (HTML, JSON…) |
| **Cookies** | Cookies sent and received for this request |
| **Timing** | Where time went (waiting for the server vs downloading) |

Useful tricks:
- **Filter** by type: `Doc`, `Fetch/XHR`, `JS`, `CSS`.
- Right-click a request → **Copy → Copy as cURL** to replay it in a terminal. You'll use this in attack labs to show that "the UI isn't the only way to send requests".
- **Throttling** (e.g. "Slow 4G") to see loading states in your React app.

---

## 5. Application: storage and cookies

- **Cookies:** every cookie for the site with its attributes: `HttpOnly`, `Secure`, `SameSite`, `Path`, `Expires`. You can edit or delete them here, which is exactly why cookies are **untrusted input** for the server.
- **Local Storage / Session Storage:** key-value storage readable by any JavaScript on the page.
- **Clear site data** button: a quick reset when testing login flows.

---

## 6. Sources: debugging JavaScript

- Set **breakpoints** in your TypeScript files (via source maps), step through, inspect variables.
- `debugger;` statement in code pauses execution when DevTools is open.

You'll use this in S08 (stale closures) and S13 (interceptors).

---

## 7. Performance and extensions

- **Performance** panel: records what the browser did (scripting, rendering, painting). Used lightly in S21.
- **React DevTools** adds **Components** (inspect props/state) and **Profiler** (what re-rendered and why) tabs, used heavily in S21.
- **Redux DevTools** adds a **Redux** tab with the action log, state diff and time travel (S14+).

---

## 8. 🎯 Mini exercise (10 minutes)

On any site you use that has a login (your own account, just observing):

1. In **Network**, with Preserve log on, reload the page. Find the main document request. Note its status code and `Content-Type`.
2. Find one `Set-Cookie` response header. Is the cookie `HttpOnly`? `Secure`? What `SameSite`?
3. In **Application → Cookies**, find the same cookie and compare.
4. In **Console**, run `document.cookie`. Is the HttpOnly cookie in the output?
5. Right-click any request → **Copy as cURL**. Paste it into a text editor and identify the method, URL and cookies.

Write your answers in `docs/notes/s01-devtools.md`.

---

## 9. Summary

- **Elements** = live DOM + CSS debugging; **View Source** = original server bytes.
- **Network** = the HTTP truth: status, headers, cookies, bodies, redirects. Turn on *Preserve log* and *Disable cache*.
- **Application** = cookies (with flags) and storage, all editable by the user, hence untrusted.
- **Console** runs JS in the page; `document.cookie` hides HttpOnly cookies.
- React and Redux DevTools extend it for S07+ and S14+.
