# Lecture 14.07 · Terminology: Actions, Action Creators, Reducers, Store, Dispatch, Selectors

> **Section:** S14 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~35 minutes
> 🔗 Official companion reading: Essentials Part 1 ("Redux Terminology")

---

## 1. Actions

An **action** is a plain JavaScript object that describes **something that happened**. It must have a `type` string. By convention, extra data goes in `payload`:

```js
{ type: 'tasks/taskCompleted', payload: 5 }
{ type: 'tasks/taskAdded', payload: { id: 26, title: 'Write docs', /* … */ } }
{ type: 'auth/loggedOut' }
```

- **`type` naming:** `'domain/eventName'`. The domain (the "slice" of state, S15) comes first, then the event in **past tense**. Think "what happened", not "what to do": `taskCompleted`, not `setTaskStatus`. 15.03 explains why events scale better than setters.
- **Plain objects only.** Verified with the development build: `store.dispatch('counter/incremented')` throws *"Actions must be plain objects. Instead, the actual type was: 'string'…"*, and the message suggests middleware such as redux-thunk for other values (S18).
- **`type` is required.** `store.dispatch({})` throws *"Actions may not have an undefined "type" property. You may have misspelled an action type string constant."*
- **Serialisable:** strings, numbers, booleans, `null`, arrays and plain objects. No functions, class instances or `Date` objects: the DevTools must be able to record and replay them.

The shape `{ type, payload, error?, meta? }` is called a **Flux Standard Action** (FSA). Redux Toolkit generates FSAs.

## 2. Action creators

A function that **creates** (returns) an action object, so you don't write the object by hand every time:

```js
const taskCompleted = (id) => ({ type: 'tasks/taskCompleted', payload: id });

store.dispatch(taskCompleted(5));
```

It prevents typos in `type` strings, keeps the payload shape in one place, and later (RTK) is generated for you. An action creator doesn't dispatch anything by itself; it just builds the object.

## 3. Reducers

A **reducer** is a function `(state, action) => newState`. It decides how the state changes in response to an action. The name comes from `Array.prototype.reduce` (04.07): a reducer "reduces" a sequence of actions into one state, exactly like `[a1, a2, a3].reduce(reducer, initialState)`.

Rules (15.04 goes deeper):
- Compute the new state **only** from `state` and `action`.
- **Never mutate** `state`: copy, then change the copy (14.06).
- **No side effects**: no API calls, no timers, no `Math.random()`, no `Date.now()`, no logging you rely on.
- If the reducer doesn't care about the action, **return the existing state unchanged**.

```js
function counterReducer(state = { value: 0 }, action) {
  switch (action.type) {
    case 'counter/incremented':
      return { ...state, value: state.value + 1 };
    default:
      return state;
  }
}
```

The `state = { value: 0 }` default parameter is the **initial state**: the store calls the reducer once at startup with `state === undefined` (verified in 14.10: the reducer's first action has a type like `@@redux/INITp.y.f.h.p.m`, a random internal type no reducer handles).

## 4. Store

The **store** holds the current state. It's created from a reducer:

```js
const store = createStore(counterReducer);
store.getState(); // { value: 0 }
```

It has three core methods:
- `getState()` returns the current state;
- `dispatch(action)` runs the reducer with the current state and the action, saves the result, and notifies subscribers;
- `subscribe(listener)` registers a function called after every dispatch, and returns an **unsubscribe** function.

There's normally **one store** per app (14.08).

## 5. Dispatch

"Dispatching an action" = calling `store.dispatch(action)`. It's **the only way** to update the state. Think of it as "triggering an event": something happened, and we want the store to know.

`dispatch` is **synchronous** for plain actions: when it returns, the new state is already in place (16.04). It returns the action you passed (verified: `store.dispatch({ type: 'x/unknown' })` returned `{ type: 'x/unknown' }`), which middleware can change (S16).

## 6. Selectors

A **selector** is a function that extracts a specific piece of information from the state:

```js
const selectCounterValue = (state) => state.value;
const selectOpenTasks = (state) => state.tasks.items.filter((t) => t.status !== 'DONE');
```

Selectors avoid repeating state-shape knowledge all over the UI: if the shape changes, you change the selector, not fifty components. They're also where **derived data** is computed (14.03 §4), and in S21 you'll **memoise** expensive ones with `createSelector`.

## 7. Summary table

| Term | Is a… | Example |
|---|---|---|
| Action | plain object with `type` | `{ type: 'tasks/taskCompleted', payload: 5 }` |
| Action creator | function returning an action | `taskCompleted(5)` |
| Reducer | pure function `(state, action) → state` | `tasksReducer` |
| Store | object holding state | `createStore(rootReducer)` |
| Dispatch | the store method that sends an action | `store.dispatch(taskCompleted(5))` |
| Selector | function `(state) → value` | `selectOpenTasks(state)` |
