# Lecture 07.09 · Events: Handlers, Synthetic Events and Typing Them

> **Section:** S07 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~20 minutes

---

## 1. Attaching handlers

```tsx
<button onClick={handleClick}>Save</button>            // pass the function
<button onClick={() => onToggle(task.id)}>Done</button> // wrap to pass arguments
<button onClick={handleClick()}>Save</button>          // ❌ CALLS it during render; passes its return value
```

The third line is a classic bug. `handleClick()` runs **while rendering** (a side effect in render, 07.04), and `onClick` receives `undefined`.

Compare with 04.13: no `addEventListener`, no event delegation, no `dataset`/`Number()` conversions. The handler closes over `task.id` (04.08), already a `number`.

## 2. Synthetic events

React passes a **SyntheticEvent**, a cross-browser wrapper with the same interface as native events (`target`, `currentTarget`, `preventDefault()`, `stopPropagation()`). Internally, React attaches listeners at the **root** container and dispatches to your handlers, which is event delegation done for you.

## 3. Typing handlers

When the handler is inline, the event type is **inferred** (contextual typing, 05.04):

```tsx
<input onChange={(e) => setTitle(e.target.value)} />   // e: React.ChangeEvent<HTMLInputElement>
```

When you extract it, annotate the event:

```tsx
import type { ChangeEvent, FormEvent, MouseEvent } from 'react';

function handleTitleChange(e: ChangeEvent<HTMLInputElement>) {
  setTitle(e.target.value);
}

function handleSubmit(e: FormEvent<HTMLFormElement>) {
  e.preventDefault();       // stop the browser's full-page form submission
  save();
}

function handleClick(e: MouseEvent<HTMLButtonElement>) {
  e.stopPropagation();      // don't also trigger the parent card's onClick
}
```

Tip: hover the prop (`onChange`) in VS Code to see the exact event type it expects.

## 4. Naming conventions

- **Props** that accept handlers: `onSomething` (`onToggle`, `onChange`, `onDelete`).
- **Functions** that handle them: `handleSomething` (`handleToggle`).
- Callback props describe **what happened** (`onToggle(id)`), not what the parent should do (`setTasks`). This keeps children reusable and ignorant of the parent's state shape. It's the same "events, not setters" idea you'll meet with Redux actions (S15).

## 5. Summary

- Pass functions (`onClick={fn}`), don't call them; wrap to pass arguments.
- React's synthetic events wrap native ones and are delegated at the root.
- Inline handlers infer event types; extracted ones use `ChangeEvent<…>`, `FormEvent<…>`, `MouseEvent<…>`.
- `onX` props, `handleX` functions; callbacks describe events.
