# Lecture 07.05 · Props: Typing with TypeScript, `children`, Defaults, and Why Props Are Read-Only

> **Section:** S07 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~25 minutes

---

## 1. Props are function arguments

A component receives **one argument**: the props object built from the JSX attributes.

```tsx
<TaskCard task={task} onToggle={handleToggle} />
// React calls: TaskCard({ task: task, onToggle: handleToggle })
```

Destructure it in the parameter list (04.04) and type it with an interface:

```tsx
interface TaskCardProps {
  task: Task;
  onToggle: (id: number) => void;
}

export function TaskCard({ task, onToggle }: TaskCardProps) {
  // …
}
```

Now `<TaskCard task={task} />` without `onToggle` is a compile error, and so is `task={42}`.

## 2. Optional props and defaults

```tsx
interface ButtonProps {
  variant?: 'primary' | 'secondary' | 'danger';
  size?: 'md' | 'sm';
}

function Button({ variant = 'secondary', size = 'md' }: ButtonProps) { … }
```

Default values in destructuring (04.04) are the standard way to give props defaults. (The old `Component.defaultProps` is legacy.)

## 3. `children`

Content between the tags arrives as the `children` prop:

```tsx
interface PageLayoutProps {
  title: string;
  children: ReactNode;          // anything renderable: elements, strings, numbers, arrays, null
}

function PageLayout({ title, children }: PageLayoutProps) {
  return (
    <main>
      <h1>{title}</h1>
      {children}
    </main>
  );
}

<PageLayout title="Tasks">
  <FilterBar … />
  <TaskList … />
</PageLayout>
```

`ReactNode` (imported as a type from `'react'`) is the type for "anything React can render". This is **composition**: `PageLayout` doesn't need to know what goes inside it (07.13).

## 4. Extending native element props

A `Button` should accept everything a real `<button>` accepts (`disabled`, `onClick`, `aria-*`, `type`…) without listing each one:

```tsx
import type { ButtonHTMLAttributes } from 'react';

interface ButtonProps extends ButtonHTMLAttributes<HTMLButtonElement> {
  variant?: 'primary' | 'secondary' | 'danger';
  size?: 'md' | 'sm';
}

function Button({ variant = 'secondary', size = 'md', type = 'button', className, ...rest }: ButtonProps) {
  // …
  return <button type={type} className={…} {...rest} />;
}
```

- `ButtonHTMLAttributes<HTMLButtonElement>` is React's type for all `<button>` attributes and event handlers.
- `...rest` collects everything else (04.04) and `{...rest}` spreads it onto the DOM element. `onClick`, `disabled`, `aria-pressed` all pass through.
- `type = 'button'` default: a `<button>` inside a `<form>` defaults to `type="submit"` in HTML, which causes surprise form submissions. A safe default avoids that.

## 5. Props are read-only

```tsx
function TaskCard({ task }: TaskCardProps) {
  task.title = task.title.trim();   // ❌ never mutate props
}
```

Props belong to the **parent**. Mutating them breaks React's model: the parent's state is silently changed, reference equality (04.03) breaks, and renders become unpredictable. To "change" something, the child calls a **callback** prop (`onToggle(id)`) and the parent updates **its** state (07.13).

## 6. Summary

- Props = the component's single argument; type them with an interface and destructure.
- Optional props + destructuring defaults.
- `children: ReactNode` enables composition.
- Extend native attribute types (`ButtonHTMLAttributes`) and spread `...rest`.
- Props are read-only; children request changes via callbacks.
