# Lecture 07.03 · JSX Is Not HTML: It Compiles to Function Calls

> **Section:** S07 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~25 minutes

---

## 1. What JSX really is

JSX looks like HTML inside JavaScript, but the browser has never heard of it. It's **syntax that a compiler turns into function calls** (Vite's React plugin, esbuild/oxc, or TypeScript with `"jsx": "react-jsx"`).

This component:

```tsx
export function Greeting({ name, count }: { name: string; count: number }) {
  return (
    <section className="greeting">
      <h2>Hello {name}</h2>
      {count > 0 && <Badge tone="info">{count} open</Badge>}
    </section>
  );
}
```

compiles to this (actual TypeScript compiler output):

```js
import { jsxs as _jsxs } from "react/jsx-runtime";
export function Greeting({ name, count }) {
    return (_jsxs("section", { className: "greeting", children: [_jsxs("h2", { children: ["Hello ", name] }), count > 0 && _jsxs(Badge, { tone: "info", children: [count, " open"] })] }));
}
```

Read it slowly:
- `<section className="greeting">` → `_jsxs("section", { className: "greeting", children: [...] })`
- A **lowercase** tag (`"section"`, `"h2"`) is passed as a **string**: a DOM element.
- A **capitalised** tag (`Badge`) is passed as a **variable**: your component function. That's why components **must** start with a capital letter. `<badge>` would become the string `"badge"`, an unknown HTML tag.
- Attributes become a **props object**; nested content becomes `children`.
- `{name}` is just the variable; `{count > 0 && …}` is just the expression.
- Types are gone (type erasure, 05.01).

(`jsxs` is used when there are several static children, `jsx` for one. The older transform used `React.createElement(type, props, ...children)`; the idea is identical.)

## 2. What the call returns: a React element (a plain object)

`_jsxs("h2", …)` doesn't create DOM. It returns a small **description object**:

```js
{ type: 'h2', props: { children: ['Hello ', 'An'] }, key: null, … }
```

A tree of these objects describes the UI. React later turns the description into real DOM (07.04). So a component is "a function that returns a description of UI".

## 3. JSX rules that follow from "it's JavaScript"

| Rule | Why |
|---|---|
| `className`, not `class`; `htmlFor`, not `for` | Props map to DOM **properties** (`element.className`), and `class`/`for` are JS reserved words |
| camelCase events and attributes: `onClick`, `tabIndex`, `aria-*` stays kebab | DOM property naming; `aria-*`/`data-*` are exceptions |
| `style={{ marginTop: 8 }}`: an **object**, not a string | Maps to `element.style` properties |
| One root element per return (or a Fragment `<>…</>`) | A function returns **one** value |
| All tags must close: `<img />`, `<input />` | It's XML-like syntax, not forgiving HTML |
| `{}` holds **expressions**, not statements | You can't put `if`/`for` inside `{}`; use `? :`, `&&`, `.map()` |
| Comments: `{/* like this */}` | Inside JSX you're writing function arguments |

### Fragments

```tsx
return (
  <>
    <h1>Tasks</h1>
    <TaskList … />
  </>
);
```

`<>…</>` groups siblings without adding a DOM wrapper.

## 4. 🛡 `{}` escapes text: why React is XSS-safe by default

When you render `{task.title}`, React inserts it as a **text node** (the equivalent of `textContent`, 04.13), never as HTML. The malicious sample title `Review <img src=x onerror="alert(1)"> onboarding doc` appears literally on screen and nothing runs. Verified in this course's reference app: the title's `<h3>` has **zero child elements**, only text.

React escapes because JSX children are **values**, not markup strings. The only ways to inject raw HTML are deliberately named: `dangerouslySetInnerHTML`, plus a few attribute-level cases like `href={userUrl}` with a `javascript:` URL. Both are covered in S26.

## 5. Summary

- JSX compiles to `jsx(type, props)` calls that return plain **element objects** (descriptions).
- Lowercase tag → DOM element string; Capitalised tag → your component function.
- JSX follows JS rules: `className`, style objects, one root, expressions in `{}`.
- `{value}` renders text safely (escaped). Raw HTML requires `dangerouslySetInnerHTML`.
