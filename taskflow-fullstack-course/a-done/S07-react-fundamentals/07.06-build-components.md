# Lecture 07.06 · 🛠 Build: `Button`, `StatusBadge`, `PriorityBadge`, `TaskCard`

> **Section:** S07 · **Type:** 🛠 Build · **Track:** ★ Core · **Time:** ~40 minutes
> **Project feature:** `src/components/` wrapping the design system; a `TaskCard` with a CSS Module for React-only styles

---

## 1. Architecture decision: wrap the design system, don't duplicate it

The design system (`styles/`) already defines `.btn`, `.badge`, `.card`… as **global BEM classes**, and the JSP portal will use those same classes in Part 2. If React components re-implemented those styles in CSS Modules, TaskFlow would have **two copies** of every component style, and they'd drift apart.

So TaskFlow's rule:

| Style | Where it lives | Used by |
|---|---|---|
| Shared visual components (button, badge, card, form, layout) | Global BEM in `styles/` | React **and** JSP |
| React-only structure (a toolbar row, the board's columns, small layout glue) | `*.module.scss` next to the component, using `@use '@styles/abstracts' as *;` | React only |
| Dynamic, prop-driven styles (priority bar width, avatar size) | styled-components (S09) | React only |

React components become **thin, typed wrappers** that choose the right classes.

## 2. ✍️ `src/components/Button.tsx`

```tsx
import type { ButtonHTMLAttributes } from 'react';

type ButtonVariant = 'primary' | 'secondary' | 'danger';
type ButtonSize = 'md' | 'sm';

interface ButtonProps extends ButtonHTMLAttributes<HTMLButtonElement> {
  variant?: ButtonVariant;
  size?: ButtonSize;
}

/** Wraps the design system's .btn classes (styles/components/_button.scss). */
export function Button({
  variant = 'secondary',
  size = 'md',
  type = 'button',
  className,
  ...rest
}: ButtonProps) {
  const classes = ['btn', `btn--${variant}`, size === 'sm' && 'btn--sm', className]
    .filter(Boolean)
    .join(' ');

  return <button type={type} className={classes} {...rest} />;
}
```

- **Typed variants** (`'primary' | 'secondary' | 'danger'`) mean `<Button variant="primay">` is a compile error. The BEM modifiers became a type-checked API.
- **`[…].filter(Boolean).join(' ')`** builds the class string and drops `false`/`undefined`. (Libraries like `clsx` do the same; this one-liner is enough.)
- **`className` is merged**, not replaced, so callers can add extra classes.
- **`{...rest}`** forwards `onClick`, `disabled`, `aria-*` and everything else. `children` is also inside `rest`, so the label renders.

## 3. ✍️ `src/components/Badge.tsx`

```tsx
import type { Priority, TaskStatus } from '../domain/types';
import { toKebab } from '../domain/format';
import { statusLabel } from '../domain/labels';

export function StatusBadge({ status }: { status: TaskStatus }) {
  return <span className={`badge badge--${toKebab(status)}`}>{statusLabel(status)}</span>;
}

const PRIORITY_TEXT: Record<Priority, string> = { LOW: 'Low', MEDIUM: 'Medium', HIGH: 'High' };

export function PriorityBadge({ priority }: { priority: Priority }) {
  return (
    <span className={`badge badge--priority-${toKebab(priority)}`}>{PRIORITY_TEXT[priority]}</span>
  );
}
```

`toKebab('IN_PROGRESS')` → `'in-progress'` → `badge--in-progress`, the class generated from the SCSS map in 03.07. The enum-to-class convention now connects TypeScript and SCSS.

### ⚠️ Why `toKebab` lives in `domain/format.ts`, not here

The linter (oxlint, rule `react/only-export-components`) warns if a component file also exports non-components:

```text
warning react(only-export-components): Fast refresh only works when a file only exports components.
```

**Fast Refresh** swaps changed components in place while keeping their state. It can do that safely only when a module exports **just components**. Exporting a helper forces a full reload of that module's importers. The fix is structural: helpers go in their own module (`domain/format.ts`). This matters day-to-day, since losing state on every save slows you down.

## 4. ✍️ `src/components/TaskCard.tsx`

```tsx
import type { Task } from '../domain/types';
import { Button } from './Button';
import { PriorityBadge, StatusBadge } from './Badge';
import { toKebab } from '../domain/format';
import styles from './TaskCard.module.scss';

interface TaskCardProps {
  task: Task;
  onToggle: (id: number) => void;
}

export function TaskCard({ task, onToggle }: TaskCardProps) {
  const isDone = task.status === 'DONE';

  return (
    <article className={`card card--priority-${toKebab(task.priority)}`}>
      <h3 className="card__title">{task.title}</h3>
      <p className="card__body">{task.description}</p>
      <footer className="card__meta">
        <div className={styles.badges}>
          <StatusBadge status={task.status} />
          <PriorityBadge priority={task.priority} />
        </div>
        <Button size="sm" onClick={() => onToggle(task.id)}>
          {isDone ? 'Reopen' : 'Mark done'}
        </Button>
      </footer>
      {task.dueDate && <p className={styles.due}>Due {task.dueDate}</p>}
    </article>
  );
}
```

And its CSS Module, `src/components/TaskCard.module.scss`:

```scss
// React-only styles for TaskCard. Tools (tokens, functions, mixins) come from the shared abstracts;
// abstracts emit no CSS, so nothing is duplicated (03.10).
@use '@styles/abstracts' as *;

.badges {
  display: flex;
  gap: space(1);
}

.due {
  font-size: to-rem(12px);
  color: theme('text-muted');
}
```

Notes:
- **`{task.title}`** is escaped text (07.03). The sample task with `<img onerror>` in its title renders harmlessly.
- **`onClick={() => onToggle(task.id)}`**: the card doesn't change data. It **reports** the user's intent to its parent through a callback prop (07.13).
- **`{task.dueDate && <p>…</p>}`** is conditional rendering (07.10). `dueDate` is `string | null`, and an empty string or `null` renders nothing.
- **Why abstracts don't duplicate CSS here:** each `.module.scss` is compiled **separately**. If `abstracts` emitted CSS (like `:root { … }`), it would be repeated in every module's output. That's exactly the rule from 03.10, now paying off.

## 7. Summary

- React components wrap the shared BEM classes; CSS Modules hold React-only styles; styled-components (S09) will handle dynamic styles.
- Typed props turn BEM modifiers into a checked API.
- Component files export only components (Fast Refresh); helpers go in their own modules.
- Children report intent via callback props; they don't change data.
