<details>
<summary><b>Answers</b></summary>

1. Children **re-render** by default (their functions run again); the **DOM changes only where the output differs**.

2. Component = the function; element = the plain object it returns describing UI; instance = React's record of a component at a position in the tree, holding its state.

3. Both calls read the same render's snapshot value of `count`; each schedules "set to count + 1". Use `setCount(c => c + 1)` to chain from the pending value.

4. `key` gives list items stable identity across renders so React keeps, moves, creates or destroys the right instances. Index keys identify positions, so after inserting, deleting or reordering, state and DOM (inputs, focus) attach to the wrong item.

5. The text **`0`**.

6. `jsx(Button, { variant: "primary", onClick: save, children: "Save" })` (from `react/jsx-runtime`), which returns an element object `{ type: Button, props: {…} }`.

7. `handleDelete(task.id)` is **called during render**, and its return value (probably `undefined`) becomes the handler. It must be `onClick={() => handleDelete(task.id)}`.

8. (a) `push` **mutates** the existing state array; (b) `push` returns the **new length** (a number), so state becomes a number; (c) even if it returned the array, it's the **same reference**, so React would bail out. Fix: `setTasks((c) => [...c, newTask])`.

9. The code mutated state objects and called `setTasks` with the **same reference**, so React bailed out. The next unrelated render displayed the mutated data. Create new arrays/objects instead.

10. In the **closest common parent** (e.g. `App`), passed down as props, with an `onChange` callback to the filter bar ("lifting state up").

11. (a) The **JSP portal** uses the same classes, so one source of truth, no drift. (b) No duplicated CSS; CSS Modules are reserved for React-only structure. (Also: typed props turn BEM modifiers into a checked API.)

12. **Derived**: `const openCount = tasks.filter((t) => t.status !== 'DONE').length;` in `App`, passed to `PageLayout` (e.g. as `subtitle` or a new prop). Storing it in state would create a second source of truth that can go stale.

</details>
