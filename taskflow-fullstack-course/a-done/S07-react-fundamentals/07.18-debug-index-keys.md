# Lecture 07.18 · 🐞 Debug: Input Text Jumps Between Rows After Deleting a Task (Index Keys)

> **Section:** S07 · **Type:** 🐞 Debug · **Track:** ★ Core · **Time:** ~20 minutes

---

## Symptom

A "quick notes" feature: each task row has an input for a private note (uncontrolled, local to the row) and a delete button.

```tsx
function NoteRow({ task, onDelete }: { task: Task; onDelete: (id: number) => void }) {
  return (
    <li>
      <strong>{task.title}</strong>
      <input placeholder="Note…" />
      <button onClick={() => onDelete(task.id)}>Delete</button>
    </li>
  );
}

function NotesList({ tasks, onDelete }: { tasks: readonly Task[]; onDelete: (id: number) => void }) {
  return (
    <ul>
      {tasks.map((task, index) => (
        <NoteRow key={index} task={task} onDelete={onDelete} />
      ))}
    </ul>
  );
}
```

Steps: type "call Minh" in the **first** row's note, then delete the **first** task. The first row now shows the **second** task's title… with "call Minh" in its note field. The note "moved" to the wrong task.

## Reproduce it

Add these components temporarily to your app, with a `handleDelete` in `App` (`setTasks((c) => c.filter((t) => t.id !== id))`), and try it.

Result observed in the course's reference app (first three sample tasks; note typed in row 1; row 1 deleted):

```text
index keys: "Fix login redirect bug [note="call Minh"]", "Plan team offsite [note=""]"   ← note moved to the wrong task
id keys:    "Fix login redirect bug [note=""]",          "Plan team offsite [note=""]"   ← correct
```

## Investigation checklist

1. What identifies each row between renders? (07.11)
2. After deleting item 0, which **instance** does React reuse for "key 0"?
3. Where does the typed note text live: in React state, or in the DOM input?
4. What should the key be?

## Explanation

- `key={index}` identifies rows by **position**. After deleting the first task, the second task is now at index 0, so React sees "key 0 still exists; its `task` prop changed".
- React **keeps** the existing instance and DOM for key 0 and just updates the title text. The `<input>` DOM element, with the text typed into it, is **reused**.
- The last row (key 2, previously the third task) disappears, even though the *first* task was deleted.

```text
before:  key0 → A [input: "call Minh"]   key1 → B [input: ""]   key2 → C
delete A
after:   key0 → B [input: "call Minh"] ← reused DOM!   key1 → C   (key2 removed)
```

**Fix:** use a stable identity from the data:

```tsx
{tasks.map((task) => (
  <NoteRow key={task.id} task={task} onDelete={onDelete} />
))}
```

Now React removes exactly the instance with `key={A.id}`, and B's row keeps B's DOM.

## Why index keys "worked" until now

In 07.12 the rows had no local state and no inputs. With index keys, React still updated text correctly; it just did more work than necessary. The bug appears only when rows have **state** (inputs, focus, animations, `useState`). That's why the rule is "IDs always", not "IDs when it breaks".
