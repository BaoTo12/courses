# Lecture 19.03 · Async Request Status: `'idle' | 'loading' | 'succeeded' | 'failed'` vs Booleans

> **Section:** S19 · **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~20 minutes
> 🔗 Official companion reading: Fundamentals Part 7 ("Async Request Status"); the Redux docs page "Reducing Boilerplate"/state machines; Style Guide: "Treat Reducers as State Machines"

---

## 1. The boolean version

```ts
interface TasksState {
  isLoading: boolean;
  hasError: boolean;
  isLoaded: boolean;
}
```

Three booleans = **8** combinations. How many are valid? `isLoading && isLoaded` (reloading?), `hasError && isLoaded` (an old list plus a failed refresh?), `isLoading && hasError`… Every component must interpret the combinations, and every reducer case must set all three consistently. One forgotten `isLoading = false` and the spinner never stops.

## 2. The status enum

```ts
export type LoadStatus = 'idle' | 'loading' | 'succeeded' | 'failed';
```

Exactly **4** states, and exactly one at a time. Each reducer case sets **one** field:

| Event | `status` becomes |
|---|---|
| (initial) | `'idle'`: nothing requested yet |
| `fetchStarted` | `'loading'` |
| `fetchSucceeded` | `'succeeded'` |
| `fetchFailed` | `'failed'` (with `error`) |

It's a small **state machine**, and it's the same idea as S06's `RequestState<T>` union. TaskFlow's slices keep the **data** (`ids`/`entities`) separate from the status, because the data should stay visible during a reload (15.06).

`'idle'` vs `'loading'` matters: "idle" means "nobody asked yet", so "fetch if needed" can decide to start (18.09); "loading" means "don't start another one".

## 3. What the enum doesn't capture

- **Stale-while-revalidate**: TaskFlow shows old data **and** `status === 'loading'`. The component combines `status` with "do we have data?" (19.04).
- **Per-item status** (saving task 5 while task 7 is being deleted): one `status` per slice isn't enough. Per-request tracking comes with RTK (`createAsyncThunk`'s request ids, S20) and RTK Query (per-endpoint, per-argument status, S22).

## 4. Summary

- One status field with four values replaces combinations of booleans.
- It makes reducers simple (one assignment per event) and components explicit (a `switch`/`if` over named states).
- Keep data separate from status, so stale data can stay visible while loading.
