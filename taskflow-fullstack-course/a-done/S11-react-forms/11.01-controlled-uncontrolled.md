# Lecture 11.01 · Controlled vs Uncontrolled Inputs: a Single Source of Truth for Form Values

> **Section:** S11 · Forms in React
> **Type:** 📖 Theory · **Track:** ★ Core · **Time:** ~20 minutes
> 🔗 Official reading: react.dev → Reference → `<input>` ("Controlling an input with a state variable")

---

## 1. Who owns the value?

An `<input>` element keeps its own value in the DOM. In React you choose who is the **source of truth**:

### Uncontrolled: the DOM owns it

```tsx
const titleRef = useRef<HTMLInputElement>(null);
<input ref={titleRef} defaultValue="Draft" />
// read it when needed:
const title = titleRef.current?.value;
```

React sets the **initial** value (`defaultValue`) and then leaves the input alone.

### Controlled: React state owns it

```tsx
const [title, setTitle] = useState('');
<input value={title} onChange={(e) => setTitle(e.target.value)} />
```

The input always displays `title`. On every keystroke, `onChange` updates state → re-render → the input shows the new state. If you **don't** update state, the input can't change: React keeps it in sync with `value`.

## 2. The loop, step by step

```text
user types "a"
  → browser fires input event → React calls onChange(e)
  → setTitle(e.target.value)         ("a")
  → re-render: <input value="a" />   (DOM already shows "a"; React confirms it)
```

## 3. Trade-offs

| | Controlled | Uncontrolled |
|---|---|---|
| Current value available during render | ✅ (validate as you type, character counters, disable submit) | ❌ (read on demand via ref or FormData) |
| Transform input (trim, uppercase, mask) | ✅ | Awkward |
| Reset / prefill programmatically | ✅ `setValues(initial)` | Via `key` or DOM manipulation |
| Re-render per keystroke | Yes (usually fine; see 11.09) | No |
| Code | More | Less |

TaskFlow's forms are **controlled**: we want live validation, counters, a dirty indicator and reset (11.10). The `SearchBox` (08.12) is controlled for the same reason.

## 4. The one rule: don't switch modes

An input is controlled if its `value` prop is **not `undefined`**. If `value` starts as `undefined` (uncontrolled) and later becomes a string (controlled), React complains, because it can't know which source of truth you meant. That's the debug lecture 11.12. Always initialise controlled values with a defined value (`''`, not `undefined`).

## 5. Summary

- Controlled: `value` + `onChange`, with state as the source of truth. Uncontrolled: `defaultValue` + ref, with the DOM as the source of truth.
- Controlled gives live validation, transforms and resets at the cost of a re-render per keystroke.
- Never let `value` go from `undefined` to defined.
