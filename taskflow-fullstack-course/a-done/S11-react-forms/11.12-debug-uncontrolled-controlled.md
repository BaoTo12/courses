# Lecture 11.12 · 🐞 Debug: "A Component Is Changing an Uncontrolled Input to Be Controlled"

> **Section:** S11 · **Type:** 🐞 Debug · **Track:** ★ Core · **Time:** ~15 minutes

---

## Symptom

A teammate builds a quick "draft" form with an optional-field state:

```tsx
interface Draft {
  title?: string;
}

function DraftForm() {
  const [draft, setDraft] = useState<Draft>({});
  return <input value={draft.title} onChange={(e) => setDraft({ title: e.target.value })} />;
}
```

It seems to work, but as soon as they type, the console shows (actual React 19 message, captured in the reference app):

```text
A component is changing an uncontrolled input to be controlled. This is likely caused by the value
changing from undefined to a defined value, which should not happen. Decide between using a
controlled or uncontrolled input element for the lifetime of the component.
```

Later, "Reset" (`setDraft({})`) doesn't clear the text in the field.

## Investigation checklist

1. What is `value` on the **first** render? (11.01 §4)
2. Is an input with `value={undefined}` controlled or uncontrolled?
3. After typing, what is `value`?
4. Why doesn't `setDraft({})` clear the field?

## Explanation

- First render: `draft.title` is `undefined` → `<input value={undefined}>` → React treats it as **uncontrolled** (no `value` prop); the DOM owns the text.
- After typing: `value="a"` → now **controlled**. React warns because a component switching owners mid-life is almost always a bug.
- Reset sets `title` back to `undefined`, making the input "uncontrolled" again, so React **stops managing** its value and the DOM keeps the old text.

**Fix:** always give controlled inputs a defined value:

```tsx
interface Draft {
  title: string;
}
const [draft, setDraft] = useState<Draft>({ title: '' });
<input value={draft.title} onChange={(e) => setDraft({ title: e.target.value })} />
```

or, if the type must stay optional: `value={draft.title ?? ''}`.

That's why `TaskFormValues` uses `''` for an empty due date (11.03) instead of `null`/`undefined`, and why the form model never has optional fields.

## Related traps

| Code | Result |
|---|---|
| `<input value={task.dueDate} />` with `dueDate: string \| null` | `null` → React warns that `value` shouldn't be null; use `?? ''` |
| `<input type="checkbox" value={done} />` | Wrong prop: use `checked` (11.03) |
| `value` without `onChange` | React warns that you provided a `value` without an `onChange`, so the field is read-only; add `onChange` or use `readOnly`/`defaultValue` |
