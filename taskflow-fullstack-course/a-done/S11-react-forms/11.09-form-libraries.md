# Lecture 11.09 · Form Libraries (React Hook Form, Formik): What They Optimise, and Why We Built by Hand First

> **Section:** S11 · **Type:** 📖 Theory · **Track:** ＋ Extended · **Time:** ~15 minutes

---

## 1. What you built by hand

Values state, a typed `setField`, touched tracking, submit-attempted tracking, derived errors, a submit lock, a dirty check, reset, and ARIA wiring. It's about 150 lines for one form. With five forms, you'd extract the logic into a custom hook… and you'd have written a small form library.

## 2. What libraries add

| Concern | By hand (S11) | Typical library |
|---|---|---|
| Re-render per keystroke | Whole form re-renders (fine for small forms) | **React Hook Form** uses uncontrolled inputs + refs, so fields re-render individually |
| Touched / dirty / submit state | Manual | Built in (`formState.touchedFields`, `isDirty`, `isSubmitting`) |
| Schema validation | Hand-written function | Resolvers for zod/yup, with the schema giving both validation and types |
| Field arrays, nested objects | Manual | Built in |
| Async validation, debounced checks | Manual | Built in |

## 3. Why learn the manual way first

- You now know **what the library is doing** (controlled vs uncontrolled, derived errors, refs as locks), so its API and its bugs make sense.
- Plenty of forms in real codebases are small and hand-written; you'll read and maintain them.
- In an interview, "how would you prevent double submission?" is answered by understanding, not by naming a library.

TaskFlow keeps the hand-written form: one form, clear code, no extra dependency. For a form-heavy product, React Hook Form + a schema library is a strong default.

## 4. Summary

- Libraries optimise re-renders and provide touched/dirty/submitting state, schemas and field arrays.
- Understanding the manual version makes libraries transparent.
