# Lecture 11.10 · 🎯 Your Turn: Edit Mode (Prefilled), a "Dirty" Indicator, and Reset

> **Section:** S11 · **Type:** 🎯 Your Turn · **Track:** ★ Core · **Time:** ~75 minutes

---

## 1. The task

Reuse `TaskForm` for **editing** an existing task:

- The card's **Edit** button opens the form **prefilled** with that task (inline title editing stays on double-click, 08.16).
- The form shows **"Unsaved changes"** when any value differs from the original.
- A **Reset** button restores the original values, and is disabled when there's nothing to reset.
- Saving calls `fakeUpdateTask` and **replaces** the task in the list (a new `taskUpdated` reducer action).
- Switching from editing task A to editing task B (or to "create") must **not** carry over A's half-typed values.

## 2. Requirements

1. `TaskForm` gets a `mode: 'create' | 'edit'` prop. It changes the submit label ("Create task" / "Save changes"), the form's `aria-label`, and whether past due dates are rejected (`validateTaskForm(…, isNew)`).
2. `isDirty` is **derived** (not state): compare every field of `values` to `initialValues`.
3. The panel state in `App` is a discriminated union: `{ mode: 'closed' } | { mode: 'create' } | { mode: 'edit'; task: Task }`.
4. The reducer handles `{ type: 'taskUpdated'; task: Task }` exhaustively.
5. Solve requirement "no carry-over" **without** an effect that copies props into state.
6. Keep the ref-based submit lock from 11.06.

## 3. Stretch goals

- After a failed submit, move focus to the first invalid field (11.07 §3).
- Warn before closing the panel with unsaved changes (`window.confirm` is acceptable here).
