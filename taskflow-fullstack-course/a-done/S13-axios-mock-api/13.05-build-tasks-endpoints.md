# Lecture 13.05 · 🛠 Build: `api/tasks.ts`, Typed Endpoint Functions

> **Section:** S13 · **Type:** 🛠 Build · **Track:** ★ Core · **Time:** ~45 minutes
> **Project feature:** `getTasks`, `getTask`, `createTask`, `updateTask`, `patchTask`, `deleteTask`, with validated responses

---

## 1. The idea: one function per endpoint

```ts
const page = await getTasks({ status: 'DONE', size: 20 });   // Page<Task>
const task = await createTask(request);                      // Task
```

Callers see **domain types** (`Task`, `Page<Task>`, `CreateTaskRequest`: the DTOs from 06.04), never URLs, HTTP methods or Axios. If the URL scheme changes, one file changes.

## 2. The trap: `api.get<Task>()` is a type assertion

Axios methods are generic: `api.get<Task>('/tasks/1')` gives `response.data` the type `Task`. That looks safe, but it's the same thing as `as Task` (06.09). **Nothing checks it at runtime.** If the server sends `{ "task": {…} }`, an HTML error page, or a field renamed in a backend refactor, TypeScript is happy and your UI crashes three components later.

TaskFlow's rule, since 06.09: **data crossing a trust boundary is `unknown` until validated.** The API is such a boundary: in Part 3 it's written by a different "team" (you, in Java), deployed separately, and it can change.

So we ask Axios for `unknown` and validate with type guards.

## 3. ✍️ A generic guard for the page envelope (`src/domain/guards.ts`)

Add, next to `isTask`:

```ts
/** Generic guard for the Page<T> envelope (13.05): checks the envelope AND every item. */
export function isPageOf<T>(value: unknown, isItem: (item: unknown) => item is T): value is Page<T> {
  return (
    isObject(value) &&
    Array.isArray(value.items) &&
    value.items.every(isItem) &&
    typeof value.page === 'number' &&
    typeof value.size === 'number' &&
    typeof value.totalItems === 'number' &&
    typeof value.totalPages === 'number'
  );
}
```

(and `import type { ApiError, Page } from './api-types';` at the top).

It's a **generic higher-order guard** (06.01, 06.08): you pass the item guard, and it returns a guard for `Page<thatItem>`. `isPageOf(data, isTask)` narrows `data` to `Page<Task>`; later, `isPageOf(data, isComment)` works for comments.

While you're here, make `isApiError` also check `fieldErrors` (used in 13.07):

```ts
const isStringRecord = (value: unknown): value is Record<string, string> =>
  isObject(value) && Object.values(value).every((v) => typeof v === 'string');

export function isApiError(value: unknown): value is ApiError {
  return (
    isObject(value) &&
    typeof value.status === 'number' &&
    typeof value.error === 'string' &&
    typeof value.message === 'string' &&
    (value.fieldErrors === undefined || isStringRecord(value.fieldErrors))
  );
}
```

## 4. ✍️ `src/api/tasks.ts`

Then the endpoints:

```ts
import { api } from './client';
import { ApiRequestError } from './api-error';
import { isPageOf, isTask } from '../domain/guards';
import type { Priority, SortDirection, SortKey, Task, TaskStatus } from '../domain/types';
import type { CreateTaskRequest, Page, UpdateTaskRequest } from '../domain/api-types';

/** Query parameters of GET /api/tasks (02-project-spec §5). */
export interface TaskQuery {
  q?: string;
  status?: TaskStatus;
  priority?: Priority;
  categoryId?: number;
  page?: number;
  size?: number;
  sort?: `${SortKey | 'id'},${SortDirection}`;
}

/** Responses are `unknown` until validated: the server is outside our type system (06.09). */
function expectTask(data: unknown): Task {
  if (!isTask(data)) throw invalidResponse();
  return data;
}

function invalidResponse(): ApiRequestError {
  return new ApiRequestError({ kind: 'unexpected', message: 'The server sent an unexpected response.' });
}

export async function getTasks(query: TaskQuery = {}, signal?: AbortSignal): Promise<Page<Task>> {
  // Axios serialises params and drops undefined values: { status: undefined } sends nothing.
  const { data } = await api.get<unknown>('/tasks', { params: query, signal });
  if (!isPageOf(data, isTask)) throw invalidResponse();
  return data;
}

export async function getTask(id: number, signal?: AbortSignal): Promise<Task> {
  const { data } = await api.get<unknown>(`/tasks/${id}`, { signal });
  return expectTask(data);
}

/** POST → 201 Created, with the new task (server-assigned id, owner, timestamps) in the body. */
export async function createTask(request: CreateTaskRequest): Promise<Task> {
  const { data } = await api.post<unknown>('/tasks', request);
  return expectTask(data);
}

/** PUT = replace all editable fields. */
export async function updateTask(id: number, request: CreateTaskRequest): Promise<Task> {
  const { data } = await api.put<unknown>(`/tasks/${id}`, request);
  return expectTask(data);
}

/** PATCH = change only the fields sent. */
export async function patchTask(id: number, changes: UpdateTaskRequest): Promise<Task> {
  const { data } = await api.patch<unknown>(`/tasks/${id}`, changes);
  return expectTask(data);
}

/** DELETE → 204 No Content. */
export async function deleteTask(id: number): Promise<void> {
  await api.delete(`/tasks/${id}`);
}
```

### Design notes

- **`sort` is a template literal type** (06.11): `'dueDate,asc'` compiles, `'password,asc'` doesn't. That's the API's `field,direction` format, typed. The server validates anyway (verified: `sort=password,asc` → `400 VALIDATION_FAILED`).
- **`signal?: AbortSignal`** on the GETs lets callers cancel (13.09). Writes don't take one: cancelling a write the server may already have performed is rarely what you want.
- **PUT vs PATCH**: the edit form sends every field (PUT, with `CreateTaskRequest`). The toggle and inline title edit change one field (PATCH, with `UpdateTaskRequest = Partial<…>`).
- **The request types exclude server-owned fields** (`id`, `ownerId`, timestamps: 06.04). Even if a client sent them, the mock ignores them (verified: a POST with `"ownerId": 2, "id": 1` created task 26 owned by alice). Your servlets will do the same (S46: mass assignment).
- **`deleteTask` ignores the body**: 204 has none.
- Validation cost: checking 100 tasks with `isTask` takes microseconds. Not a performance concern.

## 5. Try it

```js
const t = await import('/src/api/tasks.ts');
const page = await t.getTasks({ status: 'TODO', sort: 'dueDate,asc', size: 3 });
page.items.map((task) => task.dueDate);   // ascending dates
const created = await t.createTask({ title: 'From the console', description: '', status: 'TODO', priority: 'LOW', dueDate: null, categoryId: null });
created.id;                               // assigned by the server
await t.patchTask(created.id, { status: 'DONE' });
await t.deleteTask(created.id);
await t.getTask(created.id);              // ✗ rejects: 404
```
