## 1. The header

```jsp
<%--
  S39 (39.08): the navigation, with the current section highlighted, and the theme switch (39.09).
  After a FORWARD, pageContext.request.servletPath is the JSP's path (/WEB-INF/views/…): the path the USER asked
  for is kept by the container in the request attribute javax.servlet.forward.servlet_path (39.08).
--%>
<%@ taglib prefix="c" uri="http://java.sun.com/jsp/jstl/core" %>
<%@ taglib prefix="fn" uri="http://java.sun.com/jsp/jstl/functions" %>
<c:set var="currentPath" value="${requestScope['javax.servlet.forward.servlet_path']}"/>
    <nav class="page__nav">
      <a class="page__nav-link${currentPath == '/dashboard' ? ' is-active' : ''}" href="<c:url value='/dashboard'/>">Dashboard</a>
      <a class="page__nav-link${fn:startsWith(currentPath, '/tasks') and currentPath != '/tasks/new' ? ' is-active' : ''}" href="<c:url value='/tasks'/>">Tasks</a>
      <a class="page__nav-link${currentPath == '/tasks/new' ? ' is-active' : ''}" href="<c:url value='/tasks/new'/>">New task</a>
      <a class="page__nav-link${fn:startsWith(currentPath, '/categories') ? ' is-active' : ''}" href="<c:url value='/categories'/>">Categories</a>
      <%-- S41 (41.19): who is logged in, and a POST logout (it changes state: CSRF-protected). --%>
      <c:if test="${not empty currentUser}">
        <span class="page__user">Logged in as <c:out value="${currentUser.displayName}"/></span>
        <form class="inline-form" method="post" action="<c:url value='/logout'/>">
          <input type="hidden" name="_csrf" value="${csrfToken}">
          <button class="btn btn--sm btn--secondary" type="submit">Log out</button>
        </form>
      </c:if>
      <c:if test="${not empty csrfToken}">
        <c:set var="here" value="${requestScope['javax.servlet.forward.request_uri']}${empty requestScope['javax.servlet.forward.query_string'] ? '' : '?'}${requestScope['javax.servlet.forward.query_string']}"/>
        <form class="theme-switch inline-form" method="post" action="<c:url value='/preferences/theme'/>">
          <input type="hidden" name="_csrf" value="${csrfToken}">
          <input type="hidden" name="returnTo" value="${fn:escapeXml(here)}">
          <button class="btn btn--sm btn--secondary" type="submit" name="theme" value="${theme == 'dark' ? 'light' : 'dark'}">${theme == 'dark' ? 'Light' : 'Dark'} theme</button>
        </form>
      </c:if>
    </nav>
```

`${currentUser}` is the request attribute the filter sets. `<c:out>` escapes the display name: it's user data. Log out is a form (POST + token), styled as a button.

## 2. Making the token available on every page

In `AuthenticationFilter`, for logged-in requests (not static files):

```java
request.setAttribute("currentUser", user);
if (!path.startsWith("/static/")) {
  Csrf.prepare(request);
  response.setHeader("Cache-Control", "no-store");   // private pages: not kept in the browser's history cache
}
```

A logged-in user already has a session, so preparing the token costs nothing, and every page's nav can post. The `Csrf.prepare` calls in individual controllers became redundant and were removed.

## 3. Detecting an expired session

```java
if (request.getRequestedSessionId() != null && !request.isRequestedSessionIdValid()) {
  login.append(separator).append("expired=1");         // the browser sent a session id we no longer know (41.19)
}
```

`LoginServlet.doGet` turns the parameter into the `expired` attribute, and `login.jsp` shows the message. It's shown for any unknown id: an expired session, a server restart without persistence, or a tampered cookie. From the server's point of view they're the same.

### Wrong approaches

| Attempt | Problem |
|---|---|
| `${sessionScope.currentUser.displayName}` in the nav | throws in `session="false"` pages (34.25) |
| a `<a href="/logout">` link | a GET that changes state: any page can log users out (37.02) |
| `${currentUser.displayName}` without `<c:out>` | a display name like `<script>` would run (34.18) |
| detecting "expired" with `getSession(false) == null` | also true for someone who never had a session: they'd see "expired" on their first visit |
| a JavaScript timer that redirects after 15 minutes | UX only; the server must enforce the timeout |
