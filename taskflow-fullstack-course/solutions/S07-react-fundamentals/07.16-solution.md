# 💡 Lecture 07.16 · Solution Walkthrough: the Status Board

> Solution for [07.15 · Your Turn](../../lectures/S07-react-fundamentals/07.15-your-turn-board.md).
> Verified in the reference app: `npm run build` and `npm run lint` clean; in the browser, toggling a TODO task on the board changed the column counts from `To do 3 / In progress 1 / Done 1` to `To do 2 / In progress 1 / Done 2`.

## 1. `src/components/Board.tsx`

```tsx
import type { Task, TaskStatus } from '../domain/types';
import { TASK_STATUSES } from '../domain/types';
import { groupByStatus } from '../domain/task-utils';
import { statusLabel } from '../domain/labels';
import { TaskCard } from './TaskCard';
import styles from './Board.module.scss';

interface BoardProps {
  tasks: readonly Task[];
  onToggle: (id: number) => void;
}

export function Board({ tasks, onToggle }: BoardProps) {
  const groups = groupByStatus(tasks);

  return (
    <div className={styles.board}>
      {TASK_STATUSES.map((status) => (
        <BoardColumn key={status} status={status} tasks={groups[status]} onToggle={onToggle} />
      ))}
    </div>
  );
}

interface BoardColumnProps {
  status: TaskStatus;
  tasks: readonly Task[];
  onToggle: (id: number) => void;
}

function BoardColumn({ status, tasks, onToggle }: BoardColumnProps) {
  const headingId = `column-${status}`;

  return (
    <section className={styles.column} aria-labelledby={headingId}>
      <h2 id={headingId} className={styles.heading}>
        {statusLabel(status)} <span className={styles.count}>{tasks.length}</span>
      </h2>
      {tasks.length === 0 ? (
        <p className={styles.empty}>Nothing here.</p>
      ) : (
        <div className={styles.cards}>
          {tasks.map((task) => (
            <TaskCard key={task.id} task={task} onToggle={onToggle} />
          ))}
        </div>
      )}
    </section>
  );
}
```

## 3. `src/App.tsx`

```tsx
import { useState } from 'react';
import type { Task, TaskStatus } from './domain/types';
import { filterTasks, toggleTask } from './domain/task-utils';
import { SAMPLE_TASKS } from './data/sample-tasks';
import { PageLayout } from './components/PageLayout';
import { FilterBar } from './components/FilterBar';
import { TaskList } from './components/TaskList';
import { Board } from './components/Board';
import { Button } from './components/Button';

type View = 'list' | 'board';

export function App() {
  const [tasks, setTasks] = useState<Task[]>(SAMPLE_TASKS);
  const [statusFilter, setStatusFilter] = useState<TaskStatus | null>(null);
  const [view, setView] = useState<View>('list');

  const visibleTasks = filterTasks(tasks, { status: statusFilter ?? undefined });

  function handleToggle(id: number) {
    setTasks((current) => toggleTask(current, id));
  }

  return (
    <PageLayout title="Tasks" subtitle={`(${visibleTasks.length}/${tasks.length})`}>
      <div role="group" aria-label="View">
        <Button size="sm" variant={view === 'list' ? 'primary' : 'secondary'} onClick={() => setView('list')}>
          List
        </Button>
        <Button size="sm" variant={view === 'board' ? 'primary' : 'secondary'} onClick={() => setView('board')}>
          Board
        </Button>
      </div>
      <hr />
      {view === 'list' ? (
        <>
          <FilterBar value={statusFilter} onChange={setStatusFilter} />
          <TaskList tasks={visibleTasks} onToggle={handleToggle} />
        </>
      ) : (
        <Board tasks={tasks} onToggle={handleToggle} />
      )}
    </PageLayout>
  );
}
```

## 4. Reasoning

- **`view` lives in `App`.** It decides *which subtree* renders, so it must be above both views. `Board` doesn't need to know a list view exists.
- **The board shows all tasks** (`tasks`, not `visibleTasks`): the columns *are* the status grouping, so a status filter would be redundant.
- **`groupByStatus` returns all three keys** (04.15), so `groups[status]` is always an array. With `noUncheckedIndexedAccess`, a `Record<TaskStatus, Task[]>` lookup by a `TaskStatus` is still `Task[]`, not `Task[] | undefined`: the key set is known and complete (05.05).
- **`BoardColumn` in the same file, not exported.** Fast Refresh checks module *exports*; an internal component is fine. Split it into its own file when it grows or is reused.
- **Same `TaskCard`, same `onToggle`.** The card has no idea whether it's in a list or a column: composition at work. When a task toggles, `App`'s state changes, `groupByStatus` puts it in a different group, and React **moves** the card between columns. Because the columns are different parents, React actually unmounts it in one column and mounts it in the other (keys are only matched among siblings, 07.11).
- **Ternary for empty columns** instead of `tasks.length && …` (07.10's `0` gotcha).

## 5. Common wrong approaches

| Attempt | Problem |
|---|---|
| Each column holds its own `useState` copy of tasks | Two sources of truth: toggling doesn't move cards between columns |
| `tasks.filter(t => t.status === 'TODO')` three times in JSX | Works, but duplicates `groupByStatus` and hard-codes the statuses |
| `key={index}` on columns or cards | Columns are stable (fine-ish), but cards reorder, so identity is lost (07.11) |
| Defining `BoardColumn` **inside** `Board`'s function body | New component type every render, so every column remounts on each change (07.04) |
| Exporting `BoardColumn` *and* a helper from the same file | Lint warning; Fast Refresh degrades |
