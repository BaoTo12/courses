## Part A: the code (in `list.jsp`)

```jsp
<%
  …
  // 33.15 Your Turn: overdue = a due date before today, and not done. Business logic in a view: see 33.16's critique.
  LocalDate today = LocalDate.now();
  int overdueCount = 0;
  for (Task t : tasks) {
    if (!t.isDone() && t.getDueDate() != null && t.getDueDate().isBefore(today)) overdueCount++;
  }
%>

    <% if (overdueCount > 0) { %>

    <% } %>
```

## Part B: five concrete problems

| # | Line | Problem | The fix (S34–S36) |
|---|---|---|---|
| 1 | `!t.isDone() && t.getDueDate() != null && t.getDueDate().isBefore(today)` **twice** | a domain rule, duplicated **inside one file** already; `view.jsp` and the JSON API will need it too | `Task.isOverdue(LocalDate today)` in the model/service, once, unit-tested |
| 2 | `LocalDate today = LocalDate.now();` | hidden time dependency: untestable for other dates, and it uses the server's timezone, not the user's | the controller passes `today` from an injected `Clock`; the view gets `${overdueCount}` |
| 3 | `overdueCount == 1 ? "task" : "tasks"` | English plural logic in the view; the S44 translation can't express Vietnamese | a `ResourceBundle` message with a choice/plural format (S44) |
| 4 | `(List<Task>) request.getAttribute("tasks")` | an unchecked cast; a wrong attribute name → NPE → 500 | `${tasks}`: EL returns empty/null-safe values, no casts |
| 5 | `<tr<%= overdue ? " class=\"task-row--overdue\"" : "" %>>` | HTML built from Java strings again (escaped quotes), and brittle | `<tr class="${task.overdue ? 'task-row--overdue' : ''}">` with EL, or `<c:if>` |
| (6) | `<% for … { %> … <% } %>` | braces spanning HTML (33.18) | `<c:forEach items="${tasks}" var="task">` |

The common thread: the view is **deciding** things. In S36, the controller (with a service) decides, and the view displays.
