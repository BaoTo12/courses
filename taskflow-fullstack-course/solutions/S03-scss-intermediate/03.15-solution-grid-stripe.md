## Part A: three-column grid

`layout/_page.scss`:

```scss
.task-grid {
  display: grid;
  gap: space(4);
  grid-template-columns: 1fr;

  @include respond-to('md') {
    grid-template-columns: repeat(2, 1fr);
  }

  @include respond-to('lg') {
    grid-template-columns: repeat(3, 1fr);
  }
}
```

**Why the order matters.** Both queries are `min-width`. At 1200px, **both** match. When two rules have equal specificity, the **later** one wins. So `lg` must come after `md`, or wide screens would get 2 columns. Mobile-first = base, then ascending breakpoints.

Compiled:

```css
@media (min-width: 768px) {
  .task-grid { grid-template-columns: repeat(2, 1fr); }
}
@media (min-width: 1024px) {
  .task-grid { grid-template-columns: repeat(3, 1fr); }
}
```

## Part B: priority stripe from the map

`components/_card.scss`:

```scss
// .card--priority-low::before, -medium, -high (generated from the token map)
@each $priority, $color in $priority-colors {
  &--priority-#{$priority}::before {
    background: $color;
  }
}
```

Compiled output is **byte-for-byte identical** to the three hand-written rules:

```css
.card--priority-low::before { background: #14b8a6; }
.card--priority-medium::before { background: #f59e0b; }
.card--priority-high::before { background: #ef4444; }
```

Bonus: `_card.scss` no longer calls `map.get`, so its `@use 'sass:map';` line can be deleted. Remove unused imports, in SCSS as in TypeScript.

**Why this matters:** `$priority-colors` is now the *single* source for badges **and** stripes. When the backend adds `Priority.CRITICAL`, one map entry updates both.

## Part C: theme completeness guard

In `abstracts/_tokens.scss`, add `@use 'sass:list';` at the top, and after `$themes`:

```scss
// ─── Guard: every theme must define exactly the same tokens as 'light' ───
$-reference-keys: map.keys(map.get($themes, 'light'));

@each $theme-name, $theme in $themes {
  $missing: ();
  @each $key in $-reference-keys {
    @if not map.has-key($theme, $key) {
      $missing: list.append($missing, $key, $separator: comma);
    }
  }
  @if list.length($missing) > 0 {
    @error 'Theme "#{$theme-name}" is missing token(s): #{$missing}';
  }
  @each $key in map.keys($theme) {
    @if not list.index($-reference-keys, $key) {
      @error 'Theme "#{$theme-name}" defines "#{$key}", which the light theme does not have.';
    }
  }
}
```

Test: remove `'border'` from the dark theme:

```text
Error: 'Theme "dark" is missing token(s): border'
```

### Reasoning, line by line

- **`$-reference-keys`**: private (leading `-`), so it doesn't leak through `@forward` into every component's namespace.
- **Top-level `@each` in an abstracts file:** allowed, and it emits **no CSS**. It only evaluates and possibly errors. So it doesn't break the "abstracts emits no CSS" rule.
- **`$missing: ();` then reassigning inside `@if`:** in Sass, assignments inside control-flow blocks (`@if`, `@each`) update the variable from the **enclosing** scope if it exists. That's why the list accumulates across iterations of the inner loop.
- **Collect, then error once:** reporting *all* missing keys in one message is kinder than failing one key at a time.
- **The reverse check** catches a typo in the dark theme (`'boder'`), which would otherwise emit a useless `--color-boder` and silently leave `border` with its light value.

### Where else could this guard live?

- In `base/_root.scss`, right before emitting. That works too, but then the check only runs when `root` is compiled. Putting it next to the data means **any** file that loads the tokens validates them. That's better for the React setup, where component modules are compiled separately.

## Common mistakes

| Mistake | Symptom |
|---|---|
| `lg` query written before `md` | 2 columns on wide screens |
| `max-width` queries mixed with `min-width` | Overlapping ranges, hard-to-predict layouts |
| Loop outputs `&--#{$priority}::before` (forgetting `priority-`) | Selectors `.card--low::before` don't match the HTML; stripes vanish |
| `@error` inside the loop for each key | Works, but only reports the first missing key |
| Guard placed in a `base/` file that React doesn't compile | Missing tokens slip through in the SPA build |
