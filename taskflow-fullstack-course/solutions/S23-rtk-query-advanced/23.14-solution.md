## Part A: no new cache code

`patchTask`'s `onQueryStarted` applies **any** `changes` object with `Object.assign` to every cached list and to `getTask(id)`, and undoes it on failure (23.05). A priority change is just another PATCH:

```tsx
  const [patchTask] = usePatchTaskMutation();
  …
  function handlePriority(value: string) {
    // OPTIMISTIC via patchTask (23.13): the badge changes now, and rolls back if the server refuses.
    if (isPriority(value) && value !== current.priority) void patchTask({ id: current.id, changes: { priority: value } });
  }
  …
        {user && (
          <label className="text-muted">
            Priority{' '}
            <select value={task.priority} onChange={(e) => handlePriority(e.target.value)}>
              {PRIORITIES.map((priority) => (
                <option key={priority} value={priority}>
                  {priority}
                </option>
              ))}
            </select>
          </label>
        )}
```

- **`isPriority(value)`** narrows the `string` from the DOM to `Priority` (06.09). The server validates it again anyway.
- **`value !== current.priority`** avoids a pointless PATCH, and an invalidation and refetch with it.
- **The error toast** comes from the existing `patchTask.matchRejected` listener (22.09). **The rollback** comes from `patch.undo()` (23.05).
- **`void patchTask(…)`**: we don't need the result here. The cache *is* the result.

The page as a whole: [23.05 §4](../../lectures/S23-rtk-query-advanced/23.05-build-optimistic-toggle-delete.md#4-the-details-page-leave-first-then-delete).

The test you were asked to add, following the "23.04 optimistic patch" case:

```ts
  it('23.13 optimistic priority change rolls back on failure', async () => {
    const { server, store, one } = setup(task(1));
    const sub = store.dispatch(apiSlice.endpoints.getTask.initiate(1));
    await sub;
    server.state.failWrites = true;
    const patch = store.dispatch(apiSlice.endpoints.patchTask.initiate({ id: 1, changes: { priority: 'HIGH' } }));
    expect(one(1)?.priority).toBe('HIGH');
    await expect(patch.unwrap()).rejects.toMatchObject({ status: 500 });
    expect(one(1)?.priority).toBe('MEDIUM');
    sub.unsubscribe();
  });
```

## Part B: prefetch the comments

In `TasksPage`:


In `TaskList`:

```tsx
import { memo } from 'react';
import type { Task } from '../domain/types';
import { TaskCard } from './TaskCard';

/**
 * S23: the list shows a server PAGE (23.07), so it receives the page's task objects, not ids to look up in
 * the app-wide list. `memo` compares each task by reference, and RTK Query's structural sharing keeps
 * unchanged tasks identical across refetches and optimistic patches (22.06): a toggle still re-renders one card.
 */
const MemoTaskCard = memo(TaskCard);

interface TaskListProps {
  tasks: readonly Task[];
  onToggle: (id: number) => void;
  onEditTitle: (id: number, title: string) => void;
  /** Hover → prefetch the details (23.08). */
  onHoverTask?: (id: number) => void;
}

export function TaskList({ tasks, onToggle, onEditTitle, onHoverTask }: TaskListProps) {
  if (tasks.length === 0) {
    return <p className="text-muted">No tasks match this filter.</p>;
  }

  return (
    <div className="task-grid">
      {tasks.map((task) => (
        <div key={task.id} onMouseEnter={onHoverTask && (() => onHoverTask(task.id))}>
          <MemoTaskCard task={task} onToggle={onToggle} onEditTitle={onEditTitle} />
        </div>
      ))}
    </div>
  );
}
```

- **Why not prefetch `getTask`:** the list **seeded** `getTask(id)` for every task it loaded (23.06), so it's already cached, and `prefetch` would do nothing.
- **`onHoverTask` is optional.** `TaskList` doesn't know about comments or RTK Query. The page wires it.
- **Without options**, `prefetch(id)` only fetches when there's no entry yet. Hovering the same card twice sends one request. After 60 s without a visit, the entry is gone and a hover fetches again.
- The hover wrapper is a plain `<div>` **around** the memoised card, so the inline `() => onHoverTask(task.id)` doesn't break `memo(TaskCard)`: the card's own props are still the same references.
