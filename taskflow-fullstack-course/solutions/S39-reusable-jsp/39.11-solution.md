```jsp
                  <input type="hidden" name="_csrf" value="${csrfToken}">

                  <button class="btn btn--sm btn--secondary" type="submit">Delete</button>

```

The list now has one line where the row was:

```jsp
<c:forEach items="${tasks}" var="task" varStatus="row">
  <%@ include file="/WEB-INF/views/tasks/task-row.jspf" %>
</c:forEach>
```

**Why the directive:** the row reads `task` and `row`, which `<c:forEach>` puts in **page** scope. A `<jsp:include>`d JSP has its own page scope and wouldn't see them (39.13). With the directive, the fragment's text becomes part of the loop body, compiled into the same method.

## 3. The controller and the page

```java
package com.taskflow.web;

import com.taskflow.service.TaskService;
import java.io.IOException;
import javax.servlet.ServletException;
import javax.servlet.annotation.WebServlet;
import javax.servlet.http.HttpServlet;
import javax.servlet.http.HttpServletRequest;
import javax.servlet.http.HttpServletResponse;

/** S39 (39.10): GET /dashboard → overdue tasks and tasks due within 7 days, rendered with the shared task-row fragment. */
@WebServlet("/dashboard")
public class DashboardServlet extends HttpServlet {

  private TaskService service;

  @Override
  public void init() {
    service = AppContextListener.taskService(getServletContext());
  }

  @Override
  protected void doGet(HttpServletRequest request, HttpServletResponse response) throws ServletException, IOException {
    request.setAttribute("pageTitle", "Dashboard");
    request.setAttribute("today", service.today());
    request.setAttribute("overdue", service.overdue());
    request.setAttribute("dueSoon", service.dueWithin(7));
    Csrf.prepare(request);   // the rows contain POST forms (toggle, delete)
    Flash.consume(request);
    request.getRequestDispatcher("/WEB-INF/views/dashboard.jsp").forward(request, response);
  }
}
```

### Wrong approaches

| Attempt | Problem |
|---|---|
| `<jsp:include page="task-row.jsp"/>` inside the loop | the included JSP can't see `task` (page scope) → empty rows (39.13); workaround: `<c:set var="task" value="${task}" scope="request"/>` before each include, which is clumsy and slower |
| copying the row into the dashboard | the next escaping fix will be made in one copy only |
| filtering overdue tasks in the JSP with `<c:if test="${task.isOverdue(today)}">` around the rows | business logic in the view (33.13); the counts in the headings would need it again |
| forgetting `Csrf.prepare` in the dashboard controller | the rows' forms post an empty token → 403 on Toggle and Delete |
