## 1. Reducer: the new action

`src/hooks/tasks-reducer.ts` (changes marked):

```ts
import type { Task } from '../domain/types';
import type { RequestState } from '../domain/api-types';
import { toggleTask, updateTaskField } from '../domain/task-utils';   // + updateTaskField
import { assertNever } from '../domain/guards';

export type TasksState = RequestState<Task[]>;

export type TasksAction =
  | { type: 'fetchStarted' }
  | { type: 'fetchSucceeded'; tasks: Task[] }
  | { type: 'fetchFailed'; error: string }
  | { type: 'taskToggled'; id: number }
  | { type: 'titleEdited'; id: number; title: string };                // + new event

export const initialTasksState: TasksState = { status: 'idle' };

export function tasksReducer(state: TasksState, action: TasksAction): TasksState {
  switch (action.type) {
    case 'fetchStarted':
      return { status: 'loading' };
    case 'fetchSucceeded':
      return { status: 'succeeded', data: action.tasks };
    case 'fetchFailed':
      return { status: 'failed', error: action.error };
    case 'taskToggled':
      if (state.status !== 'succeeded') return state;
      return { status: 'succeeded', data: toggleTask(state.data, action.id) };
    case 'titleEdited': {                                               // + new case
      if (state.status !== 'succeeded') return state;
      const title = action.title.trim();
      if (title === '') return state;
      return { status: 'succeeded', data: updateTaskField(state.data, action.id, 'title', title) };
    }
    default:
      return assertNever(action);
  }
}
```

**Before** adding the `case`, the compiler reports (the same mechanism as 06.13):

```text
Argument of type '{ type: "titleEdited"; id: number; title: string; }' is not assignable to parameter of type 'never'.
```

Adding an event to the union **forces** you to decide how the reducer handles it.

**Why validation lives here:** the reducer is pure and React-free, so the "trim and reject empty" rule is testable with one line (`expect(tasksReducer(s, { type: 'titleEdited', id: 1, title: '  ' })).toBe(s)`), and it moves unchanged into a Redux slice in S15. Components stay about presentation. (The **server** must validate again in S37/S46. Client-side rules are UX, not security.)

**Returning `state` itself** when nothing changes preserves the reference, so React bails out (08.02 §5).

## 3. Component: `src/components/TaskCard.tsx`

```tsx
import { useEffect, useRef, useState } from 'react';
import type { KeyboardEvent } from 'react';
import type { Task } from '../domain/types';
import { Button } from './Button';
import { PriorityBadge, StatusBadge } from './Badge';
import { toKebab } from '../domain/format';
import styles from './TaskCard.module.scss';

interface TaskCardProps {
  task: Task;
  onToggle: (id: number) => void;
  onEditTitle: (id: number, title: string) => void;
}

export function TaskCard({ task, onToggle, onEditTitle }: TaskCardProps) {
  const isDone = task.status === 'DONE';
  const [isEditing, setIsEditing] = useState(false);
  const [draft, setDraft] = useState(task.title);
  const inputRef = useRef<HTMLInputElement>(null);

  // When editing starts, focus the input (a DOM side effect → an effect with a ref).
  useEffect(() => {
    if (isEditing) {
      inputRef.current?.select();
    }
  }, [isEditing]);

  function startEditing() {
    setDraft(task.title); // start from the current title, not a stale draft
    setIsEditing(true);
  }

  function save() {
    onEditTitle(task.id, draft);
    setIsEditing(false);
  }

  function handleKeyDown(e: KeyboardEvent<HTMLInputElement>) {
    if (e.key === 'Enter') save();
    if (e.key === 'Escape') setIsEditing(false);
  }

  return (
    <article className={`card card--priority-${toKebab(task.priority)}`}>
      {isEditing ? (
        <input
          ref={inputRef}
          className="form-field__input"
          aria-label="Task title"
          value={draft}
          onChange={(e) => setDraft(e.target.value)}
          onKeyDown={handleKeyDown}
          onBlur={save}
        />
      ) : (
        <h3 className="card__title" onDoubleClick={startEditing}>
          {task.title}
        </h3>
      )}
      <p className="card__body">{task.description}</p>
      <footer className="card__meta">
        <div className={styles.badges}>
          <StatusBadge status={task.status} />
          <PriorityBadge priority={task.priority} />
        </div>
        <div className={styles.badges}>
          {!isEditing && (
            <Button size="sm" onClick={startEditing}>
              Edit
            </Button>
          )}
          <Button size="sm" onClick={() => onToggle(task.id)}>
            {isDone ? 'Reopen' : 'Mark done'}
          </Button>
        </div>
      </footer>
      {task.dueDate && <p className={styles.due}>Due {task.dueDate}</p>}
    </article>
  );
}
```

Then pass `onEditTitle` through `TaskList` and `Board` (and `BoardColumn`) exactly like `onToggle`, and from `App` pass `editTitle` from `useTasks()`.

### Reasoning

- **`draft` is local state.** While typing, no other component cares about the half-typed title; only the final value is an app-level event. Putting keystrokes into the reducer (or later Redux) would re-render the whole list on every key, and store data nobody else reads.
- **`setDraft(task.title)` in `startEditing`** instead of an effect syncing `draft` with `task.title` (08.05 anti-pattern 3). That's one render, no flicker, always fresh.
- **`useRef` + `useEffect([isEditing])`**: focus is an imperative DOM API; the effect runs after the input is committed to the DOM, when `inputRef.current` exists. `select()` focuses and selects the text so typing replaces it.
- **Escape doesn't save.** Switching `isEditing` to `false` unmounts the input. In the reference test, the blur handler didn't fire on that removal, so the cancel held. (If you ever see Escape saving in some browser, guard with a `cancelledRef` set in the Escape branch and checked in `save`.)
- **Toggling passes through unchanged**, since the card only reports events.

## 4. Prop drilling, again

Notice that you just threaded `onEditTitle` through `App → TaskList → TaskCard` **and** `App → Board → BoardColumn → TaskCard`. Every new task operation (delete, change priority…) will repeat this. That's the concrete pain from 07.14 that Redux removes in S17: `TaskCard` will `dispatch` directly.

## 5. Common wrong approaches

| Attempt | Problem |
|---|---|
| Trim/validate in `TaskCard` only | Rule is untestable without rendering; duplicated if another component edits titles |
| `useEffect(() => setDraft(task.title), [task.title])` | Extra render + flicker; overwrites typing if the task updates while editing |
| Storing the draft in the reducer | Global re-render per keystroke; mixes form state with domain state |
| `autoFocus` on the input | Focuses, but doesn't select; fine too, but `autoFocus` has accessibility caveats on page load |
| `default: return state;` in the reducer | Silences exhaustiveness: a new action type compiles without handling |
