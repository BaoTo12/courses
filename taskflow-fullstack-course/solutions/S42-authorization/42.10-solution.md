# Solution 42.10 · Visibility in One Place

> Exercise: [`lectures/S42-authorization/42.09-your-turn-visibility.md`](../../lectures/S42-authorization/42.09-your-turn-visibility.md)
> Verified: `S42AuthorizationTest.usersListOnlyTheirOwnTasksAndAdminsListAll`, and every older list, dashboard and stats test (logged in as alice, who owns tasks 1–22)

---

## 1. The rule, once

```java
/** The owner a list or count is restricted to: null (everyone) for admins, the caller's own id otherwise. */
private static Long ownerScope(AuthUser caller) {
  return caller.isAdmin() ? null : caller.getId();
}
```

and every list use case applies it:

```java
public List<Task> find(TaskFilter filter, AuthUser caller) {
  return tasks.find(filter.withOwner(ownerScope(caller)));
}
public Map<String, Integer> countByStatus(AuthUser caller) { … tasks.countByStatus(ownerScope(caller)) … }
public OptionalLong latestId(AuthUser caller) { return tasks.latestId(ownerScope(caller)); }
private List<Task> byDueDate(AuthUser caller) {             // overdue() and dueWithin() use this
  return tasks.find(new TaskFilter(null, null, null, TaskSort.DUE, ownerScope(caller)));
}
```

`visible(id, caller)` (42.05) and `ownerScope(caller)` are the **entire** policy: to let a future "team lead" role see their team's tasks, you'd change these two methods and nothing else.

## 2. The filter's owner comes from the service

`TaskListServlet` builds a `TaskFilter` from the request **without** an owner, and the service overwrites it with `withOwner(ownerScope(caller))`. Even a controller that set `ownerId` by mistake (from `?owner=2`, say) couldn't widen what a user sees.

## 3. The controllers

```java
AuthUser user = CurrentUser.get(request);
List<Task> tasks = service.find(filter, user);                // S42: only what this user may see (42.09)
…
request.setAttribute("stats", service.countByStatus(user));
request.setAttribute("recentTasks", RecentTasks.ids(request).stream()
    .map(id -> service.task(id, user)).flatMap(Optional::stream).toList());
```

`DashboardServlet` passes the user to `overdue` and `dueWithin`; `TaskLatestServlet` to `latestId`.

## 4. The diagnostics exception

```java
/** For /debug/stats only (loopback, no user): NO access check. Never call it from a user-facing controller. */
public Optional<Task> taskForDiagnostics(long id) { … }
```

A separate, loudly named method is easy to find in a review (`grep taskForDiagnostics`). A `null` caller meaning "no check" would be invisible.

### Wrong approaches

| Attempt | Problem |
|---|---|
| filter the list in the JSP (`<c:if test="${task.ownerId == currentUser.id}">`) | the data was already loaded and sent to the view; the counts stay wrong; forgotten on the next page |
| `?owner=` parameter set by the controller from the session | the rule now lives in N controllers, and one of them will read the parameter from the request |
| filter in Java after loading all tasks | correct, but loads every user's tasks for every request; the database should filter |
| `find(filter)` kept as an unscoped overload "for admins" | the next controller will call it for everyone |
