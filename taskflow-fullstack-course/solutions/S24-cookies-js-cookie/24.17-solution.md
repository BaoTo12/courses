## 1. The module

✍️ `src/features/preferences/rememberedCookies.ts`

```ts
// S24 Your Turn (24.16): two more cookies, each with the attributes its PURPOSE needs.
import { readCookie, writeCookie } from '../../api/cookies';
import type { User } from '../../domain/types';

export type Language = User['locale']; // 'en' | 'vi'
const LANGUAGES: readonly Language[] = ['en', 'vi'];

/**
 * "Remember my language": a DEVICE preference. Persistent (1 year), survives logout, and harmless if read by
 * JavaScript. S25's language detector reads the same cookie (`lookupCookie: 'tf_lang'`).
 */
export function rememberLanguage(language: Language): void {
  writeCookie('language', language, { days: 365 });
}

export function readRememberedLanguage(): Language | undefined {
  const raw = readCookie('language');
  return LANGUAGES.find((language) => language === raw); // validate: user-editable
}

/**
 * "Remember the last visited task": USER data (it points at one of this user's tasks). A SESSION cookie (no
 * expiry: gone when the browser session ends) and removed on logout by `clearUserData` (23.11).
 */
export function rememberLastTask(taskId: number): void {
  writeCookie('lastTask', String(taskId));
}

export function readLastTaskId(): number | undefined {
  const raw = readCookie('lastTask');
  if (raw === undefined || !/^[1-9]\d{0,9}$/.test(raw)) return undefined; // a positive integer, nothing else
  return Number(raw);
}
```

- **`User['locale']`** reuses the domain type (`'en' | 'vi'`), so adding a language later is one change.
- **`LANGUAGES.find(...)`** validates and narrows without a cast. The same trick as the page sizes (23.07).
- **The task id regex** `^[1-9]\d{0,9}$` accepts only a positive integer of reasonable length. `Number('1;alert(1)')` would be `NaN`, but `Number(' 42 ')` would be `42`, and `Number('1e3')` would be `1000`. A regex states exactly what we accept.

## 2. Writing the last task (details page)

In `src/pages/TaskDetailsPage.tsx`, near the other hooks, **before** any early return:

```tsx
  const loadedId = task?.id;
  // 24.16: remember the last task this user OPENED (a session cookie), once it really loaded.
  useEffect(() => {
    if (loadedId !== undefined) rememberLastTask(loadedId);
  }, [loadedId]);
```

- It depends on the **loaded** task's id, not the URL's, so `/tasks/999` (not found) writes nothing.
- An effect, because writing a cookie is a side effect, and render must stay pure (08.04).

## 3. Reading it (Tasks page)

```tsx
  // 24.16: "Continue where you left off", from the session cookie. Read once per mount; shown only if the task exists.
  const [lastTaskId] = useState(readLastTaskId);
  const lastTask = useAppSelector((state) => (lastTaskId === undefined ? undefined : selectTaskById(state, lastTaskId)));
  …
      {lastTask && (
        <p className="text-muted">
          Continue where you left off: <Link to={`/tasks/${lastTask.id}`}>{lastTask.title}</Link>
        </p>
      )}
```

- `useState(readLastTaskId)` passes the function, so it's a lazy initialiser: the cookie is read once per mount, not on every render.
- **Only shown if the task is in the cache.** A deleted task, or another user's id, shows nothing.

## 4. Removed on logout

In `src/features/auth/clearUserData.ts` (23.11, extended), one more line:

```ts
  removeCookie('lastTask');
```

Every logout path (the button, `sessionExpired`) runs `clearUserData`, so there's one place to add it.

## 5. Answers to the questions

**1. Attributes**

| | `tf_lang` | `tf_last_task` |
|---|---|---|
| Lifetime | `expires: 365` days | none → **session cookie** |
| `Path` | `/` (the wrapper default) | `/` |
| `SameSite` | `Lax` | `Lax` |
| `Secure` | on HTTPS | on HTTPS |
| `HttpOnly` | impossible from JS, and unnecessary: not secret | same |

**2. Survives logout?** The language describes the **device or person at the keyboard**, not the account. The next user probably reads the same language, and it isn't sensitive. The last task is **account data**: it points at one of alice's tasks. It goes with the rest of alice's data (23.10).

**3. Leaks?** The cookie holds only an id. The title comes from the **cache**, which is empty after logout, and a different user's session can't load alice's task (the server answers 404, 12.07). Removing it on logout means even the id doesn't survive. Its value is readable by any script on the page, which is acceptable for a non-secret id and wouldn't be for a token (24.08).
