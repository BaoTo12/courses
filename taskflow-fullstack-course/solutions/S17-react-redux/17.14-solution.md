## 1. `src/features/tasks/OpenTasksBadge.tsx`

```tsx
import { useAppSelector } from '../../app/hooks';
import { selectOpenTaskCount } from './tasksSlice';

/**
 * "N open" in the header. Selects a NUMBER, so it re-renders only when the count changes:
 * not when a title is edited, not when the sort preference changes, not on toasts (17.13).
 */
export function OpenTasksBadge() {
  const openCount = useAppSelector(selectOpenTaskCount);
  return (
    <span className="badge badge--todo" aria-live="polite" title="Open tasks (to do + in progress)">
      {openCount} open
    </span>
  );
}
```

- `badge badge--todo` reuses the design system's status badge (02.09). No new CSS.
- `aria-live="polite"`: screen readers announce "16 open" when the count changes, without interrupting.
- Added to `AppLayout`'s header, before `<ThemeToggle />`.

## 2. The measurements (with a temporary `console.count`)

| Dispatch | Badge text | Renders with `selectOpenTaskCount` | Renders with the `filter(…)` selector |
|---|---|---|---|
| `listPrefs/sortChanged` | 17 open | **0** | 2 |
| `ui/toastShown` | 17 open | **0** | 2 |
| `tasks/taskUpdated` (title edit) | 17 open | **0** | — |
| `tasks/taskUpdated` (marked DONE) | 16 open | 2 | — |
| `tasks/taskUpdated` (back to TODO) | 17 open | 2 | — |

("2" = one real render, doubled by StrictMode in development.)

With the `filter` selector, React-Redux's development stability check also logged: *"Selector unknown returned a different result when called with the same parameters. This can lead to unnecessary rerenders. Selectors that return a new reference (such as an object or an array) should be memoized…"*.

The lesson in one sentence: **the number of re-renders is decided by what the selector returns**, not by which slice changed.

## 3. `src/features/tasks/task-operations.ts` (final for S17)

```ts
// S17: async logic done "by hand" around dispatch. Every function here has the same shape:
// call the API, then dispatch plain actions with the result. S18 turns them into THUNKS.
import { useMemo } from 'react';
import { createTask, deleteTask, getTasks, patchTask, updateTask } from '../../api/tasks';
import { isCancelled } from '../../api/api-error';
import { toErrorMessage } from '../../domain/guards';
import type { CreateTaskRequest, UpdateTaskRequest } from '../../domain/api-types';
import { useAppDispatch } from '../../app/hooks';
import type { AppDispatch } from '../../app/store';
import {
  completedCleared,
  fetchFailed,
  fetchStarted,
  fetchSucceeded,
  taskAdded,
  taskDeleted,
  taskUpdated,
} from './tasksSlice';

/** Until pagination arrives (S23), the list loads the first 100 tasks: the API's maximum page size. */
const LIST_QUERY = { size: 100 } as const;

/** Loads the task list into the store. Never throws: failures become `tasks/fetchFailed`. */
export async function loadTasks(dispatch: AppDispatch, signal?: AbortSignal): Promise<void> {
  dispatch(fetchStarted());
  try {
    const page = await getTasks(LIST_QUERY, signal);
    dispatch(fetchSucceeded(page.items));
  } catch (error) {
    if (signal?.aborted || isCancelled(error)) return; // cancelled on purpose (StrictMode, unmount)
    dispatch(fetchFailed(toErrorMessage(error)));
  }
}

/**
 * Write operations: server first, then dispatch what the server returned (pessimistic, 13.13).
 * They THROW on failure: the calling page decides how to tell the user.
 */
export function useTaskOperations() {
  const dispatch = useAppDispatch();
  return useMemo(
    () => ({
      reload: () => loadTasks(dispatch),
      create: async (request: CreateTaskRequest) => {
        const created = await createTask(request);
        dispatch(taskAdded(created));
        return created;
      },
      update: async (id: number, request: CreateTaskRequest) => {
        const saved = await updateTask(id, request);
        dispatch(taskUpdated(saved));
        return saved;
      },
      patch: async (id: number, changes: UpdateTaskRequest) => {
        const saved = await patchTask(id, changes);
        dispatch(taskUpdated(saved));
        return saved;
      },
      remove: async (id: number) => {
        await deleteTask(id);
        dispatch(taskDeleted(id));
      },
      /**
       * Deletes the given (completed) tasks on the server, then dispatches ONE event with the ids
       * that were really deleted. allSettled: one failure doesn't hide the successes (17.13).
       */
      clearCompleted: async (ids: readonly number[]) => {
        const results = await Promise.allSettled(ids.map((id) => deleteTask(id)));
        const deleted = ids.filter((_, index) => results[index]?.status === 'fulfilled');
        if (deleted.length > 0) dispatch(completedCleared(deleted));
        return { deleted: deleted.length, failed: ids.length - deleted.length };
      },
    }),
    [dispatch],
  );
}
```

- **`Promise.allSettled`** runs the deletes **in parallel** and never rejects. `results[index]` lines up with `ids[index]`, so `deleted` is exactly the ids whose `DELETE` succeeded.
- **One event** for the whole operation: `completedCleared(deleted)`. The `tasks` slice removes them, and the `ui` slice removes them from the selection (15.10). One DevTools entry describes the whole user action.
- **Partial failure is reported, not hidden**: the function returns `{ deleted, failed }` and the page chooses the toast.
- Parallel deletes: fine for a handful of tasks. For hundreds, you'd want a bulk endpoint (`POST /api/tasks/bulk-delete`) or limited concurrency. A good API design point for S46.

## 4. `src/pages/TasksPage.tsx` (final for S17)

```tsx
import { Link, useSearchParams } from 'react-router';
import { filterTasks } from '../domain/task-utils';
import { isTaskStatus, toErrorMessage } from '../domain/guards';
import type { TaskStatus } from '../domain/types';
import { useDebounce } from '../hooks/useDebounce';
import { useAppSelector } from '../app/hooks';
import { selectTasksState } from '../features/tasks/tasksSlice';
import { useTaskOperations } from '../features/tasks/task-operations';
import { useToast } from '../toast/toast-context';
import { useAuth } from '../auth/auth-context';
import { FilterBar } from '../components/FilterBar';
import { SearchBox } from '../components/SearchBox';
import { TaskList } from '../components/TaskList';
import { Board } from '../components/Board';
import { Button } from '../components/Button';
import { ProgressRing } from '../components/styled/ProgressRing';
import { Stack } from '../components/styled/Stack';

type View = 'list' | 'board';

export function TasksPage() {
  // One selector for the whole slice: this page shows items, status AND error (17.04).
  const { items, status, error } = useAppSelector(selectTasksState);
  const { reload, patch, clearCompleted } = useTaskOperations();
  const { user } = useAuth();
  const { show } = useToast();
  const [searchParams, setSearchParams] = useSearchParams();

  // The URL is the source of truth for filters (12.03). Parse and VALIDATE: the URL is user input.
  const rawStatus = searchParams.get('status');
  const statusFilter: TaskStatus | null = isTaskStatus(rawStatus) ? rawStatus : null;
  const view: View = searchParams.get('view') === 'board' ? 'board' : 'list';
  const q = searchParams.get('q') ?? '';

  /** Update one query parameter, keeping the others. replace: filter tweaks shouldn't flood history. */
  function setParam(name: string, value: string | null) {
    setSearchParams(
      (current) => {
        const next = new URLSearchParams(current);
        if (value === null || value === '') next.delete(name);
        else next.set(name, value);
        return next;
      },
      { replace: true },
    );
  }

  // The input shows q immediately; filtering uses a debounced copy (08.12).
  const debouncedQ = useDebounce(q, 300);

  /** Server first (PATCH), then the store updates. The toast reports what the server accepted. */
  async function handleToggle(id: number) {
    const task = items.find((t) => t.id === id);
    if (!task) return;
    const nextStatus = task.status === 'DONE' ? 'TODO' : 'DONE';
    try {
      await patch(id, { status: nextStatus });
      if (nextStatus === 'DONE') show({ tone: 'success', message: `Completed: ${task.title}` });
    } catch (err) {
      show({ tone: 'error', message: toErrorMessage(err) });
    }
  }

  async function handleEditTitle(id: number, title: string) {
    const task = items.find((t) => t.id === id);
    if (!task || title.trim() === '' || title.trim() === task.title) return; // nothing to save
    try {
      await patch(id, { title });
    } catch (err) {
      show({ tone: 'error', message: toErrorMessage(err) });
    }
  }

  async function handleClearCompleted() {
    const doneIds = items.filter((t) => t.status === 'DONE').map((t) => t.id);
    if (!window.confirm(`Delete ${doneIds.length} completed task(s)? This cannot be undone.`)) return;
    const { deleted, failed } = await clearCompleted(doneIds);
    if (failed === 0) show({ tone: 'success', message: `Deleted ${deleted} completed task(s).` });
    else show({ tone: 'error', message: `Deleted ${deleted}, but ${failed} could not be deleted.` });
  }

  const hasData = status === 'succeeded' || items.length > 0;
  const doneCount = items.filter((t) => t.status === 'DONE').length;

  let content;
  if (status === 'failed' && items.length === 0) {
    content = (
      <div role="alert">
        <p className="text-danger">{error}</p>
        <Button onClick={() => void reload()}>Try again</Button>
      </div>
    );
  } else if (!hasData) {
    content = <p className="text-muted">Loading tasks…</p>;
  } else {
    const visible = filterTasks(items, { status: statusFilter ?? undefined, q: debouncedQ });
    content =
      view === 'list' ? (
        <>
          <FilterBar value={statusFilter} onChange={(s) => setParam('status', s)} />
          <TaskList tasks={visible} onToggle={handleToggle} onEditTitle={handleEditTitle} />
        </>
      ) : (
        <Board tasks={items} onToggle={handleToggle} onEditTitle={handleEditTitle} />
      );
  }

  return (
    <>
      <h1 className="page__title">
        Tasks {hasData && <span className="text-muted">({items.length})</span>}
        {status === 'loading' && hasData && <span className="text-muted"> · refreshing…</span>}
      </h1>
      {status === 'failed' && hasData && (
        <p role="alert" className="text-danger">
          Refresh failed: {error} <Button size="sm" onClick={() => void reload()}>Try again</Button>
        </p>
      )}
      {hasData && (
        <Stack $direction="row" $gap={4} $align="center">
          <ProgressRing done={doneCount} total={items.length} />
          <span className="text-muted">tasks done</span>
        </Stack>
      )}
      <Stack $direction="row" $gap={2} $align="center" $wrap>
        <div role="group" aria-label="View">
          <Button size="sm" variant={view === 'list' ? 'primary' : 'secondary'} onClick={() => setParam('view', null)}>
            List
          </Button>
          <Button size="sm" variant={view === 'board' ? 'primary' : 'secondary'} onClick={() => setParam('view', 'board')}>
            Board
          </Button>
        </div>
        <Link className="btn btn--primary btn--sm" to="/tasks/new">
          + New task
        </Link>
        {user && doneCount > 0 && (
          <Button size="sm" variant="danger" onClick={() => void handleClearCompleted()}>
            Clear completed ({doneCount})
          </Button>
        )}
      </Stack>
      {view === 'list' && <SearchBox value={q} onChange={(value) => setParam('q', value)} />}
      <hr />
      {content}
    </>
  );
}
```

- `doneCount` is computed once and used by both the progress ring and the button.
- The button is **UX-gated** on `user` (12.07: the API is what protects the data).
- `void handleClearCompleted()` in `onClick`: the handler is async, and `void` marks the promise as deliberately not awaited.

## 5. `src/layouts/AppLayout.tsx` (final for S17)

```tsx
import { useEffect } from 'react';
import { NavLink, Outlet, useNavigate } from 'react-router';
import { ThemeToggle } from '../components/ThemeToggle';
import { Avatar } from '../components/styled/Avatar';
import { Stack } from '../components/styled/Stack';
import { Button } from '../components/Button';
import { useAuth } from '../auth/auth-context';
import { useAppDispatch } from '../app/hooks';
import { loadTasks } from '../features/tasks/task-operations';
import { OpenTasksBadge } from '../features/tasks/OpenTasksBadge';

/** NavLink passes { isActive } so the active link gets the design system's modifier class. */
const navClass = ({ isActive }: { isActive: boolean }) =>
  `page__nav-link${isActive ? ' page__nav-link--active' : ''}`;

/** The shell shared by every page: header + nav, the current page (<Outlet/>), footer. */
export function AppLayout() {
  const { user, logout } = useAuth();
  const navigate = useNavigate();
  const dispatch = useAppDispatch();

  // Load the tasks once for the whole app (every page reads them from the store). S18: a thunk.
  useEffect(() => {
    const controller = new AbortController();
    void loadTasks(dispatch, controller.signal);
    return () => controller.abort();
  }, [dispatch]);

  function handleLogout() {
    logout();
    navigate('/tasks', { replace: true });
  }

  return (
    <div className="page">
      <header className="page__header">
        <span className="page__brand">TaskFlow</span>
        <nav className="page__nav" aria-label="Main">
          <NavLink className={navClass} to="/tasks">
            Tasks
          </NavLink>
          <NavLink className={navClass} to="/dashboard">
            Dashboard
          </NavLink>
        </nav>
        <Stack $direction="row" $gap={3} $align="center" style={{ marginLeft: 'auto' }}>
          <OpenTasksBadge />
          <ThemeToggle />
          {user ? (
            <>
              <Avatar name={user.displayName} size="sm" />
              <Button size="sm" onClick={handleLogout}>
                Log out
              </Button>
            </>
          ) : (
            <NavLink className={navClass} to="/login">
              Log in
            </NavLink>
          )}
        </Stack>
      </header>
      <main className="page__main">
        <Outlet />
      </main>
      <footer className="page__footer">TaskFlow Web</footer>
    </div>
  );
}
```

## 7. Common wrong approaches

| Approach | Problem |
|---|---|
| Badge selects `state.tasks.items` and counts in the component | Correct number, but it re-renders on **every** task change (title edits included). |
| Badge selects the filtered array | Re-renders on **every action** in the app (measured above). |
| `Promise.all` for the deletes | The first failure rejects everything: you don't know which tasks were deleted, and the store is never updated for the ones that were. |
| One `taskDeleted` dispatch per id | Works, but k actions, k reducer passes, k re-render cycles, and a noisy DevTools log for one user action. |
| Dispatching `completedCleared` **before** the server responds | Tasks vanish even if the server refuses (an optimistic update without rollback). |
